## Scope (do exactly this, no more, no less)

The three named pre-checks gate auto-merge on every per-Org `<org>/iac` PR (per ADR-0009 §branch-protection). Wave-1 (G117.3) ships the PR-open + status-report machinery; this slot HARDENS the three checks themselves + integration-tests every edge case the operator-walk has surfaced.

### 1. `kyverno-admission` — per-Org Kyverno CI workflow

- Add Gitea Actions workflow at `tools/gitea-actions/kyverno-admission.yml` (template — copied into every `<org>/iac` repo on bootstrap)
- Workflow runs on every PR open + sync:
  ```yaml
  steps:
    - uses: actions/checkout@v4
    - run: |
        set -euo pipefail
        kyverno apply \
          --policy https://raw.githubusercontent.com/openova-io/openova/main/platform/kyverno-policies/chart/templates/cluster-policies/ \
          --resource ./apps/ ./envs/ ./policies/
  ```
- Exit non-zero on ANY policy violation → status check FAIL
- Must include the Catalyst-baseline ClusterPolicies:
  - `require-resource-limits` (cpu+memory request+limit on every container)
  - `disallow-host-network` (no `hostNetwork: true` outside `kube-system`-equivalent)
  - `disallow-privileged-containers`
  - `require-tls-on-public-endpoints` (Catalyst-custom — every Endpoint with `visibility: public` MUST have `tls: true`)
  - `disallow-wildcard-hostname` (Catalyst-custom — Endpoint hostname must be FQDN, not `*.<org>.<sov>`)
  - `require-sso-on-internal-endpoints` (Catalyst-custom — `visibility: internal` AND tied to a Tier-1/2/3 SSO-capable bp ⇒ `ssoEnabled: true`)

### 2. `cert-manager-precheck` — catalyst-api at PR open

- Implemented in `core/services/catalyst-api/internal/endpoints/precheck.go`
- For every endpoint manifest in the PR:
  - Parse the rendered hostname
  - Query `cert-manager.io/v1.Certificate` CRs across all Orgs' namespaces for an existing Cert with that hostname in `spec.dnsNames`
  - If found AND belongs to a DIFFERENT Org → FAIL with `Error{code: "hostname-already-certified", details: {existingOrg, existingCertName}}`
  - If found AND belongs to SAME Org but DIFFERENT App → WARN (allowed; same Org may legitimately re-route a hostname between Apps via a rename flow — captured by walk D3)
- POST result back to Gitea PR status via `/api/v1/repos/{org}/iac/statuses/{sha}`

### 3. `dns-conflict-precheck` — catalyst-api at PR open

- Implemented in `core/services/catalyst-api/internal/endpoints/precheck.go`
- For every endpoint manifest in the PR:
  - Query PowerDNS REST API at `https://pdns.<sov>/api/v1/servers/localhost/zones/<sov>.` for any A/AAAA/CNAME with the same hostname
  - If found AND points to a different Service → FAIL with `Error{code: "dns-conflict", details: {existingRecord, existingTarget}}`
  - If found AND points to SAME Service (or the rename source — verified via the rename trace in `Application.status.endpoints[].lastRenameFrom`) → PASS
- POST result back to Gitea PR status

### 4. Edge cases (integration tests — one Playwright spec per row)

| # | Edge case | Concrete scenario | Expected behavior |
|---|---|---|---|
| EC-1 | Hostname conflict same Org, same App | Endpoint manifest for app `obs-prod` proposes hostname `grafana.acme.hw86.omani.works`; that App's existing endpoint already serves this hostname | PASS — no-op rebase |
| EC-2 | Hostname conflict same Org, different App | App `obs-prod` + App `obs-staging` both propose `grafana.acme.hw86.omani.works` | FAIL (cert-manager-precheck: hostname-already-certified) |
| EC-3 | Hostname conflict cross-Org | App `obs-prod` in Org `acme` + App `obs-prod` in Org `beta` both propose `obs.hw86.omani.works` | FAIL on the second-merged PR (dns-conflict-precheck + cert-manager-precheck both fire) |
| EC-4 | Wildcard hostname | Endpoint hostname `*.acme.hw86.omani.works` | FAIL (kyverno-admission: disallow-wildcard-hostname) |
| EC-5 | IDN homograph attack | Hostname `аpps.acme.hw86.omani.works` (Cyrillic a) | FAIL (kyverno-admission: a new ClusterPolicy `disallow-non-ascii-hostnames` MUST be added in this slot) |
| EC-6 | Public endpoint without TLS | `visibility: public, tls: false` | FAIL (kyverno-admission: require-tls-on-public-endpoints) |
| EC-7 | Internal endpoint on SSO-capable bp without ssoEnabled | bp=grafana, visibility=internal, ssoEnabled=false | FAIL (kyverno-admission: require-sso-on-internal-endpoints) |
| EC-8 | Resource-limits missing | An apps manifest with a container that has no `resources.limits.memory` | FAIL (kyverno-admission: require-resource-limits) |
| EC-9 | Renamed endpoint | Endpoint `grafana` renamed to `observability`; manifest deletes old + adds new with `lastRenameFrom: grafana` | PASS on both prechecks (rename trace honored) |
| EC-10 | Concurrent merge race | Two PRs in different Orgs both propose the same hostname; both opened at the same instant | First-to-merge PASSes, second-to-merge FAILs on auto-rebase + re-run prechecks |
| EC-11 | PowerDNS API down | Pre-check times out querying PowerDNS | FAIL with `Error{code: "precheck-unavailable"}` + 503 in status — DO NOT silently PASS |
| EC-12 | cert-manager Webhook flaking | precheck.go's k8s client returns transient 503 from the API server | retry 3× with 200ms / 600ms / 1.8s backoff; FAIL only on third failure |

## Anti-theater red flags

- ClusterPolicy with `validationFailureAction: audit` (must be `enforce` — audit-only = the policy never blocks, defeats the gate)
- Pre-check Go function that returns `nil` (PASS) when API unreachable — must FAIL closed
- Integration tests that pass without actually opening a PR (mocked Gitea call = theater)
- Each EC tested in isolation without verifying the PR status callback (need to assert the Gitea PR status comment lands)
- Wildcard policy missing the `kind: Endpoint` resource targeting (would only catch Ingress/HTTPRoute, not the new Endpoint CR)
- Missing the EC-9 rename trace handling (would block legitimate operator rename walks in D3)
- Chart version bumped only in Chart.yaml — see `feedback_chart_version_collision_serialize_or_rebase.md` for the lockstep failure mode
