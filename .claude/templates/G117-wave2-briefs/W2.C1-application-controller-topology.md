## Scope (do exactly this, no more, no less)

The application-controller currently reduces every install to a singleton on the primary cluster (per G92 + the topology audit). With W1.B1's typed `Blueprint.spec.topology` shape now on main, the controller must:

1. **Resolve the topology choice** for an `Application` CR:
   - Use `Application.spec.topology` if set and present in `Blueprint.spec.topology.supported[]`
   - Otherwise fall back to `Blueprint.spec.topology.defaults.<multi-region|single-region>` keyed on the Sovereign's region count (locked decision #7: `len(Sovereign.spec.regions) > 1` ⇒ multi-region)
   - Reject with `Application.status.conditions[type=Ready,status=False,reason=InvalidTopology]` if the resolved topology is not in `supported[]`

2. **Fan out HelmReleases** per `Blueprint.spec.topology.perTopology[<choice>].placement.clusters`:
   - One `HelmRelease` per (instance × cluster) pair
   - HR name pattern: `<app-name>-<cluster-short>` (≤ 63 chars; truncate + 5-char suffix hash on overflow)
   - HR labels MUST include `catalyst.openova.io/role=<active|passive|singleton>` and `catalyst.openova.io/topology=<choice>` so observability + continuum can query them
   - HR `spec.kubeConfig.secretRef` follows the G92.1 pivot pattern (already merged in PR #2674) — pull the per-cluster kubeconfig Secret from the management vCluster namespace

3. **State role per HR** in `Application.status.perCluster[]`:
   ```go
   perCluster: []ClusterStatus{
     {Cluster: "mgmt-A", Role: "active",  HR: "grafana-mgmt-a", Status: "Ready"},
     {Cluster: "mgmt-B", Role: "passive", HR: "grafana-mgmt-b", Status: "Ready"},
   }
   ```
   This is what `GET /apps/{id}` returns to power the operator-console drill-down (per `docs/api/catalyst-api-openapi.yaml` `Application.perCluster`).

4. **Honor reconcile order**: active HR Ready ⇒ then passive HRs reconcile. This avoids the cnpg-pair race where the passive replica boots before the active primary has WAL streaming up.
