## Scope (do exactly this, no more, no less)

ADR-0009 says: every Org create triggers a `POST /catalyst/v1/orgs/{org}/iac-bootstrap` that provisions a per-Org Gitea repo + branch protection + Flux subscription + robot-account secret. Currently the controller does nothing; this slot wires the hook.

1. **catalyst-api endpoint** `POST /catalyst/v1/orgs/{org}/iac-bootstrap`:
   - Authenticated by Sovereign-admin OIDC token (NOT tenant-scoped)
   - Idempotent: re-running on an Org that already has its iac repo returns `200 {status: "already-bootstrapped", repoURL: "..."}`
   - On fresh Org: returns `202 {status: "bootstrapping", jobId: "..."}` and runs the bootstrap asynchronously via a `Job` CR
   - Job logic = the steps from ADR-0009 §Decision: (1) Gitea Org create (2) repo create with default tree (3) robot user (4) branch protection (5) `bp-flux-org-subscription` HelmRelease

2. **organization-controller hook**:
   - On Organization CR `metav1.ObjectMeta.CreationTimestamp` reconcile (i.e. first observation), call the new endpoint via in-cluster catalyst-api Service
   - Add `Organization.status.iacBootstrap` substatus: `{state: <Pending|Provisioning|Ready|Failed>, repoURL: string, lastError: string}`
   - Reconcile back to `Provisioning` state if a 5xx is returned (exponential backoff: 30s, 1m, 2m, 4m, 8m capped 5m)
   - On `Ready`: emit `Event{Type: Normal, Reason: IacBootstrapped, Message: "<org>/iac initialized at <repoURL>"}`

3. **Robot user secret rotation** (ADR-0009 §Robot account scope):
   - Secret name: `<org>-iac-bot-token` in the `<org>` namespace
   - ExternalSecret targets OpenBao path `kv/org/<org>/iac-bot-token`
   - Rotation: 90-day TTL; on rotation, controller updates the Gitea robot user's token via `/admin/users/<org>-iac-bot/tokens` then PUTs new value into OpenBao
   - First-bootstrap: controller creates the OpenBao path itself before the ExternalSecret can pull it

4. **Sovereign-admin self-serve cleanup endpoint** `DELETE /catalyst/v1/orgs/{org}/iac-bootstrap`:
   - Used in tests + when an Org is deleted
   - Deletes the Gitea repo, robot user, OpenBao path, ExternalSecret, HelmRelease (in that order)
   - On Org tombstone: organization-controller's finalizer calls this BEFORE removing the finalizer

## Anti-theater red flags

- Bootstrap endpoint that returns 202 but never actually runs the Job (verifier MUST poll the Job to completion)
- Idempotency check using filename instead of Gitea API (filename can be stale; API is ground truth)
- Robot-token rotation that skips updating Gitea — would leave External-Secrets serving a dead token
- Finalizer that deletes the OpenBao path FIRST (correct order: HR → ExternalSecret → Gitea repo → robot → OpenBao; reverse-of-create)
- Calling `tools/bootstrap-org-iac-repo.sh` via `exec.Command` from inside the controller pod (bash script will fail; the controller pod doesn't have `curl`/`jq` baked in by default — re-implement in Go OR add to controller image)
