## Scope (do exactly this, no more, no less)

Per the EPIC body, **G117.0 is "hw86 codification audit + image swap to pure-main"** — i.e. the rear-guard pass that walks every runtime patch ever applied to hw86 during the G91/G112/G113/G117 sprints, finds the merged-main PR that codifies it (or surfaces a gap if no such PR exists), then swaps the running images to a clean tag of `:main`. This slot ships the AUDIT DOC TEMPLATE that the G117.0 author will fill in.

The template is opinionated — it's not blank scaffolding, it's a 12-section structured doc whose only blanks are the live state values + per-row PR numbers. The template itself enumerates the categories of "what gets patched at runtime" so the auditor cannot miss a class.

### Template sections (the order is binding):

1. **Header** — scope statement, audit date, auditor handle, target Sovereign FQDN, baseline `main` SHA used for image swap
2. **Pre-flight enumeration commands** — exact kubectl + curl one-liners the auditor MUST run to dump live state; output captured in the doc
3. **Catalyst-CP container image manifest table** — every Pod in `catalyst-control-plane` namespace, with `image` column + `desired image (main)` column + `swap status` column
4. **bp-* HelmRelease chart-version manifest table** — every HR across every cluster, with `chart version` + `desired chart version (latest published)` + `Chart.yaml on main` columns
5. **Runtime ConfigMap patch table** — every ConfigMap that was edited via `kubectl edit` or `kubectl patch`, with `name` + `namespace` + `diff vs chart-rendered` + `codifying PR` columns
6. **Runtime Secret table** — every Secret that was created or mutated manually (not via External-Secrets), with `name` + `namespace` + `source-of-truth (chart template / ES / manual)` + `codifying PR` columns
7. **CRD patch table** — every CR (CustomResource) that was edited via `kubectl edit` after Flux applied it, with reconcile-drift detection
8. **In-cluster kubectl exec commands run** — every shell session into a Pod (per session log), with `pod` + `cmd` + `purpose` + `codifying PR or N/A`
9. **PR cross-reference table** — for every row in sections 3-8, the codifying PR number; gaps surfaced explicitly as `❌ NO CODIFYING PR — file new TBD`
10. **Image swap procedure** — exact ordered list of `kubectl set image` commands that flip each Pod from its currently-running image to the corresponding `:main` tag; rollback procedure in case of post-swap regression
11. **Self-verification curl probes** — the four mandatory probes that must return 2xx (Set-Cookie shape for catalyst_session + 4-hop SSO chain for Grafana via the G113 IDR fix); failure here BLOCKS the swap
12. **Pass/fail decision tree** — clear yes/no flowchart: ALL rows codified + ALL probes 2xx ⇒ PASS; ANY row missing codification ⇒ HOLD and dispatch a follow-up codification PR before swap

### Template format

Markdown table-heavy. Each table has clear column headers. Each section opens with a "How to fill this in" paragraph that gives the auditor a copy-pasteable command set.

The doc itself should READ as a checklist — the auditor opens it, runs each command at the top of each section, pastes the output, ticks each row of the resulting table, and when section 12's decision tree resolves PASS, the audit is done.

## Anti-theater red flags

- Sections that say "TODO: add commands later" — the template MUST be COMPLETE
- A "Pass" decision tree path with no explicit "HOLD" path (gaps would slide through)
- Probes that hit only the success path (must also test the Set-Cookie ABSENCE case to confirm the probe distinguishes broken vs working)
- Section 9 (PR cross-reference) without an explicit `❌ NO CODIFYING PR` failure mode — auditor would mark gaps as PASS
- Doc that conflates "image swap" with "PR merge" — these are independent; main can be ahead of the running images
- Missing reference to `feedback_validate_agent_outcomes_no_theater.md` § PR-merge ≠ pillar-shipped principle
