## Scope (do exactly this, no more, no less)

Per locked decision #6: **Tier-3 apps use per-Org KC realm with a "Keycloak OIDC" IdP federated to the `sovereign` realm broker (2-hop)**. Today only the sovereign realm exists. This slot:

1. **bp-keycloak template** — add `platform/keycloak/chart/templates/configmap-tenant-realm.yaml`:
   - Renders one ConfigMap per Org from `.Values.tenantRealms[]`
   - ConfigMap content = a complete realm-config JSON for KC import:
     - `realm: "<org-slug>"`
     - `displayName: "<Org Display Name>"`
     - `enabled: true`
     - `identityProviders[]` with ONE entry: `{alias: "sovereign-broker", providerId: "keycloak-oidc", config: {authorizationUrl: "https://auth.<sov>/realms/sovereign/protocol/openid-connect/auth", tokenUrl: "https://auth.<sov>/realms/sovereign/protocol/openid-connect/token", userInfoUrl: "https://auth.<sov>/realms/sovereign/protocol/openid-connect/userinfo", clientId: "<org-slug>-broker", clientSecret: "${TENANT_BROKER_SECRET}", defaultScope: "openid profile email groups"}}`
     - `authenticationFlows[]` with the IDR + defaultProvider pattern from PR #2730 — copy verbatim from `configmap-sovereign-realm.yaml`, replacing `catalyst-pin` IdP with `sovereign-broker`
     - `clientScopes[]` with `groups` scope (per the G91 manual recovery procedure)
     - `clients[]` empty — Tier-3 app clients are added via the bp-sso-bridge reconciler

2. **bp-sso-bridge reconciler extension** — on `Environment` CR create (or first reconcile after `kc-realm` not present):
   - Generate a 32-char random `TENANT_BROKER_SECRET`
   - Write it to OpenBao at `kv/org/<org>/keycloak/sovereign-broker-secret`
   - Wait for ExternalSecret in `keycloak` namespace to materialize a Secret with that value
   - Call KC API `POST /admin/realms` with the rendered realm JSON (Helm subchart already imports via realm-import; this controller-side path is for in-cluster Org-add WITHOUT a Helm upgrade)
   - On `sovereign` realm: register a `keycloak-oidc` Client with redirect URI `https://auth.<sov>/realms/<org>/broker/sovereign-broker/endpoint` and `clientId: <org>-broker`
   - Wait for KC `realm.exists` probe → True before proceeding to per-app SSO Secret creation

3. **2-hop validation**:
   - User opens `https://chat.<org>.<sov>/`
   - LibreChat redirects to `https://auth.<sov>/realms/<org>/protocol/openid-connect/auth` (hop 1 — into Org realm)
   - Org realm's IDR auto-redirects via `defaultProvider=sovereign-broker` to `https://auth.<sov>/realms/sovereign/protocol/openid-connect/auth?kc_idp_hint=catalyst-pin` (hop 2 — into Sovereign realm)
   - Sovereign realm's IDR auto-redirects via `defaultProvider=catalyst-pin` to the Catalyst-pin client and silent-SSO completes
   - End state: user has session in BOTH realms (sovereign + org), LibreChat receives id_token with `aud=librechat`, `iss=https://auth.<sov>/realms/<org>`

4. **Cross-Org isolation invariant**:
   - User logged in via Org-A realm cannot exchange their token for an Org-B-scoped one
   - Verifier MUST attempt to use Org-A's id_token against Org-B's LibreChat → expect 403
