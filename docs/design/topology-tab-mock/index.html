Key design decisions (annotated)

  1. 1One matrix, two readers. The Declared topology card and the Change-placement editor both read the component's perTopology[mode] contract from the same docs/topology-matrix.md source. The editor's per-mode helper text is produced by describeModeForComponent(mode, topology) — it is derived, never hardcoded. The old generic describeMode('active-passive') = "…backup-restore" string is dead.
  2. 2openbao active-passive now reads identically in both places: raft · async replication; raft-transition switchover (RTO 60s / RPO 30s) — a warm standby holding live KV via stretched raft, NOT "cold/warm backup-restore". The card said this all along; the editor now agrees.
  3. 3Declared vs Observed is explicit. The card shows the build-time mandate; the Observed strip shows what's actually built on this Sovereign read from the live Continuum / cnpg-pair record. When the mandate is declared but unbuilt (openbao today: no DR pair), Effective class = singleton (DEGRADED — active-passive mandate unbuilt) with a clear "what's needed" line. No green badge over a phantom pair.
  4. 4The editor can't offer a mode the component doesn't support. Options are gated on topology.supported[]; unsupported modes render disabled. Region roles (active / passive) are previewed inline from the selected mode's placement.roles.
  5. 5Preview → Apply is honest about the commit. Preview renders the exact per-region HelmRelease manifests; Apply explains it writes spec.placement on the Application CR → the application-controller fans out the per-region HelmReleases. No silent magic.
