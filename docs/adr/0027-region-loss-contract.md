# ADR-0027 — Region-loss contract: recovery point and recovery time per data class, a follower Git server with its own database, promotion of the writer by one commit fenced by a lease outside both regions

Status: Accepted
Date: 2026-11-24
Unfreezes: topology-continuum
Unfreezes: application-controller
Unfreezes: topology-region-git-layout
Unfreezes: topology-journeys

Written by work package CTL-800. It states what a Sovereign of two regions keeps, and how fast it recovers, when one region is lost and the other survives. It decides decisions R1 to R10: the numbers per data class, how the follower region gets its copy of Git (after lab test CTL-055, `docs/ledger/plan/spikes/CTL-055.md`), the lease that fences the writer, how a surviving region becomes the writer, and what this does to the bucket `dr-leases`, lock stage `topology`, per-Application DNS and the mesh loop of the API. It settles the two limits that ADR-0015 decision D8 left open: the loss of the writer region, and the database pair shared-pg, which D8 excluded because it holds the Git server's database. The loss of both regions stays the subject of ADR-0036. The four `Unfreezes:` lines are explained under "What the Unfreezes lines permit".

Terms used here:

- **Writer region**: the region whose Git server accepts commits and whose controllers and API run (ADR-0021). Every other region is a **follower region**.
- **Writer lease**: the lease, held outside both regions, that names the writer region (R3).
- **Region loss**: a region whose observations stop answering for longer than `spec.transition.regionLossSeconds` of its Continuum (ADR-0015 D8).

## Context

Measured on `main` at commit `2c6c25e1c`, on 2026-11-24.

- Each region runs its own Git server with its own repository disk. On a Sovereign of two regions both Git servers use one database: the database pair shared-pg, reached through its write alias `shared-pg-mesh-rw` (`infra/providers/_shared/cloudinit-control-plane.tftpl`, `clusters/_template/bootstrap-kit/10-gitea.yaml`). When the writer region is lost, the follower's Git server loses its database with it.
- The follower's copy of Git comes from a CronJob that runs every minute, pulls each repository from the writer and force-pushes it into the follower's Git server (`clusters/_template/sovereign-region/multi-region-follower/git-sync-cronjob.yaml`). It is an entry of the polling allow-list `scripts/baselines/polling.json`, "kept until the follower region's Git has its own database".
- Lab test CTL-055 ran Gitea 1.22.3, the version the platform pins, with two Git servers on one database. The push mirror with sync on commit carried 10 of 10 commits in each of three runs, each in 2.7 to 3.6 seconds. It needs `[migrations] ALLOWED_DOMAINS` naming the follower. A repository must exist on the follower before its mirror is created. The mirror row's `last_error` is not a health signal. Pull-request refs are not copied. On promotion each mirror must be created again in the other direction.
- ADR-0015 decision D8: the Continuum moves the Primary of a group only by commits to Git. The lease of one transition is a file in Git (`core/controllers/continuum/internal/transition/lease.go`). A region that stops answering for `regionLossSeconds` (default 300) is lost, and with `autoPromoteOnRegionLoss: true` (default false) the survivor commits the move without a demotion token (`products/continuum/chart/crds/continuum.yaml`). When the lost region holds the writer, no region can commit, and the group reports Blocked.
- The writer region is a constant of the first boot. The kit slot of the platform chart is suspended outside the primary region (`SECONDARY_HR_SUSPEND` in `clusters/_template/bootstrap-kit/13-bp-catalyst-platform.yaml`), and the follower overlay reads `SOVEREIGN_WRITER_REGION_ID`.
- The legacy auto-promoters: `platform/postgres/chart/templates/dr-promoter.yaml` for the shared-pg instances and `platform/cnpg-pair/chart/templates/dr-promoter.yaml`, each with a `dr-failback.yaml` beside it. Four templates, 4,956 lines. Each is a Deployment in the follower region that probes the peer over the mesh, patches its own region's HelmRelease and then suspends it. Nothing fences two regions against each other. Each holds an entry of the polling allow-list, and CTL-810 deletes the four.
- The lease-witness Worker of the Continuum, `products/continuum/cloudflare-worker`, with its module `infra/cloudflare-worker-leases`, serves `GET`, `PUT` and `DELETE` on `/lease/<slot>`: compare-and-swap on a generation, expiry stamped by the Worker, and release only by the holder. Its Go client was deleted with ADR-0015 D8, so nothing calls it today. FND-170 deletes it unless record 0027 keeps it.
- The JetStream bucket `dr-leases` (`platform/nats-jetstream/chart/templates/kv-buckets.yaml`) has no reader and no writer in Go. CTL-300 kept it for record 0027 to decide.
- Lock stage `topology` covers the kinds Continuum and CNPGPair and is at `audit` (`products/catalyst/chart/values.yaml`, `scripts/baselines/lock-stages.json`). The one writer of these kinds outside Flux in the tree is the Application controller: it deletes the per-Application Continuum `dr-<app>` of the time before D8 (`core/controllers/application/internal/controller/continuum.go`, `core/controllers/application/internal/controller/platform_region_files.go`), and its role holds write verbs on `continuums` (`core/controllers/application/deploy/rbac.yaml`).
- No per-Application DNS record is written. Step J3.5 of the acceptance suite (`tests/acceptance/sovereign/internal/suite/journeys.go`) passes when the name of the Application resolves to the shared ingress, or only to addresses of the new Primary. NET-200 renders `ifportup` records for the wildcard and the apex of the Sovereign through the values `geoFailover.records` of bp-powerdns and its hook (`platform/powerdns/chart/templates/zone-bootstrap-job.yaml`).
- The mesh loop, `products/catalyst/bootstrap/api/internal/handler/clustermesh.go` (4,138 lines), runs in the API that provisioned the Sovereign. NET-140 deletes the establishment of the mesh from it, and SEC-238 deletes its copies of Secret objects between regions.

## Decision

| # | Decision |
|---|---|
| R1 | **The numbers.** One region is lost and the other survives. Recovery time is counted from the loss. Git: at most 60 seconds of commits to a default branch are lost; the survivor accepts commits within 10 minutes. Database pair at `dataDurability: required` (ADR-0004): nothing is lost; at another durability, what the replica had not received. Its survivor is writable within 15 minutes. OpenBao: a shared value whose write to the peer's store returned is not lost; each region serves its own store, so recovery takes no time (ADR-0018 S14). etcd: it is not copied between regions, and the survivor's etcd is complete for its own region; a rebuilt region comes from Git and from the copies of ADR-0036. DNS of an Application: the survivor's edge answers within 2 minutes (R9). Domain events: a message of the lost region that no consumer had taken is lost. Check CTL-G10 (CTL-820) measures these numbers. |
| R2 | **The follower's Git server has its own database, and the writer pushes to it.** Each region's Git server uses its own database cluster `gitea-pg` in its own region: the own-cluster path that `clusters/_template/bootstrap-kit/10-gitea.yaml` has today, in every region. The writer's Git server pushes every repository to each follower with Gitea's push mirror and sync on commit. For each repository, the repository is first created on each follower's Git server, then the mirror on the writer. Every creation of a repository does both, and a one-time backfill does both for the repositories that exist. The writer's Git server gets `[migrations] ALLOWED_DOMAINS` with the follower's Git host; `ALLOW_LOCALNETWORKS` stays off. Health is the comparison of the default-branch heads of writer and follower. The mesh part, with area NET: the writer region gets a stub Service of each follower's Git server and the egress rule to it, as the follower has for the writer today. The one-minute job and its polling entry are deleted. A running Sovereign moves the writer's Git database out of shared-pg once; the follower's database starts empty and the backfill fills it. |
| R3 | **The writer lease is held by the lease-witness Worker.** One slot per Sovereign, `<fqdn>/writer`, held by a region id, with a time to live of 60 seconds, renewed every 20 seconds. A region acts as the writer only while it holds the lease: its controllers commit, its API accepts the routes that change intent, and its Git server runs the push mirrors. A holder that cannot renew before expiry stops acting as the writer. The Worker stays, so FND-170 removes nothing. The Continuum controller gets a client of the Worker's contract. The Git lease of one transition (ADR-0015 D8) stays: it orders the commits of one group; the writer lease decides which Git server takes commits at all. |
| R4 | **Promotion is one commit, and region loss is desired state.** The writer region is one value in the fleet repository, read by the kit of every region. It replaces the first-boot constants `SECONDARY_HR_SUSPEND` and `SOVEREIGN_WRITER_REGION_ID`. The platform chart is installed in every region; outside the writer its controllers and API run no replica. Promotion of a surviving region is the commit that sets this value to the survivor, made on the survivor's own Git server. When the writer region is lost and the writer lease has expired, the survivor's Continuum takes the lease with compare-and-swap on its generation. With `autoPromoteOnRegionLoss: true` it then makes the commit itself. With the default false it reports the loss, and the sovereign-admin makes the same commit in Git; the survivor acts on it only once its Continuum holds the lease. There is no approval step besides that commit, no break-glass and no imperative switchover, and the API of the lost region is not needed. |
| R5 | **After promotion every group moves as desired state.** The new writer's Continuum commits the region-loss move of each group whose Primary was in the lost region, backing services first (ADR-0015 D8). With R2, shared-pg holds no Git database any more, so it is delivered from Git like shared-pg-b and shared-pg-c: its kit slot 16a declares the carrier, and the Continuum moves it. This replaces the legacy auto-promoters of shared-pg and of the database pair and their failback templates. CTL-810 deletes them after the promotion package has merged. |
| R6 | **The lost region returns as a follower.** A returning region does not hold the writer lease, so its controllers do not commit and its mirrors do not run. The new writer creates its mirror toward the returned region, and that overwrites the returned region's default branches, including the value of R4. Moving the writer back is a planned move: the same commit while both regions are up, with the lease released by the holder and then taken. |
| R7 | **The bucket `dr-leases` is deleted.** It lives in the JetStream of one region, so it cannot fence one region against the other, and no code uses it. The promotion package deletes it with its values key `catalystStreams.drLeases`. |
| R8 | **Lock stage `topology`.** Region loss and promotion write no Continuum and no CNPGPair outside Git, and no break-glass identity takes part in them. The promotion package removes the Application controller's deletes of the per-Application Continuum of the time before D8 and its write verbs on `continuums`. The stage then moves to `deny` by a stage package of the form of CTL-264: at zero in the gate records of two consecutive release trains, and never back (ADR-0021 C6). |
| R9 | **Per-Application DNS follows the Primary.** For each name of an Application placed in more than one region there is one item of the shape of `geoFailover.records` that NET-200 brings: `hostname` the name, `regions` the Primary first and then the Application's other regions in placement order, `ttl` 60, `probePort` 443. It renders as `<name> 60 IN LUA A "ifportup(443, {{'<edge address of the Primary>'}, {'<edge address of the next region>'}})"`. The first group with a live address answers, so a lost edge drops out without a commit, and a planned move changes the order. The Application controller writes the items into one file of the fleet repository, ordered by the Primary that the region files name, and the kit slot of bp-powerdns reads it through `valuesFrom`; the hook of bp-powerdns writes the records. Step J3.5 changes with it: for an Application that has an item, the pass through the shared ingress is removed. The promotion package implements this. |
| R10 | **The mesh loop of the API.** Region loss and promotion need no call from the API that provisioned the Sovereign and no kubeconfig of a lost region. What remains of `clustermesh.go` after NET-140 and SEC-238 is work of the first installation; a promotion neither runs it nor waits for it, and nothing of this contract is added to it. |

## What is open

1. **The writer lease when the Worker cannot be reached.** A holder that cannot renew stops after one time to live (R3). While neither region reaches the Worker, no region is the writer: no change of intent is accepted and nothing is promoted, while Applications keep serving. Whether a second witness or an override by the sovereign-admin is added is not decided here.
2. **What is lost between the last mirror push and the loss.** Commits that the lost writer accepted after its last mirror push to the survivor are not on the survivor, and R6 overwrites them when the region returns. Whether they are kept for review before that overwrite is not decided here. Pull requests, their refs and every other row of the writer's Git database are not copied; a pull request that is open at the loss is lost (lab test CTL-055, point 6).
3. **Writes that bypass the platform.** The writer lease stops the platform's own writers. It does not make a Git server read-only, so a person who commits directly on the old writer's Git server during a partition writes a commit that R6 later overwrites.

## Alternatives rejected

**R2.** (a) Keep the one-minute job: up to a minute of commits lost, and the follower still depends on the writer region's database. (b) The push mirror on one shared database, as lab test CTL-055 ran it: the follower's Git server loses its database with the writer region, so it can never become the writer. (c) A database pair for Git across the regions: the Git server would be writable only after a database promotion, which needs a commit, which needs a writable Git server.

**R3.** (a) The Git lease file of D8: it lives on the writer's Git server and is lost with it. (b) A Kubernetes Lease: it lives in the etcd of one region. (c) The bucket `dr-leases`: it lives in the JetStream of one region. (d) A vote of the two regions: two members cannot tell a lost peer from a cut link.

**R4.** (a) An approval step through break-glass: a second path beside Git, which ADR-0021 C6 keeps for emergencies by a person, not for a planned contract. (b) An imperative switchover in the API: the API runs in the lost region. (c) Keep the legacy auto-promoters: they decide from probes inside one region with no fence, and they patch and suspend HelmReleases outside Git.

**R9.** (a) The Continuum calls the PowerDNS API: ADR-0015 D8 forbids it. (b) The wildcard record alone: it follows the control-plane region, not an Application's Primary.

## Consequences

- Until the two packages of R2 and R4 have merged, the loss of the writer region still leaves every group Blocked, and the legacy promoters stay. CTL-810 waits for the promotion package.
- The API keeps its flat files in one region until ADR-0021 C16. A promoted writer's API starts from Git and from the cluster, without them.
- Every repository is created twice, once on each Git server, so the code that creates repositories gains a caller per follower.

## What the Unfreezes lines permit

Work package FND-120 freezes the topology surface of the stability register, `docs/ledger/stability.yaml`. A pull request that changes a frozen path carries the trailer `Decision: ADR-0027`. The two packages that record 0027 names and that the plan does not hold yet are called the Git copy package (R2) and the promotion package (R3 to R5 and R7 to R9). Record 0027 is cited for these changes only:

| Entry | Work package | The change |
|---|---|---|
| `topology-continuum` | CTL-815 | One Continuum definition file stays of the two copies, and the lockstep script of the two copies is deleted. |
| `topology-continuum`, `application-controller` | CTL-816 | The Continuum observer serves its region's serving verdict at `GET /v1/serving`, with read rights on HTTPRoutes and Services, and the Application controller asks the peer region's observer. |
| `topology-continuum` | the promotion package | The client of the Worker's contract, the writer lease, and the commit of R4 by the survivor's Continuum. |
| `application-controller` | the promotion package | The DNS items of R9, and the removal of the deletes and write verbs of R8. |
| `topology-region-git-layout` | the Git copy package | In the follower overlay the one-minute job is deleted and its comment corrected; the writer region gets a stub Service of each follower's Git server and the egress to it. |
| `topology-region-git-layout` | the promotion package | The region overlays read the writer region from the value of R4. |
| `topology-journeys` | the promotion package | Step J3.5 without the pass through the shared ingress for an Application that has a DNS item. |

CTL-810 changes the charts of the database pairs and the polling allow-list, and CTL-820 adds new files to the acceptance suite. No closed entry of the register holds those paths, so they need no line here.
