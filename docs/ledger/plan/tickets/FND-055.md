# FND-055 — Vulnerability and secret scans, new findings only

## In plain words

**The problem today.** No check looks for known vulnerabilities in the dependencies or for secrets written into the code. A change can add a vulnerable library or a password, and nothing stops it. Old findings would flood a strict check, so none was ever switched on.

**What changes.** Every pull request runs Trivy twice, on the code before and after the change, for known vulnerabilities and for secrets. The pull request fails only when the change adds a finding.

**Done means:**

- A pull request that adds a dependency with a known vulnerability turns red.
- A pull request that adds a secret to a file that Trivy reads for secrets turns red.
- Trivy leaves some files out by its own rules, among them files whose path contains the word test or example, and Markdown files. A secret added there does not turn the pull request red.
- A finding that already exists before the change never fails a pull request.
- A vulnerability published today against an old dependency fails no pull request by itself.
- Trivy is the only scanner, and the check proves on itself, on every run, that a new finding fails it.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Every pull request runs the check `security-scan`. It scans the whole tree with Trivy twice: once at the merge base with `main`, once at the change. Each scan looks for known vulnerabilities in the dependency files (every `go.mod`, every `package-lock.json` and every other file Trivy reads) and for secrets in every file that Trivy's secret scanner reads. Trivy's built-in allow rules leave some paths out, among them paths that contain `test` or `example` and Markdown files. A secret added to such a file does not fail the check. This ticket does not change those rules. The check fails when the change adds a finding that the merge base does not have. An old finding never fails it. Before the real scans, the same job proves on a throw-away tree that a new vulnerability and a new secret fail the comparison and an old one does not. Trivy is the one matcher. The check also carries the trigger for merge groups, so it runs on every merge group once `main` has a merge queue.

```python
#!/usr/bin/env python3
"""scan-baseline.py - a change may add no vulnerability and no secret finding.

The workflow .github/workflows/security-scan.yaml runs Trivy twice on every pull request and
every merge group: once on the merge base with main, once on the change. Trivy is the one
matcher, for vulnerabilities and for secrets. Each run writes a Trivy JSON report. This script
compares the two reports. The merge base is the baseline: there is no stored baseline file.

Usage:

  python3 scripts/scan-baseline.py compare <merge-base report> <change report>
  python3 scripts/scan-baseline.py --self-test

Exit code 0: the change adds no finding. 1: the change adds at least one finding; one line per
new finding. 2: wrong usage, or a report that cannot be read or is not a Trivy JSON report
(schema version 2).

The rules, exactly.

A finding has an identifier.
  vulnerability   the target file, the package name and the vulnerability identifier
                  (Target, PkgName, VulnerabilityID). The installed version is not part of it,
                  so a version change that keeps a known vulnerability adds nothing.
  secret          the target file and the rule identifier (Target, RuleID). The line number is
                  not part of it, so a secret that moves inside its file adds nothing.

Findings are counted per identifier. The change adds a finding when it holds an identifier
more often than the merge base does. A second secret of the same rule in the same file is
therefore new. A finding that the change removes is not reported.

A finding of a file that the change moves or renames is new, because its target changes.

The secret text is never printed: a new secret is named by its file, its line and its rule.

Only the Python standard library is used.
"""
import contextlib
import io
import json
import os
import sys
import tempfile
from collections import Counter

EXIT_OK = 0
EXIT_NEW = 1
EXIT_USAGE = 2


class ReportError(Exception):
    """A report cannot be read, or it is not a Trivy JSON report of schema version 2."""


def load_report(path):
    try:
        with open(path, encoding="utf-8") as fh:
            data = json.load(fh)
    except OSError as exc:
        raise ReportError(f"{path}: cannot be read: {exc.strerror}")
    except ValueError as exc:
        raise ReportError(f"{path}: is not JSON: {exc}")
    return check_report(data, path)


def check_report(data, name):
    if not isinstance(data, dict):
        raise ReportError(f"{name}: is not a Trivy JSON report (the top level is not an object)")
    if data.get("SchemaVersion") != 2:
        raise ReportError(f"{name}: is not a Trivy JSON report of schema version 2")
    results = data.get("Results")
    if results is None:
        results = []
    if not isinstance(results, list):
        raise ReportError(f"{name}: Results is not a list")
    for result in results:
        if not isinstance(result, dict) or not isinstance(result.get("Target"), str):
            raise ReportError(f"{name}: a result has no Target")
    return data


def findings(report):
    """Return a list of (identifier, description) pairs, one per finding."""
    out = []
    for result in report.get("Results") or []:
        target = result["Target"]
        for vuln in result.get("Vulnerabilities") or []:
            ident = ("vulnerability", target, vuln.get("PkgName", ""), vuln.get("VulnerabilityID", ""))
            text = (f"vulnerability {ident[3]} in package {ident[2]} "
                    f"{vuln.get('InstalledVersion', '')}, severity {vuln.get('Severity', '')}, in {target}")
            out.append((ident, text))
        for secret in result.get("Secrets") or []:
            ident = ("secret", target, secret.get("RuleID", ""))
            text = (f"secret of rule {ident[2]} ({secret.get('Title', '')}), "
                    f"severity {secret.get('Severity', '')}, in {target} line {secret.get('StartLine', '')}")
            out.append((ident, text))
    return out


def new_findings(base, head):
    """Return the descriptions of the findings that head adds to base, in a stable order."""
    base_count = Counter(ident for ident, _ in findings(base))
    head_list = findings(head)
    head_count = Counter(ident for ident, _ in head_list)
    out = []
    for ident in sorted(head_count):
        extra = head_count[ident] - base_count.get(ident, 0)
        if extra <= 0:
            continue
        texts = sorted(text for i, text in head_list if i == ident)
        if base_count.get(ident, 0) == 0:
            out.extend(texts)
        else:
            out.append(f"{extra} more than at the merge base: " + "; ".join(texts))
    return out


def compare(base_path, head_path):
    try:
        base = load_report(base_path)
        head = load_report(head_path)
    except ReportError as exc:
        print(f"scan-baseline: {exc}")
        return EXIT_USAGE
    added = new_findings(base, head)
    print(f"scan-baseline: merge base {len(findings(base))} finding(s), "
          f"change {len(findings(head))} finding(s), {len(added)} new")
    for line in added:
        print(f"NEW {line}")
    return EXIT_NEW if added else EXIT_OK

    return {"RuleID": rule, "Title": title, "Severity": "CRITICAL", "StartLine": line, "EndLine": line,
            "Match": "SHOULD-NEVER-BE-PRINTED"}


def _report(*results):
    return {"SchemaVersion": 2, "ArtifactType": "repository", "Results": list(results)}


def _vulns(target, *vulns):
    return {"Target": target, "Class": "lang-pkgs", "Type": "gomod", "Vulnerabilities": list(vulns)}


def _secrets(target, *secrets):

def self_test():
    failures = []
    passed = 0

    def check(ok, name):
        nonlocal passed
        if ok:
            passed += 1
        else:
            failures.append(name)

    for name, base, head, want in CASES:
        got = len(new_findings(check_report(base, "base"), check_report(head, "head")))
        check(got == want, f"{name}: {got} new finding(s), want {want}")

    for name, data in BAD_REPORTS:
        try:
            check_report(data, "bad")
        except ReportError:
            check(True, name)
        else:
            check(False, f"{name}: the report was accepted")

    # The command line, with real files: exit codes 0, 1 and 2, and no secret text printed.
    with tempfile.TemporaryDirectory() as tmp:
        def write(name, data):
            path = os.path.join(tmp, name)
            with open(path, "w", encoding="utf-8") as fh:
                if isinstance(data, str):
                    fh.write(data)
                else:
                    json.dump(data, fh)
            return path

        base_path = write("base.json", BASE)
        head_path = write("head.json", CASES[6][2])
        bad_path = write("bad.json", "not json")
        missing_path = os.path.join(tmp, "missing.json")

        def run(*args):
            buf = io.StringIO()
            with contextlib.redirect_stdout(buf):
                code = main(list(args))
            return code, buf.getvalue()

        code, out = run("compare", base_path, base_path)
        check(code == EXIT_OK, f"compare of a report with itself: exit {code}, want 0")
        code, out = run("compare", base_path, head_path)
        check(code == EXIT_NEW, f"compare with a new finding: exit {code}, want 1")
        check("NEW secret of rule rule-two" in out and "line 9" in out,
              "compare with a new finding: the new secret is not named with its rule and line")
        check("SHOULD-NEVER-BE-PRINTED" not in out, "compare printed the text of a secret")
        code, out = run("compare", bad_path, head_path)
        check(code == EXIT_USAGE, f"compare of a file that is not JSON: exit {code}, want 2")
        code, out = run("compare", base_path, missing_path)
        check(code == EXIT_USAGE, f"compare of a missing file: exit {code}, want 2")
        code, out = run("compare", base_path)
        check(code == EXIT_USAGE, f"compare with one report: exit {code}, want 2")
        code, out = run("record")
        check(code == EXIT_USAGE, f"an unknown command: exit {code}, want 2")

    for name in failures:
        print(f"self-test FAILED: {name}")
    if failures:
        return 1
    print(f"self-test: {passed} cases passed")
    return 0


def main(argv):
    if argv == ["--self-test"]:
        return self_test()
    if len(argv) == 3 and argv[0] == "compare":
        return compare(argv[1], argv[2])
    print("usage: scan-baseline.py compare <merge-base report> <change report> | --self-test")
    return EXIT_USAGE


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

```yaml
# rules leave some paths out, among them paths that contain "test" or
# "example" and Markdown files. scripts/scan-baseline.py compares the two
# reports and fails when the change adds a finding. The merge base is the
# baseline: there is no stored baseline file, and an old finding never fails
# a change.
#
# Both scans use the same Trivy and the same vulnerability database, downloaded
# once per run, so a vulnerability published today counts on both sides and
# fails no change by itself.
#
# Before the real scans, the probe step proves the whole path on a throw-away
# tree: an old finding passes, a new vulnerability and a new secret fail.
#
# There is no path filter: every folder is scanned, on every pull request.

on:
  pull_request:
  merge_group:

permissions:
  contents: read

concurrency:
  group: security-scan-${{ github.ref }}
  cancel-in-progress: true

env:
  TRIVY_VERSION: 0.76.1
  # SHA-256 of trivy_0.76.1_Linux-64bit.tar.gz, from the release's checksums file.
  TRIVY_TARBALL_SHA256: c7cbe3137fb8a48a17574bede3dd6beb16742d1e9772929940fc90082c39d9c0
  TRIVY_NO_PROGRESS: 'true'
  TRIVY_DISABLE_TELEMETRY: 'true'
  TRIVY_SKIP_VERSION_CHECK: 'true'

jobs:
  security-scan:
    name: security-scan
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      # Full history: the merge base with origin/main must be reachable.
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false

      - name: Self-test of the comparison
        run: python3 scripts/scan-baseline.py --self-test

      - name: Install Trivy
        run: |
          set -euo pipefail
          mkdir -p "$RUNNER_TEMP/trivy-bin"
          curl -sSfL -o "$RUNNER_TEMP/trivy.tar.gz" \
            "https://github.com/aquasecurity/trivy/releases/download/v${TRIVY_VERSION}/trivy_${TRIVY_VERSION}_Linux-64bit.tar.gz"
          echo "${TRIVY_TARBALL_SHA256}  $RUNNER_TEMP/trivy.tar.gz" | sha256sum -c -
          tar -xzf "$RUNNER_TEMP/trivy.tar.gz" -C "$RUNNER_TEMP/trivy-bin" trivy
          "$RUNNER_TEMP/trivy-bin/trivy" --version

      # The first Trivy run downloads the vulnerability database. Every later
      # run reuses it with --skip-db-update.
      - name: Probe (an old finding passes, a new vulnerability and a new secret fail)
        run: |
          set -euo pipefail
          trivy="$RUNNER_TEMP/trivy-bin/trivy"
          P="$RUNNER_TEMP/probe"
          mkdir -p "$P/base/old" "$P/head/old" "$P/head/new"
          # golang.org/x/text v0.3.0 has known vulnerabilities. The access key
          # is written in two parts so that this file holds no secret itself.
          for d in "$P/base/old" "$P/head/old" "$P/head/new"; do
            printf 'module probe.invalid/app\n\ngo 1.22\n\nrequire golang.org/x/text v0.3.0\n' > "$d/go.mod"
            printf 'AWS_ACCESS_KEY_ID=%s%s\n' AKIA Q7RZ3MV2NP4KX8WD > "$d/creds.env"
          done
          "$trivy" fs --cache-dir "$RUNNER_TEMP/trivy-cache" --scanners vuln,secret --format json --timeout 20m \
            --output "$P/base.json" "$P/base"
          "$trivy" fs --cache-dir "$RUNNER_TEMP/trivy-cache" --scanners vuln,secret --format json --timeout 20m --skip-db-update \
            --output "$P/head.json" "$P/head"
          # Case 1: the same tree on both sides. Nothing is new.
          if ! python3 scripts/scan-baseline.py compare "$P/head.json" "$P/head.json"; then
            echo "::error::security-scan probe: an old finding failed the comparison"
            exit 1
          fi
          # Case 2: new/ is added. Its vulnerability and its secret are new; old/ is not.
          set +e
          python3 scripts/scan-baseline.py compare "$P/base.json" "$P/head.json" > "$P/out.txt"
          rc=$?
          set -e
          cat "$P/out.txt"
          if [ "$rc" -ne 1 ]; then
            echo "::error::security-scan probe: the new findings did not fail the comparison (exit code ${rc}, want 1)"
            exit 1
          fi
          if ! grep -q '^NEW vulnerability .* golang\.org/x/text .* in new/go\.mod$' "$P/out.txt"; then
            echo "::error::security-scan probe: the new vulnerability was not reported"
            exit 1
          fi
          if ! grep -q '^NEW secret of rule aws-access-key-id .* in new/creds\.env line 1$' "$P/out.txt"; then
            echo "::error::security-scan probe: the new secret was not reported"
            exit 1
          fi
          if grep -q 'old/' "$P/out.txt"; then
            echo "::error::security-scan probe: an old finding was reported as new"
            exit 1
          fi
          echo "probe: 2 cases passed"

      # Two clean trees of tracked files, so that both scans see the same kind
      # of tree: the merge base, and the change.
      - name: Check out the merge base and the change
        run: |
          set -euo pipefail
          base="$(git merge-base origin/main HEAD)"
          echo "merge base: ${base}"
          echo "change: $(git rev-parse HEAD)"
          git worktree add --detach "$RUNNER_TEMP/tree-base" "$base"
          git worktree add --detach "$RUNNER_TEMP/tree-head" HEAD

      - name: Scan the merge base
        run: |
          "$RUNNER_TEMP/trivy-bin/trivy" fs --cache-dir "$RUNNER_TEMP/trivy-cache" --scanners vuln,secret --format json --timeout 20m --skip-db-update \
            --output "$RUNNER_TEMP/base.json" "$RUNNER_TEMP/tree-base"

      - name: Scan the change
        run: |
          "$RUNNER_TEMP/trivy-bin/trivy" fs --cache-dir "$RUNNER_TEMP/trivy-cache" --scanners vuln,secret --format json --timeout 20m --skip-db-update \
            --output "$RUNNER_TEMP/head.json" "$RUNNER_TEMP/tree-head"

      - name: Fail on a new finding
        run: python3 scripts/scan-baseline.py compare "$RUNNER_TEMP/base.json" "$RUNNER_TEMP/head.json"
```
