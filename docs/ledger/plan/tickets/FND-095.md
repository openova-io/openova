# FND-095 — Remove the Sandbox orchestrator, grants and cutover entries

## In plain words

**The problem today.** The Sandbox product was withdrawn, but the organizations service still listens for Sandbox requests, asks for one whenever a cart names the product, and can create Sandbox objects in the cluster. The chart still gives that service and the API server the right to create Sandbox objects, and mounts a cluster token into the service only for this. The cutover chart still lists the retired Sandbox chart in two pivot lists.

**What changes.** The orchestrator, its start-up code, its client and its tests are deleted, and the service no longer asks for a Sandbox. The role grants on Sandbox objects and the token mount of the service are removed, and the cutover chart no longer names the Sandbox chart.

**Done means:**

- The organizations service holds no code that requests, reads or creates a Sandbox object, and it builds and passes all of its tests.
- A test proves that a cart which still names the Sandbox product starts no Sandbox request.
- No role in the platform chart grants access to Sandbox objects, and the organizations service runs without a cluster token.
- The cutover chart's pivot lists and its contract test no longer name the Sandbox chart.
- The list of deleted paths names the three deleted files, so a pull request that brings one back turns red.
- The guard that counts direct cluster writes passes with its lowered baseline.

The rest of this ticket is the exact instruction for the model that does the work.
