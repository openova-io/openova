# SEC-103 — Remove the SealedSecret templates from the guacamole and netbird charts

## In plain words

**The problem today.** The guacamole and netbird charts still carry SealedSecret placeholders with empty encrypted data, and guacamole still has a switch that turns its own client-secret Secret off and brings back that placeholder together with a bootstrap Job. The Sealed Secrets controller is being retired, so these objects can never give a usable Secret, and three Blueprints still declare a dependency on it. The netbird render test also fails on the main branch today, because it still expects a render without image tags to abort while the chart now ships default tags.

**What changes.** The two placeholder templates and the bootstrap Job are deleted, the switch is removed, and the guacamole, k8s-ws-proxy and netbird Blueprints stop depending on Sealed Secrets. The two chart tests lose the cases of the deleted path, and the netbird test checks that the default image tags render.

**Done means:**

- Neither the guacamole chart nor the netbird chart renders a SealedSecret, and the three deleted template files are listed as deleted paths, so a pull request that brings one back turns red.
- In its OpenID sign-in mode the guacamole chart always renders its own client-secret Secret, and no chart value turns it off.
- The guacamole chart renders the same objects as before with its default values, and its chart tests pass.
- The netbird render test passes again and checks that each of its three images renders with the tag that the chart's values file sets.
- The guacamole, k8s-ws-proxy and netbird Blueprints no longer depend on bp-sealed-secrets, and the generated catalogue says the same.

The rest of this ticket is the exact instruction for the model that does the work.
