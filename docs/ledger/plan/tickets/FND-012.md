# FND-012 — Stop the tracker commits

## In plain words

**The problem today.** A scheduled job outside the repository rewrites the status board in the ledger every 15 minutes and pushes the change straight to the main branch. About fourteen thousand such commits exist. The board says that all 41 completion gates are done, which is not true, and its numbers are not the measure the platform uses any more.

**What changes.** The board is replaced by five lines that name the two commands that do give the state: the plan tool and the gate verdict. The scheduled job cannot be stopped from the repository, so the change is made between two of its runs, and the rows it rewrote are gone with the board.

**Done means:**

- The ledger file no longer says that 41 of 41 gates are done.
- The file has five lines and names the plan tool and the gate verdict command.
- The work started right after a run of the scheduled job, or after the job had made no commit for 40 minutes.
- When the pull request was reported ready, no commit had changed the file on the main branch since the branch was last brought up to date.
- In the half hour after the merge the job did not write the old board back.

The rest of this ticket is the exact instruction for the model that does the work.
