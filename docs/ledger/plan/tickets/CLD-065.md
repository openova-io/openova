# CLD-065 — Crossplane 1.20 to 2.4

## In plain words

**The problem today.** The platform installs Crossplane core 1.20.14, the last line of Crossplane 1. The adoption Composition already runs in the form that Crossplane 2 requires, but the core has not taken the step to Crossplane 2, and the provider pin and the Workspace work wait for it.

**What changes.** The Crossplane chart installs core 2.4.3, the highest patch of the 2.4 line, through the same registry route as before. Its chart test expects the new image tag.

**Done means:**

- The Crossplane chart pulls the upstream chart at version 2.4.3.
- Every Crossplane core container image still comes through the registry proxy, now with the tag v2.4.3.
- The chart test fails when the rendered image tag is not v2.4.3 or when an image leaves the proxy route.
- No setting of the chart other than the upstream version changes, so every managed resource kind of a provider stays active by the upstream default.
- The task starts only after the gate check of the Crossplane upgrade has passed on a candidate that carries the 1.20 step and the Composition conversion.
- The gate check of the Crossplane upgrade passes on the first candidate that carries the change.

The rest of this ticket is the exact instruction for the model that does the work.
