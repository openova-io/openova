# NET-097 — Gate check NET-G10: a Pod cannot reach the instance metadata address

## In plain words

**The problem today.** Every Sovereign now installs a policy that stops pods from reading the cloud metadata address of their node, and only pods of workloads that are named as exceptions may read it. Nothing proves on a running Sovereign that an ordinary pod is really stopped, so a change that opened the address again would pass every acceptance run.

**What changes.** The acceptance suite gains a required check that, in every region, dials the metadata address from a short-lived pod without the exception label and from one with it. A run in which an ordinary pod reaches the address fails.

**Done means:**

- In every region the check starts two short-lived pods on the pod network in a namespace of its own, and deletes that namespace at the end, also when a step failed.
- The check fails when the pod without the exception label connects to the metadata address, or is refused there, instead of timing out.
- The check fails when the pod with the exception label cannot connect to the address, because a timeout of the other pod would then prove nothing.
- The check fails when a pod cannot reach the cluster DNS service first, so a pod without a working network never passes.
- The check is required in the list of gate checks, so its failure fails the cloud gate run.
- The tests of the check run on every pull request, need no cluster, and fail when the check or the policy chart drifts from these rules.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Gate check NET-G10 (census block D1.5, a dial from a Pod) proves on a running Sovereign what packages NET-095 and NET-096 built: the cluster-wide policy `baseline-deny-metadata` of `bp-network-policies` (kit slot 26) drops every connection from a Pod on the Pod network to the instance metadata address `169.254.169.254`, unless the Pod carries the label `network.openova.io/metadata-access: "true"`. The check is the new file `tests/acceptance/sovereign/internal/suite/check_metadata_blocked.go`. In every region it creates a namespace `net-metadata-<run>` of its own, starts two dial Pods in it with the Dialer that check NET-G06 exports (`check_policy_dials.go`, the image `secProbeImage` of `sec_probe.go`), one without the label and one with it, dials `169.254.169.254` on TCP port 80 from each after a control dial of the cluster DNS service, and deletes the namespace. It passes when the Pod without the label times out and the Pod with the label connects. `docs/ledger/gates.yaml` sets NET-G10 to `required` with its implementation, so the next cloud gate run records it and fails when it fails.

## 3. The model (the law)
1. The check has the identifier `NET-G10`, registers itself with `RegisterCheck` in `init` with the kubectl `kube.Region.Run`, and lives in `check_metadata_blocked.go`. `runner.go` and `registry.go` are not edited.
2. It dials from Pods of the Dialer of `check_policy_dials.go` (`Start`, `Dial`, `Pods`) and judges each dial with `judgeDial` of that file. It adds no image, no dial script and no Pod object of its own. A dial Pod is on the Pod network (no `hostNetwork`: the policy does not select host-network Pods, and then the check would prove nothing), runs as user 65534 with no capability and mounts no token.
3. Per run one identifier `<run>` (lower-case `NewRunID`). In every region of the run the check creates the namespace `net-metadata-<run>` with `kubectl create namespace`, and two dial Pods in it: the source without labels, and the source with the one label `network.openova.io/metadata-access` set to `"true"`, the exception of the policy.
4. The tool of the dial is busybox `nc -z -vv -w 3 <host> <port>` of the image (alpine 3.20, BusyBox 1.36.1), through `dialOutcome`. Exit code 0 is `connected`. Exit code 1 with `Connection refused` in the output is `refused`. Exit code 1 with `timed out` in the output is `timed-out`.
5. Each Pod first dials the cluster DNS service `kube-dns.kube-system.svc.cluster.local` on TCP port 53. When that dial does not connect, the Pod has no working network and its step fails. So a Pod without a network never passes.
6. The Pod without the label passes when its dial of `169.254.169.254:80` times out: the deny drops the packets. It fails when the dial connects (the address is open) and when it is refused: a refused dial reached the address and found no listener, so it proves no deny. This is the rule of check NET-G06 for every `deny` row, and NET-G10 follows it.
7. The Pod with the label passes when its dial of `169.254.169.254:80` connects. It fails otherwise: when something does not answer at the address even for an exempt Pod, the timeout of rule 6 proves nothing. This is the counterpart of the rule of NET-G06 that a `deny` row to a Service needs a ready endpoint.
8. Steps per region, numbered `NET-G10.<n>` in order over the regions: one step that creates the namespace and waits until both Pods are Ready (180 seconds at most, the wait of the Dialer); one step per Pod, only when the first step passed; one step that deletes the namespace with `--wait=false --ignore-not-found` and a time limit of one minute, whenever the namespace was created, also when a step failed. Every step records the block `D1.5` and the region; a dial step also the source, the target, the expectation, the outcome of the control dial, the outcome and the output of `nc`. A run without a region fails.
9. `docs/ledger/gates.yaml`: NET-G10 moves from `not-built` to `required` and gains the line `implementation: tests/acceptance/sovereign/internal/suite/check_metadata_blocked.go`. No other field of any check changes; the title and the assertion text stay as the plan publishes them.
10. The README of the suite and the package comment of `internal/kube` are the lists of the checks that write to a cluster. Both name NET-G10, and the README table of checks gets its row.
11. Nothing is deleted. No new image, no dependency of the module, no `time.Sleep`, no ticker.

+// In every region the check creates a namespace net-metadata-<run> of its own
+// and starts two dial Pods in it with the Dialer of check_policy_dials.go, on
+// the Pod network (never the host network, which the policy does not select):
+// one without the label, and one with the label set to "true", the exception
+// of the policy. Each Pod first dials the cluster DNS service on TCP port 53
+// and then 169.254.169.254 on TCP port 80, with busybox nc. The Pod without
+// the label passes when its dial times out: the deny drops the packets. The
+// Pod with the label passes when its dial connects: something answers at the
+// address, so the timeout of the first Pod is the deny and not an address
+// that answers nobody. A refused dial fails both: it reached the address. A
+// Pod whose dial of the DNS service does not connect has no working network,
+// and its step fails, so a Pod without a network never passes.

+// Per region the check records one step that starts the Pods, one step per
+// Pod, and one step that deletes the namespace if it was created, also when a
+// step failed.

+	metadataBlockedID = "NET-G10"
+	metadataAddress   = "169.254.169.254"

+	MetadataAccessLabel = "network.openova.io/metadata-access"

+func init() { RegisterCheck(metadataBlockedCheck{kubectl: kube.Region.Run}) }

+func (c metadataBlockedCheck) Run(ctx context.Context, cc *CheckContext, rec StepRecorder) error {

+		return errors.New("the run has no region")

+		expect string // the expect of a row of the dial table: deny or allow
+		what   string
