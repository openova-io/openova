# PRD-104 — Consent package

## In plain words

**The problem today.** The open-banking product has a profile with a status code for each consent state, but no code that decides how a consent may move from one state to another. Without one fixed rule, every later part of the product would decide on its own whether, for example, a revoked consent can be authorised again, and the history of a consent could miss a change.

**What changes.** A small Go package of the product holds the one table of allowed consent transitions, keeps one history entry for every transition, and gives the status code the profile names for each state. Its tests try every sequence of events for each of the four consent families.

**Done means:**

- A consent can only move along the six transitions of the table; every other move is refused with one error.
- No sequence of events takes a rejected, revoked, expired or consumed consent to another state, in any of the four families.
- Every accepted event adds exactly one history entry that names the old state, the new state, the actor, the reason and the time; a refused event changes nothing.
- Each state that a family can reach has exactly the status code the profile gives it, and a state the family cannot reach has none.
- The tests of the package run on every pull request that changes the product.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`products/fingate/internal/consent` is a Go package of the open-banking product with no storage and no network. `Next` applies an event to the state of a consent of one family and returns the new state, or the error `ErrTransition` when the transition table does not allow it. `Wire` returns the profile's wire code for a state of a family, or the error `ErrNoCode`. `Record.Apply` changes the state of one consent and appends exactly one history entry, the row that a later package writes to the table `consent_history` in the same database transaction. Its tests try every sequence of events for each of the four consent families and prove two properties: no sequence leaves a terminal state, and every transition appends one history entry. The package is two files, both embedded in this ticket.

## 3. The model (the law)
1. The package is `github.com/openova-io/openova/products/fingate/internal/consent`, in the files `consent.go` (block `consent.go`) and `consent_test.go` (block `consent_test.go`). It imports the standard library and `github.com/openova-io/openova/products/fingate/internal/profile` only. It adds no dependency: `products/fingate/go.mod` and `products/fingate/go.sum` do not change.
2. The states are `awaiting`, `authorised`, `rejected`, `revoked`, `expired` and `consumed`, plus `None` (the empty string), the state before the consent exists. The families are `account-access`, `payment`, `funds-confirmation` and `vrp`, the keys of `consentStatus` in `products/fingate/profiles/rw-4.0.0/profile.yaml`. The events are `create`, `authorise`, `reject`, `revoke`, `expire` and `consume`. The actors are `third-party`, `customer`, `bank` and `system`.
3. The only transitions allowed. Every other pair of state and event, and every other actor, returns `ErrTransition` and changes nothing.

| From | Event | To | Actors | Families |
|---|---|---|---|---|
| none | create | awaiting | third-party | all four |
| awaiting | authorise | authorised | customer | all four |
| awaiting | reject | rejected | customer, system | all four |
| authorised | revoke | revoked | customer, bank, third-party | account-access, funds-confirmation, vrp |
| authorised | expire | expired | system | account-access, funds-confirmation, vrp |
| authorised | consume | consumed | system | payment |

4. `rejected`, `revoked`, `expired` and `consumed` are terminal: they have no exit. The system rejects a consent that is not authorised within the realm's request lifetime. The system expires a consent on read, when its `expires_at` has passed, never by a timer. The system consumes a payment consent when its payment was submitted. A family can reach exactly the states that the profile gives a code for that family: `revoked` and `expired` only for the three families other than `payment`, `consumed` only for `payment`.
5. The exported interface: `Next(family Family, from State, event Event) (State, error)`; `Wire(p profile.Profile, family Family, s State) (string, error)`, which returns `p.ConsentStatus[family][state]` or `ErrNoCode`; `Families() []Family`; `Terminal(s State) bool`; the type `HistoryEntry` with the fields `Seq`, `From`, `To`, `Actor`, `Reason` and `At`, the columns `seq`, `from_state`, `to_state`, `actor`, `reason` and `at` of the table `consent_history`; the type `Record` with `Family`, `State` and `History`; and `(*Record).Apply(event Event, actor Actor, reason string, at time.Time) error`. On success `Apply` sets the new state and appends one entry whose `Seq` is one above the `Seq` of the last entry, or 1 when `History` is empty.
6. The tests prove the two consent properties for every family: `TestPropertyTerminalHasNoExit` tries every sequence of up to six events from no consent and fails if an event leaves a terminal state; `TestPropertyEveryTransitionAppendsHistory` tries every sequence of up to four pairs of event and actor and fails unless each accepted pair appends exactly one entry that names the transition and each refused pair changes nothing. Both run one subtest per family. `TestNextTable` checks `Next` for every family, state and event against the table of law 3 written out a second time. `TestWireRW400` loads the profile `rw-4.0.0` and checks each code, and that the states a family can reach are exactly those with a code. `TestFamilies` checks the families against the profile and the terminal states. `TestApplyContinuesSeq` checks the sequence number after an existing entry.
7. Nothing else is added: no database table, no migration, no store, no HTTP route. The store that writes `consent_history` in one transaction with the state is package PRD-501.

// Package consent holds the consent state machine of the open-banking product.
//
// A consent belongs to one family and is in one state. Next applies an event to a state and
// returns the state after it, or ErrTransition when the transition table below does not allow
// it. Wire maps a state to the profile's wire code for the family. Record keeps the state of
// one consent with its history: every accepted event appends exactly one history entry, the
// row that is written to the table consent_history in the same transaction as the state.
//
// The only transitions allowed:
//
//	from        event      to          actors                         families
//	(none)      create     awaiting    third-party                    all four
//	awaiting    authorise  authorised  customer                       all four
//	awaiting    reject     rejected    customer, system               all four
//	authorised  revoke     revoked     customer, bank, third-party    account-access, funds-confirmation, vrp
//	authorised  expire     expired     system                         account-access, funds-confirmation, vrp
//	authorised  consume    consumed    system                         payment
//
// The states rejected, revoked, expired and consumed have no exit. The system rejects a
// consent that is not authorised within the realm's request lifetime. The system expires a
// consent when its expires_at has passed; this is evaluated on read, never by a timer. The
// system consumes a payment consent when its payment was submitted.
package consent

import (
	"errors"
	"fmt"
	"slices"
	"time"

	"github.com/openova-io/openova/products/fingate/internal/profile"
)

// State is the internal state of a consent.
type State string

// The states of a consent. None is the state before the consent exists: only Create applies to it.
const (
	None       State = ""
	Awaiting   State = "awaiting"
	Authorised State = "authorised"
	Rejected   State = "rejected"
	Revoked    State = "revoked"
	Expired    State = "expired"
	Consumed   State = "consumed"
)

// Family is the family of a consent. Its value is the key of the family in the profile's consentStatus.
type Family string

// The four consent families.
const (
	AccountAccess     Family = "account-access"
	Payment           Family = "payment"
	FundsConfirmation Family = "funds-confirmation"
	VRP               Family = "vrp"
)

// Event is what happens to a consent.
type Event string

// The events.
const (
	Create    Event = "create"    // the third party creates the consent with a client-credentials token
	Authorise Event = "authorise" // the customer decides authorise, through the authorisation server
	Reject    Event = "reject"    // the customer decides reject, or the request lifetime has passed
	Revoke    Event = "revoke"    // the customer, the bank or the third party (delete) revokes the consent
	Expire    Event = "expire"    // expires_at has passed, seen on read
	Consume   Event = "consume"   // the payment of the consent was submitted
)

// Actor is who causes an event.
type Actor string

// The actors.
const (
	ThirdParty Actor = "third-party"
	Customer   Actor = "customer"
	Bank       Actor = "bank"
	System     Actor = "system"
)

// ErrTransition is returned for a transition, or an actor of a transition, that the table does not allow.
var ErrTransition = errors.New("consent: transition not allowed")

// ErrNoCode is returned by Wire when the profile has no wire code for the family and the state.
var ErrNoCode = errors.New("consent: no wire code")

// transition is one row of the table in the package comment.
type transition struct {
	from     State
	event    Event
	to       State
	actors   []Actor
	families []Family
}

var (
	allFamilies = []Family{AccountAccess, Payment, FundsConfirmation, VRP}
	// standing are the families whose authorised consent ends by revocation or expiry.
	standing = []Family{AccountAccess, FundsConfirmation, VRP}

	table = []transition{
		{None, Create, Awaiting, []Actor{ThirdParty}, allFamilies},
		{Awaiting, Authorise, Authorised, []Actor{Customer}, allFamilies},
		{Awaiting, Reject, Rejected, []Actor{Customer, System}, allFamilies},
		{Authorised, Revoke, Revoked, []Actor{Customer, Bank, ThirdParty}, standing},
		{Authorised, Expire, Expired, []Actor{System}, standing},
		{Authorised, Consume, Consumed, []Actor{System}, []Family{Payment}},
	}
)

// Families returns the four consent families.
func Families() []Family {
	return append([]Family(nil), allFamilies...)
}

// Terminal reports whether a state has no exit.
func Terminal(s State) bool {
	return s == Rejected || s == Revoked || s == Expired || s == Consumed
}

// find returns the row of the table for family, from and event, or false.
func find(family Family, from State, event Event) (transition, bool) {
	for _, t := range table {
		if t.from == from && t.event == event && slices.Contains(t.families, family) {
			return t, true
		}
	}
	return transition{}, false
}

// Next returns the state after applying event to a consent of the family, or ErrTransition.
func Next(family Family, from State, event Event) (State, error) {
	t, ok := find(family, from, event)
	if !ok {
		return from, fmt.Errorf("%w: %s on a %s consent in state %q", ErrTransition, event, family, from)
	}
	return t.to, nil
}

// Wire maps an internal state to the profile's code for the family, or ErrNoCode.
func Wire(p profile.Profile, family Family, s State) (string, error) {
	code, ok := p.ConsentStatus[string(family)][string(s)]
	if !ok {
		return "", fmt.Errorf("%w: profile %s has no code for the state %q of the family %q", ErrNoCode, p.ID, s, family)
	}
	return code, nil
}

// HistoryEntry is one accepted transition: one row of the table consent_history.
type HistoryEntry struct {
	Seq    int
	From   State
	To     State
	Actor  Actor
	Reason string
	At     time.Time
}

// Record is one consent: its family, its state and its history, oldest entry first.
type Record struct {
	Family  Family
	State   State
	History []HistoryEntry
}

// Apply applies event, caused by actor, to the record. When the table allows the transition
// and the actor, the state changes and exactly one entry is appended to History; its Seq is one
// above the Seq of the last entry, or 1 when History is empty. Otherwise Apply returns
// ErrTransition and changes nothing.
func (r *Record) Apply(event Event, actor Actor, reason string, at time.Time) error {
	t, ok := find(r.Family, r.State, event)
	if !ok {
		return fmt.Errorf("%w: %s on a %s consent in state %q", ErrTransition, event, r.Family, r.State)
	}
	if !slices.Contains(t.actors, actor) {
		return fmt.Errorf("%w: the actor %q may not %s a %s consent", ErrTransition, actor, event, r.Family)
	}
	seq := 1
	if n := len(r.History); n > 0 {
		seq = r.History[n-1].Seq + 1
	}
	r.History = append(r.History, HistoryEntry{Seq: seq, From: r.State, To: t.to, Actor: actor, Reason: reason, At: at})
	r.State = t.to
	return nil
}

// walkEvents calls visit for every sequence of events of length 1 to depth that starts at
// None, with the state after each prefix as Next leaves it, until Next refuses an event.
// It returns the number of sequences visited.
func walkEvents(t *testing.T, f Family, depth int, visit func(seq []Event, before, after State, err error)) int {
	t.Helper()
	n := 0
	var walk func(seq []Event, s State)
	walk = func(seq []Event, s State) {
		if len(seq) == depth {
			return
		}
		for _, e := range allEvents {
			next := append(append([]Event{}, seq...), e)
			after, err := Next(f, s, e)
			n++
			visit(next, s, after, err)
			if err == nil {
				walk(next, after)
			} else {
				walk(next, s)
			}
		}
	}
	walk(nil, None)
	return n
}

			got, err := Wire(*p, f, s)
			want, has := codes[f][s]
			if has != reachable[s] {
				t.Errorf("%s: state %q reachable %v, has a code %v", f, s, reachable[s], has)
			}
			if !has {
				if !errors.Is(err, ErrNoCode) {
					t.Errorf("Wire(%s, %q) = %q, %v; want ErrNoCode", f, s, got, err)
				}
				continue
			}
			if err != nil || got != want {
				t.Errorf("Wire(%s, %q) = %q, %v; want %q", f, s, got, err, want)
			}
			if other, dup := seen[got]; dup {
				t.Errorf("%s: the states %q and %q have the same code %s", f, other, s, got)
			}
			seen[got] = s
		}
	}
	if _, err := Wire(*p, Family("unknown"), Awaiting); !errors.Is(err, ErrNoCode) {
		t.Errorf("Wire of an unknown family: %v, want ErrNoCode", err)
	}
}
