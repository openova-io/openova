# NET-187 — The Sovereign's DNS addresses answer on port 53 (NET-G19)

## In plain words

**The problem today.** Both regions of the running Sovereign give no answer on port 53: a query over UDP times out and a connection over TCP is closed without a reply. The DNS front door takes the query, but it forwards it to a port that the PowerDNS Service does not offer, so no query ever reaches PowerDNS.

**What changes.** The front door forwards to the DNS port that the PowerDNS Service offers, for UDP and for TCP. A chart test fails when the front door's backend port is one the Service does not declare, and a second test proves that the change applies over the release the Sovereign runs.

**Done means:**

- In the default render and in the host-port render the front door has one backend, port 53 of the PowerDNS Service, and that Service declares port 53 for UDP and for TCP.
- The new chart test fails on the chart as it was before this change, naming the undeclared port 5353.
- The chart applies over the release 1.2.33 as Helm upgrades it: every object becomes the new render, the front door's Pods are replaced node by node, and no Secret gets a new value.
- No chart version line, no Service, no Secret and no NodePort is added or changed.
- Gate check NET-G19 passes in both regions on the next gate pair of a candidate that holds this change (the architect checks this after the merge).

## 2. End goal
The DNS front door of the Sovereign, dnsdist (`platform/powerdns/chart/templates/dnsdist.yaml`, the host-port DaemonSet on every provider pack since NET-185), forwards every query to a port that the PowerDNS Service declares, so a query that reaches port 53 of a region's DNS address gets an answer from PowerDNS. Today its one backend is `POWERDNS_SERVICE_HOST:5353`: the ClusterIP of the Service `powerdns`, which declares only 53 (`dns-udp`, `dns-tcp`, forwarding to the server's own port 5353) and 8081, so no query reaches PowerDNS, dnsdist drops every UDP query and closes every TCP connection, and the required gate check NET-G19 fails in both regions. After this ticket the backend is port 53 of that Service. The new chart test `platform/powerdns/chart/tests/dns-path-render.sh` fails when the backend's port is not one the Service declares for UDP and for TCP, and the new chart test `platform/powerdns/chart/tests/upgrade-over-deployed.sh` runs the case `TestPowerDNSAppliesOverEveryState` of `tools/chart-upgrade`, which proves with Helm's three-way patch that the chart applies over a fresh install and over the release 1.2.33 that both regions run. The comments of kit slot 11, of the chart values and of the dnsdist template that still put the reference cloud on the load-balancer address path are corrected. No NodePort, no Service, no Secret and no chart version line changes.

+func backendLine(t *testing.T, o Object) string {
+	t.Helper()
+	var c corev1.ConfigMap
+	if err := json.Unmarshal(o.JSON, &c); err != nil {
+		t.Fatal(err)
