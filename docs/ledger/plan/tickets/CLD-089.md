# CLD-089 — Local pack: the console in the kit core, its address and an owner session file for the suite

## In plain words

**The problem today.** The local provider pack brings up two clusters, but not the console. The kit does not fit the CPU of one machine, and the console's API may not run on a control-plane machine. Two narrow network rules deny traffic that the console's releases need, because the release that allows this traffic on a Sovereign is not part of the pack. The pack writes no console address and no session, and a wait that runs out of time does not say which release was not ready.

**What changes.** The pack leaves out five releases the console does not need, adds one worker machine in the primary region, adds two network policies that allow what the missing release would allow, and waits for the console. It writes the console address and a file with an owner session. When a wait runs out of time it prints the state of every release, and CI proves that the suite's first two discovery steps pass on it.

**Done means:**

- The reduced kit of the local pack no longer holds the object store, the registry, the DNS server, the secret store and the external-secrets operator, and the kit file is what its generator writes.
- The reduced kit holds one file of the pack with two network policies: every pod of the identity provider's namespace may send anywhere, and every pod of the Git server's namespace may be reached from anywhere.
- On a pull request that changes the pack, the check conformance-local starts two clusters, and in the primary region the console release is Ready and the console's API answers.
- The env file of the pack holds the console address and the path of a file that holds the raw session cookie value of an owner.
- The suite's discovery steps D0.1 and D0.2 pass on the pack in the check conformance-local.
- When a wait of the pack reaches its time limit, the job log names every release that is not Ready, with its reason and message, and every pod that does not run.
- A claim of 1 GiB still binds in each region, and the pack is removed at the end of the run.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket the check `conformance-local` brings the local provider pack up with two regions and the console running in the primary region. `scripts/local-pack.sh up` exits 0 only when the kit core is Ready in both regions, the console release `bp-catalyst-platform` is Ready in the primary region, the Deployment `catalyst-system/catalyst-api` there is available, an owner session has been minted with the console's own signer, and the console answers `/readyz` on the address it writes. The env file under `LOCAL_PACK_DIR` then holds `CONSOLE_URL`, `DEPLOYMENT_ID`, `REGION_A`, `REGION_B` and `SESSION_TOKEN_FILE`; the session file holds the raw `catalyst_session` cookie value. A new command, `scripts/local-pack.sh discovery`, runs the discovery of the suite `tests/acceptance/sovereign` against the pack and passes when its steps D0.1 and D0.2 pass. When `up` reaches a time limit, the job log holds, directly above the error, one line for every HelmRelease and Flux Kustomization that is not Ready, with its reason and message. A person sees the check `conformance-local` green on such a pull request, with the two discovery steps printed as PASS in its log.

## 3. The model (the law)
1. **Five releases leave the reduced kit.** `infra/providers/local/kit-exclude.txt` names `bp-external-secrets`, `bp-harbor`, `bp-openbao`, `bp-powerdns` and `bp-seaweedfs`. The generator `scripts/generators/local-kit.py` then leaves their slot files `08-openbao.yaml`, `11-powerdns.yaml`, `15-external-secrets.yaml`, `18-seaweedfs.yaml` and `19-harbor.yaml` out of `clusters/_template/providers/local/kit/kustomization.yaml`. No release the console needs depends on them (field 4). Every other release of the kit stays, `bp-kyverno` among them (the release `bp-crossplane-claims` needs its policy type).
2. **The kit is closed under `spec.dependsOn`.** Every release that a release of the reduced kit names in `spec.dependsOn` is in the reduced kit. The generator enforces it: it refuses an exclusion that a kept release depends on.
3. **Two policies stand in for the base policy.** The pack does not run the release `bp-plane-isolation` (slot 26b). The file `clusters/_template/providers/local/kit/no-plane-isolation.yaml` is the block `no-plane-isolation.yaml` of field 5, byte for byte. It holds exactly two objects of kind `NetworkPolicy`: `keycloak/local-pack-allow-egress` allows every pod of the namespace `keycloak` to send to every destination; `gitea/local-pack-allow-ingress` allows every source to reach every pod of the namespace `gitea`. They only allow. No other policy is added, and no chart, slot file or region file is changed. Network guard G2 (`scripts/check-network-guards.py`) allows a policy outside the policy chart only in a file that `scripts/network-guards-exceptions.tsv` names with its owner package and its reason; that list gets one line for this file, with the owner `CLD-089`.
4. **The kit file is generated.** `clusters/_template/providers/local/kit/kustomization.yaml` is written by `python3 scripts/generators/local-kit.py` and by nothing else; `--check` passes after the change. It lists 15 slot files, then `local-path.yaml`, then `no-plane-isolation.yaml`.
5. **One worker in the primary region.** `up` gives the region whose role is `primary` one worker machine and every other region none. Reason: slot 13 sets `catalystApi.avoidControlPlane: true`, which keeps `catalyst-api` off every control-plane node; the console runs only in the primary region (a secondary region holds `bp-catalyst-platform` suspended).
6. **Kit core per region.** In every region the six releases `bp-gateway-api`, `bp-cilium`, `bp-cert-manager`, `bp-flux`, `storage-ready`, `local-path` must exist, not be suspended and be `Ready=True`. In the primary region `bp-catalyst-platform` must too. Then `catalyst-system/catalyst-api` must report at least one available replica. All of this within 40 minutes of the end of `tofu apply`.
7. **The wait says what is not Ready.** While `up` waits for the kit core it prints every 2 minutes, for each region whose kit core is not Ready yet, the core releases that are not Ready and, on a second line, every HelmRelease of the region that is not Ready. When the 40 minutes end the wait for the kit core or the wait for `catalyst-api`, `up` prints a state report before it fails: per region every HelmRelease and Flux Kustomization with its Ready status, reason and message, every pod that does not run with its reason, and the last 12 log lines of the first 8 such pods; then a summary of what is neither Ready nor suspended, the primary region last. The report never changes the exit code.
8. **Owner session.** `up` builds the suite's own minter (`sovereign-acceptance mint-session` of `tests/acceptance/sovereign`), reads the signer file of the running `catalyst-api` through `kubectl exec` and pipes it into the minter. The signer never lands in a file on the runner. The issuer is the value of `CATALYST_PIN_ISSUER` of the Deployment, else `https://console.<sovereign_fqdn>`; the email is the `org_email` of the module inputs. The output is written to `LOCAL_PACK_DIR/session` with mode 600 and no newline.
9. **Console address.** `CONSOLE_URL` is `http://127.0.0.1:18080`, a `kubectl port-forward` of the runner to the Service `catalyst-system/catalyst-api` port 8080 of the primary region. It is not a node port and publishes nothing on the machine network. Every path the suite calls on the console (`/api/` and `/catalyst/`) is served by this Service through the console's own route; the console's gateway listener with its certificate is not in the reduced kit (field 11). `down` stops the forward.
10. **Env file.** Exactly five lines, in this order: `CONSOLE_URL=`, `DEPLOYMENT_ID=`, `REGION_A=`, `REGION_B=`, `SESSION_TOKEN_FILE=`.
11. **Discovery.** `scripts/local-pack.sh discovery` runs `sovereign-acceptance discover` with the env file and the two kubeconfigs, at most every 30 seconds for 10 minutes, and passes when the output holds the step lines of D0.1 and D0.2 with `PASS`. The later discovery steps are printed and not judged. It needs two regions.
12. **Workflow.** `.github/workflows/conformance-local.yaml` is the block `conformance-local.yaml` of field 5, byte for byte. Against the file of CLD-087 it adds: the path `tests/acceptance/sovereign/**` to the filter; a step that installs Go from `tests/acceptance/sovereign/go.mod` with `actions/setup-go` pinned by commit (`40f1582b2485089dde7abd97c1529aa768e1baff`, release v5.6.0, the pin `.github/workflows/foundation-gate.yaml` already uses); the step `bash scripts/local-pack.sh discovery` after the step "Up" and before the claim. Time limit, triggers, permissions and the other steps stay.
13. **Script.** `scripts/local-pack.sh` is the block `local-pack.sh` of field 5, byte for byte. Its command `claim`, the kubeconfig files and the exit codes are unchanged.
14. **No node port.** Nothing creates a Service of type NodePort or publishes a port.

# pod_lines: reads `kubectl get pods -A -o json` on stdin; prints one line per pod that does
# not run: a pod whose phase is neither Running nor Succeeded, or a Running pod with a
# container that is not ready. The line holds the phase, the node, the message of the
# scheduler when the pod has no node, and per container that is not ready its waiting or
# terminated reason. At most 60 lines; exit 0.
pod_lines() {
  python3 -c '

try:
    items = json.load(sys.stdin).get("items", [])
except ValueError:
    items = []
out = []
for p in items:
    md, st = p.get("metadata", {}), p.get("status", {})
    phase = st.get("phase", "Unknown")
    cs = (st.get("initContainerStatuses") or []) + (st.get("containerStatuses") or [])
    notes = []
    for c in cs:
        state = c.get("state") or {}
        w, t = state.get("waiting"), state.get("terminated")
        if w:
            notes.append("%s:%s %s" % (c.get("name"), w.get("reason", "Waiting"), " ".join(str(w.get("message", "")).split())[:160]))
        elif t and t.get("exitCode", 0) != 0:
            notes.append("%s:%s exit %s" % (c.get("name"), t.get("reason", "Terminated"), t.get("exitCode")))
        elif not c.get("ready") and not t:
            notes.append("%s:not ready, restarts %s" % (c.get("name"), c.get("restartCount", 0)))
    if phase == "Succeeded" or (phase == "Running" and not notes):
        continue
    sched = [x for x in st.get("conditions", []) if x.get("type") == "PodScheduled" and x.get("status") != "True"]

    print(line.rstrip())

}

# report_state <module inputs> <region code>...: prints the state of every named region for
# the job log. Per region: every HelmRelease and Flux Kustomization, every pod that does not
# run, and the last 12 log lines of the first 8 of those pods. Then a summary, the regions in
# the order given: the HelmReleases and Flux Kustomizations that are neither Ready nor
# suspended, and the first 8 pods that do not run. The caller names the primary region last,
# so the lines directly above the error of a failed run are the summary of that region. It is
# called when a time limit ends a wait, so that the log names what was not Ready and why. It
# never fails.
report_state() {
  local vars=$1 code m pod rest
  local -A flux=() pods=()
  shift
  for code in "$@"; do
    m=$(machine "$vars" "$code")
    flux[$code]=$(kin "$m" get helmrelease,kustomization -A -o json 2> /dev/null || true)
    pods[$code]=$(kin "$m" get pods -A -o json 2> /dev/null | pod_lines || true)
    echo "---- $code: every HelmRelease and Flux Kustomization ----"
    printf '%s' "${flux[$code]}" | state_lines all || true
    echo "---- $code: pods that do not run ----"
    [ -z "${pods[$code]}" ] || echo "${pods[$code]}"
    echo "---- $code: last log lines of at most 8 of these pods ----"
    while read -r pod rest; do
      case "$pod" in */*) ;; *) continue ;; esac
      echo "-- $pod"
      kin "$m" -n "${pod%%/*}" logs "${pod#*/}" --all-containers --tail=12 < /dev/null 2>&1 | cut -c1-300 || true
    done < <(echo "${pods[$code]}" | head -8)
  done
  echo "---- summary: what is not Ready, and the first pods that do not run ----"
  for code in "$@"; do
    { printf '%s' "${flux[$code]}" | state_lines failing || true; echo "${pods[$code]}" | head -8; }       | sed -e '/^$/d' -e "s/^/$code: /"
  done
  echo "---- end of the state report ----"
}

  mapfile -t codes < <(region_codes "$vars")
  pcode=$(primary_code "$vars")

  log "host: kernel modules and inotify limits for the machines"
  for mod in overlay br_netfilter nf_conntrack ip_tables iptable_nat iptable_filter iptable_mangle iptable_raw \
             ip6_tables ip6table_filter ip6table_nat ip6table_mangle xt_socket xt_mark xt_conntrack xt_comment \
             xt_MASQUERADE xt_TPROXY xt_CT ip_set wireguard vxlan sch_ingress cls_bpf; do
    sudo modprobe "$mod" 2> /dev/null || log "module $mod: not loaded"
  done
  sudo sysctl -w net.netfilter.nf_conntrack_max=1048576 fs.inotify.max_user_instances=8192 \
    fs.inotify.max_user_watches=1048576 fs.inotify.max_queued_events=16384 > /dev/null || log "sysctl: limits not raised"

  log "build the session minter of the suite"
  mkdir -p "$DIR/bin"
  (cd "$SUITE" && go build -o "$BIN" ./cmd/sovereign-acceptance) > "$DIR/minter-build.log" 2>&1 \
    || { tail -40 "$DIR/minter-build.log"; die "the suite did not build"; }

  log "tofu init and apply: ${#codes[@]} region(s), deployment $dep, $branch at $commit"
  tofu_run init -input=false > "$DIR/tofu-init.log" 2>&1 || { tail -40 "$DIR/tofu-init.log"; die "tofu init failed"; }
  if ! tofu_run apply -input=false -auto-approve -var-file="$vars" -state="$DIR/terraform.tfstate" > "$DIR/tofu-apply.log" 2>&1; then
    tail -60 "$DIR/tofu-apply.log"
    die "tofu apply failed"
  fi
  t0=$(date +%s)

  declare -A pinned=() done_=()
  while :; do
    local all=yes
    for code in "${codes[@]}"; do
      m=$(machine "$vars" "$code")
      if docker exec "$m" sh -c 'ls /var/lib/catalyst/*-FAILED' > /dev/null 2>&1; then
        docker exec "$m" sh -c 'ls /var/lib/catalyst/*-FAILED; tail -60 /var/log/cloud-init-output.log' || true
        die "$code: the boot template failed"
      fi
      if [ -z "${pinned[$code]:-}" ]; then
        if pin_flux "$m" "$branch" "$commit"; then pinned[$code]=1; log "$code: pull credential set, GitRepository at $commit"; fi
      fi
      if [ -z "${done_[$code]:-}" ] && docker exec "$m" test -f /var/lib/catalyst/cloud-init-complete 2> /dev/null; then
        done_[$code]=1
        log "$code: boot template complete after $(( $(date +%s) - t0 ))s"
      fi
      [ -n "${pinned[$code]:-}" ] && [ -n "${done_[$code]:-}" ] || all=no
    done
    [ "$all" = yes ] && break
    [ $(( $(date +%s) - t0 )) -lt "$MARKER_LIMIT" ] || die "the boot template did not complete within ${MARKER_LIMIT}s"
    sleep 5
  done

  # The regions for the state report: the primary region last.
  local others=()
  for code in "${codes[@]}"; do
    if [ "$code" != "$pcode" ]; then others+=("$code"); fi
  done
  local last=0 notready hrs
  while :; do
    local all=yes
    for code in "${codes[@]}"; do
      m=$(machine "$vars" "$code")
      hrs=$(kin "$m" get helmrelease -A -o json 2> /dev/null || true)
      [ -n "$hrs" ] || hrs='{"items": []}'
      if ! notready=$(printf '%s' "$hrs" | core_judge "$(core_for "$code" "$pcode")"); then
        all=no
        if [ $(( $(date +%s) - last )) -ge 120 ]; then
          log "$code: not Ready: $(echo "$notready" | tr '\n' ';')"
          log "$code: every HelmRelease that is not Ready: $(printf '%s' "$hrs" | state_lines not-ready)"
        fi
      fi
    done
    [ $(( $(date +%s) - last )) -ge 120 ] && last=$(date +%s)
    [ "$all" = yes ] && break
    if [ $(( $(date +%s) - t0 )) -ge "$CORE_LIMIT" ]; then
      report_state "$vars" "${others[@]}" "$pcode"
      die "the kit core was not Ready within ${CORE_LIMIT}s"
    fi
    sleep 15
  done
  log "kit core Ready in every region after $(( $(date +%s) - t0 ))s"

  pm=$(machine "$vars" "$pcode")
  local avail=""
  until [ "${avail:-0}" -ge 1 ] 2> /dev/null; do
    if [ $(( $(date +%s) - t0 )) -ge "$CORE_LIMIT" ]; then
      report_state "$vars" "$pcode"
      die "$pcode: catalyst-system/catalyst-api was not available within ${CORE_LIMIT}s"
    fi
    sleep 10
    avail=$(kin "$pm" -n catalyst-system get deployment catalyst-api -o jsonpath='{.status.availableReplicas}' 2> /dev/null || true)
  done
  log "$pcode: the console's API is available after $(( $(date +%s) - t0 ))s"

  local ip
  for code in "${codes[@]}"; do
    m=$(machine "$vars" "$code")
    ip=$(tofu_run output -state="$DIR/terraform.tfstate" -json control_plane_ips_per_region \
      | python3 -c 'import json,sys; print(json.load(sys.stdin)[sys.argv[1]])' "$code")
    docker exec "$m" cat /etc/rancher/k3s/k3s.yaml | rewrite_kubeconfig "$ip" > "$DIR/$code.kubeconfig"
    chmod 600 "$DIR/$code.kubeconfig"
    kubectl --kubeconfig "$DIR/$code.kubeconfig" --request-timeout=20s get --raw /readyz > /dev/null \
      || die "$code: this host does not reach the API server at $ip:6443"
  done

  local issuer signer jp='{.spec.template.spec.containers[0].env[?(@.name=="%s")].value}' n
  # shellcheck disable=SC2059
  issuer=$(console_issuer "$(kin "$pm" -n catalyst-system get deployment catalyst-api -o jsonpath="$(printf "$jp" CATALYST_PIN_ISSUER)" 2> /dev/null || true)" "$(tfvar "$vars" sovereign_fqdn)")
  # shellcheck disable=SC2059
  signer=$(kin "$pm" -n catalyst-system get deployment catalyst-api -o jsonpath="$(printf "$jp" CATALYST_HANDOVER_SIGNER_PATH)" 2> /dev/null || true)
  signer="${signer:-$SIGNER_DEFAULT}"
  rm -f "$DIR/session"
  for n in 1 2 3 4 5 6; do
    # The signer goes through the pipe only; it is never written to a file here.
    ( umask 077; kin "$pm" -n catalyst-system exec deploy/catalyst-api -- cat "$signer" \
        | "$BIN" mint-session --key - --issuer "$issuer" --email "$(tfvar "$vars" org_email)" > "$DIR/session.new" ) 2> "$DIR/mint.log" \
      && [ -s "$DIR/session.new" ] && { mv "$DIR/session.new" "$DIR/session"; break; }
    rm -f "$DIR/session.new"
    [ "$n" = 6 ] && { cat "$DIR/mint.log"; die "$pcode: the owner session could not be minted with the console's signer"; }
    sleep 10
  done
  chmod 600 "$DIR/session"
  log "$pcode: owner session minted, issuer $issuer"

  local url="http://127.0.0.1:$CONSOLE_PORT" t
  forward_start "$DIR/$pcode.kubeconfig"
  t=$(date +%s)
  until curl -fsS -o /dev/null --max-time 10 "$url/readyz" 2> /dev/null; do
    [ $(( $(date +%s) - t )) -lt 120 ] || { cat "$DIR/console-forward.log"; die "the console does not answer $url/readyz"; }
    sleep 5
    forward_start "$DIR/$pcode.kubeconfig"
  done
  write_env "$DIR/env" "$url" "$dep" "$DIR/session" "${codes[@]}"
  log "up: done; console at $url; kubeconfigs, session and env under $DIR"
}

  while :; do

      --deployment "$DEPLOYMENT_ID" --kubeconfig-a "$DIR/$a.kubeconfig" --kubeconfig-b "$DIR/$b.kubeconfig" \

  done

  log "discovery: D0.1 and D0.2 of the suite pass on the pack"
}

cmd_claim() {

  local code kc ok=yes t
  # shellcheck disable=SC1091
  . "$DIR/env"
  for code in "$REGION_A" "$REGION_B"; do
    [ -n "$code" ] || continue
    kc="$DIR/$code.kubeconfig"
    kubectl --kubeconfig "$kc" apply -f - > /dev/null <<'YAML'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: local-pack-claim
  namespace: default
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 1Gi
---
apiVersion: v1
kind: Pod
metadata:
  name: local-pack-claim
  namespace: default
spec:
  restartPolicy: Never
  containers:
    - name: claim
      image: busybox:1.36
      command: [sh, -c, "echo bound > /data/claim && cat /data/claim"]
      volumeMounts:
        - name: data
          mountPath: /data
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: local-pack-claim
YAML
    t=$(date +%s)
    until kubectl --kubeconfig "$kc" get storageclass,pvc -n default -o json | claim_judge > "$DIR/claim-$code.txt"; do
      if [ $(( $(date +%s) - t )) -ge "$CLAIM_LIMIT" ]; then ok=no; break; fi

    kubectl --kubeconfig "$kc" -n default delete pod/local-pack-claim pvc/local-pack-claim --wait=false > /dev/null || true
  done
  [ "$ok" = yes ] || die "a claim did not bind on the default storage class within ${CLAIM_LIMIT}s"
  log "claim: bound in every region"
}

  expect() { local want=$1 name=$2 got; shift 2; if "$@" > "$t/out" 2>&1; then got=0; else got=$?; fi
    if [ "$got" = "$want" ]; then ok "$name"; else bad "$name (exit $got, want $want)"; cat "$t/out"; fi; }

assert [r["code"] for r in v["regions"]] == ["region-a", "region-b"], v["regions"]

    name, state = a.split("=")
    i = {"metadata": {"name": name}, "spec": {}, "status": {"conditions": [{"type": "Ready", "status": state, "reason": "R"}]}}

print(json.dumps({"items": items}))' "$@"; }
  local all=() c
  for c in $CORE; do all+=("$c=True"); done

  expect 1 "core: a core release absent" core_judge "$CORE" < <(hr "${all[@]:1}")
