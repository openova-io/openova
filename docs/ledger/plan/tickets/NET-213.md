# NET-213 — The console states the region separation

## In plain words

**The problem today.** The console lets a request of two or more regions read as disaster recovery even when its regions share one failure domain. The installed Sovereign records its region separation and a condition that explains it, but no page of the console shows them.

**What changes.** Before anything is provisioned, the provider step of the wizard says whether the regions of the request are separated, and warns when they share one failure domain. The overview page of the Sovereign shows the recorded separation and its explanation, read from the route that already answers for the Sovereign itself.

**Done means:**

- A request of two regions in two cloud regions shows the separation site and no warning on the provider step.
- A request of two regions in one cloud region shows the separation none and the sentence Regions share one failure domain. Not a disaster-recovery configuration.
- A request of one region shows no separation and no warning.
- GET /api/v1/sovereign/self answers regionSeparation and regionSeparationMessage as the Sovereign object of its cluster holds them, and leaves both out, with its other fields unchanged, when the object, its status or the condition is absent or cannot be read.
- The overview page shows the separation and the message when the self answer carries them, and nothing when it does not.
- The API's account may get the Sovereign object sovereign-self and nothing more of that kind.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The sovereign-admin console states the region separation in two places. The provider step of the wizard (`products/catalyst/bootstrap/ui/src/pages/wizard/steps/StepProvider.tsx`) applies the rule of the writer of the Sovereign object (`core/cmd/sovereign-ops/internal/sovereignobject/separation.go`, `Separation`) to the request's own regions: site when every region has its own cloud region, none otherwise and always for fewer than two regions; a request carries no zone, so it gives site or none. Once every region of a request of two or more regions has its cloud region, the step shows "Region separation: site" or "Region separation: none", and with none the notice "Regions share one failure domain. Not a disaster-recovery configuration." The overview page (`products/catalyst/bootstrap/ui/src/pages/sovereign/Dashboard.tsx`) shows the separation and the message of the condition `RegionSeparation`, which `GET /api/v1/sovereign/self` (`products/catalyst/bootstrap/api/internal/sovself`) now reads from the Sovereign object `sovereign-self` of its own cluster and answers as `regionSeparation` and `regionSeparationMessage`. No new route, and no second reader of the object besides this route. A person sees it this way: picking the same cloud region for both regions of a request turns the line on the provider step from site to none with the warning, and the overview page of an installed Sovereign shows what its writer recorded.

## 3. The model (the law)
1. **One rule.** The wizard computes the separation with the writer's rule over the request's cloud regions (every card, the AIR-GAP region included): fewer than two regions is none; all cloud regions different is site; otherwise none. zone needs a zone per region, which a request does not carry. No per-provider copy of the provisioner, no list of providers.
2. **Stated when it is known.** The step states the separation only for two or more regions and only when every region has a cloud region. With none it shows the notice, word for word the message the writer gives the condition for none on two or more regions.
3. **The self route answers what the object holds.** `regionSeparation` is `status.regionSeparation` of the Sovereign object `sovereign-self` (group `catalyst.openova.io`, version `v1alpha1`, resource `sovereigns`, cluster-scoped); `regionSeparationMessage` is the `message` of its condition of type `RegionSeparation`. Each is left out (`omitempty`) when the object does not hold it. No other field changes.
4. **A missing object is not an error, a failed read is.** No object (or no kind installed: not found) answers without both fields and the answer is kept for `CacheTTL`. Any other read error is logged, answers without both fields with every other field as it is, and the answer is not kept, as the package already does for a ConfigMap that cannot be read.
5. **The names are the writer's.** The route reads `sovereign-self` and the condition `RegionSeparation`; `TestSovereignObjectIsTheWriters` compares both and the resource path with the constants of `core/cmd/sovereign-ops/internal/sovereignobject`.
6. **Least right.** The ClusterRole `catalyst-api-cutover-driver` gains one rule: `get` on `sovereigns` of `catalyst.openova.io`, `resourceNames: ["sovereign-self"]`. No list, no watch, no write. The file stays free of Helm directives (it is also read by Kustomize).
7. **One answer in the console.** The overview page reads the self answer under the query key `['sovereign', 'self']`, the key of `useResolvedDeploymentId`, so the console fetches the route once. A 404 (the mothership) or a failed fetch shows nothing.
