# SEC-201 — The birth Job writes a named key and an empty placeholder

## In plain words

**The problem today.** The secrets library's birth Job, the only creator of a value that reaches a pod as a file, always writes its value under the key password and refuses an empty value. A workload whose file is a document under another key, and whose real content is written later by another component, therefore cannot be mounted on a fresh install: the mount fails until that later writer runs. A chart that asks for another key today is not refused either: the library ignores the request and writes a random password.

**What changes.** A file-only value can name the key of its document and can ask for an empty placeholder. The birth Job then creates the document once, empty, under that key; a later writer replaces it, and the Job never writes it again. A value that names neither is written exactly as before.

**Done means:**

- A value that names a key is written under that key and under no other.
- A placeholder is created once, in this region and, when it is shared, in every peer region, as a document whose key holds an empty string.
- After a later writer replaces the placeholder, the birth Job writes nothing to it and succeeds.
- A value that names neither a key nor a placeholder renders the same plan line and is written under the key password, as before.
- A malformed key, a placeholder that is not true or false, a placeholder with a length, and either field on a synced value each fail the render with a message that names it.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A platform chart that uses the secrets library can declare a file-only (tier B, `delivery: mounted`) value whose OpenBao document holds its value under a named key, and can declare that value a placeholder: the birth Job creates the document once, with create-only rights, holding that key with an empty string. The OpenBao CSI provider fails a mount whose path or key is missing and mounts an empty string as an empty file, so a pod that mounts the placeholder becomes Ready on a fresh install before the real content exists. A later writer with create and update rights (SEC-192) replaces the document (AIP-160 for the first consumer); the birth Job reads the path as present and never writes it again. The first consumer is AIP-106 (`mounted/data/axon/sa/axon/model-credential/e1`, key `document`, `sharedAcrossRegions: false`). A value without the new fields is rendered and written exactly as before, and the chart tests prove it.

## 3. The model (the law)
1. A `delivery: mounted` value may set `key` (default `password`), matching `^[A-Za-z0-9][-._A-Za-z0-9]*$`, and `placeholder` (default `false`), a boolean.
2. A plan line keeps its five fields `<path> <length> <symbols> <source> <reach>`; a key other than `password` is a sixth field. A value without `key`, or with `key: password`, renders the five-field line it rendered before.
3. A placeholder renders `<path> 0 0 empty <reach>`; source `empty` is the empty string. A file source is always an absolute path (`/etc/secrets-birth/...`), so `empty` cannot name a file.
4. The birth script writes `{"options":{"cas":0},"data":{"<key>":"<value>"}}`, create-only (cas 0), with the same rights as before: create on `mounted/data/<ns>/*` here and, for a shared value, through the peer trust on every peer. No policy of bp-openbao changes.
5. A placeholder that exists (any version) is read as present: the Job writes nothing to it, logs `present`, and exits 0. Raising the epoch creates a new empty placeholder at the new path.
6. The peer detection reads the fifth field (`all`), in the template and in the script, not the end of the line, so a sixth field does not hide a shared value.
7. Refused at render, each with its message: `key` or `placeholder` on a synced value; an empty or malformed `key`; a `placeholder` that is not a boolean; a placeholder with `length` or `symbols`.
8. No chart consumes the library at this commit; this package adds no consumer. No new Python, no yq in the tests, no change to a live system.
