# NET-096 — Turn the metadata deny on in the kit

## In plain words

**The problem today.** The platform has a policy that stops pods from reading the cloud metadata address of their node, but the bootstrap kit installs the policy chart switched off. So no Sovereign carries the deny, and any pod can read its node's cloud metadata.

**What changes.** The kit installs the policy chart switched on. Every Sovereign gets the one deny of the metadata address, and none of the older default-deny policies that once cut the console off.

**Done means:**

- The kit slot of the network policies asks for the chart switched on, with no other value.
- The chart release that the slot installs contains the metadata deny, and the storage chart release that must read the address carries its exception label.
- Rendered with the values of the slot, the chart installs exactly one object: the deny of the metadata address, which puts no pod under default deny.
- The generated inventory of the kit slots shows the slot switched on, and the catalogue and the placement data are unchanged.
- That a pod on a running Sovereign is really refused is proven by a separate gate check, not by this task.

The rest of this ticket is the exact instruction for the model that does the work.
