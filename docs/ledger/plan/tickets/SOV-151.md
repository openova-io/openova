# SOV-151 — Kit pull Secret names and the hand-over switch read the Sovereign's variables

## In plain words

**The problem today.** Every Sovereign now receives its registry pull Secret name and its hand-over switch in its variables, but the bootstrap kit does not read them. The kit names the pull Secret as fixed text in 65 slot files and takes the hand-over switch from an older kit key, so changing either value in the variables has no effect.

**What changes.** The 65 slot files read the pull Secret name from the variables, with today's name as the default. The two slots that carry the hand-over switch read the contract key first and fall back to the older kit key, so a Sovereign whose variables predate the key behaves as before.

**Done means:**

- Each of the 65 bootstrap-kit slot files that names a pull Secret for its chart source reads the name from REGISTRY_PULL_SECRET, with ghcr-pull as the default.
- Slots 06a and 13 take the hand-over switch from HANDOVER_AUTO and use the kit key FIRE_CUTOVER_ON_HANDOVER only when HANDOVER_AUTO is absent.
- Every root of the kit renders exactly as before, both with the full test values and with the kit keys alone.
- Changing HANDOVER_AUTO or REGISTRY_PULL_SECRET in the test values changes the rendered kit, which shows that the kit really reads them.
- The pull Secret line of the Flux controllers, the chart source lines and every comment are unchanged, and no guard baseline moves.

The rest of this ticket is the exact instruction for the model that does the work.
