# AIP-101 — Axon builds against the pinned kit and gets a test rail

## In plain words

**The problem today.** Axon does not build on main. The agent kit it depends on no longer offers the session interface that Axon's session pool is built on, and two type errors remain in the code that talks to the kit, so no new Axon image can be made. Axon has no tests, and its build runs only after a merge, so nothing caught this before it reached main.

**What changes.** Each request starts its own run of the kit, the shared session pool is gone, and the kit is pinned to one exact release. A first set of unit tests runs with the build on every pull request that changes Axon, and a pull request never publishes an image.

**Done means:**

- Axon compiles with no type error and its unit tests pass, against the agent kit pinned at release 0.3.220.
- No Axon source names the removed session interface, and exactly one Axon source file imports the agent kit.
- A pull request that changes Axon or its build workflow builds and tests Axon, and logs in to no registry, pushes no image and signs nothing.
- The agent-plane guard counts one file that imports the kit and stores 1 as its maximum.
- The deleted session-pool file is on the deletion list, so it cannot come back unnoticed.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. One request of the Claude provider is one kit run: one call of `query({prompt, options})` from `@anthropic-ai/claude-agent-sdk`. No run and no session is shared between requests.
2. The options of a run are exactly: `model` = `resolveModel(<requested model>)`; `systemPrompt` = the caller's `system` messages joined with a blank line, or `You are a helpful assistant.` when there is none, followed by the JSON instruction when `response_format` is `json_object` or `json_schema` (emulation by instruction, `docs/contracts/model-contract.md` section 1.3); `tools: []`; `settingSources: []`; `allowedTools: []`; `permissionMode: "dontAsk"`; `persistSession: false`; `includePartialMessages: true`; `env` = the process environment without `CLAUDECODE`.
3. The prompt of a run (`formatPrompt(messages)`): the content of the one `user` message when the non-system messages are exactly that; otherwise the plain conversation (`User:`, `Assistant:` and `Tool result (<id>):` lines inside `<conversation>`), ending with `Respond to the last User message.` There is no tool-JSON instruction, no stop-sequence hint and no session-boundary marker.
4. `chat` returns the `result` of the run's success message and throws on an error result. `chatStream` yields each `text_delta` of the raw stream events and throws on an error result.
5. Deleted: `src/providers/session-pool.ts`; in `src/providers/claude.ts` `getPool`, `initPool`, `shutdownPool`, `extractText`, `chatV1`, `chatV1Stream`, `ChatV1Options`, `buildV1Prompt`, `buildConversationPrompt`, `toSDKThinking` and the import of `ThinkingConfig` (the thinking and effort plumbing; `thinking`, `effort` and `profile` are not part of the contract, section 1.3); `poolSize` and `AXON_POOL_SIZE` in `src/config.ts`; the pool warm-up, the pool shutdown and the `sessions` field of `GET /stats` in `src/index.ts`; the `useV1` selection and the `chatV1` calls in `src/routes/chat-completions.ts`.
6. The kit is pinned to one exact release, `0.3.220`, in `package.json` and in the root entry of `package-lock.json`. The lock's resolved kit entries do not change.
7. Exactly one file under `products/axon/src/` imports the kit (guard G7d of `scripts/check-agent-plane.py`, stored maximum 1).
8. The publish steps of `Build Axon` (registry login, image push, signing) run only when the event is not `pull_request`.
