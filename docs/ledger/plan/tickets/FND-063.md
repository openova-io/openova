# FND-063 — Release key pair: platform images carry a key signature

## In plain words

**The problem today.** Every platform image and chart is signed only keyless today. A keyless signature is checked against public signing services, and a Sovereign that cannot reach the internet cannot check it. The platform has no release key of its own, so nothing inside a Sovereign can prove that an image was built by this repository.

**What changes.** The repository gets a release key pair. On main the shared signing action adds a second signature made with that key, without the public log, and checks it against the public half that is kept in the repository. The keyless signature stays as it is.

**Done means:**

- The public half of the release key is the file keys/release-cosign.pub, and the private half is a secret of the repository that no file holds.
- A build on main signs its image or chart twice, keyless and with the release key, and checks the key signature against keys/release-cosign.pub without the public log.
- A build that runs without the key, or on another branch, signs keyless as before and says so in its log.
- Every workflow that calls the shared signing action passes the release key, and a guard turns a pull request red when one does not.
- After the merge, the first build of each changed workflow on main shows the release-key signature verified.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The repository holds the public half of a release key pair in `keys/release-cosign.pub`. The private half and its password are the repository secrets `RELEASE_COSIGN_KEY` and `RELEASE_COSIGN_PASSWORD`; no file holds them. The shared action `.github/actions/sign-and-attest` keeps everything it does today (keyless signature, bill of materials, keyless verification) and, on `refs/heads/main`, adds a signature made with the release key, without a transparency-log upload, and verifies it against `keys/release-cosign.pub` with the log check off. Every one of the 33 calls of the action, in 32 workflows, passes the two secrets as inputs. Where the key is empty, or the run is on another ref, the action signs keyless only and prints a warning or a notice that says so. The guard `scripts/check-builds-sign.py` gains a rule that fails a call of the action that does not pass the two secrets, and a new test runs the action's signing step with stand-in commands. After the merge a person sees, in the first run on `main` of each changed build, the log line `... is signed, attested and verified, and carries the release-key signature`.

## 3. The model (the law)
1. The release key pair is an ECDSA P-256 key pair made by cosign v2.4.1 (`cosign generate-key-pair`). Its public half is the file `keys/release-cosign.pub`, the PEM block of a P-256 public key. It is the only file under `keys/`. Its private half (an encrypted cosign private key) is the repository secret `RELEASE_COSIGN_KEY`; the password of that private half is the repository secret `RELEASE_COSIGN_PASSWORD`. No file of the repository holds either secret, and this ticket holds no key material. The architect makes the key pair and the two secrets before this ticket starts (field 9, the architect's step "release key pair").
2. A composite action cannot read a secret. Every step that uses `./.github/actions/sign-and-attest` therefore passes `release-key: ${{ secrets.RELEASE_COSIGN_KEY }}` and `release-key-password: ${{ secrets.RELEASE_COSIGN_PASSWORD }}`, the same way the callers of `.github/actions/deploy-bump` pass `secrets.RELEASE_WRITER_KEY` as `release-writer-key`.
3. The secret is used only on main. GitHub gives a repository secret to the workflow runs of every branch of the repository, so the action checks the ref itself: it uses the key only when `GITHUB_REF` is `refs/heads/main`. On another ref it prints the notice `::notice::sign-and-attest: the release key is used on refs/heads/main only ...` and signs keyless only. With an empty key it prints the warning `::warning::sign-and-attest: no release key was passed ...` and signs keyless only.
4. On main with the key, the step "Sign, attest and verify" runs these cosign commands, in this order, and fails when one fails:
   `cosign sign --yes <image>` (keyless, as today);
   `cosign sign --yes --key env://RELEASE_KEY --tlog-upload=false <image>` with `COSIGN_PASSWORD` set to the password;
   `cosign attest --yes --type spdxjson --predicate <bill of materials> <image>` (keyless, as today);
   the two keyless verifications of today;
   `cosign verify --key <workspace>/keys/release-cosign.pub --insecure-ignore-tlog=true <image>`.
   `<image>` is `<ref>@<digest>`. When the key is passed on main but `keys/release-cosign.pub` is missing or empty, the step fails before it signs anything.
5. The action gains two optional inputs, `release-key` and `release-key-password`, each with the default empty. The inputs `ref`, `digest` and `sbom-source` do not change. The step "Sign, attest and verify" reads them as the environment variables `RELEASE_KEY` and `RELEASE_KEY_PASSWORD`, and the public key path as `RELEASE_PUBLIC_KEY`, `${{ github.workspace }}/keys/release-cosign.pub`.
6. The bill of materials stays attested keyless only. The key signs the image or chart itself.
7. The guard `scripts/check-builds-sign.py` gains rule 7: a step that uses the action passes exactly `${{ secrets.RELEASE_COSIGN_KEY }}` as `release-key` and exactly `${{ secrets.RELEASE_COSIGN_PASSWORD }}` as `release-key-password`. Its self-test gains three broken trees for rule 7 (a call without the key, a call without the password, a call that passes another secret); it then reports 20 broken trees. Rules 1 to 6 do not change.
8. The new test `.github/actions/sign-and-attest/test-sign.sh` reads the step "Sign, attest and verify" out of the action and runs it with stand-in `cosign` and `syft` commands in six cases (with the key on main; without the key; on another ref; without the public key file; a failing key verification; a failing key signature) and checks the exact cosign calls of each.
9. Nothing else changes in the 32 workflows: two input lines are added to each call of the action, after its last input, and no other line changes. No trigger, permission, push, bump or release-writer step changes.
10. This ticket changes the calls of the action that exist when it starts: 33 calls in 32 workflows. A package that adds a call of the action comes after this ticket and passes the two secrets in its own call. Rule 7 of the guard fails such a package when it does not. This ticket never adds a workflow to its list.

```yaml
# Composite action: sign-and-attest
#
# Signs one image that a build has just pushed, attests an SPDX bill of
# materials of that image, and verifies the signature and the attestation.
# The action fails when any of these fails. Image builds call this one
# action, so the signing rule lives in one place: FND-061 brought it to the
# two control-plane images (catalyst-ui and catalyst-api); FND-062 brought it
# to every other image build and to the chart release; FND-063 added the
# release-key signature. The guard scripts/check-builds-sign.py fails a
# workflow that pushes an image or a chart without this action, that runs
# cosign sign or cosign attest itself, or whose call of this action does not
# pass the release key.
#
# Where to call it: right after the step that pushes the image, in the same
# job, and before any job that pins the image's tag. An image that cannot be
# signed, attested and verified stops its build there and is never rolled
# out.
#
# How it signs. Two signatures, both stored next to the image:
#   1. Keyless, on every run. cosign takes a short-lived certificate for the
#      calling workflow from the GitHub OIDC token, so the calling job needs
#      the permission `id-token: write`, and the signature is recorded in the
#      public transparency log. The bill of materials is attested the same
#      way. The verify commands accept a certificate whose subject is a
#      workflow of this repository and whose issuer is GitHub Actions.
#   2. With the release key, on refs/heads/main only. The private half of the
#      release key pair is the repository secret RELEASE_COSIGN_KEY, its
#      password the secret RELEASE_COSIGN_PASSWORD. The public half is the
#      file keys/release-cosign.pub. This signature is not uploaded to the
#      transparency log (--tlog-upload=false), and it is verified against
#      keys/release-cosign.pub with the log check off
#      (--insecure-ignore-tlog=true). A Sovereign verifies platform images
#      against this key and needs no route to a public signing service.
# A composite action cannot read a secret, so every caller passes the two
# secrets as the inputs release-key and release-key-password. When the key
# is empty, or the run is not on refs/heads/main, the action signs keyless
# only, as before, and says so in a warning or a notice.
#
# Inputs:
#   ref     the image name without tag and without digest, for example
#           ghcr.io/openova-io/openova/catalyst-api
#   digest  the digest of the pushed image, sha256:<64 hex>. With
#           docker/build-push-action it is steps.<id of the push step>.outputs.digest
#   sbom-source
#           optional. What Syft reads to write the bill of materials. Empty, the
#           default: the pushed image, registry:<ref>@<digest>. Syft cannot read
#           a Helm chart from the registry, so the chart release passes the
#           packaged chart it pushed: file:<path of the .tgz>.
#   release-key
#           ${{ secrets.RELEASE_COSIGN_KEY }}, the private half of the release
#           key pair.
#   release-key-password
#           ${{ secrets.RELEASE_COSIGN_PASSWORD }}, its password.
#
# Versions: cosign v2.4.1, the version the chart release installed before it
# called this action; Syft v1.43.0, the version platform/syft-grype/chart/values.yaml runs.
# The registry login of the calling job is used for the push of the signatures
# and the attestation and for the read of the image by Syft.
# The test .github/actions/sign-and-attest/test-sign.sh runs the step
# "Sign, attest and verify" with stand-in cosign and Syft commands.

name: sign-and-attest
description: |
  Sign an image that was just pushed, attest an SPDX bill of materials of
  it, and verify the signature and the attestation. On main, also sign it
  with the release key and verify that signature.

inputs:
  ref:
    description: |
      The image name without tag and without digest.
    required: true
  digest:
    description: |
      The digest of the pushed image, sha256:<64 hex>.
    required: true
  sbom-source:
    description: |
      Optional. Empty: Syft reads the pushed image from the registry. For a
      Helm chart: file:<path of the packaged .tgz that was pushed>.
    required: false
    default: ""
  release-key:
    description: |
      The private half of the release key pair, secrets.RELEASE_COSIGN_KEY.
      Used on refs/heads/main only. Empty: no release-key signature.
    required: false
    default: ""
  release-key-password:
    description: |
      The password of the release key, secrets.RELEASE_COSIGN_PASSWORD.
    required: false
    default: ""

runs:
  using: composite
  steps:
    - name: Check the inputs
      shell: bash
      env:
        REF: ${{ inputs.ref }}
        DIGEST: ${{ inputs.digest }}
        SBOM_SOURCE: ${{ inputs.sbom-source }}
      run: |
        set -euo pipefail
        if [ -z "$REF" ] || [[ "$REF" == *@* ]] || [[ "$REF" =~ [[:space:]] ]]; then
          echo "::error::sign-and-attest: the input ref must be an image name without a digest; it is '$REF'"
          exit 1
        fi
        if [[ ! "$DIGEST" =~ ^sha256:[0-9a-f]{64}$ ]]; then
          echo "::error::sign-and-attest: the input digest must be sha256:<64 hex>; it is '$DIGEST'. Give the push step an id and pass steps.<id>.outputs.digest."
          exit 1
        fi
        if [ -n "$SBOM_SOURCE" ]; then
          if [[ "$SBOM_SOURCE" != file:* ]] || [ ! -s "${SBOM_SOURCE#file:}" ]; then
            echo "::error::sign-and-attest: the input sbom-source must be file:<path of a file that exists>; it is '$SBOM_SOURCE'"
            exit 1
          fi
        fi
        echo "sign-and-attest: ${REF}@${DIGEST}"

    - name: Install cosign
      uses: sigstore/cosign-installer@v3
      with:
        cosign-release: v2.4.1

    - name: Install Syft
      id: syft
      uses: anchore/sbom-action/download-syft@v0
      with:
        syft-version: v1.43.0

    - name: Sign, attest and verify
      shell: bash
      env:
        REF: ${{ inputs.ref }}
        DIGEST: ${{ inputs.digest }}
        SBOM_SOURCE: ${{ inputs.sbom-source }}
        SYFT: ${{ steps.syft.outputs.cmd }}
        ISSUER: https://token.actions.githubusercontent.com
        RELEASE_KEY: ${{ inputs.release-key }}
        RELEASE_KEY_PASSWORD: ${{ inputs.release-key-password }}
        RELEASE_PUBLIC_KEY: ${{ github.workspace }}/keys/release-cosign.pub
      run: |
        set -euo pipefail
        image="${REF}@${DIGEST}"
        identity="^https://github\.com/${GITHUB_REPOSITORY}/\.github/workflows/"
        sbom="${RUNNER_TEMP}/sbom-${DIGEST#sha256:}.spdx.json"

        if [ -z "$SYFT" ]; then
          echo "::error::sign-and-attest: the step Install Syft gave no command"
          exit 1
        fi
        syft_version="$("$SYFT" version)"
        case "$syft_version" in
          *1.43.0*) ;;
          *)
            echo "::error::sign-and-attest: Syft is not version 1.43.0"
            echo "$syft_version"
            exit 1
            ;;
        esac

        # The release key is used on main only. Elsewhere, or without the
        # key, the image gets the keyless signature only, as before.
        with_key=no
        if [ -z "$RELEASE_KEY" ]; then
          echo "::warning::sign-and-attest: no release key was passed, so ${image} gets the keyless signature only"
        elif [ "${GITHUB_REF:-}" != "refs/heads/main" ]; then
          echo "::notice::sign-and-attest: the release key is used on refs/heads/main only and this run is on '${GITHUB_REF:-}', so ${image} gets the keyless signature only"
        elif [ ! -s "$RELEASE_PUBLIC_KEY" ]; then
          echo "::error::sign-and-attest: the release key was passed, but ${RELEASE_PUBLIC_KEY} is missing or empty, so its signature cannot be verified"
          exit 1
        else
          with_key=yes
        fi

        echo "sign-and-attest: signing ${image}"
        cosign sign --yes "$image"

        if [ "$with_key" = yes ]; then
          echo "sign-and-attest: signing ${image} with the release key, without a transparency-log upload"
          COSIGN_PASSWORD="$RELEASE_KEY_PASSWORD" cosign sign --yes --key env://RELEASE_KEY --tlog-upload=false "$image"
        fi

        sbom_from="${SBOM_SOURCE:-registry:${image}}"
        echo "sign-and-attest: writing the SPDX bill of materials of ${image} from ${sbom_from}"
        "$SYFT" "$sbom_from" -o "spdx-json=${sbom}"
        if [ ! -s "$sbom" ]; then
          echo "::error::sign-and-attest: Syft wrote no bill of materials"
          exit 1
        fi

        echo "sign-and-attest: attesting the bill of materials"
        cosign attest --yes --type spdxjson --predicate "$sbom" "$image"

        echo "sign-and-attest: verifying the signature"
        cosign verify --certificate-identity-regexp "$identity" --certificate-oidc-issuer "$ISSUER" "$image" > /dev/null

        echo "sign-and-attest: verifying the attestation"
        cosign verify-attestation --type spdxjson --certificate-identity-regexp "$identity" --certificate-oidc-issuer "$ISSUER" "$image" > /dev/null

        if [ "$with_key" = yes ]; then
          echo "sign-and-attest: verifying the release-key signature against keys/release-cosign.pub"
          cosign verify --key "$RELEASE_PUBLIC_KEY" --insecure-ignore-tlog=true "$image" > /dev/null
          echo "sign-and-attest: ${image} is signed, attested and verified, and carries the release-key signature"
        else
          echo "sign-and-attest: ${image} is signed, attested and verified, without the release-key signature"
        fi
```

```sh
# It runs the body of that step with stand-in `cosign` and Syft commands that only record their
# arguments, in six cases, and checks which cosign commands ran:
#   1. on main with the release key: the keyless signature, the release-key signature without a
#      log upload, the attestation, the two keyless verifications and the release-key verification
#      against keys/release-cosign.pub, in this order;
#   2. on main without the key: the keyless commands only, and a warning;
#   3. on another ref with the key: the keyless commands only, and a notice;
#   4. on main with the key and no public key file: the step fails before cosign runs;
#   5. on main with the key, when the release-key verification fails: the step fails;
#   6. on main with the key, when the release-key signature fails: the step fails.
# It needs bash and Python 3 with PyYAML. No network, no registry, no cosign.
#
# Run from the repository root: bash .github/actions/sign-and-attest/test-sign.sh
# Exit 0: every case passed. Exit 1: a case failed; the lines above name it.

set -euo pipefail

ACTION="$(cd "$(dirname "$0")" && pwd)/action.yaml"
WORK="$(mktemp -d)"
trap 'rm -rf "${WORK}"' EXIT

# The body of the step "Sign, attest and verify", exactly as the runner gets it.
python3 - "$ACTION" "${WORK}/step.sh" <<'PY'
import sys
import yaml

steps = yaml.safe_load(open(sys.argv[1], encoding="utf-8"))["runs"]["steps"]
body = [s["run"] for s in steps if s.get("name") == "Sign, attest and verify"]
if len(body) != 1:
    sys.exit("test-sign: the action has %d steps named 'Sign, attest and verify'" % len(body))
with open(sys.argv[2], "w", encoding="utf-8") as handle:
    handle.write(body[0])
PY

# Stand-in commands. cosign writes one line per call to $CALLS: its arguments, and for a call
# with --key whether the key and its password reached it. STUB_FAIL makes the call whose
# arguments start with that text fail.
mkdir -p "${WORK}/bin"
cat > "${WORK}/bin/cosign" <<'SH'
#!/usr/bin/env bash
line="$*"
case " $* " in
  *" --key env://RELEASE_KEY "*) line="${line} [key=${RELEASE_KEY:-} password=${COSIGN_PASSWORD:-}]" ;;
esac
echo "$line" >> "$CALLS"
if [ -n "${STUB_FAIL:-}" ] && [[ "$*" == "${STUB_FAIL}"* ]]; then
  exit 1
fi
exit 0
SH

#!/usr/bin/env bash
if [ "${1:-}" = version ]; then

# run_case <name> <ref> <key> <public key path> <text a failing cosign call starts with>
# Runs the step; leaves its exit code in $CODE, its output in $OUT and the cosign calls in $CALLS.
run_case() {
  CASE="$1"
  CALLS="${WORK}/calls-${CASE}"
  OUT="${WORK}/out-${CASE}"
  : > "$CALLS"
  mkdir -p "${WORK}/temp-${CASE}"
  set +e
  env PATH="${WORK}/bin:${PATH}" CALLS="$CALLS" STUB_FAIL="$5" \
    REF="ghcr.io/openova-io/openova/test" DIGEST="$DIGEST" SBOM_SOURCE="" \
    SYFT="${WORK}/bin/syft" ISSUER="$ISSUER" \
    RELEASE_KEY="$3" RELEASE_KEY_PASSWORD="test-password" RELEASE_PUBLIC_KEY="$4" \
    GITHUB_REF="$2" GITHUB_REPOSITORY="openova-io/openova" RUNNER_TEMP="${WORK}/temp-${CASE}" \
    bash -e "${WORK}/step.sh" > "$OUT" 2>&1
  CODE=$?
  set -e
}

fail() {
  echo "test-sign: FAIL case ${CASE}: $1"
  echo "--- output of the step:"
  cat "$OUT"
  echo "--- cosign calls:"
  cat "$CALLS"
  FAILED=1
}

KEYLESS_SIGN="sign --yes ${IMAGE}"
KEY_SIGN="sign --yes --key env://RELEASE_KEY --tlog-upload=false ${IMAGE} [key=test-key password=test-password]"

VERIFY_ATT="verify-attestation --type spdxjson --certificate-identity-regexp ${IDENTITY} --certificate-oidc-issuer ${ISSUER} ${IMAGE}"
KEY_VERIFY="verify --key ${WORK}/workspace/keys/release-cosign.pub --insecure-ignore-tlog=true ${IMAGE}"

# expect_calls <line> ...: the cosign calls of the case are exactly these lines, in this order.
expect_calls() {
  local want
  want="$(printf '%s\n' "$@" | sed "s#temp-CASE#temp-${CASE}#")"
  if [ "$(cat "$CALLS")" != "$want" ]; then
    fail "the cosign calls differ; expected:
${want}"
  fi
}
```

```python
#!/usr/bin/env python3
"""check-builds-sign.py - every image and chart push is signed through the shared action.

The rule of signing lives in one place: the composite action .github/actions/sign-and-attest.
It signs an image or chart that a step has just pushed, attests a bill of materials of it, and
verifies both. This guard reads every workflow and fails when a push can bypass that action.

A push step is a step of a job that is one of these:
  - a step that uses docker/build-push-action and whose input `push` is not false (an absent
    input is false, the default of that action);
  - a run step that runs `helm push`;
  - a run step that runs `docker push`, in a job that also has a step that uses
    docker/build-push-action. Such a job builds the image it pushes. A job that only copies an
    image built elsewhere is not judged.

The rules:
  1. A push step has an id, and a later step of the same job uses
     ./.github/actions/sign-and-attest with an input `digest` that reads steps.<that id>.outputs.
  2. That signing step runs exactly when the push runs: its `if` is the `if` of the push step.
     When the push step has no `if` and its input `push` is an expression ${{ X }}, the `if` of
     the signing step is X. Otherwise the signing step has no `if`.
  3. No step that uses ./.github/actions/deploy-bump stands between a push step and its signing
     step: a tag is never pinned before its image is signed.
  4. A signing step has no `continue-on-error`.
  5. The job of a signing step may ask for an OIDC token: `id-token: write` in the permissions of
     the job, or, when the job has no permissions, in those of the workflow.
  6. No workflow and no composite action other than the shared action runs `cosign sign` or
     `cosign attest` itself.
  7. A signing step passes the release key: its input `release-key` is
     ${{ secrets.RELEASE_COSIGN_KEY }} and its input `release-key-password` is
     ${{ secrets.RELEASE_COSIGN_PASSWORD }}. A composite action cannot read a secret, so the
     caller passes it; the action uses it on refs/heads/main only (FND-063).

Files read: .github/workflows/*.yml and *.yaml, and .github/actions/**/action.yml and
action.yaml. Comment lines of a run step are not read. The allowed number of failures is 0.

Usage (from the repository root):
  python3 scripts/check-builds-sign.py              judge the tree
  python3 scripts/check-builds-sign.py --root DIR   judge the tree at DIR
  python3 scripts/check-builds-sign.py --self-test  show that every rule can fail and can pass
Exit codes: 0 pass, 1 a rule failed, 2 a file cannot be read.
"""
import glob
import os
import re
import sys
import tempfile

SIGN_ACTION = "./.github/actions/sign-and-attest"
DEPLOY_BUMP = "./.github/actions/deploy-bump"
SIGN_ACTION_FILES = (".github/actions/sign-and-attest/action.yaml", ".github/actions/sign-and-attest/action.yml")
BUILD_PUSH = "docker/build-push-action"

HELM_PUSH_RE = re.compile(r"(^|[\s;&|(])helm\s+push\b")
DOCKER_PUSH_RE = re.compile(r"(^|[\s;&|(])docker\s+push\b")
COSIGN_RE = re.compile(r"\bcosign\s+(sign|attest)\b")
EXPR_RE = re.compile(r"^\$\{\{\s*(.*?)\s*\}\}$", re.S)
DIGEST_RE = re.compile(r"steps\.([A-Za-z0-9_-]+)\.outputs\.")
# The inputs of the shared action that carry the release key, and the secret each must read.
RELEASE_INPUTS = (("release-key", "RELEASE_COSIGN_KEY"), ("release-key-password", "RELEASE_COSIGN_PASSWORD"))


class ReadError(Exception):
    """A file cannot be read or parsed."""


def load_yaml(path):
    import yaml  # imported here, so that --self-test fails with one clear line when it is missing

    try:
        with open(path, encoding="utf-8") as handle:
            return yaml.safe_load(handle)
    except (OSError, yaml.YAMLError) as exc:
        raise ReadError(f"{path}: {exc}")


def uses_of(step):
    return str(step.get("uses") or "").strip()


def action_of(step):
    return uses_of(step).split("@")[0].rstrip("/")


def run_lines(step):
    """The lines of a run step that are not comment lines."""
    text = step.get("run")
    if not isinstance(text, str):
        return []
    return [line for line in text.splitlines() if not line.strip().startswith("#")]


def runs(step, pattern):
    return any(pattern.search(line) for line in run_lines(step))


def normal(value):
    """An `if` or an expression as plain text: without ${{ }} and with single spaces."""
    if value is None:
        return ""
    text = str(value).strip()
    match = EXPR_RE.match(text)
    if match:
        text = match.group(1)
    return " ".join(text.split())


def is_build_push(step):
    return action_of(step) == BUILD_PUSH


def pushes(step, job_builds):
    """True when the step is a push step."""
    if is_build_push(step):
        value = (step.get("with") or {}).get("push")
        return value is not None and value is not False and str(value).strip().lower() != "false"
    if runs(step, HELM_PUSH_RE):
        return True
    return job_builds and runs(step, DOCKER_PUSH_RE)


def expected_if(step):
    """The `if` that the signing step of this push step must carry, as plain text."""
    if step.get("if") is not None:
        return normal(step.get("if"))
    if is_build_push(step):
        value = (step.get("with") or {}).get("push")
        if isinstance(value, str) and EXPR_RE.match(value.strip()):
            return normal(value)
    return ""


def has_id_token(permissions):
    if isinstance(permissions, str):
        return permissions.strip() == "write-all"
    return isinstance(permissions, dict) and str(permissions.get("id-token", "")).strip() == "write"


def step_label(index, step):
    name = step.get("name") or uses_of(step) or "run"
    return f'step {index + 1} "{name}"'


def judge_workflow(path, data, out):
    """Rules 1 to 5 and 7 for one workflow. Returns the number of push steps."""
    if not isinstance(data, dict):
        return 0
    jobs = data.get("jobs") or {}
    found = 0
    for job_name, job in jobs.items():
        if not isinstance(job, dict):
            continue
        steps = [s for s in (job.get("steps") or []) if isinstance(s, dict)]
        builds = any(is_build_push(s) for s in steps)
        permissions = job["permissions"] if "permissions" in job else data.get("permissions")
        for index, step in enumerate(steps):
            if action_of(step) != SIGN_ACTION:
                continue
            where = f"{path}: job {job_name}, {step_label(index, step)}"
            if step.get("continue-on-error") not in (None, False) and str(step.get("continue-on-error")).strip().lower() != "false":
                out.append(f"{where}: the signing step has continue-on-error (rule 4)")
            if not has_id_token(permissions):
                out.append(f"{where}: the job cannot ask for an OIDC token; give it id-token: write (rule 5)")
            given = step.get("with") or {}
            for name, secret in RELEASE_INPUTS:
                if normal(given.get(name)) != f"secrets.{secret}":
                    out.append(f"{where}: the signing step does not pass {name}: ${{{{ secrets.{secret} }}}} (rule 7)")
        for index, step in enumerate(steps):
            if not pushes(step, builds):
                continue
            found += 1
            where = f"{path}: job {job_name}, {step_label(index, step)}"
            step_id = step.get("id")
            if not step_id:
                out.append(f"{where}: the push step has no id, so no signing step can read its digest (rule 1)")
                continue
            signer = None
            for later in range(index + 1, len(steps)):
                other = steps[later]
                if action_of(other) != SIGN_ACTION:
                    continue
                digest = str((other.get("with") or {}).get("digest") or "")
                if step_id in DIGEST_RE.findall(digest):
                    signer = later
                    break
            if signer is None:
                out.append(f"{where}: no later step uses {SIGN_ACTION} with digest from steps.{step_id}.outputs (rule 1)")
                continue
            want, have = expected_if(step), normal(steps[signer].get("if"))
            if want != have:
                out.append(f"{where}: its signing step runs on if '{have}', the push on '{want}' (rule 2)")
            for between in range(index + 1, signer):
                if action_of(steps[between]) == DEPLOY_BUMP:
                    out.append(f"{where}: {step_label(between, steps[between])} pins the tag before the signing step (rule 3)")
    return found


def all_steps(data):
    """Every step of a workflow or of a composite action."""
    if not isinstance(data, dict):
        return
    for job in (data.get("jobs") or {}).values():
        if isinstance(job, dict):
            for step in job.get("steps") or []:
                if isinstance(step, dict):
                    yield step
    composite = data.get("runs")
    if isinstance(composite, dict):
        for step in composite.get("steps") or []:
            if isinstance(step, dict):
                yield step


def judge(root):
    """(failures, push steps, workflows read) for the tree at root."""
    failures, found = [], 0
    workflows = sorted(glob.glob(os.path.join(root, ".github/workflows/*.yml")) + glob.glob(os.path.join(root, ".github/workflows/*.yaml")))
    actions = sorted(glob.glob(os.path.join(root, ".github/actions/**/action.yml"), recursive=True) + glob.glob(os.path.join(root, ".github/actions/**/action.yaml"), recursive=True))
    for full in workflows:
        rel = os.path.relpath(full, root)
        data = load_yaml(full)
        found += judge_workflow(rel, data, failures)
    for full in workflows + actions:
        rel = os.path.relpath(full, root).replace(os.sep, "/")
        if rel in SIGN_ACTION_FILES:
            continue
        data = load_yaml(full)
        for step in all_steps(data):
            if runs(step, COSIGN_RE):
                failures.append(f'{rel}: step "{step.get("name") or "run"}" runs cosign itself; call {SIGN_ACTION} instead (rule 6)')
    return failures, found, len(workflows)


def report(root):
    try:
        failures, found, count = judge(root)
    except ReadError as exc:
        print(f"check-builds-sign: ERROR {exc}")
        return 2
    for failure in failures:
        print(f"check-builds-sign: FAIL {failure}")
    if failures:
        print(f"check-builds-sign: {len(failures)} failures; allowed: 0")
        return 1
    print(f"check-builds-sign: ok, {found} push steps in {count} workflows are signed through {SIGN_ACTION}")
    return 0
```
