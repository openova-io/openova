# CTL-330 — The services stop building the Kafka client

## In plain words

**The problem today.** The seven services behind the storefront still build a Kafka client next to NATS. On a Sovereign no Kafka broker exists, so this code only adds a second, dead transport: the auth and catalog services even point their producer at a local default address that nothing listens on. NATS is the one event bus of the platform.

**What changes.** The services build no Kafka producer or consumer and no longer read REDPANDA_BROKERS. Every publisher and subscriber is wired to NATS only, and the auth service drops the login event that only Kafka carried.

**Done means:**

- No file of the seven services reads REDPANDA_BROKERS or calls the Kafka producer or consumer constructors.
- The billing, domain, provisioning and tenant services build their publisher from the NATS connection alone, and no subscriber of any service is given a Kafka consumer.
- The auth service no longer publishes the login event, and the catalog and notification services no longer hold a producer that nothing used.
- Each of the five services that use the event bus (billing, domain, notification, provisioning, tenant) stops at start, with the message that NATS_URL is not set, when it is started without NATS_URL.
- Every test and vet run of the seven service modules passes, and no go.mod or go.sum changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The seven Go services under `core/services/` that sit behind the storefront (auth, billing, catalog, domain, notification, provisioning, tenant) use NATS JetStream as their only event bus. None of them reads the variable `REDPANDA_BROKERS`, builds a Kafka producer with `events.NewProducer` or a Kafka consumer with `events.NewConsumer`. The four services that publish through `events.MultiPublisher` build it from the NATS connection alone, and every `events.MultiSubscriber` they build has no Kafka leg. The auth service stops sending the `user.login` event, which only ever went to the Kafka topic `auth.events`. The shared package `core/services/shared/events` itself, the `go.mod` files and the chart are not changed here; later packages take them.
