# CMP-024 — The API's cache holds the namespaced policy kinds, and its fan-out never sends on a closed channel

## In plain words

**The problem today.** The compliance API shows the per-Organization policy of every Organization namespace as permissive, although its engine object enforces, so a required gate check is red on the two-region Sovereign. The API's cache watches only the cluster-wide policy kinds and names each object by its bare name, while the engine names a namespaced policy namespace/name, so the API never finds the object and falls back to permissive. The cache can also panic the whole process: an unsubscribe closes a channel that a running fan-out may still send on.

**What changes.** The cache watches the namespaced policy kind and the API names its objects namespace/name, as the engine does, so the API shows the mode the object carries. The gate check also fails when the API leaves a policy object out, and the fan-out sends and the unsubscribe closes under one lock.

**Done means:**

- A per-Organization policy whose engine object enforces is listed as enforcing by the policies route, and one that audits as permissive, each under the name namespace/name.
- Two Organization namespaces that hold a policy of the same name in two modes are listed apart, and neither takes the entry of a cluster-wide policy of that bare name.
- The gate check CMP-G02 fails when the API leaves a policy object of the engine out of its list, and names each one.
- Subscribers of the cache that come and go while events are sent never crash the process, and each one's channel is closed after it leaves.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`GET /api/v1/sovereigns/{id}/compliance/policies` lists every per-Organization policy of the engine (the `kyverno.io/v1` `Policy` in an Organization namespace, such as `org-platform-scope`) under the name `<namespace>/<name>`, the name the engine's reports give it, with the mode its own object carries in the informer store; the per-resource findings take its severity and category from the same entry. Gate check CMP-G02 (`tests/acceptance/sovereign/internal/suite/check_compliance_mode.go`) compares the mode of every listed policy with its engine object, as before, and now also fails when a policy object of the engine in the first region is not listed. `Factory.fanout` of `products/catalyst/bootstrap/api/internal/k8scache` never sends on a channel that an unsubscribe has closed.

## 3. The model (the law)
1. The informer registry `k8scache.DefaultKinds` holds the kind `policy` (constant `KindPolicy`): group `kyverno.io`, version `v1`, resource `policies`, `Namespaced: true`, `Optional: true` (a cluster that does not serve the kind starts no informer for it). The ClusterRole `catalyst-api-cutover-driver` already grants `get`, `list` and `watch` on `kyverno.io` `policies`; no chart changes.
2. `adapters.PolicyMode{}.Kinds()` returns `clusterpolicy`, `policy`, `validatingpolicy`, `mutatingpolicy`, in that order: the two legacy kinds first. `PolicyMode.Mode` reads a `Policy` of `kyverno.io` by the legacy rule of `ClusterPolicy` (`spec.validationFailureAction`, else `validate.failureAction` of a rule); a `Policy` of any other group is not read.
3. `adapters.PolicyName(obj)` is `<namespace>/<name>` for an object with a namespace and the bare name otherwise. `adapters.PolicyObjects` keys its result by `PolicyName`, and `ComplianceHandler.onEvent` keys the event-fed copy by `PolicyName`. A namespaced object never takes the entry of a cluster-scoped one, and two namespaces holding one name give two entries.
4. CMP-G02 step 3 fails when a name of an engine object of the first region (the three cluster-wide kinds and the three namespaced kinds it reads) is not listed by the route, and lists each such name; a name two kinds hold during an in-place rewrite is counted once. Every earlier failure of step 3 stays, and all failures of the step are reported together.
5. `Factory.fanout` holds `subMu` over its non-blocking sends; the unsubscribe function of `Factory.Subscribe` deletes its subscriber and closes its channel under `subMu`. No send waits for a consumer, so the lock is never held while waiting.
6. Nothing is deleted; no chart, no go.mod, no Kyverno policy and no version line changes. The README row of CMP-G02 (`tests/acceptance/sovereign/README.md`) states the check as rule 4 makes it.
