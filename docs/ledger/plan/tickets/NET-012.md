# NET-012 — Second provider firewall to the same rule

## In plain words

**The problem today.** The firewall of every Sovereign on the second cloud opens the Kubernetes API port and two mesh ports to the whole internet. That cloud is offered for one region only, so the mesh ports have no peer to serve, and the API port needs only the provisioning API and the sovereign-admin.

**What changes.** The API port admits only the two lists that the provisioning API already writes for the reference cloud, and the two mesh ports are closed. The module test, the open-port guard and the module's own README say the same.

**Done means:**

- No firewall rule of the second cloud module opens a port other than 80, 443, 53 or ICMP to every address.
- The Kubernetes API port of that module admits exactly the sovereign-admin ranges and the provisioner's egress ranges, and has no rule when both lists are empty.
- A range that would open the API port to every address, or that is not a valid IPv4 network, is refused by the module.
- The network registry of that module lists both access lists.
- The open-port guard has no allowance left for the second cloud module.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A Sovereign provisioned with the module `infra/providers/hetzner` has one firewall, `hcloud_firewall.main`. Its rules open TCP 80, 443 and 53, UDP 53 and ICMP to any address, as today. TCP 6443, the Kubernetes API, is open only to the OpenTofu variables `admin_cidrs` (the ranges the sovereign-admin works from) and `provisioner_cidrs` (the egress ranges of the provisioning catalyst-api), the two variables that catalyst-api already writes for every provider. When both lists are empty there is no 6443 rule. The any-source rules for TCP 2379 and UDP 51871 are gone. The module's `network_registry` output carries both lists as `controlPlaneAccess`. The module test proves this, and the open-port guard G1 of `scripts/check-network-guards.py` counts no offence in this module.

## 3. The model (the law)
1. `infra/providers/hetzner/variables.tf` declares `admin_cidrs` and `provisioner_cidrs`: type `list(string)`, default `[]`, with the same description and the same validation as in `infra/providers/huawei/variables.tf`. The condition of each validation is `alltrue([for c in var.<name> : can(cidrnetmask(c)) && !endswith(c, "/0") && try(cidrsubnet(c, 0, 0) == c, false)])`. It accepts `[]` and refuses `0.0.0.0/0`, `::/0`, any IPv6 range, a bare address and a range with host bits set.
2. In `hcloud_firewall.main` the static 6443 rule is replaced by a `dynamic "rule"` block. It has one rule when `concat(var.admin_cidrs, var.provisioner_cidrs)` is not empty, and none otherwise. Its sources are `distinct(concat(var.admin_cidrs, var.provisioner_cidrs))`, so a range named in both lists appears once. It is TCP 6443 only.
3. The rules for TCP 2379 and UDP 51871 and their comments are deleted. The pack's `profile.yaml` declares `multiRegion: false`, and a Sovereign of one region has no mesh peer that dials them.
4. The rules for TCP 80, 443 and 53, UDP 53 and ICMP, and the dynamic SSH rule from `var.ssh_allowed_cidrs`, do not change.
5. In `local.network_registry`, `controlPlaneAccess.adminCIDRs` is `var.admin_cidrs` and `controlPlaneAccess.provisionerCIDRs` is `var.provisioner_cidrs`. The key names do not change: `scripts/check-network-registry.py` reads them.
6. Guard G1: the line `G1<TAB>infra/providers/hetzner/main.tf<TAB>3` is deleted from `scripts/network-guards-baseline.tsv`. The guard fails while a baseline line names a file that has no offence left.
7. The module test `infra/providers/hetzner/tests/multi_region.tftest.hcl`: the assertion that UDP 51871 has exactly one rule is replaced by an assertion that only TCP 80, 443, 53, UDP 53 and ICMP are open to any source, and that without the two lists no rule opens 6443, 2379 or 51871. Two runs are added: `api_port_limited` (the 6443 rule and the registry with both lists set) and `api_port_lists_refuse_any_source` (both validations refuse).
8. The firewall rows of `infra/providers/hetzner/README.md` say the same: the 6443 row names the two lists, the 51871 row is deleted.
9. No port in the range 30000-32767 is added. No load balancer, server, network or output changes.
