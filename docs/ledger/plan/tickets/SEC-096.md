# SEC-096 — Census limit set from the first measured census; SEC-G11 required

## In plain words

**The problem today.** The gate check that counts the Secrets which no register entry approves runs on every gate run, but its limit is zero and it is only expected to fail. So a new unapproved Secret on a Sovereign stops nothing, and the count can grow without anyone seeing it.

**What changes.** The limit is set to the number the first census measured in its worst region, and the check becomes required. From then on a gate run fails when any region has more unapproved Secrets than that.

**Done means:**

- The register of Secret objects allows at most 432 unmatched Secrets per region, and its comment names the gate record that number comes from.
- The Secret census check reads 432 as its limit.
- The gate manifest lists the Secret census check as required, and the manifest tool accepts that change from this task only.
- The register entries, the register guard and the census rule are otherwise unchanged.
- The next gate run records the Secret census as passed in every region.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. **The census rule** (unchanged by this ticket). `bash scripts/check-secret-object-register.sh --census <file>` reads one line `<namespace><TAB><name><TAB><type>` per Secret, skips the types `kubernetes.io/service-account-token`, `helm.sh/release.v1` and `bootstrap.kubernetes.io/token`, counts a Secret as matched when a register entry has its namespace (or `*`) and a name pattern that matches the whole name, and prints one JSON line with `allowedUnmatched`, `judged`, `skipped`, `matched`, `unmatched` and `pastReview`. Gate check SEC-G11 (`tests/acceptance/sovereign/internal/suite/check_sec_census.go`) runs it once per region and fails that region's step when more Secrets are unmatched than `allowedUnmatched`.
2. **The limit is judged per region.** Each region's unmatched count must be at or below `allowedUnmatched`. The limit is therefore the highest count of one region, not the sum of the regions.
3. **The number.** The first gate record that ran SEC-G11 (status other than `SKIP`) is `docs/ledger/acceptance/hw307-20261115T124804Z-66a6.json`. It counted 432 unmatched Secrets in region `hw-me-east-215-a-rtz-prod` and 195 in region `hw-me-east-215-b-rtz-prod`. So `allowedUnmatched` is `432`.
4. **Only lowered from now on.** After this ticket only package SEC-248 changes `allowedUnmatched`, and it may only lower it. The comment above the field says so and names the record of law 3.
5. **The state.** The entry SEC-G11 of `docs/ledger/gates.yaml` changes in one line: `  state: expected-fail` becomes `  state: required`. No other line of the file changes. The manifest tool (`scripts/acceptance-gate.py validate`, its rule 4) lets only the package named in `delivered_by`, SEC-096, set a check to `required`, and its rule 7 refuses a change of any field other than `state` and `implementation` from a work package.
6. **Nothing else changes.** The register entries, `metadataAccess`, the schema line, the guard script, the census check and its test stay as they are. No file is added or deleted.
