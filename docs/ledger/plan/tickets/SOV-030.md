# SOV-030 — Wipe refuses a handed-over Sovereign without confirmation

## In plain words

**The problem today.** One wipe request destroys a Sovereign in any state, also after it has been handed over to its owner and runs the owner's work. Nothing on the server asks for a confirmation. The console's wipe dialogs make the person type the Sovereign's name, but they do not send it, so the server never sees it.

**What changes.** After the hand-over the server refuses a wipe unless the request carries the Sovereign's name in a confirmation header, and it says why. The deployment record notes when the hand-over completed. The console's wipe dialogs and the lifecycle script send the name the person confirmed, and the dialogs say that the Sovereign's own virtual machines are destroyed too.

**Done means:**

- A wipe request for a handed-over Sovereign without its name in the confirmation header is refused with HTTP 412, and nothing is destroyed.
- A wipe request that carries the right name goes on as before.
- A deployment that was never handed over is wiped as before, without the header.
- The deployment record notes the time the hand-over completed.
- The refusal and the console's wipe dialogs say that a wipe also destroys the virtual machines the Sovereign created itself.
- The console's wipe dialogs and the lifecycle script send the name the person typed or gave.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`POST /api/v1/deployments/{id}/wipe` destroys a Sovereign that has been handed over only when the request carries the header `X-Confirm-Sovereign-FQDN` with that Sovereign's FQDN. Without the header, or with another value, the route answers HTTP 412 with the body `{"error":"confirm-fqdn-required","message":"..."}` before anything is destroyed; the message says that a wipe also destroys the virtual machines the Sovereign created itself. A deployment that was never handed over is wiped as today, without the header. The deployment record gets the field `handoverCompletedAt`, set when the hand-over completes. The three console screens that call the wipe route send the text the person typed to confirm in the header, and they list the Sovereign's own virtual machines among what is destroyed. The command `wipe` of `scripts/sovereign-lifecycle.sh` takes the FQDN as an optional second argument and sends it in the header. The new rule lives in a new package, `products/catalyst/bootstrap/api/internal/lifecycle`; the wipe handler only calls it.

## 3. The model (the law)
1. `products/catalyst/bootstrap/api/internal/lifecycle` is a new Go package of the API module, with one file `wipe_confirm.go` and its test `wipe_confirm_test.go`. Both are embedded in this ticket. No other package imports `lifecycle` except `internal/handler`.
2. The header is `X-Confirm-Sovereign-FQDN` (the constant `lifecycle.ConfirmFQDNHeader`).
3. A deployment is handed over when at least one of three timestamps of its record is set: `AdoptedAt` of the record, `Result.HandoverFiredAt` and `Result.HandoverCompletedAt`. `lifecycle.HandoverStamps(dep.AdoptedAt, dep.Result)` returns the three; a nil `Result` gives only the first. `HandoverFiredAt` and `AdoptedAt` count too, so that a Sovereign handed over before this change is protected as well.
4. `lifecycle.WipeConfirmed(fqdn, header, stamps...)` is true when the deployment was never handed over, or when the header, with spaces removed at both ends, equals the FQDN, with spaces removed and letter case not compared. An empty FQDN never confirms.
5. `lifecycle.RefuseUnconfirmedWipe(w, r, fqdn, stamps...)` writes nothing and returns false when the wipe may go on. Otherwise it answers HTTP 412, header `Content-Type: application/json`, body `{"error":"confirm-fqdn-required","message":"<lifecycle.WipeConfirmMessage>"}`, and returns true.
6. The message is exactly: `This Sovereign has been handed over to its owner. A wipe destroys all of its cloud resources, including the virtual machines the Sovereign created itself. To confirm, send the request again with the header X-Confirm-Sovereign-FQDN set to the Sovereign's FQDN.`
7. In `WipeDeployment` the stamps are read under `dep.mu`, in the block that already reads `depStatus`, `depStartedAt` and `depFQDN`. The call of `RefuseUnconfirmedWipe` comes after the minimum-life refusal (409) and before the single-flight guard. So the order of answers is: 404 unknown id, ownership, 400 body or credentials, 409 still converging, 412 not confirmed, 409 wipe in flight, 202. A refused wipe changes nothing on the record. The query `?force=true` lifts the minimum-life refusal only; it never replaces the confirmation.
8. `provisioner.Result` gets the field `HandoverCompletedAt *time.Time` with the JSON name `handoverCompletedAt`, omitted when nil. `fireHandover` in `phase1_watch.go` sets it to the same time as `HandoverFiredAt`, in the same locked block, before the record is persisted. No statement after that block returns early, so the hand-over is complete from then on.
9. The package `internal/handler` keeps its size: the lines of its non-test `.go` files do not change in sum, no method on `*Handler` is added, and no file is added to it. The six new lines of `wipe.go` (one import, one read under the lock, the three lines of the call and one empty line) and the one new line of `phase1_watch.go` are paid for by shorter comments in the same two files.
10. In the console (`products/catalyst/bootstrap/ui`), `WipeDeploymentModal.tsx`, `DeleteDeploymentModal.tsx` and `DecommissionPage.tsx` send the header with the value `confirmText.trim()`: the text the person typed. Each screen already compares that text with its required text before it lets the button work. This ticket does not change the required text and does not change the comparison. The required text is the Sovereign's FQDN when the screen has it. When the screen has no FQDN, the required text is the deployment id in `WipeDeploymentModal.tsx` and in `DeleteDeploymentModal.tsx`, and the word `unknown` in `DecommissionPage.tsx`. Then the header does not carry the FQDN, and the server answers 412 for a handed-over Sovereign, as item 4 requires: only the FQDN confirms. The screen shows that answer as its error text. That result is intended; it is not a defect to repair. Each of the three screens says that every virtual machine the Sovereign created itself is destroyed too.
11. `scripts/sovereign-lifecycle.sh wipe <id> [fqdn]` sends the header `X-Confirm-Sovereign-FQDN: <fqdn>`. Without the second argument the header value is empty, and the API refuses a handed-over Sovereign with 412.
12. This ticket deletes no file and adds no line to `docs/ledger/deleted-paths.txt`.

// Package lifecycle holds the Sovereign lifecycle rules that the API
// server applies to its routes. New lifecycle code is written here, not
// in internal/handler; a handler only calls it.
package lifecycle

import (
	"encoding/json"
	"net/http"
	"strings"
	"time"

	"github.com/openova-io/openova/products/catalyst/bootstrap/api/internal/provisioner"
)

// ConfirmFQDNHeader is the request header that confirms the wipe of a
// Sovereign that has been handed over. Its value is the Sovereign's FQDN.
const ConfirmFQDNHeader = "X-Confirm-Sovereign-FQDN"

// ErrConfirmFQDNRequired is the "error" value of the 412 answer.
const ErrConfirmFQDNRequired = "confirm-fqdn-required"

// WipeConfirmMessage is the "message" value of the 412 answer. It says
// what a wipe destroys and how to confirm it.
const WipeConfirmMessage = "This Sovereign has been handed over to its owner. " +
	"A wipe destroys all of its cloud resources, including the virtual machines " +
	"the Sovereign created itself. To confirm, send the request again with the header " +
	ConfirmFQDNHeader + " set to the Sovereign's FQDN."

// HandoverStamps returns the hand-over timestamps of a deployment record:
// adoptedAt (set when the owner adopted the Sovereign, and on the
// Sovereign's own copy of the record) and, when res is not nil,
// res.HandoverFiredAt and res.HandoverCompletedAt. The caller holds the
// record's lock.
func HandoverStamps(adoptedAt *time.Time, res *provisioner.Result) []*time.Time {
	stamps := []*time.Time{adoptedAt}
	if res != nil {
		stamps = append(stamps, res.HandoverFiredAt, res.HandoverCompletedAt)
	}
	return stamps
}

// HandedOver reports whether a deployment has been handed over: at least
// one of its hand-over timestamps is set. A nil timestamp is not set.
func HandedOver(stamps ...*time.Time) bool {
	for _, s := range stamps {
		if s != nil {
			return true
		}
	}
	return false
}

// WipeConfirmed reports whether a wipe may go on. A deployment that was
// never handed over needs no confirmation. A handed-over deployment needs
// a header value equal to its FQDN; spaces around either value are
// ignored and letter case is not compared. An empty FQDN never confirms.
func WipeConfirmed(fqdn, header string, stamps ...*time.Time) bool {
	if !HandedOver(stamps...) {
		return true
	}
	want := strings.TrimSpace(fqdn)
	got := strings.TrimSpace(header)
	return want != "" && strings.EqualFold(got, want)
}

// RefuseUnconfirmedWipe answers 412 and returns true when the wipe of the
// deployment must not go on. It returns false, and writes nothing, when
// the wipe may go on. fqdn is the deployment's Sovereign FQDN; stamps are
// its hand-over timestamps.
func RefuseUnconfirmedWipe(w http.ResponseWriter, r *http.Request, fqdn string, stamps ...*time.Time) bool {
	if WipeConfirmed(fqdn, r.Header.Get(ConfirmFQDNHeader), stamps...) {
		return false
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusPreconditionFailed)
	_ = json.NewEncoder(w).Encode(map[string]string{
		"error":   ErrConfirmFQDNRequired,
		"message": WipeConfirmMessage,
	})
	return true
}
