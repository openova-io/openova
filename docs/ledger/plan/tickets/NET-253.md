# NET-253 result: the reference cloud's native firewall with a load balancer

- Measured: 2026-11-24, 05:30 to 06:08 UTC, by hand from the agents' host in the cloud's network, on the reference cloud (ADR-0024): the project, the region, one zone.
- Outcome: **NATIVE**. The cloud's web application firewall was created, read, changed and deleted through the cloud's API, behind a load balancer of the Sovereign's shape, and the pass rule of NET-270 held through it: a clean request 200, a cross-site-scripting request 403 and an SQL injection request 403, three times each.
- The 403 needs one setting: by default the firewall answers a blocked request with HTTP 418. A custom block page on the protected host name, with status code 403, gives 403.

## Question

Decision record 0038 (WF5, WF8) gives the firewall contract a second implementation, `waf-native`: the native firewall of the cloud, with the edge nodes reachable only through the load balancer. The reference pack may ship `waf-native` only if its cloud passes this test.

- Can the firewall be created, read and deleted through the cloud's API, together with a load balancer?
- Does the pass rule of NET-270 hold through it: `GET /` 200, `GET /?q=<script>alert(1)</script>` 403 and `GET /?id=1' OR '1'='1` 403, in block mode?
- **Outcomes.** `NATIVE`: both hold. `NONE`: either fails; then a new decision record names the second implementation before NET-257 starts.

## What was run

**Where.** The reference cloud, from the agents' host. Every object was created for this test with the name prefix `nslab-net-253-`, in a network of its own, and deleted at the end. No resource of a test environment, of the jump host or of the parent was changed. A load balancer of its own was used, because a lab test never changes a resource it did not create.

**Tools.** OpenTofu 1.12.0 with the provider `huaweicloud/huaweicloud` 1.91.0, the version that `infra/providers/huawei/.terraform.lock.hcl` pins, with the endpoint pattern of `infra/providers/huawei/versions.tf` and one more endpoint, for the firewall service (`waf`). Read calls were signed requests to the cloud's API gateway with the signing method that the provider uses.

**Read-only probes first.**
- The firewall API is published: the list calls for dedicated instances (`/v1/<project>/premium-waf/instance`), protected host names (`premium-waf/host`), policies (`waf/policy`) and the subscription (`waf/subscription`) answer 200. A made-up path answers `404 APIGW.0101`. A call without a `Content-Type` header answers `400 APIGW.0106`, even a GET.
- The service's console configuration (`waf/config/console`) offers one mode only: `premium_waf: true` (a dedicated instance in the project's own network), `cloud_waf: false`, `elb_mode: false`, `premium_waf_bind_eip: false`, `load_balance_enable: false`. It lists one instance flavor, `s7n.2xlarge.2` (8 vCPU, 16 GiB), for x86 and for Arm, and the one zone.
- Before the test: no instance, no protected host, no policy (`purchased: false`). Quotas: 3 of 5 networks, 7 of 10 public addresses and 2 of 50 load balancers in use.

**The objects.**
- A network and a subnet. Two security groups: the firewall instance admits TCP 80 from anywhere; the backend admits TCP 80 from the lab subnet only.
- The backend: one small VM (`s7n.medium.2`) with no public address, from the image the provider module uses. A socket-activated shell script answers every request with `200` and the body `ok`.
- The firewall: one dedicated instance (specification `waf.instance.professional`, flavor `s7n.2xlarge.2`, x86), one policy (block mode, level 1, the lowest of the three the provider takes; basic web protection on), and one protected host name with the backend as its server, HTTP to HTTP on port 80.
- The load balancer: the shape of the Sovereign's gateway load balancer in `infra/providers/huawei/main.tf` (`huaweicloud_elb_loadbalancer.primary`): dedicated, no flavor pinned, one public address, a TCP listener on port 80, a TCP pool with a TCP health check, and one member: the firewall instance's address, port 80.

- Every object was created, read, changed and deleted through the API with the provider version the reference pack pins. The instance takes about 7 minutes to create and 1 minute to delete.
- Through the Sovereign's load balancer shape, in block mode at level 1 with basic web protection on, a clean request returned 200 and the cross-site-scripting and SQL injection requests of NET-270 were blocked and logged. They returned 403 once the host name carried a custom block page with status 403; the default is 418.
- In log mode the same requests passed with 200 and were logged.
