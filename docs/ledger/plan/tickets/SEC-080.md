# SEC-080 — External Secrets quick scope

## In plain words

**The problem today.** Any namespace of a Sovereign may create an ExternalSecret that reads through the cluster-wide store, and that store may read every key of OpenBao. So whoever can create one object in any namespace can read every secret the platform keeps there, the archive of the hand-over among them. The reconciler of the single sign-on bridge also carries that read-everything grant without needing it.

**What changes.** The OpenBao grant of the cluster-wide store shrinks to the three key prefixes the platform uses and refuses the hand-over archive by name, and the sign-on bridge loses it. An admission rule refuses an ExternalSecret or a PushSecret of a platform namespace whose key lies outside that namespace's own prefix and the legacy prefixes listed for it. A gate check proves both on a running Sovereign and becomes required.

**Done means:**

- The OpenBao policy of the cluster-wide store grants read on the prefixes sso/, catalyst/ and openova/apps/ only, and denies the hand-over archive; the sign-on bridge role no longer carries it.
- The External Secrets stores chart renders an admission rule, its binding with the action Deny, and the list of legacy key prefixes of eight platform namespaces.
- An ExternalSecret in namespace default that names a key under sso/, or one in gitea that names the hand-over archive, is refused when it is created; namespaces of an Organization are not judged.
- The render test of the stores chart fails when the rule only warns, when a namespace is missing from the list, or when a listed prefix is malformed.
- Gate check SEC-G07 is required, and its tests prove that each of its five steps can fail.
- The threat model of the security document says what a namespace can read through the cluster-wide store now.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
On a Sovereign, the OpenBao policy `external-secrets-read`, which the ClusterSecretStore `vault-region1` reads with (auth role `external-secrets`), grants `read` on `secret/data/sso/*`, `secret/data/catalyst/*` and `secret/data/openova/apps/*` (and `read`, `list` on their metadata) and nothing else, and denies `secret/data/catalyst/tofu-phase0-archive` and its metadata. The auth role `sso-bridge` carries `sso-bridge-write` only. The chart bp-external-secrets-stores renders a `ValidatingAdmissionPolicy` and its binding, both named `external-secret-remote-key-scope`, and the ConfigMap `eso-legacy-key-map` in its release namespace. The rule refuses every create or update of an ExternalSecret or a PushSecret in a namespace without the label `openova.io/organization` whose OpenBao key does not start with `openova/apps/<namespace>/`, with `<namespace>/`, or with a prefix that the ConfigMap lists for the namespace. The gate check SEC-G07 (`tests/acceptance/sovereign/internal/suite/check_sec_scope.go`) proves the rule, the replay of every existing object through it, and the OpenBao refusal of the archive, in every region; it is `required` in `docs/ledger/gates.yaml`.

## 3. The model (the law)
1. The policy text `openbao.policy.external-secrets-read` in `platform/openbao/chart/templates/_config.tpl` holds exactly eight paths, written with the template variables `.kv` (the kv mount, `secret` by default) and `.apps` (`peerTrust.kvPathPrefix`, `openova/apps` by default): `<kv>/data/sso/*` read; `<kv>/metadata/sso/*` read, list; `<kv>/data/catalyst/*` read; `<kv>/metadata/catalyst/*` read, list; `<kv>/data/<apps>/*` read; `<kv>/metadata/<apps>/*` read, list; `<kv>/data/catalyst/tofu-phase0-archive` deny; `<kv>/metadata/catalyst/tofu-phase0-archive` deny. In OpenBao an exact path wins over a glob, and `deny` wins over every other capability, so the archive is refused although `catalyst/*` is readable.
2. The auth role `sso-bridge` (and its twin on the mount `kubernetes-vcluster`) carries the one policy `sso-bridge-write`. That policy already grants read on `sso/*`, the only prefix the sign-on bridge reconciler reads or writes.
3. The role `external-secrets` keeps both its policies, `external-secrets-read` and `external-secrets-push`. The push policy does not change.
4. `platform/external-secrets-stores/chart/templates/remote-key-scope-policy.yaml` renders the `ValidatingAdmissionPolicy` `external-secret-remote-key-scope`: `failurePolicy: Fail`; parameter kind `v1` `ConfigMap`; it matches `CREATE` and `UPDATE` of `externalsecrets` and `pushsecrets` in group `external-secrets.io`, every version. Its keys are: `spec.data[].remoteRef.key` (ExternalSecret), `spec.data[].match.remoteRef.remoteKey` (PushSecret), `spec.dataFrom[].extract.key`, `spec.dataFrom[].find.path`. A `find` without a path, or with an empty path, counts as the key `*`, which no rule admits: it would search the whole store. A `dataFrom` entry with neither `extract` nor `find` is a generator and names no key (the empty key, admitted). A key is admitted when it is empty, starts with `<appsPrefix>/<namespace>/`, starts with `<namespace>/`, or starts with one of the prefixes that the ConfigMap holds under the namespace's name.
5. The binding of the same name has `validationActions: ["Deny"]`, the parameter `eso-legacy-key-map` in the release namespace with `parameterNotFoundAction: Deny`, and `matchResources.namespaceSelector` with the one expression `openova.io/organization` `DoesNotExist`. So a namespace of an Organization is not judged: those namespaces are created at run time, and their keys carry the Organization's name (`sso/<realm>/...`, `catalyst/agenity/<organization>/...`), which a static list cannot hold. Their scope moves with package SEC-205. Nothing ever sets `failurePolicy: Ignore` or `validationActions` other than `Deny`.
6. `platform/external-secrets-stores/chart/templates/legacy-key-map.yaml` renders the ConfigMap `eso-legacy-key-map` in the release namespace (`external-secrets-system`, bootstrap-kit slot 15a). One data entry per namespace of the value `legacyKeyMap`; the entry's value is the namespace's prefixes joined by commas. The render fails when a namespace name is not a DNS label, when a value is not a list or is empty, and when a prefix does not end with `/` or holds a comma.
7. `legacyKeyMap` in `platform/external-secrets-stores/chart/values.yaml` holds exactly the platform namespaces whose ExternalSecrets or PushSecrets name a key outside their own prefix, with the first path segment of each such key: `gitea`, `grafana`, `harbor`, `kube-system`, `oidc-gate`, `openbao`, `powerdns-admin` each `sso/`; `newapi` `catalyst/` and `sso/`. Field 4 says how this list was measured. It only shrinks.
8. Gate check SEC-G07 records five steps per region: (1) a server-side dry run of an ExternalSecret in `default` with key `sso/sec-g07-probe` is refused by the rule; (2) one in `gitea` with key `catalyst/tofu-phase0-archive` is refused by the rule; (3) one in `gitea` with key `sso/sec-g07-probe` is admitted; (4) every ExternalSecret and PushSecret outside the namespaces labelled `openova.io/organization` is sent back as a server-side dry-run update and admitted, and there is at least one; (5) a 10-minute token of the service account that `vault-region1` names, logged in to OpenBao inside a running OpenBao server pod, gets a 403 on `<kv>/data/catalyst/tofu-phase0-archive` and no 403 and no error on `<kv>/data/sso/sec-g07-probe`. It stores nothing and prints no token and no value.
9. In `docs/ledger/gates.yaml` the entry SEC-G07 moves from `state: not-built` to `state: required` and gains `implementation: tests/acceptance/sovereign/internal/suite/check_sec_scope.go`. No other line of the file changes.
10. No ClusterSecretStore gains a `conditions` block, no namespace gets a label, and the hand-over archive does not move.

// Check SEC-G07, External Secrets scope. The admission rule
// external-secret-remote-key-scope of bp-external-secrets-stores limits the
// OpenBao key that an ExternalSecret or a PushSecret names, and the OpenBao
// policy of the cluster-wide store refuses the hand-over archive. In every
// region the check records five steps:
//
//  1. a server-side dry run of an ExternalSecret in namespace default with
//     the remote key sso/sec-g07-probe is refused by the rule;
//  2. one in namespace gitea with the key catalyst/tofu-phase0-archive is
//     refused by the rule;
//  3. one in namespace gitea with the key sso/sec-g07-probe is admitted, so
//     the rule reads its legacy map and does not refuse everything;
//  4. every ExternalSecret and PushSecret outside the namespaces of an
//     Organization (label openova.io/organization) passes the rule again on a
//     server-side dry-run update; with none to replay, nothing was measured;
//  5. inside an OpenBao server pod, a token of the identity of the store
//     vault-region1 gets HTTP 403 on <kv>/data/catalyst/tofu-phase0-archive
//     and no 403 on <kv>/data/sso/sec-g07-probe.
//
// A dry run stores nothing. Step 5 asks the API server for a token of the
// store's service account that lives 10 minutes, logs in to OpenBao with it
// in the pod (`kubectl exec`, the script on standard input), reads the two
// paths with their output thrown away, and revokes its OpenBao token.
const secScopeID = "SEC-G07"

const (
	secScopePolicy    = "external-secret-remote-key-scope" // the ValidatingAdmissionPolicy and its binding
	secScopeStore     = "vault-region1"                    // the cluster-wide store of the region
	secScopeProbe     = "sec-g07-probe"                    // name of the dry-run objects, last segment of the probe keys
	secScopeArchive   = "catalyst/tofu-phase0-archive"     // the hand-over archive
	secScopeOrgLabel  = "openova.io/organization"          // namespaces the rule does not judge
	secScopeBaoNS     = "openbao"                          // namespace of bp-openbao (bootstrap-kit slot 08)
	secScopeBaoPods   = "app.kubernetes.io/name=openbao,component=server"
	secScopeBaoTarget = "openbao" // the server container
	secScopeManager   = "sec-g07" // field manager of the dry-run updates
)

// secScopeScript runs in an OpenBao server pod as `sh -s`, after four
// assignments that the check puts in front of it: jwt, mount, role and kv.
// It prints name=value words and never a token or a value.
const secScopeScript = `class() {
	case "$1" in
	*"Code: 403"*) echo denied ;;
	*"No value found"*) echo absent ;;
	"") echo read ;;
	*) echo error ;;
	esac
}
token=$(bao write -field=token "auth/$mount/login" role="$role" jwt="$jwt" 2>/dev/null) || token=""
if [ -z "$token" ]; then
	echo login=failed
	exit 0
fi
echo login=ok
export BAO_TOKEN="$token"
echo "archive=$(class "$(bao read "$kv/data/catalyst/tofu-phase0-archive" 2>&1 >/dev/null)")"
echo "sso=$(class "$(bao read "$kv/data/sso/sec-g07-probe" 2>&1 >/dev/null)")"
if bao token revoke -self >/dev/null 2>&1; then echo revoked=yes; else echo revoked=no; fi
`

type secScopeCheck struct{ kubectl kubectlFunc }

func init() { RegisterCheck(secScopeCheck{kubectl: kube.Region.Run}) }

func (secScopeCheck) ID() string { return secScopeID }

func (c secScopeCheck) Run(ctx context.Context, cc *CheckContext, rec StepRecorder) error {
	if len(cc.Regions) == 0 {
		return errors.New("the run has no region")
	}
	n := 0
	step := func(name string, fn func(ev Evidence) error) {
		n++
		checkStep(rec, secScopeID, n, name, fn)
	}
	for _, region := range cc.Regions {
		step("the rule refuses remote key sso/"+secScopeProbe+" in namespace default of region "+region.ID, func(ev Evidence) error {
			return c.refused(ctx, region, ev, "default", "sso/"+secScopeProbe)
		})
		step("the rule refuses remote key "+secScopeArchive+" in namespace gitea of region "+region.ID, func(ev Evidence) error {
			return c.refused(ctx, region, ev, "gitea", secScopeArchive)
		})
		step("the rule admits remote key sso/"+secScopeProbe+" in namespace gitea of region "+region.ID, func(ev Evidence) error {
			ev["namespace"], ev["key"] = "gitea", "sso/"+secScopeProbe
			_, err := c.dryRunCreate(ctx, region, "gitea", "sso/"+secScopeProbe)
			return err
		})
		step("every ExternalSecret and PushSecret outside the Organizations passes the rule on update in region "+region.ID, func(ev Evidence) error {
			return c.replay(ctx, region, ev)
		})
		step("a token of the store "+secScopeStore+" gets 403 on the hand-over archive in region "+region.ID, func(ev Evidence) error {
			return c.openbao(ctx, region, ev)
		})
	}
	return nil
}

// probeExternalSecret is an ExternalSecret named secScopeProbe in ns that reads key through the store.
func probeExternalSecret(ns, key string) string {
	return fmt.Sprintf(`{"apiVersion": "external-secrets.io/v1beta1", "kind": "ExternalSecret",
  "metadata": {"name": %q, "namespace": %q},
  "spec": {"secretStoreRef": {"kind": "ClusterSecretStore", "name": %q}, "target": {"name": %q},
    "data": [{"secretKey": "probe", "remoteRef": {"key": %q}}]}}`, secScopeProbe, ns, secScopeStore, secScopeProbe, key)
}

func (c secScopeCheck) dryRunCreate(ctx context.Context, region kube.Region, ns, key string) ([]byte, error) {
	return c.kubectl(region, ctx, strings.NewReader(probeExternalSecret(ns, key)), "create", "--dry-run=server", "-f", "-")
}

// refused passes when the dry run of a probe ExternalSecret is refused by the rule, and only then.
func (c secScopeCheck) refused(ctx context.Context, region kube.Region, ev Evidence, ns, key string) error {
	ev["namespace"], ev["key"] = ns, key
	_, err := c.dryRunCreate(ctx, region, ns, key)
	if err == nil {
		return fmt.Errorf("the API server admitted an ExternalSecret in namespace %s with remote key %s", ns, key)
	}
	if !strings.Contains(err.Error(), "ValidatingAdmissionPolicy '"+secScopePolicy+"'") {
		return fmt.Errorf("the dry run failed, but not by the rule %s: %v", secScopePolicy, err)
	}
	ev["refused_by"] = secScopePolicy
	return nil
}

// replay sends every ExternalSecret and PushSecret outside the Organization
// namespaces back to the API server as a server-side dry-run update.
func (c secScopeCheck) replay(ctx context.Context, region kube.Region, ev Evidence) error {
	out, err := c.kubectl(region, ctx, nil, "get", "namespaces", "-l", secScopeOrgLabel, "-o", "jsonpath={.items[*].metadata.name}")
	if err != nil {
		return err
	}
	orgs := map[string]bool{}
	for _, name := range strings.Fields(string(out)) {
		orgs[name] = true
	}
	out, err = c.kubectl(region, ctx, nil, "get", "externalsecrets.external-secrets.io,pushsecrets.external-secrets.io", "--all-namespaces", "-o", "json")
	if err != nil {
		return err
	}
	var list kube.List
	if err := json.Unmarshal(out, &list); err != nil {
		return fmt.Errorf("the list of ExternalSecrets and PushSecrets is not JSON: %v", err)
	}
	replayed, skipped, refused := 0, 0, []string{}
	for _, o := range list.Items {
		if orgs[o.Namespace()] || o.Get("metadata", "deletionTimestamp") != nil {
			skipped++
			continue
		}
		replayed++
		body, err := json.Marshal(map[string]any{"apiVersion": o.Str("apiVersion"), "kind": o.Str("kind"),
			"metadata": map[string]any{"name": o.Name(), "namespace": o.Namespace()}, "spec": o.Get("spec")})
		if err != nil {
			return err
		}
		if _, err := c.kubectl(region, ctx, strings.NewReader(string(body)), "apply", "--server-side", "--dry-run=server",
			"--force-conflicts", "--field-manager="+secScopeManager, "-f", "-"); err != nil {
			refused = append(refused, fmt.Sprintf("%s %s/%s: %v", o.Str("kind"), o.Namespace(), o.Name(), err))
		}
	}
	sort.Strings(refused)
	ev["replayed"], ev["skipped_organization"], ev["refused"] = replayed, skipped, refused
	switch {
	case replayed == 0:
		return fmt.Errorf("no ExternalSecret or PushSecret outside the Organizations in region %s: nothing was measured", region.ID)
	case len(refused) > 0:

func (c secScopeCheck) openbao(ctx context.Context, region kube.Region, ev Evidence) error {
	out, err := c.kubectl(region, ctx, nil, "get", "clustersecretstore.external-secrets.io", secScopeStore, "-o", "json")
	if err != nil {
		return err
	}
	var store kube.Object
	if err := json.Unmarshal(out, &store); err != nil {
		return fmt.Errorf("the store %s is not JSON: %v", secScopeStore, err)
	}

	mount := store.Str("spec", "provider", "vault", "auth", "kubernetes", "mountPath")
	role := store.Str("spec", "provider", "vault", "auth", "kubernetes", "role")
	sa := store.Str("spec", "provider", "vault", "auth", "kubernetes", "serviceAccountRef", "name")
	saNS := store.Str("spec", "provider", "vault", "auth", "kubernetes", "serviceAccountRef", "namespace")
	ev["kv"], ev["mount"], ev["role"], ev["service_account"] = kv, mount, role, saNS+"/"+sa

		return fmt.Errorf("the store %s names no kv path, mount, role or service account with its namespace", secScopeStore)
	}
	out, err = c.kubectl(region, ctx, nil, "-n", secScopeBaoNS, "get", "pods", "-l", secScopeBaoPods,

		return err
	}
	pods := strings.Fields(string(out))
	if len(pods) == 0 {
		return fmt.Errorf("no running OpenBao server pod in namespace %s", secScopeBaoNS)
	}
	ev["pod"] = pods[0]
	out, err = c.kubectl(region, ctx, nil, "-n", saNS, "create", "token", sa, "--duration=10m")
	if err != nil {
		return err

	script := "jwt=" + shellQuote(jwt) + "\nmount=" + shellQuote(mount) + "\nrole=" + shellQuote(role) + "\nkv=" + shellQuote(kv) + "\n" + secScopeScript
	out, err = c.kubectl(region, ctx, strings.NewReader(script), "-n", secScopeBaoNS, "exec", "-i", pods[0], "-c", secScopeBaoTarget, "--", "sh", "-s")
	if err != nil {
		return err
	}

	switch {
	case v.one("login") != "ok":

		return fmt.Errorf("reading %s/data/sso/%s gave %q: the store cannot reach the prefix sso/", kv, secScopeProbe, v.one("sso"))
	}

}
