# NET-095 — Block the instance metadata address from pods

## In plain words

**The problem today.** A pod on a Sovereign can open a connection to the instance metadata address of its node, and no network policy of the platform denies it. The one policy chart that could carry the deny ships an all-or-nothing default deny. That default deny cut the console entry path when it was tried, so the chart is installed switched off.

**What changes.** The policy chart carries one object that denies the instance metadata address to every pod and changes no other traffic. Its three old default-deny objects stay in the chart and render only on request, so the chart can be switched on later without cutting anything.

**Done means:**

- With its default values the policy chart renders exactly one object: the deny of the instance metadata address.
- That object puts no pod under default deny, so every other connection of a pod stays as it was.
- A workload that must read the address is exempted by one label on its pod template.
- The three old default-deny objects render only when the legacy switch is set, and then they render as they did before.
- A chart test fails when one of these rules is broken, and the test proves on changed copies of the chart that it can fail.
- Nothing changes on a running Sovereign yet, because the kit still installs the chart switched off. Switching it on is a separate task.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The chart `bp-network-policies` (`platform/network-policies/chart`) ships the object `baseline-deny-metadata`: one `CiliumClusterwideNetworkPolicy` that denies egress from every pod to the instance metadata address `169.254.169.254` and does nothing else. With default values, `helm template` of the chart prints exactly this one object. The three objects the chart rendered until now (`00-default-deny`, `10-allow-system-namespaces`, `30-allow-egress-dns`) stay in the chart as a legacy set behind the new value `legacyBaseline.enabled`, which is `false` by default. A new chart test, `platform/network-policies/chart/tests/render.sh`, holds these rules and runs on every pull request that changes the chart and in the release build of the chart.

This ticket changes the chart only. The bootstrap kit still installs the chart with `enabled: false` (`clusters/_template/bootstrap-kit/26-network-policies.yaml`), so no Sovereign renders a policy from this chart before or after this ticket. Turning the chart on in the kit is a later package, for the reason given in item 6 of field 3.

## 3. The model (the law)
1. The object is exactly this, and nothing is added to it (no labels, no description):
   - `apiVersion: cilium.io/v2`, `kind: CiliumClusterwideNetworkPolicy`, `metadata.name: baseline-deny-metadata`.
   - `spec.endpointSelector.matchExpressions`: one expression, key `network.openova.io/metadata-access`, operator `NotIn`, values `["true"]`. A pod without the label is selected.
   - `spec.enableDefaultDeny`: `ingress: false` and `egress: false`. The object puts no pod under default deny.
   - `spec.egressDeny`: one rule, `toCIDR: ["169.254.169.254/32"]`.
2. The object renders when the chart value `enabled` is true, and only then. `enabled` stays `true` by default. `enabled: false` renders no object at all.
3. The exception is one pod label, `network.openova.io/metadata-access: "true"`, set in the pod template of a workload that must read the address. This ticket sets the label on no workload.
4. The new value `legacyBaseline.enabled` is a boolean with the default `false`.
5. The three legacy templates render only when `enabled` and `legacyBaseline.enabled` are both true: `default-deny.yaml` (object `00-default-deny`), `allow-system-namespaces.yaml` (object `10-allow-system-namespaces`, which also needs a list `allowSystemNamespaces` that is not empty, as before) and `allow-egress-dns.yaml` (object `30-allow-egress-dns`, which also needs `allowEgressDNS`, as before). With `legacyBaseline.enabled=true` they render exactly what the chart rendered by default before this ticket.
6. The kit slot `clusters/_template/bootstrap-kit/26-network-policies.yaml` is not changed. It keeps `values: enabled: false`. The reason: the slot pins the chart at a published version, and a pull request cannot move that pin. The published version `1.0.6` renders the three legacy objects when `enabled` is true, and together they put every pod of the cluster under default deny for egress. A slot that said `enabled: true` while its pin still named that version would cut traffic on a whole Sovereign. The pin moves only after this ticket is merged, when the release build publishes the changed chart.
7. No version line changes: not `version:` in `platform/network-policies/chart/Chart.yaml`, not `spec.version` in `platform/network-policies/blueprint.yaml`, not the pin in the kit slot. After the merge the release build (`.github/workflows/blueprint-release.yaml`) writes the next chart version and its pins by itself.
8. The chart test `platform/network-policies/chart/tests/render.sh` holds four rules and proves that it can fail:
   - R1: default values render exactly the object of item 1, compared line by line.
   - R2: `enabled=false` renders no object.
   - R3: `legacyBaseline.enabled=true` renders four objects named `00-default-deny`, `10-allow-system-namespaces`, `30-allow-egress-dns` and `baseline-deny-metadata`; with `allowEgressDNS=false` in addition, the object `30-allow-egress-dns` is gone.
   - R4: `enabled=false` with `legacyBaseline.enabled=true` renders no object.
   - Self-test: the test changes eight copies of the chart, each in one way that breaks a rule, and fails unless every copy is refused with the line of its rule.
9. Nothing is deleted. The legacy templates and the values they read stay in the chart; package NET-150 deletes them.
10. `docs/ledger/gates.yaml` is not changed. Gate check NET-G10 stays `not-built`: it asserts the result on a running Sovereign, and no Sovereign renders the object before the kit turns the chart on.

# render <chart> <out> [helm flags...]: helm template without the lines
# helm adds (`---`, comments) and without empty lines.
render() {
  local chart="$1" out="$2"
  shift 2
  helm template t "$chart" "$@" > "$out.raw" 2> "$out.err" || return 1
  grep -v -e '^---$' -e '^#' -e '^[[:space:]]*$' "$out.raw" > "$out" || true
}

# names <file>: the object names of a render, sorted, on one line.
names() {
  grep -E '^  name: ' "$1" | sed 's/^  name: //' | sort | tr '\n' ' ' | sed 's/ $//'
}

# ---- The test must be able to fail.
# mutant <name> <rule> <file> <sed expression>: copy the chart, change one
# file of the copy, and require that check_chart reports <rule> for it.
mutants=0
mutant() {
  local name="$1" rule="$2" file="$3" expr="$4" dir="$TMP/mutant-$1"
  cp -R "$CHART_DIR" "$dir"
  sed -i "$expr" "$dir/$file"
  if cmp -s "$dir/$file" "$CHART_DIR/$file"; then
    echo "FAIL: self-test $name: the change did not apply to $file; the test is out of date." >&2
    exit 1
  fi
  if check_chart "$dir" "$TMP/out-$name" > "$TMP/out-$name.txt" 2>&1; then
    echo "FAIL: self-test $name: a chart that breaks $rule passes." >&2
    exit 1
  fi
  if ! grep -q "^$rule: " "$TMP/out-$name.txt"; then
    echo "FAIL: self-test $name: expected a line for $rule, got:" >&2

    exit 1
  fi

}

if [ "$mutants" != "8" ]; then
  echo "FAIL: self-test ran $mutants changed copies, expected 8." >&2
  exit 1
fi
echo "  PASS: self-test, 8 changed copies of the chart each fail their rule"
echo "[render] all green."
