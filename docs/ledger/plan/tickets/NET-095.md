# NET-095 — Policy chart: only the deny of the instance metadata address by default

## In plain words

**The problem today.** A pod on a Sovereign can open a connection to the instance metadata address of its node, and no network policy of the platform denies it. The one policy chart that could carry the deny ships an all-or-nothing default deny. That default deny cut the console entry path when it was tried, so the chart is installed switched off.

**What changes.** The policy chart carries one object that denies the instance metadata address to every pod and changes no other traffic, and its function test proves that deny. Its three old default-deny objects stay in the chart and render only on request, so the chart can be switched on later without cutting anything.

**Done means:**

- With its default values the policy chart renders exactly one policy object, the deny of the instance metadata address, and its test Pod.
- That object puts no pod under default deny, so every other connection of a pod stays as it was.
- A workload that must read the address is exempted by one label on its pod template.
- The function test of the chart passes when a pod cannot connect to the instance metadata address, and fails when it can.
- The three old default-deny objects render only when the legacy switch is set, and then they render as they did before.
- A chart test fails when one of these rules is broken, and the test proves on changed copies of the chart that it can fail.
- Nothing changes on a running Sovereign yet, because the kit still installs the chart switched off. Switching it on is a separate task.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The chart `bp-network-policies` (`platform/network-policies/chart`) ships the object `baseline-deny-metadata`: one `CiliumClusterwideNetworkPolicy` that denies egress from every pod to the instance metadata address `169.254.169.254` and does nothing else. With default values, `helm template --skip-tests` of the chart prints exactly this one object, and `helm template` prints it and the chart's helm test Pod. The test Pod now proves this deny: from a pod without the exception label, cluster DNS resolves and a connection to `http://169.254.169.254/` is not made. The three objects the chart rendered until now (`00-default-deny`, `10-allow-system-namespaces`, `30-allow-egress-dns`) stay in the chart as a legacy set behind the new value `legacyBaseline.enabled`, which is `false` by default. A new chart test, `platform/network-policies/chart/tests/render.sh`, holds these rules and runs on every pull request that changes the chart and in the release build of the chart.

This ticket changes the chart only. The bootstrap kit still installs the chart with `enabled: false` (`clusters/_template/bootstrap-kit/26-network-policies.yaml`), so no Sovereign renders a policy from this chart before or after this ticket. Turning the chart on in the kit is package NET-096, for the reason given in item 8 of field 3.

## 3. The model (the law)
1. The object is exactly this, and nothing is added to it (no labels, no description):
   - `apiVersion: cilium.io/v2`, `kind: CiliumClusterwideNetworkPolicy`, `metadata.name: baseline-deny-metadata`.
   - `spec.endpointSelector.matchExpressions`: one expression, key `network.openova.io/metadata-access`, operator `NotIn`, values `["true"]`. A pod without the label is selected.
   - `spec.enableDefaultDeny`: `ingress: false` and `egress: false`. The object puts no pod under default deny.
   - `spec.egressDeny`: one rule, `toCIDR: ["169.254.169.254/32"]`.
2. The object renders when the chart value `enabled` is true, and only then. `enabled` stays `true` by default. `enabled: false` renders nothing at all, test Pod included.
3. The exception is one pod label, `network.openova.io/metadata-access` with the value `"true"`, set in the pod template of a workload that must read the address. This ticket sets the label on no workload. The secret guard G10 (`scripts/secret-object-register.py`, rule e) refuses a chart whose templates or `values.yaml` carry that label in the form `<key>: "true"` on a line that is not a comment, unless the register has a `metadataAccess` entry for the chart. So the header comment of `baseline-deny-metadata.yaml` names the label and its value in words, and the one line of `values.yaml` that shows the form starts with `#`.
4. The new value `legacyBaseline.enabled` is a boolean with the default `false`.
5. The three legacy templates render only when `enabled` and `legacyBaseline.enabled` are both true: `default-deny.yaml` (object `00-default-deny`), `allow-system-namespaces.yaml` (object `10-allow-system-namespaces`, which also needs a list `allowSystemNamespaces` that is not empty, as before) and `allow-egress-dns.yaml` (object `30-allow-egress-dns`, which also needs `allowEgressDNS`, as before). With `legacyBaseline.enabled=true` they render exactly what the chart rendered by default before this ticket.
6. The function test (`templates/tests/function-test.yaml`) proves the function the chart has now, the deny of the address. It renders whenever `enabled` is true, with and without the legacy switch. Its Pod runs in `functionTest.namespace` (default `default`) and carries no exception label. It makes two requests with curl. First `https://kubernetes.default.svc.cluster.local:443/version`: only the name lookup is judged, and exit code 6 (name not resolved) fails the test, because a pod with no working network would make the second request prove nothing; any other exit code passes this request, since the legacy set may deny the connection itself. Then `http://169.254.169.254/` with a connect timeout of 5 seconds: exit code 28 (timed out) or 7 (refused) passes; exit code 0 (the address answered) fails with the reason that the deny does not hold; any other exit code fails with that code. The contract of the test file (one Pod, the hook annotations, the label `catalyst.openova.io/function-test`, the lines `FUNCTION-TEST pass` and `FUNCTION-TEST fail`) is unchanged, and `scripts/check-function-test.py` still judges it.
7. Its render check `tests/function-test-render.sh` holds four cases: the default render carries the test (in namespace `default`, dialling the address, demanding exit code 28 or 7, naming no exception label, mounting no token) beside `baseline-deny-metadata`; `legacyBaseline.enabled=true` still carries the test; `enabled=false` carries no test, with and without the legacy switch. The two cases of the old file that no longer hold go: the test no longer depends on `allowEgressDNS`, and the test namespace may be any namespace.
8. The kit slot `clusters/_template/bootstrap-kit/26-network-policies.yaml` is not changed. It keeps `values: enabled: false`. The reason: the slot pins the chart at a published version, and a pull request cannot move that pin. The published versions up to now render the three legacy objects when `enabled` is true, and together they put every pod of the cluster under default deny for egress. A slot that said `enabled: true` while its pin still named such a version would cut traffic on a whole Sovereign. The pin moves only after this ticket is merged, when the release build publishes the changed chart; package NET-096 then switches the slot on.
9. No version line changes: not `version:` in `platform/network-policies/chart/Chart.yaml`, not `spec.version` in `platform/network-policies/blueprint.yaml`, not the pin in the kit slot. After the merge the release build (`.github/workflows/blueprint-release.yaml`) writes the next chart version and its pins by itself.
10. The chart test `platform/network-policies/chart/tests/render.sh` holds four rules and proves that it can fail. R1 and R3 judge the render without the test Pod (`helm template --skip-tests`); R2 and R4 judge the whole render.
    - R1: default values render exactly the object of item 1, compared line by line.
    - R2: `enabled=false` renders nothing.
    - R3: `legacyBaseline.enabled=true` renders four objects named `00-default-deny`, `10-allow-system-namespaces`, `30-allow-egress-dns` and `baseline-deny-metadata`; with `allowEgressDNS=false` in addition, the object `30-allow-egress-dns` is gone.
    - R4: `enabled=false` with `legacyBaseline.enabled=true` renders nothing.
    - Self-test: the test changes nine copies of the chart, each in one way that breaks a rule, and fails unless every copy is refused with the line of its rule.
11. Nothing is deleted. The legacy templates and the values they read stay in the chart; package NET-150 deletes them.
12. `docs/ledger/gates.yaml` is not changed. Gate check NET-G10 is built and flipped by package NET-097, after the kit has turned the chart on.

# render <chart> <out> [helm flags...]: helm template without the lines
# helm adds (`---`, comments) and without empty lines. An empty render is
# a valid result, so the exit code 1 of grep for no line is not an error.
render() {
  local chart="$1" out="$2"
  shift 2
  helm template t "$chart" "$@" > "$out.raw" 2> "$out.err" || return 1
  grep -v -e '^---$' -e '^#' -e '^[[:space:]]*$' "$out.raw" > "$out" || true
}

# names <file>: the object names of a render, sorted, on one line.
names() {
  grep -E '^  name: ' "$1" | sed 's/^  name: //' | sort | tr '\n' ' ' | sed 's/ $//'
}

# returns 1 when a rule is broken.
check_chart() {
  local chart="$1" w="$2" bad=0

    echo "R1: the default render failed: $(cat "$w/default.yaml.err")"
    return 1

    echo "R1: the default render is not exactly the object baseline-deny-metadata"
    bad=1
  fi

    echo "R2: the render with enabled=false failed: $(cat "$w/off.yaml.err")"
    return 1
  fi

    echo "R2: enabled=false still renders: $(names "$w/off.yaml")"
    bad=1

mutants=0
mutant() {

}
