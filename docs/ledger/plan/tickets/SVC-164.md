# SVC-164 — Delete the OpenMeter Blueprint

## In plain words

**The problem today.** The repository still carries a Blueprint for OpenMeter, a usage-metering engine the platform does not use: billing is done by the platform's own chargeback component. The catalogue that every Sovereign installs lists it as an Application anyone may pick, the setup wizard offers it as a card and even pre-selects it for some organisation profiles, and the marketplace describes it as part of the observability family.

**What changes.** The Blueprint folder is deleted and recorded as deleted. The wizard, the marketplace copy and the catalogue files no longer name it, and the two guard baselines that counted it are lowered by the guards' own commands.

**Done means:**

- The folder platform/openmeter does not exist and is on the list of deleted paths, so a change that brings it back turns its pull request red.
- The catalogue read by the console, the platform API and every Sovereign holds no OpenMeter entry, and every other Blueprint stays.
- The setup wizard offers no OpenMeter card and pre-selects it for no profile; the marketplace pages do not mention it.
- The image build no longer checks for an OpenMeter logo.
- The service-model guard and the network-policy guard pass with their baselines lowered by what the deleted files carried, and every step of the tree guards passes.

The rest of this ticket is the exact instruction for the model that does the work.
