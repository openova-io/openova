# CLD-062 — Crossplane 1.19 to 1.20

## In plain words

**The problem today.** The platform installs Crossplane core 1.19.3. The road to Crossplane 2 goes one minor version at a time, and the second step, to the 1.20 line, has not been taken. Every later Crossplane step waits for it.

**What changes.** The Crossplane chart installs core 1.20.14, the highest patch of the 1.20 line, through the same registry route as before. Its chart test expects the new image tag.

**Done means:**

- The Crossplane chart pulls the upstream chart at version 1.20.14.
- Every Crossplane core container image still comes through the registry proxy, now with the tag v1.20.14.
- The chart test fails when the rendered image tag is not v1.20.14 or when an image leaves the proxy route.
- No setting of the chart other than the upstream version changes.
- The gate check of the Crossplane upgrade passes on the first candidate that carries the change.

The rest of this ticket is the exact instruction for the model that does the work.
