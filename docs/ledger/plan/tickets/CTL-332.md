# CTL-332 — The service modules no longer require the Kafka client

## In plain words

**The problem today.** The Organization services no longer build a Kafka client, and the shared events package no longer contains one. Yet the dependency files of eight service modules still list the Kafka client library and its two helper libraries, and two of them carry other requirements that no code needs any more. Two source files of the controllers' bus package still explain themselves by a Kafka transport and a Redpanda setting that are gone.

**What changes.** The dependency files of the eight modules are exactly what the Go tool writes when it tidies them, and none lists the Kafka libraries. The comments of the controllers' bus package describe the code as it is.

**Done means:**

- No go.mod or go.sum file of the repository lists the Kafka client library or the compression library it needed.
- The Go tool reports nothing to tidy in each of the eight service modules, and each of them builds and passes its vet run.
- No Go file of the repository names the Kafka client library, and no file under core names the Redpanda setting.
- The controllers' bus package names no Kafka word in its comments, and it builds and passes its vet run.
