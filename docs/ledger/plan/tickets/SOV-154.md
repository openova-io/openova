# SOV-154 — First boot applies one root Kustomization; its children come from Git

## In plain words

**The problem today.** First boot still writes five Flux Kustomizations into the control-plane user data, which is close to the size the clouds accept, although the same five are already files in Git. Every change to one of them has to change the boot template, and the template has to name a provider to pick the right certificate folder.

**What changes.** First boot applies one small root Kustomization that points at the folder for its kind of region; Flux takes the five Kustomizations from that folder. The tests and checks that read the five now read them from the folder, and the check that compared the folder with the template is removed.

**Done means:**

- The Flux bootstrap document that a new control plane receives holds one Kustomization, sovereign-root, and none of the five that it held before.
- The root points at a folder that exists in the repository: the shared folder of its region layout and role, or the role folder of its provider's overlay.
- The boot template names no provider any more.
- The checks that read the five Kustomizations (dependencies, timeouts and wait, render equivalence, kit substitution, the follower test of the cutover chart) read them from the folder and pass.
- The local pack still installs its reduced kit: the root of each of its regions patches the path of bootstrap-kit.
- The worst-case control-plane user data is smaller on every surface, and no entry is packed to make room.

The rest of this ticket is the exact instruction for the model that does the work.

1. 3. Decided here, following the order SOV-146's parity check used: the folder of a pack's overlay serves every layout. No new key of `sovereign-variables` is added.
4. The template tests no provider name: the one test it had, in the path line of sovereign-tls, leaves with that block.
5. The local pack (`infra/providers/local/main.tf`) inserts before the root's path line a `patches` entry that sets the path of the child `bootstrap-kit` to `./clusters/_template/providers/local/kit`; its precondition requires that path line once.
