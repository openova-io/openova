# FND-097 — Remove the unshipped console, the one job that drives it and the tests that only target it

## In plain words

**The problem today.** A second console sits in the repository beside the console that is shipped. It was a scaffold. No image is built from it and no chart installs it. One test job still builds it on pull requests, a second workflow installs and starts it only for four test cases that skip themselves, and one Go test reads a file of it. This costs test time and misleads a reader about where the console is.

**What changes.** The scaffold folder is deleted, together with the test job that builds it, the workflow steps that start it and the four test cases written for it. The guide for agents counts three front-end trees instead of four.

**Done means:**

- The folder of the unshipped console is gone. The list of deleted paths names it, so a pull request that brings it back turns red.
- The workflow that tests the storefront and the sovereign-admin console on pull requests keeps its two other jobs unchanged. The 21 specification files of the sovereign-admin console still run there.
- The smoke workflow no longer installs or starts the scaffold. Its other steps are unchanged.
- The two specification files that had cases for the scaffold keep their case for a live Sovereign.
- No test reads a file of the deleted folder, and the tests of the Blueprint validator pass.
- The guide for agents names three front-end trees.

The rest of this ticket is the exact instruction for the model that does the work.
