# INF-053 — Capability flag node-reboot: a gate run restarts nodes only when it declares the flag

## In plain words

**The problem today.** The gate check of coordinated reboots restarts three nodes in each region, which can take most of a gate run. It must run only in a gate run that asks for it. The gate already skips a check that needs something a run does not declare, but the flag that would mark this check does not exist yet, and the gate tool refuses any flag that is not in its closed list.

**What changes.** The gate tool accepts the flag node-reboot, in the needs of a check and in the capabilities of a gate record. The comment above the list states who adds a flag.

**Done means:**

- The closed list of capability flags in the gate tool holds node-reboot once.
- A manifest entry whose needs is node-reboot passes the manifest rules of the gate tool.
- A gate record that declares node-reboot passes the record validation.
- The gate tool's self-test and the validation of the manifest on main still pass.
- The comment above the list no longer says that a plan change adds a flag.

The rest of this ticket is the exact instruction for the model that does the work.
