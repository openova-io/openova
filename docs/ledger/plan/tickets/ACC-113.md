# ACC-113 — The sign-in probe no longer expects the removed remote-access web page

## In plain words

**The problem today.** The sign-in check of the live gate still visits the web page of the remote-access application, although that web application was removed. The page now answers HTTP 404, so the check fails on that row in every gate run, whatever the state of the other applications.

**What changes.** The probe of the sign-in check no longer has that row. It visits the ten applications a Sovereign serves, and its result and summary count those ten.

**Done means:**

- The sign-in probe has no row and no marker that names the remote-access web application.
- The probe visits exactly ten applications, in the same order as before, and every other row is unchanged.
- The probe still parses, and its hubble row still holds on the page that hubble-ui shows.
- The count and the summary line of the probe's result follow from its list of applications, so no other text of the probe had to change.
