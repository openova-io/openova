# SEC-211 — Blueprint bp-secrets-store-csi and the injection negative check

## In plain words

**The problem today.** OpenBao copies every value it holds into a Kubernetes Secret object, because no Sovereign has a way to put a value straight into a running workload. So every Application credential also rests in the cluster store, where anyone who can read Secrets in that namespace can read it.

**What changes.** Every Sovereign installs the Secrets Store CSI driver with Secret sync switched off, and OpenBao runs its CSI provider beside it. A gate check proves on every region that a value mounted into a Pod is never copied into a Secret object and that only the Pod's own identity can read it.

**Done means:**

- A fresh Sovereign runs the Secrets Store CSI driver on every node, installed after OpenBao, and the OpenBao CSI provider beside it.
- The driver has no right to create, read or change a Secret object.
- A mounted value is re-read once an hour, and the driver logs in to OpenBao with a token of the Pod's own service account.
- No SecretProviderClass in the repository copies a mounted value into a Secret.
- Gate check SEC-G08 is required: on every region a canary mounted into a Pod is in the Pod's file, in no Secret object, and refused to any other service account.

The rest of this ticket is the exact instruction for the model that does the work.

Gate check SEC-G08 (`check_sec_inject.go`) is `required`: per region it births a canary in OpenBao by role `eso-ns`, mounts it in a Pod through the driver, and asserts that the file holds it, that no Secret holds it, that the driver's service account cannot create a Secret, and that a token of another service account gets 403 on its path while the reader's own token reads it.

## 3. The model (the law)
1. The driver never creates a Secret: `syncSecret.enabled` is `false`, no Role or ClusterRole of the render names the resource `secrets`, and no `SecretProviderClass` under `platform/` or `products/` sets `secretObjects`.
2. The driver re-reads every mounted object every `3600s` (`enableSecretRotation: true`, `rotationPollInterval: 3600s`).
3. The kubelet hands the driver a token of the Pod's service account with audience `openbao` (`tokenRequests: [{audience: openbao}]`); a `SecretProviderClass` names provider `openbao`, `openbaoAddress`, `roleName: workload` and `audience: openbao` (the parameter names measured in `docs/ledger/plan/spikes/SEC-140.md`).
4. Every container image of slot 15b and of the CSI provider of slot 08 comes through the Harbor proxy, and every container declares cpu and memory requests (the kyverno policies `harbor-proxy-pull` and `resource-requests`).
5. Slot 15b depends on `bp-openbao` only; its placement row is `host` with a justification.
6. The provider's own Secret `openbao/openbao-csi-provider-hmac-key` has a register entry; nothing else of this package creates a Secret.
7. Gate check SEC-G08 writes no token and no canary to its evidence, uses a namespace of its own per region (`sec-g08-<run id>`) and deletes the canary's key and the namespace also when a step failed.

+# bp-secrets-store-csi
+
+The Secrets Store CSI driver: it mounts values from OpenBao into a Pod as
+memory-backed files, and never copies them into a Secret object.
+
+## Role in Catalyst
+
+Control-plane plumbing, installed on every region by bootstrap-kit slot 15b
+(`clusters/_template/bootstrap-kit/15b-bp-secrets-store-csi.yaml`) as
+HelmRelease `bp-secrets-store-csi` in namespace `kube-system` (the upstream default). Never a
+catalog item (`visibility: unlisted`). It is the injection mechanism of
+[`docs/adr/0018-secrets-and-trust.md`](../../docs/adr/0018-secrets-and-trust.md):
+an Application credential is delivered into the running workload from OpenBao
+and never becomes a Kubernetes Secret object. See
+[`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md) for the bootstrap kit.
+
+The driver talks to OpenBao through the OpenBao CSI provider, a DaemonSet of
+the bp-openbao chart that slot 08 switches on (`openbao.csi.enabled: true`).
+The slot depends on `bp-openbao`.
+
+## Configuration
+
+The chart wraps the upstream chart `secrets-store-csi-driver` 1.6.2; its
+values sit under the key `secrets-store-csi-driver:` of `chart/values.yaml`.
+
+| Value | Setting | Why |
+|---|---|---|
+| `syncSecret.enabled` | `false` | The driver gets no right on Secret objects. Never switch it on. |
+| `enableSecretRotation`, `rotationPollInterval` | `true`, `3600s` | One re-read an hour, equal to the default lease of a dynamic database user. |
+| `tokenRequests` | `[{audience: openbao}]` | The kubelet hands the driver the Pod's token for OpenBao role `workload`. |
+| images | `harbor.openova.io/proxy-k8s/...` | Admitted by the Harbor proxy pull policy; pivoted to the Sovereign's own Harbor at cutover. |
+
+A workload mounts a value with a `SecretProviderClass` of provider `openbao`
+(parameters `openbaoAddress`, `roleName: workload`, `audience: openbao`,
+`objects`) and a CSI volume of driver `secrets-store.csi.k8s.io`. A
+`SecretProviderClass` never names a Secret to sync the value into.
+

+	out, err := c.kubectl(region, ctx, nil, "get", "secrets", "--all-namespaces", "-o", "json")

+		} `json:"items"`
+	}

+		return fmt.Errorf("the list of Secrets is not JSON: %v", err)

+			}
+		}
+	}
+	ev["secrets"], ev["values"], ev["holders"] = len(list.Items), values, holders
+	switch {
+	case values == 0:
+		return fmt.Errorf("no Secret value was listed in region %s: nothing was measured", region.ID)
+	case len(holders) > 0:
+		return fmt.Errorf("the canary is in %d Secret values: %s", len(holders), strings.Join(holders, "; "))
+	}
+	return nil
