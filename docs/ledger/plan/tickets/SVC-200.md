# SVC-200 — Catalogue edits may change card fields only

## In plain words

**The problem today.** A catalogue edit in the console can change any field of a Blueprint, its version, class, source or topology, although those fields have one writer, the Blueprint's own source. The whole-document editor commits a version bump, a curate overwrites a live Blueprint with another version, and a first card edit whose live Blueprint cannot be read invents a minimal one. Nothing checks the result against the Blueprint schema before the commit.

**What changes.** Every route that commits an edited or curated Blueprint compares the result with the live Blueprint, refuses a change outside the card fields and visibility with 422 contract-field-read-only naming the paths, and validates the result against the Blueprint schema. A live Blueprint that cannot be read is a 502, and a refusal leaves nothing written.

**Done means:**

- A save in Edit IaC that changes the version, the class or the manifests of a live Blueprint answers 422 contract-field-read-only naming that path, and nothing is committed.
- A curate over a live Blueprint from a source at another version answers 422, and the live Blueprint stays as it was.
- A card save whose topologies differ from the live Blueprint answers 422 before anything reaches the commerce store; a title edit still reaches the store and Git.
- When the live Blueprint cannot be read, a card save answers 502 and writes nothing.
- A result that the Blueprint schema refuses is never committed, and the API tests run when that schema changes.
- The browser gate row 154 expects the refusal of a version edit.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this package a catalogue write can change only what a catalogue edit owns: the card (`spec.card.title`, `tagline`, `summary`, `description`, `icon` with its two variants `iconLight` and `iconDark`) and `spec.visibility`. Every other field of a Blueprint (version, class, lifecycle, source, manifests, topology, labels) has one writer, the Blueprint's own source. The three handlers that commit a Blueprint into `catalog-sovereign` (the card edit behind the commerce proxy, the full-document Edit IaC route `PUT /api/v1/catalog/{name}/iac`, and curate `POST /api/v1/sovereigns/{id}/blueprints/curate`) compare the result with the live Blueprint and answer 422 `contract-field-read-only`, with the changed paths, for any other change; the result is then validated against the Blueprint schema (contract C1, `platform/_schemas/blueprint.schema.json`, embedded as a copy that a test keeps equal) and a refused result answers 422 `blueprint-schema-invalid`. A live Blueprint that cannot be read answers 502 and is never taken for "absent". Every check runs before the commerce store write and before the Gitea Org and repository are ensured, so a refusal leaves nothing behind. The browser gate row 154 proves the refusal of a version edit.

## 3. The model (the law)
1. The editable paths are exactly `spec.card.title`, `spec.card.tagline`, `spec.card.summary`, `spec.card.description`, `spec.card.icon`, `spec.card.iconLight`, `spec.card.iconDark` and `spec.visibility` (`blueprintedit.Editable`). A path below an editable path is editable.
2. `blueprintedit.Check(live, proposed)` compares the two documents key by key. A key that holds a dot (`card.title` directly under `spec`) is never taken for an editable path. A mapping absent on one side compares as an empty mapping. Every other path whose value differs is refused with `ContractFieldError`, its paths sorted.
3. After the comparison the proposed document is validated against the embedded schema; a failure is `SchemaError` with every failing leaf, sorted. With no live Blueprint only the schema is checked, so a card edit with no live Blueprint (the merge would invent a `0.0.0` Blueprint with no class) is refused.
4. `blueprintedit.Answer` writes 422 `{"error":"contract-field-read-only","detail":…,"paths":[…]}` for a `ContractFieldError`, 422 `{"error":"blueprint-schema-invalid","detail":…}` for a `SchemaError`, and 502 `{"error":"gitea-upstream","detail":…}` for any other error.
5. The live Blueprint is `catalog-sovereign/<repo>/blueprint.yaml`, else the catalog client's full object, in the form the commit legs write (`liveCatalogBlueprint`). A failed read of either is an error (502), never "absent"; a file that does not parse reaches `Check`, which reports it as a read error. Only not-found from both means no live Blueprint.
6. The card edit (`writeCatalogEditToGit`, and `proxyCommerce` for `apps` before the store write), Edit IaC (`HandleCatalogBlueprintIaCEdit`) and curate (`HandleBlueprintCurate`) call the check before any write. Before the store write the commerce proxy stops on a contract-field refusal or a read error; a schema refusal there (no live Blueprint) is reported by the commit that follows the store write, as the git verdict is today.
7. `seedBlueprintYAMLFromLiveCR`, whose read swallowed every error, is deleted; `liveCatalogBlueprint` replaces it. The handler package's method count falls from 614 to 613, written into `scripts/baselines/api-structure.json` by the guard's own tool, never by hand.
8. `internal/blueprintedit/blueprint.schema.json` equals `platform/_schemas/blueprint.schema.json` byte for byte (`TestSchemaCopyMatchesSource`), and the API test workflow runs when that source changes.
9. No new Python, and no change to a live system.

+// Package blueprintedit decides whether a catalogue write may change a
+// Blueprint. Every field outside the card (version, class, source, topology,
+// labels...) has one writer: the Blueprint's own source. Check refuses a write
+// that changes another path of the live object than Editable, then validates
+// the result against blueprint.schema.json (contract C1), embedded as a copy
+// of platform/_schemas/blueprint.schema.json that a test keeps equal.
+package blueprintedit

+	"bytes"
+	_ "embed"

+//go:embed blueprint.schema.json
+var schemaJSON []byte

+// Editable lists the paths a catalogue edit may change (iconLight and
+// iconDark are the two variants of the card icon).
+var Editable = []string{"spec.card.title", "spec.card.tagline", "spec.card.summary", "spec.card.description",
+	"spec.card.icon", "spec.card.iconLight", "spec.card.iconDark", "spec.visibility"}
+
+// ContractFieldError refuses a write that changes a path outside Editable.
+type ContractFieldError struct{ Paths []string }
+
+func (e *ContractFieldError) Error() string {
+	return "contract-field-read-only: the write changes " + strings.Join(e.Paths, ", ") +
+		"; a catalogue edit may change only the card fields and spec.visibility"
+}
+
+// SchemaError refuses a result that blueprint.schema.json does not accept.
+type SchemaError struct{ Detail string }
+
+func (e *SchemaError) Error() string { return "blueprint-schema-invalid: " + e.Detail }
+
+// Check returns nil when proposed may be committed over live, both Blueprint
+// YAML in the committed form. An empty live is no live object: then only the
+// schema is checked. A live that is not empty and does not read as a mapping
+// is an error that is neither refusal type, so Answer reports it as 502.
+func Check(live, proposed []byte) error {
+	var l map[string]interface{}
+	if len(bytes.TrimSpace(live)) > 0 {
+		var err error
+		if l, err = decode(live); err != nil {
+			return errors.New("the live Blueprint cannot be read: " + err.Error())
+		}
+	}
+	p, err := decode(proposed)
+	if err != nil {
+		return &SchemaError{Detail: err.Error()}
+	}
+	if l != nil {
+		var refused []string
+		if diff(nil, l, p, &refused); len(refused) > 0 {
+			sort.Strings(refused)
+			return &ContractFieldError{Paths: refused}
+		}
+	}
+	return validate(p)
+}
+
+// Answer writes the HTTP answer for the error of a write check and reports
+// whether it wrote: 422 for a refusal of Check, 502 gitea-upstream for any
+// other error (the live object could not be read), nothing for nil.
+func Answer(w http.ResponseWriter, err error) bool {
+	var cf *ContractFieldError
+	var se *SchemaError
+	code, body := http.StatusUnprocessableEntity, map[string]interface{}{"error": "gitea-upstream"}
+	switch {
+	case err == nil:
+		return false
+	case errors.As(err, &cf):
+		body = map[string]interface{}{"error": "contract-field-read-only", "detail": cf.Error(), "paths": cf.Paths}
+	case errors.As(err, &se):
+		body["error"], body["detail"] = "blueprint-schema-invalid", se.Detail
+	default:
+		code, body["detail"] = http.StatusBadGateway, err.Error()
+	}
+	w.Header().Set("Content-Type", "application/json")
+	w.WriteHeader(code)
+	_ = json.NewEncoder(w).Encode(body)
+	return true
+}
+
+// decode reads one YAML mapping as the JSON value tree that both sides of a
+// comparison and the schema validator read.
+func decode(raw []byte) (map[string]interface{}, error) {
+	var y interface{}
+	if err := yamlv3.Unmarshal(raw, &y); err != nil {
+		return nil, err
+	}
+	js, err := json.Marshal(y)
+	if err != nil {
+		return nil, err
+	}
+	var m map[string]interface{}
+	dec := json.NewDecoder(bytes.NewReader(js))
+	dec.UseNumber()
+	if err := dec.Decode(&m); err != nil || m == nil {
+		return nil, errors.New("the document is not a mapping")
+	}
+	return m, nil
+}
+
+// diff appends each path outside Editable whose value differs between a and
+// b; a map absent on one side compares as an empty map. A path is compared
+// key by key, so a key that holds a dot ("card.title" under spec) is never
+// taken for an editable path.
+func diff(path []string, a, b interface{}, out *[]string) {
+	am, aok := a.(map[string]interface{})
+	bm, bok := b.(map[string]interface{})
+	if (aok || bok) && (aok || a == nil) && (bok || b == nil) {
+		for k, v := range am {
+			diff(append(path[:len(path):len(path)], k), v, bm[k], out)
+		}
+		for k, v := range bm {
+			if _, seen := am[k]; !seen {
+				diff(append(path[:len(path):len(path)], k), nil, v, out)
+			}
+		}
+		return
+	}
+	for _, e := range Editable {
+		if within(path, strings.Split(e, ".")) {
+			return
+		}
+	}
+	if !reflect.DeepEqual(a, b) {
+		*out = append(*out, strings.Join(path, "."))
+	}
+}
+
+// within reports whether path is the editable path e or lies below it.
+func within(path, e []string) bool {
+	if len(path) < len(e) {
+		return false
+	}
+	for i := range e {
+		if path[i] != e[i] {
+			return false
+		}
+	}
+	return true
+}
+
+var (
+	schemaOnce sync.Once
+	schema     *jsonschema.Schema
+	schemaErr  error
+)
+
+// validate checks doc against the embedded schema; the detail lists every
+// failing leaf, sorted.
+func validate(doc map[string]interface{}) error {
+	schemaOnce.Do(func() {
+		c := jsonschema.NewCompiler()
+		c.Draft = jsonschema.Draft2020
+		if schemaErr = c.AddResource("file:///blueprint.schema.json", bytes.NewReader(schemaJSON)); schemaErr == nil {
+			schema, schemaErr = c.Compile("file:///blueprint.schema.json")
+		}
+	})
+	var ve *jsonschema.ValidationError
+	if schemaErr != nil {
+		return &SchemaError{Detail: "the embedded schema does not compile: " + schemaErr.Error()}
+	} else if err := schema.Validate(doc); !errors.As(err, &ve) {
+		return err
+	}
+	var leaves []string
+	var walk func(*jsonschema.ValidationError)
+	walk = func(e *jsonschema.ValidationError) {
+		if len(e.Causes) == 0 {
+			leaves = append(leaves, "at '"+e.InstanceLocation+"': "+e.Message)
+		}
+		for _, c := range e.Causes {
+			walk(c)
+		}
+	}
+	walk(ve)
+	sort.Strings(leaves)
+	return &SchemaError{Detail: strings.Join(leaves, "; ")}
+}
