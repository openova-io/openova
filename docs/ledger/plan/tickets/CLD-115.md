# CLD-115 — The VPC pre-flight becomes the Huawei adapter's Preflighter

## In plain words

**The problem today.** Before the first OpenTofu step the provisioning engine checks the VPC quota of one cloud itself: it calls two hook variables that only that cloud's adapter sets, behind a check of that cloud's name, and it holds the quota decision in its own package. It is the last of the engine's hook variables that one cloud sets.

**What changes.** The cloud adapter runs its own check before the first OpenTofu step; the engine asks it through the pre-flight capability interface and keeps no knowledge of one cloud's quota.

**Done means:**

- The engine has no VPC hook variable and no quota decision of its own; before the first OpenTofu step it asks the adapter through the pre-flight capability interface.
- On the Huawei cloud a project over its VPC cap is first cleaned of orphaned catalyst VPCs, never of a VPC of a live deployment, and a provision is refused only when the project is still full after that clean-up.
- A quota read that fails, before or after the clean-up, lets the provision go on, as before.
- The quota decision and its tests live in the Huawei adapter and pass there.
- The lines of the engine's main file that name a cloud fall from 21 to 11.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Before `tofu init` the engine runs the adapter's `providers.Preflighter`, reached with `providers.As`, instead of the hook variables `VPCQuotaHook` and `VPCReclaimHook` behind `req.Provider == "huawei"`. The Huawei adapter implements `Preflight` in `internal/providers/huawei/capabilities.go`: it reads the VPC quota, over the cap reclaims orphaned catalyst VPCs destructively with the engine's protected deployment prefixes, reads again, and refuses only a project known to be full after the reclaim. The pure decision (`quotaReading`, `vpcPreflightRefuses`, `effectiveReading`) and its tests move unchanged from `internal/provisioner` to the adapter. With CLD-105 merged, the engine sets and reads no hook variable that one cloud sets. The verdicts and the refusal text of a Huawei provision are the same as before.

## 3. The model (the law)
1. `internal/providers/huawei/capabilities.go` declares that `*Provider` implements `providers.Preflighter`, beside `PostApplier` and `ApplyErrorClassifier` (CLD-105).
2. `Preflight` reads the credentials `access_key`, `secret_key`, `project_id` and `region` of `in.Spec` (the region trimmed; empty means `defaultRegion`, `me-east-215`), and `needed` is `len(in.Spec.Regions)`. It reads the quota through the package variable `vpcQuota` (`(*Provider).VPCQuota`) and reclaims through `sweepVPCs` (`(*Provider).SweepOrphanVPCs`); only a test reassigns them.
3. A failed first read writes `HCS VPC quota check skipped (transient API error): ...` to `in.Progress` and returns nil. A known reading writes `HCS VPC quota: used U / L, requesting N`. Over the cap, `Preflight` writes `HCS VPC quota over budget ...`, calls `sweepVPCs` with `in.ProtectedIDs` and `destructive` true, with the sweep's messages prefixed `vpc-reclaim: `, writes the result of the reclaim, and reads the quota again (`HCS VPC quota after reclaim: ...`, or `HCS VPC quota re-read after reclaim failed ...`).
4. `Preflight` returns `HCS VPC quota exhausted: project at U/L after orphan reclaim, this prov requests N more — a concurrent Sovereign genuinely occupies the project; wipe one before retrying` exactly when `vpcPreflightRefuses(needed, first, reclaimAttempted, after)` is true, quoting `effectiveReading`; otherwise nil.
5. `quotaReading`, `known`, `fits`, `vpcPreflightRefuses` and `effectiveReading` move from `internal/provisioner/vpc_quota_preflight.go` to `internal/providers/huawei/vpc_quota_preflight.go`, and their eight tests from `internal/provisioner/vpc_quota_preflight_6225_test.go` to `internal/providers/huawei/vpc_quota_preflight_6225_test.go`. Only the package line, and the comments and one failure message that name the old place, change.
6. Before `tofu init` the engine calls `Preflight` of an adapter that implements `providers.Preflighter`, with `Spec: capabilitySpec(req)`, `ProtectedIDs: reclaimProtectSet(req.DeploymentID)` (every live deployment, #4614) and a `Progress` that emits on the stage `tofu-init` at level `info`. An error fails the provision with the adapter's text.
7. Deleted: `vpcQuotaFunc`, `VPCQuotaHook`, `vpcReclaimFunc`, `VPCReclaimHook` and the inline VPC pre-flight in `internal/provisioner/provisioner.go`; `VPCQuotaPreflight`, `VPCReclaimPreflight` and the two lines of `init()` that set the hooks in `internal/providers/huawei/provider.go`; the files `internal/provisioner/vpc_quota_preflight.go` and `internal/provisioner/vpc_quota_preflight_6225_test.go`.
8. `PostApply` and `ClassifyApplyError` (CLD-105) do not change.
9. All eight paths change only through the patch `CLD-115.patch` of this ticket.
