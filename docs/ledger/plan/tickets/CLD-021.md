# CLD-021 — Delete the 24 infrastructure mutation routes and the claim writer

## In plain words

**The problem today.** The API server has 24 routes that add, change and delete regions, clusters, node pools, nodes, load balancers, networks, volumes and buckets. Each one writes a claim in an API group that nothing in the platform defines or reconciles, so every call promises a change that never happens. The console dialogs that called these routes are already gone, but the routes, the claim writer and its tests still keep the false surface alive.

**What changes.** The 24 routes, their handlers and request types, the claim writer, the bridge that recorded each call as a job, and their two test files are deleted. The four read routes of the surface stay and answer as before, and the stored size counts of the API server and its count of direct cluster writes are lowered to match.

**Done means:**

- The API server registers no route that adds, changes or deletes infrastructure under a deployment; the four read routes of the Sovereign Infrastructure surface still answer.
- No file outside the documents names the claim writer, its API group or its namespace.
- The API server builds, and every test of the four code packages this change touches passes.
- Jobs that earlier calls left in the store keep their kind and display name.
- The list of deleted paths names the four removed files, so a pull request that brings one back turns red.
- The guards that count the size of the handler package and the direct cluster writes pass with their lowered numbers.

The rest of this ticket is the exact instruction for the model that does the work.
