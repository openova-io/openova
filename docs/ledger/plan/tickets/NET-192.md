# NET-192 — Gate check NET-G11: route admission by owner

## In plain words

**The problem today.** Each Organization has two listeners on the console gateway of a Sovereign, and since NET-191 they accept web routes only from that Organization and from the console. Nothing proves on a running Sovereign that a route of one Organization is really refused by the listeners of another, so a change that opened them again would pass every acceptance run.

**What changes.** The acceptance suite gains a check that makes one route inside the cluster of one Organization, aimed at its own listeners and at those of a second Organization, and reads that the gateway accepts it on the first pair and refuses it on the second because of its owner. The check is listed among the gate checks as expected to fail until a Sovereign carries the change.

**Done means:**

- The check fails when a listener of the second Organization accepts a route of the first.
- The check fails when a listener of the first Organization refuses its own route, or when a listener of the second refuses it for a reason other than its owner.
- The check fails as not measured when the Sovereign has fewer than two Organizations with a listener pair, or when the gateway writes no verdict.
- The check creates its route in a namespace of its own inside the cluster of the first Organization, deletes that namespace and waits until the copy of the route is gone, also when a step failed; it uses no NodePort.
- Only the first region of the Sovereign, the region the platform API runs in, is asked.
- The check is listed as expected to fail, and its tests run on every pull request without a cluster.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Gate check NET-G11 proves on a running Sovereign what package NET-191 built: both listeners of an Organization's pair on the console Gateway `kube-system/cilium-gateway-console` (`console-https-<label>` and `console-http-<label>`, host name `*.<label>.<parent>`) admit HTTPRoutes only from the Organization's namespace `<label>` and from `catalyst-system` (`core/controllers/pkg/orglistener`). The check is the new file `tests/acceptance/sovereign/internal/suite/check_route_admission.go` with its test file. In the first region of the run it takes the first two Organizations A and B with a listener pair, creates one HTTPRoute inside the vCluster of A, in a namespace of its own, that names the four listeners of A and B, and reads the host copy that the syncer writes into the namespace of A: the listeners of A must accept it and the listeners of B must refuse it with the reason `NotAllowedByListeners`. NET-G11 moves in `docs/ledger/gates.yaml` from `not-built` to `expected-fail` and names its file.

## 3. The model (the law)
1. The check has the identifier `NET-G11` and registers itself with `RegisterCheck` in `init` with the kubectl `kube.Region.Run`, the port forward `portForward` and the waits of a cloud run (sync 2 minutes, status 3 minutes, deletion 3 minutes, 5 seconds between two reads). `runner.go` and `registry.go` are not edited.
2. Only `cc.Regions[0]` is asked, the region the API runs in, as CLD-G07 and CMP-G02 read it: its console Gateway, the kubeconfig Secret and the vCluster of A in it, and the host namespace of A. No other region is asked anything. A run without a region fails before it reads anything.
3. The Organizations: a listener `console-https-<label>` whose host name is `*.<label>.<parent>` and a listener `console-http-<label>` with the same host name are the pair of the Organization `<label>`. A and B are the first two labels in sort order. With fewer than two pairs nothing can be measured and the first step fails, naming the labels it found; nothing is created. The step records the `allowedRoutes` of the four listeners as evidence.
4. The connection, as check NET-G07 makes it: the key `config` of the Secret `vc-vcluster` in the host namespace of A is written to a file of mode 600 in a temporary folder that is removed at the end; `kubectl port-forward` to the Service `vcluster` of A on port 443 with the kubeconfig of the region; calls with the kubeconfig of A, `--server https://<local address>` and `--tls-server-name` set to the host of its server line (`isoJourney.vcKubectl`). The vCluster must answer `namespace/default`. The forward is ended before the check returns.
5. The route: per run one tag (the time and the random part of `NewRunID`); the namespace `net-g11-<tag>` is created in the vCluster of A, and in it the HTTPRoute `net-g11-<tag>`. Its `parentRefs` name the four listeners of A and B by `sectionName` on `kube-system/cilium-gateway-console`; its host names are `net-g11-<tag>.<label>.<parent>` of A and of B, so every listener matches it by host name and only its namespace decides; its one rule has no backend, so it serves nothing even where it is admitted. Nothing is created on the host, and no Service of any type is created.
6. The syncer of the vCluster writes the route into the host namespace of A as `net-g11-<tag>-x-net-g11-<tag>-x-vcluster`; the check waits for that host copy within the sync wait, or the step fails.
7. The verdict, read on the host copy once it holds a condition `Accepted` for each of the four listeners (or the status wait ended): each listener of A has `Accepted` `True` with the reason `Accepted`, and each listener of B has `Accepted` `False` with the reason `NotAllowedByListeners`. Any other reason fails: such a route was refused for its host name or its section, not for its owner. A listener without a condition `Accepted` fails as not measured. One step for A and one for B record what each listener wrote.
8. Before the check ends, also when a step after the connection failed, it deletes its namespace in the vCluster of A and waits until the host copy is gone from the host namespace of A; it fails naming the copy that is left.
9. Steps are numbered `NET-G11.<n>` in order.
10. `docs/ledger/gates.yaml`: NET-G11 moves from `not-built` to `expected-fail` and gains the line `implementation: tests/acceptance/sovereign/internal/suite/check_route_admission.go`. No other field of any check changes.
11. Nothing is deleted. No new image, no dependency of the module, no `time.Sleep`.

+		case o == nil:
+			return false, "no HTTPRoute " + r.copy + " in the host namespace " + r.a.label, nil
+		}
+		all := true
+		for _, l := range listeners {
+			seen[l] = routeAccepted(o, l)
+			all = all && seen[l] != ""
+		}
+		return all, fmt.Sprint(seen), nil
+	})
+	for _, side := range []struct {
+		org        routeOrg
+		what, want string
+	}{{r.a, "admit the route of A", "True/Accepted"}, {r.b, "refuse the route of A", "False/" + routeRefused}} {
+		r.step("the listeners "+strings.Join(side.org.listeners(), " and ")+" of "+side.org.label+" "+side.what+" (Accepted="+side.want+")", func(ev Evidence) error {
+			bad := []string{}

+				case "":

+			}
