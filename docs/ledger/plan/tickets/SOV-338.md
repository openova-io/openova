# SOV-338 — A kept variables document is brought to the keys of the contract before a module reads it

## In plain words

**The problem today.** A wipe of a Huawei Sovereign keeps the variables file written when the Sovereign was made. The provider modules accept the variables document only when it holds exactly the keys of the contract. When the contract gains or loses a key, every Sovereign made before that change can no longer be wiped cleanly, because its kept document has the old key set.

**What changes.** Before a wipe, the kept document is brought to the keys of the contract: a key it lacks gets the value a new document has, a key the contract no longer has is removed, and every value it holds stays. A document that is already complete is left as it is.

**Done means:**

- A kept document that lacks a contract key gets the value that a new document has for that key.
- A kept document that holds a key the contract no longer has loses that key.
- Values the kept document holds are not changed.
- A file whose document already has exactly the contract keys is not written.
- A file without a variables document still gets the whole new document, as before.
- Every test of the provisioner package passes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A wipe of a Huawei deployment keeps the provision-time `tofu.auto.tfvars.json`. Before `tofu destroy` reads it, `addVariablesIfMissing` brings its module input `variables` to exactly the keys of contract C5, the variables document. A document written under an older contract then passes the module's key check, so adding or removing a contract key no longer breaks the wipe of the Sovereigns made before. The proof is a unit test with five cases that fails on the code of today.

## 3. The model (the law)
1. The key set is the contract's. `addVariablesIfMissing` takes it from `(upstream.Variables{}).ToMap()`: the package `core/controllers/pkg/upstream` has one field per contract key, and `ToMap` writes every one. No key list is written by hand in the provisioner.
2. A contract key that the kept document lacks gets the value of a new document: `childVariables(req, <the file's own catalyst_api_url>)`, the same document a new Sovereign gets. The new document is built only when at least one key is missing, so a document that only needs keys dropped never needs the callback address.
3. A key of the kept document that is not a contract key is dropped. That includes a key the contract no longer has.
4. A value the kept document holds for a contract key stays as it is, also when a new document would have another value.
5. A file whose document has exactly the contract keys is not written: its bytes stay the same.
6. A file without `variables`, or with `"variables": null`, gets the whole new document, as before. A `variables` that is not a JSON object is an error: `decode tfvars: variables is not a JSON object`.
7. Only the input `variables` changes. Every other module input of the file keeps its value. A file that is written is written as today: `json.MarshalIndent` with two spaces, mode `0o600`.
8. Deleted: the rule "a file that has variables is left as it is", in the comment of `addVariablesIfMissing` and in the test `TestAddVariablesIfMissing`. The new rule's test takes its place under the same name.
9. `Destroy` calls `addVariablesIfMissing` in the same branch as today (Huawei, the request has no regions, the file exists). Only the comment above the call changes.
