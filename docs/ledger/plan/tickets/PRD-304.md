# PRD-304 — bp-speech chart on CPU

## In plain words

**The problem today.** The platform has no transcription service: the model plane serves embeddings on CPU but nothing turns speech into text. The product guard scans no transcription chart, so such a chart could open a route of its own, name a model provider or read a Secret into an environment variable without a check noticing.

**What changes.** A new Blueprint serves one pinned Whisper model on CPU behind a ClusterIP Service that only the model gateway and the release's own test may reach, with a function test that transcribes a bundled sample. The product guard, the DNS guard and the network guard cover the new chart, and a test in CI runs the real image against both model sources.

**Done means:**

- With home or enabled false the chart renders nothing, and it never renders a Namespace.
- The model is named by a digest or by a 40-character revision; a floating reference, a missing revision, an unknown parameter or a load time below 30 seconds fails the render with a message that names it.
- The server runs as a numeric user with a read-only root, no capability and no service-account token, reads the weights read-only with the model hub switched off, and its start-up probe allows one and a half times the declared load time.
- The network policy is on by default, admits the serving port only from the model gateway's namespace and from the function test, and opens the model hub, at public addresses only, only when asked; the tree's DNS guard renders that policy and finds cluster DNS in it.
- The chart's own test passes only when the server returns text that holds the word the bundled five-second sample says.
- The product guard fails a route, a model-provider host or a secretKeyRef in the new chart.
- The chart tests of the pull request run the real server image: it fetches the model from the hub, copies it from a model image pulled by digest, and transcribes the sample both ways.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`platform/speech` is the CPU transcription service of the model plane, a new Blueprint `bp-speech`. Its chart runs one speaches server (`ghcr.io/speaches-ai/speaches:0.8.3-cpu@sha256:21e3df06d842fb7802ab470dd77c25f0e8c0d22950e8d8c6ae886e851af53ef8`, MIT) on port 8000 that serves one Whisper model in CTranslate2 form with int8 weights on `POST /v1/audio/transcriptions`. By default the model is `hf://deepdml/faster-whisper-large-v3-turbo-ct2` at `4df90f75321148c3a29a9e2351b7ddf8f5b115a8`, served as `whisper-large-v3-turbo`. The chart's parameters are the Blueprint's `configSchema` (`home`, `enabled`, `model`, `cache`, `startup`), and the chart refuses at render what that schema refuses. With `home` or `enabled` false it renders nothing; nothing installs the chart yet (PRD-306 adds the kit slot). A person sees it this way: the check `chart/tests/*.sh — platform/speech` of the pull request is green, and its log shows `model-load: all cases passed` after a real run of the server that transcribed the sample.

## 3. The model (the law)
1. The Service is `ClusterIP`. The chart renders no `HTTPRoute`, `Ingress`, `Gateway` or `GRPCRoute`, and the Blueprint declares no endpoint.
2. The chart renders no Namespace. The kit's namespace `model-serving` is rendered and owned by the release of `bp-bge` (`platform/bge/chart/templates/namespace.yaml`), and Helm refuses to install an object that another release owns; so the kit slot of this chart (PRD-306, slot 85) is ordered after slot 42. Every object of the chart renders only when `home` and `enabled` are both true. The values are judged at every render, whatever `home` and `enabled` say.
3. The server image is named by digest. The model `source` is `oci://<host>/<path>@sha256:<64 hex>` or `hf://<owner>/<name>`; an `hf://` source needs `revision`, 40 lowercase hexadecimal characters, and an `oci://` source takes none. Any other value fails the render.
4. The parameters are exactly `home`, `enabled`, `model` (`source`, `revision`, `servedName`), `cache` (`sizeGi`, at least 10, and `storageClass`) and `startup` (`loadSeconds`, at least 30). Any other key of `model`, `cache` or `startup` fails the render. There is no language parameter and no `gpu` object: a language-specific model is a second release behind a second alias.
5. The Pod runs as user and group 1000 (the image's user is the name `ubuntu`, uid 1000) with `runAsNonRoot`, the `RuntimeDefault` seccomp profile, a read-only root file system, every capability dropped, no privilege escalation and `automountServiceAccountToken: false` on the Pod and on its ServiceAccount. `HF_HOME` is on the `/tmp` emptyDir.
6. One model, one server, `replicas: 1`. The update strategy is `Recreate` when `cache` makes the weights a claim, otherwise a rolling update with no unavailable replica.
7. The server reads a Hugging Face cache at `/models/hf` (`HF_HUB_CACHE`), read-only, with `HF_HUB_OFFLINE=1`, `WHISPER__COMPUTE_TYPE=int8`, `ENABLE_UI=false` and `WHISPER__TTL=-1` (the model loads on the first request and stays loaded). Init containers write the cache and point `refs/main` at the one pinned snapshot. An `hf://` model is fetched by the server image's `huggingface-cli` at its revision. An `oci://` model is a model image whose files are in `/model` and which holds a statically linked `/bin/cp`; the server image lays out the repository `oci/model` and the model image copies `/model/.` in as the snapshot named by the first 40 characters of its digest. The release's ConfigMap mounts `model_aliases.json` over the image's own, mapping `servedName` to that repository.
8. The start-up probe (`GET /health`, every 10 seconds) lets `startup.loadSeconds` x 1.5 seconds pass before a failure counts, rounded up to whole periods: `failureThreshold` is (3 x `loadSeconds` + 19) / 20 in whole numbers, 5 for the default 30.
9. No credential is a value and no template contains `secretKeyRef`. A model-hub token is the object `hf-token` of the SecretProviderClass that `hubToken.secretProviderClass` names, mounted by the Secrets Store CSI driver at `/var/run/secrets/openova/hf-token` into the fetching init container; `HF_TOKEN_PATH` names that file. A token with an `oci://` model fails the render.
10. The release's one NetworkPolicy, on by default, selects every Pod of the release. Ingress: the serving port, from namespace `networkPolicy.gatewayNamespace` (`model-gateway`) and from the release's function test. Egress: cluster DNS, the server's port, and TCP 443 to public addresses (every address except 10.0.0.0/8, 100.64.0.0/10, 169.254.0.0/16, 172.16.0.0/12 and 192.168.0.0/16) only when `networkPolicy.hubEgress` is true (default false). An `hf://` model with the policy on and the hub egress off fails the render.
11. `templates/tests/function-test.yaml` meets `docs/RUNBOOKS.md` section 4.5: it waits for `GET /health` until 120 seconds before its bound, posts the bundled sample to `/v1/audio/transcriptions` for `model.servedName`, and passes only when the answer's `text` is not empty and holds the word `americans`. The sample `chart/files/function-test-sample.ogg` (19,582 bytes, Opus in Ogg, 16 kHz mono) is the first five seconds of `samples/jfk.wav` of github.com/ggml-org/whisper.cpp at commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`, a 1961 address of the President of the United States and so in the public domain; it reaches the test Pod through the release's ConfigMap. The test Pod's name label is not the server's, so the Service never selects it.
12. The guards cover the chart, and no baseline rises: `platform/speech` is added to the scan lists of the product guard's rules G-P1, G-P2 and G-P3 and to their fixtures, with no baseline entry (a new file starts at zero); the count of charts with a function test rises by one; the DNS guard renders the chart with `home`, `enabled` and `networkPolicy.hubEgress` true; network guard G2 names the chart's policy file as an exception owned by PRD-304 until the allow file of `model-serving` (PRD-212) takes over. The DNS guard and the product guard are existing Python and their Python may not grow (`tools/guards/cmd/python-shrinks`): the DNS guard's bge entry becomes one line that gives both charts the same values, and each changed line of the product guard replaces one line.
13. The Blueprint declares `class: ai-service`, `lifecycle: experimental`, `visibility: listed`, the `singleton` topology only, `metrics: none`, and `spec.version` equal to the chart's `version`, `1.0.0`. The generated catalogue and component list carry the new Blueprint.

+# bp-speech
+
+Transcription on CPU: one speaches server (github.com/speaches-ai/speaches, MIT, `0.8.3-cpu` by digest) serves one Whisper model in CTranslate2 form with int8 weights.
+
+## Role in Catalyst
+
+An AI-service Blueprint (`class: ai-service`) of the platform's model plane, not an Application a User installs. The platform's model gateway is its one caller: the Service is `ClusterIP`, and the chart renders no `HTTPRoute`, `Ingress`, `Gateway` or `GRPCRoute`. The kit's target namespace is `model-serving`, which `bp-bge`'s release creates and owns; this chart renders no Namespace, because Helm refuses an object another release owns. See [`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md) for where model services sit.
+
+Route: `POST /v1/audio/transcriptions` (multipart: `file`, `model`, `language`, `response_format`), and `GET /health` for the probes. The caller sends audio in segments of at most 30 seconds: on one long file the measured defaults drop words or repeat themselves (`docs/ledger/plan/spikes/PRD-080.md`). The chart has no language routing; a language-specific model is a second release behind a second alias.
+
+## Configuration
+
+The Blueprint's `configSchema` (`blueprint.yaml`) is the chart's parameters; the chart refuses at render what it refuses.
+
+| Value | Meaning |
+|---|---|
+| `home`, `enabled` | Set by the kit slot (`enabled` from `MODEL_PLANE_TRANSCRIPTION`). Both true: the chart renders its workloads. Otherwise it renders nothing. |
+| `model` | `source`, `revision`, `servedName`. Default: `hf://deepdml/faster-whisper-large-v3-turbo-ct2` at `4df90f75…`, served as `whisper-large-v3-turbo`. |
+| `cache` | Optional weights claim: `sizeGi` (at least 10), `storageClass`. Without it, an emptyDir of 10Gi. |
+| `startup` | `loadSeconds` (at least 30, default 30): the start-up probe allows 1.5 times it, rounded up to whole periods of 10 seconds. |
+
+A `source` is never a floating reference: `oci://<host>/<path>@sha256:<64 hex>`, or `hf://<owner>/<name>` with `revision`, the 40-character commit. `servedName` is the name a request gives as its `model`, the `upstreamModel` of the gateway's alias; the release's alias file (`model_aliases.json`, mounted over the image's own) maps it to the model.
+
+Outside the schema: `image`, `port` (8000), `resources` (2 to 4 CPUs, 3 to 5Gi of memory; the server's threads follow `limits.cpu`), `hubToken.secretProviderClass`, `networkPolicy`, `functionTest`.
+
+**Weights.** The server reads a Hugging Face cache on the weights volume, read-only, with the hub switched off (`HF_HUB_OFFLINE`); `refs/main` names the one pinned snapshot, so the model never floats. Init containers write it.
+
+**hf:// models.** An init container of the server image fetches the model's files at the pinned revision with the image's hub client. That needs `networkPolicy.hubEgress: true` (default false; with the policy on and it false, an `hf://` source is refused at render). A gated model's token is one file: `hubToken.secretProviderClass` names a SecretProviderClass of the release namespace whose object `hf-token` the Secrets Store CSI driver mounts as `/var/run/secrets/openova/hf-token` (`HF_TOKEN_PATH`). No credential is a value, and the chart reads no Secret.
+
+**Model image.** An `oci://` model is an image of the Sovereign's registry with one layer over `scratch`: the files of one revision of a CTranslate2 Whisper repository (`model.bin`, `config.json`, `tokenizer.json`, `preprocessor_config.json`, `vocabulary.*` and `README.md`, whose model card names the library `ctranslate2` and the task `automatic-speech-recognition`), readable by every user, in `/model`, and a statically linked `/bin/cp` (for example busybox's). An init container of the server image lays out the repository `oci/model`; then the model image's `/bin/cp -R /model/.` copies the files in as its snapshot, named by the first 40 characters of the image digest. The kubelet pulls the image, so the Pod needs no egress for it.
+
+## Operations
+
+- One replica. The Pod runs as user 1000 (the image's user `ubuntu`, by number) with a read-only root file system, all capabilities dropped and no service-account token; the hub client's files are on a `/tmp` emptyDir.
+- The server answered in about 3 seconds when measured. The model loads on the first request (6.5 to 13.9 seconds measured for the default model) and then stays loaded (`WHISPER__TTL=-1`). The measured speed of the default model, segment by segment, was 1.28 to 1.76 seconds of audio per second on CPUs with AVX-512 and 0.82 on one without; measure on the target CPU before a speed is promised.
+- The network policy (on by default) admits the serving port only from namespace `model-gateway` and from the release's function test, and lets the Pods send to cluster DNS, to the server's port and, with `hubEgress`, to TCP 443 of public addresses (10.0.0.0/8, 100.64.0.0/10, 169.254.0.0/16, 172.16.0.0/12 and 192.168.0.0/16 excepted).
+

+# The contract is docs/RUNBOOKS.md section 4.5; scripts/check-function-test.py checks it.

+SERVE=(--set home=true --set enabled=true --set networkPolicy.hubEgress=true)

+  helm dependency build >/dev/null
+fi
+

+helm template speech . --namespace model-serving "${SERVE[@]}" > "$TMP/serve.yaml"

+[ "$(env_of HEALTH_URL)" = "$ROOT/health" ] || fail "the test does not wait on the server's /health"
