# NET-110 — Cilium base values to target

## In plain words

**The problem today.** The shared Cilium chart carries the control-plane address of one cloud and a routing range that is only right for two regions. A Sovereign with three or more regions would route a part of its pod traffic through address translation. The chart also ships three mesh files that Cilium never reads, and its notes name an upstream version it does not bundle.

**What changes.** The chart has no address and no range of its own. Each Sovereign gets both from its variables: the address the node detects at first boot, and the pod supernet that the provider module computes. A release that names a cluster and no range is refused with a clear message. Four Hubble metrics are on. The three stale mesh files and the wrong version notes are gone.

**Done means:**

- The chart folder of Cilium holds neither the fixed control-plane address nor the fixed two-region range.
- A new Sovereign with three regions gets the range 10.40.0.0/13 for native routing, and one with one or two regions gets 10.42.0.0/15, in the Cilium that cloud-init installs and in the Cilium that Flux installs.
- A Cilium release for a cluster whose variables hold no routing range does not render, the error names the missing key, and the installed release stays as it is.
- The chart still renders with its own values, so the release workflow and the lint keep working.
- Every agent serves the Hubble metrics dns, drop, flow and policy, and no ServiceMonitor and no NodePort is rendered for them.
- The three mesh files that Cilium never read are deleted, and no test or document of the platform points at them.
- The chart test for these rules has a self-test that fails on a chart copy that breaks any one rule.

The rest of this ticket is the exact instruction for the model that does the work.

#!/usr/bin/env bash
# bp-cilium: the API host and the native-routing range have no chart default (NET-110).
#
# cilium.k8sServiceHost and cilium.ipv4NativeRoutingCIDR differ per Sovereign. The
# bootstrap-kit slot sets them from the kit keys CILIUM_K8S_SERVICE_HOST and
# CILIUM_NATIVE_ROUTING_CIDR. This test renders the chart and proves five rules:
#
#   1. The chart's own values name no API host and no range, and still render
#      (the release workflow's smoke render and `helm lint` use them).
#   2. A release with an API host and no range does not render, and the error
#      names the value and the kit key. The same holds for a null range, which
#      is what Flux substitutes from a missing key.
#   3. With both values the render carries exactly these two values.
#   4. The four Hubble metrics of the slot render the metrics Service, no
#      ServiceMonitor and no NodePort.
#   5. The chart renders no ConfigMap catalyst-clustermesh-config: Cilium never read it.
#
# Usage: bash tests/native-routing-cidr.sh [CHART_DIR]
#        bash tests/native-routing-cidr.sh --self-test
# The self-test copies the chart, breaks one rule per copy and proves that this
# test fails on each copy with the message of that rule.
# Needs bash and helm. Contacts no cluster. When chart/charts is empty it fetches
# the upstream chart from the repository that Chart.yaml names.
# Exit: 0 every rule holds (or the self-test passed), 1 a rule failed.

set -euo pipefail

SELF="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)/$(basename "${BASH_SOURCE[0]}")"
HOST="10.9.8.7"
RANGE="10.40.0.0/13"
METRICS='cilium.hubble.metrics.enabled=["dns","drop","flow","policy"]'
WORK="$(mktemp -d)"
trap 'rm -rf "$WORK"' EXIT

# The upstream chart is fetched only when chart/charts is empty. `update` and
# not `build`: without a Chart.lock, `build` needs `helm repo add` first.
build_deps() {
  if [ ! -d "$1/charts" ] || [ -z "$(ls -A "$1/charts" 2>/dev/null)" ]; then
    helm dependency update "$1" >/dev/null
  fi
}

run_rules() {
  local chart="$1" tmp="$WORK/rules" m
  mkdir -p "$tmp"
  build_deps "$chart"

  echo "[native-routing-cidr] Rule 1: the chart's own values name no API host and no range, and render"
  if ! helm template smoke-cilium "$chart" > "$tmp/default.yaml" 2> "$tmp/default.err"; then
    echo "FAIL rule 1: the chart does not render with its own values:" >&2
    cat "$tmp/default.err" >&2
    return 1
  fi
  if grep -q 'ipv4-native-routing-cidr:' "$tmp/default.yaml"; then
    echo "FAIL rule 1: the chart's own values carry a native-routing range. The range comes from the kit key CILIUM_NATIVE_ROUTING_CIDR, never from the chart." >&2
    return 1
  fi
  if grep -q 'name: KUBERNETES_SERVICE_HOST' "$tmp/default.yaml"; then
    echo "FAIL rule 1: the chart's own values carry an API host. The host comes from the kit key CILIUM_K8S_SERVICE_HOST, never from the chart." >&2
    return 1
  fi
  echo "  PASS"

  echo "[native-routing-cidr] Rule 2: an API host without a range does not render"
  if helm template smoke-cilium "$chart" --set "cilium.k8sServiceHost=$HOST" > "$tmp/norange.yaml" 2> "$tmp/norange.err"; then
    echo "FAIL rule 2: a release with an API host and no native-routing range rendered. The agents would stop at their next start." >&2
    return 1
  fi
  if ! grep -q 'cilium.ipv4NativeRoutingCIDR is not set' "$tmp/norange.err" || ! grep -q 'CILIUM_NATIVE_ROUTING_CIDR' "$tmp/norange.err"; then
    echo "FAIL rule 2: the render failed, but not with the message that names the value and the kit key:" >&2
    cat "$tmp/norange.err" >&2
    return 1
  fi
  if helm template smoke-cilium "$chart" --set "cilium.k8sServiceHost=$HOST" --set cilium.ipv4NativeRoutingCIDR=null > "$tmp/null.yaml" 2> "$tmp/null.err"; then
    echo "FAIL rule 2: a release with an API host and a null native-routing range rendered." >&2
    return 1
  fi
  if ! grep -q 'cilium.ipv4NativeRoutingCIDR is not set' "$tmp/null.err"; then
    echo "FAIL rule 2: the render with a null range failed, but not with the message that names the value:" >&2
    cat "$tmp/null.err" >&2
    return 1
  fi
  echo "  PASS"

  echo "[native-routing-cidr] Rule 3: with both values the render carries them"
  if ! helm template smoke-cilium "$chart" --set "cilium.k8sServiceHost=$HOST" --set "cilium.ipv4NativeRoutingCIDR=$RANGE" > "$tmp/both.yaml" 2> "$tmp/both.err"; then
    echo "FAIL rule 3: the chart does not render with an API host and a range:" >&2
    cat "$tmp/both.err" >&2
    return 1
  fi
  if [ "$(grep -c "^  ipv4-native-routing-cidr: $RANGE\$" "$tmp/both.yaml")" != "1" ]; then
    echo "FAIL rule 3: the render does not carry 'ipv4-native-routing-cidr: $RANGE' exactly once." >&2
    return 1
  fi
  if ! grep -q '^  routing-mode: "native"$' "$tmp/both.yaml"; then
    echo "FAIL rule 3: the render does not carry routing-mode native." >&2
    return 1
  fi
  if ! grep -A1 'name: KUBERNETES_SERVICE_HOST' "$tmp/both.yaml" | grep -q "value: \"$HOST\""; then
    echo "FAIL rule 3: the render does not give the agents the API host $HOST." >&2
    return 1
  fi
  echo "  PASS"

  echo "[native-routing-cidr] Rule 4: the four Hubble metrics render a Service, no ServiceMonitor, no NodePort"
  if ! helm template smoke-cilium "$chart" --set "cilium.k8sServiceHost=$HOST" --set "cilium.ipv4NativeRoutingCIDR=$RANGE" \
      --set-json "$METRICS" --set cilium.hubble.metrics.serviceMonitor.enabled=false > "$tmp/metrics.yaml" 2> "$tmp/metrics.err"; then
    echo "FAIL rule 4: the chart does not render with the four Hubble metrics:" >&2
    cat "$tmp/metrics.err" >&2
    return 1
  fi
  if ! grep -q '^  name: hubble-metrics$' "$tmp/metrics.yaml" || ! grep -q '^  hubble-metrics-server: ":9965"$' "$tmp/metrics.yaml"; then
    echo "FAIL rule 4: the render has no Service hubble-metrics or no metrics server on port 9965." >&2
    return 1
  fi
  for m in dns drop flow policy; do
    if ! grep -q "^    $m\$" "$tmp/metrics.yaml"; then
      echo "FAIL rule 4: the Hubble metric '$m' is not in the rendered cilium-config." >&2
      return 1
    fi
  done
  if grep -q '^kind: ServiceMonitor$' "$tmp/metrics.yaml"; then
    echo "FAIL rule 4: the render holds a ServiceMonitor. A fresh Sovereign has no such kind when bp-cilium installs." >&2
    return 1
  fi
  if grep -qE '(^|[[:space:]])type:[[:space:]]*NodePort|(^|[[:space:]])nodePort:[[:space:]]*[1-9]' "$tmp/metrics.yaml"; then
    echo "FAIL rule 4: the render holds a NodePort." >&2
    return 1
  fi
  echo "  PASS"

  echo "[native-routing-cidr] Rule 5: no ConfigMap catalyst-clustermesh-config"
  if ! helm template smoke-cilium "$chart" --set "cilium.k8sServiceHost=$HOST" --set "cilium.ipv4NativeRoutingCIDR=$RANGE" \
      --set cilium.cluster.name=region-a --set cilium.cluster.id=1 \
      --set cilium.clustermesh.useAPIServer=true --set cilium.clustermesh.config.enabled=true > "$tmp/mesh.yaml" 2> "$tmp/mesh.err"; then
    echo "FAIL rule 5: the chart does not render with ClusterMesh values:" >&2
    cat "$tmp/mesh.err" >&2
    return 1
  fi
  if grep -q 'name: catalyst-clustermesh-config' "$tmp/mesh.yaml"; then
    echo "FAIL rule 5: the render holds the ConfigMap catalyst-clustermesh-config, which Cilium does not read." >&2
    return 1
  fi
  echo "  PASS"

  echo "[native-routing-cidr] All bp-cilium native-routing rules hold."
}

# expect_fail <name> <chart copy> <text the failure must print>
expect_fail() {
  local name="$1" chart="$2" want="$3" out
  if out="$(bash "$SELF" "$chart" 2>&1)"; then
    echo "SELF-TEST FAIL $name: the test passed on a chart that breaks the rule" >&2
    return 1
  fi
  if ! printf '%s\n' "$out" | grep -q -F -- "$want"; then
    echo "SELF-TEST FAIL $name: the test failed, but not with '$want':" >&2
    printf '%s\n' "$out" | tail -5 >&2
    return 1
  fi
  echo "  self-test ok: $name"
}

self_test() {
  local chart work="$WORK/self-test"
  chart="$(cd "$(dirname "$SELF")/.." && pwd)"
  build_deps "$chart"
  mkdir -p "$work"

  echo "[native-routing-cidr] self-test: the unchanged chart passes"
  bash "$SELF" "$chart" > /dev/null

  # Rule 1 can fail: the chart's values get a range again.
  cp -r "$chart" "$work/r1"
  sed -i 's|^  routingMode: native$|  routingMode: native\n  ipv4NativeRoutingCIDR: "10.99.0.0/16"|' "$work/r1/values.yaml"
  expect_fail "rule 1 (a range in the chart's values)" "$work/r1" "FAIL rule 1: the chart's own values carry a native-routing range"

  # Rule 1 can fail: the chart's values get an API host again (with tunnel
  # routing, so that the value check does not stop the render first).
  cp -r "$chart" "$work/r1b"
  sed -i 's|^  k8sServiceHost: ""$|  k8sServiceHost: 10.0.0.1|' "$work/r1b/values.yaml"
  sed -i 's|^  routingMode: native$|  routingMode: tunnel|' "$work/r1b/values.yaml"
  expect_fail "rule 1 (an API host in the chart's values)" "$work/r1b" "FAIL rule 1: the chart's own values carry an API host"

  # Rule 2 can fail: the value check is gone.
  cp -r "$chart" "$work/r2"
  rm -f "$work/r2/templates/validate-values.yaml"
  expect_fail "rule 2 (no value check)" "$work/r2" "FAIL rule 2: a release with an API host and no native-routing range rendered"

  # Rule 2 can fail: the value check fails with another message.
  cp -r "$chart" "$work/r2b"
  sed -i 's|cilium.ipv4NativeRoutingCIDR is not set|a value is missing|' "$work/r2b/templates/validate-values.yaml"
  expect_fail "rule 2 (another message)" "$work/r2b" "FAIL rule 2: the render failed, but not with the message"

  # Rule 3 can fail: a second object carries the range.
  cp -r "$chart" "$work/r3"
  printf '{{- with .Values.cilium.ipv4NativeRoutingCIDR }}\napiVersion: v1\nkind: ConfigMap\nmetadata:\n  name: second-range\ndata:\n  ipv4-native-routing-cidr: {{ . }}\n{{- end }}\n' > "$work/r3/templates/second-range.yaml"
  expect_fail "rule 3 (the range rendered twice)" "$work/r3" "FAIL rule 3: the render does not carry 'ipv4-native-routing-cidr: $RANGE' exactly once"

  # Rule 4 can fail: a template renders a ServiceMonitor.
  cp -r "$chart" "$work/r4"
  printf 'apiVersion: monitoring.coreos.com/v1\nkind: ServiceMonitor\nmetadata:\n  name: hubble\n' > "$work/r4/templates/servicemonitor.yaml"
  expect_fail "rule 4 (a ServiceMonitor)" "$work/r4" "FAIL rule 4: the render holds a ServiceMonitor"

  # Rule 5 can fail: a template renders the ConfigMap again.
  cp -r "$chart" "$work/r5"
  printf 'apiVersion: v1\nkind: ConfigMap\nmetadata:\n  name: catalyst-clustermesh-config\n' > "$work/r5/templates/clustermesh-config.yaml"
  expect_fail "rule 5 (the ConfigMap is back)" "$work/r5" "FAIL rule 5: the render holds the ConfigMap catalyst-clustermesh-config"

  echo "[native-routing-cidr] self-test passed: each broken copy failed with its rule."
}

case "${1:-}" in
  --self-test) self_test ;;
  *) run_rules "${1:-$(cd "$(dirname "$SELF")/.." && pwd)}" ;;
esac
