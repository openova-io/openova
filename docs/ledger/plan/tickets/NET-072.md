# NET-072 — Placement selectors offer the host only

## In plain words

**The problem today.** When an Application carries no target list, the sovereign-admin console builds its placement from the older shape and gives every target the vCluster tier mgmt. That tier was retired: no Sovereign has a namespace of that name. The placement editor then preselects it, and an Apply writes a target whose install fails because the namespace does not exist.

**What changes.** Such a target gets the host vCluster instead, the same default the placement editor already uses. The placement code of the console names no retired tier any more.

**Done means:**

- An Application without a target list shows its targets on the vCluster host, not mgmt.
- The placement editor no longer preselects or offers mgmt for such an Application.
- The console's placement code contains none of the words mgmt, dmz, rtz or mgt.
- The console's type check and unit tests pass on the pull request.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The function `targetsFromLegacy` in `products/catalyst/bootstrap/ui/src/shared/lib/placement.ts` gives a target the vCluster `host` (the constant `HOST_VCLUSTER` of the same file) when the caller names none. Today it gives `mgmt`, a tier that no Sovereign installs. The only caller, `useResolvedPlacement.ts`, never names a vCluster, so every Application placed by the older shape (a `mode` and a `regions` list, or the per-region status rollup) shows `mgmt` on the Topology tab, and the placement editor preselects `mgmt` for it. After the change those targets carry `host`, and the editor offers `host` plus the real vCluster namespaces of the Sovereign. The file names none of the retired tiers `mgmt`, `dmz`, `rtz` or `mgt`. A person sees the result on the Topology tab of such an Application: the target line ends in `· host`.
