# SEC-237 — Slot 08 names the namespaces of shared mounted values in peerTrust.birthNamespaces

## In plain words

**The problem today.** A secret that a chart mounts from the store and shares between the regions is created once, in the primary region, by a job that then writes it into the other region. That job may write there only for the namespaces that the store's chart lists, and the kit never sets that list. Nothing checks it either, so the first chart that adds such a secret fails in the second region before anything is written.

**What changes.** The kit sets the list explicitly; it is empty today. A tree guard compares it on every pull request with the shared mounted secrets the kit's charts declare, and refuses the change when the two differ.

**Done means:**

- The store's slot of the kit names the list of namespaces, empty today, with a comment that says what it is for.
- A pull request that adds a shared mounted secret in a namespace the list lacks turns the tree guards red and names the namespace and the secret.
- A pull request that lists a namespace no shared mounted secret needs, or removes the list, turns the tree guards red.
- The guard's own test makes each of its rules fail once, and runs on every pull request.
- The store's chart renders the same objects as before, so a running Sovereign sees no change.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Kit slot 08 (`clusters/_template/bootstrap-kit/08-openbao.yaml`) sets `peerTrust.birthNamespaces` of bp-openbao explicitly. A value of the library secrets-lib with `delivery: mounted` and `sharedAcrossRegions` true (the default) is born in every region by the primary region's birth Job, which logs in at each peer as `secrets-birth-<ns>`; bp-openbao makes that peer role only for the namespaces of this list. No kit namespace holds such a value today, so the list is `[]`. The new tree guard `tools/guards/cmd/kit-birth-namespaces` holds the list to exactly the namespaces of the kit charts' shared mounted values on every pull request: the first chart that adds one (the chargeback master key of SEC-246, in namespace `chargeback`) is red until slot 08 lists its namespace, in the same change. bp-openbao renders byte for byte what it rendered before.

## 3. The model (the law)
1. Slot 08 sets `peerTrust.birthNamespaces` as a list, `[]` when no namespace needs it. An absent key is a finding: the list is explicit.
2. A namespace needs the list when a kit HelmRelease of a chart that includes `openova.generatedSecrets` resolves, in that namespace, a value with `delivery: mounted` and `sharedAcrossRegions` true or unset. The namespace is the include's quoted `"namespace"` literal, else the release's `spec.targetNamespace` (else its `metadata.namespace`). The values are the chart's `values.yaml` at the `.Values.<path>` the include passes, with the slot's `spec.values` at that path laid over them as Helm merges (a field of the slot wins, `null` removes).
3. Every namespace that needs the list is in it, and every namespace in it is needed. A `sharedAcrossRegions` that is not a boolean is a finding.
4. The guard judges the shared kit `clusters/_template/bootstrap-kit/*.yaml` and each pack's kit `clusters/_template/providers/*/kit/*.yaml`, suspended releases included. It does not see `valuesFrom`. An include it cannot read (no `.Values.<path>` as `secrets`, a namespace that is not a quoted name), a file or tool it cannot read, or no kit release of a library chart at all is exit 2, never a pass.
5. Exit 0 the list is exact, 1 a finding. The guard's test makes each rule fail once. The tree-guards job runs the test and the guard, two steps.
6. bp-openbao reads the list in one place (`_config.tpl` line 428, `| default list`): absent and `[]` render the same objects. No chart version line changes.
