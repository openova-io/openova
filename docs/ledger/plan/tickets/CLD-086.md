# CLD-086 — local module and reduced kit

## In plain words

**The problem today.** The platform has no environment where a change can be proven without a cloud account. Every proof of a first boot needs a real cloud, so a change to the boot path is found wrong only after it has merged and a cloud environment has been built. A test on a CI runner needs a provider pack that starts machines on the runner itself and a bootstrap kit small enough to converge there.

**What changes.** A third provider pack, local, starts the machines of a Sovereign as containers on one host, two regions as two clusters, and boots them with the same boot template as the cloud packs. A smaller bootstrap kit for it is generated from the shared kit, its module tests and kit build run on every pull request, and the ban on node-local storage makes one named exception for the two files of this pack that need it.

**Done means:**

- The local pack has a module, a pack declaration and a cloud profile, and the provider list in the generated providers document shows it.
- The module's tests, run with mocked providers, pass for one and for two regions and show one control-plane machine and its workers per region.
- The control-plane boot data points Flux at the reduced kit and names local-path as the storage class, and the load-balancer address pool of a region is never a machine's own address.
- The reduced kit holds the releases the pack runs and every release they depend on, plus the local-path storage release, and it builds with kustomize.
- A generator writes the reduced kit, and the generated-files check fails when the kit file is stale.
- The check that bans node-local storage passes with the pack in the tree, skips only the profile and the storage release of the pack, and still fails on any other file that names that storage class.
- The two cloud packs, the shared boot template and the shared kit are unchanged.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The repository has a third provider pack, `local`. Its OpenTofu module `infra/providers/local` meets contract version 1 (`infra/providers/_contract/contract.json`): it declares every contract variable and output, and the map input `variables` with the validation of the other two modules. For each region it starts one control-plane machine and `worker_count` worker machines. A machine is a privileged container that runs systemd and cloud-init, started with the OpenTofu provider `kreuzwerker/docker`; cloud-init reads its user-data from the NoCloud seed directory, which the module fills before the container starts. The control-plane machine boots the shared template `infra/providers/_shared/cloudinit-control-plane.tftpl` unmodified; the module then points the Flux Kustomization `bootstrap-kit` at the reduced kit `clusters/_template/providers/local/kit` and writes the substitutes of the pack into the ConfigMap `flux-system/sovereign-variables`. The reduced kit is written by the new generator `scripts/generators/local-kit.py`: the slot files of eleven root releases and of every release they depend on, then the pack's own `local-path.yaml`, which installs the upstream local-path provisioner as the default storage class. A person sees the result in the new folders, in the row `local` of `docs/generated/providers.md`, in the generated kit file, and in the two checks of the new workflow `infra-local-tofu` on the pull request: the module's mocked `tofu test` (nine runs, seven of them with two regions) and a `kustomize build` of the reduced kit. The guard `scripts/check-no-local-path.sh`, which bans the local-path storage class in every source of the platform, skips the two files of the pack that name that class, by their full paths, and bans it everywhere else as before. No machine is started by this ticket; the job that boots the pack on a runner is CLD-087.

## 3. The model (the law)
1. **Contract.** The module declares the 33 variables of `contract.json` with their types, and the six outputs; since SOV-133 the map `variables` is a contract variable and `fire_cutover_on_handover` is not, and the module declares no variable that the contract dropped. `contract_version` is `"1"`. The map `variables` holds exactly the 39 keys of `docs/contracts/c5-upstream-variables.schema.json`, and its key `HANDOVER_AUTO` is `true` or `false` (the same two validations as `infra/providers/huawei/variables.tf`). The pack's own inputs are `runner_socket`, `machine_image`, `machine_cidr`, `external_cidr`, `clustermesh_proxy_port`, `registry_mirror_yaml`, `object_storage_access_key` and `object_storage_secret_key`, each with a default, so the contract fixtures alone plan the module.
2. **Names.** Every network, volume and container is named `catalyst-<fqdn with dots as dashes>-<first 8 characters of deployment_id>` followed by its own suffix. A control-plane container is `<prefix>-<region code>-cp1`; worker i (from 1) is `<prefix>-<region code>-w<i>`. The cluster region id of a region is `local-<region code>-rtz-prod`.
3. **Addresses.** One machine network per Sovereign, range `machine_cidr` (default `172.30.0.0/16`). Region i (from 0) uses the /24 number i + 1 in it; its control-plane machine has host 10, its workers hosts 20 and up. Pod ranges are `10.<42+i>.0.0/16`, service ranges `10.<96+i>.0.0/16`.
4. **Front doors.** The control-plane machine's own address is the front door: outputs `control_plane_ip`, `load_balancer_ip` and, when `console_isolation_enabled` is `"true"`, `console_load_balancer_ip` are the primary control-plane machine's address. The gateway binds host ports 443 and 80 (console 8443 and 8080) on it, and the DNS server binds port 53 on it (`POWERDNS_DNSDIST_HOSTPORT` `"true"`). No node port is used anywhere.
5. **Load-balancer pool.** The address pool of region i is one address, host 10 + i of `external_cidr` (default `198.51.100.0/24`), which is on no machine. It is never the machine's own address: a pool that holds the machine's own address takes that address away from the machine and cuts its egress and its API server (lab test CLD-055, `docs/ledger/plan/spikes/CLD-055.md`).
6. **Boot of the control plane.** The module renders the shared template with `provider = "local"` and the same input names that `infra/providers/huawei/main.tf` passes, among them `variables = var.variables`, from which the template reads the hand-over switch. It then changes the render at exactly two texts, each of which must occur exactly once (a `precondition` on the control-plane container stops the plan otherwise): the line `        path: ./clusters/_template/bootstrap-kit` becomes `        path: ./clusters/_template/providers/local/kit`, and the 19 lines of the pack substitutes are inserted before the line that starts `            WILDCARD_CERT_ISSUER: `. The shared template itself does not change, and nothing tests `provider == "local"`. Then the comment lines are stripped as in the other modules.
7. **Pack substitutes.** Per region: `SOVEREIGN_CNPG_STORAGE_CLASS` = `default_storage_class` (the storage gate of slot 15b waits for this class to be the default); `HCLOUD_HR_SUSPEND` and `HUAWEI_HR_SUSPEND` `"true"`; `HCLOUD_CSI_ENABLED`, `EVS_CSI_ENABLED` and `HUAWEI_VPC_ROUTES_ENABLED` `"false"`; `SECONDARY_HR_SUSPEND` `"false"` in the primary and `"true"` in a secondary, `SECONDARY_EDGE_SUSPEND` the inverse; `CILIUM_LB_IPAM_ENABLED` `"true"` and `CILIUM_LB_IPAM_CIDRS` `<pool address>/32`; `CILIUM_CLUSTERMESH_PROXY_ENABLED` `"true"`, `CILIUM_CLUSTERMESH_PROXY_PORT` and `CLUSTERMESH_APISERVER_DIAL_PORT` = `clustermesh_proxy_port`; `CILIUM_GATEWAY_HOSTNETWORK_ENABLED` `"true"`; `SOVEREIGN_GATEWAY_HTTPS_PORT` `"443"`, `SOVEREIGN_GATEWAY_HTTP_PORT` `"80"`, `CONSOLE_GATEWAY_HTTPS_PORT` `"8443"`, `CONSOLE_GATEWAY_HTTP_PORT` `"8080"`; `POWERDNS_DNSDIST_HOSTPORT` `"true"`. Every key is a kit key of `docs/contracts/c5-kit-keys.txt`.
8. **Machines.** Each container is privileged, restarts `unless-stopped` (so it restarts after a reboot inside it), stops with `SIGRTMIN+3`, has tmpfs on `/run` and `/run/lock`, `/lib/modules` mounted read-only, and two volumes for `/var/lib/rancher` and `/var/lib/kubelet`. The user-data and the meta-data (instance id, host name, the break-glass key) are uploaded to `/var/lib/cloud/seed/nocloud/`. `upload` is in `lifecycle.ignore_changes`: boot data never replaces a machine. The image is built from `infra/providers/local/image/` (Ubuntu 22.04 with systemd, cloud-init and an SSH server; `systemd-resolved` masked so port 53 is free) unless `machine_image` names one.
9. **Workers.** `infra/providers/local/cloudinit-worker.tftpl` writes the k3s agent configuration (server `https://<control-plane address>:6443`, the agent token, the node address, the worker and region labels) and a `k3s-agent` systemd unit, downloads the k3s binary of `k3s_version` from the k3s release and checks it against the release's own `sha256sum-amd64.txt`. It does not use the install script host that the source-address ratchet counts.
10. **Network registry.** Output `network_registry` has the form that `scripts/check-network-registry.py` checks: pod supernet `10.42.0.0/15` for one or two regions (`10.40.0.0/13` above), MTU 1420, region separation `none`, empty access lists, and per region code, cloud region, zone (the cloud region when the zone is empty), mesh name and identifier (primary: `cluster_mesh_name`/`cluster_mesh_id` when set, else `<first label of the fqdn>-<code>` and 1; region i: identifier of the primary plus i), node, pod and service ranges, the control-plane address as edge and egress address, and with more than one region a mesh endpoint on the control-plane address and `clustermesh_proxy_port`.
11. **Reduced kit.** `scripts/generators/local-kit.py` reads the slot files listed in `clusters/_template/bootstrap-kit/kustomization.yaml`, takes the eleven roots `bp-cilium`, `bp-cert-manager`, `bp-flux`, `bp-crossplane`, `bp-openbao`, `bp-gitea`, `bp-powerdns`, `bp-catalyst-platform`, `bp-seaweedfs`, `bp-harbor`, `bp-kyverno` and every release they depend on through `spec.dependsOn`, leaves out the releases named in `infra/providers/local/kit-exclude.txt` (empty at first; a kept release that depends on an excluded one is an error), and writes `clusters/_template/providers/local/kit/kustomization.yaml`: the slot files in the order of the shared kit, by the relative path `../../../bootstrap-kit/<file>`, then every other `*.yaml` of the kit folder by name. It has `--check` and `--self-test`, and the workflow `check-generated-docs.yaml` runs both by itself. Its output carries no version.
12. **Storage.** `clusters/_template/providers/local/kit/local-path.yaml` holds a GitRepository of the upstream local-path provisioner at tag `v0.0.30` and a HelmRelease `local-path` of its chart `./deploy/chart/local-path-provisioner` with the class `local-path` as the cluster default and provisioner `rancher.io/local-path`.
13. **Pack files.** `infra/providers/local/pack.yaml` and `profile.yaml` are valid against the two schemas of `infra/providers/_contract/`. The profile: display name `Local machines`, lifecycle `unproven`, credentials from the operator with the one optional, non-secret field `runner_socket`, one region `local-1`, flavors `small` (2 vCPU, 4 GiB) and `medium` (4 vCPU, 8 GiB), storage class `local-path`, load-balancer mode `external-hostport`, no user-data limit, multi-region and not multi-cloud-region. The pack: OpenTofu providers `hashicorp/random` and `kreuzwerker/docker`, leak token `kreuzwerker`. Because every folder below `infra/providers` is a pack, `docs/generated/providers.md` gains the pack, and `TestLoadBothPacks` expects the three packs.
14. **Tests and workflow.** `tests/contract.tftest.hcl` is the module's mock header, the marker line `# --- contract body ---`, then `infra/providers/_contract/contract.tftest.body.hcl` byte for byte; the body takes the variables document from the contract fixture. `tests/local.tftest.hcl` holds the pack's own six runs and takes every value, the variables document among them, from the two-region contract fixture, with `default_storage_class` `local-path`. The workflow `.github/workflows/infra-local-tofu.yaml` runs, on pull requests that touch the module, the shared or contract folders, the shared kit or the reduced kit: `tofu init`, `fmt -check`, `validate` and `test` with OpenTofu 1.11.6 (job `local module validate fmt test`), and `kustomize build --load-restrictor=LoadRestrictionsNone` of the reduced kit with kustomize 5.4.3, which the workflow names in the input `kustomize-version` of the action `imranismail/setup-kustomize@v3` (job `local kit kustomize build`).
15. **What does not change.** The shared template, the Hetzner and Huawei modules, the contract files, the shared kit and every guard baseline.
16. **The ban on the local-path class.** `scripts/check-no-local-path.sh` (issue #3971) fails a pull request when a source file under `platform`, `products`, `clusters`, `infra` or `core` names the local-path storage class or its provisioner `rancher.io/local-path`: on a cloud Sovereign that class keeps data on a node's own disk, and replacing the node destroys it. The local pack runs on one host with no cloud account, so it has no cloud block volume, and the lab test CLD-055 found no built-in storage class on its machines and chose the upstream local-path provisioner for this pack. The guard therefore skips exactly two files, each by its full path: `infra/providers/local/profile.yaml` and `clusters/_template/providers/local/kit/local-path.yaml`. No folder is skipped: any other file that names the class, also one inside the pack, fails the guard as before. Nothing else of the ban changes: the Hetzner and Huawei modules keep refusing `local-path` in the validation of `default_storage_class`, the shared template keeps the k3s flag `--disable=local-storage`, and the Kyverno policy that denies the class at admission stays as it is (its release, slot `27a-kyverno-policies`, is not in the reduced kit).

+#!/usr/bin/env python3
+"""local-kit.py - the reduced bootstrap kit of the local provider pack, generated from the tree.
+
+It reads   clusters/_template/bootstrap-kit/kustomization.yaml   (the slot files, in their order)
+           clusters/_template/bootstrap-kit/<slot file>           (each listed slot file)
+           infra/providers/local/kit-exclude.txt                  (releases the reduced kit leaves out)
+           clusters/_template/providers/local/kit/*.yaml          (the pack's own files of the kit)
+It writes  clusters/_template/providers/local/kit/kustomization.yaml
+
+Usage, from any directory:
+  python3 scripts/generators/local-kit.py              write the file
+  python3 scripts/generators/local-kit.py --check      write nothing; exit 1 when the file on disk differs
+  python3 scripts/generators/local-kit.py --self-test  prove every rule on a throw-away tree
+
+Exit codes: 0 done or current; 1 the file is stale, or a self-test case failed;
+2 an input is missing or cannot be read, or breaks a rule below.
+
+The rules:
+  - the reduced kit holds the slot files of the releases in ROOTS and of every release they
+    depend on, directly or through others (spec.dependsOn of a HelmRelease or of a Flux
+    Kustomization, matched by metadata.name);
+  - a release named in the exclusion list is left out with its slot file, and the walk does
+    not go through it; a release that stays and depends on an excluded release is an error;
+  - every release in ROOTS and every name in the exclusion list is defined in a listed slot
+    file, every name in spec.dependsOn is defined in a listed slot file, and no name is
+    defined twice;
+  - the slot files are listed in the order of the shared kit, by a path relative to the
+    output folder, then the pack's own files (every *.yaml of the output folder except
+    kustomization.yaml) by name.
+The output carries no chart version: CI writes versions on main without a pull request, and
+this file must not go stale when it does.
+
+This file names no cloud: the provider-leak scanner reads it as shared code.
+"""
+import difflib
+import os
+import sys
+import tempfile
+
+try:
+    import yaml
+except ImportError:
+    sys.stderr.write("local-kit.py needs PyYAML: pip install pyyaml\n")
+    sys.exit(2)
+
+SCRIPT = "scripts/generators/local-kit.py"
+KIT = "clusters/_template/bootstrap-kit"
+PACK_KIT = "clusters/_template/providers/local/kit"
+OUTPUT = PACK_KIT + "/kustomization.yaml"
+EXCLUDE = "infra/providers/local/kit-exclude.txt"
+RELATIVE = "../../../bootstrap-kit/"
+
+# The releases the local pack must run. The kit holds them and everything they need.
+ROOTS = (
+    "bp-cilium",
+    "bp-cert-manager",
+    "bp-flux",
+    "bp-crossplane",
+    "bp-openbao",
+    "bp-gitea",
+    "bp-powerdns",
+    "bp-catalyst-platform",
+    "bp-seaweedfs",
+    "bp-harbor",
+    "bp-kyverno",
+)
+
+# The kinds whose metadata.name a spec.dependsOn entry names.
+RELEASE_KINDS = ("HelmRelease", "Kustomization")
+
+
+class InputError(Exception):
+    """An input is missing, cannot be read, or breaks a rule of this generator."""
+
+
+def read_text(root, relative):
+    try:
+        with open(os.path.join(root, relative), encoding="utf-8") as handle:
+            return handle.read()
+    except OSError as error:
+        raise InputError("%s: cannot be read: %s" % (relative, error.strerror))
+
+
+def load_documents(root, relative):
+    text = read_text(root, relative)
+    try:
+        return [d for d in yaml.safe_load_all(text) if d is not None]
+    except yaml.YAMLError as error:
+        raise InputError("%s: is not valid YAML: %s" % (relative, str(error).splitlines()[0]))
+
+
+def listed_slot_files(root):
+    documents = load_documents(root, KIT + "/kustomization.yaml")
+    if len(documents) != 1 or not isinstance(documents[0], dict) or not isinstance(documents[0].get("resources"), list):
+        raise InputError("%s/kustomization.yaml: has no list under the key resources" % KIT)
+    return [str(name) for name in documents[0]["resources"]]
+
+
+def releases(root, files):
+    """name -> (slot file, [names it depends on]) for every HelmRelease and Kustomization."""
+    found = {}
+    for name in files:
+        for document in load_documents(root, "%s/%s" % (KIT, name)):
+            if not isinstance(document, dict) or document.get("kind") not in RELEASE_KINDS:
+                continue
+            release = str((document.get("metadata") or {}).get("name") or "")
+            if not release:
+                raise InputError("%s/%s: a %s has no metadata.name" % (KIT, name, document.get("kind")))
+            if release in found:
+                raise InputError("%s/%s: the release %s is also defined in %s/%s" % (KIT, name, release, KIT, found[release][0]))
+            needs = []
+            for item in (document.get("spec") or {}).get("dependsOn") or []:
+                if not isinstance(item, dict) or not item.get("name"):
+                    raise InputError("%s/%s: an entry of spec.dependsOn of %s has no name" % (KIT, name, release))
+                needs.append(str(item["name"]))
+            found[release] = (name, needs)
+    return found
+
+
+def excluded(root):
+    names = []
+    for line in read_text(root, EXCLUDE).splitlines():
+        line = line.strip()
+        if line and not line.startswith("#"):
+            names.append(line)
+    return names
+
+
+def own_files(root):
+    try:
+        names = os.listdir(os.path.join(root, PACK_KIT))
+    except OSError as error:
+        raise InputError("%s: cannot be listed: %s" % (PACK_KIT, error.strerror))
+    return sorted(n for n in names if n.endswith(".yaml") and n != "kustomization.yaml")
+
+
+def generate(root):
+    files = listed_slot_files(root)
+    known = releases(root, files)
+    leave_out = excluded(root)
+    for name in leave_out:
+        if name not in known:
+            raise InputError("%s: names %s, which no listed slot file defines" % (EXCLUDE, name))
+    for name in ROOTS:
+        if name not in known:
+            raise InputError("the root release %s is defined in no listed slot file" % name)
+
+    keep = set()
+    stack = [name for name in ROOTS if name not in leave_out]
+    while stack:
+        name = stack.pop()
+        if name in keep:
+            continue
+        keep.add(name)
+        for need in known[name][1]:
+            if need not in known:
+                raise InputError("%s/%s: %s depends on %s, which no listed slot file defines" % (KIT, known[name][0], name, need))
+            if need in leave_out:
+                raise InputError("%s: %s is left out, but %s depends on it" % (EXCLUDE, need, name))
+            stack.append(need)
+
+    kept_files = {known[name][0] for name in keep}
+    lines = [
+        "# Generated by %s. Do not edit." % SCRIPT,
+        "# The reduced bootstrap kit of the local provider pack: the slot files of the releases",
+        "# the pack runs and of every release they depend on, then the pack's own files.",
+        "# To change it, change an input and run: python3 %s" % SCRIPT,
+        "apiVersion: kustomize.config.k8s.io/v1beta1",
+        "kind: Kustomization",
