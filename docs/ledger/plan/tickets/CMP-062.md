# CMP-062 — Validate policies to ValidatingPolicy, batch 1 (7 policies)

## In plain words

**The problem today.** Seven policies of the policy chart are still written in the engine's legacy policy kind, which the engine line after the current one no longer serves. No test proves what any of them admits or refuses, so a rewrite could change a verdict unseen. catalyst-api reads the mode of the legacy kind only, so a rewritten policy would drop out of the compliance views.

**What changes.** The seven policies are written in the new kind, in the same files and under the same names. Each has a test suite that was green on the legacy policy and is green on the new one with the same resources, and every reader of the policies reads both kinds.

**Done means:**

- The policy chart renders seven ValidatingPolicy objects named multi-replica-drainability, topology-spread, resource-requests, resource-limits, hpa-effective, runasnonroot-readonlyrootfs and substrate-stays-on-host.
- Each of the seven has a test suite under the chart's tests directory, and a suite whose policy copy is not the current render turns the pull request red.
- The bootstrap window still counts 1, 9 and 9 enforcing policies in its three renders.
- The legacy policy guard counts 38 objects, and seven checks leave the list of checks without a suite.
- catalyst-api reads the mode of the legacy and of the new policy kinds through one adapter, keeps a policy's entry while either object of its rewrite exists, and its policy-mode route accepts a ValidatingPolicy name.
- The chart's function test waits for every ValidatingPolicy to be ready, and the chargeback gates judge their charts against both policy kinds with the engine's tool version v1.19.2.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. **In place.** Each of the seven templates keeps its path, its `metadata.name`, its labels and annotations (the read model reads title, severity and description from them), its values keys under `compliancePolicies.<key>`, its `enabled` switch and every exclusion. Nothing a policy checks changes; no two policies merge.
2. **Shape.** `apiVersion: policies.kyverno.io/v1`, `kind: ValidatingPolicy`; `spec.validationActions` from the new helper `bp-kyverno-policies.actions`; `spec.evaluation.background.enabled: true`; `spec.matchConstraints.resourceRules` with operations `CREATE` and `UPDATE`; namespace exclusions as a match condition from the new helper `bp-kyverno-policies.excludeNamespacesExpr`; the checks as CEL `validations`. No automatic generation of controller rules: a policy that judged Pods and their controllers keeps one explicit resource rule per kind, so every resource gets exactly one result.
3. **The bootstrap window.** `bp-kyverno-policies.actions` renders `[Audit]` while the window of CMP-073 is open (`bootstrapMode` true and `sovereignConsume` not `local`) or when the policy's action is not `Enforce`, and `[Deny]` otherwise: the same rule as the legacy helper `bp-kyverno-policies.action`, which stays for the remaining legacy templates. `tests/bootstrap-window.sh` also counts a ValidatingPolicy whose `validationActions` holds `Deny`; its counts stay 1, 9 and 9.
4. **Same verdicts.** Each suite was written and run on the legacy render first (tool v1.19.2) and was green there. Then only `policy.yaml` (the new render) and one key of each result (`rule: <name>` became `isValidatingPolicy: true`) changed; the resources and the expected results are the same, and the suite is green. One exception: the legacy `runasnonroot-readonlyrootfs` had two rules and so two results per resource; the new policy gives one, `fail` when either rule failed, `pass` when both passed, `skip` when both skipped, on the same resources. Flipping any single expected result of a new suite turns it red. No resource of `tests/fixtures/` is edited.
5. **Current copies.** `tests/suites-current.sh` (in `scripts/run-policy-chart-tests.sh` and run by the chart tests) fails when a listed suite has no `policy.yaml` or its template does not render (C1), when the render holds no ValidatingPolicy of the suite's name (C2), when `policy.yaml` is not the render with the chart defaults (C3), and when a suite holding a ValidatingPolicy is not listed (C4). `--self-test` has one failing case per check.
6. **Readers of the new kind.** catalyst-api: the aggregator (`handler/compliance.go`) subscribes to `adapters.PolicyMode{}.Kinds()` and reads every mode through `adapters.PolicyMode{}.Mode`; its own `enginePolicyMode` is deleted. It keeps one entry per cluster, name and kind, and shows a name while either object of an in-place rewrite exists, preferring the legacy kind. A report result of source `KyvernoValidatingPolicy` counts as source kyverno (`adapters/policyreport.go`). The policy-mode route lists `validatingpolicies` beside `clusterpolicies` when it checks a policy name. The chart's function test also waits for `status.conditionStatus.ready` of each ValidatingPolicy and may get `validatingpolicies`. The chargeback gates select both kinds, and the chart gate's tool pin moves from v1.18.0 to v1.19.2 (v1.18.0 cannot map a CiliumNetworkPolicy for a ValidatingPolicy).
7. **Baselines.** `scripts/baselines/kyverno-legacy.json` loses the seven template entries (45 to 38 objects); `scripts/baselines/policy-suites.json` loses the seven checks that now have a suite.
8. **One difference, by convention.** The legacy rules named no operation; the new policies match `CREATE` and `UPDATE` only, the convention of the new kind, so a `DELETE` request is no longer judged. No suite case is a `DELETE`.

+#!/usr/bin/env bash
+# suites-current.sh - each ValidatingPolicy suite of the policy chart judges
+# the policy as the chart renders it, not a stale copy of it (CMP-062).
+#
+# A policy suite tests/<name>/ holds a COPY of its policy (policy.yaml):
+# `kyverno test` reads a file, never the chart. A copy that no longer equals
+# its template would keep the suite green while the real admission changed.
+# For every suite of the list SUITES below this test fails when
+#   C1 policy.yaml is missing, or the template does not render;
+#   C2 the render holds no ValidatingPolicy named like the suite;
+#   C3 policy.yaml is not the render of the template with the chart defaults;
+# and it fails when
+#   C4 a suite under tests/ holds a ValidatingPolicy and is not in SUITES.
+# CMP-063 and CMP-064 add the suites of their batches to SUITES.
+#
+# Usage:
+#   bash suites-current.sh              run the test on the chart above this file
+#   bash suites-current.sh <chart>      run the test on that chart directory
+#                                       (the workflow Chart tests (PR) passes it)
+#   bash suites-current.sh --self-test  prove each check can fail
+#
+# Re-render a suite's copy with:
+#   helm template platform/kyverno-policies/chart --show-only templates/<template> \
+#     | grep -v '^# Source:' | sed '1{/^---$/d}' > platform/kyverno-policies/chart/tests/<name>/policy.yaml
+#
+# Exit code: 0 pass. 1 a check failed. 2 wrong usage.
+#
+# HELM_BIN  The helm command. Default: helm. The self-test sets a fake one.
+set -euo pipefail
+export LC_ALL=C
+
+CHART="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
+HELM="${HELM_BIN:-helm}"
+TAG="[suites-current]"
+
+# One suite per line: <suite directory, the policy's name> <template under templates/>.
+SUITES=(
+  "multi-replica-drainability baseline/01-multi-replica.yaml"
+  "topology-spread baseline/03-topology-spread.yaml"
+  "resource-requests baseline/05-resource-requests.yaml"
+  "resource-limits baseline/06-resource-limits.yaml"
+  "hpa-effective baseline/08-hpa-effective.yaml"
+  "runasnonroot-readonlyrootfs baseline/17-runasnonroot-readonlyrootfs.yaml"
+  "substrate-stays-on-host baseline/22-substrate-on-host.yaml"
+)
+
+# check_suite <chart> <name> <template>: C1 to C3 for one suite. Prints one
+# line. Returns 1 when a check fails.
+check_suite() {
+  local chart="$1" name="$2" template="$3" copy render
+  copy="$chart/tests/$name/policy.yaml"
+  render="$TMP/render-$name.yaml"
+  if [ ! -f "$copy" ]; then
+    echo "$TAG FAIL C1 $name: $copy is missing"
+    return 1
+  fi
+  if ! "$HELM" template "$chart" --show-only "templates/$template" > "$render.raw" 2> "$TMP/err"; then
+    cat "$TMP/err"
+    echo "$TAG FAIL C1 $name: templates/$template does not render"
+    return 1
+  fi
+  grep -v '^# Source:' "$render.raw" | sed '1{/^---$/d}' > "$render"
+  if ! grep -q -x 'kind: ValidatingPolicy' "$render" || ! grep -q -x "  name: $name" "$render"; then
+    echo "$TAG FAIL C2 $name: the render of templates/$template holds no ValidatingPolicy $name"
+    return 1
+  fi
+  if ! diff -u "$copy" "$render" > "$TMP/diff"; then
+    cat "$TMP/diff"
+    echo "$TAG FAIL C3 $name: policy.yaml is not the current render of templates/$template; re-render it (see the header of this file)"
+    return 1
+  fi
+  echo "$TAG PASS $name"
+}
+
+# check_listed <chart>: C4. Prints one line per suite that holds a
+# ValidatingPolicy and is not in SUITES. Returns 1 when there is one.
+check_listed() {
+  local chart="$1" copy name entry listed rc=0
+  for copy in "$chart"/tests/*/policy.yaml; do
+    [ -f "$copy" ] || continue
+    grep -q -x 'kind: ValidatingPolicy' "$copy" || continue
+    name="$(basename "$(dirname "$copy")")"
+    listed=0
+    for entry in "${SUITES[@]}"; do
+      if [ "${entry%% *}" = "$name" ]; then listed=1; fi
+    done
+    if [ "$listed" -eq 0 ]; then
+      echo "$TAG FAIL C4 $name: the suite holds a ValidatingPolicy and is not in SUITES of this file"
+      rc=1
+    fi
+  done
+  return "$rc"
+}
+
+run_test() {
+  local entry failed=0
+  for entry in "${SUITES[@]}"; do
+    # shellcheck disable=SC2086 # the entry is two words on purpose
+    check_suite "$CHART" $entry || failed=1
+  done
+  check_listed "$CHART" || failed=1
+  if [ "$failed" -ne 0 ]; then
+    echo "$TAG FAILED"
+    return 1
+  fi
+  echo "$TAG ALL PASS: ${#SUITES[@]} suites current"
+}
+
+# st_case <name> <wanted exit code> <function> <arguments...>
+st_case() {
+  local label="$1" want="$2" rc=0
+  shift 2
+  "$@" > "$ST_TMP/out" 2>&1 || rc=$?
+  if [ "$rc" != "$want" ]; then
+    echo "self-test FAIL: $label: exit code $rc, want $want"
+    cat "$ST_TMP/out"
+    exit 1
+  fi
+  echo "self-test ok: $label"
+}
+
+self_test() {
+  local doc legacy
+  ST_TMP="$(mktemp -d)"
+  trap 'rm -rf "$ST_TMP" "$TMP"' EXIT
+  mkdir -p "$ST_TMP/chart/tests/s1" "$ST_TMP/chart/tests/s2" "$ST_TMP/chart/tests/s3"
+  doc=$'apiVersion: policies.kyverno.io/v1\nkind: ValidatingPolicy\nmetadata:\n  name: s1\nspec:\n  validationActions: [Audit]'
+  legacy=$'apiVersion: kyverno.io/v1\nkind: ClusterPolicy\nmetadata:\n  name: s1\nspec:\n  validationFailureAction: Audit'
+
+  # A fake helm: prints the file render with the lines helm adds, or fails
+  # when the file says FAIL. The single quotes are wanted: the fake expands
+  # the path itself.
+  # shellcheck disable=SC2016
+  printf '%s\n' '#!/usr/bin/env bash' \
+    'if [ "$(cat "'"$ST_TMP"'/render")" = "FAIL" ]; then echo "render error" >&2; exit 1; fi' \
+    'echo "---"; echo "# Source: x/templates/t.yaml"; cat "'"$ST_TMP"'/render"' > "$ST_TMP/helm"
+  chmod +x "$ST_TMP/helm"
+  HELM="$ST_TMP/helm"
+
+  printf '%s\n' "$doc" > "$ST_TMP/render"
+  printf '%s\n' "$doc" > "$ST_TMP/chart/tests/s1/policy.yaml"
+  st_case "1 a copy equal to the render passes (the --- and Source lines are not part of it)" 0 check_suite "$ST_TMP/chart" s1 t.yaml
+  printf '%s\n' "${doc/Audit/Deny}" > "$ST_TMP/chart/tests/s1/policy.yaml"
+  st_case "2 C3 a copy that differs from the render fails" 1 check_suite "$ST_TMP/chart" s1 t.yaml
+  st_case "3 C1 a missing policy.yaml fails" 1 check_suite "$ST_TMP/chart" s9 t.yaml
+  printf 'FAIL\n' > "$ST_TMP/render"
+  st_case "4 C1 a template that does not render fails" 1 check_suite "$ST_TMP/chart" s1 t.yaml
+  printf '%s\n' "$legacy" > "$ST_TMP/render"
+  printf '%s\n' "$legacy" > "$ST_TMP/chart/tests/s1/policy.yaml"
+  st_case "5 C2 a render of the legacy kind fails, even when the copy equals it" 1 check_suite "$ST_TMP/chart" s1 t.yaml
+  printf '%s\n' "$doc" > "$ST_TMP/render"
+  printf '%s\n' "$doc" > "$ST_TMP/chart/tests/s2/policy.yaml"
+  st_case "6 C2 a render of another policy's name fails, even when the copy equals it" 1 check_suite "$ST_TMP/chart" s2 t.yaml
+  rm "$ST_TMP/chart/tests/s2/policy.yaml"
+
+  SUITES=("s1 t.yaml")
+  printf '%s\n' "$doc" > "$ST_TMP/chart/tests/s1/policy.yaml"
+  printf '%s\n' "$legacy" > "$ST_TMP/chart/tests/s3/policy.yaml"
+  st_case "7 C4 every suite with a ValidatingPolicy listed, a legacy suite not: passes" 0 check_listed "$ST_TMP/chart"
+  printf '%s\n' "${doc/s1/s2}" > "$ST_TMP/chart/tests/s2/policy.yaml"
+  st_case "8 C4 a suite with a ValidatingPolicy that is not listed fails" 1 check_listed "$ST_TMP/chart"
+
+  echo "self-test: 8 cases passed"
+}
+
+TMP="$(mktemp -d)"
+trap 'rm -rf "$TMP"' EXIT
+if [ "$#" -eq 0 ]; then
+  run_test
+elif [ "$#" -eq 1 ] && [ "$1" = "--self-test" ]; then
+  self_test
+elif [ "$#" -eq 1 ] && [ -d "$1" ]; then
+  CHART="$(cd "$1" && pwd)"
+  run_test
+else
+  echo "usage: bash suites-current.sh [<chart directory> | --self-test]" >&2
+  exit 2
+fi
