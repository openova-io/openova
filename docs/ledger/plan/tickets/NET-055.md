# NET-055 — Canonical documents state the zone, firewall and default-deny design of record 0019

## In plain words

**The problem today.** The architecture document, the definition of done and the glossary still describe a Sovereign as a management cluster, workload clusters and internet-facing clusters, and the definition of done still requires a zone virtual cluster in every region. That design was withdrawn months ago. Several sentences also claim a firewall at the edge, a default-deny baseline and a private-link ban that the code does not have.

**What changes.** The sections on cluster topology, zones and the link between regions say what decision record 0019 decided and what the code does today. Default deny, the edge node pool and the firewall are written as target, not built, with the work that builds them.

**Done means:**

- No canonical document names an internet-facing zone cluster, a management cluster or a zone virtual cluster as part of a Sovereign.
- The architecture invariants A2 and A4 of the definition of done state the encryption between nodes and the one cluster per region of decision record 0019.
- The glossary defines a zone as a part of a region's one cluster, and the building block as a fixed token without zone meaning.
- The security document has a section on network separation and the firewall, marked target with decision record 0019.
- Every rewritten section of the four documents links decision record 0019, and the check of the canonical documents passes.

The rest of this ticket is the exact instruction for the model that does the work.

A reader of `docs/ARCHITECTURE.md`, `docs/DOD.md`, `docs/GLOSSARY.md` and `docs/SECURITY.md` learns the zone model that ADR-0019 decided: a Sovereign region is one cluster, and its zones are the edge node pool, the platform namespaces and one namespace and one vCluster per Organization. ## 3. The model (the law)
1. ADR-0019 is the decision. A Sovereign region is one cluster (its point 2). The zones inside it are the edge (the edge node pool), the platform (the bootstrap-kit namespaces) and the Organizations (one namespace and one vCluster each). A vCluster is created only per Organization (point 4). The building-block token `rtz` in cluster names has no zone meaning and is not changed (point 5).
2. The network claims the documents may make are the five of ADR-0019 point 7, read with point 8: encryption in transit between nodes, with the exclusion of the control-plane node; identity-based default-deny policy; no workload mutual TLS; no egress gateway; a firewall in the path only where a `WebApplicationFirewall` is Ready.
3. A statement about something that is not built says so in the words "target, not built" and names the work that builds it: default deny (epic NET-160, gate check NET-G06), the Organization fence (NET-170, gate check NET-G07), the edge node pool (epic NET-180), a firewall in the path (epic NET-250). Both gate checks are `not-built` in `docs/ledger/gates.yaml` (P3).
4. A statement about something that is built names the code that does it, and only facts measured in field 4 are stated.
5. Removed from the four documents: every mention of the zone `dmz` (16 lines in `docs/ARCHITECTURE.md`, 8 in `docs/DOD.md`, 1 in `docs/GLOSSARY.md`); the management cluster as a cluster of its own; the claims "mTLS via WireGuard", "Default-deny CCNP baseline", per-Application egress rules from `Blueprint.spec.networking.egress` (no code reads that field), "DMZ WireGuard over PUBLIC IPs" and "no VPC peering"; mesh certificates from SPIRE as a deferred path; the 6/6 zone-vCluster count of gate D15.
6. Every second-level section that this ticket changes links ADR-0019 outside a code block: sections §1, §3, §4, §5, §6, §8 and §10 of `docs/ARCHITECTURE.md`, sections §1, §2, §3 and §6 of `docs/DOD.md`, section "Infrastructure" of `docs/GLOSSARY.md` and section 2 of `docs/SECURITY.md`.
7. `docs/SECURITY.md` gains the third-level section `### 2.2 Network separation and the firewall`, placed before `### Why this configuration is sufficient today`. Its first non-empty line is the target marker `> State: target. Decision: ADR-0019`, and its next paragraph starts with "Target, not built.". `scripts/check-doc-state.py` counts markers of second-level sections only, so no count of `docs/ledger/doc-state-baseline.txt` changes and that file is not edited.
