# CTL-816 — A peer region's serving verdict reaches the Application, and the API sees a running move

## In plain words

**The problem today.** The application controller runs in one region and can test only that region's endpoints. When the Primary moves to the other region, the controller reports that region as not observable, takes that as the Application's verdict, and the Application stays not ready after every planned move. The application API also looks for an old phase name that the Continuum controller no longer writes, so it reports no move while one runs, and it shows none of the move's steps.

**What changes.** Each region's Continuum observer runs the same endpoint test for its own region and answers it to the other region. The application controller asks for that answer, so after a planned move the Application follows the new Primary's verdict. The application API recognises a running move and lists its steps with a link to the move's Jobs group.

**Done means:**

- With the Primary in the other region and that region serving, the Application becomes Ready.
- When the other region's observer reports the endpoint failing, the Application is not ready and carries that region's reason and message.
- When the other region's observer does not answer, the Application's serving verdict is unknown and says why, never true.
- A Continuum in the middle of a move is reported by the application API as a move in progress, with each step and the name of the Jobs group that records it.
- The endpoint test exists once in the code, and the Continuum's rights grow only by reading routes and services.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After a planned move of an Application's Primary to the second region, the Application reports `Ready=True` when the second region serves, `Ready=False` with that region's reason when it does not, and `Ready=Unknown` with reason `ServingNotObservable` only when the second region cannot be asked. The application controller of the writer region gets the second region's verdict from that region's Continuum observer, which runs the same functional probe the controller runs locally. While a Continuum moves the Primary, the application API reports `switchoverInProgress: true`, the step it is on, and every step of the move with a link to its Jobs group.

## 3. The model (the law)
1. **One probe.** The functional endpoint probe lives in the new package `core/controllers/pkg/serving`: for every HTTPRoute a HelmRelease installed (label `app.kubernetes.io/instance=<release>` or `helm.toolkit.fluxcd.io/name=<release>`), a GET of the declared health path through the region's own gateway Service `cilium-gateway-<gateway>` in the gateway's namespace, with Host and TLS server name set to the route hostname. Status below 500 is `True`/`Serving`; 5xx or a transport error is `False`/`EndpointNotServing`; a route without hostname or parent, or a gateway Service that cannot be read or has no 443, 8443, 80 or 8080 port, is `Unknown`/`ServingProbeUnverifiable`. The application controller and the Continuum observer both call this package. The controller keeps no copy: its `ServingProbe` and `ServingProber` become aliases of `serving.Probe` and `serving.Prober`.
2. **The observer serves its region's verdict.** `GET /v1/serving?namespace=<ns>&app=<app>[&helmRelease=<hr-ns>/<hr-name>][&path=<health path>]` on the observer port (8082) answers `{"region","status","reason","message"}` for the member's HelmReleases in this region: the one named by `helmRelease`, else those labelled `catalyst.openova.io/app=<app>` and `catalyst.openova.io/region=<this region>` whose namespace or target namespace is `<ns>`. The path defaults to `/`. No HelmRelease found gives `Unknown`/`ServingProbeUnverifiable` with a message that starts `region <region>: `. Any method other than GET is 405; a request without `namespace` or `app` is 400. The route is read-only.
3. **Rights.** The Continuum's ClusterRole gains exactly two rules: `get` and `list` on `httproutes.gateway.networking.k8s.io`, and `get` on `services`. No write verb is added; `scripts/check-continuum-no-workload-mutation.sh` keeps passing.
4. **The controller asks the peer.** For every plan region that is not the controller's own region, and only when `LocalRegionID` is set, the controller asks that region's observer for each leg placed there (a `status.perCluster` row whose `region` is that region's canonical id): `GET <DefaultPeerObserverURLTemplate with {region}>/v1/serving` with `namespace` and `app` of the Application, `helmRelease=<row namespace>/<row hr>` and `path` = the Blueprint's health path. It uses the existing 3-second client `peerObserverHTTP` and `Cfg.PeerObserverURLTemplate` when set. The region's verdict is the worst of the answers (False over Unknown over True). An answer that is not HTTP 200, does not decode, names another region, or has a status other than `True`, `False` or `Unknown` is no answer: the region is `Unknown`/`ServingNotObservable` with the main message `region <r> is not observable from the application-controller in region <local>` followed by `: ` and the cause. A region with no leg of the Application, and every peer region of a controller without `LocalRegionID`, keeps that main message unchanged.
5. **The aggregate rule does not change.** The local region's `False` wins; otherwise the aggregate is the Primary region's verdict, which is now the peer's answer when the Primary is a peer. `Ready` follows the aggregate through the existing code of `application_controller.go`, which this ticket does not touch.
6. **The API sees a move.** `switchoverInProgress` is `status.switchoverInProgress` when the Continuum carries it, else true for the phase `Transitioning` (what the Continuum controller writes) or `SwitchingOver` (the name before ADR-0015). The new field `transition` carries `{id, from, to, startedAt, outcome, message, active, jobName, steps[]}` from `status.transition` and `status.activity`, and is absent when the Continuum has no activity entry with an id and no `status.transition.id`. While a move runs, `step` is `status.message` when present, else `step N/M — <phase>: <message>` of the first step that has not succeeded. `jobName` is set only when steps exist, and it is the Jobs group the Jobs projection writes: both name it with `continuummove.JobsGroup`. This logic lives in the new package `products/catalyst/bootstrap/api/internal/continuummove`.
7. **The handler package does not grow.** The non-test files directly in `products/catalyst/bootstrap/api/internal/handler` keep exactly the same number of lines, so `scripts/check-api-structure.py` passes with its baseline unchanged.
8. **Deleted.** The controller's own copy of the probe: `httpServingProber`'s body, `probeOneRoute`, `gatewayProbePort` and the HTTPRoute loop of `probeHTTPRoutes` in `application_controller_serving.go`, and the inline group naming of the Jobs projection. Nothing else is deleted.
9. No chart version line, pin or image tag changes. CI writes the next chart version after the merge.

+func ProbeRoutes(ctx context.Context, dyn dynamic.Interface, prober Prober, namespace, release, path string) []Verdict {
+	seen := map[string]bool{}
+	var routes []unstructured.Unstructured
+	for _, sel := range []string{InstanceLabel + "=" + release, "helm.toolkit.fluxcd.io/name=" + release} {
+		list, err := dyn.Resource(HTTPRouteGVR).Namespace(namespace).List(ctx, metav1.ListOptions{LabelSelector: sel})
+		if err != nil {
+			if kindAbsent(err) {
+				continue
+			}
+			return []Verdict{{
+				Status:  "Unknown",
+				Reason:  ReasonServingProbeUnverifiable,
+				Message: fmt.Sprintf("could not list HTTPRoutes in %s for %s: %v", namespace, release, err),
+			}}
+		}
+		for _, it := range list.Items {
+			if !seen[it.GetName()] {
+				seen[it.GetName()] = true
+				routes = append(routes, it)
+			}
+		}
+	}
+	out := make([]Verdict, 0, len(routes))
+	for i := range routes {
+		out = append(out, ProbeRoute(ctx, dyn, prober, &routes[i], path))
+	}
+	return out
+}

+// ProbeRoute probes one HTTPRoute through its parent gateway.
+func ProbeRoute(ctx context.Context, dyn dynamic.Interface, prober Prober, rt *unstructured.Unstructured, path string) Verdict {
+	id := rt.GetNamespace() + "/" + rt.GetName()
+	hosts, _, _ := unstructured.NestedStringSlice(rt.Object, "spec", "hostnames")
+	parents, _, _ := unstructured.NestedSlice(rt.Object, "spec", "parentRefs")
+	if len(hosts) == 0 || hosts[0] == "" || len(parents) == 0 {
+		return Verdict{Status: "Unknown", Reason: ReasonServingProbeUnverifiable,
+			Message: fmt.Sprintf("HTTPRoute %s declares no hostname or no parent Gateway; nothing to probe", id)}
+	}
+	pm, _ := parents[0].(map[string]interface{})
+	gw, _ := pm["name"].(string)
+	gwNS, _ := pm["namespace"].(string)
+	if gwNS == "" {
+		gwNS = rt.GetNamespace()
+	}
+	if gw == "" {
+		return Verdict{Status: "Unknown", Reason: ReasonServingProbeUnverifiable,
+			Message: fmt.Sprintf("HTTPRoute %s parentRefs[0] names no Gateway", id)}
+	}
+	svcName := "cilium-gateway-" + gw
+	svc, err := dyn.Resource(ServiceGVR).Namespace(gwNS).Get(ctx, svcName, metav1.GetOptions{})
+	if err != nil {
+		return Verdict{Status: "Unknown", Reason: ReasonServingProbeUnverifiable,
+			Message: fmt.Sprintf("gateway Service %s/%s for HTTPRoute %s not readable: %v", gwNS, svcName, id, err)}
+	}
+	port, useTLS, ok := GatewayProbePort(svc)
+	if !ok {
+		return Verdict{Status: "Unknown", Reason: ReasonServingProbeUnverifiable,
+			Message: fmt.Sprintf("gateway Service %s/%s exposes no 443/8443/80/8080 port", gwNS, svcName)}
+	}
+	p := Probe{
+		Addr: fmt.Sprintf("%s.%s.svc.cluster.local:%d", svcName, gwNS, port),
+		Host: hosts[0],
+		Path: path,
+		TLS:  useTLS,
+	}
+	scheme := "http"
+	if useTLS {
+		scheme = "https"
+	}
+	target := fmt.Sprintf("%s://%s%s via gateway %s/%s", scheme, p.Host, p.Path, gwNS, gw)
+	code, err := prober.Probe(ctx, p)
+	if err != nil {
+		return Verdict{Status: "False", Reason: ReasonEndpointNotServing,
+			Message: fmt.Sprintf("GET %s failed: %v", target, err)}
+	}
+	if code >= 500 {
+		return Verdict{Status: "False", Reason: ReasonEndpointNotServing,
+			Message: fmt.Sprintf("GET %s answered HTTP %d", target, code)}
+	}
+	return Verdict{Status: "True", Reason: ReasonServing,
+		Message: fmt.Sprintf("GET %s answered HTTP %d", target, code)}
+}

+// GatewayProbePort picks the TLS listener (443/8443 or a port named https*),
+// else the plain one (80/8080).
+func GatewayProbePort(svc *unstructured.Unstructured) (int64, bool, bool) {
+	ports, _, _ := unstructured.NestedSlice(svc.Object, "spec", "ports")
+	var plain int64
+	for _, p := range ports {
+		pm, ok := p.(map[string]interface{})
+		if !ok {
+			continue
+		}
+		n, _ := pm["port"].(int64)
+		name, _ := pm["name"].(string)
+		if n == 443 || n == 8443 || strings.HasPrefix(name, "https") {
+			return n, true, true
+		}
+		if plain == 0 && (n == 80 || n == 8080) {
+			plain = n
+		}
+	}
+	if plain != 0 {
+		return plain, false, true
+	}
+	return 0, false, false
+}

+// Worst rolls verdicts up: False > Unknown > True. No verdicts at all =
+// NoFunctionalProbeDeclared.
+func Worst(vs []Verdict) Verdict {
+	if len(vs) == 0 {
+		return Verdict{
+			Status:  "Unknown",
+			Reason:  ReasonNoFunctionalProbe,
+			Message: "no functional probe declared: the app installed no HTTPRoute and no database that requires synchronous replication",
+		}
+	}
+	var unknown *Verdict
+	var msgs []string
+	for i := range vs {
+		switch vs[i].Status {
+		case "False":
+			return vs[i]
+		case "Unknown":
+			if unknown == nil {
+				unknown = &vs[i]
+			}
+		default:
+			msgs = append(msgs, vs[i].Message)
+		}
+	}
+	if unknown != nil {
+		return *unknown
+	}
+	sort.Strings(msgs)
+	return Verdict{Status: "True", Reason: ReasonServing, Message: strings.Join(msgs, "; ")}
+}

+// Package continuummove reads the primary move a Continuum records in its
+// status, for the application API (ADR-0015 D8).
+//
+// The continuum controller (core/controllers/continuum) writes, for every
+// member it acts on:
+//
+//	status.phase       "Transitioning" while a move runs; "Healthy" once it
+//	                   converged; "Failed", "Degraded", "Pending" otherwise
+//	status.transition  {group, outcome, message} on every pass, plus
+//	                   {id, from, to, startedAt, lossMode} once a move exists
+//	status.activity[]  one entry per step: {id, phase, member, state,
+//	                   transition, startedAt, finishedAt, message}
+//
+// It writes no status.switchoverInProgress and no status.message. Before this
+// package the API read only the pre-ADR-0015 phase "SwitchingOver", so it
+// reported no move while one ran, and it returned none of the steps.
+package continuummove
+
+import (
+	"strconv"
+	"strings"
+
+	"k8s.io/apimachinery/pkg/apis/meta/v1/unstructured"
+
+	"github.com/openova-io/openova/products/catalyst/bootstrap/api/internal/jobs"
+)
+
+// Step is one status.activity entry, verbatim.
+type Step struct {
+	Phase      string `json:"phase"`
+	Member     string `json:"member,omitempty"`
+	State      string `json:"state"`
+	StartedAt  string `json:"startedAt,omitempty"`
+	FinishedAt string `json:"finishedAt,omitempty"`
+	Message    string `json:"message,omitempty"`
+}
+
+// Transition is the Continuum's current or most recent primary move.
+type Transition struct {
+	ID        string `json:"id,omitempty"`
+	From      string `json:"from,omitempty"`
+	To        string `json:"to,omitempty"`
+	StartedAt string `json:"startedAt,omitempty"`
+	// Outcome is the controller's verdict: Transitioning while the move
+	// runs, then Converged or a failure outcome.
+	Outcome string `json:"outcome,omitempty"`
+	Message string `json:"message,omitempty"`
+	// Active is true while the move runs.
+	Active bool `json:"active"`
+	// JobName is the Jobs group that records this move (JobsGroup), so the
+	// console can link to its full log. Empty when no step is on record.
+	JobName string `json:"jobName,omitempty"`
+	Steps   []Step `json:"steps"`
+}
+
+// Moving reports whether the Continuum is running a primary move:
+// status.switchoverInProgress when the CR carries it, else a phase of
+// "Transitioning" (what the continuum controller writes) or "SwitchingOver"
+// (the name before ADR-0015).
+func Moving(cr *unstructured.Unstructured) bool {
+	if b, ok, _ := unstructured.NestedBool(cr.Object, "status", "switchoverInProgress"); ok {
+		return b
+	}
+	phase, _, _ := unstructured.NestedString(cr.Object, "status", "phase")
+	return phase == "Transitioning" || phase == "SwitchingOver"
+}
+
+// Of returns the move on record, or nil when there is none: no activity entry
+// with an id and no status.transition.id. moving is the answer of Moving;
+// jobName is the Jobs group of the move (JobsGroup).
+func Of(cr *unstructured.Unstructured, moving bool, jobName string) *Transition {
+	steps := stepsOf(cr)
+	rec, _, _ := unstructured.NestedMap(cr.Object, "status", "transition")
+	id, _ := rec["id"].(string)
+	if len(steps) == 0 && id == "" {
+		return nil
+	}
+	t := &Transition{ID: id, Active: moving, Steps: steps}
+	t.From, _ = rec["from"].(string)
+	t.To, _ = rec["to"].(string)
+	t.StartedAt, _ = rec["startedAt"].(string)
+	t.Outcome, _ = rec["outcome"].(string)
+	t.Message, _ = rec["message"].(string)
+	for _, s := range steps {
+		if !moving && t.Outcome == "" && (s.State == "running" || s.State == "pending") {
+			t.Active = true
+		}
+	}
+	if len(steps) > 0 {
+		t.JobName = jobName
+	}
+	return t
+}

+// StepLine is the line the API shows while a move runs: status.message when
+// the CR carries one, else "step N/M — <phase>: <message>" for the first step
+// that has not succeeded, else "".
+func StepLine(cr *unstructured.Unstructured, t *Transition) string {
+	if s, _, _ := unstructured.NestedString(cr.Object, "status", "message"); s != "" {
+		return s
+	}
+	if t == nil {
+		return ""
+	}
+	for i, s := range t.Steps {
+		if s.State == "succeeded" {
+			continue
+		}
+		line := "step " + strconv.Itoa(i+1) + "/" + strconv.Itoa(len(t.Steps)) + " — " + s.Phase
+		if s.Message != "" {
+			line += ": " + s.Message
+		}
+		return line
+	}
+	return ""
+}

+// JobsGroup is the Jobs group JobName of one object's move:
+// "topology-transition-<namespace>-<name>", plus "-<slug>" when the move has
+// an id. The Jobs projection of the handler and Of's jobName both use it, so
+// the link names the group the projection writes.
+func JobsGroup(namespace, name, slug string) string {
+	group := jobs.TopologyTransitionGroupPrefix + namespace + "-" + name
+	if slug != "" {
+		group += "-" + slug
+	}
+	return group
+}
+
+// stepsOf reads status.activity verbatim. An entry without an id is skipped,
+// as the Jobs projection skips it.
+func stepsOf(cr *unstructured.Unstructured) []Step {
+	raw, _, _ := unstructured.NestedSlice(cr.Object, "status", "activity")
+	out := make([]Step, 0, len(raw))
+	for _, r := range raw {
+		m, ok := r.(map[string]interface{})
+		if !ok {
+			continue
+		}
+		if id, _ := m["id"].(string); strings.TrimSpace(id) == "" {
+			continue
+		}
+		s := Step{}
+		s.Phase, _ = m["phase"].(string)
+		s.Member, _ = m["member"].(string)
+		s.State, _ = m["state"].(string)
+		s.StartedAt, _ = m["startedAt"].(string)
+		s.FinishedAt, _ = m["finishedAt"].(string)
+		s.Message, _ = m["message"].(string)
+		out = append(out, s)
+	}
+	return out
+}
