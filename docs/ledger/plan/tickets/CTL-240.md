# CTL-240 — Batch G: catalogue writers onto the library

## In plain words

**The problem today.** The API's catalogue screens write Blueprint files into Git with their own direct file calls, one file at a time, with no check of the content and no record of who asked or through which surface. The edit-pr route opens a pull request on a side branch that nothing reviews. When Gitea is not set up, the card edit skips its Git write in silence.

**What changes.** Every catalogue write goes through the platform's one commit library, which checks the content, refuses a Kubernetes Secret and stamps the commit with a change id and the surface it came through. The edit-pr route commits straight to the main branch, as publish does. Without a commit library the write routes answer 503 git-unavailable and the card edit reports the failure.

**Done means:**

- Publishing, curating, editing a Blueprint card and saving the full Blueprint YAML each make a commit through the commit library, with a change id and the surface named in the commit message.
- The edit-pr route commits the edited file to the main branch and opens no pull request and no branch.
- When the API has no commit library, publish, curate, edit-pr and the full YAML edit answer 503 with the error git-unavailable, and the card edit reports that its Git write failed.
- The three catalogue handler files call no direct Gitea write.
- Every test of the API module passes on the pull request, and the handler package of the API is smaller than before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
In the API module (`products/catalyst/bootstrap/api`), the three catalogue handler files `internal/handler/blueprints.go`, `internal/handler/catalog_edit_git.go` and `internal/handler/catalog_iac_edit.go` make every write to Git through the commit library `core/controllers/pkg/gitwrite` (contract C4, `docs/contracts/C4-git-layout-and-commit-library.md`), with scope `gitwrite.Catalog()`. They call no `PutFile`, `PutFileIfMatch`, `DeleteFile`, `CreatePullRequest` or `EnsureBranch` of the Gitea client any more. The route `POST /api/v1/sovereigns/{id}/blueprints/edit-pr` commits directly to `main` of `<org>/shared-blueprints`, as publish does; its response keeps every field name and carries the commit address where it carried the pull-request address. When no commit library is configured, the four catalogue write routes (`PUT /api/v1/catalog/{name}/iac`, `POST …/blueprints/publish`, `POST …/blueprints/curate`, `POST …/blueprints/edit-pr`) answer HTTP 503 with `{"error":"git-unavailable", ...}`, and the card edit and the Flux aggregator write return an error instead of skipping in silence. The repositories, branches, paths and file contents that are written do not change. A new test file proves the change; the handler package shrinks by 42 lines and the baseline of its guard is lowered by the same number.

## 3. The model (the law)
The change is one embedded patch. These are the rules it implements, so that a reader can check them; you do not write any of it.

1. **Where the commit library comes from.** `NewGiteaClientFromEnv` in `blueprints.go` (called by `cmd/api/main.go`, which does not change) still returns the Gitea client built from `CATALYST_GITEA_URL` and `CATALYST_GITEA_TOKEN`, or nil when either is empty. When `SOVEREIGN_FQDN` is also set, it returns a `catalogGitClient`: a struct that embeds the `*gitea.Client` and a `gitwrite.Writer` built with `gitwrite.New(gitwrite.Config{BaseURL: <CATALYST_GITEA_URL>, Tokens: gitwrite.SharedTokenSource(<CATALYST_GITEA_TOKEN>), RobotDomain: "robots." + <SOVEREIGN_FQDN>})`. Reads still go to the Gitea client; writes go to the `gitwrite.Writer`. Without `SOVEREIGN_FQDN` it returns the plain `*gitea.Client`, which has no commit library. The handler's field `giteaClient` and `handler.go` do not change.
2. **How a handler finds the library.** `catalogWriterOf(c GiteaBlueprintClient) gitwrite.Writer` returns `c` as a `gitwrite.Writer` when it is one, else nil. A nil client gives nil. It is a plain function, not a method of `Handler`, so the method count of the handler package does not change.
3. **One commit helper.** `commitCatalogFile(ctx, w, repo, path, content, summary, author) (committed bool, commitSHA string, err error)` commits one file with `Change{Scope: gitwrite.Catalog(), Repo: repo, Files: [{Path: path, Op: OpUpsert, Content: content}], Summary: <summary>, Author: author, ChangeID: gitwrite.NewChangeID(), Via: gitwrite.ViaAPI}`. The summary is the first line of the given text, trimmed; an empty one becomes `catalog: update <path>`; it is then cut to 72 characters, the library's limit. With the shared token the committer is `catalyst-shared@robots.<SOVEREIGN_FQDN>`; this is the identity behind the token, as before.
4. **Authors are unchanged.** Publish, curate and edit-pr pass no author (the robot is the author, as the token's user was before). The card edit, the full IaC edit and the Flux aggregator pass `catalogEditCommitAuthor()`, which now returns a `gitwrite.Identity` with the same values as before: `CATALYST_GITOPS_COMMITTER_NAME` (default `catalyst-api`) and `CATALYST_GITOPS_COMMITTER_EMAIL` (default `ops@openova.io`). The commit summaries are the messages of before.
5. **The six writes that move.** Publish: `<org>/shared-blueprints` branch `main`, path `<bp-name>/blueprint.yaml`. Curate: `catalog-sovereign/<bp-name>` branch `main`, path `blueprint.yaml`. Edit-pr: `<org>/shared-blueprints` branch `main` (no branch `edit/<hash>` any more), the requested path. Card edit (`writeCatalogEditToGit`): `catalog-sovereign/<bp-name>` branch `main`, path `blueprint.yaml`. Full IaC edit (`writeCatalogFullBlueprintToGit`): `catalog-sovereign/<resolved repo>` branch `main`, path `blueprint.yaml`. Flux aggregator (`writeCatalogSovereignAggregatorBytes`): `openova/openova` branch `catalog-sovereign`, path `clusters/<SOVEREIGN_FQDN>/catalog-sovereign/<bp-name>.yaml`. `EnsureOrg`, `EnsureRepo`, `GetFile`, `ListOrgRepos` and `ListContents` stay on the Gitea client: the library writes files, it does not create repositories.
6. **Edit-pr commits to `main`.** It makes one commit with the summary `message`, else `title`, else `Edit <path> via Catalyst`. The response keeps its fields: `prURL` and `pr.url` are `/<org>/shared-blueprints/commit/<commit SHA>`, `prNumber` and `pr.number` are `0`, `branch` is `main`, `repo` and `path` as before, `message` is `committed <commit SHA> to main`. A commit that `gitwrite` refuses with `ErrNotFound` (the repository does not exist) answers 404 as before; any other failure answers 502 `gitea-upstream` as before. The functions `editPRBranchName` and `fnv1a64`, used only by edit-pr, are deleted with their test.
7. **No silent skip.** `errCatalogGitUnavailable` wraps `gitwrite.ErrUnavailable`. Without a commit library: the four write routes answer 503 `{"error":"git-unavailable","detail":"<the error text>"}` (helper `writeGitUnavailable`) at the place where they answered `gitea-not-wired` before: publish, curate and edit-pr before they read the request body, the full IaC edit after it has validated the body; `writeCatalogEditToGit`, `writeCatalogFullBlueprintToGit` and `writeCatalogSovereignAggregatorBytes` return `errCatalogGitUnavailable`. The card-edit route in `org_commerce.go` (not changed) already reports such an error as `committed:false` with a reason. One no-op stays: the Flux aggregator does nothing when `SOVEREIGN_FQDN` is empty (a parent installation without a local catalogue reconcile); that is not the missing-Gitea skip.
8. **Read routes do not change.** `GET /api/v1/catalog/{name}/iac` still answers 503 `gitea-unwired` without a client, and `GET …/blueprints/curatable` still answers an empty list.
9. **Tests.** The test double `fakeGiteaClient` (`blueprints_test.go`) gains `Commit`, `Read` and `List`, so it is also a `gitwrite.Writer`: `Commit` records the `Change` in `changes` and writes each file as `PutFile` does, with the same injected delay and errors, or returns `commitErr` when that is set. The new file `catalog_gitwrite_test.go` runs `commitCatalogFile` against the real library (`gitwrite/fake`), checks the `Change` of publish, checks the 503 answers and errors with a client that has no library, and checks `NewGiteaClientFromEnv`. Changed tests: the edit-pr test now expects a commit on `main` and no pull request; the 404 test injects `gitwrite.ErrNotFound`; the "unwired is a no-op" test of the card edit now expects `gitwrite.ErrUnavailable`; the aggregator guard test expects that error for an unwired client with `SOVEREIGN_FQDN` set; three 503 tests also check the error code.
