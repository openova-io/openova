# NET-070 — Wizard shows what the provisioner builds

## In plain words

**The problem today.** The first steps of the Sovereign wizard offer five topology cards. Four of them promise things the provisioner does not build: separate clusters per network zone, virtual clusters per zone, and a four-region layout with separate management regions. The provisioner builds one cluster per region, and the only effect of the choice is the number of regions.

**What changes.** The step offers two choices, one region or two or more, and says what each region really is. The retired template names leave the console code, and a browser that stored one of them gets the two-region choice.

**Done means:**

- The topology step of the wizard shows exactly two choices, "One region" and "Two or more regions".
- Each choice carries the sentence "One cluster per region. The edge, the platform and Organizations are separated by network policy."
- A new wizard starts with the two-region choice selected, and the provider step shows two region cards named Region 1 and Region 2.
- No console code outside tests names the retired templates or promises separate clusters or virtual clusters per zone.
- The provisioning request the wizard sends is the same as before for one region and for two regions.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The topology step of the sovereign-admin wizard (`products/catalyst/bootstrap/ui/src/pages/wizard/steps/StepTopology.tsx`) shows two choices: "One region" and "Two or more regions". Each carries the sentence "One cluster per region. The edge, the platform and Organizations are separated by network policy." This is what ADR-0019 decides: a Sovereign region is one cluster, and a virtual cluster exists only per Organization. The five cards with zone diagrams (CITADEL, DUAL, ZONED, COMPACT, SOLO) are gone. The choice is still stored as a `TopologyTemplate` id, now `'solo'` or `'dual'`, and its only effect is the number of regions. The four retired names `citadel`, `triangle`, `zoned` and `compact` leave `model.ts` and `store.ts`. A browser that stored one of them gets `'dual'`. A new unit test, `StepTopology.test.tsx`, proves the two choices, their text, the default and the stored-value rule.

## 3. The model (the law)
1. The topology step renders exactly two choices, in this order: "One region" (id `solo`, 1 region) and "Two or more regions" (id `dual`, 2 regions). Each is a radio button and carries the sentence "One cluster per region. The edge, the platform and Organizations are separated by network policy."
2. The step names no zone (DMZ, RTZ, MGMT), no virtual cluster and no retired template. The AIR-GAP add-on stays, with its toggle and its numbers "+1 reg" and "+1 cls"; its number "+1 vC" is removed, because a virtual cluster is created only per Organization (ADR-0019, decision 4).
3. `TopologyTemplate` is `'dual' | 'solo'`. `TOPOLOGY_REGION_COUNT` is `{ dual: 2, solo: 1 }`. `TOPOLOGY_REGION_LABELS` is `{ dual: ['Region 1', 'Region 2'], solo: ['Region 1'] }`. These two records are the only effect of the choice: `StepProvider.tsx` and `StepReview.tsx` read them and do not change.
4. A new wizard starts with `topology: 'dual'`. Before the change it started with `'zoned'`, which also meant two regions.
5. When the wizard store loads a stored state whose `topology` is not `'dual'` or `'solo'`, it sets `topology` to `'dual'` and clears the per-region choices, as it cleared them before. Before the change it set `topology` to `null`; a returning browser that held the old default `'zoned'` would then have built one region.
6. The provisioning request does not change: it carries the regions and, for one region, `bcpTopology: 'single-region'`, and never a template name. The test `StepReview.bcp-topology-wire.5661.test.tsx` keeps its cases for `solo` and `dual`; its cases for the three retired names are deleted.
7. Deleted: the five card definitions, the five zone diagrams and their colour palette, the detail panel of `StepTopology.tsx`; the names `citadel`, `triangle`, `zoned` and `compact` from the type, from both records, from the store's list of valid values and from the 5661 test. No file is deleted, so `docs/ledger/deleted-paths.txt` does not change.
