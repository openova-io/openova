# FND-061 — One signing action, used by the control-plane images first

## In plain words

**The problem today.** The two control-plane images, the console and the API, are pushed and rolled out with no signature and no bill of materials. Nobody can check that an image a Sovereign runs was built by the platform's own pipeline. The builds that do sign today each carry their own copy of the signing steps, and most of them attest a placeholder instead of a real bill of materials.

**What changes.** One shared action signs a pushed image, attests a real bill of materials of it and verifies both. The console and API builds call it right after each push, so an image that cannot be signed is never rolled out.

**Done means:**

- The repository has one shared signing action. It signs an image, attests an SPDX bill of materials of it, verifies both, and fails when any of them fails.
- The console and API image builds call that action right after each push, before the deploy job pins the new image tag.
- The console and API images are pushed with the same tags as before.
- After the merge, the first run of the console and API build on the main branch shows both signing steps green.
- Signing with the platform's own release key is not part of this task. It needs a person to create the key, and a later task switches the action to it.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The repository has one composite action, `.github/actions/sign-and-attest`, that every image build can call with an image name and a digest. It signs the image, writes an SPDX bill of materials of it with Syft, attests that bill of materials, and verifies the signature and the attestation; it fails when any of these fails. The workflow `Build & Deploy Catalyst` (`.github/workflows/catalyst-build.yaml`) calls it right after it pushes the console image (`catalyst-ui`) and the API image (`catalyst-api`). Its deploy job waits for both build jobs, so an image that could not be signed is never pinned and never rolled out. Today the action signs keyless, with a short-lived certificate for the workflow. Switching it to the platform's release key is a later package.

## 3. The model (the law)
1. One new file: `.github/actions/sign-and-attest/action.yaml`. It is the block `action.yaml` of this ticket, byte for byte (step 3 checks its SHA-256).
2. The action is a composite action with exactly two inputs, both required: `ref` (the image name without tag and digest) and `digest` (`sha256:` and 64 hex characters).
3. The action installs cosign v2.4.1 with `sigstore/cosign-installer@v3` and Syft v1.43.0 with `anchore/sbom-action/download-syft@v0`. cosign v2.4.1 is the version `.github/workflows/blueprint-release.yaml` installs; Syft v1.43.0 is the version `platform/syft-grype/chart/values.yaml` runs. The action refuses to go on when the installed Syft is not 1.43.0.
4. In this order the action runs: `cosign sign`, Syft (SPDX JSON of the image read from the registry), `cosign attest --type spdxjson`, `cosign verify`, `cosign verify-attestation --type spdxjson`. Each command that fails fails the action. The two verify commands accept only a certificate issued by GitHub Actions (`https://token.actions.githubusercontent.com`) to a workflow of this repository.
5. Signing is keyless: cosign takes a short-lived certificate from the GitHub OIDC token, and the signature is written to the public transparency log. That is why each calling job has the permission `id-token: write`.
6. In `.github/workflows/catalyst-build.yaml`, the jobs `build-ui` and `build-api` each get the permission `id-token: write`. Their push steps (`Push UI image`, `Push API image`) each get `id: push`. Right after each push step there is one new step that calls the action with the image name of that job (`${{ env.UI_IMAGE }}` or `${{ env.API_IMAGE }}`) and `${{ steps.push.outputs.digest }}`.
7. Nothing else in `catalyst-build.yaml` changes: no line is removed, the tags of both push steps stay the same, the triggers stay the same, and the deploy job still `needs: [build-ui, build-api]`.
8. No key is created, no secret is read or written, and no file under `keys/` is added. The action reads no secret.

```yaml
# Composite action: sign-and-attest
#
# Signs one image that a build has just pushed, attests an SPDX bill of
# materials of that image, and verifies the signature and the attestation.
# The action fails when any of these fails. Image builds call this one
# action, so the signing rule lives in one place: FND-061 brings it to the
# two control-plane images (catalyst-ui and catalyst-api); FND-062 brings it
# to the other builds.
#
# Where to call it: right after the step that pushes the image, in the same
# job, and before any job that pins the image's tag. An image that cannot be
# signed, attested and verified stops its build there and is never rolled
# out.
#
# How it signs today: keyless. cosign takes a short-lived certificate for the
# calling workflow from the GitHub OIDC token, so the calling job needs the
# permission `id-token: write`, and the signature is recorded in the public
# transparency log. The verify commands accept a certificate whose subject is
# a workflow of this repository and whose issuer is GitHub Actions.
#
# How it will sign: with the release key. That change is a later package. It
# stores the private half of the release key pair as a repository secret
# usable only on main, adds the public half as keys/release-cosign.pub, and
# changes the commands of the step "Sign, attest and verify" to sign with the
# key and to verify against that file, without the transparency log. The
# inputs of this action stay as they are, so no caller changes then.
#
# Inputs:
#   ref     the image name without tag and without digest, for example
#           ghcr.io/openova-io/openova/catalyst-api
#   digest  the digest of the pushed image, sha256:<64 hex>. With
#           docker/build-push-action it is steps.<id of the push step>.outputs.digest
#
# Versions: cosign v2.4.1, the version .github/workflows/blueprint-release.yaml
# installs; Syft v1.43.0, the version platform/syft-grype/chart/values.yaml runs.
# The registry login of the calling job is used for the push of the signature
# and the attestation and for the read of the image by Syft.

name: sign-and-attest
description: |
  Sign an image that was just pushed, attest an SPDX bill of materials of
  it, and verify the signature and the attestation.

inputs:
  ref:
    description: |
      The image name without tag and without digest.
    required: true
  digest:
    description: |
      The digest of the pushed image, sha256:<64 hex>.
    required: true

runs:
  using: composite
  steps:
    - name: Check the inputs
      shell: bash
      env:
        REF: ${{ inputs.ref }}
        DIGEST: ${{ inputs.digest }}
      run: |
        set -euo pipefail
        if [ -z "$REF" ] || [[ "$REF" == *@* ]] || [[ "$REF" =~ [[:space:]] ]]; then
          echo "::error::sign-and-attest: the input ref must be an image name without a digest; it is '$REF'"
          exit 1
        fi
        if [[ ! "$DIGEST" =~ ^sha256:[0-9a-f]{64}$ ]]; then
          echo "::error::sign-and-attest: the input digest must be sha256:<64 hex>; it is '$DIGEST'. Give the push step an id and pass steps.<id>.outputs.digest."
          exit 1
        fi
        echo "sign-and-attest: ${REF}@${DIGEST}"

    - name: Install cosign
      uses: sigstore/cosign-installer@v3
      with:
        cosign-release: v2.4.1

    - name: Install Syft
      id: syft
      uses: anchore/sbom-action/download-syft@v0
      with:
        syft-version: v1.43.0

    - name: Sign, attest and verify
      shell: bash
      env:
        REF: ${{ inputs.ref }}
        DIGEST: ${{ inputs.digest }}
        SYFT: ${{ steps.syft.outputs.cmd }}
        ISSUER: https://token.actions.githubusercontent.com
      run: |
        set -euo pipefail
        image="${REF}@${DIGEST}"
        identity="^https://github\.com/${GITHUB_REPOSITORY}/\.github/workflows/"
        sbom="${RUNNER_TEMP}/sbom-${DIGEST#sha256:}.spdx.json"

        if [ -z "$SYFT" ]; then
          echo "::error::sign-and-attest: the step Install Syft gave no command"
          exit 1
        fi
        syft_version="$("$SYFT" version)"
        case "$syft_version" in
          *1.43.0*) ;;
          *)
            echo "::error::sign-and-attest: Syft is not version 1.43.0"
            echo "$syft_version"
            exit 1
            ;;
        esac

        echo "sign-and-attest: signing ${image}"
        cosign sign --yes "$image"

        echo "sign-and-attest: writing the SPDX bill of materials of ${image}"
        "$SYFT" "registry:${image}" -o "spdx-json=${sbom}"
        if [ ! -s "$sbom" ]; then
          echo "::error::sign-and-attest: Syft wrote no bill of materials"
          exit 1
        fi

        echo "sign-and-attest: attesting the bill of materials"
        cosign attest --yes --type spdxjson --predicate "$sbom" "$image"

        echo "sign-and-attest: verifying the signature"
        cosign verify --certificate-identity-regexp "$identity" --certificate-oidc-issuer "$ISSUER" "$image" > /dev/null

        echo "sign-and-attest: verifying the attestation"
        cosign verify-attestation --type spdxjson --certificate-identity-regexp "$identity" --certificate-oidc-issuer "$ISSUER" "$image" > /dev/null

        echo "sign-and-attest: ${image} is signed, attested and verified"
```
