# NET-135 — The plane-isolation policies admit the cross-region file sync and the snapshot job, and no longer depend on which namespaces exist at render time

## In plain words

**The problem today.** The network isolation chart writes its policies only for the namespaces that exist when it renders, and it renders again only when its chart or its settings change. A namespace made later stays without a policy for months and then gets one, untested, at an unrelated upgrade. When that happened, the new policy of the object store cut the file sync between the two regions and refused callers of its storage interface that are not on its list.

**What changes.** The chart renders the policies of every listed namespace every time, and a missing namespace makes the install fail with its name instead of being skipped. The policy of the object store admits the file sync of the other region and every namespace on the port of its storage interface.

**Done means:**

- What the chart renders does not depend on which namespaces exist when it renders.
- A listed namespace that does not exist makes the install fail and names that namespace; it is never skipped in silence.
- The object store namespace admits the file sync of the other region in both directions, on its two filer ports only.
- Every namespace of a cluster may reach the port of the storage interface of the object store, and no other port of any namespace is open to every namespace.
- A chart test fails on the chart as it was, passes after the change, and proves that each of its rules can fail.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The chart `platform/plane-isolation/chart` renders one fixed set of policies, computed from its values alone: for every entry of `components` its default-deny NetworkPolicy and its CiliumNetworkPolicies, whether or not the namespace exists at that moment. A namespace that is listed and does not exist makes the install fail, and the error names the namespace. In the `seaweedfs` namespace two callers are admitted that the policy refused: the file sync of the peer region, on the filer ports 8888 and 18888, in both directions; and every namespace of the cluster on the S3 port 8333. A person can see it with `helm template plane-isolation platform/plane-isolation/chart --api-versions cilium.io/v2`: it prints 64 policies, and the two `seaweedfs` policies carry the new rules. The new chart test `platform/plane-isolation/chart/tests/render-contract.sh` checks all of this on every pull request that changes the chart.

## 3. The model (the law)
1. No file under `platform/plane-isolation/chart/templates/` calls the Helm function `lookup`. The values `renderUnconditional` and `ensureNamespacePresent` no longer exist in the chart: the patch deletes the value and every template line that reads either of them.
2. For every entry of `components`, a plain `helm template` with `--api-versions cilium.io/v2` renders: the NetworkPolicy `<ns>-default-deny`; the CiliumNetworkPolicies `<ns>-allow-apiserver-egress` and `<ns>-allow-crossregion-db-egress`; `<ns>-allow-gateway-ingress` when `gatewayIngress` is true; `<ns>-allow-apiserver-webhook-ingress` when `apiserverWebhookPorts` is set. Nothing else. With the values of this ticket that is 18 NetworkPolicies and 46 CiliumNetworkPolicies.
3. A component entry may carry two new fields. `allowIngressFromAnyNamespaceOnPorts` (a list of TCP ports) adds to its default-deny one ingress rule `from: [namespaceSelector: {}]` on those ports. `crossRegionPeerPorts` (a list of TCP ports) adds to its `<ns>-allow-crossregion-db-egress` one egress rule `toEndpoints` and one ingress rule `fromEndpoints`, each with the selector "key `io.cilium.k8s.policy.cluster` operator `Exists`, key `k8s:io.kubernetes.pod.namespace` operator `In` values `[<ns>]`" on those ports. A component without the fields renders exactly as before.
4. Only the `seaweedfs` entry sets the fields: `allowIngressFromAnyNamespaceOnPorts: [8333]` and `crossRegionPeerPorts: [8888, 18888]`. No other entry changes. No `allowIngressFrom` list changes.
5. The object `seaweedfs-allow-crossregion-db-egress` keeps its name, so that no live policy is replaced. No template file is added: the network guard G2 counts one policy kind line per template file, and its baseline may not grow.
6. Nothing outside the seven files of field 14 changes: no `Chart.yaml`, no `blueprint.yaml`, no kit slot, no other chart.
