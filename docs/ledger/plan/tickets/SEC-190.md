# SEC-190 — Mounts, templated policies and generic roles

## In plain words

**The problem today.** OpenBao has one shared key-value store that its readers reach by broad grants, no store for values a pod reads as a mounted file, and no key to encrypt the infrastructure state. Every member of the administrators group is a superuser of OpenBao.

**What changes.** OpenBao gets a store for mounted values that each pod and each namespace reaches only for itself, and a key for the infrastructure state, with a short-lived token for the provider and one offline backup. The administrators get a read-mostly policy instead of full control.

**Done means:**

- A pod's own identity reads the values of its own service account and of its own namespace in the new store, and nothing of another namespace or service account.
- A namespace's External Secrets identity creates a value there once and can neither rewrite nor read it.
- A token minted for the infrastructure state encrypts with the state key and reaches nothing in the key-value store and not the key's backup.
- The administrators take the one wrapped backup of the state key with the two commands of the runbook, and read no secret value.
- The configuration reconciler cannot use the state key, back it up or mint a token, and every earlier policy and role is unchanged.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The desired state of the bp-openbao configuration reconciler (ConfigMap `openbao-config-desired`, `platform/openbao/chart/templates/_config.tpl`) enables the secrets mounts `mounted/` (kv version 2) and `transit/` from the new value `engines`, writes six new policies, binds four generic auth roles on mount `kubernetes/` (a fifth when the new value `stateKey.backupIdentities` is set), creates the state key `transit/keys/tofu-state` and writes the token role `auth/token/roles/tofu-state`. One policy serves every namespace: the policies `workload` and `eso-ns` name the caller's namespace and service account by the identity template of its Kubernetes auth alias, which the reconciler completes with the accessor of its login mount. The sign-on reconciler (`templates/sso-configure-deployment.yaml`) no longer writes the superuser policy: `sso-operator-admin` carries the read-mostly text of `sovereign-admin`, and the realm groups map to `sovereign-admin` (the admin group also to `tofu-state-backup`). `docs/RUNBOOKS.md` section 2.17 "Offline backup of the state key" gives the two commands of the one offline backup. A new chart test (`platform/openbao/chart/tests/policy-templates-render.sh`) pins the rendered state, and the live test `tests/e2e/bp-openbao-config-live.sh` proves every grant and refusal against a real OpenBao 2.7.2 (case L8).

## 3. The model (the law)
1. **Mounts.** New value `engines` (`platform/openbao/chart/values.yaml`): each key is a mount path, each value the payload of `sys/mounts/<key>`. Defaults: `mounted: {type: kv, options: {version: "2"}}` and `transit: {type: transit}`. The desired state has one `secrets-mount sys/mounts/<key>` op per key, in key order, right after the op of the kv mount `secret/` and before the first policy.
2. **The reconciler's own grant** (`openbao.configAdminPolicy`, also the policy of the self-initialisation) gains exactly: `sys/mounts/<key>` create and update for each key of `engines`; `transit/keys/*` create, update and read; `transit/keys/+/config` create and update; `auth/token/roles/*` create, update and read. It gains nothing else: it cannot use a key (`transit/datakey`, `transit/decrypt`), back one up (`transit/backup`) or create a token (`auth/token/create`).
3. **Identity templates.** `NS` is `{{identity.entity.aliases.AUTH_ACCESSOR_KUBERNETES.metadata.service_account_namespace}}` and `SA` is `{{identity.entity.aliases.AUTH_ACCESSOR_KUBERNETES.metadata.service_account_name}}`, written in the template as Helm string literals so that Helm does not read them. The reconciler (`files/openbao-config-reconcile.sh`, unchanged) puts the accessor of its login mount in place of `AUTH_ACCESSOR_KUBERNETES`.
4. **Policies** (each written as one `write sys/policies/acl/<name>` op, after the existing ones; the exact text is pinned by case T2 of the new chart test):
   - `workload`: read on `mounted/data/NS/sa/SA/*` and `mounted/data/NS/shared/*`.
   - `eso-ns`: create (only) on `mounted/data/NS/*`; read and delete on `mounted/metadata/NS/*`; create, update and read on `secret/data/openova/apps/NS/*`; read, list and delete on `secret/metadata/openova/apps/NS/*` (`secret` is `kubernetesAuth.kvMountPath`, `openova/apps` is `peerTrust.kvPathPrefix`). It never reads a value below `mounted/`.
   - `tofu-state`: update on `transit/datakey/plaintext/<key>` and `transit/decrypt/<key>`.
   - `tofu-state-backup`: read on `transit/backup/<key>`.
   - `tofu-state-mint`: update on `auth/token/create/tofu-state`.
   - `sovereign-admin`: read and list on `secret/metadata/*`, `mounted/metadata/*` and `sys/policies/acl/*`; read on `sys/mounts` and `sys/auth`; read, list and sudo on `sys/leases/lookup/*`; update on `sys/leases/revoke/*`.
   `<key>` is `stateKey.name` (default `tofu-state`). No new policy has `sudo` except `sovereign-admin` on lease lookup, which lists leases and reads no value.
5. **Auth roles** on `auth/<kubernetesAuth.mountPath>/role/<name>`, after every policy, each with `ttl` 15m:
   - `workload`: every service account (`*`) of every namespace (`*`), audience `openbao`, policy `workload`, max 1h.
   - `eso-ns`: `eso-reader` of every namespace, policy `eso-ns`, max 1h.
   - `tofu-state-mint`: `eso-reader` of `crossplane-system`, policies `eso-ns` and `tofu-state-mint`, max 1h.
   - `tofu-state`: the service accounts and namespaces of `stateKey.jobIdentities` (default `sovereign-ops` in `catalyst`), audience `openbao`, policy `tofu-state`, max 1h. Kubernetes auth binds every listed name in every listed namespace.
   - `tofu-state-backup`: the same from `stateKey.backupIdentities` (default empty: no role), audience `openbao`, policy `tofu-state-backup`, max 15m.
   Every earlier role payload is unchanged (no `audience` key).
6. **State key.** When `engines` has `transit`: `write transit/keys/<key>` with `{"type":"aes256-gcm96","exportable":true,"allow_plaintext_backup":true}` and then `write transit/keys/<key>/config` with `{"deletion_allowed":false,"exportable":true,"allow_plaintext_backup":true}`, after the last policy and before the first role. Both flags are one-way in OpenBao. Without `transit` in `engines` neither op renders and the own grant has no `sys/mounts/transit`.
7. **Token role.** `write auth/token/roles/tofu-state` with `{"allowed_policies":["tofu-state"],"orphan":true,"renewable":false,"token_explicit_max_ttl":"1h"}`, after every auth role and before the peer-trust ops.
8. **Administrators.** The sign-on reconciler writes the `sovereign-admin` text (the same template definition) as `sys/policies/acl/sso-operator-admin`, so that a token that still names that policy is no longer a superuser; it maps the external group `sso.adminGroup` to policies `sovereign-admin` and `tofu-state-backup` and `sso.opsGroup` to `sovereign-admin`. The policy write still gates the tick, and the policy still comes before the role (the existing test `sso-policy-write-gates-tick-5829.sh`). Break-glass is cluster administration, never an OIDC login.
9. **Runbook.** `docs/RUNBOOKS.md` section `### 2.17 Offline backup of the state key`, after section 2.16: the wrapped read `bao read -wrap-ttl=1h -field=wrapping_token transit/backup/tofu-state > tofu-state.wrap` on the Sovereign, and `BAO_TOKEN="$(cat tofu-state.wrap)" bao unwrap -field=backup > tofu-state.backup` on the custody machine.
10. **Tests that read the changed files follow.** `config-desired-render.sh` C3 admits exactly the new grants of law 2; `config-reconcile-idempotence.sh` expects the three secrets mounts once each and compares the substituted payloads; the live test compares policies after substitution and also the `audience` of a role. Every edit to an embedded Python program of these three files changes a line in place: none adds a line of Python.
11. No chart version changes; the release writer bumps it after the merge.
