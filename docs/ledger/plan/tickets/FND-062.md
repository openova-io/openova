# FND-062 — Every image and chart build signs through the action

## In plain words

**The problem today.** Only the console and API images are signed through the shared signing action. Of the other image builds, sixteen sign with their own copy of the signing steps, twelve of them attest a placeholder text instead of a real bill of materials, and fifteen do not sign at all. The chart release signs with a copy of its own. Nothing stops a new build from pushing an unsigned image.

**What changes.** Every build that pushes an image, and the chart release, calls the shared action right after the push, so each image and each chart is signed and carries a real bill of materials. A guard on every pull request fails a workflow that pushes without the action or signs by itself.

**Done means:**

- Every workflow that builds and pushes an image calls the shared signing action right after the push, before any step pins the new tag.
- The chart release signs every chart through the same action, with a bill of materials written from the packaged chart.
- No workflow attests the placeholder text any more, and none runs the signing commands itself.
- A guard runs on every pull request and turns it red when a workflow pushes an image or a chart without the shared action.
- The stored count of action references that are not pinned by a commit is lowered to the new, smaller count.
- After the merge, the first run on the main branch of each changed build shows its signing step green.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Every workflow of the repository that builds an image and pushes it, and the chart release `.github/workflows/blueprint-release.yaml`, calls the shared composite action `.github/actions/sign-and-attest` right after the push. The action signs the pushed image or chart, attests an SPDX bill of materials of it and verifies both. No workflow keeps its own copy of the signing commands, and no workflow attests the placeholder text `in-toto-spdx attached at build time`. A new guard, `scripts/check-builds-sign.py`, runs on every pull request in the workflow `check-pins` and fails a workflow that pushes an image or a chart without the action. The stored count of action references that are not pinned by a commit, `docs/ledger/pin-baseline.json`, falls to the new count, because the old signing steps each installed cosign with an unpinned action.

## 3. The model (the law)
1. A **push step** is a step of a job that is one of these: a step that uses `docker/build-push-action` and whose input `push` is not `false` (an absent input is `false`, the default of that action); a run step that runs `helm push`; a run step that runs `docker push`, in a job that also has a step that uses `docker/build-push-action`. A job that only copies an image built elsewhere with `docker push` is not judged.
2. Every push step has an `id`, and a later step of the same job uses `./.github/actions/sign-and-attest` with the input `digest` read from `steps.<that id>.outputs`.
3. That signing step runs exactly when the push runs: its `if` is the `if` of the push step. When the push step has no `if` and its input `push` is an expression `${{ X }}`, the `if` of the signing step is `X`. Otherwise the signing step has no `if`.
4. No step that uses `./.github/actions/deploy-bump` stands between a push step and its signing step. A signing step has no `continue-on-error`.
5. A job with a signing step has `id-token: write`: in its own `permissions`, or, when the job has no `permissions`, in those of the workflow. The action signs keyless and needs the GitHub OIDC token.
6. No workflow and no composite action other than `.github/actions/sign-and-attest/action.yaml` runs `cosign sign` or `cosign attest` itself. Comment lines do not count.
7. Rules 1 to 6 are the guard `scripts/check-builds-sign.py`. It has a `--self-test` that builds its own trees and shows that every rule can fail. The allowed number of failures is 0; there is no baseline file. The guard runs as the job `check-builds-sign` of `.github/workflows/check-pins.yaml`, which runs on every pull request and merge group.
8. The action gains one optional input, `sbom-source`, with the default empty. Empty means what it means today: Syft reads the pushed image from the registry. A Helm chart is not an image and Syft cannot read it from the registry, so the chart release passes `file:` and the path of the packaged chart it pushed. The inputs `ref` and `digest` do not change. Every other caller passes no `sbom-source`.
9. The four builds that load an image, test it and then push it with `docker push` (`agenity-build.yaml`, `build-chargeback.yaml`, `build-docrender.yaml`, `build-openova-mcp.yaml`) give their push step `id: push`. After the pushes, that step asks the registry for the digest of the pushed tag and writes it as the step output `digest`.
10. Deleted: the 16 steps `Install cosign` of the image builds; every run step of a workflow that runs `cosign sign` or `cosign attest`, 27 of them in 16 image builds and 2 in the chart release; the steps `Install Cosign` and `Install Syft` of the chart release. The 12 placeholder attestations go with them.
11. Nothing else changes. Every image is pushed with the same tags, contexts, files, platforms and build arguments as before. No trigger, no deploy job, no bump step and no release-writer step changes.
12. `docs/ledger/pin-baseline.json` is written by its own tool, `python3 scripts/check-pins.py --write-baseline`, never by hand. The tool refuses to raise a number.

The rule of signing lives in one place: the composite action .github/actions/sign-and-attest.
It signs an image or chart that a step has just pushed, attests a bill of materials of it, and
verifies both. This guard reads every workflow and fails when a push can bypass that action.

A push step is a step of a job that is one of these:
  - a step that uses docker/build-push-action and whose input `push` is not false (an absent
    input is false, the default of that action);
  - a run step that runs `helm push`;

                out.append(f"{where}: the signing step has continue-on-error (rule 4)")
            if not has_id_token(permissions):
                out.append(f"{where}: the job cannot ask for an OIDC token; give it id-token: write (rule 5)")
        for index, step in enumerate(steps):
            if not pushes(step, builds):
                continue
            found += 1
            where = f"{path}: job {job_name}, {step_label(index, step)}"
            step_id = step.get("id")
            if not step_id:
                out.append(f"{where}: the push step has no id, so no signing step can read its digest (rule 1)")
                continue
            signer = None
            for later in range(index + 1, len(steps)):
                other = steps[later]
                if action_of(other) != SIGN_ACTION:
                    continue
                digest = str((other.get("with") or {}).get("digest") or "")
                if step_id in DIGEST_RE.findall(digest):
                    signer = later
                    break
            if signer is None:
                out.append(f"{where}: no later step uses {SIGN_ACTION} with digest from steps.{step_id}.outputs (rule 1)")
                continue
            want, have = expected_if(step), normal(steps[signer].get("if"))
            if want != have:
                out.append(f"{where}: its signing step runs on if '{have}', the push on '{want}' (rule 2)")
            for between in range(index + 1, signer):
                if action_of(steps[between]) == DEPLOY_BUMP:
                    out.append(f"{where}: {step_label(between, steps[between])} pins the tag before the signing step (rule 3)")
    return found


def all_steps(data):
    """Every step of a workflow or of a composite action."""
    if not isinstance(data, dict):
        return
    for job in (data.get("jobs") or {}).values():
        if isinstance(job, dict):
            for step in job.get("steps") or []:
                if isinstance(step, dict):
                    yield step
    composite = data.get("runs")
    if isinstance(composite, dict):
        for step in composite.get("steps") or []:
            if isinstance(step, dict):
                yield step


def judge(root):
    """(failures, push steps, workflows read) for the tree at root."""
    failures, found = [], 0
    workflows = sorted(glob.glob(os.path.join(root, ".github/workflows/*.yml")) + glob.glob(os.path.join(root, ".github/workflows/*.yaml")))
    actions = sorted(glob.glob(os.path.join(root, ".github/actions/**/action.yml"), recursive=True) + glob.glob(os.path.join(root, ".github/actions/**/action.yaml"), recursive=True))
    for full in workflows:
        rel = os.path.relpath(full, root)
        data = load_yaml(full)
        found += judge_workflow(rel, data, failures)
    for full in workflows + actions:
        rel = os.path.relpath(full, root).replace(os.sep, "/")
        if rel in SIGN_ACTION_FILES:
            continue
        data = load_yaml(full)
        for step in all_steps(data):
            if runs(step, COSIGN_RE):
                failures.append(f'{rel}: step "{step.get("name") or "run"}" runs cosign itself; call {SIGN_ACTION} instead (rule 6)')
    return failures, found, len(workflows)


def report(root):
    try:
        failures, found, count = judge(root)
    except ReadError as exc:
        print(f"check-builds-sign: ERROR {exc}")
        return 2
    for failure in failures:
        print(f"check-builds-sign: FAIL {failure}")
    if failures:
        print(f"check-builds-sign: {len(failures)} failures; allowed: 0")
        return 1
    print(f"check-builds-sign: ok, {found} push steps in {count} workflows are signed through {SIGN_ACTION}")
    return 0
