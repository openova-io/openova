# CMP-014 — Run the policy chart's tests on every pull request

## In plain words

**The problem today.** The security policies have four test suites, and no CI run executes them. A policy can be broken without anyone noticing until it is live.

**What changes.** A new check runs every test of the policy chart on each pull request that changes the policies, with the same tool version a Sovereign runs.

**Done means:**

- A pull request that changes a policy gets the check policy-chart-tests.
- A failing policy test turns the pull request red.
- The check uses the same policy engine version as a running Sovereign.
- The check proves on itself that it can fail.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A pull request that changes the policy chart, the policy engine chart, the test runner or the workflow gets a check named `policy-chart-tests`. The check renders the policy chart, runs its four policy suites and its two shell tests, and is red when any of them fails. It uses the Kyverno command-line tool at the same version as the engine that a Sovereign runs. The same check runs on a merge group that changes one of those files.

What is new to CI: the four policy suites. Today no workflow runs them.

What already runs in CI: the two shell tests. `.github/workflows/chart-tests-pr.yaml` runs them on a pull request that changes a file under `platform/kyverno-policies/chart/`, and `.github/workflows/blueprint-release.yaml` runs them after the merge. Both workflows stay as they are. The new check runs the two shell tests as well, so that one check holds every test of the policy chart, and so that they also run when only the engine chart, the runner or the new workflow changes.

## 3. The model (the law)
1. One script, `scripts/run-policy-chart-tests.sh`, is the only place that says which tests of the policy chart the check `policy-chart-tests` runs. The new workflow calls it and lists no test itself.
2. The script installs nothing. It expects `helm` and `kyverno` on the PATH. The workflow provides them.
3. The script runs, in this order: one render of the chart (`helm template`, output discarded); every policy suite in name order; the shell tests in the order of its list `SHELL_TESTS`. It prints one line for each. It stops at the first failure with exit code 1.
4. A policy suite is a directory directly under `platform/kyverno-policies/chart/tests/` that holds a file named `kyverno-test.yaml`. The script finds suites by that rule, so a suite added later needs no change to the script. A directory without that file is not a suite.
5. A chart with no suite is a failure (exit code 1). A run that tests nothing must not be green.
6. The script has a `--self-test`. It runs the script against a fake chart with fake tools and proves six cases, five of which are refusals or failures.
7. The workflow pins the tool with two variables, `KYVERNO_VERSION` and `KYVERNO_SHA256`. `KYVERNO_VERSION` equals the `appVersion` of `platform/kyverno/chart/Chart.yaml`. A step of the workflow fails when the two differ. The downloaded archive is checked against `KYVERNO_SHA256` before it is used.
8. The value of `KYVERNO_SHA256` is given by this ticket. The executor never computes a checksum and never replaces this one.
9. The workflow runs on `pull_request` for four paths and on `merge_group`. The merge-group event has no path filter, so the workflow's step "Decide whether to run" applies the same four paths. When the changed files cannot be listed, the tests run.
10. No policy, suite, fixture or shell test changes. A suite that fails with the pinned tool is reported with a wrong report. It is not repaired here.
11. Nothing is deleted. `.github/workflows/build-docrender.yaml` keeps its own pin of the tool (`v1.13.4`), which serves another chart.
12. `.github/workflows/chart-tests-pr.yaml` and `.github/workflows/blueprint-release.yaml` do not change. They keep running the two shell tests. On a pull request that changes the policy chart the two shell tests therefore run twice, once in each check. That is intended.

```bash
#!/usr/bin/env bash
# run-policy-chart-tests.sh - runs every test of the policy chart (CMP-014).
#
# Order: one chart render, then every policy suite in name order, then the
# shell tests listed in SHELL_TESTS. It stops at the first failure.
#
# A policy suite is a directory under <chart>/tests/ that holds a file named
# kyverno-test.yaml. A directory without that file (fixtures) is not a suite.
#
# This script installs nothing. `helm` and `kyverno` must be on the PATH.
#
# Usage:
#   bash scripts/run-policy-chart-tests.sh              run the tests
#   bash scripts/run-policy-chart-tests.sh --self-test  prove the runner can fail
#
# Exit code: 0 every test passed. 1 a test failed, or no suite was found.
# 2 wrong usage.
#
# POLICY_CHART_DIR  The chart to test. Default: platform/kyverno-policies/chart
#                   of this repository. The self-test points it at a fake chart.
set -euo pipefail
export LC_ALL=C

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
CHART="${POLICY_CHART_DIR:-$ROOT/platform/kyverno-policies/chart}"
TAG="[policy-chart-tests]"

# Shell tests under <chart>/tests/, run in this order. One file name per line.
SHELL_TESTS=(
  nodeport-enforce-5491.sh
  apicall-rbac-correspondence.sh
)

# step <label> <command...>
# Runs the command. Prints one line. On failure prints the command's output
# first and stops the script.
step() {
  local label="$1" rc
  shift
  if "$@" >"$LOG" 2>&1; then
    echo "$TAG PASS $label"
  else
    rc=$?
    cat "$LOG"
    echo "$TAG FAIL $label (exit $rc)"
    exit 1
  fi
}

run_tests() {
  local test_file name suites=0
  LOG="$(mktemp)"
  trap 'rm -f "$LOG"' EXIT

  step "render" helm template "$CHART"

  shopt -s nullglob
  for test_file in "$CHART"/tests/*/kyverno-test.yaml; do
    name="$(basename "$(dirname "$test_file")")"
    step "suite $name" kyverno test "$CHART/tests/$name"
    suites=$((suites + 1))
  done
  shopt -u nullglob

  if [ "$suites" -eq 0 ]; then
    echo "$TAG FAIL no suite found under $CHART/tests"
    exit 1
  fi

  for name in "${SHELL_TESTS[@]}"; do
    step "shell $name" bash "$CHART/tests/$name"
  done

  echo "$TAG ALL PASS: 1 render, $suites suites, ${#SHELL_TESTS[@]} shell tests"
}

# st_case <name> <wanted exit code> <STUB_FAIL value> <wanted calls> [argument]
# Runs this script against the fake chart with the fake tools first on the
# PATH. Compares the exit code and the list of calls the fake tools recorded.
st_case() {
  local name="$1" want_rc="$2" fail="$3" want_calls="$4" rc=0 got_calls
  shift 4
  : >"$ST_TMP/calls"
  PATH="$ST_TMP/bin:$PATH" POLICY_CHART_DIR="$ST_TMP/chart" \
    STUB_CALLS="$ST_TMP/calls" STUB_FAIL="$fail" \
    bash "${BASH_SOURCE[0]}" "$@" >"$ST_TMP/out" 2>&1 || rc=$?
  got_calls="$(paste -s -d '|' "$ST_TMP/calls")"
  if [ "$rc" != "$want_rc" ] || [ "$got_calls" != "$want_calls" ]; then
    echo "self-test FAIL: $name"
    echo "  exit code: got $rc, want $want_rc"
    echo "  calls got:  $got_calls"
    echo "  calls want: $want_calls"
    cat "$ST_TMP/out"
    exit 1
  fi
  echo "self-test ok: $name"
}

self_test() {
  local name suites_calls shell_calls="" first_shell
  ST_TMP="$(mktemp -d)"
  trap 'rm -rf "$ST_TMP"' EXIT

  # A fake chart: two suites, one fixture directory that is not a suite.
  mkdir -p "$ST_TMP/bin" "$ST_TMP/chart/tests/a-suite" \
    "$ST_TMP/chart/tests/b-suite" "$ST_TMP/chart/tests/fixtures"
  : >"$ST_TMP/chart/tests/a-suite/kyverno-test.yaml"
  : >"$ST_TMP/chart/tests/b-suite/kyverno-test.yaml"
  : >"$ST_TMP/chart/tests/fixtures/resource.yaml"

  # Fake tools. Each records its call. Each fails when STUB_FAIL names it.
  # The single quotes are wanted: the fake tools expand the variables.
  # shellcheck disable=SC2016
  printf '%s\n' '#!/usr/bin/env bash' \
    'echo "helm $1" >>"$STUB_CALLS"' \
    'if [ "${STUB_FAIL:-}" = "render" ]; then exit 1; fi' \
    'exit 0' >"$ST_TMP/bin/helm"
  # shellcheck disable=SC2016
  printf '%s\n' '#!/usr/bin/env bash' \
    'echo "kyverno $1 ${2##*/}" >>"$STUB_CALLS"' \
    'if [ "${2##*/}" = "${STUB_FAIL:-}" ]; then exit 1; fi' \
    'exit 0' >"$ST_TMP/bin/kyverno"
  chmod +x "$ST_TMP/bin/helm" "$ST_TMP/bin/kyverno"
  for name in "${SHELL_TESTS[@]}"; do
    # shellcheck disable=SC2016
    printf '%s\n' '#!/usr/bin/env bash' \
      'echo "shell ${0##*/}" >>"$STUB_CALLS"' \
      'if [ "${0##*/}" = "${STUB_FAIL:-}" ]; then exit 1; fi' \
      'exit 0' >"$ST_TMP/chart/tests/$name"
    shell_calls="$shell_calls|shell $name"
  done
  suites_calls="helm template|kyverno test a-suite|kyverno test b-suite"
  first_shell="${SHELL_TESTS[0]}"

  st_case "1 every test passes, in order, and the fixture directory is skipped" \
    0 "" "$suites_calls$shell_calls"
  st_case "2 a failed render stops the run" \
    1 "render" "helm template"
  st_case "3 a failed suite stops the run before the shell tests" \
    1 "b-suite" "$suites_calls"
  st_case "4 a failed shell test stops the run" \
    1 "$first_shell" "$suites_calls|shell $first_shell"
  rm "$ST_TMP/chart/tests/a-suite/kyverno-test.yaml" \
    "$ST_TMP/chart/tests/b-suite/kyverno-test.yaml"
  st_case "5 a chart with no suite fails" \
    1 "" "helm template"
  st_case "6 an unknown argument is refused" \
    2 "" "" --no-such-option

  echo "self-test: 6 cases passed"
}

if [ "$#" -eq 0 ]; then
  run_tests
elif [ "$#" -eq 1 ] && [ "$1" = "--self-test" ]; then
  self_test
else
  echo "usage: bash scripts/run-policy-chart-tests.sh [--self-test]" >&2
  exit 2
fi
```

# Runs every test of the policy chart on a pull request and on a merge group
# (CMP-014): one chart render, the policy suites under
# platform/kyverno-policies/chart/tests/, and the chart's shell tests.
# The runner is scripts/run-policy-chart-tests.sh.
#

# step "Tool version equals the engine chart's appVersion" fails when the two
# differ. An engine upgrade therefore changes KYVERNO_VERSION and
# KYVERNO_SHA256 below in the same pull request.
#
# The merge-group event has no path filter. The step "Decide whether to run"
# applies the same four paths to it.

on:
  pull_request:
    paths:
      - 'platform/kyverno-policies/**'
      - 'platform/kyverno/**'
      - 'scripts/run-policy-chart-tests.sh'
      - '.github/workflows/policy-chart-tests.yaml'
  merge_group:

env:
  # Pinned with the checksum that the release publishes in its checksums.txt.
  # An unverified download into a job that judges admission policies would be
  # a supply-chain hole in the guard.
  KYVERNO_VERSION: v1.18.0
  KYVERNO_SHA256: 3aa7b7aa68732fd6bc5732f1030d0ed12e1b0ffe7dbac5f5aa21fd8695718904

permissions:
  contents: read

jobs:
  policy-chart-tests:
    name: policy-chart-tests
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4

      - name: Decide whether to run
        id: decide
        env:
          EVENT_NAME: ${{ github.event_name }}
          BASE_SHA: ${{ github.event.merge_group.base_sha }}
        run: |
          set -euo pipefail
          if [ "$EVENT_NAME" != "merge_group" ]; then
            echo "run=true" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          paths='^(platform/kyverno-policies/|platform/kyverno/|scripts/run-policy-chart-tests\.sh$|\.github/workflows/policy-chart-tests\.yaml$)'
          if ! git fetch --no-tags --depth=1 origin "$BASE_SHA" || ! changed="$(git diff --name-only "$BASE_SHA" HEAD)"; then
            echo "The changed files of this merge group could not be listed. The tests run."
            echo "run=true" >> "$GITHUB_OUTPUT"
          elif grep -q -E "$paths" <<<"$changed"; then
            echo "run=true" >> "$GITHUB_OUTPUT"
          else
            echo "This merge group changes no file of the policy chart, the engine chart, the runner or this workflow. Nothing to run."
            echo "run=false" >> "$GITHUB_OUTPUT"
          fi

      - name: Tool version equals the engine chart's appVersion
        if: steps.decide.outputs.run == 'true'
        run: |
          set -euo pipefail
          chart_version="$(awk -F'"' '/^appVersion:/ {print $2}' platform/kyverno/chart/Chart.yaml)"
          if [ "$chart_version" != "$KYVERNO_VERSION" ]; then
            echo "::error title=policy-chart-tests::KYVERNO_VERSION is ${KYVERNO_VERSION} but platform/kyverno/chart/Chart.yaml has appVersion ${chart_version:-none}. Set KYVERNO_VERSION and KYVERNO_SHA256 in this workflow to the engine's version."
            exit 1
          fi
          echo "KYVERNO_VERSION ${KYVERNO_VERSION} equals the engine chart's appVersion."

      - name: Set up Helm
        if: steps.decide.outputs.run == 'true'
        uses: azure/setup-helm@v4
        with:
          version: v3.18.4

      - name: Install PyYAML
        if: steps.decide.outputs.run == 'true'
        run: python3 -m pip install --quiet pyyaml

      - name: Install the Kyverno CLI (pinned + checksum-verified)
        if: steps.decide.outputs.run == 'true'
        run: |
          set -euo pipefail
          url="https://github.com/kyverno/kyverno/releases/download/${KYVERNO_VERSION}/kyverno-cli_${KYVERNO_VERSION}_linux_x86_64.tar.gz"
          curl -fsSL -o /tmp/kyverno.tar.gz "$url"
          echo "${KYVERNO_SHA256}  /tmp/kyverno.tar.gz" | sha256sum -c -
          tar -xzf /tmp/kyverno.tar.gz -C /tmp kyverno
          sudo install -m 0755 /tmp/kyverno /usr/local/bin/kyverno
          kyverno version

      - name: Runner self-test
        if: steps.decide.outputs.run == 'true'
        run: bash scripts/run-policy-chart-tests.sh --self-test

      - name: Run the policy chart's tests
        if: steps.decide.outputs.run == 'true'
        run: bash scripts/run-policy-chart-tests.sh
