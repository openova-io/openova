# NET-020 — Disable the k3s kube-proxy

## In plain words

**The problem today.** Cilium is installed to replace kube-proxy, but k3s still starts its own kube-proxy on every node. Two programs then handle every Service on the node. Nothing checks that kube-proxy is gone.

**What changes.** The k3s server starts without kube-proxy, and the render test and the stored render values say so. A new required gate check reads every node of every region and fails when kube-proxy's Service chains are there or Cilium does not report itself as the replacement.

**Done means:**

- The k3s server line of the shared boot template turns kube-proxy off, and no worker line carries that flag.
- The render test of the boot template fails for either cloud branch when the flag is missing.
- The stored render values match the changed template, so the golden render check is green.
- Gate check NET-G03 is required. It fails a region when a node has no running Cilium agent, when an agent does not report kube-proxy replacement as True, or when the nat table of a node holds a kube-proxy Service chain.
- The tests of the new check run on every pull request without a cluster.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Every control-plane node of a new Sovereign starts k3s with `--disable-kube-proxy` on the server line of the shared boot template `infra/providers/_shared/cloudinit-control-plane.tftpl`. Cilium already runs with `kubeProxyReplacement: true`, so it is then the only Service proxy. The render test of the template fails when the flag is missing, for the hetzner and the huawei fixture, and the stored golden render values match the changed template. The acceptance suite has the gate check NET-G03 "kube-proxy absent", in state `required`: in every region, every node runs a Cilium agent pod in phase Running, `cilium-dbg status` of every agent prints `KubeProxyReplacement:` with the value `True`, and the nat table of every node holds no chain whose name starts with `KUBE-SVC-`.

6. Gate check NET-G03 is one file, `tests/acceptance/sovereign/internal/suite/check_kube_proxy.go`, that calls `RegisterCheck` in `init()`. It records one step per region, `NET-G03.<n>`. A step reads the nodes of the region and the pods of `kube-system` with the label `k8s-app=cilium`. It fails when the region has no node, and when a node has no agent pod in phase `Running`. For each Running agent it runs, with `kubectl exec` in the container `cilium-agent`:
   - `cilium-dbg status`. The value after `KubeProxyReplacement:` must be `True`. The exit code of the command is not judged; a missing line with a failed command fails the step.
   - `sh -c` with a fixed script that lists the nat table with `iptables-legacy`, `iptables-nft` and `iptables` (`-t nat -S`), each that exists and succeeds, and marks each listing with a line `#listed <program>`. At least one program must list the table. No line of a listing may hold `KUBE-SVC-`.
7. k3s runs kube-proxy inside its own process, so the check does not look for a process name. The `KUBE-SVC-` chains are what kube-proxy leaves on a node.
8. The check only reads. It uses `kubectl get` and `kubectl exec` through `internal/kube`, as discovery step D0.10 does with `cilium-dbg`. Its tests use the fake kubectl of `fake_kubectl_test.go` for the reads and a replaced exec function for the two commands. One test runs the listing script with `sh` and fake iptables programs. A fake iptables program is the test binary under the name of the program, as the fake kubectl is the test binary; the test writes no program file. The two new files hold no comment that switches a lint finding off: no `//nolint` and no `#nosec`.
9. In `docs/ledger/gates.yaml` the entry NET-G03 moves from `state: not-built` to `state: required` and gains the line `implementation: tests/acceptance/sovereign/internal/suite/check_kube_proxy.go`. No other line of the file changes.
10. No live node is changed by hand. A Sovereign that was built before this change keeps kube-proxy until its nodes are built again, and NET-G03 fails on it until then. That is the truth.

+//     "KubeProxyReplacement:" with the value True. The exit code of the

+// kubeProxyNode reads one agent and returns "" when its node is clean, or what is wrong.
+func kubeProxyNode(ctx context.Context, region kube.Region, pod string) string {
+	status, err := kubeProxyExec(ctx, region, pod, "cilium-dbg", "status")
+	value := kubeProxyReplacement(string(status))

+		return "listing the nat table failed: " + err.Error()
+	case len(listed) == 0:
+		return "no iptables program could list the nat table"
+	}
+	if chains > 0 {
+		return fmt.Sprintf("the nat table names a %s chain in %d line(s) (listed with %s): kube-proxy runs or ran on this node", kubeProxyChain, chains, strings.Join(listed, ", "))
+	}
+	return ""

+// kubeProxyReplacement returns the value of the line "KubeProxyReplacement:"
+// of `cilium-dbg status`, or "" when the line is missing.
+func kubeProxyReplacement(status string) string {
+	for _, line := range strings.Split(status, "\n") {
+		f := strings.Fields(line)
+		if len(f) >= 2 && f[0] == "KubeProxyReplacement:" {
+			return f[1]
+		}
+	}
+	return ""
+}

+// kubeProxyNat reads the output of kubeProxyNatScript: the programs that
+// listed the table, and the number of lines that name a KUBE-SVC- chain.
+func kubeProxyNat(out string) (listed []string, chains int) {

+		case strings.Contains(line, kubeProxyChain):
+			chains++
+		}
+	}
+	return listed, chains
