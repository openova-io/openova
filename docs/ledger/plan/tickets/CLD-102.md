# CLD-102 — Delete the dead Provision method of the provider port

## In plain words

**The problem today.** The cloud provider interface of the API server still declares a method that provisions a deployment, and both cloud adapters implement it. Nothing calls it: provisioning runs through the engine directly. The dead method misleads every reader of the interface and must be kept compiling by every new adapter and test stub.

**What changes.** The method and its result type leave the interface, and the two adapters, one test and one test stub lose their copies of it. Wipe, the credential check and the server listing work as before.

**Done means:**

- The provider interface has four methods: Name, Wipe, ListServers and ValidateCreds.
- No file under the provider packages, and not the wipe test stub, names the deleted method, its result type or the request converter of the adapters.
- The API server builds, and its provider, wipe and janitor tests pass unchanged.
- No line that names a cloud is added to shared code.

The rest of this ticket is the exact instruction for the model that does the work.
