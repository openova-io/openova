# CMP-020 — The API tells the truth: live mode, no fixture data, no invented list

## In plain words

**The problem today.** The compliance screens of a Sovereign show things nobody measured. The mode of a policy comes from a setting of the API instead of the policy itself, the scorecard lists two test application names that may not exist, and the policy list can be cut to a fixed list of nineteen names with a fixed count. The page of one policy also asks the cluster on every request instead of using what the API already watches.

**What changes.** Every mode shown is the mode of the policy object, and every name and number comes from what the API has observed. The direct cluster reads of the compliance code can only become fewer from now on, and the two gate checks for the score and the mode become required.

**Done means:**

- For every policy the API watches, the policy list and the page of one policy show the mode Enforce exactly when the policy object of the engine enforces.
- The scorecard names only applications for which the API has seen a policy report, and it has no category scores.
- The policy list has no baseline filter and no fixed count of nineteen.
- The violations of one policy can be asked for and are filtered on the server.
- The page of one policy is answered without a request to the cluster.
- A new direct cluster read in the compliance code turns the pull request red.
- The gate checks CMP-G01 and CMP-G02 are required.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The compliance routes of catalyst-api state only what they observe. `GET /api/v1/sovereigns/{id}/compliance/policies` and `GET /api/v1/sovereigns/{id}/compliance/policies/{name}` show for each policy the mode that the engine's policy object carries, and the by-name route answers from the aggregator, with no request to the cluster. The scorecard lists only applications the aggregator has seen and has no category block. The policy list has no fixed list of nineteen names. `GET /api/v1/sovereigns/{id}/compliance/violations` accepts `policy=<name>`. A new guard, `scripts/check-compliance-live-reads.sh`, run by the job `tree-guards`, fails a change that adds a direct cluster read to the compliance code. The gate checks CMP-G01 (the score moves by push) and CMP-G02 (the shown mode is the engine's mode) move from `expected-fail` to `required`. A person sees it in the tests of `internal/handler`, in the step `compliance-live-reads` of the check `tree-guards`, and in `docs/ledger/gates.yaml`.

## 3. The model (the law)
1. **The mode is the engine's.** The mode of a policy is the mode its engine object carries, by this rule: a `ValidatingPolicy` enforces when `spec.validationActions` holds `Deny`; a legacy `ClusterPolicy` enforces when `spec.validationFailureAction` is `Enforce`, or when `validate.failureAction` of one of its rules is `Enforce`; every other policy audits. Upper and lower case are the same. This is the rule the gate check CMP-G02 (`tests/acceptance/sovereign/internal/suite/check_compliance_mode.go`, function `engineMode`) applies. The new function `enginePolicyMode` computes it when the cache delivers a policy object, and stores `enforce` or `audit` in the new field `mode` of `policyMeta`. The cache delivers one policy kind today, the legacy `ClusterPolicy` (kind `clusterpolicy`), so this ticket makes the shown mode true for every policy the cache delivers; the kind for `ValidatingPolicy` objects is CMP-061's (field 11). `policiesFor` sets `PolicyView.Mode` from it: `enforcing` for `enforce`, `permissive` otherwise. The two words on the wire stay `enforcing` and `permissive`, because the console reads exactly these two (`products/catalyst/bootstrap/ui/src/pages/admin/compliance/compliance.api.ts` line 23); CMP-G02 accepts both vocabularies. No other source of a mode remains: `policiesFor` no longer reads the modes of an `EnvironmentPolicy`, the field `Modes` leaves `EnvironmentPolicySpec`, and the resolver no longer reads `spec.compliance.modes`.
2. **The policy routes answer from the aggregator.** `HandleCompliancePolicies` returns what `policiesFor` returns, with no fallback. The fallback that listed the cluster's `ClusterPolicy` objects when the aggregator was empty (`listLivePoliciesFromCluster`) is deleted. `HandleCompliancePolicyByName` returns the row of `policiesFor` whose name matches: 200 with that `PolicyView`, 404 with `{"error": "policy not found"}` when there is none, 503 `compliance handler not wired` when the aggregator is not wired, like the other compliance routes. Its `Get` of the cluster and the function `projectClusterPolicyToView` are deleted.
3. **No fixture data.** `appRefsFromEnv`, `mergeSortedAppRefs` and the variable `CATALYST_QA_APPLICATIONS` (with its comment) in both deployment templates are deleted. `appRefs` of the scorecard holds only the applications of the aggregator's rollups (`scorecardAppRefs`).
4. **No invented list.** `canonicalBaselinePolicyCount`, `canonicalBaselinePolicyNames`, `filterBaselinePolicies`, the query parameter `baseline` and the answer keys `baseline` and `baselineCount` are deleted. `?baseline=true` is ignored like any unknown parameter.
5. **No category block.** The fields `CategoryScores`, `Security`, `SRE`, `Baseline` and `Reliability` of `ScorecardResponse`, the type `CategoryScore`, and the functions `computeCategoryScores` and `categoryBucket` are deleted. No field is kept "for compatibility".
6. **Violations by policy.** `HandleComplianceViolations` reads `policy=<name>` and `violationsFor(clusterID, app, policy)` keeps only that policy's violations, before the page is cut. `limit`, `offset` and their bounds do not change.
7. **The guard.** `scripts/check-compliance-live-reads.sh` counts, per file, the lines that read a cluster directly, and compares them with `scripts/baselines/compliance-live-reads.json` (metric `compliance_live_reads`). Files: `products/catalyst/bootstrap/api/internal/handler/compliance_runtime.go`, and every `.go` file that is not a `_test.go` file under `products/catalyst/bootstrap/api/internal/compliance/`. A line counts when it is not a comment line and matches `\.Resource\(.*\.(List|Get|Watch)\(`, or, under `internal/compliance/`, `(DynamicClientFor|CoreClient|RestConfigFor)\(`. A count above its entry fails; a count below its entry fails too (the baseline is lowered in the same change). After this ticket the baseline holds 6 for `compliance_runtime.go`. Its `--self-test` proves every rule can fail. The job `tree-guards` runs both.
8. **The gate.** CMP-G01 and CMP-G02 are `required` in `docs/ledger/gates.yaml`; no other field of the two entries changes.
9. **The handler package shrinks** and `scripts/baselines/api-structure.json` is lowered by its own tool. No file is added to `internal/handler`; `policy_mode.go` is not touched.

# check-compliance-live-reads.sh - the compliance code of catalyst-api may read the cluster directly only less often.
#
# The compliance routes answer from the informer cache of catalyst-api. A route that asks the API server
# of a cluster on every request can disagree with the cache, is slow, and hides a kind the cache does not
# watch. This guard counts the lines that read a cluster directly, and the count of each file may only fall.
#
#   bash scripts/check-compliance-live-reads.sh              check the repository
#   bash scripts/check-compliance-live-reads.sh --self-test  prove on throw-away folders that each rule can fail
#
# Files read: products/catalyst/bootstrap/api/internal/handler/compliance_runtime.go, and every file whose
#   name ends in .go and not in _test.go under products/catalyst/bootstrap/api/internal/compliance/, sub-folders
#   included. A file that does not exist counts zero. If the folder products/catalyst/bootstrap/api/internal
#   does not exist, nothing can be judged: exit 1.
# A line counts once, and only when its first characters other than blanks are not //:
#   in every file read, when it matches the expression  \.Resource\(.*\.(List|Get|Watch)\(
#   in a file under internal/compliance/, also when it matches  (DynamicClientFor|CoreClient|RestConfigFor)\(
# Rule: the count of each file equals its entry under the metric compliance_live_reads of
#   scripts/baselines/compliance-live-reads.json; a file absent from the baseline is allowed zero. A count
#   above its entry fails; a count below its entry fails too, so a change that removes a read lowers the
#   baseline in the same change, and a file at zero leaves it. The baseline is
#   {"schema": "openova.io/guard-baseline/v1", "counts": {"compliance_live_reads": {"<path>": <n>}},
#   "allow": []}: exactly these three keys, one metric, an empty allow list, every entry a whole number of
#   1 or more.
# Every run that can read the tree prints, as its last line, compliance_live_reads=<total>.
# Exit code 0: the rule holds. 1: a finding, or the tree or the baseline cannot be read. 2: wrong usage.

root = sys.argv[1]

    sys.exit(1)

def region(text, check):
    """(start, end) of the entry of check in the manifest text; (0, len) when check is None."""
    if check is None:
        return 0, len(text)
    head = "- id: %s\n" % check
    if text.count(head) != 1:
        return None
    start = text.index(head)
    end = text.find("\n- id: ", start + len(head))
    return start, (len(text) if end < 0 else end + 1)


def find(text, old):
    """(found, start, end): how often old occurs, and the span to replace when it occurs once.
    A pair (first, after) spans from the line of first to the line before after; it is found
    once when each bounding text occurs once and first comes before after."""
    if isinstance(old, tuple):
        first, after = old
        cf, ca = text.count(first), text.count(after)
        if cf != 1 or ca != 1:
            return (0 if 0 in (cf, ca) else max(cf, ca)), 0, 0
        a, b = text.index(first), text.index(after)
        if a >= b:
            return 0, 0, 0
        return 1, a, b + 1
    n = text.count(old)
    if n != 1:
        return n, 0, 0
    a = text.index(old)
    return 1, a, a + len(old)


def main():
    if sys.argv[1:] not in ([], ["--check"]):
        print("usage: CMP-020-edits.py [--check]")
        return 2
    check_only = sys.argv[1:] == ["--check"]
    texts, bad = {}, 0
    for name, path, check, old, new in EDITS:
        if path not in texts:
            with open(path, encoding="utf-8") as f:
                texts[path] = f.read()
        text = texts[path]
        r = region(text, check)
        found, a, b = (0, 0, 0) if r is None else find(text[r[0]:r[1]], old)
        if check_only:
            print("%s %s found %d" % (name, path, found))
        if found != 1:
            bad += 1
            if not check_only:
                print("%s %s: the text was found %d times, not once" % (name, path, found))
            continue
        texts[path] = text[:r[0] + a] + new + text[r[0] + b:]
    if bad:
        if not check_only:
            print("nothing was written")
        return 1
    if check_only:
        return 0
    for path, text in texts.items():
        with open(path, "w", encoding="utf-8") as f:
            f.write(text)
    for name, path, _, _, _ in EDITS:
        print("%s %s edited" % (name, path))
    return 0


if __name__ == "__main__":
    sys.exit(main())
