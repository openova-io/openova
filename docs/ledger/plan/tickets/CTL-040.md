# CTL-040 — Flux manifests to stable API versions

## In plain words

**The problem today.** Flux has served the chart-source kind at a stable version for a long time, yet the platform still writes the old beta version in the per-Organization pipelines, in one chart and in several test fixtures. The beta version is deprecated, and the planned Flux upgrade waits until nothing writes it any more. The falco README also shows its release examples at a deprecated beta version.

**What changes.** Every chart source that the Organization pipelines generate, that the vcluster source chart installs, and that the cutover and acceptance tests use as a fixture, is declared at the stable version. The falco README examples use the stable release version. Nothing else in these objects changes.

**Done means:**

- No file under core, products, platform or tests names the beta version of the Flux chart-source kind.
- No file of the repository, outside the plan's own files, names a beta version of the Flux release kind.
- The vcluster source chart renders its chart source at the stable version.
- The tests of the provisioning service's GitOps generator, the Organization pipeline tests of the API and the acceptance-suite unit tests pass.
- The cutover chart's shell tests pass on the pull request.
- No chart version, pin or bootstrap-kit slot file is changed by the pull request.

The rest of this ticket is the exact instruction for the model that does the work.
