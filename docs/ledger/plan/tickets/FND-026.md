# FND-026 — Two tasks that share only record files may run together

## In plain words

**The problem today.** The plan tool keeps two work packages apart whenever both change the same file. Many packages only add their own lines to a few shared record files, such as the list of gate checks or the list of deleted paths, and those lines never collide. So packages that could run side by side wait for each other, and the plan moves slower than it needs to.

**What changes.** The plan tool no longer counts a shared record file when it decides whether two packages may run together, and the plan file may list further record files in a new optional field. The check list still keeps two packages apart when both name the same check, and every other shared file keeps them apart as before.

**Done means:**

- Two packages that share only the check list, and name different checks, may run together; two that name one check may not.
- Two packages that share only the list of deleted paths, or only a file the plan lists as a record file, may run together.
- Two packages that share any other file, a lock, a stability entry of class thrashing or frozen, or a resource still may not run together.
- The commands that hand out work (ready, batch and claim-check) follow the same rule.
- The plan file on main stays valid without the new field, and a plan file with a wrong list of record files is refused.
- The protocol states the rule beside its paragraph on files with many writers.

The rest of this ticket is the exact instruction for the model that does the work.
