# SOV-136 — Nodes share the images they hold: the k3s embedded registry mirror is on from first boot

## In plain words

**The problem today.** When a worker node is drained, its Pods start again on other nodes and must pull every image those nodes do not hold. After the cutover a node may pull only from the Sovereign's own registry, so when the moved Pod is part of that registry, or the registry is down for another reason, the Pod waits forever, even though the drained node, back within minutes, still holds the image. Today no node can take an image from another node.

**What changes.** The first boot starts k3s with its built-in registry mirror, so the nodes of a region share the images they hold. A test fails when the setting is missing or misplaced.

**Done means:**

- The k3s server line of the shared first-boot template passes --embedded-registry once and still passes --disable-default-registry-endpoint.
- No worker template passes the flag; workers take the setting from their server.
- A Go test fails when the flag is missing, doubled or set a second time, when a worker passes it, when a provider pins a k3s release older than the flag, or when a cloud provider's registries.yaml loses its wildcard entry.
- The stored golden values match the new render, and every file the first boot writes keeps its bytes.
- Each control plane's start-up data grows by 20 bytes and every node role of both cloud providers stays under its size limit.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A new Sovereign's control plane starts k3s with `--embedded-registry`. k3s then runs its embedded distributed registry mirror (Spegel) on every node of the region's cluster: each node serves the images of its containerd store on the supervisor port 6443 and advertises them to its peers on TCP 5001; a node takes part only with a client certificate of the cluster CA and the preshared key that the server controls; agents take the setting from the server. For every name that has an entry in `/etc/rancher/k3s/registries.yaml` (every proxy name and the wildcard `"*"`), containerd asks the peers first and the name's configured endpoints after them; `--disable-default-registry-endpoint` stays, so no public fallback returns. A Pod that a drain moves to a node without its image takes the image from any node of the region that holds it; an image that no node holds comes from the region's registry as before. The Go test `products/catalyst/bootstrap/api/internal/provisioner/cloudinit_embedded_registry_test.go` holds the four facts this rests on. The start-up data of each control plane grows by 20 bytes, plain text.
