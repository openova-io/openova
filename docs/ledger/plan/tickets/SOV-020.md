# SOV-020 — One default for the zero-touch switch

## In plain words

**The problem today.** A Sovereign is meant to run its self-sovereignty cutover after hand-over without a person. The switch for this has several defaults, and two of them still say false: the fallback in the bootstrap-kit slot of the cutover chart and the default of the cutover chart itself. When the value is missing, the chart's trigger hook therefore stays away while the platform API expects the cutover to run.

**What changes.** Both defaults become true, so every default of the switch agrees. The chart's contract test now proves that the hook renders by default and that a false value still keeps it away.

**Done means:**

- Slot 06a falls back to true for the cutover switch, the same as slot 13.
- The cutover chart rendered with its own defaults contains the auto-trigger hook Job.
- The cutover chart rendered with the switch set to false contains no auto-trigger hook Job.
- The kit renders exactly as before with the stored value sets, because those sets give the switch a value.
- The cutover chart's contract test passes, and its Case 8 fails when the chart default is false.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After hand-over a Sovereign starts its self-sovereignty cutover by itself unless the variables document sets `HANDOVER_AUTO` to `false`. The switch reaches two readers through a Flux substitution: the catalyst-api (slot 13, `catalystApi.fireCutoverOnHandover`) and the cutover chart's auto-trigger hook (slot 06a, `trigger.fireCutoverOnHandover`). Since SOV-151 both slots read `HANDOVER_AUTO` first and the kit key `FIRE_CUTOVER_ON_HANDOVER` second, and end in a last default. Every default of the switch is true except two: the last default in slot 06a (`${HANDOVER_AUTO:=${FIRE_CUTOVER_ON_HANDOVER:-false}}`, after SOV-151) and the chart default in `platform/self-sovereign-cutover/chart/values.yaml` (`fireCutoverOnHandover: false`). After this ticket both are true, the comments that describe them say so, and the chart's contract test asserts the new default instead of the old one.
