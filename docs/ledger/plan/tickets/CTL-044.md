# CTL-044 — Publish contracts C3 and C4

## In plain words

**The problem today.** Several areas publish or consume platform events, and several write intent into the platform's Git repositories. They need fixed names and places to build against before they start. Today the event subjects are scattered in the code, and most are not even written in full: a service names a short event type and the subject is built from it. No file says where each kind of intent lives in Git, and nothing stops a new event subject or a new message stream from appearing unnoticed.

**What changes.** Two contract files are published: the list of event subjects with their owners, producers, consumers and payloads, and the Git layout with the interface of the commit library. A check on every pull request fails when the code names an event that the list lacks, by its subject or by its event type, or adds a call that creates a message stream.

**Done means:**

- Every event subject that the code publishes or subscribes to today is in the published list, with its owner, producers, consumers and payload. This holds for a subject written in full and for a subject built from an event type.
- The list reserves the alert event, with the twelve fields of its payload, and the durable audit event; nothing publishes either yet.
- The Git layout contract names the three places where intent lives, the reserved folders and the two released folders.
- A pull request that names an unlisted event subject, or an unlisted event type in a publish call or in a subscription list, turns red.
- A pull request that adds a call that creates a message stream, or a publish call or subscription list whose event type the check cannot read, turns red.
- The check proves on itself that each of its rules can fail.
- No product code changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. The guard is `scripts/check-event-subjects.py`. It reads the working tree from the repository root. It needs Python 3; only the run against the real files imports the YAML library. Its rules are written at its head; they are, in short:
   - Rule 1, the registry's form. `docs/contracts/C3-event-subjects.yaml` has exactly the keys `schema` (`openova.io/event-subjects/v1`), `stream` (`CATALYST_ORG`) and `subjects` (a list that is not empty). Each entry has exactly `subject`, `envelope` (`cloudevents`, `legacy` or `foreign`), `owner` (three capital letters), `producers` and `consumers` (lists of distinct names; either may be empty), `payload` (a file of the repository; a `.json` file must be valid JSON) and `delivery` (`at-least-once`, or `at-most-once` and then only with envelope `foreign`).
   - Rule 2, the names. No subject is listed twice. A `legacy` subject is `catalyst.<token>.<token>`, with more tokens allowed. A `cloudevents` or `foreign` subject is `catalyst.<domain>.<event>.v<major>`. A token is a lower-case letter followed by lower-case letters, digits or underscores.
   - Rule 3, registration. Every subject that a Go file names is listed. The Go files are the `.go` files that git lists as tracked, or as new and not ignored, except `*_test.go`. A Go file names a subject in two ways, (a) and (b).
   - Rule 3 (a), a subject literal. It is a quoted or raw string literal outside comments whose whole text is a legacy subject name. A literal with a wildcard (`*` or `>`) is a subscription filter and is not checked.
   - Rule 3 (b), an event type. Most services do not write a subject in full. They name an event type, for example `provision.started`, and the function `CanonicalSubject` in `core/services/shared/events/bridge.go` builds the subject from it: `catalyst.billing.<type>` when the type starts with `order.`, and `catalyst.<type>` otherwise. The guard builds the subject the same way and checks it like a subject literal. It reads an event type in two places. The first place is a call of `NewEvent` or `publishEvent`: the first string literal after the opening parenthesis, on the same line, is an event type when its text is `<token>.<token>`, with more tokens allowed. The second place is a list that opens with `EventTypes: []string{` or `eventTypes := []string{`: every string literal up to the first `}` is an event type. A line that starts with `//` is not read.
   - Rule 3, two names that are no subjects. `catalyst.openova.io` is the API group of the platform's kinds. `catalyst.event.dead_letter` is what rule 3 (b) builds from the event type `event.dead_letter` in `core/services/shared/events/dlq.go`; that event goes to a Kafka topic only and never to the stream.
   - Rule 4, two counts. Per Go file, each count, less its allow entries, must equal the file's entry under the metric of that count in `scripts/baselines/streams.json`. A file absent from a metric is allowed zero. A count above its entry fails. An entry above the count fails too, so a change that removes a counted line lowers the baseline in the same pull request. The baseline has the form `openova.io/guard-baseline/v1` with `counts` and `allow`.
   - Rule 4, the metric `stream_create_calls`: the lines that call `AddStream`, `CreateStream`, `CreateOrUpdateStream` or `UpdateStream`. A line that starts with `//` is not counted.
   - Rule 4, the metric `event_type_indirections`: the places where rule 3 (b) cannot read an event type. There are three kinds. One: a call of `NewEvent` or `publishEvent` that has no string literal on its line, or whose first string literal is not an event type; the `func` line that defines either function is not counted. Two: a line with `EventTypes:` that opens no list. Three: a line that builds `events.Event{` or `natsbus.Event{`. Three such places exist today, and rule 3 (b) reads the event types behind each of them: the two functions named `publishEvent` pass their event type on to `NewEvent`, and their callers write it; the notification service fills `EventTypes:` from the list `eventTypes`. A new indirection fails. Its baseline entry may be raised only in a pull request that also makes the guard read the new name.
2. Output: one line `FAIL rule <n>: <text>` per failure, then the four lines `subjects=<n>`, `code_subjects=<n>`, `event_type_indirections=<n>` and `stream_create_calls=<n>`. `subjects` counts the entries of the registry. `code_subjects` counts the distinct subjects that the Go files name by rule 3 (a) or (b). Exit code 0 when every rule holds, 1 when one fails, 2 when a file cannot be read (then it judges nothing).

```python
  cloudevents or foreign subject is catalyst.<domain>.<event>.v<major>. A token is [a-z][a-z0-9_]*.

  and not ignored), *_test.go excepted; NOT_SUBJECTS are no subjects. (a) A subject literal is a quoted

def literals(src):
    """The string literals of Go source; comments and rune literals are skipped."""
    out, i, n = [], 0, len(src)
    while i < n:
        if src.startswith("//", i):
            j = src.find("\n", i)
            i = n if j < 0 else j
        elif src.startswith("/*", i):
            j = src.find("*/", i + 2)
            i = n if j < 0 else j + 2
        elif src[i] == "`":
            j = src.find("`", i + 1)
            j = n if j < 0 else j
            out.append(src[i + 1:j]); i = j + 1
        elif src[i] in "\"'":
            j = i + 1
            while j < n and src[j] not in (src[i], "\n"):
                j += 2 if src[j] == "\\" else 1
            if src[i] == '"':
                out.append(src[i + 1:j])
            i = j + 1
        else:
            i += 1
    return out

def event_types(src):
    """Rule 3 (b): the subjects of the event types a Go file names, and its indirections."""
    types, hidden, lines = [], 0, src.split("\n")
    for k, line in enumerate(lines):
        if line.lstrip().startswith("//"): continue
        call, opened = EVENT_CALL.search(line), TYPE_LIST.search(line)
        if call and not call.group(1):
            first = literals(line[call.end():])[:1]
            if first and EVENT_TYPE.fullmatch(first[0]): types += first
            else: hidden += 1
        if opened: types += literals("\n".join(lines[k:])[opened.end():].split("}")[0])
        elif TYPE_FIELD.search(line): hidden += 1
        hidden += bool(EVENT_BUILD.search(line))
    return [t if t.startswith("catalyst.") else ("catalyst.billing." if t.startswith("order.") else "catalyst.") + t for t in types], hidden

def check_baseline(base, have):

    if not isinstance(base, dict) or sorted(base) != ["allow", "counts", "schema"] or base["schema"] != "openova.io/guard-baseline/v1":
        return ["rule 4: the baseline must have exactly the keys schema, counts and allow, schema openova.io/guard-baseline/v1"]
    c, allow, allowed = base["counts"], base["allow"], {}

            and all(type(v) is int and v >= 1 for m in METRICS for v in c[m].values())):
        return ["rule 4: counts must hold exactly %s, each entry 1 or more" % " and ".join(METRICS)]
    for a in allow if isinstance(allow, list) else [None]:
        if not (isinstance(a, dict) and sorted(a) == ["count", "metric", "owner", "path", "reason"] and a["metric"] in METRICS
                and type(a["count"]) is int and a["count"] >= 1 and isinstance(a["path"], str)
                and isinstance(a["reason"], str) and len(a["reason"]) >= 10 and isinstance(a["owner"], str) and AREA.fullmatch(a["owner"])):
            return ["rule 4: an allow entry needs a metric of counts, path, count, owner and a reason of ten characters or more"]

    f = []
    for m in METRICS:
        for path in sorted(set(have[m]) | set(c[m]) | {p for am, p in allowed if am == m}):
            n, w = have[m].get(path, 0) - allowed.get((m, path), 0), c[m].get(path, 0)

            elif n > w: f.append("rule 4: %s has %d %s; the baseline allows %d" % (path, n, m, w))
            elif n < w: f.append("rule 4: %s has %d %s; lower its baseline entry from %d" % (path, n, m, w))
    return f

def judge(reg, read, go_files, base):
    """All four rules; go_files maps a path to its text. Returns (failures, metric lines)."""
    f, registered = check_registry(reg, read)
    found, have = {}, {m: {} for m in METRICS}
    for path in sorted(go_files):
        typed, hidden = event_types(go_files[path])
        for s in [x for x in literals(go_files[path]) if LEGACY.fullmatch(x)] + typed:
            if s not in NOT_SUBJECTS: found.setdefault(s, path)
        n = sum(1 for line in go_files[path].splitlines() if STREAM_CALL.search(line) and not line.lstrip().startswith("//"))
        for m, v in zip(METRICS, (hidden, n)):
            if v: have[m][path] = v
    f += ["rule 3: %s (in %s) is not listed in %s" % (s, found[s], REGISTRY) for s in sorted(found) if s not in registered]
    f += check_baseline(base, have)
    return f, ["subjects=%d" % len(registered), "code_subjects=%d" % len(found)] + ["%s=%d" % (m, sum(have[m].values())) for m in METRICS]
```

````markdown
## 1. Go package `gitwrite`

Import path `github.com/openova-io/openova/core/controllers/pkg/gitwrite` (CTL-110). It
calls the existing client `core/controllers/pkg/gitea` and nothing else. It is the only
package allowed to author files under an `intent/` path.

```go
package gitwrite

// Repo names one repository. Branch "" means "main".
type Repo struct {
	Owner  string
	Name   string
	Branch string
}

// Identity is a Git author or committer.
type Identity struct {
	Name  string
	Email string
}

type Op string

const (
	OpUpsert Op = "upsert" // create the file or replace its content
	OpDelete Op = "delete" // delete the file; deleting an absent file is not an error
)

// AbsentSHA as IfMatch means "the file must not exist".
const AbsentSHA = "absent"

// FileChange is one file in a commit.
type FileChange struct {
	Path    string // repository-relative, no leading slash, no ".." element
	Op      Op
	Content []byte // ignored for OpDelete
	IfMatch string // "" no precondition; AbsentSHA; or the blob SHA the file must have
}

type Via string

const (
	ViaConsole    Via = "console"
	ViaAPI        Via = "api"
	ViaMCP        Via = "mcp"
	ViaEvent      Via = "event"      // a projected database decision
	ViaController Via = "controller" // adoption commits and rendered files
)

// Change is one atomic commit.
type Change struct {
	Scope    Scope             // selects the robot and the allowed paths; required
	Repo     Repo              // required
	Files    []FileChange      // 1..200; paths unique
	Summary  string            // first line of the message, 1..72 characters, required
	Author   Identity          // the person; zero value means the robot is also the author
	ChangeID string            // required; from NewChangeID
	Via      Via               // required
	Trailers map[string]string // extra trailers; keys match ^[A-Z][A-Za-z-]*$; default nil
}

type FileResult struct {
	Path    string
	BlobSHA string // "" for a deleted file
}

type Result struct {
	Commit    string // commit SHA; the current head when Committed is false
	Committed bool   // false when every file already had the wanted content
	Files     []FileResult
}

type Entry struct {
	Path    string
	BlobSHA string
	IsDir   bool
}

// Writer is what handlers, controllers and consumers depend on.
type Writer interface {
	// Commit applies all files in one commit or none.
	Commit(ctx context.Context, c Change) (Result, error)
	// Read returns a file and its blob SHA. A missing file returns ErrNotFound.
	Read(ctx context.Context, s Scope, r Repo, path string) (content []byte, blobSHA string, err error)
	// List returns the entries directly under dir. A missing dir returns an empty slice.
	List(ctx context.Context, s Scope, r Repo, dir string) ([]Entry, error)
}

// Scope binds a robot identity to the path prefixes it may write.
type Scope struct {
	Name     string   // "fleet-intent", "org-intent", "catalog", "fleet-rendered", "org-rendered"
	Robot    string   // Gitea user whose token is used and who is the committer
	Prefixes []string // a Change may only touch paths under one of these; "" allows every path
}

func FleetIntent(sovereignFQDN string) Scope   // robot "catalyst-fleet-bot", prefix "clusters/<fqdn>/intent/"
func OrgIntent(slug string) Scope              // robot "<slug>-iac-bot",     prefix "intent/"
func Catalog() Scope                           // robot "catalyst-fleet-bot", prefix ""
func FleetRendered(sovereignFQDN string) Scope // robot SharedRobot, prefix "clusters/<fqdn>/regions/"  (first used by CTL-260)
func OrgRendered() Scope                       // robot SharedRobot, prefixes "regions/", "vcluster/", "continuum/"  (first used by CTL-260)

// SharedRobot names the identity behind the token the controllers use today (CATALYST_GITEA_TOKEN).
const SharedRobot = "catalyst-shared"

// TokenSource returns the access token of a robot.
type TokenSource interface {
	Token(ctx context.Context, robot string) (string, error)
}

// SharedTokenSource returns the same token for every robot. With it, the committer
// of every commit is SharedRobot whatever Scope.Robot says. Used until CTL-126.
func SharedTokenSource(token string) TokenSource

type Config struct {
	BaseURL     string        // Gitea base URL, in-cluster; required
	Tokens      TokenSource   // required
	RobotDomain string        // e-mail domain of robot identities; required; "robots.<sovereign-fqdn>"
	HTTPTimeout time.Duration // default 15s
	MaxRetries  int           // default 3; used only when no FileChange has IfMatch set
}

func New(cfg Config) (*Client, error) // *Client implements Writer
func NewChangeID() string             // 26-character ULID

var (
	ErrNotFound      = errors.New("gitwrite: not found")
	ErrForbiddenPath = errors.New("gitwrite: path outside the scope")
	ErrSecretContent = errors.New("gitwrite: content holds a Secret object")
	ErrInvalid       = errors.New("gitwrite: invalid change")
	ErrUnavailable   = errors.New("gitwrite: git server unavailable")
)

// ConflictError is returned when an IfMatch precondition fails.
type ConflictError struct {
	Path    string
	Want    string // the IfMatch value
	Current string // current blob SHA, "" if the file is absent
}

func (e *ConflictError) Error() string
func IsConflict(err error) bool

Region scopes (CTL-112): `RegionPlatform(fqdn, modules, regionIDs)` has robot
`catalyst-fleet-bot` and allows only `clusters/<fqdn>/regions/<listed region>/platform/<listed module>/**`;
an empty list refuses every commit. `Regions` lists the region folders. `WriteAllRegions`
writes the same files into every listed region folder in one commit, with compare-and-swap
on the file of the first region in sorted order.

Semantics:

1. **Atomic.** One call to `POST /api/v1/repos/{owner}/{repo}/contents` with a `files` array (`operation` `create`, `update` or `delete`; `path`; base64 `content`; `sha`). The library reads each file's current blob SHA first to choose `create` or `update`. If the spike CTL-050 shows that this call is not all-or-nothing, the library uses the Git data sequence of `commitOnceGitData` in `core/services/provisioning/github/client.go` behind the same interface.
2. **No-op.** If every upsert equals the current content byte for byte and every delete targets an absent file, no commit is made and `Committed` is false.
3. **Compare-and-swap.** A non-empty `IfMatch` is checked against the blob SHA read in item 1 and is also sent as `sha`. A mismatch at either point returns `*ConflictError`. With no `IfMatch` on any file, a server-side mismatch is retried up to `MaxRetries` times from item 1.
4. **Path policy.** A path outside `Scope.Prefixes`, or with a `..` element, returns `ErrForbiddenPath` before any network call.
5. **No secrets.** Each upsert whose path ends in `.yaml`, `.yml` or `.json` is parsed as a stream of documents. A document with `apiVersion: v1` and `kind: Secret` returns `ErrSecretContent`, whatever fields it has. A file that does not parse is committed as it is (the caller validated it).
6. **Field checks.** A missing required field, an empty `Files`, more than 200 files, a duplicate path, or a summary outside 1 to 72 characters returns `ErrInvalid`.
7. **Message.** Exactly the lines below; the extra trailers are sorted by key, one per line.
8. **Identity.** `author` is `Change.Author` when set, otherwise the committer. `committer` is `{Name: <robot>, Email: <robot> + "@" + RobotDomain}`, where `<robot>` is `Scope.Robot`, or `SharedRobot` when the token source is `SharedTokenSource`.
9. **No index files.** No caller writes a `kustomization.yaml` into an `intent/` directory. Flux generates one from the directory content.
10. **Errors from Gitea.** HTTP 5xx, a time-out or a connection error returns `ErrUnavailable` (wrapped). HTTP 401 or 403 returns the Gitea error wrapped, not `ErrUnavailable`.
````
