# FND-101 — Truth reset of the status surfaces

## In plain words

**The problem today.** The acceptance ledger prints 110 green rows for the live environment, but only 17 of them were measured there; the others were copied forward from environments that no longer exist. Seven older reports read like current statements about the product, and the status document still calls every pillar code-complete and one of them proven live. Rows about a console panel that was deleted, and a region-kill row backed by a walk on a wiped environment, still count as green.

**What changes.** The ledger is titled a console regression list and its header carries one generated line: how many greens were measured on its environment, how many were carried, and the newest date. The seven old reports start with a line that says they are historical. The pillar section of the status document says that no pillar is proven on what main publishes. Eight rows are retired and point at the gate checks that replace them.

**Done means:**

- The ledger's title calls it a console regression list, and it still holds 286 rows.
- One command prints the line 'Measured on hw307: 17. Carried from earlier environments: 88. Newest stamp: 2026-09-02.', and the ledger's header carries exactly that line.

- The pillar section of the status document carries a rule marker and says that no pillar is proven on what main publishes.
- The ledger guards that run on the pull request stay green.

## 3. The model (the law)
1. ADR-0022 section 5 decides that `docs/ledger/UAT.md` is a regression list, not the measure of done. It keeps its rows and its frozen count of 286. A row is never deleted: a retired row keeps its slot.
2. The title line of `UAT.md` keeps the form every ledger tool reads: it starts with `# UAT`, it names the environment as ``on `hw307.omani.works` ``, and it does not contain the word `pending`. `scripts/uat-drift-guard.py`, `scripts/reset-uat.py`, `scripts/check-function-rows-cite-acceptance.py` and `scripts/check-walk-respects-scheduler.sh` all read the environment from it.
3. The provenance line is printed by `scripts/uat-tally.py --provenance` and is never typed by hand. Its rules: the environment is the one the title names (read exactly as `uat-drift-guard.py` reads it; a title that names none, or says `pending`, is refused with exit code 1); "measured" counts the ✅ rows whose stamp names that environment; "carried" counts every other ✅ row except a row stamped `repo-…` (verified in source, measured on no environment); the newest stamp is the latest date in the stamp of any row.
4. A retired row has the verdict ☐, a stamp cell `— retired 2026-11-13, not walked`, a clause that names the gate check that replaces it, and evidence that starts with `RETIRED AND REPLACED 2026-11-13`. Its clause is the same in `docs/ledger/uat-testcases.csv`, and `docs/ledger/uat-retirements.csv` holds one line for it with the old clause, the new clause and the ground.
5. The tally line of `UAT.md` states the true counts after the change: ✅ 107 · ❌ 12 · ⚠️ 11 · ⏳ 147 · ☐ 9.
6. The first line of each historical report is `Historical. Describes <what>. Not a statement about the product today.` followed by an empty line. Nothing else in those reports changes.
7. The pillar section of `docs/STATUS.md` (section 9) keeps its heading and holds only the state marker `> State: rule. Enforced by: nothing` and the sentence that no pillar is proven on what `main` publishes. Its table, its diagram and its two paragraphs are deleted.
