# FND-024 — The deploy-bump action and its 20 callers push under the release-writer identity

## In plain words

**The problem today.** Twenty build workflows write their image pins to the main branch through one shared deploy action, and that action pushes with the workflow's own token. That token cannot be let past a protected main branch, so main cannot be protected while these builds depend on it. The bot-writer check still lets these twenty jobs through on a list of exceptions.

**What changes.** The shared deploy action pushes with the repository's release-writer deploy key, which every caller hands to it, and marks its commit so that the push starts no workflow. The list of exceptions becomes empty, so the bot-writer check now holds for every job that pushes to main.

**Done means:**

- The shared deploy action sets up the release-writer deploy key in a step of its own before it commits and pushes.
- Every commit the shared deploy action makes ends its first line with the marker that tells GitHub to start no workflow for it.
- Each of the twenty build workflows that use the action passes the key to it from the repository secret.
- The bot-writer check passes with no job left on its list of exceptions, and a job that pushes without the key fails it.
- The action's own tests for the plain push, the push race and the clobber case still pass.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket, the composite action `.github/actions/deploy-bump` pushes its commit to `main` with the release-writer deploy key, whose private half is the secret `RELEASE_WRITER_KEY`. The action gets a new required input `release-writer-key`. Its commit line ends the first line of the message with `[skip ci]`, so that a push with the key starts no workflow, exactly as a push with the workflow token starts none today. Each of the 20 workflows that call the action passes `release-writer-key: ${{ secrets.RELEASE_WRITER_KEY }}` in the `with:` block of that step. The list `docs/ledger/bot-writers.txt` keeps only its two comment lines. The guard `scripts/check-bot-writers.py` (made by FND-017) then reports every job that pushes to main as pushing with the key and none as listed. A person sees the result in the job log of `check-repo-hygiene` (the step "Every job that pushes to main pushes with the release-writer key" prints `0 of them push with the workflow token and are listed`) and, after the merge, in the deploy commits on main, whose first line ends with `[skip ci]`.

## 3. The model (the law)
1. The release-writer identity is one write deploy key of this repository; its private half is the secret `RELEASE_WRITER_KEY`. No token and no machine account is used.
2. A composite action cannot read a secret. So the action takes the key as the input `release-writer-key`, marked `required: true`, with no default, and every caller passes the secret in the `with:` block of its deploy-bump step. The action and all its callers change in one pull request: a caller without the input would fail at its next push.
3. The key step is a `uses:` step of its own, the first step of the action, before the step with `id: run`. The three tests of the action (`test-basic.sh`, `test-clobber.sh`, `test-race.sh`) cut the body of the first `      run: |` line out of `action.yaml` with awk and run it without a key; a `uses:` step has no such line, so they still run only the body.
4. The commit line of the action holds the literal text `[skip ci]` at the end of the first line of the message: `git commit -m "${subject} [skip ci]${DEPLOY_BUMP_MESSAGE#"$subject"}"`, where `subject` is the message up to its first newline. The guard's rule `skip-ci` reads this line. A caller's message does not carry `[skip ci]` itself; the two callers that do today lose it from their `commit-message:` line, so their commits read as before.
5. Nothing else of the action changes: its inputs `paths`, `commit-message`, `max-attempts`, `user-name`, `user-email`, its outputs `pushed` and `commit-sha`, and its retry loop stay as they are.
6. In the job `deploy` of `catalyst-build.yaml` the key step that FND-017 placed after the deploy-bump step stays: the chart-bump step after it pushes by itself and needs it. Only its comment line changes.
7. Every job line of `docs/ledger/bot-writers.txt` is removed. Its two comment lines stay, the second one reworded. The file stays: the guard fails when it is missing.
8. The hand dispatches `gh workflow run blueprint-release.yaml` of the callers stay. Nothing of this ticket applies a ruleset or sets the repository variable `RELEASE_WRITER_LOGIN`.
