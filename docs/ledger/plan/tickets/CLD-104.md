# CLD-104 — The engine writes neutral variables; adapters write their own

## In plain words

**The problem today.** The provisioning engine still writes the OpenTofu variables of each cloud itself: it carries six request fields named after two clouds, writes their tokens and keys, and has a branch for one cloud that rewrites the regions and the parent domains. The adapters, which should own everything about their cloud, return no variables at all. Adding a cloud would mean editing the shared engine again.

**What changes.** Each cloud adapter returns the variables of its cloud and places the regions of its module, the engine writes only what every module shares, and a request carries every cloud credential in one map.

**Done means:**

- The shared engine writes no OpenTofu variable that belongs to one cloud, and no line of its main file names a cloud.
- Each cloud adapter returns the variables of its own cloud, and a variable an adapter returns that clashes with a shared variable fails the provision before OpenTofu runs.
- The deployment request has no field named after a cloud; every cloud credential is a key of its credentials map, and the operator's own keys still never come from a request body.
- For the two reference requests the variables written are the same as before, except that the Huawei file no longer carries the two empty Hetzner keys and writes its parent domains in the engine's own rendering, which decodes to the same list.
- The command that rebuilds a deployment's variables file from its record still writes the same file, also for a record written before the credentials map existed.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`writeTfvars` writes the common variables and the engine extras of module contract version 1 and nothing that belongs to one cloud. Each adapter's `TfVars` returns the variables of its cloud: the Hetzner adapter `hcloud_token` and `hcloud_project_id`; the Huawei adapter `huawei_access_key`, `huawei_secret_key`, `huawei_project_id`, `obs_bucket_name` and `huawei_region`. The engine merges them and fails with `providers.ErrTfVarCollision` when a key is one it wrote or a name of the contract. The place of each module region (code, cloud region, zone) is the one the adapter's `Normalize` gives the spec. The six provider-named fields of `provisioner.Request` (`HetznerToken`, `HetznerProjectID`, `HuaweiAccessKey`, `HuaweiSecretKey`, `HuaweiProjectID`, `HuaweiRegion`) are deleted; every reader uses the credentials map. For the two reference requests of `TestTfvarsGolden` the variables change only as field 5 states.

## 3. The model (the law)
1. `writeTfvars` writes only the common variables and engine extras of `infra/providers/_contract/contract.json`, plus `admin_cidrs` and `provisioner_cidrs`, the two neutral address lists the engine already wrote (field 11). Deleted from it: `hcloud_token`, `hcloud_project_id` and the whole branch for one provider (`huawei_access_key`, `huawei_secret_key`, `huawei_project_id`, `huawei_region`, the rewrite of `cloud_region` and `availability_zone` in `regions`, `obs_bucket_name` and the override of `parent_domains_yaml`).
2. `moduleSpec(req)` resolves the adapter and the effective cloud profile, builds `providerSpec()` from a copy of the request whose Object Storage keys are synchronised, and runs the adapter's `Normalize` on it. `writeTfvars` is not a validator: Provision validates before it, and Destroy writes the variables of a wipe request that nothing validates, so a refusal of `Normalize` is not returned there and the spec is used as `Normalize` left it.
3. `contractRegions(req, spec)` takes `code`, `cloud_region` and `availability_zone` of each entry from the spec and `role` (from the position), the two sizes and the count from the request, which `Validate` set from the same `Normalize`.
4. After the engine's own variables, `adapter.TfVars(spec, profile)` is called and `mergeAdapterVariables` adds its keys in sorted order. A key the engine wrote, or a name of `variables` or `engine_extras` of the contract file below `ProvidersDir`, returns `providers.ErrTfVarCollision` wrapped with the key, and nothing is written. An error of `TfVars` fails the write.
5. The Huawei adapter's `Normalize` places the regions first, before any check: an entry's `cloudRegion` becomes its code when the code is empty, `CloudRegion` becomes `regionFromCreds`, and `Zone` becomes empty (the module's `huawei_az` places each region, as the engine's branch did). Then the credential, region and floor checks run as before.
6. The Huawei adapter keeps returning `huawei_region`, which its module no longer declares, because the wipe (`loadHuaweiCredsFromTfvars`, `internal/handler/wipe.go`), the janitor (`internal/handler/janitor.go`) and the adapter's leftovers lister read it back from the stored variables file. It is a variable of class 3 (its name belongs to one cloud).
7. `parent_domains_yaml` is the engine's rendering for every provider. For the parent domains of the golden request both renderings decode with YAML to the same list (`TestParentDomainsYAML_SameListAsTheFormerCloudRendering`).
8. `Request` keeps `Credentials` as the only place of a cloud credential. New: `RedactedMarker` (the value a stored record holds; `internal/store` uses it), `Credential(key)` (reads the marker as empty, so a rehydrated value is never sent to a cloud), `SetCredential(key, value)` and `WithCredential(key, value)` (a copy with a copied map). `syncLegacyCredentials` keeps only the three Object Storage fields and their keys. `ServerOnlyCredentialKeys` (`access_key`, `secret_key`, `project_id`, `region`) replaces the server-only flags; `RefuseServerOnlyCredentials` refuses a body map that names one. `UnmarshalJSON` resolves the provider with `ResolveProvider`, so a wizard body that names its provider only per region still gets its legacy aliases.
9. `Provisioner` replaces its four provider-named fields with `OperatorCredentials map[string]map[string]string` (provider, then credential key), read by `operatorCredentialsFromEnv()` from the same four environment variables. `Provision` copies the request's map and fills every key the request leaves empty (or holds as the marker) from the entry of its provider. The pre-flight hooks read `req.Credential(...)`.
10. The create handler stamps the operator credentials with `SetCredential` and derives the Object Storage keys from `Credential`; the wipe, the gateway and adoption hand-over steps and the infrastructure view read `Credential`. The Hetzner wipe request is `dep.Request.WithCredential("hcloud_token", body.HetznerToken)`. The handler package shrinks by one line and `scripts/baselines/api-structure.json` is lowered in the same change.
11. The store drops `hetznerToken` and `hetznerProjectID` from the stored record; the credentials map carries them. `redactedMarker` is `provisioner.RedactedMarker`.
12. The command `tfvars-regenerate` finds the credentials of the map as it finds the string fields: every key the stored record holds, every credential field of the effective cloud profile and every server-only key gets a probe value, and the key of the variables file that holds it is read back.
13. `TestTfvarsGolden` moves to the package `internal/provisioner/tfvarsgolden`, which links the two real adapters (the adapters import the engine, so the engine's own tests run against the port double). The double of `port_double_test.go` gains `withDouble`, which gives it a region placement and variables for one test.
14. The messages of `Validate` for Object Storage and the progress messages of plan, apply and destroy no longer name a cloud.
15. All 33 paths change only through the patch `CLD-104.patch` of this ticket.

+// sortedJSON encodes a JSON document again with the keys of every object
+// sorted, an indent of two spaces, no HTML escaping and a final newline.
+func sortedJSON(raw []byte) ([]byte, error) {
+	dec := json.NewDecoder(bytes.NewReader(raw))
+	dec.UseNumber()
+	var doc any
+	if err := dec.Decode(&doc); err != nil {
+		return nil, err
+	}
+	var out bytes.Buffer
+	enc := json.NewEncoder(&out)
+	enc.SetIndent("", "  ")
+	enc.SetEscapeHTML(false)
+	if err := enc.Encode(doc); err != nil {
+		return nil, err
+	}
+	return out.Bytes(), nil
+}

+// firstDifference names the first line where two documents differ.
+func firstDifference(want, got []byte) string {
+	w, g := strings.Split(string(want), "\n"), strings.Split(string(got), "\n")
+	for i := 0; i < len(w) || i < len(g); i++ {
+		var wl, gl string
+		if i < len(w) {
+			wl = w[i]
+		}
+		if i < len(g) {
+			gl = g[i]
+		}
+		if wl != gl {
+			return fmt.Sprintf("line %d\n golden: %s\n now:    %s", i+1, wl, gl)
+		}
+	}
+	return "the documents differ"
+}
