# SEC-246 — Roll-out: products/chargeback master key

## In plain words

**The problem today.** The billing engine reads its master key only from an environment variable, filled from a Kubernetes Secret that a Job of the chart writes. The key wraps every stored credential, so it should come from the secret store as a mounted file, but the engine cannot read a file today, and the chart cannot move until the engine can.

**What changes.** The engine reads the key from the mounted file when it exists and from the variable only when nothing is mounted. The chart is not changed yet: it mounts the file in a second step, after this image is published.

**Done means:**

- With the key file mounted, the engine uses the file's value even when the variable is also set.
- With nothing mounted, as in a local run or on a Sovereign today, the engine uses the variable as before.
- A key file that exists but is empty stops the engine at start, naming the file, and the variable does not take its place.
- A key carried over from the Secret of today (44 characters) and a fresh key of 43 characters both open the engine's keyring; a key of 32 characters is refused.
- The image version of the engine moves to 0.1.68, so the release publishes an image that can read the file, and no chart template changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The chargeback engine can take its master key from the file `/var/run/secrets/openova/app-encryption-key`, the file the Secrets Store CSI driver mounts for the objectName `app-encryption-key`, and still runs on every Sovereign of today, where nothing mounts that file and the key comes from `APP_ENCRYPTION_KEY`. This is the first piece of the roll-out of the master key: the image that reads the file must be published before a chart mounts the file and drops the variable, as the first release of a chart came before its slot for AIP-106 and as SEC-226 shipped its mounted half first. The second piece (the chart mounts the value of the library, seeded from the Secret the key Job wrote, and the Job is deleted) is proposed as its own package (field 11).

## 3. The model (the law)
1. `config.FromEnv` reads the master key with `secretfile.Read("app-encryption-key")`. When the file exists and holds a value, `EncryptionKeyB64` is that value without the line ends at its end, whatever `APP_ENCRYPTION_KEY` holds.
2. When the file does not exist (`secretfile.ErrNotMounted`), `EncryptionKeyB64` is `APP_ENCRYPTION_KEY`, exactly as before.
3. When the file exists but is empty, or cannot be read, `FromEnv` returns an error that names the file; the variable never stands in for a mount that went wrong.
4. Package `products/chargeback/internal/secretfile` is a copy of package `secretfile` of `core/services/auth` (SEC-212): mount directory `/var/run/secrets/openova` (a variable tests may change), one plain file name per value (a path, `..` or a hidden name is refused), the file read on every call, `ErrNotMounted` and `ErrEmpty`.
5. The key's format does not change: `crypto.NewKeyring` takes base64 of 32 bytes in any of its four encodings. A value carried over from the Secret of today (base64 of 32 bytes, 44 characters with padding) and a fresh value of 43 letters and digits (raw base64 of 32 bytes) both make a keyring; 32 characters decode to 24 bytes and are refused with `crypto.ErrKeyLength`.
6. No chart template, value, slot or Secret changes. `appVersion` moves from 0.1.67 to 0.1.68 (the image's source changed, which `scripts/check-appversion-bumped-with-source.sh` requires); the chart's `version:` line is the release's and does not change.
7. The README's row of `APP_ENCRYPTION_KEY` says when the variable is read.

+// Dir is the mount directory. Tests may change it.
+var Dir = "/var/run/secrets/openova"
+
+// ErrNotMounted means the file of the value does not exist: the volume is not
+// mounted, or it does not hold that object.
+var ErrNotMounted = errors.New("secretfile: not mounted")
+
+// ErrEmpty means the file exists and holds nothing but line ends.
+var ErrEmpty = errors.New("secretfile: empty")
+
+// Read returns the content of Dir/<name> without the line ends at its end. It opens
+// the file on every call, so a call after the driver rotated the file returns the new
+// value. A name that is not one plain file name is refused.
+func Read(name string) (string, error) {
+	if name == "" || name != filepath.Base(name) || strings.HasPrefix(name, ".") {
+		return "", fmt.Errorf("secretfile: %q is not a file name", name)
+	}
+	path := filepath.Join(Dir, name)
+	b, err := fs.ReadFile(os.DirFS(Dir), name)
+	if errors.Is(err, fs.ErrNotExist) {
+		return "", fmt.Errorf("%w: %s", ErrNotMounted, path)
+	}
+	if err != nil {
+		return "", fmt.Errorf("secretfile: %w", err)
+	}
+	v := strings.TrimRight(string(b), "\r\n")
