# CLD-125 — Check CLD-G07 reads the provider packs in the region the API runs in

## In plain words

**The problem today.** The live check of the providers list asks the platform API in every region which provider packs its image carries. The second region of a Sovereign has no platform API while its platform release is suspended, which is by design, so the check fails there in every gate run before it looks at the list.

**What changes.** The check asks the platform API only in the region where the API runs, as the compliance check already does. It still reads the installation documents in every region and still fails when the regions carry different ones.

**Done means:**

- A Sovereign whose second region has no platform API passes the providers check when the list is right.
- A Sovereign whose first region has no platform API still fails the check, with the reason of that region.
- Two regions that carry different installation documents still fail the check, with both lists in the message.
- Every case the check judged before keeps its verdict.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Gate check CLD-G07 (`tests/acceptance/sovereign/internal/suite/check_providers.go`) compares the answer of `GET /api/v1/providers?include=all` with the packs that the image of `catalyst-system/catalyst-api` carries and the installation ConfigMaps of the cluster. Today it runs `kubectl exec deploy/catalyst-api` in every region, and the second region of a Sovereign has no `catalyst-api` while its platform release is suspended by design, so the check fails there with `deployments.apps "catalyst-api" not found` before it judges the list. After the change it reads the packs only in the first region, the region the API runs in, as CMP-G02 does; it still reads the installation ConfigMaps in every region and fails when they differ. A unit case with a second region that has no API fails on the code of `origin/main` and passes with the change.

## 3. The model (the law)
1. The packs are read with `kubectl exec deploy/catalyst-api` in `cc.Regions[0]` only. No other region is asked for the packs.
2. The installation ConfigMaps (label `catalyst.openova.io/cloud-installation=true` in `catalyst-system`) are read in every region of `cc.Regions`, and every region must give the same sorted list; a difference fails the step with both lists and both region ids.
3. The expected list is the packs of the first region plus the installation ids, sorted, and the route must list exactly it; the evidence keeps the key `expected` and adds `packs_read_in` with the region id.
4. A first region without `catalyst-api` still fails the check, with that region's own reason.
5. Every case of `TestProvidersCheck` that existed keeps its verdict; the message of the case `regions disagree` now names the installation documents.
6. The function `expected` is replaced by two functions, `packs` and `installations`; nothing outside `check_providers.go` calls it. No other file changes.
