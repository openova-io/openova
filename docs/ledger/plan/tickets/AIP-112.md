# AIP-112 — Streamed responses are metered

## In plain words

**The problem today.** The model meter passes a streamed answer through but publishes no usage event for it, so every streamed model call goes unmetered and unbilled. It does not ask the back end for the usage numbers of a stream, and it sets no limit on the size of a request body.

**What changes.** The meter asks the back end for the usage numbers of every stream, reads them from the last chunk while the answer passes through unbuffered, and publishes one usage event. A stream cut off before its end is recorded as aborted and is not metered, and a request body above 16 MiB is refused.

**Done means:**

- A streamed answer that ends normally produces exactly one usage event with the token counts of its final usage chunk.
- The caller receives each chunk as soon as the back end sends it, not when the answer is complete.
- The usage chunk reaches the caller only when the caller asked for it.
- A stream that the caller or the back end cuts off before its end produces no usage event and is recorded with the status aborted.
- A chat request body larger than 16 MiB is refused with status 413 and is not forwarded.
- The meter's tests, run with the race detector, pass on the pull request.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The model meter (`core/services/model-meter`, package `meter`) meters streamed answers. For `POST /v1/chat/completions` with `"stream": true` it forwards the request with `stream_options.include_usage` set to `true`, so the back end always sends its usage chunk. It writes the answer through as it arrives and flushes after every write. A stream parser reads the `data:` lines as they pass, keeps the last usage object and counts the tool calls. When the caller had not asked for usage, the usage-only chunk is not written to the caller. When the stream ends with `data: [DONE]`, the meter publishes exactly one usage event with the measures of that usage object, the same event an unstreamed answer gives. A stream that either side cuts off before `data: [DONE]` gets the ring status `aborted` and no event. A request body of `POST /v1/chat/completions` above 16 MiB gets 413 and is not forwarded. The change is the four files of the block `AIP-112.patch`; nothing else changes.

## 3. The model (the law)
1. The stream format is the one of `docs/contracts/model-contract.md` section 1.4: `data: <chunk JSON>` lines, each event ended by a blank line; a usage chunk with an empty `choices` list and a `usage` object; then `data: [DONE]`. Only this format is parsed. The meter does not parse any other stream format: the model gateway converts other formats before the meter.
2. Request rewrite. For `POST /v1/chat/completions` the meter reads the body before it forwards it. When the body is a JSON object with `"stream": true` and `stream_options.include_usage` is not `true`, the forwarded body has `stream_options.include_usage: true` (other keys of `stream_options` kept, `<`, `>` and `&` not escaped) and the usage chunk is held back from the caller. When the caller set `include_usage: true`, the body is forwarded unchanged and the usage chunk reaches the caller. Any other body is forwarded unchanged.
3. Request limit. A body of `POST /v1/chat/completions` larger than 16 MiB (`MaxRequestBytes = 16 << 20`), whether its length is declared or not, gets HTTP 413 with the error code `request_too_large`, is not forwarded, publishes no event and has the ring status `rejected`. A body that cannot be read gets 400 `invalid_request`. The body of any other route is not read. The checks for path, host and identity headers come first, unchanged.
4. Pass-through. The proxy flushes after every write (`FlushInterval: -1`). The parser forwards each line as soon as its line end arrives; it holds at most the one line that has not ended. A line longer than 8 MiB is forwarded as it arrives and is not read. The meter never buffers a streamed body. A streamed answer has no `Content-Length`.
5. Usage. The usage of a stream is the last `usage` object seen in any chunk. A tool call is counted once, at the delta that carries its `id`. The model is the last non-empty `model` of a chunk.
6. Outcome. Status `error` when the back end failed or answered outside 2xx; `aborted` when a 2xx stream ended, on either side, before `data: [DONE]` (also when the server aborts the handler because the copy broke off); `ok` otherwise. Exactly one usage event when the status is `ok` and a usage object was read, streamed or not; none otherwise. Every request still gives one log line and one ring entry.
7. Go surface added to package `meter`: `type StreamParser interface { Write(p []byte) (forward []byte); Close() (forward []byte, u Usage) }`, `func NewStreamParser(dropUsageChunk bool) StreamParser` and `const MaxRequestBytes = 16 << 20`.
8. Deleted: the test `TestStreamedResponseGivesNoEventYet` of `meter/meter_test.go`, which asserted that a stream publishes no event.

+// A stream is "data: <chunk>" events ended by blank lines, then "data: [DONE]"; the usage
+// chunk before it has empty "choices" (docs/contracts/model-contract.md, section 1.4).
+
+// MaxRequestBytes is the largest body of POST /v1/chat/completions; a larger one gets 413.
+const MaxRequestBytes = 16 << 20
+
+// maxStreamLine is the longest line the parser holds to read; a longer one is forwarded unread.
+const maxStreamLine = MaxBodyBytes
+
+// StreamParser consumes server-sent-event bytes as they pass and reports usage at the end.
+type StreamParser interface {
+	// Write returns the bytes to forward to the caller. It may hold back the final usage-only chunk.
+	Write(p []byte) (forward []byte)
+	// Close returns the bytes still held and the usage seen.
+	Close() (forward []byte, u Usage)
+}
+
+// NewStreamParser returns a parser. dropUsageChunk is true when the caller did not ask for usage.
+func NewStreamParser(dropUsageChunk bool) StreamParser { return &sseParser{drop: dropUsageChunk} }
+
+// sseParser forwards each line when the line has ended, reads the "data:" lines, keeps the last
+// usage object, counts the starts of tool calls and notes "data: [DONE]".
+type sseParser struct {
+	drop     bool   // hold back the usage-only chunk
+	line     []byte // the line that has not ended yet
+	long     bool   // that line is too long to read and is forwarded as it arrives
+	skipping bool   // a usage-only chunk was held back: hold back the rest of its event
+	done     bool   // "data: [DONE]" was seen
+	usage    Usage
+}
+
+// Write implements StreamParser.
+func (s *sseParser) Write(p []byte) []byte {
+	var out []byte
+	for len(p) > 0 {
+		i := bytes.IndexByte(p, '\n')
+		if i < 0 {
+			if s.long {
+				return append(out, p...)
+			}
+			if s.line = append(s.line, p...); len(s.line) > maxStreamLine {
+				out, s.line, s.long = append(out, s.line...), nil, true
+			}
+			return out
+		}
+		piece := p[:i+1]
+		p = p[i+1:]
+		if s.long {
+			out, s.long = append(out, piece...), false
+			continue
+		}
+		s.line = append(s.line, piece...)
+		out = append(out, s.take()...)
+	}
+	return out
+}
+
+// Close implements StreamParser. A last line without its end is read like any other line.
+func (s *sseParser) Close() ([]byte, Usage) { return s.take(), s.usage }
+
+// take reads the held line and returns what to forward for it: the line, or nothing when the
+// line belongs to a usage-only chunk that is held back.
+func (s *sseParser) take() []byte {
+	line := s.line
+	s.line = nil
+	text := bytes.TrimRight(line, "\r\n")
+	switch {
+	case len(text) == 0: // a blank line ends an event, the held-back one too
+		if s.skipping {
+			s.skipping = false
+			return nil
+		}
+		return line
+	case s.skipping:
+		return nil
+	}
+	data, ok := bytes.CutPrefix(text, []byte("data:"))
+	if !ok {
+		return line
+	}
+	if data = bytes.TrimSpace(data); string(data) == "[DONE]" {
+		s.done = true
+	} else if s.read(data) && s.drop {
+		s.skipping = true
+		return nil
+	}
+	return line
+}

+// meteredBody is a streamed body as the proxy copies it to the caller: the back end's bytes
+// passed through the parser, and at the end the bytes the parser still holds.
+type meteredBody struct {
+	rc       io.ReadCloser
+	p        *sseParser
+	buf, out []byte
+	err      error
+}
+
+// Read implements io.Reader.
+func (m *meteredBody) Read(b []byte) (int, error) {
+	for len(m.out) == 0 {
+		if m.err != nil {
+			return 0, m.err
+		}
+		n, err := m.rc.Read(m.buf)
+		m.out = append(m.out, m.p.Write(m.buf[:n])...)
+		if errors.Is(err, io.EOF) {
+			rest, _ := m.p.Close()
+			m.out = append(m.out, rest...)
+		}
+		m.err = err
+	}
+	n := copy(b, m.out)
+	m.out = m.out[n:]
+	return n, nil
+}

+// Close implements io.Closer.
+func (m *meteredBody) Close() error { return m.rc.Close() }

+// withStreamUsage returns the body to forward for POST /v1/chat/completions, and whether the
+// usage chunk of the stream is held back from the caller. A request with "stream": true is
+// forwarded with "stream_options.include_usage": true; the chunk is held back when the caller
+// had not set it. Any other body is forwarded unchanged.
+func withStreamUsage(body []byte) ([]byte, bool) {
+	var doc map[string]json.RawMessage
+	var stream, asked bool
+	if json.Unmarshal(body, &doc) != nil || json.Unmarshal(doc["stream"], &stream) != nil || !stream {
+		return body, true
+	}
+	opts := map[string]json.RawMessage{}
+	if raw := doc["stream_options"]; raw != nil && json.Unmarshal(raw, &opts) != nil {
+		return body, true
+	}
+	if opts == nil {
+		opts = map[string]json.RawMessage{}
+	}
+	if json.Unmarshal(opts["include_usage"], &asked) == nil && asked {
+		return body, false
+	}
+	opts["include_usage"] = json.RawMessage("true")
+	raw, err := marshalNoEscape(opts)
+	if err != nil {
+		return body, true
+	}
+	doc["stream_options"] = raw
+	if out, err := marshalNoEscape(doc); err == nil {
+		return out, true
+	}
+	return body, true
+}
+
+// marshalNoEscape encodes v without escaping <, > and &, so the caller's text reaches the back
+// end as it was written.
+func marshalNoEscape(v any) ([]byte, error) {
+	var b bytes.Buffer
+	enc := json.NewEncoder(&b)
+	enc.SetEscapeHTML(false)
+	err := enc.Encode(v)
+	return bytes.TrimRight(b.Bytes(), "\n"), err
+}
