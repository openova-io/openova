# FND-151 — The suite as an image, with the `self` selection

## In plain words

**The problem today.** The acceptance suite runs only from outside a Sovereign, with a console session and a kubeconfig for each region. A Sovereign therefore cannot check itself after an install or a release, and the gate tool refuses the record of any run inside a cluster.

**What changes.** The suite gains the place self. Started inside a Job, it reads its own cluster with the pod's ServiceAccount, waits until the releases have rolled, runs the checks that list self and writes one ClusterPolicyReport. The gate tool accepts the record of such a run.

**Done means:**

- The suite started with --run-in self needs no console session and no kubeconfig, and calls kubectl without a kubeconfig argument.
- Before its checks, a run in self waits until every HelmRelease runs the chart version that its own spec names, and records that wait as a step.
- A run in self writes one ClusterPolicyReport with one result per selected check: pass, fail, warn or skip.
- In a run in self a failed check does not make the program fail; it exits with an error only when the run could not run.
- The gate tool accepts the record of a run in self only with the digest of the suite image and an empty candidate, and refuses it otherwise.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket the acceptance suite `tests/acceptance/sovereign` has a third place to run in, `self`: a Job inside a Sovereign. `sovereign-acceptance run --run-in self --env <label> --region-a <region> --manifest <gates.json> --suite-image-digest sha256:<64 hex>` needs no console session and no kubeconfig. It skips the discovery and the journeys, calls `kubectl` without `--kubeconfig` so that `kubectl` uses the ServiceAccount of its pod, waits (step D0.12, at most `--wait-for-release` minutes) until every HelmRelease runs the chart version that its own spec names, runs every check whose manifest entry lists `self` and is not destructive, and writes one `ClusterPolicyReport` (API version `wgpolicyk8s.io/v1alpha2`, name `--report-name`, default `conformance`) with one result per check. With `--record` it also writes its record, and `python3 scripts/acceptance-gate.py validate-record` accepts that record. A person sees this in the test `TestExecuteSelf` of `tests/acceptance/sovereign/internal/suite/report_test.go`, which runs the whole path against a stand-in `kubectl`, and in the record it writes. The image of the suite, its build workflow and the run of a Job on the local provider pack are later work packages of the epic FND-150.

## 3. The model (the law)
1. **The place `self`.** `--run-in` takes `local`, `cloud` or `self`; any other value exits 2, as today. `RunInSelf` (`self`) already exists in `internal/suite/registry.go`, and `SelectChecks` already leaves out a destructive check in `self`.
2. **A run in self has no outside inputs.** `Execute` sends a run in self to `executeSelf` (in `internal/suite/runner.go`) before it asks for `CATALYST_SESSION` and the two kubeconfigs. `executeSelf` refuses, with an error and exit code 3 and before it reads a cluster: a `discover` run; a `--suite-image-digest` that is not `sha256:` and 64 lower-case hexadecimal characters; an empty `--region-a`; an empty `--manifest`; an empty `--report-name`; a negative `--wait-for-release`. A manifest that cannot be read, or a selected entry without a registered check, exits 2 with no record, as in every place.
3. **One region, no kubeconfig.** The run has one region, `kube.Region{ID: <--region-a>}`, with an empty `Kubeconfig`. `kube.Region` (its function `once`, which every call of `Run` goes through) passes `--kubeconfig <path>` only when `Kubeconfig` is not empty; with an empty one `kubectl` uses the ServiceAccount of its pod. Every other caller sets a kubeconfig and is unchanged.
4. **Step D0.12.** Before the checks, the run records the step `D0.12` of the journey `D0`, "every HelmRelease runs the chart version its spec names". It reads `helmreleases.helm.toolkit.fluxcd.io` in every namespace every 15 seconds, for at most `--wait-for-release` minutes (default 30; 0 reads once). A HelmRelease with `spec.suspend: true`, or whose `spec.chart.spec.version` is empty, is not compared; every other one must have, as the newest `deployed` entry of `status.history`, that chart version. The step fails when the time runs out, when no HelmRelease is found, or when the list cannot be read. A failed D0 step makes the record `FAIL`. The checks run after the step in every case. A run in self has no discovery, so no check is skipped for a failed discovery; a check whose `needs` the run did not declare with `--capabilities` is skipped, as in every place.
5. **The record of a run in self.** `run_in` is `self`; `candidate` is `{"id": "", "commit": ""}` (a run in self has no checkout); the new field `suite_image_digest` holds the value of `--suite-image-digest`; `suite_git_sha` is the value of the variable `SUITE_GIT_SHA` when it is set, else `GITHUB_SHA`, else `git rev-parse HEAD`, as before. The producer is `{"kind": "job", "job": {"namespace", "name", "uid"}}` when the variables `ACCEPT_JOB_NAMESPACE`, `ACCEPT_JOB_NAME` and `ACCEPT_JOB_UID` are all set, and `{"kind": "manual"}` otherwise. `journeys` is empty. No other field changes.
6. **The report.** After the checks, the run applies one object with `kubectl apply -f -`: `apiVersion: wgpolicyk8s.io/v1alpha2` (the constant `ReportAPIVersion` of `internal/suite/report.go`, the one place a later move of the compliance pipeline to another group changes), `kind: ClusterPolicyReport`, `metadata.name` the value of `--report-name`, the labels `app.kubernetes.io/managed-by: catalyst-conformance` and `catalyst.openova.io/run-id: <run id>`, a `summary` with the counts `pass`, `fail`, `warn`, `error` and `skip`, and one entry of `results` per selected check in manifest order: `source: catalyst-conformance`, `policy` and `rule` the check identifier, `result` `pass` (PASS), `fail` (FAIL of a required check), `warn` (FAIL of an expected-fail check) or `skip` (SKIP), `severity` `high` for a required check and `low` otherwise, `message` the reason (at most 1000 characters) or `every step passed`, `timestamp` the end of the run in seconds, and `properties.state` the state of the check at the run.
7. **Exit codes in self.** The program exits 0 when the report was applied, also when the record is `FAIL`: a failed check is in the report, so the Job that runs the suite never fails because of a check. It exits 2 on a manifest error and 3 when the run could not run or the report could not be written. The function `exitCode` of `main.go` decides this. In `local` and `cloud` the exit codes are unchanged (1 on a `FAIL` record, 4 on a run that could not reach the Sovereign).
8. **The gate tool.** In `scripts/acceptance-gate.py` the record schema accepts `run_in: self`, the optional string `suite_image_digest`, the producer kind `job` and the optional object `producer.job` (`namespace`, `name`, `uid`, all strings). `validate-record` adds these rules, each with a self-test case that shows it can fail: a run in self has an empty `candidate.id` and `candidate.commit` and a `suite_image_digest` of the form of law 2; any other run has a `candidate.commit` of 40 hexadecimal characters and no `suite_image_digest`; a producer of kind `job` belongs to a run in self and names its Job with three values that are not empty; only a producer of kind `job` has `job`. A record of a run in self never counts for a verdict: the verdict already counts only records of `cloud` runs by a workflow.
9. **New flags.** `--suite-image-digest` (`ACCEPT_SUITE_IMAGE_DIGEST`, default empty), `--wait-for-release` (`ACCEPT_WAIT_FOR_RELEASE`, minutes, default 30), `--report-name` (`ACCEPT_REPORT_NAME`, default `conformance`). Each is read only by a run in self. The README of the suite lists them and describes a run in self.
10. **Standard library only.** The module gets no dependency and no Kubernetes client library: every read and the report write go through `kubectl`. No ServiceAccount, role or Job is created by this ticket.

func selfProducer(getenv func(string) string) Producer {
	job := ProducerJob{Namespace: getenv("ACCEPT_JOB_NAMESPACE"), Name: getenv("ACCEPT_JOB_NAME"), UID: getenv("ACCEPT_JOB_UID")}
	if job.Namespace == "" || job.Name == "" || job.UID == "" {
		return Producer{Kind: "manual"}

	return Producer{Kind: "job", Job: &job}
}

// releasesBehind compares the deployed chart version of each HelmRelease with
// the version its spec names; a suspended one, or one whose spec names none, is
// not compared. It returns the number compared and, sorted, those behind.
func releasesBehind(releases []kube.Object) (int, []string) {
	compared, behind := 0, []string{}
	for _, hr := range releases {
		want := hr.Str("spec", "chart", "spec", "version")
		if suspend, _ := hr.Get("spec", "suspend").(bool); suspend || want == "" {
			continue
		}
		compared++
		if got := deployedChartVersion(hr); got != want {
			behind = append(behind, hr.Namespace()+"/"+hr.Name()+" runs "+nonEmpty(got, "no deployed version")+" and its spec names "+want)
		}
	}
	sort.Strings(behind)
	return compared, behind
}

// waitForReleases is step D0.12 of a run in self: it reads the HelmReleases
// until none is behind, for at most timeout (0: once). It fails when the time
// runs out, when none is found or when they cannot be read.
func (r *runner) waitForReleases(ctx context.Context, region kube.Region, timeout time.Duration) {
	r.step("D0", "D0.12", "every HelmRelease runs the chart version its spec names", func(ev Evidence) error {
		start := time.Now()
		releases, compared, behind := 0, 0, []string{}
		_, err := poll(ctx, timeout, releaseWaitInterval, func() (bool, string, error) {
			list, err := region.GetList(ctx, hrResource, "")
			if err != nil {
				return false, "", err
			}
			releases = len(list)
			compared, behind = releasesBehind(list)
			if releases == 0 {
				return false, "no HelmRelease was found", nil
			}
			if len(behind) > 0 {
				return false, fmt.Sprintf("%d of %d HelmReleases do not run their version: %s", len(behind), compared, strings.Join(behind, "; ")), nil
			}
			return true, "", nil
		})
		ev["releases"], ev["compared"], ev["behind"] = releases, compared, behind
		ev["waited_seconds"] = int(time.Since(start).Seconds())
		return err
	})
}

// BuildReport is the report of a finished run in self, one result per check:
// pass, fail (a required check failed), warn (an expected-fail check failed)
// or skip, with the severity high for a required check and low otherwise.
func BuildReport(name string, run *Run) map[string]any {
	labels := map[string]any{"app.kubernetes.io/managed-by": ReportSource, reportRunIDLabel: run.RunID}
	summary := map[string]any{"pass": 0, "fail": 0, "warn": 0, "error": 0, "skip": 0}
	results := []any{}
	for _, c := range run.Checks {
		result, severity, message := "pass", "low", "every step passed"
		if c.StateAtRun == StateRequired {
			severity = "high"
		}
		switch c.Status {
		case Fail:
			result, message = "warn", trunc(c.Reason, 1000)
			if c.StateAtRun == StateRequired {
				result = "fail"
			}
		case Skip:
			result, message = "skip", trunc(c.Reason, 1000)
		}
		summary[result] = summary[result].(int) + 1
		results = append(results, map[string]any{
			"source": ReportSource, "policy": c.ID, "rule": c.ID, "result": result, "severity": severity,
			"message": message, "timestamp": map[string]any{"seconds": run.FinishedAt.Unix(), "nanos": 0},
			"properties": map[string]any{"state": c.StateAtRun},
		})
	}
	return map[string]any{
		"apiVersion": ReportAPIVersion,
		"kind":       "ClusterPolicyReport",
		"metadata":   map[string]any{"name": name, "labels": labels},
		"summary":    summary,
		"results":    results,
	}
}

// applyReport writes the report into the region with `kubectl apply -f -`.
func applyReport(ctx context.Context, region kube.Region, report map[string]any) error {
	b, err := json.Marshal(report)
	if err != nil {
		return err
	}
	_, err = region.Run(ctx, bytes.NewReader(b), "apply", "-f", "-")
	return err
}
