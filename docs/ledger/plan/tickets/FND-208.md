# FND-208 — The size check of a pull request measures a chart that has dependencies

## In plain words

**The problem today.** Before a merge, the size check of the Helm release Secret measures only the charts that have no dependencies. A chart with dependencies, the umbrella chart and the largest charts among them, is measured only by the release job after the merge, so a change that makes such a chart too large to install is found too late.

**What changes.** The size check of a pull request builds the dependencies of each chart and measures every chart. Two charts that cannot render without the values of a running Sovereign are named, each with its reason, in a list that may only shrink.

**Done means:**

- The size check of a pull request measures every chart, and a chart that declares dependencies is measured after those dependencies are built.
- A chart that is not on the list and cannot be measured, because its dependencies do not build or it does not package or render, turns the check red.
- The list names two charts, the knative chart and the librechat chart, each with the value it asks for, its reason and the day 27 November 2026.
- A chart added to the list turns the check red, and so does a listed chart that renders again until it is taken off the list.
- The Python checker has as many lines as before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The check `check-helm-release-payload-size / guard` of a pull request measures the Helm release Secret of every chart of `platform/` and `products/` at its default values, including every chart that declares `dependencies:` (the umbrella `products/catalyst/chart` among them), after `helm dependency update`; before this change those charts were deferred to the release job, which measures them only after the merge. Two charts cannot render at their default values, `platform/knative/chart` and `platform/librechat/chart`: they are named in the new list `scripts/baselines/payload-sweep.json`, each with the value it asks for, its reason and the day 2026-11-27. The new Go command `tools/guards/cmd/payload-sweep` runs the check without them and fails when a chart not on the list cannot be measured, when the list grows, and when a listed chart renders again and is still on the list.

## 3. The model (the law)
1. **Every chart is measured.** `sweep()` of `scripts/check-helm-release-payload-size.py` (the `--all` mode) no longer defers a chart that declares `dependencies:`. For such a chart it runs `helm dependency update <chart>` first and then measures it as any other chart. A failed update is recorded as a chart that could not be measured (`::error title=Chart could not be measured::`), and the sweep exits 1: never a pass. The summary line reads `measured <n> chart(s); <k> of them after a dependency update; ...`. One chart given by path (the call of `.github/workflows/blueprint-release.yaml`, after its own `helm dependency build`) is measured as given, as before.
2. **The list.** `scripts/baselines/payload-sweep.json` holds the key `charts`, a list of entries with the fields `chart`, `value`, `reason` and `since`. It names exactly `platform/knative/chart` (value `knativeOverlay.knativeServing.sovereignFqdn`) and `platform/librechat/chart` (value `ingress.host`), each dated `2026-11-27`. Both charts carry the annotation `catalyst.openova.io/smoke-render-mode: "requires-overlay"` and the release's smoke render skips them too.
3. **The command.** `cd tools/guards && go run ./cmd/payload-sweep --base <commit>` copies the files Git lists under `platform/` and `products/` into a temporary folder, takes the listed charts out of the copy, and runs the checker's `--all` on the copy. It exits 1, one `FAIL` line per finding, when an entry lacks its chart, value or reason, is not a chart folder of the sweep, names a chart twice or carries another day than 2026-11-27; when an entry is not on the list at the base commit (the list only shrinks; a base without the file holds nothing against it); when a listed chart renders at its defaults, fails without asking for the value its entry names (`<value> is required`), or is not in the tree; and when the checker fails on the copy (a chart over the budget, or one that cannot be measured). It exits 2 when it cannot run (no list, a list without the key `charts`, an unreadable base, no helm or python3).
4. **The workflow.** `.github/workflows/check-helm-release-payload-size.yaml` checks out two commits (`fetch-depth: 2`), sets up the Go of `tools/guards/go.mod`, runs the checker's `--self-test`, then `go test -count=1 ./cmd/payload-sweep`, then `go run ./cmd/payload-sweep --base HEAD^1`; its path filters also name the list and the command; its timeout is 30 minutes. The direct step `python3 scripts/check-helm-release-payload-size.py --all .` is removed: with the two listed charts in the tree it exits 1.
5. **No new Python.** The checker keeps its 454 lines; the list and the rules about it are Go and JSON. No chart changes; no gate check flips; nothing is written to a cluster.

+	}

+	return 0
