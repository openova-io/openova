# INF-060 — Remove the reboot settings from cloud-init

## In plain words

**The problem today.** First boot of every control plane, and of every Hetzner worker, still switches the unattended-upgrade service on with a command of its own. The package already does that when it is installed, and the reboot chart now owns the upgrade configuration on every node, so the command only spends bytes of a first-boot text that is close to its size limit. Nothing stops the command from coming back.

**What changes.** First boot installs the package and leaves the service to it, as the Huawei workers already do. The render test also fails when the command returns or when the package is no longer installed.

**Done means:**

- The shared control-plane template and the Hetzner worker template hold no command that enables the unattended-upgrade service.
- Every node template still installs the package unattended-upgrades.
- The render test of the shared template fails when a render enables the service or no longer installs the package.
- The stored golden render values match the changed render; every stored file hash is unchanged.
- The worst-case control-plane user data is 55 bytes smaller on each Huawei surface and 67 bytes smaller on each Hetzner surface.

The rest of this ticket is the exact instruction for the model that does the work.
