# SEC-120 — etcd dump check and node hygiene check, as check files

## In plain words

**The problem today.** Nothing tests what a person who reads the disk of a control-plane node would find. The etcd database stores every Secret in the clear today, the kubeconfig on the node can be read by every user, and the files that carried the bootstrap secrets stay on the node after they were applied. No acceptance run would notice if a fix for any of this were undone.

**What changes.** The acceptance suite gains two checks. In every region they start a short-lived reader on each control-plane node: one looks for a fresh test secret in the etcd files and wants to find it only encrypted, the other looks at the k3s token, the kubeconfig and the bootstrap files. The list of checks marks both as expected to fail, so they run and are recorded and cannot fail a run yet.

**Done means:**

- The first check fails when the value of the test secret is readable in the etcd database or its log on any control-plane node, or when it is stored with an encryption other than secretbox.
- The first check also fails when it cannot find the test secret in the files at all, so a check that read the wrong files never passes.
- The second check fails when the k3s token has the form of a token computed from identifiers, when the kubeconfig on the node is not readable by its owner only, or when a bootstrap secret file remains.
- Both checks leave nothing behind: their namespace is deleted also when a step failed.
- The list of checks marks both as expected to fail, so a failure does not fail a run.
- The tests of both checks run on every pull request and need no cluster.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite under `tests/acceptance/sovereign/` has two more gate checks. SEC-G01 (etcd at rest) creates a canary Secret with a random value in every region and reads, on every control-plane node, the etcd database file and the write-ahead log files. It passes only when the canary's value is in none of them in the clear and every record of the canary in the database is `secretbox` ciphertext. SEC-G02 (node hygiene) reads, on every control-plane node, the k3s token file, the mode of the kubeconfig and the folder of the bootstrap files. Both read the node through a short-lived probe Pod that mounts the node's files read-only, and both delete everything they created. Each check is one file `check_sec_<name>.go` that registers itself. The gate manifest `docs/ledger/gates.yaml` names the two files and has both entries in state `expected-fail`: a run that is given the manifest runs them and records their results, and a failure does not fail the run. The tests of both checks run on every pull request without a cluster. The README of the suite and the package comment of `internal/kube` say which checks write to a cluster.

1. The six files of the suite that this ticket changes are the result of the embedded patch `SEC-120.patch` and of nothing else. The patch creates four files; work step 5 states the checksum of each. It changes lines of two files, the README of the suite and `kube.go`; work step 6 states how many lines it adds and removes in each. `docs/ledger/gates.yaml` is changed by the two commands of work steps 7 and 8 and by nothing else: four lines are added and two are removed.
2. A gate check of the suite is one file in `tests/acceptance/sovereign/internal/suite/` that calls `RegisterCheck` in `init()` and holds the identifier of the check as a string constant. The two files are `check_sec_etcd.go` (SEC-G01) and `check_sec_node.go` (SEC-G02). The probe that both use is in `sec_probe.go`. The tests of all three are in `check_sec_test.go`.
3. Both checks call `kubectl` through their field `kubectl`, of the type `kubectlFunc` (declared in `check_compliance_push.go`). The registered checks hold `kube.Region.Run` there; the tests put a function there.
4. The probe, per region, in this order:
   - Step 1, "a probe Pod is Ready on every control-plane node of region `<id>`": it lists the nodes with `kubectl get nodes -l node-role.kubernetes.io/control-plane=true -o jsonpath={.items[*].metadata.name}`. No such node fails the step, and no namespace is created. Otherwise it creates the namespace `<prefix>-<run>` with `kubectl create namespace`, where `<run>` is the result of `NewRunID` in lower case and `<prefix>` is `sec-etcd` (SEC-G01) or `sec-node` (SEC-G02). SEC-G01 then creates its canary (item 5). Then one Pod `probe-<n>` per node, `<n>` counted from 0, with `kubectl -n <namespace> create -f -` and the Pod as JSON on standard input. Then `kubectl -n <namespace> wait --for=condition=Ready pod --all --timeout=180s`.
   - The Pod: `nodeName` is the node; `restartPolicy: Never`; no service-account token and no service links; it tolerates every taint; one container `probe` with the image `harbor.openova.io/proxy-dockerhub/library/alpine:3.20`, a command that only keeps the container running for 900 seconds, user 0, no privilege escalation, a read-only root file system, every capability dropped, the requests `cpu: 50m` and `memory: 32Mi` and the memory limit `128Mi`. It mounts the node's `/var/lib` at `/host/var/lib` and the node's `/etc/rancher/k3s` at `/host/etc/rancher/k3s`, both read-only, both of type `Directory`.
   - One step per node, only when step 1 passed: `kubectl -n <namespace> exec -i probe-<n> -c probe -- sh -s -- /host <mode> <arguments>`, with the probe script (item 7) on standard input. The check judges what the script printed (items 6 and 8).
   - A last step, whenever the namespace was created, also when a step before it failed: `kubectl delete namespace <namespace> --wait=false --ignore-not-found`, with a time limit of one minute of its own that does not end when the run is cancelled.
5. The canary of SEC-G01: the Secret `etcd-canary` in the namespace of the probe, created with `kubectl -n <namespace> create -f -` from JSON with `stringData: {"canary": "<value>"}`. The value is `CANARY-` and 40 hexadecimal characters from `crypto/rand`. Its etcd key is `/registry/secrets/<namespace>/etcd-canary`. The script gets the key and the value as its two arguments after the mode `etcd`. The check looks for this one value and not for the value of every Secret: many Secret values (a CA certificate, a host name) are also stored in the clear in objects that are not Secrets, so a search for every value could never pass.
6. SEC-G01 judges the step of a node in this order; the first rule that holds fails it:
   - the script printed `db=unreadable`: the etcd file `/var/lib/rancher/k3s/server/db/etcd/member/snap/db` cannot be read;
   - a number is missing;
   - `db_key` is 0: no record of the database holds the key, so nothing was measured;
   - `wal_key` is 0: no write-ahead log file (`.../member/wal/*.wal`) holds the key, so nothing was measured;
   - `db_canary` plus `wal_canary` is above 0: the value is in the clear;
   - `db_key_secretbox` differs from `db_key`: a record of the canary is not `secretbox` ciphertext.
7. The probe script reads and prints; it judges nothing and writes nothing. It sets `LC_ALL=C`. It reads a binary file as records: every NUL byte becomes a line end and every line end a space (`tr '\000\n' '\n '`). In a record of the etcd database the key, the two revisions, the version and the start of the value contain no NUL byte, so the key and the prefix `k8s:enc:secretbox:v1:` of an encrypted value are one line. A value stored in the clear starts with `k8s` and a NUL byte, so its line ends there. In mode `etcd` it prints `db_canary`, `db_key` and `db_key_secretbox` (lines of the database that hold the value, that hold the key, and that hold the key and the prefix), and `wal_files`, `wal_canary` and `wal_key` over every readable `.wal` file. In mode `node` it prints `token=<class>`, `kubeconfig_mode=<mode>`, one `bootstrap_file=<path>` per file found and `bootstrap_files=<count>`. The token class is `hex64` when the token (the part after `::server:` of `/var/lib/rancher/k3s/server/token`, or the whole file) is 64 lower-case hexadecimal characters, `empty`, `unreadable` or `other`. The token itself is never printed. The bootstrap files are `/var/lib/catalyst/*-secret.yaml` and `/var/lib/catalyst/flux-bootstrap.yaml`. The script runs alike in the image (BusyBox) and with `sh`, `tr`, `grep`, `cat` and `stat` of a CI runner.
8. SEC-G02 fails the step of a node when the token class is not `other`, when `kubeconfig_mode` is not `600` (`missing` when `/etc/rancher/k3s/k3s.yaml` does not exist), when a bootstrap file is found, or when the script did not print `bootstrap_files`. The error names every fault of the node.
9. Neither check sleeps or polls: the one wait is `kubectl wait`. The non-test Go files add no `time.Sleep`, `time.NewTicker` or `time.Tick`.
10. `docs/ledger/gates.yaml`: the entries SEC-G01 and SEC-G02 have `state: expected-fail` and an `implementation` line that names their file. No other line of the file changes.
11. The README of the suite says that the suite writes with `kubectl create`, `apply` and `delete` in gate checks CMP-G01, SEC-G01 and SEC-G02 only, describes the probe, and lists the two checks in its table of checks. The package comment of `internal/kube/kube.go` says the same; no code line of `kube.go` changes.
12. No other file of the suite changes. The module keeps using the Go standard library only. This ticket deletes no file.

+// probeValues holds the name=value words of the script, every value of a name in order.
+type probeValues map[string][]string

+func parseProbe(out []byte) probeValues {
+	v := probeValues{}
+	for _, word := range strings.Fields(string(out)) {
+		if name, value, found := strings.Cut(word, "="); found {
+			v[name] = append(v[name], value)
+		}
+	}
+	return v
+}
+
+// one returns the last value of name, or "" when the script printed none.
+func (v probeValues) one(name string) string {
+	if n := len(v[name]); n > 0 {
+		return v[name][n-1]
+	}
+	return ""
+}

+		return errors.New("the run has no region")

+			if err != nil {
+				return err
+			}
+			nodes = strings.Fields(string(out))
+			ev["namespace"], ev["nodes"] = ns, nodes
+			if len(nodes) == 0 {
+				return fmt.Errorf("region %s has no node with the label %s", region.ID, secControlPlane)
+			}
+			if _, err := p.kubectl(region, ctx, nil, "create", "namespace", ns); err != nil {
+				return err
+			}
+			created = true
+			if p.setup != nil {
+				if args, err = p.setup(ctx, region, ns); err != nil {
+					return err

+		}
