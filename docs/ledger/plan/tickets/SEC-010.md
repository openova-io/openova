# SEC-010 — Close the public route to OpenBao system paths

## In plain words

**The problem today.** The public address of OpenBao sends every path to OpenBao, the system paths included. From the internet anyone can reach root-token generation, unseal, seal, init, rekey, raw storage and the server configuration of a Sovereign's secret store. Root generation needs no token there, only the unseal key.

**What changes.** The route answers those system paths itself, with a redirect to the user interface, and never passes them to OpenBao. The rest of the OpenBao API and the sign-in stay as they are. A gate check asks each closed path from outside the cluster and becomes required.

**Done means:**

- The rendered OpenBao route holds two redirect rules with the 15 system path prefixes and no backend, with the bare-URL sign-in switched on and off, and its last rule still sends everything else to OpenBao.
- The render test of the route fails when one prefix is missing, when a redirect rule has a backend, when the redirect goes elsewhere, or when the rules sit inside the sign-in block.
- Gate check SEC-G04 asks each closed path four times from outside the cluster and passes only on a 302 to the user interface, and its control path still answers from OpenBao.
- Gate check SEC-G04 is required in the gate manifest, and its tests show that each of its rules can fail.
- The threat model of the security document and the README of the acceptance suite say what is true now.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A request from the internet to `https://bao.<sovereign FQDN>/v1/sys/generate-root/attempt`, or to any of the 15 OpenBao system path prefixes of field 3, gets a 302 to `https://bao.<sovereign FQDN>/ui/` from the Cilium gateway and never reaches OpenBao. Every other path of the OpenBao API and the bare-URL sign-in through Keycloak work as before. The HTTPRoute of the bp-openbao chart carries the two redirect rules, the render test of the chart proves them, and the gate check SEC-G04 (`tests/acceptance/sovereign/internal/suite/check_sec_route.go`) proves them from the machine that runs the acceptance suite. SEC-G04 is `required` in `docs/ledger/gates.yaml`.

## 3. The model (the law)
1. **The closed prefixes.** The public route answers these 15 path prefixes with a redirect and reaches no backend for them: `/v1/sys/generate-root`, `/v1/sys/generate-recovery-token`, `/v1/sys/unseal`, `/v1/sys/seal`, `/v1/sys/init`, `/v1/sys/rekey`, `/v1/sys/rekey-recovery-key`, `/v1/sys/step-down` (rule A), and `/v1/sys/raw`, `/v1/sys/storage`, `/v1/sys/rotate`, `/v1/sys/pprof`, `/v1/sys/audit`, `/v1/sys/config`, `/v1/sys/replication` (rule B). Each is a match of type `PathPrefix`. A Gateway API path prefix matches whole path segments, so `/v1/sys/seal` does not match `/v1/sys/seal-status`.
2. **The redirect.** Both rules have no `backendRefs` and one filter: `type: RequestRedirect` with `hostname` the value `gateway.host`, `port: 443`, `path` of type `ReplaceFullPath` with `replaceFullPath: "/ui/"`, and `statusCode: 302`. The path is the literal `"/ui/"`. The variable `$landingPath` is not used: it is defined only inside the block that tests `sso.bareURL`.
3. **Where the rules sit.** Both rules sit outside the `sso.bareURL` block and directly before the catch-all rule of `gateway.path`, which stays the last rule. So they render with the bare-URL sign-in on and off. The route has at most 16 rules (the Gateway API limit); with the sign-in on it has 7.
4. **The gate check SEC-G04.** It reads the name of the Sovereign from step D0.1 of the discovery and asks `https://bao.<FQDN>` with anonymous `GET` requests, four times per path, without following a redirect. Step SEC-G04.1 is the control: `/v1/sys/seal-status` answers 200 with a JSON body that holds the boolean `sealed`. Steps SEC-G04.2 to SEC-G04.17: each of the 15 prefixes and `/v1/sys/generate-root/attempt` answers 302 with the Location `https://bao.<FQDN>/ui/` (a written port 443 is accepted). Every other answer fails. The check uses `GET` on every path: when the route is open a `GET` changes nothing in OpenBao, while a `PUT` to `/v1/sys/generate-root/attempt` would start a root-token generation; the route matches paths and not methods. The check runs only in a cloud run (`runs_in: [cloud]`), like FND-G06, because the local pack has no publicly trusted certificate.
5. **The manifest.** The entry SEC-G04 moves from `state: not-built` to `state: required` and gains `implementation: tests/acceptance/sovereign/internal/suite/check_sec_route.go`. No other line of `docs/ledger/gates.yaml` changes. Its `title` and `asserts` stay: only a change with `Work-Package: PLAN` may set them.
6. **Nothing else of the route changes**: not the landing rule, not the three exact redirects of the sign-in, not the catch-all, not the parent reference. The in-cluster Service of OpenBao does not change. No allow-list of user-interface paths is added, and the route is not removed.

+// baoSamples asks baoRouteSamples times, keeps every sample in ev["samples"]

+		}
+	}

+// baoAnswer is what one request returned.

+	location   string

+// askBao makes one anonymous GET.
+func askBao(ctx context.Context, client *http.Client, target string) (baoAnswer, error) {
+	req, err := http.NewRequestWithContext(ctx, http.MethodGet, target, nil)
+	if err != nil {
+		return baoAnswer{}, err
+	}
+	res, err := client.Do(req)
+	if err != nil {
+		return baoAnswer{}, err
+	}
+	defer func() { _ = res.Body.Close() }()
+	body, err := io.ReadAll(io.LimitReader(res.Body, 1<<16))
+	if err != nil {
+		return baoAnswer{code: res.StatusCode}, err
+	}
+	var status map[string]any
+	sealed := false
+	if json.Unmarshal(body, &status) == nil {
+		_, sealed = status["sealed"].(bool)
+	}
+	return baoAnswer{code: res.StatusCode, location: res.Header.Get("Location"), sealStatus: sealed}, nil
+}

+func newBaoServer(t *testing.T, answers map[string][]baoAnswerSpec) *baoServer {
+	t.Helper()

+	b.srv = httptest.NewUnstartedServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
+		b.mu.Lock()
+		n := b.asked[r.URL.Path]
+		b.asked[r.URL.Path] = n + 1
+		specs := b.answers[r.URL.Path]
+		b.mu.Unlock()

+			a = specs[min(n, len(specs)-1)]
+		}
+		if a.location != "" {
+			w.Header().Set("Location", a.location)
+		}
+		w.WriteHeader(a.code)
+		_, _ = io.WriteString(w, a.body)
+	}))
+	b.srv.Config.ErrorLog = log.New(io.Discard, "", 0) // the refused handshakes of the untrusted case
+	b.srv.StartTLS()
+	t.Cleanup(b.srv.Close)
+	return b

+// transport dials the test server for every host. trusted: it trusts the

+	return &http.Transport{TLSClientConfig: cfg, DialContext: func(ctx context.Context, network, _ string) (net.Conn, error) {
+		return (&net.Dialer{}).DialContext(ctx, network, addr)
