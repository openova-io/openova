# INF-055 — Leave the kured slot out of the local reduced kit

## In plain words

**The problem today.** The local provider pack runs its machines as containers, which have no boot of their own, so kured has nothing to do there. The kured slot stays out of the pack's reduced kit today only because no release that the kit keeps depends on it. Nothing records that it must stay out, and a new dependency would pull it in without a warning.

**What changes.** The exclusion list of the reduced kit names kured, with the reason. The generated kit stays as it is, and its generator fails if a release that the kit keeps comes to depend on kured.

**Done means:**

- The exclusion list of the local reduced kit names bp-kured once, under a comment that gives the reason.
- The generated reduced kit is current and names no slot file 04b-bp-kured.yaml.
- When a release that the reduced kit keeps is made to depend on bp-kured, the generator fails and names both releases.
- The check conformance-local is green on the pull request.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. The exclusion list holds one HelmRelease name per line; blank lines and lines that start with `#` are skipped (the header of the file, and `excluded()` in `scripts/generators/local-kit.py`). The line this ticket adds is the release name `bp-kured`, not the slot file name `04b-bp-kured`: the generator resolves a release name to its slot file, and a name that no listed slot file defines as a release makes it exit 2.
2. The new entry is four lines at the end of the file: a line `#`, two comment lines that give the reason (a container node has no boot of its own, so kured has nothing to reboot there), and the line `bp-kured`. The reason is its own, so it does not stand under the comment of the five entries above it, which are left out for the CPU of the pack's machines.
3. No other line of the list changes, and no other file changes. The reduced kit does not change: no release that it keeps depends on `bp-kured`, so running the generator after the change writes the same file.
4. After the change, a release that the reduced kit keeps and that depends on `bp-kured` makes the generator exit 2 with the line `infra/providers/local/kit-exclude.txt: bp-kured is left out, but <release> depends on it`. Before the change, the same dependency silently adds slot 04b to the kit.
