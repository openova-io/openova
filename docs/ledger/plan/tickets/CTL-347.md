# CTL-347 — The flow server and adapter sources, charts and builds are deleted

## In plain words

**The problem today.** The flow canvas of the console is answered by the platform API from its own store, and no Sovereign installs the flow server or the flow emitter any more. Their sources, charts and image builds are still in the repository. They are still built, still seeded into the catalogue as Blueprints, still named in the cutover, the dependency updates and several baselines, so the retired path still looks alive and still costs build and review time.

**What changes.** The two sources, the two charts and their two build workflows are deleted and listed as deleted paths. Every line that still builds, installs, pins, grants or tests them goes with them, and the generated catalogue and component list are written again by their generators.

**Done means:**

- The folders of the flow server and flow adapter sources, the two flow charts and their two build workflows are gone, and the list of deleted paths names each of them, so a pull request that brings one back turns red.
- The flow core and flow canvas packages that the console imports are still there.
- The catalogue seed, the generated catalogue and the component list hold no flow server or flow emitter Blueprint.
- The platform API no longer gets a flow-server address, and the cutover no longer pivots a flow-server release.
- The polling, provider-leak and service-model guards pass with baselines that name nothing deleted.
- The ratchet of the hand-over machinery and the ratchet of written source addresses are lowered by what the deletion removes, so one more such line in the cutover chart turns a pull request red.

The rest of this ticket is the exact instruction for the model that does the work.
