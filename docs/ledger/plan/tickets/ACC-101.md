# ACC-101 — Delete the fabricated session surface in the API and the console

## In plain words

**The problem today.** The shell button of a pod first asks the server to create a session, and the server makes one up: an identifier and an address of a remote-desktop gateway that nothing serves. Three pages list and replay sessions that were never recorded, and the panel says a recording exists. The shell itself closes right after it opens, because the panel closes its connection whenever its state changes.

**What changes.** The shell button opens the pod's shell connection directly and says that the shell is not recorded; the connection stays open until the panel closes or the user retries. The session list and replay pages, their addresses and their client code are gone from the console.

**Done means:**

- Clicking Open Shell opens the shell connection of the pod directly and sends no request to create a session.
- Once the shell is connected it stays connected, and it closes when the panel closes.
- A connection that cannot be made, or that fails, shows an error, and Retry connects again.
- The console has no session list or session replay page, and none of its addresses leads to one.
- No text of the shell panel says that the shell is recorded.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The pod shell of the sovereign-admin console (the Exec tab of a pod, `ExecPanel`) opens the exec WebSocket `GET /api/v1/sovereigns/{id}/k8s/exec/{ns}/{pod}/{container}?command=/bin/sh` itself, through `execWebSocketURL` of `resource.api.ts`, and mounts the terminal on it. It no longer calls `POST /api/v1/sovereigns/{id}/k8s/exec/{ns}/{pod}/{container}/session`, which answers with a made-up session identifier and a gateway address. The connection stays open once it is open. The console has no session list or replay page: the three files of `products/catalyst/bootstrap/ui/src/pages/sovereign/sessions/`, their four routes, the session client functions and the two browser cases that visited the pages are deleted. This is the console part of the story; the API part (handlers, store, route registrations, contract and baselines) is a further piece that comes after it (field 11).

## 3. The model (the law)
1. **One way to open a shell.** Open Shell and Retry each start one connection attempt. An attempt dials `execWebSocketURL(deploymentId, ns, pod, container)` with the WebSocket constructor (or the test seam `websocketFactory`). No HTTP request is sent before the dial.
2. **The socket lives as long as its attempt.** The effect that opens the socket depends on the attempt counter and the pod coordinates, never on the phase. A phase change (connecting, ready, error) does not close the socket. A new attempt or the unmount of the panel closes it.
3. **Phases.** `idle`, `connecting`, `ready`, `error`. `onopen` sets `ready`; `onerror` sets `error` with the text `WebSocket error`; a constructor that throws sets `error` with its message; no terminal container sets `error` and closes the socket. The panel root carries `data-phase`.
4. **No claim of a recording.** The idle text says the session is not recorded; the banner says `direct shell, not recorded`. No iframe, no session identifier, no `Recording: ON`.
5. **What is deleted.** `SessionsPage.tsx`, `SessionsPage.test.tsx`, `SessionsRoute.tsx`; the routes `/provision/$deploymentId/sessions`, `/console/sessions` (path `/sessions` under the console layout), `/app/$deploymentId/shells/sessions` and `/app/$deploymentId/shells/sessions/$sessionId`; from `resource.api.ts` the functions `createExecSession`, `listSessions`, `getSessionReplay` and the types `ExecSessionRequest`, `ExecSessionResponse`, `SessionListItem`, `SessionListResponse`, `SessionListFilter`, `SessionReplayResponse`; the ExecPanel props `createSession` and `iframeLoadTimeoutMs`; the two Playwright cases `SessionsPage renders the list shell` and `SessionsPage filter form is visible`.
6. **Records.** The folder `products/catalyst/bootstrap/ui/src/pages/sovereign/sessions` is added at the end of `docs/ledger/deleted-paths.txt`. The first line of `products/catalyst/bootstrap/ui/eslint-max-warnings.txt` (the allowed number of ESLint warnings) falls by one: the one warning of `SessionsPage.tsx` leaves with it.
