# FND-192 — Remove the second matcher from the console

## In plain words

**The problem today.** Trivy is the one vulnerability matcher of the platform, but the console still offers a second one, Syft with Grype. The provisioning wizard shows it as a card of the security family, the marketplace describes it, and three console tests use its job as their sample. The chart that runs it is removed later, and nothing in the console may point at it when that happens.

**What changes.** The wizard, the marketplace copy and the console tests no longer name the second matcher. The tests that used its job as a sample use the Trivy job, and the image build no longer checks for its logo.

**Done means:**

- The provisioning wizard shows no Syft and Grype card, and the security family lists eight components.
- The marketplace text of the security family names Trivy and Sigstore only, and the marketplace has no entry for the second matcher.
- The retry test and the two cron schedule tests use the Trivy job and pass with the rest of the console tests.
- The image build no longer asks the built console for the second matcher's logo.
- The service-model baseline counts one wizard entry less, so the count can not grow back.
