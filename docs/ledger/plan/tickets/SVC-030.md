# SVC-030 — The Catalog page honours visibility and refuses what has no chart

## In plain words

**The problem today.** The Catalog page of the sovereign-admin console shows every Blueprint it knows, including the infrastructure parts that are marked unlisted and are never meant to be picked. It also offers to create an instance of entries that have no published chart; such an install can only fail.

**What changes.** By default the Catalog page shows only the Blueprints marked listed, and a "Show unlisted" switch, kept in the page address, shows the rest. The class page of an entry without a published chart says so and disables its "+ New instance" buttons.

**Done means:**

- A person who opens the Catalog page sees only Blueprints marked listed.
- Turning on "Show unlisted" shows every Blueprint, as the page did before, and the page address then ends in ?unlisted=1.
- Opening the page with ?unlisted=1 in its address shows every Blueprint at once.
- On the class page of a Blueprint at version 0.0.0 both "+ New instance" buttons are disabled and the page says "Not installable: no published chart".
- The console's type check and unit tests pass on the pull request.

## 2. End goal
The Catalog page of the sovereign-admin console (`/catalog`, and `/provision/<id>/catalog` on the provision monitor) shows only Blueprints whose visibility is `listed`. A checkbox "Show unlisted" in the toolbar, off by default, shows every card as the page does today; it is kept in the page address as `?unlisted=1`, so a link can open the page with it on. The class page of a Blueprint (`/catalog/<blueprint>`) reads the version of the catalog entry. When the version is `0.0.0`, the entry has no published chart: both "+ New instance" buttons are disabled and the page shows the line "Not installable: no published chart" under the heading "Instances". A person sees the result in the console: fewer cards on the Catalog page, the checkbox, and the disabled button on the class page of an entry such as Ferretdb.

## 3. The model (the law)
1. With "Show unlisted" off, the Catalog page renders a card only when the card's visibility is exactly `listed`.
2. A card's visibility is decided in this order. First the live catalog item of the same Blueprint (`GET /api/v1/catalog`, field `visibility`), when that field is not empty. When the live list holds both a `bp-`-qualified item and a bare-name item of one Blueprint, the `bp-`-qualified item wins. Second, when no live item gives a value, the build-time catalog `BLUEPRINT_BY_ID[<card id>].visibility` of `src/shared/constants/catalog.generated.ts`. A card with neither has no visibility and counts as not listed.
3. "Show unlisted" is a checkbox in the toolbar of the Catalog page, labelled `Show unlisted`, with `data-testid="sov-catalog-show-unlisted"`. It is on exactly when the page address carries `unlisted=1`. Turning it on writes `unlisted=1` into the address; turning it off removes the parameter. Both replace the current history entry and keep every other parameter of the address.
4. With "Show unlisted" on, the page shows exactly the cards it shows today.
5. The search box filters the cards that the checkbox allows. Its placeholder counts those cards.
6. When no card is shown and "Show unlisted" is off, the empty state says: `Clear the search, or turn on Show unlisted, to see the full catalog.`
7. On the class page, a catalog entry whose `version` is exactly `0.0.0` cannot be installed. Both "+ New instance" buttons (`btn-new-instance` and `btn-new-instance-empty`) are disabled, and the line `Not installable: no published chart` (`data-testid="sov-instances-not-installable"`) is shown under the heading "Instances". The list of existing instances still renders. Every other version behaves as today.
8. The page filters on visibility only. It never filters on `card.category`. No route definition, no wizard file and no generated catalogue file changes.
9. The existing page tests of the Catalog page open the page with `?unlisted=1` and are otherwise unchanged. Nothing is deleted.
