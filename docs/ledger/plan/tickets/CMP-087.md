# CMP-087 — Gate check CMP-G06 after the move of the access policy

## In plain words

**The problem today.** Since the access policy moved into the policy chart, the only legacy policy object that should be left in a cluster is the image verifier, and every other policy should be of the new kind and ready. Nothing proves it on a Sovereign: the gate check that says so is listed but not built, so a leftover legacy policy, a policy that is not ready or an engine that judges nothing would pass the gate unseen.

**What changes.** The acceptance suite gains the check, and the gate requires it. The check reads every region on its own and only reads.

**Done means:**

- A region that still holds a legacy policy object other than the image verifier fails the check, and so does one whose image verifier does more than verify images.
- A policy of the new kind that is not ready, a region that serves no such policy or holds none, and an image verifier that is not ready each fail the check.
- A check of the compliance model whose every report result is an error fails the check, and so does a region where no check of the model has a result; a check without a result is listed, not failed.
- A legacy rule that the engine still counts, other than the image verifier's, fails the check, and so does an image verifier that the engine does not count.
- A fault in the second region fails the check as one in the first does: each region has its own four steps.
- The gate lists the check as required, with its implementation, and the suite's list of checks has its row.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite holds check CMP-G06 (`tests/acceptance/sovereign/internal/suite/check_policy_engine.go`), and `docs/ledger/gates.yaml` marks it `required` with that implementation. In every region of a run the check proves four things, each as a step of its own: no legacy policy object of `kyverno.io` exists but the image verifier `cosign-verified`, whose every rule only verifies images; every `ValidatingPolicy` and `MutatingPolicy`, of the cluster and of every namespace, is ready, and so is the image verifier; the checks of source `kyverno` of the region's ComplianceModel `default` have report results, and none has only error results; and the engine's legacy rule counter, read from the admission controller's metrics, names no policy but the image verifier. A run of two regions records eight steps, so a fault of the second region fails the check as one of the first. Since CMP-086 (merged) the access policy `useraccess-boundary` is a `ValidatingPolicy` of `platform/kyverno-policies/chart`, so a cluster that runs the kit's charts holds no other legacy object.

## 3. The model (the law)
1. **One check, four steps per region.** `policyEngineCheck.Run` loops over every region of `cc.Regions`, in order, and records four steps for each with `checkStep`, numbered on through the run: `CMP-G06.1` to `CMP-G06.4` for the first region, `CMP-G06.5` to `CMP-G06.8` for the second. Each step name ends in or holds `region <id>`. A run with no region fails the check.
2. **Step 1, no legacy object but the image verifier.** It reads `clusterpolicies.kyverno.io` and `policies.kyverno.io` with the reader of CMP-G02 (`complianceModeCheck.policyObjects`). It fails on every `Policy`, on every `ClusterPolicy` not named `cosign-verified`, and on a `cosign-verified` with no rule or with a rule that holds `validate`, `mutate` or `generate`, or no `verifyImages`. It keeps the image verifier for steps 2 and 4.
3. **Step 2, every policy ready.** It reads `validatingpolicies`, `mutatingpolicies`, `namespacedvalidatingpolicies` and `namespacedmutatingpolicies` of `policies.kyverno.io`. Each object must carry `status.conditionStatus.ready` true; the image verifier, when step 1 read it, its condition `Ready` `True`. A region that does not serve `ValidatingPolicy`, or holds none, fails: nothing was measured.
4. **Step 3, results.** It reads the `compliancemodels.compliance.openova.io` object `default` and every `policyreports` and `clusterpolicyreports` of `wgpolicyk8s.io`. The model must hold a check of source `kyverno`. A check whose every result is `error` fails the step, and so does a region in which no such check has a result that is not `error`. A check without any result is listed, not failed, following the precedent of check CMP-G03 (CMP-042), which lists a check without a subject: evidence `no_subject` when its `ValidatingPolicy` exists (it matches no object, or judges at admission only), `not_installed` when it does not (CMP-G03 judges that agreement). The step fails when step 2 did not read the policies.
5. **Step 4, the legacy counter.** It finds the one Service labelled `app.kubernetes.io/name=kyverno-admission-controller` with a port named `metrics-port` (the upstream chart of `platform/kyverno/chart` renders `<release>-kyverno-svc-metrics`), reads its metrics with `kubectl get --raw /api/v1/namespaces/<ns>/services/<name>:metrics-port/proxy/metrics` through the API server, and judges `kyverno_policy_rule_info_total`: a series of value not 0 for a policy other than `cosign-verified` fails, as does no series for the image verifier when step 1 read it. The metrics must hold a sample of `kyverno_info`, and a series of the counter without a `policy_name` or a readable value fails. A Service count other than one fails.
6. **The check only reads.** Every call is `kubectl get`; nothing is created, changed or deleted, and no port is opened: the metrics are read through the API server's service proxy, never through a node port.
7. **The records.** `docs/ledger/gates.yaml`: CMP-G06 `state: required` and `implementation: tests/acceptance/sovereign/internal/suite/check_policy_engine.go` (`delivered_by: CMP-087` is already there; rule 2 of `scripts/plan.py check-pr` lets a package change only the state and implementation lines of a check). `runs_in: [local, cloud]` is plan data and stays. `tests/acceptance/sovereign/README.md` gains the row of CMP-G06 after the row of CMP-G02. `docs/generated/custom-resources.md`: the row ComplianceModel ends in `yes`, as `scripts/generators/custom-resources.py` writes it once a non-test Go file names `compliancemodels.compliance.openova.io`.
8. Not here: no chart, policy, value or `Chart.yaml` version line changes; no new Python; nothing is written to a live system.

+// legacyRules reads the metrics text: the samples of kyverno_info, and by policy
+// name the series of the legacy counter whose value is not 0 (0 is a deleted

+func legacyRules(text string) (rules map[string]int, info int, err error) {
+	rules = map[string]int{}
+	for i, line := range strings.Split(text, "\n") {
+		line = strings.TrimSpace(line)
+		switch {
+		case strings.HasPrefix(line, engineInfoMetric+"{"), strings.HasPrefix(line, engineInfoMetric+" "):
+			info++
+		case strings.HasPrefix(line, engineLegacyMetric+"{"), strings.HasPrefix(line, engineLegacyMetric+" "):
+			m := engineLegacySeries.FindStringSubmatch(line)
+			v := 0.0
+			if m != nil {
+				v, err = strconv.ParseFloat(m[2], 64)
+			}
+			if m == nil || err != nil {
+				return nil, 0, fmt.Errorf("line %d of the metrics cannot be read: %q", i+1, line)
+			}
+			if v != 0 {
+				rules[strings.ReplaceAll(m[1], `\"`, `"`)]++
+			}
+		}
+	}
+	return rules, info, nil
+}
