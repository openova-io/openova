# SEC-239 — powerdns-api-credentials carries helm.sh/resource-policy keep one release before SEC-235

## In plain words

**The problem today.** The Secret that holds the PowerDNS API key and the web server password is rendered by the PowerDNS chart without the annotation that tells Helm to keep an object. A later release moves the two values into the secret store and stops rendering that Secret. Helm would then delete it during that upgrade, and with it the two values the store must be seeded from.

**What changes.** The Secret carries the keep annotation. The upgrade from the release a Sovereign runs today only adds the annotation to the live Secret and keeps its values, and a later release that no longer renders the Secret leaves it in place.

**Done means:**

- The PowerDNS API credentials Secret that the chart renders carries the annotation helm.sh/resource-policy with the value keep.
- The patch Helm builds for the upgrade from bp-powerdns 1.2.33 adds only that annotation and sends back the values already stored, so both values of the live Secret are unchanged.
- After that upgrade a release that no longer renders the Secret leaves it in place, where from 1.2.33 it would be deleted.
- No other object of the render changes, so the upgrade restarts no Pod.
- No chart version line changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket the Secret `powerdns/powerdns-api-credentials` that `platform/powerdns/chart/templates/api-credentials-secret.yaml` renders carries the annotation `helm.sh/resource-policy: keep`. Before Helm deletes an object that left the manifest of a release, it reads that annotation on the live object and skips the delete when the value is `keep`. So the release of SEC-235, which stops rendering this Secret, leaves it in place, and SEC-226 can seed the two keys `api-key` and `webserver-password` from it (gap G4 of `docs/ledger/plan/spikes/SEC-227.md`, row D1). The proof is the case `TestPowerDNSCredentialsKeptOverDeployed` of `tools/chart-upgrade`, run by the new chart test `platform/powerdns/chart/tests/api-credentials-kept.sh`: it computes Helm's three-way patch with bp-powerdns 1.2.33 deployed and live, as a Sovereign holds it today, and shows that the patch adds only the annotation, that the stored values stay, and that a release without the Secret then keeps it. The test lives in `tools/chart-upgrade`, as the cases of SEC-163 (`openbao_test.go`) and of pull request 9030 (`huawei_evs_csi_test.go`) do.

## 3. The model (the law)
1. **Keep on the rendered Secret.** The Secret `powerdns-api-credentials` of every render with `powerdns.useExistingApiSecret: false` (the default) carries `metadata.annotations["helm.sh/resource-policy"] == "keep"`. Its other annotations, its labels, its type and its keys do not change.
2. **The upgrade applies over what runs.** Helm's three-way patch with bp-powerdns 1.2.33 deployed and live adds the annotation and refuses nothing; Helm neither deletes nor recreates the Secret. The patch carries `stringData` with the values read back from the live Secret by the template's `lookup`, as every upgrade does today, so `data` of the live Secret is unchanged.
3. **A release without the Secret keeps it.** After that upgrade, a release that does not render the Secret leaves it in place. From 1.2.33 live, the same release deletes it (the known answer of the case).
4. **Nothing else moves.** At the default values and at the values of kit slot 11 the render differs from `main` only in the annotation and its comment lines, so no Pod template changes and no Pod restarts.
5. **No chart version line**, no value of `values.yaml`, no kit slot and no file of `tools/chart-upgrade` other than the new case change.

+// stored is the Secret as the API server keeps it: stringData written into data

+func stored(t *testing.T, o Object) corev1.Secret {
+	t.Helper()
+	var s corev1.Secret
+	if err := json.Unmarshal(o.JSON, &s); err != nil {
+		t.Fatal(err)
+	}

+		if s.Data == nil {
+			s.Data = map[string][]byte{}
+		}
+		s.Data[k] = []byte(v)
+	}
+	s.StringData = nil
+	return s

+	}

+	}
