# FND-161 — Row map and browser harness

## In plain words

**The problem today.** The console regression list holds 286 rows that people walk by hand, and nothing says which rows a gate check will prove, which another check already proves, and which are no longer wanted. The gate runs Go checks and scripts against a Sovereign, but it cannot run a browser test of the console, so no row can become a gate check.

**What changes.** A row map gives every row exactly one disposition, and a guard keeps it complete and true. The gate workflow gains a browser harness: a gate check whose implementation is a folder of browser specifications runs as one project, signed in as users created for the run, and its result is added to the gate record.

**Done means:**

- Every one of the 286 rows of the ledger has exactly one line in the row map, and the guard fails a missing, doubled or malformed line, an unknown check or decision record, and a row whose test is due and missing.
- A gate check whose implementation is a folder of the browser harness and whose state is expected-fail or required runs in the live gate run without a change to the workflow.
- Each live gate run creates three users in the sign-in realm of the Sovereign (the run's user, a second administrator and a viewer), signs the browser in as them, and deletes them in a step that always runs.
- Each browser check gets one result in the gate record; a check without a result, with a skipped test or with a failing test is a FAIL.
- The self-test of the harness runs Chromium for real on every pull request that changes the harness, the row map or its guard.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. The row map has one line per ledger row, 286 lines that are not comments, and no blank line: `<row id>,<disposition>[,<test file>]`. Only a `test:` line has a test file. The map, not `UAT.md`, carries the denominator: a package that converts rows deletes them from `UAT.md` and keeps their lines.
2. The first disposition of each row comes from the row's area in `UAT.md` (the word before the issue link of its first cell), never from walking the row: areas of applications and the catalogue go to FND-G20, of jobs, resources, cloud and infrastructure to FND-G21, of Organizations, sign-in and access to FND-G22, of the funnel, cut-over, wizard and hand-over to FND-G23, with the overrides the header of the map lists; `covered:` only where the row's own clause names the check that took it over (rows 57 to 63, FND-G11; G12, CTL-G10) or one check asserts the same outcome (R2, NET-G18; R13, FND-G04); `retire:ADR-0022` for rows 184 and 185, which assert properties of the hand-walked ledger itself.
3. The guard fails: a malformed or blank line, an id not of the ledger's form, another kind of disposition; two lines for one row; a row of `UAT.md` without a line; a map without 286 rows; a check not in `docs/ledger/gates.yaml`, or a `test:` check whose implementation is not a folder of the harness; a decision record that is not a file `docs/adr/<nnnn>-*.md`; a test file on a line that is not `test:`, or one that is not a `.spec.ts` file of the tree under the check's folder; a test file with no `test('<row id> ...` (skip, fixme and fail do not count); a `test:` line without a test file whose check is not `not-built`, or whose row has left `UAT.md`. Its `--self-test` and its Go tests show every rule failing on a tree they build.
4. The harness selects its checks with one function (`e2e/gate/checks.ts`), which the gate workflow also calls to list them: a folder under one of the two roots, `expected-fail` or `required`, `cloud` in `runs_in`. A check named on the command line of `e2e/gate/run.sh` that the selector does not give stops the run.
5. A check's result is PASS only when every one of its tests ran and passed. A skipped test, a test marked to fail, a project without a test, an error of the run, and a run that was interrupted or timed out make it FAIL. The result file has the form `merge-check` reads: `{"id", "status", "steps"}`, each step with `journey` (the check), `id` (the row id), `name`, `status`, `started_at`, `finished_at`, `duration_ms`, `evidence`, `error`.
6. The three identities are created for the run in the realm `sovereign` of region A, by `kcadm.sh` inside the Pod `keycloak/keycloak-0`, as for FND-G07: `gate-<run id>-run@<fqdn>` in `sovereign-admins` and `sovereign-viewers`, `gate-<run id>-second@<fqdn>` in `sovereign-admins`, `gate-<run id>-viewer@<fqdn>` in `sovereign-viewers`. Their sessions are minted with the Sovereign's own signer. They are deleted in a step that always runs; the next run deletes what an earlier run left. The names never match the user of FND-G07 (`gate-<run id>@<fqdn>`), and its cleanup never matches them.
7. The harness runs on the hosted machine only. In parent execution, and whenever the harness did not run, `merge-check` records each listed browser check as FAIL: a missing result file is never a pass. While no browser check is `expected-fail` or `required` (until FND-162), the steps list none and add nothing to the record.
8. No traces leave the runner: a trace holds the requests of the test with its session cookie. The workflow uploads the result files, the screenshots and the error contexts.
9. No Python is added: the guard is Go in `tools/guards`, the harness is TypeScript, the workflow steps are shell (JSON of the identity provider is read as CSV with `kcadm.sh --format csv --noquotes`, parsed with awk).
10. Playwright 1.59 has no Chromium build for the 26.04 machines that `ubuntu-latest` gives since November 2026. +# e2e/gate — the browser harness of the gate (FND-161)
+
+The console regression list (`docs/ledger/UAT.md`) becomes browser tests here, one folder per gate check.
+The harness runs in the live job of `.github/workflows/foundation-gate.yaml`, after the suite, against the
+candidate Sovereign; no Sovereign runs it.
+
+## A check is a folder
+
+- A gate check whose `implementation` in `docs/ledger/gates.yaml` is a folder under
+  `products/catalyst/bootstrap/ui/e2e/gate/` or `core/marketplace/e2e/gate/` is one Playwright project, named
+  by the check id, that runs every `*.spec.ts` of the folder (`checks.ts`). It runs when the check is
+  `expected-fail` or `required` and lists `cloud` in `runs_in`. A new check is a new folder and a manifest

+/**
+ * e2e/gate/reporter.ts — one result file per check (FND-161).
+ *
+ * For every project of the run (one project per gate check) it writes
+ * <outputDir>/<check id>.json in the form scripts/acceptance-gate.py
+ * merge-check reads (the form of FND-036):
+ *
+ *   {"id": "<check>", "status": "PASS" | "FAIL", "steps": [<one step per test>]}
+ *
+ * A step has the fields of a step of the gate record: journey (the check),
+ * id (the first word of the test's title: the ledger row id), name (the
+ * title), status, started_at, finished_at, duration_ms, evidence (the spec
+ * file and line, the files of the failure) and error. A check passes only
+ * when every one of its tests ran and passed: a skipped test, a test marked
+ * to fail, a project without a test and an error of the run each make it FAIL.
+ */

+import { join, relative } from 'node:path'
+import type { FullConfig, FullResult, Reporter, TestCase, TestError, TestResult } from '@playwright/test/reporter'

+interface Step {
+  journey: string
+  id: string
+  name: string
+  status: 'PASS' | 'FAIL' | 'SKIP'
+  started_at: string
+  finished_at: string
+  duration_ms: number
+  evidence?: Record<string, unknown>
+  error?: string
+}

+const ANSI = new RegExp(String.fromCharCode(27) + '\\[[0-9;]*m', 'g')
+
+function firstLine(text: string | undefined): string {
+  return (text ?? '').replace(ANSI, '').split('\n').map((l) => l.trim()).find((l) => l !== '') ?? ''
+}
+
+export default class GateResults implements Reporter {
+  private readonly outputDir: string
+  private readonly repoRoot: string
+  private projects: string[] = []
+  private readonly outputDirs = new Map<string, string>()
+  private readonly last = new Map<string, { project: string; test: TestCase; result: TestResult }>()
+  private readonly errors: string[] = []
+  private started = new Date()
+
+  constructor(options: { outputDir: string; repoRoot: string }) {
+    this.outputDir = options.outputDir
+    this.repoRoot = options.repoRoot
+  }
+
+  onBegin(config: FullConfig): void {
+    this.projects = config.projects.map((p) => p.name)
+    for (const p of config.projects) this.outputDirs.set(p.name, p.outputDir)

+        finished_at: now, duration_ms: Math.max(0, Date.now() - this.started.getTime()), error,

+      for (const e of this.errors) steps.push(fail('the harness ran without an error', e))
+      if (result.status === 'interrupted' || result.status === 'timedout') {
+        steps.push(fail('the harness run ended', `the run ended ${result.status}`))
+      }
+      const status = steps.every((s) => s.status === 'PASS') ? 'PASS' : 'FAIL'
+      writeFileSync(join(this.outputDir, `${project}.json`), JSON.stringify({ id: project, status, steps }, null, 2) + '\n')

+      id: test.title.split(/\s+/)[0] || '-',
+      name: test.titlePath().slice(3).join(' › ') || test.title,
+      status: passed ? 'PASS' : r.status === 'skipped' ? 'SKIP' : 'FAIL',
+      started_at: start.toISOString(),
+      finished_at: new Date(start.getTime() + r.duration).toISOString(),
+      duration_ms: Math.max(0, Math.round(r.duration)),
+      evidence: {
+        file: relative(this.repoRoot, test.location.file),
+        line: test.location.line,
+        retry: r.retry,
+        // The files of a failure, from the folder of the test results (GATE_OUTPUT), which the workflow uploads.
+        files: r.attachments.filter((a) => a.path).map((a) => relative(this.outputDirs.get(project) ?? this.repoRoot, a.path as string)),
+      },

+    }

+ *
+ * The global setup of a self-test run. Every host of the stand-in domain
+ * (the browser sends *.self-test.invalid to 127.0.0.1) gets a page that
+ * shows the host it was asked for, the console session cookie the browser
+ * sent, and a canvas that writes every key it receives into #typed.

+import { createServer } from 'node:http'
+
+function escapeHTML(s: string): string {
+  return s.replace(/[&<>"']/g, (c) => `&#${c.charCodeAt(0)};`)
+}
+
+export default async function globalSetup(): Promise<() => Promise<void>> {
+  const port = Number(process.env.GATE_PORT)
+  if (!Number.isInteger(port) || port <= 0) throw new Error('GATE_PORT is not the port of the self-test server')
+  const server = createServer((req, res) => {
+    const host = (req.headers.host ?? '').split(':')[0]
+    const session = /(?:^|;\s*)catalyst_session=([^;]*)/.exec(req.headers.cookie ?? '')?.[1] ?? ''
+    res.writeHead(200, { 'content-type': 'text/html; charset=utf-8' })
+    res.end(`<!doctype html><title>${escapeHTML(host)}</title>
+<p id="host">${escapeHTML(host)}</p><p id="session">${escapeHTML(session)}</p>
+<canvas id="screen" width="320" height="120" tabindex="0"></canvas><p id="typed"></p>
+<script>const t = document.getElementById('typed');
+document.getElementById('screen').addEventListener('keydown', (e) => { t.textContent += e.key.length === 1 ? e.key : '[' + e.key + ']'; });</script>`)
+  })
+  await new Promise<void>((ok, fail) => {
+    server.once('error', fail)
+    server.listen(port, '127.0.0.1', () => ok())
+  })
+  return async () => {
+    await new Promise<void>((ok) => server.close(() => ok()))
+  }
