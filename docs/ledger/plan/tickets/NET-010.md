# NET-010 — Close peer and stale ports on the reference provider

## In plain words

**The problem today.** On the reference cloud provider the security group of every Sovereign admits the whole internet on ports that only its own regions use: the embedded etcd port, the mesh endpoint and two WireGuard ports. Two more rules open tunnel ports that nothing uses. Nothing checks from outside that these ports are closed.

**What changes.** The mesh endpoint admits only the Sovereign's own public addresses and its node and pod ranges, WireGuard admits only the node and pod ranges, and the unused rules are deleted. A new gate check tries the closed ports from outside, and it is required from now on.

**Done means:**

- No security-group rule of the reference provider admits the whole internet on the etcd port, the mesh endpoint, a WireGuard port or a tunnel port.
- The mesh endpoint still admits every region's control-plane and NAT addresses and every node and pod range, so the regions still reach each other.
- The rules for the web ports, the API port and ICMP are unchanged.
- The module test fails when a rule for the mesh endpoint or for WireGuard admits the whole internet.
- A gate run fails unless, from the gate runner, the etcd port and the mesh endpoint of every control-plane address time out, the API port of the same address answers, and the mesh step of discovery passed.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
On the reference provider (`infra/providers/huawei`), the security group of each region admits nobody from the internet on the ports that only the Sovereign's own regions use. The mesh dial port (TCP 12379, `var.clustermesh_proxy_port`) admits only the Sovereign's own public addresses (every region's control-plane EIP and NAT EIP, as `/32`) and every region's node subnet and pod range. Cilium WireGuard (UDP 51871) admits only the node subnets and pod ranges. The rules for TCP 2379, UDP 51820, UDP 8472 and UDP 6081 are gone. ICMP, the web ports and the API port are unchanged. The acceptance suite has the gate check NET-G01 "Peer ports closed", in state `required`: from the machine that runs the suite, ports 2379 and 12379 of every control-plane public address time out, port 6443 of the same address answers, and discovery step D0.10 (the mesh between the regions) passed.

## 3. The model (the law)
1. No rule of `huaweicloud_networking_secgroup_rule` in `infra/providers/huawei/main.tf` opens TCP 2379, UDP 51820, UDP 8472 or UDP 6081. The four resources `ingress_wireguard`, `ingress_clustermesh_2379`, `ingress_cilium_vxlan` and `ingress_cilium_geneve` are deleted.
2. The mesh dial port rule `ingress_clustermesh_proxy` has one rule per target region and per source. The sources are every value of the new local `sovereign_public_sources` and every entry of the existing local `mesh_ingress_cidrs`. Its `for_each` keys are static strings: `<target region>|cp|<region>`, `<target region>|nat|<region>` and `<target region>|<cidr>`.
3. `sovereign_public_sources` is a map with one entry per region for `huaweicloud_vpc_eip.cp` (key `cp|<region>`) and one per region for `huaweicloud_vpc_eip.nat` (key `nat|<region>`). The value is `<address>/32`.
4. The Cilium WireGuard rule `ingress_cilium_wireguard` has one rule per target region and per entry of `mesh_ingress_cidrs`, keyed `<target region>|<cidr>`, as `ingress_cilium_health` is built.
5. `ingress_icmp`, `ingress_443`, `ingress_8443`, `ingress_8080`, `ingress_80` and `ingress_6443` are not changed. After the change exactly six rules of `main.tf` carry `remote_ip_prefix = "0.0.0.0/0"`: 443, 8443, 8080, 80, 6443 and ICMP.
6. `infra/providers/huawei/tests/multi_region.tftest.hcl` gains the runs `peer_ports_closed` (two regions) and `peer_ports_closed_single_region`. They fail when a rule for 12379 or 51871 has the source `0.0.0.0/0`, when a source is missing, and when ICMP is no longer open.
7. Gate check NET-G01 is one file, `tests/acceptance/sovereign/internal/suite/check_peer_ports.go`, that calls `RegisterCheck` in `init()`. It reads the `ExternalIP` addresses of the nodes with the label `catalyst.openova.io/role=control-plane` in every region. For each address a TCP connection to 6443 must be accepted (the control: the address answers from here) and a TCP connection to 2379 and to 12379 must time out after 5 seconds. An accepted or a refused connection on 2379 or 12379 fails. A region without such an address fails. Discovery step D0.10 must have status PASS in the same run.
8. In `docs/ledger/gates.yaml` the entry NET-G01 moves from `state: not-built` to `state: required` and gains the line `implementation: tests/acceptance/sovereign/internal/suite/check_peer_ports.go`. No other line of the file changes.

+func peerPortsOutcome(err error) string {

+		return "timeout"

+		return "refused"
+	}
