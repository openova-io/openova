# CLD-112 — Credential check from the profile; one registry

## In plain words

**The problem today.** The route that checks cloud credentials before a deployment knows one cloud by heart: the minimum token length, the name of the token field and the cloud used when the body names none are written into its code. The Object Storage check keeps a second registry of clouds beside the provider registry. A new cloud would need edits to the route and a second registration.

**What changes.** The route reads the rules of each credential from the cloud profile and asks the cloud adapter to call the cloud. The Object Storage check is a capability of the adapter, found in the one provider registry, and the second registry is gone.

**Done means:**

- A Hetzner token shorter than its cloud profile allows is refused with an answer that names the token field, before the cloud is called.
- A credentials check that names no provider is refused with an answer that names the provider field, and is never treated as one particular cloud; an unknown provider is answered with 404.
- A credentials map that lacks a field its cloud profile marks required is refused with an answer that names that field.
- The wizard's present token check and Object Storage check give the same answers as before.
- There is one provider registry; the separate Object Storage registry no longer exists.
- The guard against cloud names in capability-named places still fails on a violation.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`POST /api/v1/credentials/validate` takes `{"provider","installation","credentials":{<key>:<value>}}` and the wizard's legacy body `{"provider","token"}`. It refuses an empty provider with 400 `{"valid":false,"field":"provider",…}`, answers an unknown provider with 404, reads the effective cloud profile with `provisioner.EffectiveProfile`, checks every credential value against the pattern of its field in the profile (and every required field when no legacy field supplied a value) with the new neutral rule `providers.CheckCredentialValues`, and answers a refused field with 400 `{"valid":false,"field":"<key>","message":…}`; only then the adapter's `ValidateCreds` calls the cloud. `POST /api/v1/credentials/object-storage/validate` resolves its adapter with `providers.As[providers.ObjectStorageValidator]`; the Hetzner adapter implements that capability with the code of the deleted package `internal/objectstorage`. The credentials handler names no cloud.

## 3. The model (the law)
1. The handler `ValidateCredentials` (`internal/handler/credentials.go`) holds no cloud name, no credential key and no length rule. The 64-character rule, the default provider `hetzner` and the key `hcloud_token` are deleted.
2. An empty `provider` is answered 400 with `field: provider`; a provider that `providers.Get` does not know is answered 404. The provider is lower-cased.
3. The effective profile is `provisioner.EffectiveProfile(provider, installation)`. When it cannot be read the answer is 400 with `field: installation` if the body names an installation, else `field: provider`.
4. The credentials are the body's `credentials` map (values trimmed), plus every legacy JSON field that the adapter names through `providers.LegacyAliaser` and the map lacks (`credentialsOf`). The Hetzner adapter adds the legacy field `token` → `hcloud_token`, the field of the wizard's body today.
5. `providers.CheckCredentialValues(creds, profile, required)` (`internal/providers/normalize.go`) checks each credential field of the profile: a non-blank value must match the field's `pattern`; with `required` true a field the profile marks `required` must be non-blank. Its `*FieldError` names the credential key. A pattern that does not compile is a plain error (answer 500). The handler passes `required` true unless a legacy field supplied a value, so the wizard's token-only body is checked by pattern alone, and a credentials map by both.
6. The answers of the cloud call stay as they are: 200 `valid:true`; 200 `valid:false` when the adapter's error says `rejected`; 503 otherwise, whose message names the profile's `displayName`.
7. `ValidateObjectStorageCredentials` finds its adapter with `providers.As[providers.ObjectStorageValidator]`. An empty provider means the one registered adapter that has the capability (the wizard's Object Storage body names no provider); when not exactly one has it, the answer is 400 with `field: provider`. The region, length and answer rules of the route do not change.
8. The Hetzner adapter implements `ObjectStorageValidator` in `internal/providers/hetzner/objectstorage.go`: `ObjectStorageEndpoint` and `ValidateObjectStorage` are the `Endpoint` and `Validate` of the deleted `internal/objectstorage/hetzner`, unchanged in behaviour. Its tests move to `internal/providers/hetzner/objectstorage_test.go`.
9. Deleted: the package `internal/objectstorage` with its four files (the registry `Register`, `Resolve`, `MustResolve` and the Hetzner implementation).
10. `scripts/check-vendor-coupling.sh` hard-failed only while the folder `internal/objectstorage` existed. It hard-fails always now, so deleting the folder does not turn the guard into a warning.
11. The handler package shrinks; `scripts/baselines/api-structure.json` is lowered by its own tool in the same change.

+// ValidateObjectStorage issues an S3 ListBuckets call against Hetzner Object
+// Storage with the operator-supplied pair, the permission the module needs to
+// create the Sovereign's bucket.
+//
+//	(true,  nil) — the keys authenticate and can list buckets
+//	(false, nil) — the keys are rejected (AccessDenied, InvalidAccessKeyId, …)
+//	(false, err) — the endpoint cannot be reached (timeout, DNS, 5xx)
+//
+// The keys are never logged.
+func (p *Provider) ValidateObjectStorage(ctx context.Context, region, accessKey, secretKey string) (bool, error) {
+	if strings.TrimSpace(accessKey) == "" {
+		return false, errors.New("access key is empty")
+	}
+	if strings.TrimSpace(secretKey) == "" {
+		return false, errors.New("secret key is empty")
+	}
+	endpoint := p.ObjectStorageEndpoint(region)
+	if endpoint == "" {
+		return false, fmt.Errorf("unknown Hetzner Object Storage region %q (must be fsn1, nbg1, or hel1)", region)
+	}
+
+	client, err := minio.New(endpoint, &minio.Options{
+		Creds:  credentials.NewStaticV4(accessKey, secretKey, ""),
+		Secure: true, // Hetzner Object Storage requires HTTPS
+		Region: region,
+	})
+	if err != nil {
+		return false, fmt.Errorf("construct minio client: %w", err)
+	}
+
+	// Only whether the call is refused matters, not the bucket list (a new
+	// tenant has none).
+	_, err = client.ListBuckets(ctx)
+	if err == nil {
+		return true, nil
+	}

+	if errors.As(err, &errResp) {
+		switch errResp.Code {
+		case "AccessDenied", "InvalidAccessKeyId", "SignatureDoesNotMatch", "InvalidSecurity":
+			return false, nil
+		}
+	}
