# SOV-035 — Delete the ProvisioningState kind and its unwired store

## In plain words

**The problem today.** The platform chart installs a custom resource kind, ProvisioningState, on every cluster, and the API server carries a store of about 750 lines that was meant to write objects of that kind. No program creates that store, so no object of the kind is ever written or read. The chart still describes the kind as the persistence of provisioning runs, which misleads anyone who reads it.

**What changes.** The definition, the store and its tests are deleted. The chart's notes, values and comments, the schema bundle of the API server, the generated inventory of custom resources and two guard baselines no longer name them, and the list of deleted paths names the three files.

**Done means:**

- The platform chart no longer holds a definition of the kind ProvisioningState, and the API server no longer holds a store that writes it.
- Outside the docs folder, no file of the repository names the kind.
- The chart still renders, its values no longer carry a setting for the kind, and every other definition of the chart is still there.
- The API server builds, and the tests of its flat-file store and of its schema bundle pass.
- The generated inventory of custom resources is current and does not list the kind.
- The direct-cluster-write and provider-leak guards pass with baselines that no longer name the deleted files.
- The list of deleted paths names the three files, so a pull request that brings one back turns red.

The rest of this ticket is the exact instruction for the model that does the work.
