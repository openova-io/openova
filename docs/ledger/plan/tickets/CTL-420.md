# CTL-420 — Watches in the organization and environment controllers

## In plain words

**The problem today.** The Organization controller learns that the virtual cluster of an Organization or its console door has become ready only by asking again every 30 seconds, for every Organization that is still being set up. The Environment controller asks again every five minutes even when all its work is done. Both are polls where the platform should be told about a change.

**What changes.** The Organization controller watches the release of the virtual cluster and the shared console gateway, and is woken when their readiness changes. The waits that remain in both controllers ask again every ten minutes as a safety net, and the polling guard lists them as such.

**Done means:**

- A readiness change of a HelmRelease that carries an Organization label wakes that Organization at once.
- A readiness change of the console gateway wakes every Organization that has a public console address, and a change of any other gateway wakes none.
- A change of a watched object that does not touch its readiness wakes nothing.
- An Organization that waits for its virtual cluster, its console or its checks asks again after ten minutes instead of 30 seconds; the retries of a deletion keep their 30 seconds.
- A ready Environment asks again after ten minutes instead of at its configured retry interval.
- The polling guard passes and lists the three remaining requeues of the two controllers as safety nets and a clock event.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The Organization reconciler (`core/controllers/organization/internal/controller`) watches two kinds besides the Organization: every Flux `HelmRelease` labelled `openova.io/organization=<slug>`, which enqueues the Organization `<slug>`, and the console `Gateway` (the name and namespace the reconciler is configured with, `kube-system/cilium-gateway-console` by default), which enqueues every Organization that has a pool `parentDomain`. Each watch passes an update only when the readiness of the object changed. The requeue that waited for the virtual cluster, the console and the provisioning checks every 30 seconds now waits ten minutes, as a safety net. The Environment reconciler returns a ten-minute requeue when every region is ready. `scripts/baselines/polling.json` lists the two ten-minute requeues and the spend-limit clock in its `allow` list, and the polling guard passes.

## 3. The model (the law)
1. **HelmRelease watch.** The reconciler watches `helm.toolkit.fluxcd.io/v2` `HelmRelease` objects in every namespace, read as unstructured objects. A HelmRelease whose label `openova.io/organization` is not empty enqueues the cluster-scoped Organization of that name. A HelmRelease without the label enqueues nothing. The vCluster HelmRelease that the controller renders (`gitops.vclusterTemplate`) carries the label.
2. **Gateway watch.** The reconciler watches `gateway.networking.k8s.io/v1` `Gateway` objects in every namespace. Only the Gateway whose namespace and name equal `consoleGatewayNamespace()` and `consoleGatewayName()` maps to Organizations: it enqueues every Organization for which `orgEngagesTenantNetworking` is true (its `spec.tenantPublic.parentDomain` is not empty), sorted by name. The console Gateway is shared by every Organization and carries no Organization label, and a listener that was rewritten away is no longer on it to name its owner; this is why it maps to all such Organizations and not by a label. Any other Gateway enqueues nothing. A failed list of Organizations enqueues nothing and is logged.
3. **Predicate.** Both watches use one predicate. A create and a delete always pass. A generic event never passes. An update passes only when one of these differs between the old and the new object: `status.observedGeneration`; the `status` or the `observedGeneration` of the condition of type `Ready`; the `status` or the `observedGeneration` of the condition of type `Programmed`. A change of anything else (an annotation, a condition's time or message, the spec) does not pass. No watch is added without this predicate.
4. **Requeues of the Organization reconciler.** The one requeue at the end of `Reconcile` that waits while the virtual cluster is not ready, the console-serving steps reported a failure, or a provisioning check is missing or could not be verified returns `RequeueAfter: 10 * time.Minute` instead of 30 seconds. The four 30-second retries of the deletion branch, the 30-second retry of `fail()` and the requeue at the instant a spend-limit stop lifts (`stopLifts + time.Second`) do not change. A Ready Organization still returns `ctrl.Result{}`.
5. **Requeue of the Environment reconciler.** When every region is ready, `Reconcile` returns `RequeueAfter: 10 * time.Minute`. The branch that is not ready, `markPending` and `markDegraded` keep `cfg.RequeueAfter` (default five minutes, environment variable `REQUEUE_AFTER_SECONDS`).
6. **Polling baseline.** The guard `scripts/check-no-new-polling.py` counts the matches of `ctrl.Result{RequeueAfter` per file and allows only one `allow` entry per metric and path. The counts do not change (7 in the Organization file, 4 in the Environment file); three of them move to `allow`: one entry for the Environment file with count 1 and reason `safety net, ten minutes`, and one entry for the Organization file with count 2 (the ten-minute safety net and the spend-limit clock) and reason `safety net, ten minutes; clock event`. Both have owner `CTL`. The `counts` entries fall to 3 and 5, written by the guard's own `--write-baseline`.
7. **Only the local cluster is watched.** The console Gateways of the other regions are read through their own clients in `consoleRegionTargets`; they stay covered by the ten-minute safety net.
8. **Nothing else.** No new label, no new kind, no shared controller package, no change to `main.go`, to the manager options or to the chart: the ClusterRole already grants `get`, `list` and `watch` on `gateways` and `helmreleases`.

+// readinessChanged passes every create and delete, and an update only when
+// readinessSignature differs between the old and the new object.
+func readinessChanged() predicate.Funcs {
+	return predicate.Funcs{
+		CreateFunc: func(event.CreateEvent) bool { return true },
+		DeleteFunc: func(event.DeleteEvent) bool { return true },
+		UpdateFunc: func(e event.UpdateEvent) bool {
+			if e.ObjectOld == nil || e.ObjectNew == nil {
+				return true
+			}
+			return readinessSignature(e.ObjectOld) != readinessSignature(e.ObjectNew)
+		},
+		GenericFunc: func(event.GenericEvent) bool { return false },
+	}
+}

+// readinessSignature is the part of an object that the predicate compares:
+// status.observedGeneration, then the status and the observedGeneration of
+// each watched condition. An object that is not unstructured has none.
+func readinessSignature(obj client.Object) string {
+	u, ok := obj.(*unstructured.Unstructured)
+	if !ok {
+		return ""
+	}
+	var b strings.Builder
+	observed, _, _ := unstructured.NestedFieldNoCopy(u.Object, "status", "observedGeneration")
+	b.WriteString(fieldText(observed))
+	conds, _, _ := unstructured.NestedSlice(u.Object, "status", "conditions")
+	for _, want := range watchedConditionTypes {
+		b.WriteString("|" + want + "=")
+		for _, ci := range conds {
+			c, ok := ci.(map[string]any)
+			if !ok || c["type"] != want {
+				continue
+			}
+			b.WriteString(fieldText(c["status"]) + "/" + fieldText(c["observedGeneration"]))
+			break
+		}
+	}
+	return b.String()
+}

+// fieldText renders a status field for readinessSignature; an absent field is
+// the empty string.
+func fieldText(v any) string {
+	if v == nil {
+		return ""
+	}
+	return fmt.Sprint(v)
