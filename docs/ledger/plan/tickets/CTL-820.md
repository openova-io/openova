# CTL-820 — Region-loss gate check

## In plain words

**The problem today.** Decision record 0027 states how much data each kind of state may lose and how fast a Sovereign recovers when one of its two regions is lost. No test measures any of these numbers, so nothing shows whether a Sovereign could keep them, or that it cannot yet.

**What changes.** The acceptance suite gains a region-loss check. It reads both regions and judges, for Git, the database pairs and OpenBao, the quantity that bounds each number, and it says that the recovery times are not measured yet. The list of checks marks it as expected to fail, so it runs and is recorded and cannot fail a run.

**Done means:**

- On a Sovereign of one region the check fails at once and reads nothing.
- The check fails and names the region when a Git server uses the shared database pair, when its own database cluster is missing or not ready, and when a region still runs the one-minute Git copy job.
- The check fails when a follower lacks, 60 seconds later, the head of a repository that the writer had, and passes when the follower holds the writer's newer head.
- The check fails when a database pair at dataDurability required has fewer synchronous standbys outside its own instances than it declares, and when the writer region has no such pair.
- The check fails when the OpenBao of a region is sealed, and its last step always fails with the reason that no loss drill measures the recovery times yet.
- The check writes nothing to a cluster, and the list of checks marks it as expected to fail.

The rest of this ticket is the exact instruction for the model that does the work.

   4. Git, at most 60 seconds of commits lost: in one running pod `app.kubernetes.io/name=gitea` of namespace `gitea` (the first by name), container `gitea`, the check runs the script `regionLossHeads` with `sh -c`. The check reads the writer's heads, waits 60 seconds, reads the writer's heads again and then each follower's. The wait ends with the run's context.
   5. Database pair at `dataDurability: required` (ADR-0004), nothing lost: on the writer region every CNPG cluster (`clusters.postgresql.cnpg.io`, all namespaces) with `spec.postgresql.synchronous.dataDurability: required` and without `spec.replica.enabled: true`. A writer region with no such cluster fails: nothing is measured.
