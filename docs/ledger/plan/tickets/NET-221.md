# NET-221 — Delete the four retired charts and their seed entries

## In plain words

**The problem today.** The platform planes of a Sovereign were once run inside three virtual clusters, and a fourth chart offered a virtual cluster for the internet-facing zone. That design was withdrawn: the planes are plain host namespaces now, and no bootstrap-kit slot installs these charts any more. The four chart folders are still in the repository, the catalogue seed still renders three of them as Blueprints on every Sovereign, and three guards still render or list them, so the retired design still looks alive.

**What changes.** The four chart folders are deleted and listed as deleted paths. The three Blueprint documents leave the catalogue seed, the generated catalogue and the inventory of components, and the guard scripts, the guard baselines and the repository map lose every line that names them.

**Done means:**

- The four chart folders are gone, and the list of deleted paths names each of them, so a pull request that brings one back turns red.
- Only the HelmRepository chart platform/bp-vcluster-helmrepo still has vcluster in its folder name.
- The rendered catalogue seed carries no Blueprint of the three retired planes, and still carries bp-vcluster-helmrepo.
- The generated catalogue and the inventory of components are in sync with their generators and name none of the retired Blueprints.
- The network-guard, provider-leak, service-model and upstream-literal guards pass, and their baselines name no deleted file.
- The NodePort guard, the proxy-image guard and the egress-completeness guard name no deleted chart, and the proxy-image guard still passes.
