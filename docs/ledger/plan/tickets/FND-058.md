# FND-058 — The guard-wiring meta-guard never reports a guard that a workflow runs as orphaned

## In plain words

**The problem today.** The check that every self-testing guard is run by some workflow sometimes says that a guard is run by nothing, although a workflow runs it. It then fails a pull request that changed nothing wrong. The cause is how it looks a name up in its list: on a busy machine the look-up can fail by chance.

**What changes.** The check looks a name up in its list in a way that cannot fail by chance. Its own self-test proves that, and it still fails when a guard really is run by no workflow.

**Done means:**

- The check gives the same answer on every run of the same tree: 500 runs in a row all pass on main.
- A guard that a workflow runs is never reported as run by nothing.
- A self-testing guard that no workflow runs still fails the check, and the check names it.
- The self-test of the check fails if the look-up is put back the old way.
- The output lines and exit codes of the check are the same as before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`scripts/check-guards-are-wired.sh` checks that every `scripts/check-*.sh` which offers `--self-test` is run by at least one workflow. Today it decides "is this name in the list of guards that workflows run" by piping the list into `grep -q` while `set -o pipefail` is on. `grep -q` exits at its first match; the writer of the pipe can then be killed by the closed pipe, and `pipefail` turns a name that was found into "not found". So the script now and then reports a guard that a workflow runs as `ORPHANED GUARD` and exits 1. After this ticket the script decides membership with a pure-bash test that has no pipe and no child process. The same test serves the real run and the self-test. The self-test gains a case that fails on every run if the look-up is a pipe again. The real run gives the same verdict on every run, and a guard that really is run by no workflow is still reported and still fails the script.

## 3. The model (the law)
1. Membership of a name in the newline-separated list of invoked guards is decided by the function `in_set <name> <list>`, written in pure bash with a `case` pattern. A name is a member only when it is one whole line of the list.
2. The real run and the self-test's `is_invoked` both use `in_set`. No other membership test is used.
3. A substring test of a text is decided by the function `contains <text> <needle>`, written in pure bash with a `case` pattern. The three end-to-end checks of the self-test use it.
4. After the change, no line of `scripts/check-guards-are-wired.sh` pipes into `grep -q` (or any `grep` whose flags hold `q`).
5. The self-test has a case (e) that tests membership in a list of 20000 names, far larger than a pipe's buffer of 64 KiB. The first name must be a member on 20 runs in a row; the last name must be a member; a name not in the list, a part of a line, and a line with more text after it must not be members.
6. The matcher of invoked guards (`INVOKE_RE` and `invoked_set`), the rule of which scripts are checked (`advertises_self_test`), every printed line of the real run, the exit codes 0, 1 and 2, the options `--self-test` and `--root`, and the file mode 100755 do not change.
7. The file after the change is exactly the result of the patch `FND-058.patch` of field 16. Nothing is deleted.
