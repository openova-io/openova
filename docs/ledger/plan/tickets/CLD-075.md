# CLD-075 — Generator for the provider and profile tables

## In plain words

**The problem today.** The facts about each cloud the platform can provision on (its regions, machine sizes, credential fields, storage, load-balancer mode and plug-in charts) now live in one data file per cloud. The documents still describe the clouds in hand-written tables that drift from the code. No table is produced from the data files, so a document has nothing true to link to.

**What changes.** A new generator writes one document with the tables of every provider pack and its cloud profile, read from the data files. The existing drift check runs it on every pull request, and the list of generated files of the provider contract names its output.

**Done means:**

- The file docs/generated/providers.md exists and has one row and one section for each provider pack in the repository.
- A pull request that changes a pack declaration or a cloud profile without running the generator turns the drift check red.
- The generator proves each of its rules in a self-test that runs on every pull request.
- The generator names no cloud, so the provider-leak check stays green.
- The list of generated files of the provider contract names the new document, and its first entry is unchanged.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The repository holds the generator `scripts/generators/providers.py` and its output `docs/generated/providers.md`. The output lists every provider pack under `infra/providers/` with the fields of its pack declaration (`pack.yaml`) and of its cloud profile (`profile.yaml`), and the regions and flavors of each profile. The workflow `check-generated-docs` already runs every file `scripts/generators/*.py` with `--self-test` and with `--check`, so from this change on a pull request that changes a `pack.yaml` or a `profile.yaml` and does not commit the regenerated document is red. `infra/providers/_contract/generated-files.txt` names `docs/generated/providers.md` as a generated file. Documents can then link to the generated tables instead of keeping their own; that replacement is package CLD-076.

## 3. The model (the law)
1. `scripts/generators/providers.py` is the embedded block `providers.py` of this ticket, byte for byte: 634 lines, SHA-256 `ba34ab87a5d047b0634284d5fb948b4a12343913e647e10f01afc18c78c4aa46`.
2. It has the form of every generator of `scripts/generators/`, as the head comment of `.github/workflows/check-generated-docs.yaml` states it. With no argument it writes its output file. With `--check` it writes nothing and exits 1 when the file on disk differs from what it would write, and 2 when an input cannot be read. With `--self-test` it proves each of its rules on a throw-away tree. It needs Python 3 and PyYAML only.
3. Its inputs are `infra/providers/<pack>/pack.yaml` and `infra/providers/<pack>/profile.yaml`. A pack is a folder directly under `infra/providers/` whose name starts with neither `_` nor `.`. This is the rule of the Go package `products/catalyst/bootstrap/api/internal/cloudprofile` (after CLD-080). These are the input errors (exit 2):
   - a tree without the folder `infra/providers`, or without any pack folder;
   - a pack folder without one of the two files;
   - a file that is not valid YAML, or that is not a mapping with the key `spec`;
   - a wrong `kind`, or a `metadata.name` that is not the folder name;
   - in `pack.yaml`, a missing field of the generator's list `PACK_FIELDS`: `spec.contractVersion`, `spec.module`, `spec.overlay`, `spec.adapter`, `spec.tofuProviders`;
   - in `profile.yaml`, a missing field of the generator's list `PROFILE_FIELDS`: `spec.displayName`, `spec.lifecycle`, `spec.contractVersion`, `spec.credentials.source`, `spec.credentials.fields`, `spec.regions`, `spec.compute.image`, `spec.compute.flavors`, `spec.storage.defaultClass`, `spec.storage.driver`, `spec.network.loadBalancer.mode`, `spec.capabilities.multiRegion`, `spec.capabilities.multiCloudRegion`;
   - a field of the generator's list `LISTS` that is present and is not a list;
   - an entry of `spec.tofuProviders` without `source`, a credential field without `key`, a region without `code`, a flavor without `name`;
   - `spec.compute.defaults` or `spec.compute.minimumFlavor` that is set and is not a mapping.

   Every other field that the document shows may be missing, and that is no error: the document then shows `not set`, or a dash when the field is a list. This holds for `spec.charts`, `spec.leakTokens`, `spec.requiresInstallation`, `spec.compute.defaults`, `spec.compute.minWorkerCount`, `spec.compute.minimumFlavor`, `spec.objectStorage.checksumAlgorithm`, `spec.seal.kind`, `spec.bootstrap.userDataLimitBytes` and `spec.day2.contracts`. Whether a file must have such a field is a rule of the two schemas in `infra/providers/_contract/`. They judge every other rule of the files; the generator does not repeat them, and it ignores a field it does not show.
4. Its output is `docs/generated/providers.md`. The first line is `Generated by scripts/generators/providers.py. Do not edit.` It has a table "Packs" with one row per pack in the order of the folder names, a section "Pack <name>" per pack with one row per shown field, a table "Regions" and a table "Flavors". The output is written only by running the generator, never by hand. It carries no value that CI writes on `main` (no chart version, no pin, no image tag): the pack declarations and the cloud profiles hold none.
5. The generator names no cloud, neither on a code line nor on a comment line. The provider-leak scanner `scripts/check-provider-leaks.py` reads it as shared code, and its baseline `scripts/provider-leak-baseline.tsv` has no line for it and gets none.
6. `infra/providers/_contract/generated-files.txt` gains exactly one line at its end, `docs/generated/providers.md`. Its existing line `products/catalyst/bootstrap/api/internal/providers/all/all.go` stays.
7. No workflow changes. `check-generated-docs` finds the new generator by its file name (its own comment says: "A new generator needs no change here").
8. Nothing else changes: no pack declaration, cloud profile, schema, other generator, other generated file or document.

        value = lookup(document, field)
        if value is not MISSING and not isinstance(value, list):
            raise InputError("%s: %s is not a list" % (relative, field))
    return document


def read_packs(root):
    folder = os.path.join(root, PACKS)
    try:
        names = sorted(name for name in os.listdir(folder)
                       if os.path.isdir(os.path.join(folder, name)) and not name.startswith(("_", ".")))
    except OSError as error:
        raise InputError("%s: cannot be listed: %s" % (PACKS, error.strerror))
    if not names:
        raise InputError("%s: has no pack folder" % PACKS)
    packs = []
    for name in names:
        pack = load(root, "%s/%s/pack.yaml" % (PACKS, name), "ProviderPack", name, PACK_FIELDS)
        profile = load(root, "%s/%s/profile.yaml" % (PACKS, name), "CloudProfile", name, PROFILE_FIELDS)
        packs.append((name, pack, profile))
    return packs


def listed(values):
    """A list as code words joined by commas, or a dash when it is empty or not set."""
    if values is MISSING or not values:
        return "-"
    return ", ".join(code(show(v)) for v in values)


def scalar(value):
    """A single value as code, `-` when it is empty, `not set` when the file does not set it."""
    if value is MISSING or value is None:
        return NOT_SET
    if value == "":
        return "-"
    return code(show(value))


def needs_installation(profile):
    return lookup(profile, "spec.requiresInstallation") is True


def count_or_installation(profile, path):
    values = lookup(profile, path)
    if not values and needs_installation(profile):
        return FROM_INSTALLATION
    return str(len(values))


def credential_fields(fields):
    shown = []
    for field in fields:
        if not isinstance(field, dict) or "key" not in field:
            raise InputError("a credential field has no key")
        marks = ["secret" if field.get("secret") is True else "not secret",
                 "required" if field.get("required") is True else "optional"]
        shown.append("%s (%s)" % (code(field["key"]), ", ".join(marks)))
    return ", ".join(shown) if shown else "-"


def defaults(value):
    if value is MISSING or value is None:
        return NOT_SET
    if not isinstance(value, dict):
        raise InputError("spec.compute.defaults is not a mapping")
    return "control plane %s, worker %s" % (scalar(value.get("controlPlaneFlavor", MISSING)),
                                             scalar(value.get("workerFlavor", MISSING)))


def size(value):
    if not isinstance(value, dict):
        return NOT_SET
    return "%s vCPU, %s GiB" % (show(value.get("vcpu", "?")), show(value.get("memoryGiB", "?")))


def minimum_flavor(value):
    if value is MISSING or value is None:
        return NOT_SET
    if not isinstance(value, dict):
        raise InputError("spec.compute.minimumFlavor is not a mapping")
    return "control plane %s; worker %s" % (size(value.get("controlPlane")), size(value.get("worker")))


def image(profile):
    value = lookup(profile, "spec.compute.image")
    if value == "" and needs_installation(profile):
        return FROM_INSTALLATION
    return scalar(value)


def price(value):
    if not isinstance(value, dict):
        return "-"
    return "%s %s per %s" % (number(value.get("amount", "?")), cell(value.get("currency", "?")),
                             cell(value.get("per", "?")))
