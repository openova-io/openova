# CMP-016 — An optional informer kind starts when its definition arrives

## In plain words

**The problem today.** The API watches some kinds only if the cluster serves them at the moment the cluster is added. A kind whose definition is installed later, for example by a chart upgrade, is never watched until the API restarts, so its objects never reach the screens.

**What changes.** The API remembers each kind it skipped. When the definition of that kind arrives on the cluster, the API starts watching the kind at once, without restarting and without polling.

**Done means:**

- A kind skipped at cluster add is watched as soon as its definition appears on the cluster, without a restart of the API.
- Objects of that kind, old and new, reach the live event stream and the list views.
- A definition that does not yet serve the kind's version starts nothing, and a later change that serves it starts the watch.
- A second event of the same definition starts nothing twice.
- No timer and no repeated discovery call is added, and kinds that are always present behave as before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The catalyst-api watches the objects of every kind in its registry through one informer per kind and cluster. A kind marked `Optional` is probed once when its cluster is added, and skipped when the cluster does not serve it. After this ticket the skipped kind is remembered for that cluster, and the event of its CustomResourceDefinition (ADDED or MODIFIED, delivered by the `customresourcedefinition` informer that every cluster already runs) starts the kind's informer as soon as the definition serves the kind's version. `Factory.List` then serves the kind, existing objects are listed, and new objects reach every subscriber of the event stream. Nothing polls and nothing restarts.

## 3. The model (the law)
1. When `AddCluster` skips an optional kind because discovery does not serve its GVR, it records the kind in a new per-cluster map `skippedOptional map[string]Kind`. The key is `<group>/<resource>` (function `optionalKey`). The existing log line `k8scache: skipping optional kind — GVR not served` stays.
2. `dispatch` calls `startOptionalOnDefinition` for every event of the kind whose GVR is group `apiextensions.k8s.io`, resource `customresourcedefinitions`, when the event type is `ADDED` or `MODIFIED`. The call runs before the event is fanned out to subscribers.
3. `startOptionalOnDefinition` reads `spec.group` and `spec.names.plural` of the definition. If `skippedOptional` holds that key, and one entry of `spec.versions` has `name` equal to the kind's version and `served: true`, it removes the key, builds the kind's informer with the same handlers as every other kind, starts it with `cs.factory.Start(cs.stop)`, starts a sync-watcher for that one kind, and logs one line `k8scache: optional kind started after its definition arrived` with the cluster, the kind and the GVR. Otherwise it does nothing and the key stays.
4. A kind starts at most once per cluster registration: the key is removed before the informer is built, so a second definition event finds nothing to start.
5. A cluster whose stop channel is closed (removed, superseded or quarantined) starts nothing.
6. Nothing else starts a skipped kind: no timer, no retry loop, no second discovery call. `AddCluster` makes no new network call.
7. The building of one kind's informer and its handlers moves from the `AddCluster` loop into one method, `addKindInformer`, used by both paths.
8. `cs.informers` and `cs.indexers` can now gain an entry while informers run. A new per-cluster lock `kindsMu` guards both maps and `skippedOptional`. Every reader that can run while informers run reads through `informersSnapshot`, `indexersSnapshot` or `indexerFor`. This covers `List`, `RemoveCluster`, the two log lines of `AddCluster`, `startClusterInformers`, `GetResourcesByOwner` and `GetResourcesBySelector` in `tree.go`, `snapshotOnce` in `snapshot.go` and `hydrateAll` in `hydrate.go`.
9. `runSyncWatcher` takes the informers it watches as a parameter. `startClusterInformers` passes a copy taken before `cs.factory.Start`, so a kind added later is watched only by its own sync-watcher.
10. Unchanged: the bounded discovery probe of optional kinds, every kind that is not optional, the fields of `Event` (the wire format of the event stream), the registry in `kinds.go`, and the names of the fields `informers` and `indexers` that existing tests read.
11. Nothing is deleted.
