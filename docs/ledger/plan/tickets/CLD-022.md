# CLD-022 — Delete the infrastructure mutation dialogs from the console

## In plain words

**The problem today.** The sovereign-admin console offers dialogs that add, edit, scale and delete single regions, clusters, vClusters, node pools, worker nodes, load balancers, networks, volumes, volume claims and buckets. They call API routes that write claims under an API group that nothing in the platform defines or reconciles, so every such dialog promises a change that never happens. The dialogs, their client library and the tests that assert them keep that false surface alive.

**What changes.** The add, edit and delete dialogs, their form parts and their client library are deleted and recorded as deleted. The cloud list pages and the architecture graph keep their read-only tables, drawers and panels; only the deployment delete and wipe dialogs remain. The tests, the browser test workflow, the allowed lint error count and the provider-name baseline follow the removal.

**Done means:**

- No cloud list page shows a New button, a row action menu or edit and delete buttons in its detail drawer.
- A right-click on the architecture graph opens no menu, and only the Cloud root's panel offers an action: the deployment wipe.
- The deployment delete dialog of the deployments list and the deployment wipe dialog still open.
- The console builds and all its unit tests pass.
- The removed files are on the list of deleted paths, so a guard fails if one of them comes back.
- The console's allowed lint error count is two lower, and five lines leave the provider-name baseline, because the removed code held those findings.

The rest of this ticket is the exact instruction for the model that does the work.
