# CLD-161 — Installation document for the installation in use

## In plain words

**The problem today.** Later work takes the endpoints, region, image and machine sizes of the cloud installation in use out of the cloud module and reads them from an installation document instead. Nothing in the platform can check such a document against the cloud profiles, or put it into the form in which a cluster keeps it. The document would be written and applied by hand, unchecked, and its readers would have to guess where it is kept.

**What changes.** A small command checks an installation document against the cloud profiles of the repository and prints the ConfigMap that carries it. The namespace, name, label and key of that ConfigMap are fixed once, in the Go package that reads cloud profiles.

**Done means:**

- A valid installation document gives a ConfigMap in the namespace catalyst-system, labelled catalyst.openova.io/cloud-installation=true, with the document unchanged under the key profile.yaml.
- A document that extends no known cloud pack, sets a field an installation may not set, or lacks a region, an image or a machine size is refused with the field it got wrong, and no ConfigMap is printed.
- The command only reads files: it writes nothing and talks to no cluster.
- No installation document is stored in the repository.
- The new tests run in the pull-request checks of the API module and pass.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A person who holds the installation document of a cloud installation (a file kept outside this repository) runs one command of the API module on it. The command checks the document against the cloud profiles under `infra/providers` with the merge rules of package `cloudprofile`. If the document is valid, the command prints the ConfigMap that carries it on a cluster: namespace `catalyst-system`, name `cloud-installation-<metadata.name of the document>`, label `catalyst.openova.io/cloud-installation: "true"`, the document unchanged under the key `profile.yaml`. That person then applies the printed ConfigMap with their own cluster access. If the document is not valid, the command prints the field that is wrong and prints no ConfigMap. The place of the ConfigMap is fixed as Go constants that the later readers use. This ticket writes the command and its tests. It writes no installation document and applies nothing.

## 3. The model (the law)
1. An installation document has the kind `CloudProfile`, sets `spec.extends` to the name of a pack under `infra/providers`, and may set only the installation fields that `Merge` in `products/catalyst/bootstrap/api/internal/cloudprofile/cloudprofile.go` allows. It is checked by merging it over that pack's profile with `Merge`. This ticket does not change these rules.
2. On a cluster, an installation document is kept in exactly one ConfigMap: namespace `catalyst-system`; name `cloud-installation-` followed by the document's `metadata.name`; one label, `catalyst.openova.io/cloud-installation` with the value `"true"`; one data key, `profile.yaml`, whose value is the document byte for byte. These four values are the constants `InstallationNamespace`, `InstallationConfigMapPrefix`, `InstallationLabel` and `InstallationKey` of package `cloudprofile`, in the new file `installation.go`.
3. `CheckInstallation(dir, data)` loads the pack profiles below `dir`, parses `data`, finds the pack named by `spec.extends`, and returns the effective profile from `Merge`. A document without `spec.extends` is refused with `ErrMissingField`; one whose `spec.extends` names no pack below `dir` with `ErrUnknownPack`. Every other refusal is the one `Merge` gives.
4. `InstallationConfigMap(dir, data)` calls `CheckInstallation` and returns the ConfigMap of rule 2 as YAML. It returns no ConfigMap when the check fails, or when the ConfigMap name would be longer than 253 characters (`ErrBadValue` at `metadata.name`).
5. The command `products/catalyst/bootstrap/api/cmd/cloud-installation` is run as `cloud-installation -providers <providers directory> <installation document>`. Exit code 0: the ConfigMap is on standard output. Exit code 1: the document is refused; the reason, with its field path, is on standard error and standard output is empty. Exit code 2: a usage error or a file that cannot be read.
6. The command and the package read files only. They write no file, run no cluster client and open no network connection.
7. No installation document is stored in this repository. The tests use neutral values only (`example-cloud.test`, `region-1`, `192.0.2.0/24`, an all-zero image identifier).
8. No existing file changes. The command is not built into the API image.

package cloudprofile

import (
	"fmt"
	"strconv"

	"sigs.k8s.io/yaml"
)

// Where an installation document is kept on a cluster: one ConfigMap per
// document, in InstallationNamespace, named InstallationConfigMapPrefix
// followed by the document's metadata.name, labelled InstallationLabel with
// the value "true", and holding the document, unchanged, under the key
// InstallationKey. A reader lists the ConfigMaps of the namespace by the label
// and reads the key. The document itself is never stored in this repository.
const (
	InstallationNamespace       = "catalyst-system"
	InstallationLabel           = "catalyst.openova.io/cloud-installation"
	InstallationKey             = "profile.yaml"
	InstallationConfigMapPrefix = "cloud-installation-"
)

// maxConfigMapName is the longest name a ConfigMap may have.
const maxConfigMapName = 253

// CheckInstallation reads the pack profiles below dir with Load, parses the
// installation document data, and merges it over the pack profile that its
// spec.extends names. It returns the effective profile, or the first error
// (a *FieldError for every fault of the document).
func CheckInstallation(dir string, data []byte) (*Profile, error) {
	inst, err := Parse(data)
	if err != nil {
		return nil, err
	}
	packs, err := Load(dir)
	if err != nil {
		return nil, err
	}
	if inst.Spec.Extends == "" {
		return nil, &FieldError{Err: ErrMissingField, Path: "spec.extends"}
	}
	pack, ok := packs[inst.Spec.Extends]
	if !ok {
		return nil, &FieldError{Err: ErrUnknownPack, Path: "spec.extends", Detail: strconv.Quote(inst.Spec.Extends)}
	}
	return Merge(pack, inst)
}

// InstallationConfigMap checks the installation document data with
// CheckInstallation and returns, as YAML, the ConfigMap that carries it on a
// cluster. It returns no ConfigMap when the document fails the check.
func InstallationConfigMap(dir string, data []byte) ([]byte, error) {
	eff, err := CheckInstallation(dir, data)
	if err != nil {
		return nil, err
	}
	name := InstallationConfigMapPrefix + eff.Metadata.Name
	if len(name) > maxConfigMapName {
		return nil, &FieldError{Err: ErrBadValue, Path: "metadata.name", Detail: fmt.Sprintf("the ConfigMap name %q is longer than %d characters", name, maxConfigMapName)}
	}
	cm := map[string]any{
		"apiVersion": "v1",
		"kind":       "ConfigMap",
		"metadata": map[string]any{
			"name":      name,
			"namespace": InstallationNamespace,
			"labels":    map[string]any{InstallationLabel: "true"},
		},
		"data": map[string]any{InstallationKey: string(data)},
	}
	return yaml.Marshal(cm)
}
