# BSS-030 — Order capture never prices from a second list

## In plain words

**The problem today.** The storefront sells packages from one published price book, but an order that names no package is still priced from the older catalog plan list, which carries other prices. A customer whose browser did not load the price book is billed from that second list, and nobody notices. Nothing checks on a running Sovereign that only one price list sells.

**What changes.** While the price book publishes packages, an order without a package is refused with a clear answer instead of being priced from the catalog. Only while the price book publishes nothing, as on a fresh Sovereign before its first Organization, does the catalog still price the order. A new required gate check asks a running Sovereign for such a quote and judges the answer.

**Done means:**

- A quote or an order without a package is refused with HTTP 409 and the error package-required while the price book publishes packages, and the catalog is not asked.
- While the price book answers 404 or lists no package, such a quote or order is priced from the catalog as before, so a fresh Sovereign still sells.
- When the price book cannot be read, such a quote or order is refused with HTTP 503, before a voucher or an order is touched.
- An order that names a package while the price book publishes none is refused with HTTP 422 naming the package.
- The gate check BSS-G02 is required, and it fails when a Sovereign that publishes packages prices a quote without a package from another list.
- The README of order capture states these answers.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Order capture (`core/services/billing`) has one price list at any time. While the BSS price book (`GET <CHARGEBACK_PUBLIC_URL>/api/v1/public/packages`) publishes packages, a quote or a checkout that carries no `package_sku` is refused with HTTP 409 and the body `{"error":"package-required"}`, and the catalog plan list is not read. While the price book publishes no package (it answers HTTP 404, the state of every fresh Sovereign before its first Organization, or it lists no package), such an order is priced from the catalog exactly as today. When the price book cannot be read, such an order is refused with HTTP 503 "prices unavailable". An order that carries a `package_sku` while the price book publishes no package is refused with HTTP 422 naming the package. The acceptance suite has the gate check BSS-G02 "One price list", in state `required`: on a running Sovereign it reads the price book, takes the cheapest plan of the storefront's plan deck, asks for a quote without a package, and judges the answer.

## 3. The model (the law)
1. `core/services/billing/packages/packages.go` has `var ErrNoPackages = errors.New("price book publishes no packages")`. `Client.fetch` returns it for an HTTP 404. `Parse` returns it for a document whose `packages` list is empty or absent. `Client.Get` returns it as it is: `errors.Is(err, packages.ErrUnavailable)` is false for it, and the result is not kept in the cache. Every other failure of `Get` is wrapped in `ErrUnavailable`, as today.
2. `core/services/billing/handlers/handlers.go` has `var errPackageRequired = errors.New("package required")`. `pricingErrorResponse` maps it to HTTP 409 with the body `{"error":"package-required"}`.
3. At the top of `priceFromCatalog`, so that both of its callers (`priceOrder` and `computeOrderTotal`) are covered: when `h.Packages.Configured()` is true, it calls `h.Packages.Get(ctx)`. A nil error (the price book publishes packages) returns `errPackageRequired`. An error for which `errors.Is(err, packages.ErrNoPackages)` holds goes on to the catalog path as today. Any other error is returned as it is and maps to 503. When `Configured()` is false, the catalog path runs as today.
4. In `priceFromPackages`, an error of `h.Packages.Get` for which `errors.Is(err, packages.ErrNoPackages)` holds returns `packages.Refused(req.PackageSKU, "", ...)`, which maps to HTTP 422 naming the package. Every other error is returned as today (503).
5. The catalog path is not removed, and no setting turns the refusal off. An HTTP 404 of the price book is never treated as an outage: it is the state of every fresh Sovereign, and treating it as an outage would refuse the first sale.
6. Tests: `packages_test.go` proves that 404 and an empty list give `ErrNoPackages`, unwrapped and not cached, and that a 500 gives `ErrUnavailable`. `checkout_bss_test.go` proves, on the quote route and on the checkout route, the four cases of item 3 (published: 409 and the catalog is not asked; 404: the catalog price; empty list: the catalog price; connection refused: 503), and the 422 of item 4. Two tests that asserted "the price book is never consulted on an order without a package" contradict item 3 and are changed: the price book there answers 404.
7. Gate check BSS-G02 is the file `tests/acceptance/sovereign/internal/suite/check_bss_price_list.go`, which calls `RegisterCheck` in `init()`. The name of the Sovereign is the value `sovereignFQDN` of discovery step D0.1, read with the function `sovereignFQDN` (after FND-034); without it the check fails and makes no request. It makes three anonymous requests, the ones the storefront makes:
   - `GET https://chargeback.<fqdn>/api/v1/public/packages`. HTTP 404, or HTTP 200 with no package, is the state `none`. HTTP 200 with packages is the state `published`. Any other answer, or a body that is not JSON, fails.
   - `GET https://marketplace.<fqdn>/api/catalog/plans?product=generic`. The cheapest plan without a `product_slug` is taken; its package is `plan.<slug>`.
   - `POST https://marketplace.<fqdn>/api/billing/quote` with the body `{"plan_id":"<id>","apps":[],"addons":[],"topology":"single-region","overage_mode":"capped"}`: the storefront's body for a cart that holds only that plan, with no `package_sku`.
   In the state `published` the check passes on HTTP 409 with the error `package-required`, or on HTTP 200 with an `amount_baisa` equal to the `price_month` of the package `plan.<slug>` in baisa. A 200 when the price book does not list `plan.<slug>` fails. In the state `none` it passes on HTTP 200. The evidence holds the state, the status of each answer, the plan, the price of the price book and the amount of the quote.
8. In `docs/ledger/gates.yaml` the entry BSS-G02 moves from `state: not-built` to `state: required` and gains the line `implementation: tests/acceptance/sovereign/internal/suite/check_bss_price_list.go`. No other line of the file changes.
9. `core/services/billing/README.md` states the answers of items 3 and 4 in its section on the fallback and in its table of answers.

+func priceListBaisa(s string) (int64, error) {
+	whole, frac, _ := strings.Cut(strings.TrimSpace(s), ".")
+	if whole == "" || len(frac) > 3 || strings.Trim(whole+frac, "0123456789") != "" {
+		return 0, fmt.Errorf("price %q is not an amount with at most 3 decimals", s)
+	}
+	n, err := strconv.ParseInt(whole+frac+strings.Repeat("0", 3-len(frac)), 10, 64)
+	if err != nil {
+		return 0, fmt.Errorf("price %q: %w", s, err)
+	}
+	return n, nil
+}
