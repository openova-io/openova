# CMP-023 — The policies route shows the mode the engine carries after the audit window, and CMP-G02 reads namespaced policies

## In plain words

**The problem today.** The compliance API shows some policies as permissive although the engine object of each one carries enforce, and the difference grows as the audit window flips more policies to enforce. The API kept the mode in its own copy, fed only by change events, and an event that is dropped or sent before the API listens is never sent again. The gate check that compares the two also cannot find any per-Organization policy, because it reads cluster-wide policy kinds only.

**What changes.** The API reads the mode from the store the watch keeps exact, not from the events. The gate check reads the namespaced policy kinds in every namespace and finds a per-Organization policy in its own namespace.

**Done means:**

- A policy whose engine object carries enforce is listed as enforcing by the policies route, also when the route never received the event of that change.
- A policy whose change event was dropped because the API was busy is listed with the mode its engine object carries now.
- When two policy kinds hold the same name, the route shows the legacy object, as before.
- The gate check compares a policy listed as namespace/name with the object of that name in that namespace, and reports a difference of mode for it.
- A namespaced name is never matched with a cluster-wide object, and a bare name never with a namespaced one.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`GET /api/v1/sovereigns/{id}/compliance/policies` lists, for every policy of a cluster the API's informer cache holds, the mode its engine object carries in the informer store at the time of the request, and the per-resource findings take their policy metadata from the same store. The event-fed copy of the metadata stays only for a cluster the cache does not hold. Gate check CMP-G02 (`tests/acceptance/sovereign/internal/suite/check_compliance_mode.go`) reads `policies.kyverno.io`, `namespacedvalidatingpolicies.policies.kyverno.io` and `namespacedmutatingpolicies.policies.kyverno.io` with `-A` and compares a listed `<namespace>/<name>` with the object of that name in that namespace, in that order of kinds.

## 3. The model (the law)
1. The stale side is the route's copy, not the mode reader. `adapters.PolicyMode` (`internal/compliance/adapters/policymode.go`) reads the fields the chart renders and the check reads; it is unchanged.
2. `adapters.PolicyObjects(store, cluster, read)` lists the objects of each kind of `PolicyMode{}.Kinds()` from the store, the legacy kind first, and returns by name what `read` accepts; the first kind that holds an accepted object of a name gives the entry. It returns `held == false` for a cluster the store does not hold. A kind whose `List` fails gives no object.
3. `ComplianceHandler.policyMetaOf(cluster)` returns `adapters.PolicyObjects(c.k8sCache, cluster, policyMetaFrom)` when the cache holds the cluster, else a copy of `policyMetaByName[cluster]`. `policiesFor` and `resourceComplianceFor` read it; neither reads `policyMetaByName` directly any more.
4. `ingestEnginePolicy` becomes the pure function `policyMetaFrom(obj) (policyMeta, bool)`; `onEvent` calls it and keeps feeding `setPolicyObject`, so the event-fed copy and its legacy-first rule stay for a cluster the cache does not hold.
5. CMP-G02 keys a namespaced object `<namespace>/<name>`. A listed name with a slash is looked up in the namespaced kinds only; a name without a slash in the cluster-wide kinds only. A namespaced kind the cluster does not serve holds no object; a namespaced kind that cannot be read fails step 2 of the check.
6. Nothing is deleted; no chart, no go.mod and no Kyverno policy changes.
