# SVC-166 — The umbrella chart's Blueprint file moves beside its chart

## In plain words

**The problem today.** The Blueprint file of the umbrella chart lives in a platform folder of its own, with no chart beside it and the placeholder version 0.0.0. A mapping file must tell the catalogue generator where its chart is, and the catalogue that the console reads shows the version 0.0.0.

**What changes.** The file sits beside its chart and carries the chart's version, which the release workflow keeps in step. The mapping entry is gone, and the seed object still takes its version from the chart it is part of.

**Done means:**

- The folder platform/catalyst-platform does not exist and is on the list of deleted paths; products/catalyst/blueprint.yaml declares bp-catalyst-platform.
- The Blueprint file's version equals the umbrella chart's version at the commit that added it, and the console's catalogue shows that version instead of 0.0.0.
- The mapping file names no Blueprint, and the seed object of bp-catalyst-platform still carries the version of the chart it is rendered from.
- The catalogue files and the component list are what their generators write.
- The version sweep test passes while the umbrella chart is ahead of its Blueprint, as main is between an image build and the release writer's commit, and fails when the Blueprint is ahead of its chart.
- The guard that runs the release writer expects the umbrella Blueprint file to move to the chart's version, and passes.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. **Moved, not copied.** The file is renamed; its content is the same except four comment lines at its top and the version line. The folder `platform/catalyst-platform` holds no other file, so it is gone, and its path is appended to `docs/ledger/deleted-paths.txt`.
2. **The version is set once, here.** The version line becomes the chart's version, by the same `sed` expression that the release writer uses on a Blueprint file. A version line in an added file is not a release-owned line. From the next umbrella release on, the release writer keeps it.
3. **The seed object carries its chart's version.** The seed is a template of the umbrella chart, so the umbrella's own seed object takes `{{ .Chart.Version | quote }}`, which Helm renders to the version of the chart it is part of. Until now one mapping entry gave the generator that chart folder; now the folder beside the file gives it. The generator names no Blueprint: the rule reads the chart folder (beside the file, or the mapped one) and compares it with the chart that holds the seed. A literal version in the seed would trail the published chart by one release, because the release writer moves the Blueprint file after it has published the chart.
4. **The umbrella Blueprint may lag its chart, never pass it.** The image builds raise the umbrella chart's version on `main` many times a day (`deploy(bp-catalyst-platform): bump chart version`), and the release writer moves the Blueprint file after them. `TestBootstrapKit_BlueprintVersionLockstepSweep` in `tests/e2e/bootstrap-kit/main_test.go` now covers the pair `products/catalyst`; for that pair it accepts a Blueprint version at or below the chart's and fails on one above it. Every other pair keeps the equality rule.
5. **The release-writer guard expects the move.** In `scripts/check-release-lockstep-writer.py` the three cases on `products/catalyst` (`umbrella`, `umbrella-defer`, `dispatch-umbrella`) expect site 2, the Blueprint file, to be `literal` (equal to the chart's version in what the writer pushes) instead of `absent`. The two texts that said the umbrella has no Blueprint file (the docstring of the control and the description of the case `umbrella`) say instead that only site 3 is a no-op, in the same number of lines. Nothing else of that file changes.
6. **The catalogue follows its source.** `blueprints.json` and `catalog.generated.ts` are written only by `python3 scripts/generate-catalog.py`, and `docs/generated/components.md` only by `python3 scripts/generators/components.py`.
