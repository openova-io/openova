# FND-051 — Billing-engine and tool-server tests run on pull requests

## In plain words

**The problem today.** The tests of the billing engine and of the tool server run only after a change is already merged. A change that breaks them is found too late.

**What changes.** Both sets of tests run on the pull request, before the merge. A pull request builds and tests, and publishes no image.

**Done means:**

- A pull request that changes the billing engine or the tool server runs that product's tests.
- A failing test turns the pull request red.
- No image is published from a pull request.
- After the merge, a push to the main branch builds and publishes exactly as today. A run started by hand builds and tests and publishes nothing.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. Each of the two workflow files has a `pull_request` trigger. Its `paths` list is equal to the `paths` list of the `push` trigger of the same file.
2. Two steps publish. In both files they have the same names: `Login to GHCR` and `Push image (only after smoke gate is green)`. Each of these two steps carries the condition `if: github.event_name == 'push'`.
3. No other step carries a condition. Every test step, build step and smoke step runs on every event.
4. On a push to `main` every step runs, as today. The `push` trigger keeps `branches: [main]`, so only a push to `main` publishes an image.
5. A manual run (`workflow_dispatch`) builds, tests and smoke-tests, and pushes nothing. Before this ticket a manual run pushed an image. This change is intended.
6. The word `pull_request` stands on exactly one line of each file: the trigger line. No comment and no condition contains that word. Acceptance checks A1 and A2 count it.
7. No step gets `continue-on-error`. The two workflows are not split. No `merge_group` trigger is added.
