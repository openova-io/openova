# FND-130 — The gate suite runs on the local provider pack on every pull request

## In plain words

**The problem today.** The local provider pack comes up in CI with two regions and the console, but the gate checks never run on it. Its workflow runs only when the pack's own files change, so most pull requests are merged without any check on a running platform, and the ruleset of main does not require it.

**What changes.** The workflow runs on every pull request and every merge group, and after the pack is up it runs the acceptance suite on it with the checks that list the local pack. The job fails unless the suite's record passes, and the ruleset of main names the job as a required check.

**Done means:**

- The check conformance-local runs on every pull request and on every merge group, whatever files the change touches.
- On the local pack the job runs the acceptance suite with the gate checks that list local, requests no journey, and fails when a discovery step or a required check does not pass.
- The suite's record is checked for its form, uploaded as the artifact conformance-local-record of the run, and never committed.
- The file of the ruleset of main lists conformance-local among its required status checks exactly once.
- The check conformance-local is green on the pull request of this task.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket the check `conformance-local` runs on every pull request and every merge group, with no path filter. After the local provider pack is up with two regions, its discovery steps D0.1 and D0.2 pass and a claim binds (all three as `CLD-089` left them), the job runs the acceptance suite `tests/acceptance/sovereign` on the pack through `scripts/acceptance-sovereign.sh`: in the place `local`, with the gate manifest of the commit under test, with no journey, and with the capability `multi-region`. The job checks the record with `scripts/acceptance-gate.py validate-record`, uploads it as the artifact `conformance-local-record` (it is never committed), and fails unless the record's `result` is `PASS`. `.github/rulesets/main.json` lists `conformance-local` among the required status checks. A person sees the check `conformance-local` green on the pull request of this ticket, with the suite's table in the summary of the job and the record in the artifact of the run.

## 3. The model (the law)
1. **One workflow, no mode.** The suite runs in the one job `conformance-local` of `.github/workflows/conformance-local.yaml`, on the pack that the job brought up. There is no second workflow, no mode variable (`CONFORMANCE_LOCAL_MODE` or any other), no report-only mode and no `continue-on-error`.
2. **Every pull request, every merge group.** The workflow is triggered by `pull_request` with no `paths` filter, by `merge_group` and by `workflow_dispatch`. The ruleset of main requires the job by its name, and a check that did not run is not green.
3. **What the run selects.** The suite runs as `run` with `--run-in local` and `--manifest` set to the export of `docs/ledger/gates.yaml` of the commit under test. It then selects every check whose entry is `expected-fail` or `required`, lists `local` in `runs_in` and is implemented by a Go file of the suite. A check implemented by a script (`CLD-G02`, `CLD-G03`, `CLD-G11`) is proven by its own job and is not selected.
4. **No journey.** The run passes `--journeys ''`. A run that requests no journey leaves out the discovery steps D0.3, D0.4 and D0.5 (`FND-131`). An empty `ACCEPT_JOURNEYS` is not used, because the suite reads an empty variable as its default list.
5. **Capability.** The run declares `--capabilities multi-region`, because the pack has two regions; a run declares a flag when its environment has the capability. No other flag is declared.
6. **Inputs from the pack.** The console address, the deployment id, the region codes and the session file come from the env file `$RUNNER_TEMP/local-pack/env` that `scripts/local-pack.sh up` writes. The kubeconfig of each region is `$RUNNER_TEMP/local-pack/<region code>.kubeconfig`. The session is read from its file into `CATALYST_SESSION` and never printed.
7. **The record.** The suite writes exactly one record into `$RUNNER_TEMP/acceptance`, never into the checkout. The job uploads it, with the suite's log, as the artifact `conformance-local-record`, also when the run failed. It is never committed.
8. **Pass rule of the job.** The job fails when the suite exits with a code other than 0, when it wrote other than one record, when `scripts/acceptance-gate.py validate-record` refuses the record, or when the record's `result` is not `PASS`. The suite makes the result `FAIL` when a discovery step does not pass or a `required` check does not pass; an `expected-fail` check never fails the run.
9. **Required in the ruleset.** `.github/rulesets/main.json` holds `{"context": "conformance-local"}` once in the list `required_status_checks`, after `{"context": "vendor-disk-library"}`. Nothing else of the file changes.
10. **What stays.** Every step that `CLD-087` and `CLD-089` put into the workflow stays, with its text, in its order: checkout, free disk, OpenTofu, kubectl, Go, self-test, up, discovery, claim, collect and upload of the evidence on failure, down always. The time limit stays 60 minutes. `scripts/acceptance-sovereign.sh` and `scripts/local-pack.sh` are not changed.
11. **New action references are pinned.** The one new `uses:` line names a commit: `actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4.6.2`, the pin `.github/workflows/foundation-gate.yaml` already uses.
12. **No node port.** Nothing in the change creates a Service or publishes a port. The console address is the port forward that `scripts/local-pack.sh up` started.

````yaml
# conformance-local.yaml - the local provider pack, brought up on the runner with two regions,
# and the gate suite run on it.
#
# The local pack (infra/providers/local) starts each region's control-plane machine as a
# privileged container on the runner's own Docker and boots it with the shared template; Flux
# then installs the reduced kit clusters/_template/providers/local/kit from the commit under
# test. scripts/local-pack.sh does the work:
#   up         two regions; exit 0 only when the kit core is Ready in both, the console
#              runs in the primary region and answers on the address of the env file, an
#              owner session is minted, and the runner reaches both API servers with the
#              kubeconfigs it writes;
#   discovery  the suite tests/acceptance/sovereign passes its discovery steps D0.1 and D0.2
#              on the pack;
#   claim      a claim of 1 GiB binds on the default storage class of each region (gate
#              check CLD-G11);
#   down       removes every machine, volume and network, also when an earlier step failed.
# Then the gate suite runs on the pack through scripts/acceptance-sovereign.sh: --run-in local
# selects every check of docs/ledger/gates.yaml that is expected-fail or required, lists local
# in runs_in and is a Go file of the suite; --journeys '' requests no journey, so the discovery
# leaves out the steps that only the journeys need. The record is checked with
# scripts/acceptance-gate.py validate-record and uploaded as the artifact
# conformance-local-record; it is never committed. The job fails when the record's result is
# not PASS: a discovery step or a required check that does not pass.
# On a failure the evidence of every machine is uploaded as the artifact local-pack-evidence.
# Nothing publishes a port and nothing uses a node port.
#
# No path filter, on purpose: the ruleset of main (.github/rulesets/main.json) requires the
# job by its name, conformance-local, so it must run and pass on every pull request and every
# merge group; a check that did not run is not green.
# Charts and images come from ghcr.io at the versions the kit pins; the job token pulls them.
name: conformance-local

on:
  pull_request:
  merge_group:
  workflow_dispatch:

permissions:
  contents: read
  packages: read

concurrency:
  group: conformance-local-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: true

jobs:
  conformance-local:
    name: conformance-local
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Free disk (toolchains this job does not use)
        run: |
          sudo rm -rf /usr/share/dotnet /usr/local/lib/android /opt/ghc /usr/local/.ghcup /opt/hostedtoolcache/CodeQL
          df -h /

      - name: Install OpenTofu
        uses: opentofu/setup-opentofu@v1
        with:
          tofu_version: 1.11.6
          tofu_wrapper: false

      - name: Install kubectl
        uses: azure/setup-kubectl@v4
        with:
          version: v1.31.4

      - name: Install Go (the suite's session minter and discovery)
        uses: actions/setup-go@40f1582b2485089dde7abd97c1529aa768e1baff # v5.6.0
        with:
          go-version-file: tests/acceptance/sovereign/go.mod
          cache: false

      - name: Install PyYAML (the manifest export)
        run: python3 -m pip install --quiet pyyaml

      - name: Self-test of the script
        run: bash scripts/local-pack.sh --self-test

      - name: Up (two regions)
        env:
          GHCR_USER: ${{ github.actor }}
          GHCR_TOKEN: ${{ github.token }}
          BRANCH: ${{ github.head_ref || github.ref_name }}
          COMMIT: ${{ github.event.pull_request.head.sha || github.sha }}
        run: bash scripts/local-pack.sh up --regions 2 --branch "$BRANCH" --commit "$COMMIT"

      - name: Discovery steps D0.1 and D0.2 of the suite
        run: bash scripts/local-pack.sh discovery

      - name: Claim of 1 GiB on the default storage class (CLD-G11)
        run: bash scripts/local-pack.sh claim

      - name: Gate suite on the pack (run in local, no journey)
        id: suite
        run: |
          set +e
          set -uo pipefail
          # The step writes the suite's table into the summary before it fails, so errexit is off.
          d="$RUNNER_TEMP/local-pack"
          # The env file of up: CONSOLE_URL, DEPLOYMENT_ID, REGION_A, REGION_B, SESSION_TOKEN_FILE.
          # shellcheck disable=SC1091
          . "$d/env"
          export ACCEPT_CONSOLE="$CONSOLE_URL" ACCEPT_DEPLOYMENT_ID="$DEPLOYMENT_ID"
          export ACCEPT_KUBECONFIG_A="$d/$REGION_A.kubeconfig" ACCEPT_KUBECONFIG_B="$d/$REGION_B.kubeconfig"
          # The session is read from its file and never printed.
          CATALYST_SESSION="$(cat "$SESSION_TOKEN_FILE")"
          export CATALYST_SESSION
          python3 scripts/acceptance-gate.py export > "$RUNNER_TEMP/gates.json" || exit 1
          mkdir -p "$RUNNER_TEMP/acceptance"
          bash scripts/acceptance-sovereign.sh local-pack --record --record-dir "$RUNNER_TEMP/acceptance" \
            --run-in local --manifest "$RUNNER_TEMP/gates.json" --repo-root . \
            --capabilities multi-region --journeys '' | tee "$RUNNER_TEMP/acceptance.log"
          rc=${PIPESTATUS[0]}
          { echo '### Gate suite on the local pack'; echo; echo '```'; sed -n '/^ACCEPTANCE /,$p' "$RUNNER_TEMP/acceptance.log"; echo '```'; } >> "$GITHUB_STEP_SUMMARY"
          echo "suite exit code: $rc"
          exit "$rc"

      - name: Validate the record; its result must be PASS
        if: always() && steps.suite.outcome != 'skipped'
        run: |
          set -euo pipefail
          n="$(find "$RUNNER_TEMP/acceptance" -maxdepth 1 -name '*.json' | wc -l)"
          if [ "$n" != 1 ]; then echo "::error::The suite wrote $n records, not 1."; exit 1; fi
          rec="$(find "$RUNNER_TEMP/acceptance" -maxdepth 1 -name '*.json')"
          python3 scripts/acceptance-gate.py validate-record "$rec"
          result="$(python3 -c 'import json, sys; print(json.load(open(sys.argv[1])).get("result", "FAIL"))' "$rec")"
          echo "record $(basename "$rec"): result $result"
          if [ "$result" != PASS ]; then echo "::error::The record's result is $result, not PASS."; exit 1; fi

      - name: Upload the record
        if: always() && steps.suite.outcome != 'skipped'
        uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4.6.2
        with:
          name: conformance-local-record
          path: |
            ${{ runner.temp }}/acceptance/*.json
            ${{ runner.temp }}/acceptance.log
          if-no-files-found: warn

      - name: Collect evidence
        if: failure()
        run: bash scripts/local-pack.sh collect

      - name: Upload evidence
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: local-pack-evidence
          path: ${{ runner.temp }}/local-pack/evidence
          if-no-files-found: warn

      - name: Down
        if: always()
        run: bash scripts/local-pack.sh down
````
