# INF-140 — Vulnerability matching and daily re-matching

## In plain words

**The problem today.** The platform collects a bill of materials of every node, but nothing compares it with the list of known vulnerabilities. A node can run a package with a published vulnerability and no report shows it. A vulnerability that is published after a scan stays unseen until the machine is scanned again.

**What changes.** After every scan the bills of materials are matched against the vulnerability database, and each machine gets a vulnerability report. Once a day the stored bills of materials are matched again, so a new advisory shows within a day. A gate check reads the reports.

**Done means:**

- A node with a package that has a known advisory gets a vulnerability report with one failing result that names the release that fixes it.
- Every result of a vulnerability report names the version of the database it was matched against, and the report turns to a warning once that database is older than seven days.
- When the database cannot be fetched, the run ends failed and says that the database is unavailable, and the previous report stays in place.
- Once a day one rematch run is created for each policy that scans for vulnerabilities, and two firings for the same time create one run.
- The default scan of the nodes scans for vulnerabilities, and the chart passes the database repository and the rematch time to the controller.
- The gate check of host vulnerability reports is registered and recorded as expected to fail until the database can be reached after hand-over.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
A ScanPolicy may name the profile `vulnerability`. Every run of such a policy ends with one match Job: it fetches the vulnerability database once, runs `trivy sbom` on the bill of materials of each machine of the run, and stores one findings file per machine under `_match/<run>/` in the evidence bucket. From those files the operations controller writes the PolicyReport `machine-<machine>-vulnerability`: first the rule `database-age` (`pass` while the database is at most 7 days old, `warn` after that), then one `fail` per advisory and package, worst severity first, with `fixedVersion`, and one `pass` for each advisory fixed since the last report. Every result names `databaseVersion`, the update time of the database. A match that cannot fetch the database ends the run `Failed` with `database-unavailable` and leaves the previous report in place. Once a day, at the chart value `rematch.schedule` (`30 3 * * *` UTC), one timer of the controller creates one MachineRun of kind `rematch` per such policy; a rematch run starts no Job on a machine and matches the newest stored bill of materials of each one again. The default node scan has the profile. The chart passes `vulnerabilityDb.repository` and `rematch.schedule` to the controller. Gate check INF-G11 reads the reports, read only, and is `expected-fail`; INF-145 sets it to `required` once the database is reachable inside a Sovereign after hand-over.

## 3. The model (the law)
1. **One matcher, one database.** The matcher is Trivy, the scanner the compliance plane already runs. The match Job fetches the database from `--db-repository`, which the controller passes from `--vulnerability-db-repository` (chart value `vulnerabilityDb.repository`). An empty value means Trivy's own public repositories, which is what the scanner `bp-trivy` uses while its kit slot names none; INF-145 sets the value to the repository `bp-trivy` uses. The value is not required: the kit slot of INF-160 does not set it (the precondition of INF-145 says so), and a render failure would stop that install. No second matcher, no second database and no event subject.
2. **The profile.** `vulnerability` is a value of `ScanPolicy.spec.profiles` and implies `inventory`: a scan run of a policy with it runs the inventory task on each node even when `inventory` is not listed.
3. **The match Job.** One per run, name `JobName(<run>, "match")`, in the controller's namespace, created when every node Job of the run has ended (a rematch run: at once). One container `match`, user 65534, read-only root file system, no host mount, no node name, no token, service account `mr-node`, a disk work volume of at most 4Gi, the evidence binding as the CSI volume `evidence-store`, label `machines.openova.io/task: match`. Arguments: `--task=match --run=<ns>/<run> --sbom-keys=<key>,... --evidence-*` with prefix `_match/<run>/`, and `--db-repository` when set. The run stays `Running` until the Job has ended; `status.match` records the Job, its outcome, its message and the database version.
4. **The runner task `match`.** It has no target: `--mode`, `--machine`, `--address`, `--os-family` and `--os-version` are refused, `--sbom-keys` (1 to 1000 keys `<ns>/<machine>/<run>/sbom.cdx.json`) is required. It runs `trivy image --download-db-only --cache-dir <work>/trivy-cache [--db-repository R]` once; a failure there, or a `trivy version --format json` without `VulnerabilityDB.UpdatedAt`, ends the task `Failed` with a message that starts with `database-unavailable` and stores nothing. Then for each key: fetch the object, run `trivy sbom --format json --skip-db-update --skip-java-db-update --offline-scan`, and store `_match/<run>/<ns>/<machine>.json` (schema `openova.io/machine-vulnerability-findings/v1`). A key that cannot be read or matched gets an `error` in the index; the others are still matched. The index `_match/<run>/index.json` (schema `openova.io/machine-match-index/v1`) names each findings file with its SHA-256 and is the one file of the result document, so the document stays under 4096 bytes for any number of machines.
5. **The report.** The controller reads the index and each findings file, each checked against its SHA-256, and writes `machine-<machine>-vulnerability` in the namespace of the Machine: source `machine-vulnerability`; `policy` the advisory, `rule` the package; `severity` critical, high, medium, low or info; properties `installedVersion`, `fixedVersion`, `publishedAt`, `runName`, `evidenceKey`, `databaseVersion`. The first result is policy `vulnerability-database`, rule `database-age`. At most 200 results; a longer list is cut and annotated `machines.openova.io/results-truncated: "true"`. Labels, scope and owner as the hardening report.
6. **A failed match keeps the report.** When the Job fails, or a machine has no valid findings file, the previous report stays; its `database-age` turns to `warn` once its database is older than 7 days. The target's message gains `match: <reason>` and a target that had succeeded takes the outcome of the Job (`Failed`, `Timeout`, ...) or `Failed`; so a run whose match failed ends `Failed`.
7. **The rematch timer.** One timer, at the next time of `--rematch-schedule` (five-field cron, UTC, default `30 3 * * *`, checked at start). At each time it creates, for every valid ScanPolicy with the profile that is not suspended, one MachineRun of kind `rematch` named `RunName(<policy>, <uid>/rematch, <time>)`: the same policy and time give the same name, so two firings in one slot create one run. No ticker, no sleep. It runs on the leader only.
8. **A rematch run** of a policy without the profile is outside its policy. Its targets are the machines the policy selects; one whose Machine has no `status.sbom` ends `Refused` with `no-sbom-stored`; the others end `Succeeded` or `Failed` with the match.
9. **The chart.** The default ScanPolicy `nodes` has profiles `inventory`, `hardening`, `vulnerability`. The operations Deployment passes `--rematch-schedule=<rematch.schedule>` and, when set, `--vulnerability-db-repository=<vulnerabilityDb.repository>`. `render.sh` gains rule R15.
10. **Check INF-G11** reads, in each region, the Machines, MachineRuns and PolicyReports of `catalyst-infra`, and writes nothing. It fails without a Machine of class node; without a MachineRun of kind `scan` of the policy `nodes` in phase `Succeeded`; when a node has no report `machine-<node>-vulnerability`; when a result has no `databaseVersion`; or when `database-age` is missing or not `pass`. The manifest entry moves to `expected-fail` with its implementation.

+// sum. A file that cannot be fetched is an error, tried again; a file that does not

+func (r *RunReconciler) writeVulnerability(ctx context.Context, run *v1alpha1.MachineRun, mach *v1alpha1.Machine, t *v1alpha1.RunTarget, e runner.MatchEntry, at metav1.Time) (string, error) {
+	switch {
+	case e.Machine == "":
+		return MessageNoFindings, nil
+	case e.Error != "":
+		return e.Error, nil
+	}
+	var f runner.Findings
+	ok, err := r.readChecked(ctx, e.FindingsKey, e.SHA256, &f)
+	if err != nil {
+		return "", err
+	}
+	if !ok || f.Schema != runner.FindingsSchema || f.Machine != t.Machine {
+		return MessageResultsInvalid, nil
+	}
+	t.Evidence = append(t.Evidence, e.FindingsKey)
+	if mach == nil {
+		return "", nil
+	}
+	previous := newObject(PolicyReportKind)
+	err = r.Client.Get(ctx, types.NamespacedName{Namespace: mach.Namespace, Name: VulnerabilityReportName(mach.Name)}, previous)
+	switch {
+	case apierrors.IsNotFound(err):
+		previous = nil
+	case err != nil:
+		return "", err
+	}
+	if err := r.putReport(ctx, VulnerabilityReport(mach, run.Name, f, e.FindingsKey, previous, at.Time)); err != nil {
+		return "", err
+	}
+	if run.Spec.Kind == v1alpha1.RunKindRematch {
+		t.ReportName = VulnerabilityReportName(mach.Name)
+	}
+	return "", nil

+// DefaultRematchSchedule is the time of the daily rematch runs, in UTC: the default of
+// the chart value rematch.schedule and of the flag --rematch-schedule.
+const DefaultRematchSchedule = "30 3 * * *"
+
+// Rematcher creates, at each time of its schedule, one MachineRun of kind rematch for
+// every ScanPolicy that has the profile vulnerability, is valid and is not suspended. A
+// rematch run touches no machine: it matches the newest stored bill of materials of each
+// machine against the database again, so a new advisory reaches the reports within a day
+// of the database's update. It holds one timer, set to the next time of the schedule;
+// nothing reads state in a loop. It runs on the leader only.
+type Rematcher struct {
+	Client   client.Client
+	Schedule Schedule
+	Text     string // the schedule as written; it goes into spec.reason
+	Now      func() time.Time
+}
+
+// RematchRunName is the name of the rematch run of one policy and one time of the
+// schedule. The same policy and time give the same name, so a time is never run twice,
+// and the name differs from the name of the policy's scan run of the same time.
+func RematchRunName(policy, uid string, slot time.Time) string {
+	return RunName(policy, uid+"/"+v1alpha1.RunKindRematch, slot)
+}
+
+// Start waits for each time of the schedule and fires it, until ctx ends. A firing that
+// fails is logged; the next time of the schedule comes all the same.
+func (r *Rematcher) Start(ctx context.Context) error {
+	log := ctrl.LoggerFrom(ctx).WithName("rematch")
+	for {
+		now := r.now()
+		next := r.Schedule.Next(now)
+		if next.IsZero() {
+			return fmt.Errorf("the rematch schedule %q has no time in the next five years", r.Text)
+		}
+		timer := time.NewTimer(next.Sub(now))
+		select {
+		case <-ctx.Done():
+			timer.Stop()
+			return nil
+		case <-timer.C:
+		}
+		if err := r.Fire(ctx, next); err != nil {
+			log.Error(err, "the rematch runs of a scheduled time were not all created", "scheduledFor", next.Format(time.RFC3339))
+		}
+	}
+}
+
+func (r *Rematcher) now() time.Time {
+	if r.Now != nil {
+		return r.Now()
+	}
+	return time.Now()
+}
+
+// Fire creates the rematch runs of one time of the schedule. A run that exists already
+// is the run of that time and is left as it is.
+func (r *Rematcher) Fire(ctx context.Context, slot time.Time) error {
+	list := &unstructured.UnstructuredList{}
+	list.SetGroupVersionKind(v1alpha1.ScanPolicyKind.GroupVersion().WithKind(v1alpha1.ScanPolicyKind.Kind + "List"))
+	if err := r.Client.List(ctx, list); err != nil {
+		return fmt.Errorf("list ScanPolicies: %w", err)
+	}
+	var errs []error
+	for i := range list.Items {
+		p, err := v1alpha1.ScanPolicyFromUnstructured(&list.Items[i])
+		if err != nil || p.Spec.Suspended || !NeedsMatch(p) {
+			continue
+		}
+		if _, err := PlanOf(p); err != nil {
+			continue
+		}
+		run := &v1alpha1.MachineRun{
+			ObjectMeta: metav1.ObjectMeta{Name: RematchRunName(p.Name, string(p.UID), slot), Namespace: p.Namespace},
+			Spec: v1alpha1.MachineRunSpec{
+				Kind:        v1alpha1.RunKindRematch,
+				PolicyRef:   v1alpha1.PolicyRef{Kind: v1alpha1.ScanPolicyKind.Kind, Name: p.Name},
+				RequestedBy: v1alpha1.RequestedByController,
+				Reason:      "rematch schedule " + r.Text,
+			},
+		}
+		obj, err := v1alpha1.MachineRunToUnstructured(run)
+		if err != nil {
+			errs = append(errs, err)
+			continue
+		}
+		unstructured.RemoveNestedField(obj.Object, "status")
+		if err := r.Client.Create(ctx, obj); err != nil && !apierrors.IsAlreadyExists(err) {
+			errs = append(errs, fmt.Errorf("create MachineRun %s/%s: %w", run.Namespace, run.Name, err))
+		}
+	}
+	return errors.Join(errs...)
+}

+// readTrivyReport reads the findings of a Trivy JSON report: one per advisory, package
+// and installed version, sorted by advisory, package and version.
+func readTrivyReport(path string) ([]Finding, error) {
+	data, err := os.ReadFile(path) //nolint:gosec // a fixed name in the work folder
+	var report struct {
+		Results []struct {
+			Vulnerabilities []struct {
+				VulnerabilityID, PkgName, InstalledVersion, FixedVersion, Severity, PublishedDate string
+			}
+		}
+	}
+	if err != nil || json.Unmarshal(data, &report) != nil {
+		return nil, errors.New("trivy wrote no readable report")
+	}
+	seen, out := map[string]bool{}, []Finding{}
+	for _, r := range report.Results {
+		for _, v := range r.Vulnerabilities {
+			k := v.VulnerabilityID + "\x00" + v.PkgName + "\x00" + v.InstalledVersion
+			if v.VulnerabilityID == "" || v.PkgName == "" || seen[k] {
+				continue
+			}
+			seen[k] = true
+			out = append(out, Finding{ID: v.VulnerabilityID, Package: v.PkgName, InstalledVersion: v.InstalledVersion,
+				FixedVersion: v.FixedVersion, Severity: severity(v.Severity), PublishedAt: v.PublishedDate})
+		}
+	}
+	sort.Slice(out, func(i, j int) bool {
+		a, b := out[i], out[j]
+		if a.ID != b.ID {
+			return a.ID < b.ID
+		}
+		if a.Package != b.Package {
+			return a.Package < b.Package
+		}
+		return a.InstalledVersion < b.InstalledVersion
+	})
+	return out, nil
+}

+// severity maps a Trivy severity to the severity of a report: UNKNOWN and anything else
+// that is not critical, high, medium or low is info.
+func severity(s string) string {
+	switch s = strings.ToLower(s); s {
+	case "critical", "high", "medium", "low":
+		return s
+	}
+	return "info"
+}

+			nodes = append(nodes, m.Name())
