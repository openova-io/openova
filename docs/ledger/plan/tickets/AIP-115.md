# AIP-115 — No Organization can take the slug axon

## In plain words

**The problem today.** The Axon gateway is to run in a platform namespace named axon on the host cluster. An Organization's slug names its own namespace there, and today nothing stops a new Organization from taking the slug axon, which would take the platform namespace over. The guard that keeps the reserved lists in step with the bootstrap kit therefore turns red as soon as the Axon slot is added.

**What changes.** The word axon joins the reserved slugs of the tenant service and of the Organization kind, and the schemas bundle the console API validates with is regenerated from the kind. The Axon slot can then be added with the guard green.

**Done means:**

- Creating an Organization with the slug axon is refused, both by the tenant service and by the Organization kind.
- The reserved-slugs guard passes on a tree whose bootstrap kit has a slot in the namespace axon.
- The schemas bundle of the console API equals what the Organization kind generates, and it holds axon in the reserved list.
- No chart version and no other slug changes.

The rest of this ticket is the exact instruction for the model that does the work.
