# CLD-131 — Provider substitutes move from the template into the modules (pure move)

## In plain words

**The problem today.** The shared boot template of the control plane carries two blocks of Flux substitutes, one for each cloud, chosen by a test on the provider name. Every value that only one cloud needs sits in the shared file, so the template is not neutral and a new cloud would have to edit it.

**What changes.** Each cloud module keeps its own substitutes in a file beside its main.tf and passes the text to the template as one input; the template writes that input and has no block for one cloud. What a node boots with does not change by one byte.

**Done means:**

- The shared boot template has no block of Flux substitutes for one provider; it writes the input provider_substitutes_yaml in their place.
- The Hetzner and the Huawei module each render their substitutes from a file of their own and pass the text in every call of the template; the local module passes an empty text.
- The golden render of the template is unchanged: its check stays green with the stored values untouched.
- The boot data of every control plane is the same as before, byte for byte, for every provider and region.
- The test harness of the template, the cloud-init lint and the size check render the same substitutes as the modules.
- The self-test of the golden check still passes: the copy of the tree it renders in holds the substitutes file of every cloud.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The shared boot template `infra/providers/_shared/cloudinit-control-plane.tftpl` no longer holds the two blocks of Flux substitutes that start with `%{ if provider == "hetzner" ~}` and `%{ if provider == "huawei" ~}`. In their place it writes the new template input `provider_substitutes_yaml`: a YAML mapping of extra substitute keys, indented by zero spaces, which the template indents into the data of the ConfigMap `flux-system/sovereign-variables`. Each cloud module keeps the text of its old block, unchanged, in the new file `infra/providers/<pack>/provider-substitutes.yaml.tftpl`, renders it with `templatefile()` in every call of the shared template, and passes the result. The `local` module passes an empty text. The render harness `infra/providers/_shared/tests/render.tf`, the lint `scripts/lint-cloudinit.sh` and the size check `scripts/cloudinit-size-check.sh` render the same files. The self-test of `scripts/update-cloudinit-golden.sh`, which renders the harness in a copy of a part of the tree, copies the substitutes file of every pack into that copy. A person sees it on the pull request: the check `golden` is green and `infra/providers/_shared/tests/golden.auto.tfvars.json` is not part of the change, so every node boots with the same data as before.

## 3. The model (the law)
1. The shared template has no block of substitutes chosen by the provider name. The two blocks (52 and 130 lines of keys and comments) move out whole. No key or value is renamed, dropped or added, and every comment line moves with them; one word of one comment line of the Huawei text is reworded (the comment that says the IAM problem of the storage driver is fixed now calls it a fault). The other tests on the provider name stay; package CLD-132 replaces them.
2. The template input `provider_substitutes_yaml` is a string: a YAML mapping of substitute keys to string values, indented by zero spaces, ending with one newline. The template writes it in the data of the ConfigMap `sovereign-variables`, at the place of the old blocks (after the key `SOVEREIGN_CONFIGURED_REGIONS_YAML`, before the key `WILDCARD_CERT_ISSUER`), every line indented by twelve spaces. An empty text writes nothing, not even an empty line.
3. Each cloud pack holds its text in `infra/providers/<pack>/provider-substitutes.yaml.tftpl`. Its first six lines are a comment that says what the file is; the rest is the old block, each line with its first twelve spaces removed, and the one reworded comment word of point 1. Comment lines never reach a node: the template drops comment lines from the Flux bootstrap document before it packs it, as it did before.
4. A module renders its file with the values of the same call: the Hetzner file reads `region`, `sovereign_fqdn_slug` and `default_storage_class`; the Huawei file reads `region`, `default_storage_class`, `sovereign_region_role`, `node_external_ip_value`, `clustermesh_proxy_port` and `pdns_api_host`. Each value is the same expression the call already passes for the argument of that name.
5. The `local` module passes `""`: it writes its own substitutes into the decoded document after the render (`local.pack_substitutes`), and that does not change here.
6. Every program that renders the shared template with a map of its own passes the input as the modules do: `render.tf` and the two shell scripts render the pack's own file with the values of their fixture. No copy of the moved text exists anywhere. A program that renders the harness in a copy of a part of the tree copies the substitutes file of every pack into that copy: the self-test of `scripts/update-cloudinit-golden.sh` is the one such program.
7. The boot data is unchanged, byte for byte, for every provider, region and fixture. The golden file is not edited.

"""CLD-131: the provider substitutes move from the shared template into the modules.

Run once from the repository root. The two provider
blocks of the template are found by their opening line and the line of the key
WILDCARD_CERT_ISSUER after them, and must have the SHA-256 measured for this

import hashlib
import sys

TEMPLATE = "infra/providers/_shared/cloudinit-control-plane.tftpl"

    """The two provider blocks of the template, or None if they are not as measured."""

        return None
    return text[i:j]
