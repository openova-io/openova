# AIP-108 — Shrink Axon

## In plain words

**The problem today.** Axon still carries a second model provider, a cache service and a stored conversation history that nothing uses. They add two dependencies, three extra chart objects, a public ingress and a credential job to every install, and the later work on Axon would have to carry them along.

**What changes.** Axon serves the Claude path only. Its chart installs the gateway and its service and nothing else, and the removed files are on the deletion list so they cannot return unnoticed.

**Done means:**

- Axon compiles and its unit tests pass with no vLLM, Valkey or conversation-store code left in its source.
- Axon no longer depends on the Redis client or the UUID library, and its lock file installs cleanly without them.
- The Axon chart renders exactly one Deployment and one Service, with no provider switch, pool, conversation or cache settings.
- The single-replica guard and the agent-plane guard pass with the removed files gone from their lists, and the agent-plane counts G1, G2 and G3 are each one lower.
- The nine removed paths are on the deletion list.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. Axon has one provider, the agent kit (`src/providers/claude.ts`). There is no provider switch: no `Provider` type, no `AXON_PROVIDER`, no `vllm` settings in `src/config.ts`; `Config` is exactly `port`, `apiKeys` and `defaultModel`.
2. Axon keeps no state between requests. No conversation is stored or read: the request field `conversation_id` and the response and chunk field `conversation_id` are gone from `src/types/openai.ts`, and the route `GET /v1/conversations/:id` is gone.
3. `GET /stats` is gone: it reported only the Valkey pool numbers and the stored conversation count. The admin statistics come later on their own port (package AIP-104).
4. A completion id is `chatcmpl-` followed by `randomUUID()` from `node:crypto`, which replaces the `uuid` package; the id format (a version-4 UUID) is unchanged.
5. `GET /healthz` (liveness) and `GET /health` (readiness) stay, always answer 200, and need no bearer token; every other route still needs one.
6. The chart has exactly the templates `_helpers.tpl`, `deployment.yaml` and `service.yaml`. `values.yaml` has exactly the top-level keys `image`, `axon` and `resources`; `axon` has exactly `port`, `defaultModel`, `existingSecret` and `claudeAuthSecret`; `resources` has exactly `axon`. The credential init container, its mount and its volumes render without a condition.
7. Deleted: the three source files above; `chart/templates/valkey-deployment.yaml`, `valkey-pvc.yaml`, `valkey-service.yaml`, `ingress.yaml` and `token-refresh-cronjob.yaml`; the folder `products/axon/scripts/` (`e2e-test.sh`, `pod-up.sh`). Removing only the `valkey` values key while its templates stay makes `helm template` fail on a nil pointer, so templates and values go together.
8. The lock is npm's own resolution without the three packages: nine entries leave (`@ioredis/commands`, `@types/uuid`, `cluster-key-slot`, `denque`, `ioredis`, `redis-errors`, `redis-parser`, `standard-as-callback`, `uuid`), `debug` and `ms` gain `"peer": true` (they are now reached only through peer dependencies of the kit), and every other entry, including the `libc` fields, is unchanged.
9. Ratchets only fall: `valkey-deployment.yaml` leaves `KNOWN_TRAPPED` of `scripts/check-single-replica-rollout.py`, and G1, G2 and G3 of `scripts/agent-plane-baseline.yaml` each fall by one, written by the guard itself.
