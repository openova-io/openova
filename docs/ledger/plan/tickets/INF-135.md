# INF-135 — Lock stage machine-ops in audit

## In plain words

**The problem today.** The machine plane has kinds whose desired state is meant to live in Git: machine sources, scan policies, hardening baselines, and later maintenance windows, patch policies, test scopes and machine images. The intent lock does not cover them, so a direct write to one of them is neither counted nor warned about, and the count that must reach zero before the lock may refuse such writes does not exist.

**What changes.** The intent lock gets a group of kinds for the machine plane that only counts and warns, like every other group today. The machine records and the run records, which the machine controller writes itself, stay outside the lock.

**Done means:**

- A fresh render of the platform chart holds a binding for the machine-plane group that counts and warns and refuses nothing.
- That binding covers exactly the seven machine-plane kinds that are born in Git, and not the machine records or the run records.
- The stored list of groups records the machine-plane group as counting, so a later change can move it to refusing but never back.
- The chart test expects nine bindings, and the platform API treats the seven kinds as owned by Git.

The rest of this ticket is the exact instruction for the model that does the work.

2. Stage `machine-ops` is `audit`. No stage changes its action in this ticket. Package INF-540 moves `machine-ops` to `deny`.
3. 4. Four of the seven kinds have no definition yet (`maintenancewindows` and `patchpolicies` come with INF-450, `testscopes` with INF-510, `machineimages` with INF-620). A binding rule for a kind the API server does not serve is accepted and matches nothing, as the rules of the stages `topology` and `flux` already show on the test API server, which has neither definition. No later package adds these kinds to the lock: this ticket does.
5. The writers allowed are the Flux writers of the policy, as for every stage. The policy does not change.
6. `lockedKinds` in `clusterwrite.go` equals the union of `intentLock.resources`; `TestLockedKindsEqualTheIntentLockOfTheChart` fails otherwise. So the resource browser of catalyst-api answers `409 managed-by-git` for a direct write of the seven kinds, as it does for every locked kind.
7. All five changed files are written by one embedded tool, `INF-135-edits.py`, that replaces texts which occur exactly once. The executor writes no line by hand.
