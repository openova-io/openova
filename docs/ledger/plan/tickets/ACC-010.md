# ACC-010 — Close the default-install exposure of the access gateway

## In plain words

**The problem today.** On a default installation every user of the Sovereign's sign-in realm passes the gate of the browser access gateway. A job then enrolls each such user, every minute, in a group that holds the gateway's administrator permission, and the gateway offers a root shell on a node. The exec proxy behind the gateway accepts a shell in any namespace.

**What changes.** The gate admits only members of sovereign-admins. The enrolled group keeps read access to the seeded connection and loses every system permission. The node shell connection is turned off and removed, and the exec proxy is limited to namespace catalyst-system. A new required gate check reads all of this on the environment.

**Done means:**

- A user who is not in sovereign-admins is refused at the gate of the access gateway.
- The enrolled group of the gateway holds no system permission, and a database seeded by an earlier version loses them at the next run of the seed job or of the per-minute job.
- The default installation seeds the cluster-shell connection only, and removes a sovereign-node connection left by an earlier version.
- The exec proxy of the default installation execs only into namespace catalyst-system.
- Gate check ACC-G01 is required. It fails a region where the gate admits every user, where the gateway database holds a system permission or the node connection, or where the exec proxy is not limited.
- Every other gate instance renders exactly as before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The default installation no longer turns every signed-in user into an administrator of the browser access gateway (`platform/guacamole`). Four changes do it. (1) The generic sign-in gate (`platform/oidc-gate`) gains the per-instance value `allowedGroups`, rendered as one `--allowed-group=<group>` argument per entry; kit slot 13c sets `allowedGroups: [sovereign-admins]` on the instance `guacamole` and on no other instance. (2) The gateway's seed scripts grant the group `sovereign-admins` no system permission and delete any that an earlier version granted, on both legs (the one-shot seed Job and the per-minute CronJob). The group keeps `READ` on the seeded connections. (3) The node shell connection `sovereign-node` is off by default, and while it is off the seeder deletes it. The `cluster-shell` connection stays. (4) Kit slot 51 sets `allowedNamespaces: [catalyst-system]` on the exec proxy, so it execs only into the namespace where `cluster-shell` lands. The acceptance suite gains gate check ACC-G01 "Gateway closed by default", in state `required`; it reads these facts on every region of the environment.

+    upstream: http://grp.default.svc.cluster.local:80
+    allowedGroups: [a, b]
+  - name: open
+    upstream: http://open.default.svc.cluster.local:80
+  - name: emptylist
+    upstream: http://emptylist.default.svc.cluster.local:80
