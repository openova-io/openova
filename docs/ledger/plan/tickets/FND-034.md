# FND-034 — Checks: NodePort, front doors, mesh, encryption, clean wipe; journeys as checks

## In plain words

**The problem today.** Five facts that a Sovereign must prove are not checked by the acceptance suite: no service is reachable on a node port, every public address answers over a trusted certificate, the two regions see each other's gateways, traffic between the regions is encrypted, and the wipe of the previous installation left nothing behind. Two scripts of the repository already judge node ports and encryption, but no gate runs them. The mesh step and the five journeys run, but they are not reported as gate checks, so the list of checks still points at code that registers nothing.

**What changes.** The suite gains six check files. Two run the existing scripts and take their verdict, one asks every public address four times, one reads the counted leftovers of the wipe, and two report the mesh step and the journeys that the run has already recorded. The list of checks names the new files and marks the checks as expected to fail, so they run and are recorded and cannot fail a run yet. The suite gains two flags for the wipe, and the record carries their values.

**Done means:**

- The node-port check fails when the script finds a node port, and also when the script ends without its verdict because it could not read the cluster.
- The front-door check fails when one of four answers of a public address is a 404, an error code, or comes over a certificate that is not publicly trusted. It does not follow a redirect.
- The encryption check fails whenever the encryption script does not end with exit code 0.
- The mesh check and the three journey checks fail when the step they report is missing, failed or was skipped.
- The clean-wipe check fails when the run was not told the previous deployment and its count of leftovers, and when that count is not 0.
- The list of checks marks the eight checks as expected to fail and names their files. A failure of one of them does not fail a run.
- The tests of all the checks run on every pull request and need no cluster.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite under `tests/acceptance/sovereign/` has eight more gate checks, in six new files of `internal/suite/`, each of which registers itself. FND-G05 runs `scripts/check-live-nodeports.sh` once per region. FND-G06 asks eight public hosts of the Sovereign four times each over a publicly trusted certificate. FND-G08 reports the mesh step `D0.10` of the discovery. FND-G09 runs `scripts/check-live-node-encryption.sh` over all regions. FND-G10, FND-G11 and FND-G12 report the journeys J1 and J2, J3 and J4, and J5. FND-G13 judges the count of leftovers of the previous wipe, which the run is given by two new flags; the record carries the two values in its object `provision`, and the record tool `scripts/acceptance-gate.py` accepts them. The gate manifest `docs/ledger/gates.yaml` names the new files as the implementation of the eight checks, and the four checks that were `not-built` are `expected-fail`: a run that is given the manifest runs them and records their results, and a failure does not fail the run. The tests of all eight checks run on every pull request without a cluster.

## 3. The model (the law)
1. The nineteen files of the patch are the result of the embedded patch `FND-034.patch` and of nothing else. The patch creates twelve files and changes seven. Work step 5 states the checksum of each new file. Work step 6 states the checksum of the lines that the patch adds and removes in the seven changed files; the other lines of those files are not pinned, because other packages also change them. `docs/ledger/gates.yaml` is changed by the eight commands of work steps 8 to 15 and by nothing else: twelve lines are added and eight are removed.
2. A gate check of the suite is one file in `tests/acceptance/sovereign/internal/suite/`. It calls `RegisterCheck` in `init()` and holds the identifier of each check it registers as a string. The files are `check_nodeport.go` (FND-G05), `check_front_doors.go` (FND-G06), `check_mesh.go` (FND-G08), `check_encryption.go` (FND-G09), `check_journeys.go` (FND-G10, FND-G11, FND-G12) and `check_wipe.go` (FND-G13). Each has one test file `check_<name>_test.go`.
3. A step of a check has the identifier `<check>.<n>`, with `n` counted from 1.
4. FND-G05, No NodePort. For each region, in order, one step runs `bash <repo root>/scripts/check-live-nodeports.sh --kubeconfig <kubeconfig of the region>`, where the repository root is `CheckContext.RepoRoot` (the flag `--repo-root`). The step passes only when the script exits 0 **and** its output holds the text `OK: zero live node ports in owned namespaces across `. The script exits 0 without that line when `kubectl` is missing or the Services cannot be read (field 4); that is a failure, never a pass. Any other exit code fails the step. The check does not copy the script and does not change it.
5. FND-G09, Transit encryption. One step runs `bash <repo root>/scripts/check-live-node-encryption.sh --kubeconfig <A> --kubeconfig <B>` with the kubeconfig of every region, in region order. The exit code of the script is the verdict: 0 passes, any other code fails. The check does not copy the script and does not change it.
6. The function `runRepoScript` runs a script of the checkout with `bash`, in the working directory of the suite, so that a relative kubeconfig path means what it means to the suite. It records the script, the exit code and the last 40 lines of the output (standard output and standard error together) in the evidence. A script that is missing makes `bash` exit 127, which fails the step.
7. FND-G06, Front doors. The name of the Sovereign is the evidence value `sovereignFQDN` of step `D0.1` of the discovery, read from `CheckContext.Prior`. Without it the check fails and asks no host. The hosts are `<name>.<Sovereign name>` for the eight names of layer L5 of `scripts/sovereign-dod-verify.sh`, in this order: `console`, `api`, `auth`, `gitea`, `harbor`, `bao`, `marketplace`, `pdns`. One step per host makes four anonymous `GET https://<host>/` requests, each with a time limit of 45 seconds, over the default transport, so the certificate must be trusted by the public roots of the machine. A redirect is not followed. A host is open or closed. An open host passes only when every one of the four answers is 200, 301, 302, 303, 307 or 308. A closed host passes only when every answer is 401 or 403. Every other answer fails the step, 404 among them, and so does an error of the request (an untrusted certificate, a host that does not answer). The evidence holds each sample: its code, the issuer of the certificate, and the error. All eight hosts are open; no host is closed. A host that must refuse anonymous access is added as closed by the package that needs it.
8. FND-G08, Mesh. The check runs nothing. Its one step finds the step with journey `D0` and identifier `D0.10` in `CheckContext.Prior`. It passes only when that step exists and is PASS. A missing step, or a step that is FAIL or SKIP, fails it. The evidence of step `D0.10` is copied into the evidence of the check's step.
9. FND-G10, FND-G11 and FND-G12, the journeys. The checks run nothing. FND-G10 reports journeys J1 and J2, FND-G11 journeys J3 and J4, FND-G12 journey J5, one step per journey. A journey passes only when `CheckContext.Prior` holds at least one step of it and every one of its steps is PASS. A journey without a step fails, and a step that is FAIL or SKIP fails it: a journey that did not run has not passed. The function `priorPassed` holds this rule for items 8 and 9.
10. FND-G13, Clean wipe. The run is given two values: `--previous-deployment-id` (the deployment whose wipe this fire follows) and `--previous-wipe-orphans` (the number of its resources that a listing of the cloud account still found after the wipe). Both are given, or neither; one without the other, or a number of orphans that is not a whole number of 0 or more, stops the run before anything runs, with exit code 3. `DeploymentInfo` carries them as `PreviousDeploymentID` and `PreviousWipeOrphans`; when they were not given these are `""` and `-1`. The one step of the check fails when no previous deployment was named, when the number of orphans was not given, when the previous deployment is the deployment under test, and when the number of orphans is not 0. The manifest gives the check `needs: [previous-wipe]`, so a run that does not declare that capability records it SKIP and does not run it (this is the existing rule of the runner).
11. The record. When the two values of item 10 are given, the record holds the object `provision` with the two fields `previous_deployment_id` (string) and `previous_wipe_orphans` (whole number; 0 is written, never left out). Without them the record has no object `provision`, as before. The suite writes no other field of `provision`.
12. `scripts/acceptance-gate.py`. The table `RECORD` holds the two fields as optional fields of `provision`. `validate-record` refuses a record whose `provision` has `previous_deployment_id` without `previous_wipe_orphans`, and one whose `previous_wipe_orphans` is below 0. The self-test gains three cases and counts 108.
13. `docs/ledger/gates.yaml`. FND-G05, FND-G06, FND-G09 and FND-G13 move from `not-built` to `expected-fail` and gain an `implementation` line that names their file. FND-G08 changes its `implementation` from `discover.go` to `check_mesh.go`; FND-G10, FND-G11 and FND-G12 change theirs from `journeys.go` to `check_journeys.go`. Their state stays `expected-fail`. No other line of the file changes.
14. `tests/acceptance/sovereign/README.md` names the two flags in its table of flags, the eight checks in its table of checks, the two scripts in its section on what the suite writes, and the two fields of `provision` in its section on the record.
15. No other file of the suite changes. `journeys.go`, `match.go`, `discover.go` and `internal/kube/kube.go` are not changed. The module keeps using the Go standard library only.
16. This ticket deletes no file.

+// scriptOutputLines is how many of the last lines of a script's output the

+// runRepoScript runs `bash <root>/<script> <args>` in the working directory of
+// the suite, so that a relative kubeconfig path means what it means to the
+// suite. It returns the exit code and the output (standard output and
+// standard error together), and puts the script, the exit code and the last
+// lines of the output in ev. The error is not nil only when bash could not
+// be started.
+func runRepoScript(ctx context.Context, root string, ev Evidence, script string, args ...string) (int, string, error) {
+	path := filepath.Join(root, filepath.FromSlash(script))
+	cmd := exec.CommandContext(ctx, "bash")
+	// cmd.Args[0] is bash. The script and its arguments follow it.
+	cmd.Args = append(append(cmd.Args, path), args...)
+	var out bytes.Buffer
+	cmd.Stdout, cmd.Stderr = &out, &out
+	err := cmd.Run()
+	code := 0
+	var exit *exec.ExitError
+	switch {
+	case errors.As(err, &exit):
+		code = exit.ExitCode()
+	case err != nil:
+		return 0, "", fmt.Errorf("%s could not be started: %w", script, err)
+	}
+	text := out.String()
+	ev["script"], ev["exit_code"], ev["output"] = script, code, lastLines(text, scriptOutputLines)
+	return code, text, nil
+}

+// lastLines returns the last n lines of s that are not empty.
+func lastLines(s string, n int) []string {
+	lines := []string{}
+	for _, line := range strings.Split(s, "\n") {
+		if line = strings.TrimRight(line, " \r\t"); strings.TrimSpace(line) != "" {
+			lines = append(lines, line)
+		}
+	}
+	if len(lines) > n {
+		lines = lines[len(lines)-n:]
+	}
+	return lines
+}

+// lastLine returns the last line of s that is not empty, or "(no output)".
+func lastLine(s string) string {
+	if lines := lastLines(s, 1); len(lines) == 1 {
+		return strings.TrimSpace(lines[0])
+	}
+	return "(no output)"

+// Check FND-G13, Clean wipe: the wipe of the deployment before this one left
+// nothing behind. The suite does not count the leftovers itself. The run that
+// follows a wipe is given two values: --previous-deployment-id, the
+// deployment that was wiped, and --previous-wipe-orphans, the number of its
+// resources that a listing of the cloud account still found after the wipe.
+// The check passes when the previous deployment is named, is not the
+// deployment under test, and left 0 orphans. Without the two values it fails;
+// it never assumes 0. The manifest gives the check `needs: [previous-wipe]`,
+// so a run that does not follow a wipe records it SKIP and does not run it.
+const wipeID = "FND-G13"
+
+type wipeCheck struct{}
+
+func init() { RegisterCheck(wipeCheck{}) }
+
+func (wipeCheck) ID() string { return wipeID }
+
+func (wipeCheck) Run(_ context.Context, cc *CheckContext, rec StepRecorder) error {
+	rec.Step(wipeID+".1", "the wipe of the previous deployment left no orphan", func(ev Evidence) error {
+		d := cc.Deploy
+		if d == nil || d.PreviousDeploymentID == "" {
+			return errors.New("the run did not name the previous deployment (--previous-deployment-id)")
+		}
+		ev["deployment_id"], ev["previous_deployment_id"] = d.ID, d.PreviousDeploymentID
+		if d.PreviousWipeOrphans < 0 {
+			return fmt.Errorf("the run did not say how many orphans the wipe of deployment %s left (--previous-wipe-orphans)", d.PreviousDeploymentID)
+		}
+		ev["previous_wipe_orphans"] = d.PreviousWipeOrphans
+		if d.PreviousDeploymentID == d.ID {
+			return fmt.Errorf("the previous deployment %s is the deployment under test", d.ID)
+		}
+		if d.PreviousWipeOrphans != 0 {
+			return fmt.Errorf("the wipe of deployment %s left %d orphans", d.PreviousDeploymentID, d.PreviousWipeOrphans)
+		}
+		return nil
+	})
+	return nil
+}

+// parsePreviousWipe reads the values of --previous-deployment-id and
+// --previous-wipe-orphans. Both are given, or neither. When neither is given
+// it returns "" and -1: the run did not say. The number of orphans is a whole
+// number of 0 or more.
+func parsePreviousWipe(id, orphans string) (string, int, error) {
+	id, orphans = strings.TrimSpace(id), strings.TrimSpace(orphans)
+	switch {
+	case id == "" && orphans == "":
+		return "", -1, nil
+	case id == "":
+		return "", -1, errors.New("--previous-wipe-orphans is given without --previous-deployment-id")
+	case orphans == "":
+		return "", -1, errors.New("--previous-deployment-id is given without --previous-wipe-orphans")
+	}
+	n, err := strconv.Atoi(orphans)
+	if err != nil || n < 0 {
+		return "", -1, fmt.Errorf("--previous-wipe-orphans: %q is not a whole number of 0 or more", orphans)
+	}
+	return id, n, nil
+}
