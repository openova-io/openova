# ACC-114 — Gate check ACC-G15: session images start hardened

## In plain words

**The problem today.** The access plane now has its two session images, the remote-desktop daemon and the session agent, each pinned by digest and named to the access controller. Nothing proves on a Sovereign that a session pod built from them starts and stays up under the hardened settings, with the daemon reachable only inside the pod and the agent serving its tunnel port. The check that should prove it is listed in the gate record but not built.

**What changes.** The acceptance suite gains the check, its test and the pod it creates. The gate record lists the check as expected to fail, with its file, so every gate run measures it and it counts as green once two runs pass it.

**Done means:**

- The acceptance suite registers the check for session images in a file of its own, with a test that passes on a healthy cluster and fails at the right step for each of seven defects.
- The check names both session images only by digest, as the access controller reads them, and refuses an image given by tag or missing.
- The session pod the check creates has no credential volume and no service-account token, runs as a numeric user that is not root, and records nothing.
- Every object the check creates is labelled for it and deleted at its end, also when a step fails.
- The gate record lists the check as expected-fail with its file and this task as its implementer, and the record tool accepts the change.
- No other gate check changes, and the existing tests of the suite stay green.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Gate check ACC-G15 is a file of the acceptance suite, `tests/acceptance/sovereign/internal/suite/check_acc_g15.go`, that registers itself and runs five steps in the primary region. (1) It reads the environment of container `controller` of Deployment `guacamole/access-controller`: `ACCESS_IMAGE_GUACD` and `ACCESS_IMAGE_AGENT`, each `<repository>@sha256:<64 hex>` (ACC-106). (2) It creates a namespace of its own and applies the target fixture of ACC-G13 there as the Flux account, waits up to 30 seconds for the target to be Ready, and reads service account `guacamole/access-session`, which the controller makes for a Ready target of kind pod. (3) It creates in namespace `guacamole` one session pod from `tests/acceptance/sovereign/fixtures/access/g15/pod.yaml` with those two images, no credential volume and an agent configuration for protocol `ssh` with `chunkBytes` 0, and waits up to 3 minutes until both containers are Running. (4) Both containers stay Running for 30 seconds with restart count 0, the same start time and the controller's images. (5) From a dial pod of namespace `guacamole` (the `Dialer` of NET-G06) a dial of the pod's address on port 4822 is refused (guacd listens on `127.0.0.1` only) and one on port 8443 connects (the agent). Every object it creates carries the label `acc-check: acc-g15` and is deleted at its end. In `docs/ledger/gates.yaml` ACC-G15 moves from `not-built` to `expected-fail` with that implementation; it turns green once it passes in both records of a gate pair.

## 3. The model (the law)
1. One file registers the check: `check_acc_g15.go` holds `accG15ID = "ACC-G15"` and `RegisterCheck(accG15Check{...})` in its `init`.
2. The images come from the controller only, never from the chart or the test: an image that is not `@sha256:` and 64 hex characters fails step 1, and the pod's containers must run exactly those images in step 4.
3. The session pod is the fixed shape of ADR-0033 decision A8 and A10 for a check: namespace `guacamole`, service account `access-session`, `automountServiceAccountToken: false`, user and group 10001, `RuntimeDefault` seccomp, every container with `readOnlyRootFilesystem`, no privilege escalation and all capabilities dropped; no Secrets Store volume and no path under `/var/run/secrets/openova`; guacd started with `-b 127.0.0.1 -l 4822`; the agent's configuration of schema `openova.io/access-session-config/v1` projected from the pod's annotation to `/etc/access/config.json`, with `chunkBytes` 0 so that nothing is recorded or shipped.
4. A later step runs only when the steps it needs passed: steps 2 and 3 stop the check when they fail; step 5 is not dialed when step 4 gave no address.
5. Cleanup: the session pod, the dial pod and the namespace of the check are deleted at its end on a context of their own, whatever step failed.
6. The check reuses the suite's helpers unchanged: `accG13Fill`, `accG13Check.get`, `accG13Flux`, `accG13Fixtures`, `accG13Ready` (`check_acc_g13.go`), the `Dialer` (`check_policy_dials.go`), `checkStep`, `NewRunID`. Standard library only.

+				return "", fmt.Errorf("container %s runs the image %q, want %q by digest", name, st.Image, images[name])
+			case !st.Running || st.Restarts != 0 || st.StartedAt != first[name].StartedAt:

+			}
+		}

+			if ip == "" {
+				return "", errors.New("the pod has no address")
+			}

+		}
+		if err := c.sleep(ctx, time.Second); err != nil {
+			return "", err

+	}
