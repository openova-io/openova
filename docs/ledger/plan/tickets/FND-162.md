# FND-162 — Console regression: applications grid, application detail, catalogue

## In plain words

**The problem today.** The console regression list holds 82 rows about the applications grid, the application detail page and the catalogue that people walk by hand. The row map assigns them to a gate check, but no browser test asserts them, so a regression on those pages is found only when someone walks them again.

**What changes.** Each of the 82 rows becomes one browser test of the gate harness, titled with its row id and its clause, and the row map names its file. The gate check of these pages points at the folder of the tests and enters the gate as expected to fail, so every live gate run runs them and records the result; the rows stay in the ledger until a later task deletes them together with the scripts that read them.

**Done means:**

- Every row that the row map gives to FND-G20 has one browser test whose title starts with the row id, and its line in the row map names that test file.
- The row map guard passes, and a row of FND-G20 whose line names no file, a file without the row's test, or a skipped test turns it red.
- Gate check FND-G20 is expected-fail and its implementation is the folder of the tests, so the harness selects it and lists 82 tests in 8 files.
- The 286 rows of the ledger are unchanged: the 82 converted rows stay until FND-166 deletes them together with the scripts that read them.

+  const end = Date.now() + timeoutMs

+    } catch (e) {
