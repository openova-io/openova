# CMP-010 — Gate checks: the score moves by push; the shown mode is the engine's mode

## In plain words

**The problem today.** No test checks what the compliance screens show. Nothing proves that a new failing workload changes the score of the Sovereign, or that the change reaches an open browser without a reload. The policy list shows a mode for each policy that is not read from the policy engine, so it can say that a policy only audits while the engine refuses workloads.

**What changes.** The acceptance suite gains two checks. One applies a known failing workload, waits for the event stream and the score to show it, and removes it again. The other compares the mode of every listed policy with the policy engine. The list of checks marks both as expected to fail, so they run and are recorded and cannot fail a run yet.

**Done means:**

- The first check fails when the Sovereign has no score, when no event names the test workload within two minutes, when the score does not count the workload as failing, and when the workload is still listed after it was deleted.
- While the first check waits it makes no request. It reads the score again only after an event arrived.
- The test workload starts no pod and lives in a namespace of its own. That namespace is deleted also when the check fails.
- The second check fails and names every policy whose shown mode differs from the mode in the policy engine, and every listed policy that the engine does not know.
- The list of checks marks both checks as expected to fail. A failure of one of them does not fail a run.
- The tests of both checks run on every pull request and need no cluster.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite under `tests/acceptance/sovereign/` has two compliance gate checks. CMP-G01 applies one known failing workload (the seed) in the first region, sees it arrive as a frame on the open compliance stream, sees the Sovereign score count it, deletes it, and sees the violations drop it. It makes no request on a timer. CMP-G02 compares, for every policy that the API lists, the mode in the answer with the mode that the policy object of the engine carries. Each check is one file `check_<name>.go` that registers itself. The gate manifest `docs/ledger/gates.yaml` names the two files and has both entries in state `expected-fail`: a run that is given the manifest runs them and records their results, and a failure does not fail the run. The tests of both checks run on every pull request without a cluster. The README of the suite and the package comment of `internal/kube` say which check writes to a cluster.

## 3. The model (the law)
1. The five files of the suite that this ticket changes are the result of the embedded patch `CMP-010.patch` and of nothing else. The patch creates three files; work step 5 states the checksum of each. It changes lines of two files, the README of the suite and `kube.go`; work step 6 states how many lines it adds and removes in each. `docs/ledger/gates.yaml` is changed by the two commands of work steps 7 and 8 and by nothing else: four lines are added and two are removed.
2. A gate check of the suite is one file in `tests/acceptance/sovereign/internal/suite/`. It calls `RegisterCheck` in `init()` and holds the identifier of the check as a string constant. The two files are `check_compliance_push.go` (CMP-G01) and `check_compliance_mode.go` (CMP-G02). Their tests are in `check_compliance_test.go`.
3. Both checks work on the first region, `CheckContext.Regions[0]`: the API runs in that region. They call the console API through `CheckContext.API`. The compliance routes are under `/api/v1/sovereigns/<id>/compliance`, where `<id>` is `CheckContext.Deploy.ID`. When the run has no console session, no deployment identifier or no region, `Run` returns an error, and the runner records it as a failed step.
4. A step of a check has the identifier `<check>.<n>`, with `n` counted from 1, in the order of the list below. The function `checkStep` records a step and reports whether it passed.
5. A check calls `kubectl` through its field `kubectl`, of the type `kubectlFunc`. The two registered checks hold `kube.Region.Run` there. The tests put a function there. No test of this ticket starts a process.
6. The seed of CMP-G01:
   - Its namespace is `cmp-gate-<id>`. `<id>` is the result of `NewRunID` for the current time, in lower case. The suite does not give a check the identifier of the run, so the check makes one of the same form. The namespace is created with `kubectl create namespace <namespace>`. It gets no label, so it is not the namespace of an Organization.
   - The seed is the Deployment `cmp-bad` (`apps/v1`) in that namespace. Its labels are `app.kubernetes.io/managed-by: flux` and `kustomize.toolkit.fluxcd.io/name: cmp-gate`. It has `replicas: 0`. Its selector and its pod template carry the label `app: cmp-bad`. The pod template also carries `policy.cilium.io/enforced: "true"`. It has one container, `main`, with a `livenessProbe` and a `readinessProbe` of the type `tcpSocket` on port 8080, the requests `cpu: 10m` and `memory: 16Mi`, and no limits.
   - The image of the container is the image of the first container of the first Deployment of the namespace `kyverno` in the same region. The check reads it with `kubectl -n kyverno get deploy -o jsonpath={.items[0].spec.template.spec.containers[0].image}`. When that prints nothing, the step fails.
   - The seed is applied with `kubectl -n <namespace> apply -f -`, as JSON on standard input.
   - With zero replicas no Pod starts, so the image never runs. The seed satisfies the nine policies that enforce after hand-over (field 4). It fails the policy `multi-replica-drainability`, which asks for two replicas and audits.
   - The namespace is deleted with `kubectl delete namespace <namespace> --wait=false --ignore-not-found`. That happens whenever the namespace was created, also when a step before it failed. The delete has a time limit of one minute of its own, which does not end when the run is cancelled.
7. CMP-G01, the score moves by push. Its steps, in order:
   - Step 1: `GET <base>/scorecard`. The check keeps `sovereign.numerator` and `sovereign.denominator`. The step fails with the words `scorecard empty` when the denominator is 0 or less. When it fails, the check ends: nothing is applied.
   - Step 2: `GET <base>/stream` is opened and stays open until the check ends. The request carries the cookie `catalyst_session` of the console client and has no time limit. The step fails unless the answer is HTTP 200 with a content type that starts with `text/event-stream`. When it fails, the check ends.
   - Step 3: the image is read, the namespace is created and the seed is applied (item 6). The evidence holds the namespace and the image. When the cluster refuses the seed, the step fails with the message of the cluster.
   - Step 4: the check waits for a frame whose data holds the text `/<namespace>/cmp-bad"`: the end of the resource key of the seed. It waits 120 seconds at most. While it waits it makes no request. The evidence holds the number of frames read and the seconds waited.
   - Step 5: the check reads `GET <base>/scorecard` and every page of `GET <base>/violations?limit=500&offset=<n>`. The step passes when the denominator is greater than before the seed, the difference of denominator and numerator is greater than before the seed, and the violations list the seed at least once. A violation is of the seed when its `namespace` is the namespace of the seed and its `resource` ends in `/cmp-bad`. When that does not hold yet, the check waits for the next frame and reads again, for 120 seconds at most.
   - Step 6: the frames that are already waiting are thrown away, and the namespace is deleted (item 6).
   - Step 7: after each frame that arrives, the check reads every page of the violations. The step passes when they do not list the seed. It fails when that has not happened after 120 seconds. This step is recorded only when steps 3, 4, 5 and 6 passed.
8. A frame is one event of the stream body. The body is read line by line. A line that starts with `data:` adds to the data of the event, without the first space after the colon. An empty line ends the event. An event without data is no frame. A line that starts with a colon is a comment and is no frame. An event that the end of the body cuts off is no frame.
9. The check makes no request on a timer. The function `onFrames` is the only place that waits: it calls its function after a frame arrived, and once before the first frame only in step 5: step 4 has just read a frame, and step 5 starts from it.
10. CMP-G02, the shown mode is the engine's mode. Its steps, in order:
    - Step 1: `GET <base>/policies`. The step fails with the words `nothing was measured` when the list `items` is empty. When it fails, the check ends.
    - Step 2: the policy objects of the engine are read in the first region, with `kubectl get clusterpolicies.kyverno.io -o json` and `kubectl get validatingpolicies.policies.kyverno.io -o json`. When the error text of `kubectl` holds `the server doesn't have a resource type`, the cluster does not serve that kind, and its list is empty. Any other error fails the step. The step also fails when the cluster serves neither kind. When it fails, the check ends.
    - Step 3: for every listed policy, the engine object is the `ClusterPolicy` of that name, or the `ValidatingPolicy` of that name when there is no such `ClusterPolicy`. The step fails and names every policy whose shown mode is not the mode of its engine object, and every policy without an engine object. One exception: a policy whose `source` is `evaluator` and that has no engine object is not compared; the evidence lists it. The step fails with the words `nothing was measured` when no policy was compared.
11. The mode of an engine object (`engineMode`) is `enforce` when `spec.validationActions` holds `Deny`, or when `spec.validationFailureAction` is `Enforce`, or when `validate.failureAction` of one entry of `spec.rules` is `Enforce`. In every other case it is `audit`. Upper and lower case are the same. The shown mode (`shownMode`) is `enforce` for the words `enforcing` and `enforce`, and `audit` for the words `permissive` and `audit`. Any other word equals neither, so the policy is named as differing.
12. `docs/ledger/gates.yaml`: the entries CMP-G01 and CMP-G02 have `state: expected-fail` and an `implementation` line that names their file. No other line of the file changes.
13. `tests/acceptance/sovereign/README.md` lists the two checks in its table of checks. Its section "What the suite writes, and what it never does" says that the suite writes through the console API and, in gate check CMP-G01 only, with `kubectl create`, `apply` and `delete`; the sentence that the suite writes only through the console API, and the sentence that it never runs `kubectl apply` or `delete`, are gone. The package comment of `tests/acceptance/sovereign/internal/kube/kube.go` says the same: the verbs are `get` and `exec`, and `create`, `apply` and `delete` in CMP-G01 only; the words `never applies, patches or deletes` are gone. That comment names the person who runs a Sovereign `sovereign-admin`, the term of `docs/GLOSSARY.md`; the patch removes the word `operator` from it. No code line of `kube.go` changes.
14. No other file of the suite changes. The module keeps using the Go standard library only.
15. This ticket deletes no file.

+// readFrames calls emit with the data of every event of a text/event-stream
+// body. A comment line, which starts with a colon, is not an event.
+func readFrames(body io.Reader, emit func(data string)) error {
+	lines := bufio.NewScanner(body)
+	lines.Buffer(make([]byte, 0, 64<<10), 4<<20)
+	var data []string
+	for lines.Scan() {
+		line := strings.TrimSuffix(lines.Text(), "\r")
+		if line == "" && data != nil {
+			emit(strings.Join(data, "\n"))
+			data = nil
+		} else if strings.HasPrefix(line, "data:") {
+			data = append(data, strings.TrimPrefix(line[len("data:"):], " "))
+		}
+	}
+	return lines.Err()
+}

+// openStream opens a stream route with the session of the console client and
+// sends the data of its frames to a channel. The request has no time limit:
+// it lives until ctx ends. The channel is closed when the body ends.
+func openStream(ctx context.Context, c *api.Client, path string) (<-chan string, error) {
+	req, err := http.NewRequestWithContext(ctx, http.MethodGet, c.Base+path, nil)
+	if err != nil {
+		return nil, err
+	}
+	req.Header.Set("Accept", "text/event-stream")
+	req.AddCookie(&http.Cookie{Name: "catalyst_session", Value: c.Session})
+	client := &http.Client{} // no Timeout: it would end the stream
+	if c.HTTP != nil {
+		client.Transport = c.HTTP.Transport
+	}
+	res, err := client.Do(req)
+	if err != nil {
+		return nil, fmt.Errorf("GET %s: %w", path, err)
+	}
+	if kind := res.Header.Get("Content-Type"); res.StatusCode != http.StatusOK || !strings.HasPrefix(kind, "text/event-stream") {
+		_ = res.Body.Close()
+		return nil, fmt.Errorf("GET %s: HTTP %d with content type %q, want 200 and text/event-stream", path, res.StatusCode, kind)
+	}
+	frames := make(chan string, 1024)
+	go func() {
+		defer close(frames)
+		defer func() { _ = res.Body.Close() }()
+		_ = readFrames(res.Body, func(data string) {
+			select {
+			case frames <- data:
+			case <-ctx.Done():
+			}
+		})
+	}()
+	return frames, nil
+}
+
+// onFrames calls done with every frame that arrives, until done says true, the
+// stream ends or the wait is over. With first set it calls done once before it
+// waits for a frame. It returns the number of frames it read. When it gives up,
+// the error holds the last text that done returned.
+func onFrames(frames <-chan string, wait time.Duration, first bool, done func(frame string) (bool, string, error)) (int, error) {
+	timer := time.NewTimer(wait)
+	defer timer.Stop()
+	n, last, frame := 0, "no frame arrived", ""
+	for ; ; first = false {
+		if !first {
+			select {
+			case data, open := <-frames:
+				if !open {
+					return n, fmt.Errorf("the stream ended after %d frames: %s", n, last)
+				}
+				n, frame = n+1, data
+			case <-timer.C:
+				return n, fmt.Errorf("not within %s (%d frames read): %s", wait, n, last)
+			}
+		}
+		ok, text, err := done(frame)
+		if err != nil || ok {
+			return n, err
+		}
+		last = text
+	}
+}

+func (a *complianceAPI) ServeHTTP(w http.ResponseWriter, r *http.Request) {
+	route := r.URL.Path[strings.LastIndex(r.URL.Path, "/")+1:]
+	if route == "stream" {
+		w.Header().Set("Content-Type", "text/event-stream")
+		_, _ = io.WriteString(w, ": connected\n\nevent: snapshot\ndata: {\"type\":\"snapshot\"}\n\n")
+		for {
+			w.(http.Flusher).Flush()
+			select {
+			case text := <-a.frames:
+				_, _ = fmt.Fprintf(w, "event: score\ndata: %s\n\n", text)
+			case <-r.Context().Done():
+				return
+			}
+		}
+	}
+	a.Lock()
+	defer a.Unlock()
+	if a.waiting {
+		a.early++
+	}
+	body := map[string]any{"items": a.policies}
+	switch route {
+	case "scorecard":
+		body = map[string]any{"sovereign": map[string]int{"numerator": a.num, "denominator": a.den}}
+	case "violations": // one item per page: the check must read every page
+		offset, _ := strconv.Atoi(r.URL.Query().Get("offset"))
+		body = map[string]any{"total": len(a.violations),
+			"items": a.violations[min(offset, len(a.violations)):min(offset+1, len(a.violations))]}
+	}
+	_ = json.NewEncoder(w).Encode(body)
