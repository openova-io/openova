# CLD-076 — Documents link to the generated provider tables

## In plain words

**The problem today.** Four documents still list the clouds the platform can provision on by hand. Their lists disagree with the code: they name clouds that have no provider pack, a Crossplane package that is no longer installed, and they miss a pack that exists. A generated file with the true tables exists, but nothing links to it.

**What changes.** The four hand-written lists are replaced by a link to the generated provider tables. The two component documents also state the one Crossplane provider package that is really installed.

**Done means:**

- No document of the four still holds the old provider table or the old list of clouds.
- Each of the four documents links to the generated provider tables, and every such link opens the file.
- The OpenTofu and Crossplane documents say that one Crossplane provider package is installed on every Sovereign, provider-opentofu.
- The state markers of the canonical documents still pass their check.

The rest of this ticket is the exact instruction for the model that does the work.
