# CLD-103 — Credentials map, validation through the port, storage class from the profile

## In plain words

**The problem today.** The engine decides what a valid deployment request is with cloud names written into its own code: a switch over two providers with their credential checks, a table of the server types each cloud sells where, and a table of storage classes. A request that names no provider silently counts as one particular cloud, and the Huawei sizing floors sit in the create handler. Every new cloud would need edits in all of these places.

**What changes.** Each cloud adapter checks and adjusts the request from its cloud profile, the request carries its credentials as one map keyed by the profile, a request without a provider is refused, and the default storage class comes from the profile.

**Done means:**

- A deployment request that names no provider is refused with a field error on the provider, and is never treated as one particular cloud.
- A request that lacks a credential which its cloud profile marks required is refused with a field error that names the credential.
- A Huawei request gets the same worker count and machine sizes as before, now from the floors in the cloud profile.
- A Hetzner server type that cannot be ordered in the chosen location is still refused, now by the Hetzner adapter.
- The stored deployment record lists the names of the attached credentials and never their values.
- The OpenTofu variables written for the two reference requests are the same, byte for byte, as before.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`provisioner.Request` carries `Installation` and a `Credentials` map keyed by the credential fields of the cloud profile. `Request.Validate` no longer names a cloud: it refuses an empty provider with the field error of the port, resolves the adapter with `providers.Get`, reads the effective cloud profile of the request, builds the adapter's view of the request with `providerSpec()` and calls the adapter's `Normalize`. The required credentials, the region capabilities, the Hetzner Object Storage region rule and server-type matrix, and the Huawei worker minimum and flavor floors are adapter code, driven by the profile. The default storage class is the profile's `spec.storage.defaultClass`. The create handler answers a field error with HTTP 400 `{"error":"invalid-field","field":…,"message":…}`. The stored record keeps the keys of the credentials map and redacts every value. The variables that a module receives do not change.

## 3. The model (the law)
1. `Request` gains `Installation` (`json:"installation,omitempty"`) and `Credentials map[string]string` (`json:"credentials,omitempty"`). The provider-named fields `HetznerToken`, `HetznerProjectID`, `HuaweiAccessKey`, `HuaweiSecretKey`, `HuaweiProjectID` and `HuaweiRegion` stay until CLD-104. One function, `syncLegacyCredentials`, keeps them and the map equal: a non-empty field is written into the map under its credential key (`hcloud_token`, `hcloud_project_id`, `access_key`, `secret_key`, `project_id`, `region`), and an empty field is filled from the map. The three Object Storage fields are mirrored the same way under `object_storage_access_key`, `object_storage_secret_key` and `object_storage_region`, the keys of the Hetzner profile's credential fields. A field set by the server, such as the operator credentials the create handler stamps, therefore wins over a value the body carried in the map.
2. `Request.UnmarshalJSON` decodes as before and then, when the adapter of the request's provider implements `providers.LegacyAliaser`, copies every legacy JSON field it names into `Credentials`, unless the map already holds that key. The Hetzner adapter names `hetznerToken`, `hetznerProjectID`, `objectStorageAccessKey`, `objectStorageSecretKey` and `objectStorageRegion`. CLD-124 removes the aliases.
3. `Validate` keeps its checks that name no cloud. In place of the provider switch it calls `normalize()`: an empty provider returns `&providers.FieldError{Field: "provider"}`; an unknown one returns `unsupported provider "<x>"; known: <providers.Names()>`; the name becomes lower case; `EffectiveProfile(provider, installation)` reads the pack profile below `ProvidersDir` (default `/infra/providers`, the folder the image copies) and merges the installation document named by `Installation`, read through the package variable `ReadInstallation`; a request that names an installation while no reader is set is refused. `Normalize` gets `providerSpec()`; the sizes and worker counts it sets are copied back into the request. Region codes and cloud regions are not copied back, because the engine still writes the module's regions from the request until CLD-104.
4. The neutral rules every adapter applies live in `internal/providers/normalize.go`: `CheckCredentials` (every field the profile marks `required` must be non-blank in `spec.Creds`, else a field error on `credentials.<key>`) and `CheckRegions` (more than one region needs `capabilities.multiRegion`; more than one cloud region needs `capabilities.multiCloudRegion`).
5. The Hetzner `Normalize` applies both, then the Object Storage region rule (the pattern of the profile's credential field `object_storage_region`) and the server-type matrix, moved unchanged from the engine into `internal/providers/hetzner/sku.go`. The Hetzner profile says `multiRegion: false`, so a Hetzner request with two regions is refused.
6. The Huawei `Normalize` applies `CheckCredentials`; then, because a Huawei Sovereign has one cloud region (the value the engine writes as the cloud region of every entry since CLD-090), it keeps each entry's `cloudRegion` as its code and sets the cloud region of every entry to `regionFromCreds`, and applies `CheckRegions`. It then raises the worker count of every region to `spec.compute.minWorkerCount` and replaces an empty flavor, or a listed flavor below `spec.compute.minimumFlavor`, with the smallest listed flavor of the role that meets the floor. A flavor that no list names is kept as sent. The pack profile lists no flavor (flavors are installation values), so while a request names no installation the floors are measured against the four flavors of the installation in use today, kept in `floors.go`; an effective profile that lists flavors replaces them. This gives the sizes the create handler gave before.
7. Deleted: the provider switch of `Validate`, the per-region and the legacy single-region server-type checks of `Validate`, the Hetzner Object Storage region switch of `Validate`, `internal/provisioner/sku_availability.go` and its test, `StorageClassDefaultHetzner`, `StorageClassDefaultHuawei` and `defaultStorageClassForProvider`, the default provider of `normalizeProvider` in `region_health.go`, and the worker minimum and flavor floors of the create handler.
8. `DeriveStorageClass` returns the explicit class, or the profile's default class; `writeTfvars` fails when it cannot read the profile and no class is set. The Hetzner adapter's wipe request names its provider, so the destroy run reads the Hetzner profile.
9. The store keeps `Installation` verbatim and the keys of `Credentials` with every non-empty value replaced by the redaction marker; rehydration returns a copy of the map.
10. The create handler answers a `*providers.FieldError` from admission with HTTP 400 `{"error":"invalid-field","field":…,"message":…}`. The handler package shrinks, and `scripts/baselines/api-structure.json` is lowered in the same change.
11. The tests of the engine run against a double of the port registered under the two pack names (`port_double_test.go`), because the adapters import the engine; the tests of the handler and the store read the profiles of the repository. Every test body that relied on the default provider names it.
12. All 31 paths change only through the patch `CLD-103.patch` of this ticket.

+// skuAvailableInRegion reports whether sku can be ordered in region. An

+		}
+	}

+// provisions on today. The pack profile lists no flavor, because flavors are
+// installation values; while a request names no installation document, the
+// floors are measured against this list. An effective profile that lists
+// flavors replaces it.
+var installationFlavors = []cloudprofile.Flavor{
+	{Name: "s7n.large.4", VCPU: 2, MemoryGiB: 8, Roles: []string{roleControlPlane, roleWorker}},
+	{Name: "m7n.large.8", VCPU: 2, MemoryGiB: 16, Roles: []string{roleControlPlane, roleWorker}},
+	{Name: "m7n.xlarge.8", VCPU: 4, MemoryGiB: 32, Roles: []string{roleControlPlane, roleWorker}},

+// applyFloors raises every region of spec to the floors of profile: the
+// worker count to spec.compute.minWorkerCount, and an empty flavor or a
+// listed flavor below spec.compute.minimumFlavor to the smallest listed
+// flavor of the role that meets the floor. A flavor the list does not name
+// is kept as sent.
+func applyFloors(spec *providers.ProvisionSpec, profile *cloudprofile.Profile) {
+	c := profile.Spec.Compute
+	flavors := c.Flavors
+	if len(flavors) == 0 {
+		flavors = installationFlavors
+	}
+	var cp, worker cloudprofile.Floor
+	if c.MinimumFlavor != nil {
+		cp, worker = c.MinimumFlavor.ControlPlane, c.MinimumFlavor.Worker
+	}
+	for i := range spec.Regions {
+		r := &spec.Regions[i]
+		if r.WorkerCount < c.MinWorkers() {
+			r.WorkerCount = c.MinWorkers()
+		}
+		r.ControlPlaneSize = floorFlavor(r.ControlPlaneSize, roleControlPlane, cp, flavors)
+		r.WorkerSize = floorFlavor(r.WorkerSize, roleWorker, worker, flavors)
+	}
+}
+
+// floorFlavor returns name, or the smallest flavor of flavors with role that
+// meets floor when name is empty or a listed flavor below floor. A zero
+// floor, a name the list does not hold, and a floor no listed flavor meets
+// all return name.
+func floorFlavor(name, role string, floor cloudprofile.Floor, flavors []cloudprofile.Flavor) string {
+	if floor.VCPU == 0 && floor.MemoryGiB == 0 {
+		return name
+	}
+	if name != "" {
+		f, ok := flavorNamed(name, flavors)
+		if !ok || meets(f, floor) {
+			return name
+		}
+	}
+	var fit []cloudprofile.Flavor
+	for _, f := range flavors {
+		if hasRole(f, role) && meets(f, floor) {
+			fit = append(fit, f)
+		}
+	}
+	if len(fit) == 0 {
+		return name
+	}
+	sort.Slice(fit, func(a, b int) bool {
+		if fit[a].VCPU != fit[b].VCPU {
+			return fit[a].VCPU < fit[b].VCPU
+		}
+		if fit[a].MemoryGiB != fit[b].MemoryGiB {
+			return fit[a].MemoryGiB < fit[b].MemoryGiB
+		}
+		return fit[a].Name < fit[b].Name
+	})
+	return fit[0].Name
+}
+
+func flavorNamed(name string, flavors []cloudprofile.Flavor) (cloudprofile.Flavor, bool) {
+	for _, f := range flavors {
+		if f.Name == name {
+			return f, true
+		}
+	}
+	return cloudprofile.Flavor{}, false
+}
+
+func meets(f cloudprofile.Flavor, floor cloudprofile.Floor) bool {
+	return f.VCPU >= floor.VCPU && f.MemoryGiB >= floor.MemoryGiB
+}
+
+func hasRole(f cloudprofile.Flavor, role string) bool {
+	for _, r := range f.Roles {
+		if r == role {
+			return true
+		}
+	}
+	return false
+}

+// CheckCredentials returns a *FieldError for the first credential field that
+// the profile marks required (spec.credentials.fields[].required) and that
+// spec.Creds lacks or holds only blanks. The field is "credentials.<key>".
+func CheckCredentials(spec *ProvisionSpec, profile *cloudprofile.Profile) error {
+	if profile == nil {
+		return &FieldError{Field: "provider", Message: "no cloud profile"}
+	}
+	for _, f := range profile.Spec.Credentials.Fields {
+		if f.Required && strings.TrimSpace(spec.Creds.Get(f.Key)) == "" {
+			return &FieldError{Field: "credentials." + f.Key, Message: "required (" + f.Label + ")"}
+		}
+	}
+	return nil
+}
+
+// CheckRegions applies the region capabilities of the profile: more than one
+// region needs spec.capabilities.multiRegion, and regions in more than one
+// cloud region need spec.capabilities.multiCloudRegion. It returns a
+// *FieldError on "regions".
+func CheckRegions(spec *ProvisionSpec, profile *cloudprofile.Profile) error {
+	if profile == nil {
+		return &FieldError{Field: "provider", Message: "no cloud profile"}
+	}
+	caps := profile.Spec.Capabilities
+	if len(spec.Regions) > 1 && !caps.MultiRegion {
+		return &FieldError{Field: "regions", Message: fmt.Sprintf("%d regions requested; the cloud profile %q allows one", len(spec.Regions), profile.Metadata.Name)}
+	}
+	if caps.MultiCloudRegion {
+		return nil
+	}
+	for i, r := range spec.Regions {
+		if r.CloudRegion != spec.Regions[0].CloudRegion {
+			return &FieldError{Field: fmt.Sprintf("regions[%d].cloudRegion", i), Message: fmt.Sprintf("%q differs from %q; the cloud profile %q allows one cloud region", r.CloudRegion, spec.Regions[0].CloudRegion, profile.Metadata.Name)}
+		}
+	}
+	return nil
+}
