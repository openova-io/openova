# CMP-058 — Engine to the 1.19 line

## In plain words

**The problem today.** The policy engine of a Sovereign runs Kyverno 1.18, one line behind the 1.19 line that the migration to the current policy kinds starts from. The command-line tool that tests the policy chart is pinned to the same old version, and one test suite only passes because of a behaviour that the 1.19 tool no longer has.

**What changes.** The engine chart installs the newest patch release of the 1.19 line, every engine image is pulled through the registry proxy at that version, and the policy chart tests run with the matching tool. The one suite that relied on the old tool reads its fake cluster the way the new tool does; no policy changes.

**Done means:**

- The engine chart depends on the upstream chart 3.9.2, whose application version is v1.19.2, and names v1.19.2 as its own application version.
- A render of the engine chart pulls exactly seven engine images, each through the registry proxy and each at the tag v1.19.2.
- The policy chart tests run with the command-line tool v1.19.2, checked against the checksum of its release, and every suite and shell test passes.
- The suite of the cleanup policy for orphaned replication CA seeds still fails when the policy stops reading the HelmReleases of its fake cluster.
- No policy, no policy test resource and no line that the release writes changes.

The rest of this ticket is the exact instruction for the model that does the work.
