# CLD-061 — Crossplane 1.18 to 1.19

## In plain words

**The problem today.** The platform installs Crossplane core 1.18.0. The road to Crossplane 2 goes one minor version at a time, and the first step, to the 1.19 line, has not been taken. The gate check that tells whether the adoption of the cloud resources is intact exists, but a failure of it does not yet stop a release.

**What changes.** The Crossplane chart installs core 1.19.3, the highest patch of the 1.19 line, through the same registry route as before. The gate check of the Crossplane upgrade becomes required.

**Done means:**

- The Crossplane chart pulls the upstream chart at version 1.19.3.
- Every Crossplane core container image still comes through the registry proxy, now with the tag v1.19.3.
- The chart test fails when the rendered image tag is not v1.19.3 or when an image leaves the proxy route.
- No setting of the chart other than the upstream version changes.
- Gate check CLD-G06 is required in the gate manifest, so a gate run fails when an adoption claim or its Workspace is not Synced and Ready.

The rest of this ticket is the exact instruction for the model that does the work.
