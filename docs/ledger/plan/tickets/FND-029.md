# FND-029 — A published chart version is never published again with other content

## In plain words

**The problem today.** Nine image builds write a new image tag into a chart and then start the chart release without a new chart version. The release then publishes the new content under the version that is already published, so one version stands for two contents: a running Sovereign keeps the copy it has, and a new Sovereign gets the new one. The continuum chart stayed at one version through six image bumps in one day.

**What changes.** A started release compares the chart with what the registry holds under its version. Other files get the next patch version, moved everywhere in one commit; the same files are not pushed again; and no version that the registry holds is ever published again with other files.

**Done means:**

- A release started after an image build that changed a chart's values publishes the chart under the next patch version, and the chart version, its kit pin, its blueprint version and its entry in the catalogue seed move in one commit.
- The same holds for the umbrella chart that six controller builds release: its version and its kit pin move in one commit.
- The generated catalogue moves in that commit only for a chart that has a card there which follows its version. The continuum chart and the umbrella chart have no such card, so their release changes nothing in the generated catalogue for them.
- A release started for a chart whose files the registry already holds under its version pushes nothing to the registry.
- The release job fails, with one line naming the version and the package, when it would publish a version that the registry holds with other files.
- The release guard proves these by running the workflow's own steps against a stand-in registry, and each of its four new proofs fails on the workflow as it was before this task.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. A dispatched run of `.github/workflows/blueprint-release.yaml` is a run with no push range: `github.event.before` is empty. Nine image builds commit a new image tag into a chart's values through `./.github/actions/deploy-bump` (its commit ends its first line with `[skip ci]`, so the push starts no run) and then dispatch this workflow without changing `Chart.yaml`: into `products/catalyst/chart/values.yaml` (the umbrella chart bp-catalyst-platform) `build-application-controller.yaml`, `build-blueprint-controller.yaml`, `build-environment-controller.yaml`, `build-organization-controller.yaml`, `build-projector.yaml` and `useraccess-controller-build.yaml`; into their own chart `build-continuum-controller.yaml` (bp-continuum), `build-openova-flow-server.yaml` (bp-openova-flow-server) and `build-openova-flow-adapter-flux.yaml` (bp-openova-flow-emitter). None of these nine workflows changes.
2. In the step "Release writer: bump the chart version" (`id: bump_chart`) a dispatched run of a chart that is not a library chart does this, in order:
   - It pulls `oci://ghcr.io/openova-io/<name>` at the version in `Chart.yaml` with `helm pull`. When the pull fails and its output holds `not found`, the registry does not hold that version: the run publishes it as it stands (`bumped=false`), as today. When the pull fails for any other reason, the step fails: it never guesses.
   - Otherwise it runs `helm dependency build` and `helm package` on the chart into a temporary folder and compares the two packages with `python3 scripts/chart-package-diff.py <published> <packaged>`.
   - Exit 0, the same files: it writes `unchanged=true` and `bumped=false`. Exit 1, other files: it writes the next patch version into `Chart.yaml` by the same code a push run uses (the higher of the chart's version and the version on `origin/main`, plus one patch). Any other exit fails the step.
   The push branch of the step is unchanged: a push run bumps when a merge changed the chart's files and left its version as it was, and the four charts that their own build versions (`products/catalyst`, `platform/guacamole`, `platform/newapi`, `platform/k8s-ws-proxy`) keep `defer=true` on a push run.
3. A bumped dispatched run is a bumped push run from here on: the steps `bump_pin`, `bump_blueprint`, `sync_seed` and the commit step move every lockstep site to the new version in its one commit, with the same retry. The umbrella chart is a dispatched chart like the others. The lockstep sites of a chart are the sites it has. The generated catalogue (`products/catalyst/bootstrap/api/internal/catalog/blueprints.json` and `products/catalyst/bootstrap/ui/src/shared/constants/catalog.generated.ts`) is written by `products/catalyst/bootstrap/ui/scripts/build-catalog.mjs` from `platform/<name>/blueprint.yaml` and `products/<name>/blueprint.yaml` and from nothing deeper. bp-continuum keeps its file at `products/continuum/chart/blueprint.yaml`, and the umbrella chart has none in `products/catalyst` (the card `bp-catalyst-platform` comes from `platform/catalyst-platform/blueprint.yaml`, whose version is the placeholder `0.0.0` that no release writes). So the generated catalogue holds no version that follows either chart, and their release changes no line of the two generated files for them. (The release writer regenerates the catalogue in every run. When `main` carries a stale card of another chart, that card is corrected in the same commit; this is today's behaviour and stays.) A chart such as bp-keycloak (`platform/keycloak/blueprint.yaml`) has a card there, and its release commit carries both files. This ticket does not change which charts have a card.
4. `scripts/chart-package-diff.py` (new) compares files, never the archive digest: `helm package` writes the time of packaging into every tar entry and the gzip header, and `helm dependency build` writes a `Chart.lock` with the time it ran. Its rules: every regular file is compared by its path in the archive and its bytes; a symbolic link by its target; a `.tgz` file inside that is a gzip tar (a packed subchart) is opened and compared file by file under `<file>!/<path>`; in a file named `Chart.lock` a line starting with `generated:` is left out. Exit 0 same files, 1 other files (one line per difference, at most 20), 2 a package cannot be read. Its `--self-test` shows each rule failing and passing.
5. The step "Read chart metadata" (`id: chart`) writes a new output `publish`: `false` when `bump_chart` wrote `unchanged=true`, otherwise `true`. It still writes `name`, `version` and `skip=false`, so the lockstep steps run: a site that an earlier run of the same version left behind still moves, and when every site is already there nothing is committed.
6. The steps "Helm push to GHCR" (`id: push`), "Verify upstream subcharts present in pulled OCI artifact (post-helm-push)", "Sign and attest the chart" and "Summary" run on `steps.chart.outputs.skip != 'true' && steps.chart.outputs.publish != 'false'`. The push step and the signing step keep one and the same `if`, which `scripts/check-builds-sign.py` requires (its rule 2).
7. A new step right before "Helm push to GHCR", "Release writer: a published version is never published again with other files" (`id: no_republish`), with the same `if` as the push step, is the floor. It pulls the version about to be pushed. Not found: it passes. Found: it compares the published package with the package that "Helm package" wrote (`${CHARTS_DIR:-/tmp/charts}/<name>-<version>.tgz`; the guard sets `CHARTS_DIR`). Other files: it fails with one `::error` line that names `ghcr.io/openova-io/<name>:<version>` and the package file. The same files: it passes, so a run that is repeated after a failure later in the job can finish. A failed pull for another reason, or a compare that cannot read a package, fails the step.
8. The step "Helm registry login (for OCI dependencies)" moves from after "Read chart metadata" to right after "Login to GHCR", without its `if`, so that `bump_chart` can pull. Its command is unchanged.
9. The guard `scripts/check-release-lockstep-writer.py` runs every workflow step with a stand-in for `helm` first on `PATH`. The stand-in keeps a local registry per case (`HELM_STUB_REGISTRY`): `package` writes the chart's files in a random order with fresh times, `pull` serves what the case put in the registry or prints `Error: ghcr.io/openova-io/<name>:<version>: not found`, `registry` and `dependency build` do nothing, and every other subcommand goes to the real `helm`. The scratch copy of the repository also takes new files that are not ignored, so a new script is tested before it is committed; a scratch folder inside the repository is left out. The stand-in is removed when the guard ends. Four new cases, each failing on the workflow before this change: `dispatch-changed` (bp-continuum: the registry holds the version with the files before a values change; the writer must bump to the next patch version and move every site in one commit), `dispatch-umbrella` (the same for bp-catalyst-platform: `Chart.yaml` and the slot 13 pin in one commit), `dispatch-unchanged` (the registry holds the chart's own files: the step `push` must not run, and no file of the chart and no site moves) and `republish-refused` (the step `no_republish` must fail with one line naming both on other files, and pass on the same files and on an absent version). The check "one commit" of a case asks for the two generated catalogue files exactly when the case chart has a `blueprint.yaml` that `build-catalog.mjs` reads (new function `catalog_card_source`): that is the chart of each existing case this check judges (bp-keycloak, bp-postgres), and neither bp-continuum nor the umbrella chart. For every chart it also refuses a generated catalogue file that differs from the tree before the release and is not in the writer's last commit. The 19 existing cases keep their results.
10. `.github/workflows/check-release-lockstep-writer.yaml` also triggers on `scripts/chart-package-diff.py` and runs its `--self-test`.
11. `docs/RUNBOOKS.md` section 2.4 says that a dispatched release bumps a changed chart, that a published version is never published again with other files, why, and what to do when the floor is red.
12. Nothing is deleted.

#!/usr/bin/env python3
"""chart-package-diff.py - do two packaged charts hold the same files? (FND-029)

The release writer in .github/workflows/blueprint-release.yaml uses it twice: a
dispatched run compares the chart it packaged with the version the registry
holds, and the step before `helm push` refuses a version that the registry holds
with other files.

A package that `helm package` writes is not byte-reproducible: every tar entry
and the gzip header carry the time of packaging, and `helm dependency build`
writes a Chart.lock with the time it ran. So this tool compares FILES, never the
digest of the archive:

  1. Every regular file of each archive is read, by its path in the archive.
     Directories are not compared; a symbolic link is compared by its target.
  2. A file whose name ends in .tgz and that is itself a gzip tar (a packed
     subchart) is opened as well; its files are compared under the path
     <file>!/<path in it>, to any depth.
  3. In a file named Chart.lock, a line that starts with `generated:` is left
     out: helm writes the time of the run there.
  4. The two packages hold the same files when both have the same paths and
     each path has the same bytes.

Usage (from the repository root):
  python3 scripts/chart-package-diff.py A.tgz B.tgz   compare two packages
  python3 scripts/chart-package-diff.py --self-test   show that every rule can fail and pass
Exit codes: 0 the same files, 1 the files differ (one line per difference, at
most 20, the first line first), 2 a package cannot be read.
"""
import io
import os
import sys
import tarfile
import tempfile
import time

MAX_DEPTH = 5
MAX_LINES = 20


class ReadError(Exception):
    """A package cannot be read."""


def lock_text(data):
    """Rule 3: a Chart.lock without its `generated:` line."""
    lines = data.split(b"\n")
    return b"\n".join(ln for ln in lines if not ln.startswith(b"generated:"))


def read_archive(data, label, prefix="", depth=0):
    """path -> bytes for every file of the gzip tar `data` (rules 1 to 3)."""
    if depth > MAX_DEPTH:
        raise ReadError("%s: subcharts nested deeper than %d levels" % (label, MAX_DEPTH))
    try:
        archive = tarfile.open(fileobj=io.BytesIO(data), mode="r:gz")
    except (tarfile.TarError, OSError, EOFError) as exc:
        raise ReadError("%s: not a gzip tar archive (%s)" % (label, exc))
    files = {}
    with archive:
        try:
            members = archive.getmembers()
        except (tarfile.TarError, OSError, EOFError) as exc:
            raise ReadError("%s: cannot be read (%s)" % (label, exc))
        for member in members:
            name = member.name[2:] if member.name.startswith("./") else member.name
            path = prefix + name
            if member.isdir():
                continue
            if member.issym() or member.islnk():
                files[path] = b"link -> " + member.linkname.encode()
                continue
            if not member.isfile():
                continue
            handle = archive.extractfile(member)
            content = handle.read() if handle else b""
            if path in files:
                raise ReadError("%s: the path %s occurs twice" % (label, path))
            if os.path.basename(path) == "Chart.lock":
                content = lock_text(content)
            if path.endswith(".tgz") and content[:2] == b"\x1f\x8b":
                try:
                    files.update(read_archive(content, label, path + "!/", depth + 1))
                    continue
                except ReadError:
                    pass
            files[path] = content
    return files


def read_package(path):
    try:
        with open(path, "rb") as handle:
            data = handle.read()
    except OSError as exc:
        raise ReadError("%s: %s" % (path, exc.strerror or exc))
    return read_archive(data, path)


def differences(a, b, label_a, label_b):
    out = []
    for path in sorted(set(a) | set(b)):
        if path not in b:
            out.append("only in %s: %s" % (label_a, path))
        elif path not in a:
            out.append("only in %s: %s" % (label_b, path))
        elif a[path] != b[path]:
            out.append("differs: %s" % path)
    return out


def compare(path_a, path_b):
    """Exit code and the lines to print."""
    try:
        a = read_package(path_a)
        b = read_package(path_b)
    except ReadError as exc:
        return 2, ["cannot read: %s" % exc]
    diff = differences(a, b, path_a, path_b)
    if not diff:
        return 0, ["same files: %s and %s hold the same %d files" % (path_a, path_b, len(a))]
    lines = diff[:MAX_LINES]
    if len(diff) > MAX_LINES:
        lines.append("... and %d more differences" % (len(diff) - MAX_LINES))
    return 1, lines


# --------------------------------------------------------------------------- self-test
def make_tgz(path, files, mtime, order=None):
    """Write a gzip tar of `files` (path -> bytes, or ('link', target))."""
    names = list(files) if order is None else order
    with tarfile.open(path, "w:gz") as archive:
        for name in names:
            value = files[name]
            info = tarfile.TarInfo(name)
            info.mtime = mtime
            if isinstance(value, tuple):
                info.type = tarfile.SYMTYPE
                info.linkname = value[1]
                archive.addfile(info)
                continue
            info.size = len(value)
            archive.addfile(info, io.BytesIO(value))


def tgz_bytes(files, mtime):
    buf = io.BytesIO()
    with tarfile.open(fileobj=buf, mode="w:gz") as archive:
        for name, value in files.items():
            info = tarfile.TarInfo(name)
            info.mtime = mtime
            info.size = len(value)
            archive.addfile(info, io.BytesIO(value))
    return buf.getvalue()

    case("rule 2: a packed subchart with the same files, packed at another time",

    case("exit 2: a file that is not a gzip tar", base, 2, b_raw=b"not an archive")

    failed = 0
    with tempfile.TemporaryDirectory() as tmp:
        for i, (label, a_files, b_files, want, order, b_raw) in enumerate(cases):
            pa = os.path.join(tmp, "a%d.tgz" % i)
            pb = os.path.join(tmp, "b%d.tgz" % i)
            make_tgz(pa, a_files, 1000)
            if b_raw is not None:
                with open(pb, "wb") as handle:
                    handle.write(b_raw)
            else:
                make_tgz(pb, b_files, int(time.time()), order)
            got, lines = compare(pa, pb)
            ok = got == want
            failed += 0 if ok else 1
            print("%s %s: exit %d (want %d)%s" % ("PASS" if ok else "FAIL", label, got, want,
                                                  "" if ok else " " + " | ".join(lines)))
        got, _ = compare(os.path.join(tmp, "absent.tgz"), os.path.join(tmp, "a0.tgz"))
        ok = got == 2
        failed += 0 if ok else 1
        print("%s exit 2: a package that does not exist: exit %d (want 2)" % ("PASS" if ok else "FAIL", got))
    if failed:
        print("self-test FAILED: %d case(s)" % failed)
        return 1
    print("self-test passed: %d cases" % (len(cases) + 1))
    return 0


def main(argv):
    if argv == ["--self-test"]:
        return self_test()
    if len(argv) != 2 or argv[0].startswith("-") or argv[1].startswith("-"):
        print("usage: chart-package-diff.py A.tgz B.tgz | --self-test", file=sys.stderr)
        return 2
    code, lines = compare(argv[0], argv[1])
    for line in lines:
        print(line)
    return code


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
