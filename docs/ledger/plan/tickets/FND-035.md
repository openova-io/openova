# FND-035 — The gate workflow

## In plain words

**The problem today.** The acceptance suite runs from a workflow that knows nothing of release candidates or of the gate manifest. It does not wait for the hand-over of a new Sovereign to finish, it commits whatever record the suite writes, and it would fail a long-lived environment for checks that only a fresh installation can pass.

**What changes.** One gate workflow replaces it. It verifies the candidate, waits for the hand-over chain, runs the suite with every gate check of the manifest, and commits only a record that the record schema accepts. A small tool decides whether the run fails on the environment it ran against.

**Done means:**

- The old workflow file is gone, and no workflow or script names it any more.
- A pull request that changes the suite or the gate tools still runs the suite's unit tests, under the same check name as before.
- A run that names a candidate does not start the suite when the candidate cannot be verified.
- A run waits until the hand-over chain of the Sovereign has completed or failed, and writes which of the two into its summary.
- Only a record that the record validator accepts is committed to main, pushed with the release-writer key in a commit that starts no workflow.
- A failed required check whose change reaches an environment only by a fresh installation does not fail a run on an environment created before that change merged; the result stays in the record.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket the gate of the platform is one workflow, `.github/workflows/foundation-gate.yaml`, and `.github/workflows/acceptance-sovereign.yaml` is gone. A person or a later workflow starts it by hand (`workflow_dispatch`) or calls it (`workflow_call`) with an environment label and, optionally, a candidate `rc/<id>`. Its job `unit` runs the suite's unit tests and the gate tools' self-tests, on pull requests that change them too, under the unchanged check name `suite unit tests + gate self-tests (no cluster)`. Its job `candidate` runs `scripts/release-candidate.sh verify <id>` when a candidate is named, and its job `live` does not start when that fails. The job `live` runs in the environment `gate`, on the runner whose label the input `runner` names (default `foundation-gate`). It checks out the workflow's own commit, which holds the gate tools and is where the record is committed from, and in the folder `candidate/` the commit under test. It waits until the hand-over chain of the Sovereign has ended, runs the suite with `--run-in cloud --record` and the manifest of the commit under test, validates the record with `scripts/acceptance-gate.py validate-record`, commits a valid record to `main` with the release-writer key, and lets the new tool `scripts/gate-run-outcome.py` decide whether the run fails on this environment. A person sees the result in the job summary of the run (the lines `Hand-over chain: ...`, `Environment created at: ...`, the step table of the suite and the outcome lines) and, for a valid record, in a commit `docs(acceptance): <env> gate run <PASS or FAIL> [skip ci]` on `main`.

## 3. The model (the law)
1. `.github/workflows/foundation-gate.yaml` is the block `foundation-gate.yaml` of field 20, copied exactly. `scripts/gate-run-outcome.py` is the block `gate-run-outcome.py`, copied exactly. `.github/workflows/acceptance-sovereign.yaml` is deleted. Line 38 of `tests/acceptance/sovereign/README.md` names the new workflow instead of the old one; nothing else of the README changes.
2. Triggers of the new workflow: `workflow_dispatch` and `workflow_call` with the same eight inputs (`env` required; `deployment_id`, `candidate_id`, `previous_deployment_id`, `previous_wipe_orphans`, `nodes_requested`, `capabilities` empty by default; `runner` with the default `foundation-gate`); `pull_request` with the paths of the old workflow, with `scripts/gate-run-outcome.py` added and the workflow's own path changed to the new file; `merge_group` with no path filter. The old inputs `journeys` and `record` are gone: a gate run always runs the default journeys and always records.
3. Jobs: `unit` (the old job, plus the self-test of `scripts/gate-run-outcome.py`); `candidate`, only when `candidate_id` is not empty and the event is not a pull request or merge group: it sets up the tools exactly as the job `cut` of `.github/workflows/cut-release-candidate.yaml` does and prints the commit that `verify` prints; `live`, only on a dispatch or call, only when `unit` succeeded and `candidate` succeeded or was skipped because no candidate was named.
4. The job `live` checks out the commit under test into `candidate/`: the commit that `verify` printed, or else `github.sha`. Without a candidate the record has an empty `candidate.id` and never counts for a verdict (pass rule 1 of `scripts/acceptance-gate.py`).
5. The hand-over chain has ended when the ConfigMap `self-sovereign-cutover-status` in the namespace `catalyst` of region A (the kubeconfig `ACCEPTANCE_KUBECONFIG_A`) has `cutoverComplete` equal to `true` (completed) or a non-empty `failedStep` (failed). The job reads it every 30 seconds for at most 180 minutes. It writes `Hand-over chain: completed` or `Hand-over chain: failed at step <step>` (then also `Hand-over error: <lastError>`) into the job summary and goes on in both cases. When the chain has not ended after 180 minutes, or the ConfigMap could not be read for that long, the job writes `Hand-over chain: did not end within 180 minutes; last observed: ...` and fails without running the suite. The job never starts or stops the chain.
6. The environment's creation time is the earliest `metadata.creationTimestamp` of the namespace `kube-system` in the two regions. When it cannot be read the suite still runs, and the last step fails because it cannot judge the run.
7. The suite runs through `scripts/acceptance-sovereign.sh <env> --record` inside `candidate/`, with `ACCEPT_RUN_IN=cloud`, `ACCEPT_MANIFEST` set to the JSON that `scripts/acceptance-gate.py export` prints in `candidate/`, the inputs passed as `ACCEPT_*` variables, and `ACCEPT_CAPABILITIES` set to `multi-region`, plus `previous-wipe` when `previous_deployment_id` is given, plus the input `capabilities`. `GITHUB_SHA` is set to the commit of `candidate/` for the suite, because the suite takes the commit it was built from from that variable. `scripts/acceptance-sovereign.sh` is not changed: it passes every argument through, and the suite reads every one of these inputs from its `ACCEPT_*` variable.
8. The suite writes exactly one new file under `candidate/docs/ledger/acceptance/`. The job copies it to `docs/ledger/acceptance/` of the workflow's checkout and runs `scripts/acceptance-gate.py validate-record` on it there. A valid record is committed, PASS or FAIL, with the step `uses: ./.github/actions/use-release-writer` before the commit and `[skip ci]` in the commit's first line, and pushed to `main`. A record that is not valid is not committed; it is uploaded as an artifact of the run, and the job fails.
9. `scripts/gate-run-outcome.py --record <file> --born <time>` decides whether a run with a valid record passes on its environment. A PASS record passes. A FAIL record passes only when every cause is excused. Causes: a step of journey `D0` that is not PASS, a journey that is not PASS, and a required check that is not PASS (a SKIP whose `needs` the run did not declare is no cause). A failed required check is excused when its `delivered_by` package touches a first-boot path (under `infra/providers/` or `clusters/_template/bootstrap-kit/`, or `scripts/expected-bootstrap-deps.yaml`) and the commit that added `docs/ledger/plan/done/<package>.yaml` is later than the creation time, or when the check's `proof` is `fresh` and the record's `provision.fresh` is not true. A FAIL record with no cause at all fails. Every cause is printed and goes into the job summary; the record itself is unchanged.

#!/usr/bin/env python3
"""gate-run-outcome.py - does one gate run pass on the environment it ran against.

  python3 scripts/gate-run-outcome.py --record <file> --born <time> | --self-test
The job live of .github/workflows/foundation-gate.yaml runs it on the record the suite wrote
(docs/ledger/acceptance/<env>-<run_id>.json). <time> is when the environment was created: the
earliest creation time of the namespace kube-system in its regions, such as 2026-11-20T08:15:00Z.
The tool reads docs/ledger/gates.yaml, docs/ledger/plan.yaml and the history of HEAD.

A record whose result is PASS passes. A record whose result is FAIL passes only when every cause of
the FAIL is excused. The causes, and the two rules that excuse:
  discovery  a step of the journey D0 that is not PASS. Never excused.
  journey    a journey of the record's journeys map that is not PASS. Never excused.
  check      a check with state_at_run required whose status is not PASS. A SKIP whose needs the
             run did not declare is no cause.
    born     The package that delivered_by names in docs/ledger/gates.yaml touches a first-boot
             path in docs/ledger/plan.yaml (a path under infra/providers/ or
             clusters/_template/bootstrap-kit/, or scripts/expected-bootstrap-deps.yaml), and the
             commit of HEAD's history that added docs/ledger/plan/done/<package>.yaml is later
             than <time>. Such a change reaches an environment only by a fresh installation, so an
             environment created before it cannot pass the check. The result stays in the record.
    fresh    The check has proof fresh in docs/ledger/gates.yaml and the record's provision.fresh
             is not true: only a record of a fresh installation proves such a check.
  unknown    the result is FAIL and none of the causes above is found. Never excused.
Every cause is printed, an excused one with its rule.
Exit 0: the run passes. 1: it fails. 2: an input cannot be read or the usage is wrong.
"""
import datetime, json, os, re, subprocess, sys, tempfile

MANIFEST = "docs/ledger/gates.yaml"
PLAN = "docs/ledger/plan.yaml"
DONE = "docs/ledger/plan/done/%s.yaml"
FIRST_BOOT = re.compile(r"^(infra/providers/|clusters/_template/bootstrap-kit/|scripts/expected-bootstrap-deps\.yaml$)")


class Bad(Exception):
    """An input cannot be read. The tool then gives no verdict: exit 2."""


def parse_time(text):
    if not isinstance(text, str) or not re.match(r"^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d", text):
        return None
    try:
        t = datetime.datetime.fromisoformat(text[:-1] + "+00:00" if text.endswith("Z") else text)
    except ValueError:
        return None
    return t if t.tzinfo else None


def utc(t):
    return t.astimezone(datetime.timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")


def outcome(rec, checks, touches, merged_at, born):
    """(passes, lines). checks: {id: manifest entry}. touches(pkg) -> list of paths or None.
    merged_at(pkg) -> the time the marker of pkg was added, or None."""
    if not isinstance(rec, dict) or rec.get("result") not in ("PASS", "FAIL"):
        raise Bad("the record has no result PASS or FAIL")
    if rec["result"] == "PASS":
        return True, ["PASS: the record's result is PASS"]
    hard, lines = [], []
    for s in rec.get("steps") or []:
        if s.get("journey") == "D0" and s.get("status") != "PASS":
            hard.append("discovery: step %s is %s" % (s.get("id"), s.get("status")))
    for j, status in sorted((rec.get("journeys") or {}).items()):
        if status != "PASS":
            hard.append("journey: %s is %s" % (j, status))
    declared = set(rec.get("capabilities") or [])
    fresh_record = isinstance(rec.get("provision"), dict) and rec["provision"].get("fresh") is True
    found = 0
    for c in rec.get("checks") or []:
        if c.get("state_at_run") != "required" or c.get("status") == "PASS":
            continue
        entry = checks.get(c.get("id")) or {}
        if c.get("status") == "SKIP" and entry and not set(entry.get("needs") or []) <= declared:
            continue
        found += 1
        what = "check: %s is %s" % (c.get("id"), c.get("status"))
        pkg = entry.get("delivered_by")
        paths = touches(pkg) if pkg else None
        at = merged_at(pkg) if pkg and paths and any(FIRST_BOOT.match(p) for p in paths) else None
        if at is not None and at > born:
            lines.append("excused (born): %s; %s changes first-boot files and merged at %s, after the environment was created at %s"
                         % (what, pkg, utc(at), utc(born)))
        elif entry.get("proof") == "fresh" and not fresh_record:
            lines.append("excused (fresh): %s; its proof is fresh and this record is not of a fresh installation" % what)
        else:
            hard.append(what)
    if not hard and not found:
        hard.append("unknown: the record's result is FAIL and it names no cause")
    lines = ["cause: " + h for h in hard] + lines
    if hard:
        return False, lines + ["FAIL: %d cause(s) are not excused" % len(hard)]
    return True, lines + ["PASS on this environment: every cause of the FAIL is excused and stays in the record"]


def merged_at_git(pkg):
    r = subprocess.run(("git", "log", "-1", "--diff-filter=A", "--format=%cI", "HEAD", "--", DONE % pkg), stdout=subprocess.PIPE, stderr=subprocess.PIPE)
    if r.returncode != 0:
        raise Bad("git log failed: %s" % r.stderr.decode("utf-8", "replace").strip())
    out = r.stdout.decode("utf-8", "replace").strip()
    return parse_time(out) if out else None


def load_yaml(rel):
    try:
        import yaml  # imported here: the self-test runs without the YAML library
    except ImportError:
        raise Bad("the Python YAML library is not installed")
    try:
        with open(rel, encoding="utf-8") as f:
            return yaml.safe_load(f)
    except (OSError, yaml.YAMLError) as e:
        raise Bad("%s cannot be read: %s" % (rel, str(e).split("\n")[0]))


def run(record, born_text, say=print):
    try:
        born = parse_time(born_text)
        if born is None:
            raise Bad("--born %r is not a time such as 2026-11-20T08:15:00Z" % born_text)
        try:
            with open(record, encoding="utf-8") as f:
                rec = json.load(f)
        except (OSError, ValueError) as e:
            raise Bad("%s cannot be read: %s" % (record, e))
        manifest, plan = load_yaml(MANIFEST), load_yaml(PLAN)
        checks = {c["id"]: c for c in manifest["checks"]}
        touches = {p["id"]: p.get("touches") or [] for p in plan["packages"]}
        ok, lines = outcome(rec, checks, touches.get, merged_at_git, born)
    except (Bad, KeyError, TypeError) as e:
        say("gate-run: cannot judge the run: %s" % e)
        return 2
    for ln in lines:
        say("gate-run: " + ln)
    return 0 if ok else 1
