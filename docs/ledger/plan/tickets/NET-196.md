# NET-196 — Organization passthrough listeners: the platform API writes them for internal Organizations and its orphan reaper removes them

## In plain words

**The problem today.** An Organization can list hosts whose TLS sessions the console gateway passes unopened to the back end, but only the organization controller writes those passthrough listeners. Internal Organizations, whose listeners only the platform API writes, get none, and when the platform API removes the listeners of an Organization that no longer exists it leaves the passthrough listeners behind.

**What changes.** The platform API writes the passthrough listeners of each Organization it reconciles, in every region, and removes them when the host leaves the list. Its cleaner of orphaned Organizations removes them with the listener pair.

**Done means:**

- An internal Organization that lists a host label has a TLS passthrough listener for exactly that host on the console Gateway of every region, on the port of the HTTPS listener.
- A label removed from the list loses its listener in every region on the next reconcile pass.
- A second pass with nothing changed writes nothing, and a host list that cannot be read writes nothing.
- The cleaner of orphaned Organizations removes the listener pair and every passthrough listener of the orphaned Organization, and keeps the listeners of an Organization whose name starts with the same letters.
- The platform API and the organization controller write the same listener for the same host, so neither rewrites the other's.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After NET-195 an Organization lists in `spec.tenantPublic.passthroughHosts` the leftmost labels of hosts under its own zone, and the organization controller writes one TLS passthrough listener `console-tls-<slug>-<label>` per label on the console Gateway `kube-system/cilium-gateway-console`. This ticket is the second piece of that plan text: the platform API (catalyst-api) does the same for every Organization its console reconcile pass accepts, which includes the internal Organizations whose listeners only the platform API writes, in every region the pass reaches; and its orphan reaper, which today strips only the pair `console-https-<slug>` and `console-http-<slug>` of an Organization whose resource is gone, also strips that Organization's passthrough listeners. Both writes go through a new package `products/catalyst/bootstrap/api/internal/orglisteners`, which builds and merges the listeners with the functions of `core/controllers/pkg/orglistener` (NET-195), so the two writers compute one value.

## 3. The model (the law)
1. `orglisteners.Gateway{Dyn, Namespace, Name}` is one region's console Gateway. Every write is a read-modify-write `Update` of `spec.listeners`, written only when the listeners changed; a missing Gateway is no change and no error. Server-side apply is not used: it cannot prune list entries another field manager owns, and the organization controller writes its listeners by `Update`.
2. `orglisteners.EnsurePassthrough(ctx, org, slug, zone, consoleRouteNamespace, gateways)` reads `spec.tenantPublic.passthroughHosts` of the Organization resource and, in each Gateway, makes the Organization's passthrough listeners equal to `orglistener.PassthroughListeners(slug, zone, labels, port, consoleRouteNamespace)` with `orglistener.MergePassthrough`. `port` is the port of the apex listener `console-https` (fallback 8443), the port the organization controller takes. A host list that cannot be read (not a list of strings) is an error and writes nothing.
3. `reconcileOrgConsoleTLSOnce` (`org_console_tls_reconcile.go`) calls it after `provisionOrgConsoleTLS` for each Organization it accepts, with `names.Slug` and `names.OrgZone` of `resolveOrgConsoleTLSNames`, the namespace `catalyst-system`, and the Gateways of `orgConsoleTLSTargets` (resolved once per pass). An error is logged and the next tick retries. The BSS door's provisioning path does not write them: its record carries no host list.
4. `Gateway.RemoveOrg(ctx, slug)` removes `console-https-<slug>`, `console-http-<slug>` and every listener for which `orglistener.IsPassthroughListenerOf(name, slug)` holds, keeps every other listener in its order, and reports whether it removed one. The reaper `reapScanOrphans` (`org_console_tls_reap.go`) calls it in place of `removeOrphanConsoleListeners`, which is deleted.
5. For an Organization both writers handle (one with `spec.tenantPublic.parentDomain`), the platform API and the organization controller compute the same listener (same name, host, port, protocol, mode and admission), and `MergePassthrough` ignores a field the API server defaults, so neither writer finds a change to make after the other.
6. `scripts/baselines/api-structure.json` is lowered to the measured line count of the handler folder by its own command (`--write-baseline`), never by hand.
