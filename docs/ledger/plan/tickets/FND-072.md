# FND-072 — Flight checklist in the lifecycle script: the sweep command and the fire that refuses without a clean sweep

## In plain words

**The problem today.** A fresh installation can be fired while the wiped one still holds networks, disks or addresses in the cloud account, and nothing in the lifecycle script stops it. The variables document that a listing of the account needs is deleted by a wipe that converges. The runbook also states the certificate limit of Let's Encrypt wrongly.

**What changes.** The lifecycle script keeps the variables document before every wipe, gains a sweep command that waits for an empty account, and refuses a fire without a clean sweep of the wiped deployment. The runbook gets a section on these three steps and the correct certificate limit.

**Done means:**

- Before a wipe, the lifecycle script keeps the deployment's variables document outside the repository, readable by its owner only.
- The sweep command lists the cloud account again while leftovers remain, for at most 30 minutes, and ends with a clean result, a leftover result or not measured.
- A fire without the id of the last wiped deployment, or with leftovers or an unmeasured listing of it, is refused before the pre-flight gate runs.
- A fire after a clean sweep prints the line with the leftover count and goes on to the pre-flight gate.
- The runbook has a section that lists the wipe, the sweep and the fire in order, and states the certificate limit as five certificates for the same set of names in seven days.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`scripts/sovereign-lifecycle.sh` runs the flight checklist around a fresh installation. `wipe <id>` keeps the deployment's variables document before the wipe, through its capture step. `sweep <id>` runs `scripts/flight-sweep.sh` (package FND-071) on that document until the account holds nothing of the deployment, at most 30 minutes, and then prints `SWEEP PASS <id> leftovers=0`. `PREV_ID=<id> fire <subdomain> [pool]` lists the account once more and refuses unless that listing is clean; only then does it run the pre-flight gate. Section 0.7 of `docs/RUNBOOKS.md` describes the three steps, and the certificate limit is stated as five certificates for the same set of names in seven days. A test with stand-ins proves every rule without a cloud account.

## 3. The model (the law)
1. **The leftover lister is used, not changed.** `scripts/flight-sweep.sh` (package FND-071) takes one argument, the variables document of a wiped deployment. Exit code 0: nothing of the deployment is left. Exit code 1: something is left. Every other exit code means the account was not measured. This ticket relies on nothing else of it, and does not read what it prints.
2. **The document is kept before the wipe.** The function `capture <id>`, which `wipe` calls first, ends with `keep_vars <id>`. `keep_vars` copies `/var/lib/catalyst/tofu/<id>/tofu.auto.tfvars.json` (or `/deps/tofu/<id>/...`) out of the catalyst-api Pod of namespace `catalyst` to `${FLIGHT_DIR}/<id>-vars.json`. `FLIGHT_DIR` defaults to `/tmp/flight`, outside the repository, because the document holds cloud credentials. The folder has mode 700 and the file mode 600. The copy is written to a temporary file and moved into place only when it is a JSON document, so a failed copy never removes an earlier one. A failed copy prints a warning and never stops the capture or the wipe. An id that is not made of letters, digits and dashes is not used.
3. **The sweep.** `sweep <id>`: exit code 2 for a missing or not plain id; exit code 3 (`SWEEP NOT MEASURED`) when no kept document exists, before any listing. Otherwise it runs `bash scripts/flight-sweep.sh <kept document>`. Code 0: it prints `SWEEP PASS <id> leftovers=0` and exits 0. Code 1: it lists again after `SWEEP_INTERVAL` seconds (default 60) while the time used plus one interval is below `SWEEP_TIMEOUT` seconds (default 1800); then it prints `SWEEP FAIL <id>: ...` and exits 1. Any other code: it prints `SWEEP NOT MEASURED <id>: ...` and exits 3 at once.
4. **The fire.** The first thing `fire` does is `SWEEP_TIMEOUT=0 sweep "${PREV_ID:-}"`: one listing, no waiting. When that does not exit 0, `fire` prints `!! NO CLEAN SWEEP — fire ABORTED: ...` and returns 1, before the variables fetch, the pre-flight gate, the reset of the acceptance ledger and the request. A clean sweep prints `SWEEP PASS <id> leftovers=0`; that line is the leftover count for the gate input. There is no bypass.
5. **What does not change.** The function `wipe`, the request body line of `fire` and everything in `fire` after the new block are byte for byte as they are. Other packages' acceptance commands read the first lines of `wipe` and the body line.
6. **The runbook.** A new section `### 0.7 Flight checklist — wipe, sweep, fire` follows section 0.6 and comes before the line `---` that ends section 0, so the number of second-level sections does not change. The troubleshooting row that said `5 per registered domain per week` says `5 certificates for the same set of names in 7 days`.
7. **The test.** `scripts/tests/test-sovereign-lifecycle-flight.sh` copies the lifecycle script into a temporary tree beside stand-ins for `scripts/flight-sweep.sh` and `scripts/prov-preflight.sh`, puts stand-ins for `kubectl` and `curl` first on `PATH`, and checks every rule of points 2 to 4 in 14 cases. It sets `CATALYST_MOTHERSHIP_KEY` to a path that does not exist, so the copied script signs no token, whatever key the host holds. It sends nothing over the network.
8. This ticket deletes no file.
