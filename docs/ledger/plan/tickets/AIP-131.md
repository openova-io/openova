# AIP-131 — Model checks AIP-G02 to AIP-G05 as expected-fail

## In plain words

**The problem today.** The model gateway has four gate checks in the record, for a tool round trip, a metered streamed call, usage that carries the verified Organization and the simulation aliases, but none of them is built. Without them a run of the acceptance suite cannot show whether the gateway keeps the model contract, and no later task can turn them on. Other checks also need one metered model call with no real model, and there is no shared way to make it.

**What changes.** The four checks exist in the acceptance suite, one file each, and the record lists them as expected to fail until the gateway is delivered. The suite can read the meter's entry of a request and offers one shared, metered probe call for every check that needs it.

**Done means:**

- The acceptance suite registers the checks AIP-G02, AIP-G03, AIP-G04 and AIP-G05, each in a file of its own.
- The gate record lists each of the four checks as expected-fail with the path of its file, and the record tool accepts the change.
- The suite reads the meter's entry of a request and judges it against the usage of the answer by the mapping of the model contract; a test shows that a wrong stream flag, wrong token counts or another Organization is refused.
- The suite exports one probe function that makes a single metered call per run and returns the Organization of its usage event, the alias and the request identifier.
- No other gate check changes, and the existing tests of the suite stay green.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite (`tests/acceptance/sovereign`, Go module `github.com/openova-io/openova/tests/acceptance/sovereign`) gains the four gate checks of the model gateway, each a file of `internal/suite` that registers itself, on the model contract client `internal/modelcontract` (AIP-130). `internal/modelcontract/meter.go` reads the meter: `Measures` maps a usage block to the measures of section 4 of `docs/contracts/model-contract.md`, `ReadEntry` asks one meter pod for its entry of a request (`GET /internal/events/{requestId}` on the admin port), and `Entry.Metered` judges that entry against the usage of the answer. `internal/suite/check_aip_model.go` holds only helpers: a `kubectl port-forward` to `service/model-gateway` port 8080 and one to port 9090 of each pod with the label `app.kubernetes.io/name=model-meter` in namespace `model-gateway`, an agent token minted as check AIP-G07 mints it, and "the meter has the entry" meaning that exactly one meter pod returns it, waited for with the suite's `poll` for up to 30 seconds. It exports `ModelUsageProbe(ctx) (organization, alias, requestID string, err error)`, made once per run on `conformance-echo` with the header `x-openova-organization: someone-else`; check AIP-G04 calls it, and BSS-G09 and AIP-G09 will. In `docs/ledger/gates.yaml` the four checks move from not-built to expected-fail with their implementation paths. AIP-140 flips AIP-G02 to AIP-G04 to required, AIP-320 flips AIP-G05.

## 3. The model (the law)
1. One file per check: `check_aip_g02.go`, `check_aip_g03.go`, `check_aip_g04.go` and `check_aip_g05.go` each hold `const aipG0NID = "AIP-G0N"` and `func init() { RegisterCheck(modelCheck{id: aipG0NID, steps: aipG0NSteps}) }`. `check_aip_model.go` registers no check.
2. The first step of every model check opens the session: the forward to the gateway, one forward per meter pod, the agent token. Its later steps run only when that step passed. Every forward is stopped when the check ends.
3. AIP-G02: `GET /v1/models` lists `conformance-echo` with `owned_by` `stub`; a tool offered on that alias is called, and the follow-up with the tool result is answered `echo:probe-result-42` (the stub's rule 1).
4. AIP-G03: a streamed call on `conformance-echo` with `include_usage` keeps the order of section 1.4 and ends with a usage chunk whose completion tokens are the stub's (the answer's byte length divided by 4, rounded up) with 0 cached tokens; exactly one meter pod has the entry: status `ok`, `stream` true, published, Organization `conformance` (the token's), measures equal to `Measures` of that usage.
5. AIP-G04: the call of `ModelUsageProbe` names Organization `someone-else` in a header, and its usage event names `conformance`, the token's (section 3); a call without a token gets 401 `invalid_token` and no meter pod has an entry for its request; the model `nope` gets 404 `model_not_found` (section 1.5).
6. AIP-G05: on `agent-default` a tool round trip, two tool calls in one answer, a streamed tool call as deltas with an index and a usage with no zero count; on `agent-fast` a tool round trip. `needs` stays empty.
7. `Measures` is the meter's mapping: input is prompt less cached and cache-write tokens, then cache_read, cache_write and output, a token measure of 0 left out, `llm.requests` always 1. `Entry.Metered` refuses an entry that is not `ok` and published, whose stream flag differs from the call's, whose Organization differs between entry, event and subject, whose alias differs, or whose measures differ from `Measures` of the answer's usage; each error starts with the section of the contract, `3` or `4`.
8. `ModelUsageProbe` takes only `ctx`: the runner puts no run in a context, so a caller wraps it with `withModelRun(ctx, cc)`, as check AIP-G04 does and BSS-G09 will. The call is made once per run; every later caller gets the stored result.
9. Standard library only; `check_aip_g07.go` is not changed: the helpers reuse its constants and `agentCall`.

+type Measure struct {
+	Meter    string `json:"meter"`
+	Quantity int64  `json:"quantity"`
+}
+
+// Measures maps a usage block to the measures of section 4, in the meter's order: input is the
+// prompt less the cached and cache-write tokens, never below 0, then cache_read, cache_write and
+// output; a token measure of 0 is left out; llm.requests is always 1.
+func Measures(u Usage) []Measure {
+	var cached int64
+	if u.Details.Cached != nil {
+		cached = *u.Details.Cached
+	}
+	out := []Measure{}
+	for _, m := range []Measure{{"llm.tokens.input", u.Prompt - cached - u.Details.CacheWrite},
+		{"llm.tokens.cache_read", cached}, {"llm.tokens.cache_write", u.Details.CacheWrite}, {"llm.tokens.output", u.Completion}} {
+		if m.Quantity > 0 {
+			out = append(out, m)
+		}
+	}
+	return append(out, Measure{"llm.requests", 1})
+}

+// Entry is the meter's record of one request: GET /internal/events/{requestId} on the admin port
+// of a meter pod. Event is the usage event as published, or empty.
+type Entry struct {
+	RequestID    string `json:"requestId"`
+	Organization string `json:"organization"`
+	Alias        string `json:"alias"`
+	Stream       bool   `json:"stream"`
+	Status       string `json:"status"`
+	Published    bool   `json:"published"`
+	Event        struct {
+		Subject string `json:"subject"`
+		Data    struct {
+			Organization string `json:"organization"`
+			Resource     struct {
+				ID string `json:"id"`
+			} `json:"resource"`
+			Measures []Measure `json:"measures"`
+		} `json:"data"`
+	} `json:"event"`
+}
+
+// ReadEntry asks one meter pod, at its admin address base, for the entry of requestID. found
+// is false when the pod answers 404.
+func ReadEntry(ctx context.Context, base, requestID string) (e Entry, found bool, err error) {
+	req, err := http.NewRequestWithContext(ctx, http.MethodGet, strings.TrimRight(base, "/")+"/internal/events/"+url.PathEscape(requestID), nil)
+	if err != nil {
+		return e, false, err
+	}
+	res, err := httpClient.Do(req)
+	if err != nil {
+		return e, false, fmt.Errorf("GET /internal/events/%s on %s got no answer", requestID, base)
+	}
+	defer func() { _ = res.Body.Close() }()
+	switch {
+	case res.StatusCode == http.StatusNotFound:
+		return e, false, nil
+	case res.StatusCode != http.StatusOK:
+		return e, false, fmt.Errorf("GET /internal/events/%s on %s answered %d", requestID, base, res.StatusCode)

+		return e, false, fmt.Errorf("GET /internal/events/%s on %s answered no entry: %v", requestID, base, err)
+	}
+	return e, true, nil
