# SVC-159 — The Blueprint files say what the seed says

## In plain words

**The problem today.** Every installed Sovereign holds a catalogue seed that is written by hand. The Blueprint files, from which that seed is to be generated, disagree with it on 809 fields in 70 Blueprints, so generating the seed today would change how installations behave. Some of the seed's values cannot simply be copied into the files: the repository's guards refuse a claim of session recording and the name of a cloud provider in shared files, and a console test refuses the replication the seed names for the OpenBao secret store, which only the commercial edition offers. The seed also describes the replicated database pair as asynchronous with a 30 second recovery point, while its chart runs synchronous replication that loses no committed transaction.

**What changes.** The Blueprint files say what the seed says, and a check proves it on every pull request that touches them. The refused texts lose only the refused words, and the replication of OpenBao and of the database pair is named as their charts run it, in the seed and in the files alike, and the category of a provider's Blueprint is declared in that provider's own folder.

**Done means:**

- For every Blueprint the seed holds, its file says what the seed says, field by field, except the configuration schema.
- A check compares the files with the seed and fails with the list of differing fields; it says in its output that the configuration schema is not compared yet.
- The check runs on every pull request that changes a Blueprint file, the seed or a category file.
- The remote-desktop gateway no longer claims session recording, and the media gateway and chargeback texts no longer name a cloud provider, in the seed and in the files alike.
- The category of a provider's Blueprint is declared in that provider's own folder, and the shared category file names no provider.
- The OpenBao secret store and the replicated database pair are described with the replication their charts run, in the seed and in the files alike.
- The number of Blueprint files that carry a card family falls from 35 to 31, and the number that carry a category stays at 37.

The rest of this ticket is the exact instruction for the model that does the work.

The application controller reads the backend only when the switchover mechanism is unknown (`core/controllers/application/internal/controller/continuum.go` line 239), and the mechanism of `bp-openbao` is `raft-transition` in both. The chart runs Raft storage in each region (`platform/openbao/chart/values.yaml` lines 37 to 41, `ha.raft.enabled: true`; line 481, an independent Raft per region), so `raft` is what it does. The card description's words "async perf-replication across regions" name a replication the chart does not run: they are removed in the seed and in the file; the rest of the description does not change.

+"""check-seed-equals-blueprints.py - the Blueprint files say what the hand-written seed says (SVC-159).
+
+products/catalyst/chart/templates/catalog-seed/blueprints.yaml is what every installed Sovereign holds. SVC-160
+replaces it with a file that scripts/generate-catalog.py writes from the Blueprint files, and that switch may
+change nothing the application controller or the console reads. This check computes, without writing a file, the
+object the generator will write for each Blueprint file, compares it parsed with the seed as Helm renders it, and
+exits 1 with one line per differing object and field. SVC-160 deletes it with the hand-written seed.
+
+The files are read as the generator reads them: platform/<name>/blueprint.yaml and products/<name>/blueprint.yaml,
+parsed with its Loader and named by its entry(). The projection of a file to its seed object:
+  spec          the file's spec, with spec.source derived: kind HelmRepository, type oci, url oci://ghcr.io/openova-io,
+                chart the Blueprint's name, version its spec.version;
+  version       the file's spec.version, except: the Blueprint named in the Chart.yaml of products/catalyst/chart,
+                the chart that holds the seed, takes that chart's version (Helm renders it there); a Blueprint
+                without a chart folder whose pin is registered in scripts/expected-unpublished-catalog-seed-pins.yaml
+                takes the registered version, because spec.version of a Blueprint file is release-owned;
+  card.category the file's, or else the one a category data file declares for the Blueprint: the shared
+                platform/_catalog/card-categories.yaml, or for a provider's Blueprint (its folder is listed in
+                spec.charts of infra/providers/<provider>/pack.yaml) that provider's own
+                infra/providers/<provider>/card-categories.yaml. A category is said in one place: a data file never
+                names a Blueprint whose file carries one, and a Blueprint is named only in the data file of its owner.
+Compared: every key of spec but NOT_READ and NOT_COMPARED_YET, and the labels in READ_LABELS. A seed object
+without a Blueprint file is a difference unless GHOSTS names it; a Blueprint file without a seed object is not
+compared.
+
+  python3 scripts/check-seed-equals-blueprints.py              exit 0 equal; 1 differences, one line each; 2 cannot run
+  python3 scripts/check-seed-equals-blueprints.py --self-test  one failing case per rule
