# CLD-114 — Adoption map, name lists and schema enums

## In plain words

**The problem today.** The code that hands cloud resources to the day-2 layer keeps one shared table of the resource types of every cloud, and assumes one cloud when none is recorded. The job page keeps its own list of cloud names and labels an unknown cloud as one particular cloud. The controller that creates an Organization's Environment assumes one cloud on every Sovereign, and the Environment and Sovereign definitions accept only a fixed list of cloud names, so a new cloud pack needs edits in all of these places.

**What changes.** Each cloud adapter declares the resource types it adopts, and the job label is made from the cloud name itself. The controller writes the cloud pack that the platform chart passes to it, or no cloud when none is known, and both definitions accept any pack name of the agreed form.

**Done means:**

- The adoption generator holds no cloud resource type: both cloud adapters declare theirs, and an empty or unknown cloud is refused instead of guessed.
- The Phase-0 job group is labelled from the cloud name itself, and a deployment with no recorded cloud is labelled Provision infrastructure.
- The Organization controller writes the cloud pack that the platform chart passes to it into each new Environment, and writes no cloud when the chart passes none.
- The Environment and Sovereign definitions accept any lower-case pack name of up to 31 characters and refuse a name with upper case or a dot.
- The new tests of the generator, the job label and the controller pass, and the provider-leak guard passes with lower counts for the changed files.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
No shared code of this package names a cloud provider to decide what to do. `GenerateAdoptionClaims` (`products/catalyst/bootstrap/api/internal/provisioner/adoption.go`) reads the OpenTofu resource types it adopts from the adapter of the given provider through `providers.As[providers.AdoptionMapper]`; the Huawei and Hetzner adapters implement `AdoptionKinds` with the entries the shared map held, and the map and both `"huawei"` defaults are deleted. `ProvisionerDisplay` (`internal/jobs/types.go`) makes the label from the provider name itself and keeps no list; an empty provider gives `Provision infrastructure`. The Organization controller reads the Environment provider from `CLOUD_PROVIDER`, which its Deployment sets from `global.cloud.provider`, with no default and no list: a value that does not match the pattern is left out of the Environment. The `provider` property of the Environment kind (`spec.regions[].provider`) and of the Sovereign kind (`spec.provider`) becomes `type: string, pattern: '^[a-z][a-z0-9-]{1,30}$'`, the pack-name rule of `providers.CloudProvider.Name`. A person sees it on the pull request: the new tests pass and the changed files name no provider in code.

## 3. The model (the law)
1. `adoptionKinds(cloud)` returns `AdoptionKinds()` of the adapter registered under `cloud`. An adapter that does not implement `providers.AdoptionMapper` adopts nothing (nil map, no error). An empty or unregistered `cloud` is an error, which `GenerateAdoptionClaims` returns as `adoption kinds: <cause>`.
2. `GenerateAdoptionClaims(tfstateJSON, sovereignFQDN, cloud, region)` keeps its signature and output. It never defaults `cloud`; `collectAdoptableResources` takes the kinds map as a parameter. `writeAdoptionClaims` passes `strings.TrimSpace(req.Provider)` (after `Validate`, never empty). The address comments that named clouds move into the function's doc comment.
3. `providers/huawei` and `providers/hetzner` each declare `var _ providers.AdoptionMapper = (*Provider)(nil)` and `AdoptionKinds()` with exactly the five entries of that cloud that `tfTypeToAdoptionKind` held.
4. `ProvisionerDisplay(p)`: trim and lower-case `p`; empty gives `GroupProvisionerDisplay`, which is `Provision infrastructure`; otherwise `Provision ` and `p` with its first letter upper-cased. `providerDisplayNames` is deleted.
5. The Organization controller: `cmd/main.go` sets `EnvRegionProvider` from `strings.TrimSpace(os.Getenv("CLOUD_PROVIDER"))`; `CATALYST_ENV_REGION_PROVIDER` and its default are gone. `envProviderAllowed` is replaced by `envProviderPattern` (`^[a-z][a-z0-9-]{1,30}$`). `envRegionDefaults` lower-cases the configured provider and returns it when it matches the pattern, else empty; a canonical host-cluster name still gives all three segments, its provider checked by the pattern. `ensureEnvironment` leaves `provider` out of the region when it is empty; the kind requires it, so the API server refuses that object and the Organization reports `EnvironmentEnsureFailed` instead of recording a guessed provider.
6. The organization-controller Deployment sets `CLOUD_PROVIDER` from `.Values.global.cloud.provider | default ""`, the value bootstrap-kit slot 13 fills from `${PROVIDER:-}` (CLD-113).
7. The Environment and Sovereign kinds: the provider enum is replaced by the pattern of law 5; no other property changes. `internal/intent/crds/schemas.json` is regenerated from the kinds by its own test (`INTENT_WRITE_SCHEMAS=1`). The invalid Sovereign sample keeps a provider the kind refuses (`Digital.Ocean`).
8. Nothing else changes: no chart version, no pin, no `go.mod`, no baseline file, no handler file.
