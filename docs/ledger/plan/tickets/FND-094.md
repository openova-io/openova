# FND-094 — Remove the Sandbox pages of the console

## In plain words

**The problem today.** The Sandbox product was withdrawn, but the sovereign-admin console still carries its four pages, the client file that calls its API, three routes that serve the pages, and a browser test that drives them. The pages call API routes that are about to be removed, and they hold eight of the console's lint errors. Comments in the console still say that the Sandbox routes stay.

**What changes.** The four pages, the client file and the browser test are deleted and recorded as deleted. The three routes, the navigation code for them, the test's place in the browser test workflow and the wrong comments are removed. The stored number of allowed lint errors falls by the eight errors that leave with the pages.

**Done means:**

- Opening a Sandbox address in the console no longer shows a Sandbox page.
- The console builds and all its unit tests pass.
- The agent workspace entry in the sidebar still opens the workspace through its Blueprint's own address.
- The browser test workflow no longer runs a Sandbox test, and its other twenty tests still run.
- The six removed files are on the list of deleted paths, so a guard fails if one of them comes back.
- The console's allowed lint error count is eight lower, and the console stays within it.

The rest of this ticket is the exact instruction for the model that does the work.
