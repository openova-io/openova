# FND-013 — Merge queue: aggregate check, queue triggers, rulesets and code owners as files

## In plain words

**The problem today.** The main branch has no merge queue, no required check and no code owners. A required check cannot simply name the existing workflows, because many of them run only when certain paths change, and a check that does not run would hold a pull request for ever. ## 2. End goal

## 3. The model (the law)
1. The required check is named `ci-gate`: the job `ci-gate` of `.github/workflows/ci-gate.yaml`, with `name: ci-gate`. GitHub requires a check by the name of its check run, which is the job's `name` (or its key when it has no `name`). The checks of the workflow `work-package` are therefore required as `scope` and `acceptance`, not as `work-package / scope`.
2. `ci-gate` judges every check run of the head commit except its own runs. Four rules apply.
   - A check is one job name in one workflow on one event. Of several runs of one check the newest counts. This is the rule of the command `checks` of `scripts/plan.py`.
   - Green is `success`, `skipped` or `neutral`, as in `scripts/plan.py`. A completed check with any other conclusion is red.
   - A red check fails the gate at once, with one exception. While a run of the check's workflow on the check's event has not finished, the job may run again: the check counts as unfinished, and the gate waits.
   - The gate also waits for every workflow run of the commit that has not finished, except the runs of its own workflow. A job of such a run may have no check run yet.

   `ci-gate` is stricter than `scripts/plan.py` in two points and quicker in one. This is intended. `scripts/plan.py` holds a red check back only while the workflow run of that same check run has not finished; `ci-gate` also holds it back while another run of the same workflow on the same event has not finished. `scripts/plan.py` does not wait for a workflow run whose check runs are all green; `ci-gate` does. `scripts/plan.py` reports red only after two readings 20 seconds apart; `ci-gate` reads for the first time after 60 seconds and fails on the first reading that shows a red check.
3. `ci-gate` never passes on missing evidence: three failed reads of the API in a row fail it, no check besides itself fails it, and a check or a workflow run still unfinished 90 minutes after the first read fails it.
4. Every workflow that runs on `pull_request` without `paths` or `paths-ignore` also runs on `merge_group`. In a merge group the jobs that read the pull-request body or its labels find none and pass; the same jobs judged the pull request before it entered the queue.
5. The ruleset files are the body of the REST call that creates a repository ruleset, with one difference: a bypass actor of type `Team` names its team by the slug (`"team": "release-writer"`) instead of `actor_id`, because the team's number does not exist before the team does. `scripts/check-ruleset-drift.py --body <file> --team-id <number>` prints the body to apply.
6. `main.json`: target `refs/heads/main`; merge queue with method `SQUASH`, strategy `ALLGREEN`, up to 5 entries built and up to 5 merged together, at least 5 per group with a wait of 5 minutes (after the wait a smaller group merges), and 120 minutes for a check to report; required checks `ci-gate`, `scope`, `acceptance`, not strict; a pull request with zero approvals and a review by a code owner; no force push; no deletion; one bypass actor, the team `release-writer`, mode `always`. `rc.json`: target `refs/heads/rc/**`; creation, update and deletion restricted; the same one bypass actor.
7. `.github/CODEOWNERS` owns exactly ten paths, each by `@alierenbaysal`: `docs/ledger/plan.yaml`, `docs/ledger/plan/tickets/`, `docs/ledger/gates.yaml`, `docs/ledger/stability.yaml`, `docs/adr/`, `.github/rulesets/`, `.github/CODEOWNERS`, `scripts/plan.py`, `scripts/acceptance-gate.py`, `scripts/check-frozen-paths.py`.
8. The drift checker fails when its token is absent or a read fails; it never passes on a read that did not happen. Its workflow has the trigger `workflow_dispatch` only.
9. Nothing in this package changes who may push or merge. No ruleset, setting or secret is changed by this package.

"""ci-gate.py - one required check that stands for every check run of a commit.

A workflow with a path filter does not run on every pull request, so it cannot be a required

Usage:

  python3 scripts/ci-gate.py --sha <commit>   the gate; reads GITHUB_TOKEN and GITHUB_REPOSITORY

1. Wait 60 seconds, so that every workflow of the event has created its runs.
2. Read every check run and every workflow run of the commit through the API, all pages.
   Leave out the check runs named ci-gate and every run of the gate's workflow: they are this
   gate. The gate's workflow is the one of a check run named ci-gate, and the one of the
   workflow run whose number is in GITHUB_RUN_ID.
3. A check is a job name in one workflow on one event. When a check has several runs, the
   newest counts (the latest start, then the higher id; a run not started yet is the newest),
   as in the command checks of scripts/plan.py.

   fails the gate at once, with one exception: while a run of its workflow on its event has
   not finished, the job may run again, so the check is unfinished.
5. A check whose status is not completed is unfinished. A workflow run whose status is not
   completed is unfinished too, also when each of its check runs is completed: one of its
   jobs may have no check run yet. While something is unfinished: read again after 30 seconds.
6. When nothing is unfinished and no check is red, the gate passes. When no check is found
   besides the gate, it fails: nothing was measured.
7. When something is still unfinished 90 minutes after the first read, the gate fails.
8. When the API cannot be read three times in a row, the gate fails. A failed read never passes.

    (workflow, event) of the check, or None when its workflow run is not known."""

              if w.get("check_suite_id") in mine or str(w.get("id")) == own_run)

            for line in lines:
                out(line)
            return 0 if verdict == "pass" else 1
        out("%d unfinished, reading again in %d seconds" % (len(lines), INTERVAL))
        sleep(INTERVAL)
