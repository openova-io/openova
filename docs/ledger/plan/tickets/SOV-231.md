# SOV-231 — The settled-roll pre-flight no longer offers its annotation override for a release the kit applies

## In plain words

**The problem today.** When the cutover refuses to start because a platform release is stuck for good, it tells the sovereign-admin to put a named override mark on that release. For a release that the platform's own GitOps kit applies, the kit removes that mark again within minutes, before the cutover reads it. The advice cannot work there, and the admin is sent round in a circle.

**What changes.** For a stuck release that the kit applies, the cutover no longer offers the mark: it names the release with what applies it and the three remedies that do work. For every other stuck release the offer, its checks and its record stay as they are, and the chart's documentation says where the mark holds.

**Done means:**

- A cutover refused by a stuck release that a Kustomization applies prints no override mark and no command to set one.
- That refusal names the release with the Kustomization that applies it, and the three remedies that work for it.
- A stuck release that no Kustomization applies is still offered the override, and the closing line says where the override holds.
- An override that is still present on a release is checked, honoured and recorded exactly as before.
- The chart's documentation of the override says that it holds only on a release that no Flux Kustomization applies.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. **Where the override holds.** On a HelmRelease that no Flux Kustomization applies. kustomize-controller removes a hand-set annotation from an object it applies, and such an object carries the label `kustomize.toolkit.fluxcd.io/name`, the label the delivery rule of the same values block already reads.
2. **The enumeration.** The jq program that builds `hr_all` keeps its `PLT `, `ORG ` and `REP ` lines unchanged. For a `PLT ` offender with that label it prints one more line: `KST HelmRelease/<ns>/<name>` followed by a tab and the Kustomization's name when the release is terminal (Stalled, or its pinned chart version is absent), `KSM ...` otherwise. `ORG ` and `REP ` offenders get no such line. `hr_ks_terminal` holds the `KST` lines, `hr_ks_count` counts the `KST` and `KSM` lines.
3. **The remedy for terminal offenders.** `terminal_ks` counts the `KST` lines. The three lines of the override offer are printed only when `terminal` is greater than `terminal_ks`, and their first line says that the override is for a release that no Flux Kustomization applies. When `terminal_ks` is above 0, the step prints the count, one line `  applied by Kustomization <ks>: HelmRelease/<ns>/<name>` per `KST` release, and the three remedies of field 2, each on its own line.
4. **The closing line.** It names the override (`named per-release override, on a HelmRelease no Flux Kustomization applies: the ${SETTLED_ROLL_OVERRIDE_ANNOTATION} annotation; `) only while the platform HelmRelease offenders outnumber `hr_ks_count`. A run whose offenders are all applied by a Kustomization, or are all workloads (the override is HelmRelease-only, #6273), no longer names it; the whole-gate switch is always named.
5. **Unchanged.** The verdict for every input (block or pass), the annotation key, the fail-closed validation (`or_bad`), the honoured overrides (`or_used`), the record in the cutover status ConfigMap (`srp_record_overrides`), the delivery rule and the hollow-pin and stalled remedies. No API route is added.
6. **Where the text lives.** The comment of Phase A0 gets two lines that point to `values.yaml`; the explanation is written there, above the key `prewarm.settledRollPreflight`, because the comments of a template are stored in every Helm release Secret and those of `values.yaml` are not (#6004).
7. **The render comparison.** `tests/step6490-secondary-gitea-mirror.sh` compares the single-region render of the change with that of its merge base modulo named axes. It gets one more axis: while the base render lacks `hr_ks_terminal=`, the step-03 document is left out of both renders. The axis switches itself off once `main` holds the change.
8. **No version line.** `platform/self-sovereign-cutover/chart/Chart.yaml` is not edited; its history lines 295 to 320, which record the release that added the override, stay.
