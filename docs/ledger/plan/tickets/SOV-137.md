# SOV-137 — The registry pivot keeps the nodes' shared mirror first and starts with the outside blocked

## In plain words

**The problem today.** After the cutover a node may pull an image only from its region's registry. The cutover's registry step replaces the registry file of each name on every node, and the file it writes leaves out the entry through which the nodes of a region share the images they hold. When a node is drained, a moved Pod whose image its new node lacks waits on the registry, and when the registry's own front ran on the drained node nothing starts again. The step's own Pod also downloads its tools from the internet each time it starts, so on a rebooted node with the outside blocked it cannot start.

**What changes.** The registry step keeps the nodes' shared mirror as the first entry of every name it rewrites and the region's registry as the second. Its Pod runs an image that already holds its tools and installs nothing.

**Done means:**

- On a node whose k3s shares images between the nodes, every registry file the cutover writes asks the nodes of the region first, then the region's registry, and names no registry outside the Sovereign.
- The shared-mirror entry is the one k3s wrote, line for line, on the first sweep, on every later sweep and after a k3s restart rewrote the files.
- On a node without the shared mirror the cutover writes the same files as before.
- The step's Pod installs nothing when it starts and reaches its first call to the cluster with the outside blocked; a tool missing from its image still stops it with an error.
- The step's Pod runs the image the other cutover steps run, and the image setting that only it used is gone.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After the cutover every node still asks the nodes of its region for an image before it asks the region's registry. Cutover step 04 (the DaemonSet `registry-pivot` of `platform/self-sovereign-cutover/chart`) writes the containerd file `certs.d/<name>/hosts.toml` of every name it pivots with the k3s embedded-mirror block first, copied line for line from the file k3s wrote for that name, and the region's registry second, never an origin. Where k3s wrote no such block (k3s without `--embedded-registry`, which SOV-136 turns on at first boot) the file is byte for byte the file of today. The DaemonSet's Pod runs `images.kubectl` (alpine/k8s 1.31.4, the image steps 06, 10 and 11 run), which carries curl and jq, so its script installs nothing and the Pod starts on a rebooted node with the outside blocked. A drain that moves a Pod to a node without its image then takes the image from a node of the region that holds it, also while the registry's front is down.

## 3. The model (the law)
1. **What k3s writes.** With `--embedded-registry`, k3s v1.31.8+k3s1 adds the node's embedded mirror, `https://<loopback>:<supervisor port>/v2` with the cluster's CA and client certificate, as the FIRST endpoint of every mirror of `registries.yaml` (`pkg/spegel/registry.go`, `InjectMirror`; `pkg/agent/config/config.go` lines 796 to 816: the loopback `127.0.0.1`, or `::1` on a cluster without IPv4, and the supervisor port, 6443) and writes it as the first host table of the name's `hosts.toml` (`pkg/agent/templates/templates.go`, `HostsTomlTemplate`, rendered through `trimEmpty`). For the kit's paths the block is exactly these four lines:
   ```text
   [host."https://127.0.0.1:6443/v2"]
     capabilities = ["pull", "resolve"]
     ca = ["/var/lib/rancher/k3s/agent/server-ca.crt"]
     client = [["/var/lib/rancher/k3s/agent/client-k3s-controller.crt", "/var/lib/rancher/k3s/agent/client-k3s-controller.key"]]
   ```
2. **The new shell function `k3s_mirror_block <dir>`** in `pivot.sh` prints that block of the file k3s wrote for the name of `<dir>`: from `<dir>/hosts.toml` when it exists and is not the pivot's own (its first line is not the pivot's mark, `pivot_owns`); else from `<dir>/hosts.toml.pre-pivot` (the k3s file the pivot kept aside); else from `<certs.d>/_default/hosts.toml` when it is not the pivot's own (k3s's file of the name `*`, which containerd read for a name that has no file of its own). It prints, line for line, every non-empty line of the table whose header is `[host."https://127.0.0.1:<port>/v2"]` or `[host."https://[::1]:<port>/v2"]`, up to the next line that starts with `[`. When the chosen file has no such table it prints nothing; it never reads a further file.
3. **`write_offline_mirror_hosts`** puts that output into each file it writes, right after the mark line (after the `server` line in the file of the region's registry itself) and before the table of the region's registry. Every other line of each file stays as it is. No file of the pivot names an origin host. The log line of a pivoted name says `the nodes (k3s embedded mirror), then` before the registry address when the block is there.
4. **Unchanged:** the mark, `pivot_owns`, `put_hosts_toml` (k3s's file kept as `hosts.toml.pre-pivot`), the rollback and the dormant first run (`remove_offline_mirror_hosts`), the re-apply after a k3s restart (`offline_mirror_hosts_in_place`), the `/etc/hosts` pin, the dfdaemon flip and the per-node acks.
5. **The start of `pivot.sh`.** The `apk add --no-cache curl jq` retry loop is deleted. What stays of #5191 is the check: for `curl` and for `jq`, when `command -v` does not find it, the script prints `[registry-pivot] FATAL <tool> is not in the image; refusing to proceed tool-less (#5191)` and exits 1, so the Pod restarts instead of going on without its tools.
6. **The image.** The DaemonSet (the define `bp-self-sovereign-cutover.registryPivotDaemonSet`, used for the primary and for every follower region) runs `.Values.images.kubectl` (`harbor.openova.io/proxy-dockerhub/alpine/k8s:1.31.4`). The values key `images.hostExec` (`library/alpine:3.20`), which nothing else reads, is deleted.
7. **The chart's size does not rise.** The templates of the chart keep 20,770 lines, the baseline of `chart_lines` in `scripts/lifecycle-ratchets-baseline.txt`; the deleted loop pays for the new function.
8. **The render comparison of `tests/step6490-secondary-gitea-mirror.sh`** leaves the step-04 document out of both renders while `origin/main` lacks `k3s_mirror_block() {` (its axis 20 is widened, as SOV-132 did for `pivot_owns`); the axis switches itself off once `main` holds the change.
9. **Must be deleted:** the `apk` loop and its `FATAL toolchain unavailable after 6 attempts` message; the values key `images.hostExec` with its comment.
