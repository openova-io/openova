# SEC-127 — The k3s bootstrap-flags test pins its checkout action by commit hash and its k3s image by digest

## In plain words

**The problem today.** The test that proves the k3s bootstrap flags on a CI runner checks out the repository with an action named by a tag, and starts k3s from an image named by a tag. A tag can be moved to other content, so the test could run other code than the code that was reviewed. The guard that counts such references lets the count only fall, and this test is one of the references it still counts.

**What changes.** The workflow names the checkout action by the commit of its release v4.4.0, and the script names the k3s image by its tag and the digest of its content. The stored count of action references that are not pinned by a commit is lowered by one.

**Done means:**

- The workflow of the k3s bootstrap-flags test has one action step, and it names a 40-character commit with the release as a comment.
- The script starts k3s from the image of release v1.31.8-k3s1 fixed by its digest, unless the run sets another image.
- The pin guard no longer counts the workflow of this test, and its stored count of unpinned action references is one lower than before.
- The k3s bootstrap-flags test runs on the pull request with the pinned image and finishes green.
- The self-test of the script still passes all of its cases.

The rest of this ticket is the exact instruction for the model that does the work.
