# CTL-331 — The shared events package is Kafka-free

## In plain words

**The problem today.** The shared events package of the Organization services still carries a Kafka client: a producer, a consumer, a dead-letter subscriber and a list of topic names. The services no longer build that client, so none of this code is called, yet the package still pulls in the Kafka library. The package also keeps a deprecated function that would create a second usage stream, and the stream guard has to tolerate it.

**What changes.** The package holds NATS code only. The publisher is built from the NATS connection alone, the subscriber has no second leg, the three Kafka-only files and the deprecated usage-stream code are gone, and the stream guard records no stream-creating call for the package.

**Done means:**

- No file of the shared services module names Kafka, Redpanda or the Kafka client library, in code, in a comment or in the dependency list.
- The dead-letter subscriber, its test and the topic list no longer exist, and their three paths are on the list of deleted paths.
- The publisher is built from the NATS connection alone and refuses to be built without one. The publish call keeps its three arguments, so no handler and no test fake changes.
- The billing, domain, provisioning and tenant services compile against the new publisher, and every module that uses the shared package passes its vet run.
- The stream guard passes with no stream-creating call recorded for the shared package.

The rest of this ticket is the exact instruction for the model that does the work.
