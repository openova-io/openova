# AIP-104 — Limits, queue, time-outs, admin listener

## In plain words

**The problem today.** Axon starts a model run for every request it receives, with no upper bound, and keeps every conversation that waits for tool results until it expires. A burst of requests can start more runs than the pod can hold, a step that never ends holds its run forever, and nobody can read how busy Axon is. Its health routes share the model port, so whoever may call the model can also probe it, and a shutdown has no time limit.

**What changes.** Axon admits a fixed number of runs, queues a bounded number of requests and refuses the rest with 429, ends a step that takes too long with 504, and reports its load on a separate admin port that also carries the health routes. A shutdown closes every run and ends within 10 seconds.

**Done means:**

- With four steps running, a fifth request waits and starts as soon as one of them ends.
- When sixteen requests already wait, the next one gets 429 with Retry-After 5 at once, and a request that waits longer than the queue limit gets the same answer.
- A model step that runs longer than the step time-out is answered 504 and its run is closed.
- When a ninth conversation waits for tool results, the oldest waiting one is closed.
- The health routes and /stats answer on the admin port only, and the model port serves only the model routes; /stats reports the active, parked and queued runs and the counters.
- On SIGTERM Axon stops accepting, ends every open request with an error, closes every run and exits, within 10 seconds even when a run does not close.
- Axon's earlier unit tests pass unchanged.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
`products/axon` enforces its capacity. A new chain needs one of `AXON_MAX_ACTIVE` (default 4) active slots; while none is free the request waits in a queue of at most `AXON_QUEUE_MAX` (16) entries for at most `AXON_QUEUE_WAIT_MS` (30000), and a full queue or a wait that runs out answers 429 `rate_limit_exceeded` with `Retry-After: 5`. When more than `AXON_MAX_PARKED` (8) chains wait for tool results, the oldest is closed. A single model step longer than `AXON_STEP_TIMEOUT_MS` (1800000) answers 504 `backend_timeout` and closes its run. A second listener on `AXON_ADMIN_PORT` (3001) serves `/healthz`, `/health` and `/stats`; the model listener on `AXON_PORT` serves only `/v1/chat/completions` and `/v1/models`. On SIGTERM Axon stops accepting, closes every chain and exits within 10 seconds. `cd products/axon && npm ci && npm run build && npm test` passes 66 tests, ten of them in the new `test/limits.test.ts`.

## 3. The model (the law)
1. `src/config.ts` reads `AXON_PORT` (3000), `AXON_ADMIN_PORT` (3001), `AXON_MODEL_MAP`, `AXON_MAX_ACTIVE` (4), `AXON_MAX_PARKED` (8), `AXON_QUEUE_MAX` (16), `AXON_QUEUE_WAIT_MS` (30000), `AXON_PARK_TTL_MS` (600000) and `AXON_STEP_TIMEOUT_MS` (1800000). Each number is a positive whole number, and the admin port differs from the model port; otherwise the start stops with an error that names the variable. The defaults are the exported constant `DEFAULTS` and are not raised.
2. An active slot is held by a chain in state `active`. A new chain takes a slot at once when one is free and nobody waits; otherwise the request waits in the queue, first in first out. The queue's seventeenth entry is refused at once. A refusal or a wait that runs out answers 429 `rate_limit_exceeded` with `Retry-After: 5` (contract error body). A slot is freed when its chain parks or closes, and the first queued request takes it.
3. A follow-up that resumes a parked chain does not queue: its chain already holds its run. It counts as active. So the number of runs alive is at most `AXON_MAX_ACTIVE + AXON_MAX_PARKED`.
4. A caller that goes away while queued leaves the queue (the step throws `Disconnected`, as in AIP-103).
5. When a chain parks and more than `AXON_MAX_PARKED` chains are parked, the chain that parked first is closed. A later follow-up for it starts a new run with the transcript, as after expiry.
6. Each step has one deadline of `AXON_STEP_TIMEOUT_MS`, from the start of reading upstream events to the step's answer, including the wait for the run's result after the last model message. When it passes, the chain is closed and the step answers 504 `backend_timeout`. The deadline is an `AbortSignal.timeout`; it delays nothing, so the AIP-103 test "no timer is used by the stream path" stays unchanged and passes.
7. `TurnManager` gains `counters()`: `requests` (every step call), `resumed` (steps that resumed a parked chain), `replayed` (new chains whose prompt is a transcript), `rejected429` (429s of the queue) and `upstreamErrors` (steps ended by a run error of rule 8 of the turn chain, or by the deadline). `stats()` keeps its shape `{active, parked, queued}` and now reports the queue.
8. `src/index.ts` exports `servers(config, turns)`, which builds two Fastify instances: `model` with `/v1/models` and `/v1/chat/completions` only, and `admin` with `/healthz` (200 `{"status":"alive"}` always), `/health` (503 `{"status":"starting"}` until both listeners are up, then 200 `{"status":"ok"}`) and `/stats` (200, no authentication: `{"credential":{"state":"absent"},"turns":{"active","parked","queued","maxActive","maxParked"},"counters":{"requests","resumed","replayed","rejected429","upstreamErrors"}}`). The credential object stays `{"state":"absent"}` until AIP-105.
9. `src/index.ts` exports `stop(servers, turns, exit, graceMs = SHUTDOWN_GRACE_MS)`, with `SHUTDOWN_GRACE_MS = 10000`. It closes both listeners, calls `turns.shutdown()` and exits 0; if that has not finished after `graceMs`, it exits 1. `Turns.shutdown()` refuses new steps and answers every queued request with 502 `backend_error`, closes every chain (an active step then answers 502 `backend_error`, not counted as an upstream error) and waits for each run's interrupt. SIGTERM and SIGINT call `stop` once.
10. `main()` runs only when `index.ts` is the entry point (`node dist/index.js`); importing the module starts nothing.
11. `products/axon/package.json` declares `@modelcontextprotocol/sdk` at `1.30.0`, the release the lock already installs, because `src/upstream.ts` imports it.
