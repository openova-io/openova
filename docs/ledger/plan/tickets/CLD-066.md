# CLD-066 — provider-opentofu v1.1.11 by digest

## In plain words

**The problem today.** Every Sovereign installs the OpenTofu provider of Crossplane at release v1.1.3, named by a tag. A tag can be moved on the registry, so the same file can install different code over time. The later Workspace work needs release v1.1.11.

**What changes.** The provider package is named by the content digest of release v1.1.11, from the same registry as before. The guard that checks the provider package accepts the digest form.

**Done means:**

- Every Sovereign installs the OpenTofu provider at release v1.1.11, named by its content digest.
- The package comes from the same registry as before, and its digest is the one the package mirror copies.
- Nothing else in the provider file changes.
- The provider guard accepts the digest form and still fails when the package is not the OpenTofu provider.
- The change rides a release candidate of its own, after the candidate that carries the Crossplane core 2.4.3 has passed the gate check of the Crossplane upgrade.
- The gate check of the Crossplane upgrade passes on the first candidate that carries the change.

The rest of this ticket is the exact instruction for the model that does the work.
