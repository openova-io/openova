# PRD-508 — Account-information read operations and the ledger client

## In plain words

**The problem today.** The open-banking product can create, read and delete an account-access consent, but a third party holding an authorised consent cannot read anything with it. The 26 operations that read accounts, balances, transactions, standing orders and the other account data all answer not found, and the product has no client that calls the core-banking adapter.

**What changes.** The product gains a client of the core-banking adapter and implements the 26 read operations behind the token check. Each answer shows only what the customer consented to, and the resources the bank does not offer answer not found as the standard asks.

**Done means:**

- A third party with an authorised consent reads the consented accounts, their balances and their transactions, and every answer validates against the publisher's document.
- A consent without a detail permission sees the basic form of an account, a beneficiary or a transaction, and a consent with it sees the account identifications and the transaction details.
- A resource the core-banking adapter does not offer, and every offer, product and statement operation, answers status 404 after the token check.
- A long list is read page by page, and following the next-page link returns every item once.
- The conformance test prints the counter 29/63, and the product guard holds the list of operations not yet implemented at 34 lines.
- Every test of the product passes on the pull request, and the linter and the security scan find nothing new.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The resource server of the open-banking product, `products/fingate/internal/api`, serves the 26 account-information operations that a customer consents to, in addition to the three account-access consent operations of `PRD-501`. Each one runs behind the full token check of the route, reads the consent the token carries from the consent store, and reads core banking only through a new client of the ledger port, `products/fingate/internal/ledgerclient`. Accounts, balances, transactions, beneficiaries, standing orders, direct debits, scheduled payments and parties come from the ledger. The offer, product and statement operations, which the port does not carry, answer 404 after the token check. The 26 lines leave `products/fingate/internal/api/unimplemented.txt`; the test `TestDocumentConformance` prints `C1: 29/63`, and the product guard's G-P7 baseline falls from 60 to 34. A new test, `TestReadOperationsConformToTheDocument`, validates every request and every answer of the 26 operations against the publisher's document.

## 3. The model (the law)
1. **Core banking is reached only through the ledger port.** `ledgerclient.Client` wraps a gRPC connection to an adapter of `products/fingate/api/ledger/v1`. Every call has a deadline (`DefaultTimeout`, 5 seconds, when none is given). Every error of the port maps to exactly one error kind: `NOT_FOUND` to `ErrNotFound`, `PERMISSION_DENIED` to `ErrNotOwned`, `FAILED_PRECONDITION` to `ErrRefused`, `UNIMPLEMENTED` to `ErrNotOffered`, `ALREADY_EXISTS` to `ErrConflict`, `INVALID_ARGUMENT` to `ErrBadRequest`, every other code to `ErrUnavailable`. `ledgerclient.Dial` opens the connection over TLS only, at least TLS 1.2, with the server name it is given; it refuses a missing TLS configuration and never changes the configuration it receives.
2. **The server needs the ledger.** `api.Config` gains the field `Ledger *ledgerclient.Client`, and `api.New` refuses a configuration without it, with the message `api: the configuration needs Profile, Documents, Definitions, Checker, Store and Ledger`.
3. **The token check comes first.** Every one of the 26 operations is a customer operation of the consent family `account-access`. The route check of `router.go` already applies rules T1 to T10. For rule T9 it asks the method `permissions` of the account-information implementation, which this ticket adds: the consent must grant one of the listed permissions (table of rule 4), the account of the path must be in the consent, and the consent must be authorised and not expired. Only then does the operation run. The operation reads the consent again from the store for its customer, its accounts, its permissions and its transaction window.
4. **The permissions of each operation**, from the standard's account and transaction profile. A Detail code grants its Basic code too.

   | Operations (paths after `/open-banking/v4.0/aisp`) | Permissions, one of |
   |---|---|
   | `/accounts`, `/accounts/{AccountId}` | `ReadAccountsBasic`, `ReadAccountsDetail` |
   | `/balances`, `/accounts/{AccountId}/balances` | `ReadBalances` |
   | `/transactions`, `/accounts/{AccountId}/transactions`, `/accounts/{AccountId}/statements/{StatementId}/transactions` | `ReadTransactionsBasic`, `ReadTransactionsDetail` |
   | `/beneficiaries`, `/accounts/{AccountId}/beneficiaries` | `ReadBeneficiariesBasic`, `ReadBeneficiariesDetail` |
   | `/standing-orders`, `/accounts/{AccountId}/standing-orders` | `ReadStandingOrdersBasic`, `ReadStandingOrdersDetail` |
   | `/direct-debits`, `/accounts/{AccountId}/direct-debits` | `ReadDirectDebits` |
   | `/scheduled-payments`, `/accounts/{AccountId}/scheduled-payments` | `ReadScheduledPaymentsBasic`, `ReadScheduledPaymentsDetail` |

5. **What a consent shows.** Only the accounts of the consent are read; an operation without an account in its path reads every account of the consent, in the consent's order. A Detail permission adds the fields the standard reserves for it: the account identification of an account (`Account`), the creditor's account of a beneficiary, a standing order and a scheduled payment (`CreditorAccount`), and the transaction information and the counterparty of a transaction (`TransactionInformation`; `CreditorAccount` of a debit, `DebtorAccount` of a credit). Without `ReadPAN`, an identification under the scheme `UK.OBIE.PAN` shows its last four characters, the others replaced by `*`. `ReadTransactionsCredits` shows the credits and `ReadTransactionsDebits` the debits; a consent with neither sees no transaction. A transaction is shown only when it was booked inside the consent's window (`TransactionFromDateTime`, `TransactionToDateTime`) and inside the call's window (`fromBookingDateTime`, `toBookingDateTime`).
6. **The values of the ledger are written as they are.** The adapter writes the documents' codes; the sandbox ledger of `products/fingate/internal/sandbox` does, and the tests read it. An empty value is left out. A text longer than the document allows is cut to its limit. A telephone number without the document's form `+<country code>-<number>` is left out. The port's balance after a transaction and the mandate identifier of a direct debit are not shown: the documents hold them only in objects that need values the port does not carry.
7. **Errors of the ledger.** `ErrNotOffered` (a resource absent from the ledger's capabilities) answers 404 with no body on every operation whose document declares 404, which is every operation of this ticket except `/accounts`, `/accounts/{AccountId}`, `/accounts/{AccountId}/balances` and `/accounts/{AccountId}/transactions`; on those four it answers 500. `ErrNotFound` and `ErrNotOwned` answer 400 with the message `account "<id>" is not held for the customer at the ledger`, or, for an operation without an account in its path, `the customer of the consent is not known at the ledger`. `ErrBadRequest` answers 400 `the page is not one this server issued`. Every other error answers 500 with the message `the answer could not be written`. An operation answers an error by returning an `*answer` with its status, and `internalError` in `router.go` writes it: 404 with no body, any other status with the documents' error body.
8. **Pages.** A list answers one page of the ledger. `Links.Self` is the address of the call. When there is a next page, `Links.Next` is the same address with the query parameter `page` set: for an operation of one account, the ledger's page token; for an operation over every account of the consent, `<index of the account in the consent>.<ledger page token>`. A `page` value this server did not issue answers 400. The account and balance operations are not paged.
9. **Not offered by the bank.** The port carries no offer, product or statement. The nine operations of rule 4 for offers, products and statements answer 404 after the token check of the route.
10. **The list only shrinks.** The 26 lines that start with `account-info ` leave `unimplemented.txt`; 34 lines stay. G-P7 of `scripts/check-products.py` is lowered to 34 by the guard's own tool, `--write-baseline`. The counter of test C1 is 29/63.
11. Nothing is deleted.

// Package ledgerclient is the resource server's client of the ledger port
// (products/fingate/api/ledger/v1).
//
// Core banking is reached only through the port. Dial opens the connection to the adapter over
// TLS; New wraps a connection. Every call carries a deadline, and every error of the port is
// mapped to one of the errors below, so that a caller decides on the kind of failure and never
// on a gRPC code:
//
//	NOT_FOUND            ErrNotFound      unknown customer, account or payment
//	PERMISSION_DENIED    ErrNotOwned      the account is not the customer's
//	FAILED_PRECONDITION  ErrRefused       the ledger refuses the payment
//	UNIMPLEMENTED        ErrNotOffered    a resource or payment type absent from the capabilities
//	ALREADY_EXISTS       ErrConflict      an idempotency key reused with different content
//	INVALID_ARGUMENT     ErrBadRequest    a page token the ledger did not issue, a bad value
//	anything else        ErrUnavailable   the ledger could not answer; retry is safe
//
// The error's text is the operation and the ledger's message, for the log; it is never written
// to a third party.
package ledgerclient

import (
	"context"
	"crypto/tls"
	"errors"
	"fmt"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"
	"google.golang.org/grpc/credentials"
	"google.golang.org/grpc/status"

	ledgerv1 "github.com/openova-io/openova/products/fingate/api/ledger/v1"
)

// DefaultTimeout bounds a call when New is given no timeout.
const DefaultTimeout = 5 * time.Second

// The kinds of failure. Every error a Client returns wraps exactly one of them.
var (
	ErrNotFound    = errors.New("not found")
	ErrNotOwned    = errors.New("not the customer's")
	ErrRefused     = errors.New("refused")
	ErrNotOffered  = errors.New("not offered")
	ErrConflict    = errors.New("conflict")
	ErrBadRequest  = errors.New("bad request")
	ErrUnavailable = errors.New("unavailable")
)

// Client calls the ledger port. It is safe for concurrent use.
type Client struct {
	c       ledgerv1.LedgerClient
	timeout time.Duration
}

// New returns a Client over cc. A timeout of zero or less is DefaultTimeout.
func New(cc grpc.ClientConnInterface, timeout time.Duration) *Client {
	if timeout <= 0 {
		timeout = DefaultTimeout
	}
	return &Client{c: ledgerv1.NewLedgerClient(cc), timeout: timeout}
}

// Dial opens a connection to the adapter at target (the form dns:///<host>:<port> of the
// definitions' ledger.target) over TLS. tc holds the roots that verify the adapter's
// certificate; serverName, when not empty, is the name that certificate must carry. tc is not
// changed. The connection is made on the first call.
func Dial(target, serverName string, tc *tls.Config) (*grpc.ClientConn, error) {
	if tc == nil {
		return nil, errors.New("ledgerclient: a TLS configuration is required")
	}
	c := tc.Clone()
	if c.MinVersion < tls.VersionTLS12 {
		c.MinVersion = tls.VersionTLS12
	}
	if serverName != "" {
		c.ServerName = serverName
	}
	cc, err := grpc.NewClient(target, grpc.WithTransportCredentials(credentials.NewTLS(c)))
	if err != nil {
		return nil, fmt.Errorf("ledgerclient: %w", err)
	}
	return cc, nil
}

// kinds maps the port's codes to the errors above.
var kinds = map[codes.Code]error{
	codes.NotFound:           ErrNotFound,
	codes.PermissionDenied:   ErrNotOwned,
	codes.FailedPrecondition: ErrRefused,
	codes.Unimplemented:      ErrNotOffered,
	codes.AlreadyExists:      ErrConflict,
	codes.InvalidArgument:    ErrBadRequest,
}

// mapErr returns nil for nil, otherwise an error that wraps the kind of failure.
func mapErr(op string, err error) error {
	if err == nil {
		return nil
	}
	st, _ := status.FromError(err)
	kind, ok := kinds[st.Code()]
	if !ok {
		kind = ErrUnavailable
	}
	return fmt.Errorf("ledger %s: %w: %s", op, kind, st.Message())
}

// call runs f with the deadline of one call and maps its error.
func call[T any](ctx context.Context, c *Client, op string, f func(context.Context) (T, error)) (T, error) {
	ctx, cancel := context.WithTimeout(ctx, c.timeout)
	defer cancel()
	out, err := f(ctx)
	if err != nil {
		var zero T
		return zero, mapErr(op, err)
	}
	return out, nil
}

// Capabilities returns what the ledger offers.
func (c *Client) Capabilities(ctx context.Context) (*ledgerv1.Capabilities, error) {
	return call(ctx, c, "GetCapabilities", func(ctx context.Context) (*ledgerv1.Capabilities, error) {
		return c.c.GetCapabilities(ctx, &ledgerv1.GetCapabilitiesRequest{})
	})
}

// ResolveCustomer maps an identity of the authorisation server to a customer.
func (c *Client) ResolveCustomer(ctx context.Context, scheme, subject string, attributes map[string]string) (*ledgerv1.Customer, error) {
	return call(ctx, c, "ResolveCustomer", func(ctx context.Context) (*ledgerv1.Customer, error) {
		return c.c.ResolveCustomer(ctx, &ledgerv1.ResolveCustomerRequest{Scheme: scheme, Subject: subject, Attributes: attributes})
	})
}

// Accounts lists the customer's accounts.

		r, err := c.c.ListAccounts(ctx, &ledgerv1.ListAccountsRequest{CustomerId: customer})

}

// Account returns one of the customer's accounts.

// Page is one page of a list and the token of the next page; "" means it is the last page.
type Page[T any] struct {
	Items []T
	Next  string
}

// Transactions returns one page of an account's transactions booked from from to to (RFC 3339;
// "" leaves the bound open). page is "" for the first page, otherwise a Next of an earlier page.

// the consent in turn. In that case the page parameter is "<index of the account>.<ledger token>".
// It returns the items and the page parameter of the next page.
func readList[T any](ctx context.Context, g grant, account string, read func(ctx context.Context, customer, account, page string) (ledgerclient.Page[T], error)) ([]listed[T], string, error) {
	page := pageParam(ctx)
	if account != "" {
		p, err := read(ctx, g.customer, account, page)
		if err != nil {
			return nil, "", ledgerAnswer(err, account, true)
		}
		out := make([]listed[T], 0, len(p.Items))
		for _, x := range p.Items {
			out = append(out, listed[T]{account, x})
		}
		return out, p.Next, nil
	}
	i, token := 0, ""
	if page != "" {
		idx, tok, ok := strings.Cut(page, ".")
		n, err := strconv.Atoi(idx)
		if !ok || err != nil || n < 0 || n >= len(g.accounts) || strconv.Itoa(n) != idx {
			return nil, "", badRequest("the page is not one this server issued")
		}
		i, token = n, tok
	}
	if len(g.accounts) == 0 {
		return nil, "", nil
	}
	for {
		acc := g.accounts[i]
		p, err := read(ctx, g.customer, acc, token)
		if err != nil {
			return nil, "", ledgerAnswer(err, acc, true)
		}
		out := make([]listed[T], 0, len(p.Items))
		for _, x := range p.Items {
			out = append(out, listed[T]{acc, x})
		}
		switch {
		case p.Next != "":
			return out, strconv.Itoa(i) + "." + p.Next, nil
		case i+1 == len(g.accounts):
			return out, "", nil
		case len(out) > 0:
			return out, strconv.Itoa(i+1) + ".", nil
		}
		i, token = i+1, "" // an account without items: read the next one in the same answer
	}
}

// window returns the later of two lower bounds and the earlier of two upper bounds, RFC 3339;
// "" is an open bound. ok is false when the window is empty.
func window(consentFrom, consentTo string, from, to *time.Time) (string, string, bool) {
	lo, hi := consentFrom, consentTo
	if from != nil {
		if f := from.UTC().Format(timeLayout); lo == "" || later(f, lo) {
			lo = f
		}
	}
	if to != nil {
		if t := to.UTC().Format(timeLayout); hi == "" || later(hi, t) {
			hi = t
		}
	}
	return lo, hi, lo == "" || hi == "" || !later(lo, hi)
}

// later says whether the time a is after the time b; both are RFC 3339.
func later(a, b string) bool {
	ta, errA := time.Parse(time.RFC3339, a)
	tb, errB := time.Parse(time.RFC3339, b)
	return errA == nil && errB == nil && ta.After(tb)
}
