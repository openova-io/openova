# CTL-346 — Kit slots 56 and 57 (flow server and emitter) leave the kit

## In plain words

**The problem today.** Every Sovereign still installs a flow server with a database of its own and a flow emitter on every node, as two slots of the bootstrap kit. The flow canvas of the console is answered by the platform API from its own jobs store, so nothing reads what these two services hold. They still cost a database, a Pod on every node and two releases that every installation, every upgrade and every cutover has to carry.

**What changes.** The two slots leave the bootstrap kit. A new Sovereign never installs the flow server or the flow emitter, and an existing Sovereign removes both when it takes the change. Every list that names the two slots is brought in line: the kit list, the placement table, the dependency list, the cutover lists and the generated inventories.

**Done means:**

- The bootstrap kit holds no slot for the flow server or the flow emitter, and the kit list, the placement table and the dependency list name neither.
- A Sovereign installed from this state has no flow server and no flow emitter, and an existing Sovereign removes both releases when its Flux reconciles the kit.
- The cutover no longer repoints, mirrors or pivots the two releases.
- The generated slot list, the generated component list and the generated catalogue are current and show no kit slot for the two.
- The service-model baseline counts two slots fewer without a ring label.
- The two slot files are on the deletion list, so a change that brings one back turns its pull request red.

The rest of this ticket is the exact instruction for the model that does the work.
