# SVC-130 — Enable function tests on the foundation slots

## In plain words

**The problem today.** Most charts of the foundation ring now ship a function test, but no slot of the kit asks Flux to run it. So no release ever records whether its chart works, and the gate has nothing to read. Nothing in the repository says which foundation charts still have no test, so a new chart without one would enter unnoticed.

**What changes.** Each foundation slot asks Flux to run the chart's test after every install and upgrade, and a failed test never changes whether the release counts as ready. The service-model guard names the foundation charts that have no test yet and refuses any change that adds a name to that list.

**Done means:**

- Every foundation slot of the kit asks Flux to run its chart's test, with failures ignored, and no other slot does.
- Apart from that request, every foundation slot renders exactly as before.
- The service-model guard names the six foundation charts that have no function test yet, and it fails when a foundation chart without a test is not on that list.
- The guard also fails when a listed chart gains a test or leaves the ring and the list still names it.
- Rewriting the guard's record from the tree reproduces the record of this change exactly.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After the merge, every HelmRelease of a foundation slot of `clusters/_template/bootstrap-kit` carries `spec.test.enable: true` and `spec.test.ignoreFailures: true`, so helm-controller runs the chart's `helm.sh/hook: test` Pod after every install and upgrade and records the hook phases in the release status, where gate check SVC-G06 (package SVC-125) reads them. A failed test does not change `Ready` and starts no remediation. The service-model guard `scripts/check-service-model.py` keeps a named list in `scripts/service-model-baseline.yaml`: the foundation charts whose chart folder has no function test. The list must equal the tree and may only lose names, so a foundation chart cannot join the kit without a test, and a chart that gains a test leaves the list in the same change.

3. `ignoreFailures` is `true` and never `false`.
4. The baseline of the service-model guard gains a top-level `lists:` mapping with exactly one key, `G6.foundation-without-function-test`: the sorted chart names (`spec.chart.spec.chart`) of the HelmReleases of the foundation slot files whose chart folder (the `platform/<x>/chart` or `products/<x>/chart` whose `Chart.yaml` has that `name`) has no `chart/templates/tests/function-test.yaml` with a test Pod. The test-Pod rule is the one that counts `G6.function-test-charts`.
5. The guard fails when the list in the baseline differs from the tree: a name that is in the tree and not in the list may never be added ("the list may only lose names"); a name in the list that is no longer in the tree must be removed in the same change. `--write-baseline` writes the list from the tree and refuses a name that would join. `--print` and the judging run print one line `G6.foundation-without-function-test=<names joined by commas>` after the count lines. A baseline without the list cannot be judged (exit 2).
6. No count of the baseline changes. No gate check moves.
