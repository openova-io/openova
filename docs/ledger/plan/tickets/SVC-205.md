# SVC-205 — Lock stage blueprints to deny

## In plain words

**The problem today.** Every Blueprint on a Sovereign comes from Git and is written by Flux, and the gate records show that nothing else has written one. Yet the admission lock on Blueprints only warns, and the API's own account may still update and patch them. A hand edit or a stray program can therefore change a Blueprint on the cluster, and Git no longer says what runs.

**What changes.** The lock on Blueprints rejects every write that does not come from Flux, and the API's account loses its write verbs on Blueprints. The record of lock stages says deny for Blueprints, so the switch cannot be undone quietly.

**Done means:**

- The platform chart renders the binding of stage blueprints with the action Deny alone; every other stage keeps its action.
- The baseline of lock stages says deny for blueprints, and the guard that keeps a stage from moving back passes.
- No role of the platform chart grants create, update, patch or delete on Blueprints; the read rules stay.
- The chart test of the lock passes, and checks each binding against the action the chart values give its stage.
- The lock on a real API server, run by its own workflow, accepts the policy and the nine bindings with this default.

The rest of this ticket is the exact instruction for the model that does the work.
