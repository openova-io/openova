# SOV-344 — The sovereignty proof counts the cloud Workspaces, and the tether list names the OpenTofu providers

## In plain words

**The problem today.** The sovereignty proof holds the Sovereign without the outside for ten minutes and counts only Helm releases, Flux kustomizations and the front door. The cloud Workspaces that hold the Sovereign's own cloud resources are none of these: on a fresh install most of them could not reach the public provider registry inside the hold and the proof still passed. The documents list eight tethers and not this one.

**What changes.** Before the hold the proof checks that the OpenTofu configuration names only the Sovereign's registry, and during the hold a cloud Workspace that was healthy before it and is not in it fails the proof, in every region. The tether lists name the OpenTofu providers as the ninth tether.

**Done means:**

- A cloud Workspace that is Ready and Synced before the hold and loses either condition in it fails the proof, and the log names its kind, namespace and name.
- A Workspace that was already unhealthy before the hold is named in the log and does not fail the proof.
- A secondary region's Workspace that loses a condition in the hold fails that region's verdict.
- A list of Workspaces that cannot be read fails the proof; a region that does not serve the kind passes.
- An OpenTofu CLI configuration, live or in the provider pod, that names a direct installation or a mirror outside the Sovereign fails the proof before the hold.
- The tether lists of the design documents, the decision record and the chart name the OpenTofu provider binaries from registry.opentofu.org, and none counts eight tethers.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. The Workspaces are those of `workspaces.opentofu.upbound.io` and, where the region serves it, `workspaces.opentofu.m.upbound.io`. `ws_read REGION KUBECONFIG` (block `workspace-hold` of step 08's script) lists both kinds of the region into `/work/ws_now`, one row `<kind>/<namespace>/<name> Ready=<status> Synced=<status>` (the namespace is empty for the cluster-scoped kind). A kind the region does not serve (`the server doesn't have a resource type`, `could not find the requested resource`, `no matches for kind`) has no rows; a list that cannot be read for another reason makes `ws_read` return 1, which fails the proof and never passes it.
2. The baseline. `ws_baseline REGION KUBECONFIG` keeps in `/work/ws_base_<region>.txt` the Workspaces that are `Ready=True Synced=True`, names every other one as `baseline[<region>] WS (not Ready and Synced before the hold, excluded) <row>`, and prints how many it keeps. It runs in every region (the primary as `primary`, each secondary by the base name of its kubeconfig under `/secondary-kubeconfigs`) in the block `tofu-pre-hold`, after the front-door check and before the hold is applied: the baseline is the state before the hold. A failed read there ends the step with exit 1 before the hold.
3. The window. In each poll, after the HelmRelease and Kustomization diff of the primary, `ws_regressed primary ""` prints `  NEW[<region>] WS <kind>/<namespace>/<name> <state>` for each kept Workspace that is not `Ready=True Synced=True` (or `absent`) and returns 1, as it does when the list cannot be read; that is one more regression cycle (`new_failures`). In the loop over the secondaries the same for each region, which is also written to `/work/secondary_failed_regions.txt`, so that region's verdict on the status ConfigMap is `failed`. No other line of the window changes.
4. The CLI configuration lint. `run_tofu_cli_config_host_lint REGION KUBECONFIG` (block `tofu-cli-lint`) reads the key `.tofurc` of the ConfigMap `TOFU_NAMESPACE/TOFU_CLI_CM` (`crossplane-system/opentofu-cli-config`) and, in every running pod of `TOFU_NAMESPACE` that mounts it, `<mountPath>/.tofurc` with `kubectl exec ... cat` (the pod selection is step 11's). Each is judged by `tofu_cli_judge`: lines starting with `#` or `//` are not read; a block `direct`, `network_mirror`, `filesystem_mirror` or `dev_overrides` is an offender `method=<name>`; the host (the text before the first `/`) of every `repository_template` must be `LOCAL_REGISTRY_HOST` (the host of `sovereign.harborPublicURL`, the host step 11 writes), `registry.<SOVEREIGN_FQDN>` or `harbor.<SOVEREIGN_FQDN>`, else an offender `oci_mirror=<template>`; no `repository_template` at all is an offender. Each offending file is one line `    EXTERNAL-TOFU-SOURCE [<region>] <configmap=...|pod=...>:<offenders>`. A ConfigMap that cannot be read, no running pod that mounts it, or an absent ConfigMap in a region that serves a Workspace kind fails (without it `tofu init` takes the implied configuration, which installs from `registry.opentofu.org`); an absent ConfigMap in a region that serves no Workspace kind passes. It runs for every region in the block `tofu-pre-hold`, before the baseline; any failure ends the step before the hold.
