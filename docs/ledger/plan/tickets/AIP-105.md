# AIP-105 — One owner of the credential

## In plain words

**The problem today.** Axon refreshes the subscription credential from a file in its home folder, and every model run it starts reads the same file and may refresh the same login on its own. A refreshed document is written to that folder only, so it is lost with the pod and nobody else learns of it. Nobody can see whether the credential is valid, and a missing credential surfaces as an error from deep inside a run.

**What changes.** One module in the Axon parent owns the credential: it reads the mounted document once, refreshes it on one timer, stores each new document in OpenBao with check-and-set, and hands each run only the short-lived access token with a home folder that holds no credential. Its state is shown on /stats, and every request answers 503 while the credential is not valid.

**Done means:**

- Axon refreshes the credential once, a fixed margin before it expires, and never runs two refreshes at the same time.
- A refreshed document is written to OpenBao with check-and-set before Axon uses the new access token; when another writer has changed it, Axon stops refreshing and answers 503.
- A refresh token refused by the provider stops refreshing and every request answers 503; a refresh that fails for another reason is retried after 60, 120 and 240 seconds and then every 600 seconds.
- Without a credential document every chat request answers 503 simulation_credential_invalid, and /stats reports the state absent.
- Each model run receives the access token in its environment and a home folder with no credential file; the refresh token never reaches it.
- No log line written by the credential owner contains a token, and the old refresh module is gone.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. `src/config.ts` reads `AXON_CREDENTIAL_FILE` (`/var/run/secrets/openova/model-credential`), `AXON_CREDENTIAL_KV_PATH` (`mounted/data/axon/sa/axon/model-credential/e1`), `AXON_CREDENTIAL_ROLE` (`axon-credential`), `OPENBAO_ADDR` (`http://openbao.openbao.svc.cluster.local:8200`, a trailing `/` removed) and `AXON_REFRESH_MARGIN_MS` (600000) into `Config.credential`. The margin is a positive whole number and the KV path has the form `<mount>/data/<path>`; otherwise the start stops with an error that names the variable.
2. The document is the provider tool's credential file, unchanged: one object under the key `claudeAiOauth` with `accessToken`, `refreshToken` (non-empty strings) and `expiresAt` (integer, milliseconds), and optional further fields that are kept. `load()` reads it once. No file, an empty file, or a text that is not such a document: state `absent`.
3. States: `absent`; `valid`; `expired` (the clock is past `expiresAt`, the refresh not yet done); `rejected` (the provider refused the refresh token); `conflict` (the write-back lost check-and-set). `rejected` and `conflict` stop refreshing for the life of the process.
4. `accessToken()` returns the access token in use when the state is `valid` and otherwise throws `HttpError` 503 `simulation_credential_invalid`. `guarded(turns, credential)` makes every step call it first, so every chat request, streamed or not, answers that 503 while the state is not `valid`. The turn manager's existing `accessToken` option gives each new run the token in use when it starts.
5. One timer only. `start()` reads the KV version once (`GET /v1/<mount>/metadata/<path>`, `data.current_version`; 404 means 0) and arms the timer at `expiresAt - AXON_REFRESH_MARGIN_MS`. No timer is armed while a refresh or write-back is in flight; a second `start()` does nothing.
6. A refresh is `POST` to the token endpoint with `grant_type`, `refresh_token` and `client_id`, the endpoint and client identifier unchanged and present in `src/credential.ts` only. HTTP 400 or 401: state `rejected`, nothing written. Any other failure: retried after 60, 120 and 240 seconds, then every 600 seconds.
7. Write-back, after a successful refresh and before the new token is used: `POST /v1/auth/kubernetes/login` with `{"role": AXON_CREDENTIAL_ROLE, "jwt": <the projected token at /var/run/secrets/openova-token/token>}`, then `POST /v1/<AXON_CREDENTIAL_KV_PATH>` with header `X-Vault-Token` and body `{"options":{"cas":<version>},"data":{"document":"<the document as JSON>"}}`. Success: the returned `data.version` is the version of the next write, and the new token is put in use. HTTP 400 naming check-and-set: state `conflict`, the new token is not used. Any other failure: the new token is used, `lastPersistError` is set, and the write is retried every 30 seconds without a new refresh.
8. `GET /stats` returns `credential: {"state":"absent"}` without a document, otherwise `{"state", "expiresAt", "lastRefreshAt", "lastPersistAt", "lastPersistError"}` with ISO times (`""` when not yet).
9. A child's environment is the parent's without `CLAUDECODE`, with `CLAUDE_CODE_OAUTH_TOKEN` set to the access token and `HOME` set to one empty directory made under the temporary directory at the first run (`childEnv` in `src/upstream.ts`). No child sees the refresh token or a credential file. Nothing in `products/axon/src` writes a file.
10. No log line contains any part of the document, of a token or of a response body: the credential owner logs states, HTTP status codes and times only.
