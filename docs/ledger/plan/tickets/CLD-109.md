# CLD-109 — Port interface, capability interfaces

## In plain words

**The problem today.** The cloud provider interface of the API server has no place for the provider-specific work the provisioning engine will hand to each adapter: filling defaults, validating a request, and writing the adapter's own OpenTofu variables. Optional abilities of an adapter have no shared shape either. One adapter answers the server listing with an empty result although it lists nothing, and the janitor reads that as an account with no servers.

**What changes.** The interface gains the two methods and the error types the engine will use, the optional abilities become small interfaces that a caller looks up by provider name, and an adapter that cannot list servers says so with an error that the janitor treats as unknown.

**Done means:**

- Every cloud adapter and every test stub of the provider interface implements six methods, and the API server builds.
- A caller can ask whether a registered provider has an optional ability and gets a clear yes, no, or unknown-provider answer.
- A failed deployment whose provider cannot list its servers keeps its record, its state and its cluster credentials, and is never destroyed by the janitor.
- The provider conformance test still passes for every pack, with its adapter sub-test waiting for the local adapter.
- No line that names a cloud is added to shared code, and the handler package does not grow.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. `CloudProvider` has exactly six methods: `Name`, `Normalize(spec *ProvisionSpec, profile *cloudprofile.Profile) error`, `TfVars(spec ProvisionSpec, profile *cloudprofile.Profile) (map[string]any, error)`, `Wipe`, `ListServers` and `ValidateCreds`. `Normalize` and `TfVars` never call the cloud.
2. `ErrNotSupported` is returned by a method the adapter cannot perform. A caller treats it as unknown, never as empty. `FieldError` names the request field that failed `Normalize` and prints `<field>: <message>`. `ErrTfVarCollision` is the engine's error for an adapter variable that collides with an engine variable.
3. `ProvisionSpec` is what an adapter sees of one request: `DeploymentID`, `SovereignFQDN`, `Installation`, `Regions`, `Creds`, `StorageClass` and `ObjectStorage` (`ObjectStorageSpec`: `Region`, `Bucket`, `AccessKey`, `SecretKey`). The fields `ParentDomains`, `GitOpsRepoURL`, `HandoverJWTPublic` and `Raw` are deleted; nothing reads them since CLD-102. `RegionSpec` gains `CloudRegion` (the cloud's own region) and `Zone` ("" means the profile's default zone); `Code` becomes the Sovereign-unique key of the region.
4. `capabilities.go` declares the capability interfaces with their input and result types: `Preflighter`, `PostApplier`, `ApplyErrorClassifier`, `OrphanSweeper`, `LivenessProber`, `FrontDoorReconciler`, `LegacyAliaser`, `AdoptionMapper` and `ObjectStorageValidator`. `IdentityManager` and `KeyProber` are not declared here; CLD-107 adds them.
5. `As[T any](name string) (T, bool, error)` returns the registered adapter as `T`. The boolean is false when the adapter does not implement `T`; the error is non-nil only when no adapter is registered under the name.
6. The adapters' `Normalize` returns nil and their `TfVars` returns an empty map. The Hetzner `ListServers` returns `nil, providers.ErrNotSupported`.
7. `internal/handler/janitor.go` does not change. Its probe already reports a deployment as alive, with the error, for any `ListServers` error, and the janitor then keeps the record and destroys nothing. Two new tests prove it with the production probe: one with a stub provider that returns `ErrNotSupported`, armed destructive, and one with the registered Hetzner adapter.
8. In the conformance test, `t.Skip("until CLD-102")` becomes `t.Skip("until CLD-088")`. Without the skip the adapter sub-test fails for the local pack, whose adapter arrives with CLD-088.
9. The package comment of `provider.go` says what is true today: the port, the capability interfaces reached with `As[T]`, the generated registry in `providers/all` and the module contract in `infra/providers/_contract/contract.json`.
10. All nine files change only through the patch `CLD-109.patch` of this ticket.
