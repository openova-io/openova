# PRD-509 — Internal authorisation API

## In plain words

**The problem today.** Before a customer can agree to a consent, the consent step of the authorisation server must show what the third party asks for and which accounts the customer holds. The open-banking product has nothing that answers those two questions: the consent step is built and tested only against a stand-in. So no customer can authorise a consent.

**What changes.** The product gains the package of its internal authorisation API. It accepts only the short-lived token of the consent step, shows a consent that awaits a decision to the application that created it, and turns a signed-in customer into the list of accounts held at the bank. The call that records the decision, and the listener that serves the package, come in two later tasks.

**Done means:**

- A call without the token of the consent step is refused whatever it addresses, and so is a token that was issued for the resource server.
- The consent step reads a consent that awaits a decision and sees its permissions and its expiry; another application, and a consent that is already decided, get a refusal.
- The consent step turns a signed-in identity into the customer and the accounts of that customer, with each account number masked to its last four characters.
- An unknown customer and a core-banking adapter that cannot answer each give their own error.
- Neither call changes a consent.
- Every test of the product passes on the pull request, and the linter and the security scan find nothing new.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The open-banking product `products/fingate` gains the package `products/fingate/internal/authz`, its internal authorisation API. The package is an HTTP handler, `authz.Server`, built by `authz.New`. It serves two calls for the consent step of the authorisation server (the Keycloak extension `platform/keycloak/extensions/fapi-consent`): `GET /internal/v1/authorisations/{consentId}?client_id=<id>` shows a consent that awaits a decision, and `POST /internal/v1/authorisations/{consentId}/customer` resolves an identity to the customer and lists the accounts of the customer through the ledger port. Every call, whatever it addresses, must carry the token of the consent step: a token of the realm with the audience `fingate-authz`, the subject `fapi-consent` and a lifetime of at most 60 seconds. A token made for the resource server is refused. Both calls read; neither changes a consent. A person sees the result on the pull request: the five tests of the new package run and pass in the check `go vet and go test — products/fingate`.

This ticket is the first of three pieces of the API. The third call, which records the decision of the customer, and the listener of the program `fingate-api` that serves this package are later work packages. This ticket adds no listener and changes no program.

## 3. The model (the law)
1. **A handler, not a listener.** `authz.New(authz.Config)` returns `*authz.Server`, an `http.Handler`. `Config` holds `Profile` (its signing algorithms are read), `Issuer` (the issuer of the realm, an `https` address), `Keys` (the key set of the realm, a `token.KeySource`), `Store` (the consents, a `store.Store`), `Ledger` (the ledger port, a `*ledgerclient.Client`), `Now` (nil: `time.Now`) and `Logf` (nil: nothing is logged). `New` refuses a configuration without `Store` or `Ledger`, and one that `token.New` refuses; each error starts with `authz: `. The package opens no listener, reads no flag and no environment variable, and no other package imports it yet.
2. **The token is checked first, on every call.** `ServeHTTP` reads the bearer token of the header `Authorization` and runs three checks before it looks at the method or the path:
   - rules T1 to T5 of the package `products/fingate/internal/token` (`Checker.Verify`), with the audience `fingate-authz` (`authz.Audience`). The server builds this checker itself from `Profile`, `Issuer` and `Keys`; it cannot be given one. So a token whose audience is the resource server is refused here.
   - the subject is `fapi-consent` (`authz.Subject`).
   - the token ends at most `authz.MaxLifetime` (60 seconds) plus `token.Skew` (60 seconds) from now.

   These are the values the caller writes: `AUDIENCE`, `SUBJECT` and `TOKEN_SECONDS` in `platform/keycloak/extensions/fapi-consent/src/main/java/io/openova/keycloak/fapi/AuthzClient.java`. A refused token is answered with status 401, the header `WWW-Authenticate: Bearer error="invalid_token"` and the body `{"error":"invalid_token"}`, and one line goes to `Logf`. When the check could not run (the key set could not be fetched) the answer is 500 `internal`. There is no switch that weakens a check.
3. **Then the route.** Two routes exist. Any other method or path is answered with 404 `no-route`, after the token check.
4. **The read call**, `GET /internal/v1/authorisations/{consentId}?client_id=<id>`. The checks run in this order, and the first that fails ends the call:

   | Check | Answer when it fails |
   |---|---|
   | a consent with this identifier exists | 404 `consent-not-found` |
   | the query parameter `client_id` equals the client that created the consent (a missing parameter does not) | 403 `client-mismatch` |
   | the consent is in the state `awaiting` | 409 `not-awaiting` |
   | the consent is of the family `account-access`, the only family that has a summary | 500 `internal` |

   The answer 200 is one JSON object with the members `consentId`, `family`, `clientId`, `state`, `expiresAt` and `summary`. `expiresAt` is the expiry of the consent as RFC 3339 in UTC, or the empty string when the consent has no expiry. `summary` is `{"permissions": [...]}`, the permissions of the stored consent request in their stored order.
5. **The customer call**, `POST /internal/v1/authorisations/{consentId}/customer`, with the body `{"identity": {"scheme": <string>, "subject": <string>, "attributes": {<string>: <string>}}}`. `attributes` may be absent. The checks run in this order:

   | Check | Answer when it fails |
   |---|---|
   | a consent with this identifier exists | 404 `consent-not-found` |
   | the body is one JSON object of at most 64 KiB with no other member; `scheme` and `subject` are not empty; every attribute is a string | 400 `bad-request` |
   | the consent is in the state `awaiting` | 409 `not-awaiting` |
   | the ledger resolves the identity (`ResolveCustomer`); the error kind `ledgerclient.ErrNotFound` means it knows no such customer | 404 `customer-unknown` |
   | the ledger answers `ResolveCustomer` with a customer that has an identifier, and answers `ListAccounts` for that customer | 502 `ledger-unavailable`, and one line to `Logf` |

   The answer 200 is `{"customerId": <string>, "accounts": [{"id", "displayName", "maskedNumber", "currency"}]}`, the accounts in the order of the ledger. `displayName` is the nickname of the account, or its sub-type when it has no nickname. `maskedNumber` is four asterisks followed by the last four characters of the account identification; an identification of four characters or fewer gives the empty string. The full identification never leaves the package.
6. **Both calls read.** Neither call writes to the store. No consent changes its state and no history entry is added.
7. **Every answer** has the header `Content-Type: application/json` and the header `Cache-Control: no-store`. An answer other than 200 has the body `{"error": "<code>"}` with one of the codes of rules 2 to 5.
8. **No customer data and no fixtures in the product.** The package keeps nothing between two calls: the customer and the accounts come from the ledger port on every call. The package issues no code and no token. The test data is the in-memory ledger of `products/fingate/internal/ledgertest`, used by the test file only.
9. **No new module.** `products/fingate/go.mod` and `products/fingate/go.sum` do not change.
10. Nothing is deleted.

// Package authz is the internal authorisation API of the open-banking product: the calls with
// which the consent step of the authorisation server shows a consent to the customer.
//
//	GET  /internal/v1/authorisations/{consentId}?client_id=<id>   the consent, as the customer will see it
//	POST /internal/v1/authorisations/{consentId}/customer         the customer of an identity, and the customer's accounts
//
// Both calls read; neither changes a consent. The call that records the customer's decision is
// not served yet.
//
// Every call, whatever it addresses, is checked first. Rules T1 to T5 of package token run with
// the audience Audience, so a token made for the resource server is refused here. Then the
// subject must be Subject and the token must end within MaxLifetime. A refused token is
// answered with 401 and the header WWW-Authenticate.
//
// An answer other than 200 has the body {"error": "<code>"}:
//
//	400 bad-request          the body is not the JSON the call takes, or a value is missing
//	401 invalid_token        the token was refused
//	403 client-mismatch      client_id is not the client that created the consent
//	404 consent-not-found    no consent has this identifier
//	404 customer-unknown     the ledger knows no customer of this identity
//	404 no-route             the method and the path are none of the calls
//	409 not-awaiting         the consent does not await a decision
//	500 internal             the store failed, the token could not be checked, or the consent has no summary
//	502 ledger-unavailable   the ledger could not answer
//
// The package issues no code and no token and holds no customer data: the customer and the
// accounts come from the ledger port on every call.
package authz

import (
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"strings"
	"time"

	"github.com/openova-io/openova/products/fingate/internal/consent"
	"github.com/openova-io/openova/products/fingate/internal/gen/accountinfo"
	"github.com/openova-io/openova/products/fingate/internal/ledgerclient"
	"github.com/openova-io/openova/products/fingate/internal/profile"
	"github.com/openova-io/openova/products/fingate/internal/store"
	"github.com/openova-io/openova/products/fingate/internal/token"
)

// Audience is the audience of the token a caller presents.
const Audience = "fingate-authz"

// Subject is the subject of the token a caller presents: the consent step of the authorisation server.
const Subject = "fapi-consent"

// MaxLifetime is the longest lifetime of a caller's token. A token that ends later than
// MaxLifetime plus token.Skew from now is refused.
const MaxLifetime = 60 * time.Second

// Config configures a Server.
type Config struct {
	Profile *profile.Profile              // its signing algorithms are read (rule T1)
	Issuer  string                        // the realm's issuer, an https address (rule T3)
	Keys    token.KeySource               // the realm's key set (rule T2)
	Store   store.Store                   // the consents
	Ledger  *ledgerclient.Client          // the ledger port
	Now     func() time.Time              // nil: time.Now
	Logf    func(format string, a ...any) // receives one line per refused token and per failure; nil: nothing is logged
}

// Server is the internal authorisation API. It is an http.Handler.
type Server struct {
	cfg     Config
	checker *token.Checker
	mux     *http.ServeMux
}

// New checks the configuration and builds the routes.
func New(cfg Config) (*Server, error) {
	if cfg.Store == nil || cfg.Ledger == nil {
		return nil, errors.New("authz: the configuration needs Profile, Issuer, Keys, Store and Ledger")
	}
	if cfg.Now == nil {
		cfg.Now = time.Now
	}
	if cfg.Logf == nil {
		cfg.Logf = func(string, ...any) {}
	}
	checker, err := token.New(token.Config{Profile: cfg.Profile, Issuer: cfg.Issuer, Audience: Audience, Keys: cfg.Keys, Now: cfg.Now})
	if err != nil {
		return nil, fmt.Errorf("authz: %w", err)
	}
	s := &Server{cfg: cfg, checker: checker, mux: http.NewServeMux()}
	s.mux.HandleFunc("GET /internal/v1/authorisations/{consentId}", s.read)
	s.mux.HandleFunc("POST /internal/v1/authorisations/{consentId}/customer", s.customer)
	return s, nil
}

// ServeHTTP checks the token of the call and then routes it.
func (s *Server) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	jws := ""
	if scheme, value, ok := strings.Cut(r.Header.Get("Authorization"), " "); ok && strings.EqualFold(scheme, "Bearer") {
		jws = strings.TrimSpace(value)
	}
	claims, err := s.checker.Verify(r.Context(), jws)
	if err == nil && claims.Subject != Subject {
		err = &token.Error{Rule: "subject", Status: token.StatusUnauthorized, Reason: fmt.Sprintf("sub %q is not %q", claims.Subject, Subject)}
	}
	if err == nil && claims.ExpiresAt.After(s.cfg.Now().Add(MaxLifetime+token.Skew)) {
		err = &token.Error{Rule: "lifetime", Status: token.StatusUnauthorized, Reason: fmt.Sprintf("the token ends more than %s from now", MaxLifetime+token.Skew)}
	}
	var refused *token.Error
	switch {
	case errors.As(err, &refused):
		s.cfg.Logf("authz: %s %q: %v", r.Method, r.URL.Path, err)
		w.Header().Set("WWW-Authenticate", token.Challenge)
		fail(w, http.StatusUnauthorized, "invalid_token")
		return
	case err != nil:
		s.internal(w, r, err)
		return
	}
	if _, pattern := s.mux.Handler(r); pattern == "" {
		fail(w, http.StatusNotFound, "no-route")
		return
	}
	r.Body = http.MaxBytesReader(w, r.Body, 64<<10) // no call takes a larger body
	s.mux.ServeHTTP(w, r)
}

// write writes v as the JSON body of an answer.
func write(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.Header().Set("Cache-Control", "no-store")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(v)
}

// fail writes an answer other than 200.
func fail(w http.ResponseWriter, status int, code string) {
	write(w, status, map[string]string{"error": code})
}

// internal logs err and answers 500.
func (s *Server) internal(w http.ResponseWriter, r *http.Request, err error) {
	s.cfg.Logf("authz: %s %q: %v", r.Method, r.URL.Path, err)
	fail(w, http.StatusInternalServerError, "internal")
}

// load returns the consent the path names. When there is none it answers and returns false.
func (s *Server) load(w http.ResponseWriter, r *http.Request) (store.Consent, bool) {
	c, found, err := s.cfg.Store.Get(r.Context(), r.PathValue("consentId"))
	switch {
	case err != nil:
		s.internal(w, r, err)
	case !found:
		fail(w, http.StatusNotFound, "consent-not-found")
	}
	return c, err == nil && found
}

// decode reads the one JSON object of a request body into v. A member v does not have, a
// second value and a body that is not JSON are refused.
func decode(r *http.Request, v any) error {
	d := json.NewDecoder(r.Body)
	d.DisallowUnknownFields()
	if err := d.Decode(v); err != nil {
		return err
	}
	if _, err := d.Token(); err != io.EOF {
		return errors.New("the body holds more than one value")
	}
	return nil
}

// summary is what the customer is asked to agree to. Only account-access consents exist; the
// package that adds another consent family adds its summary here.
func summary(c store.Consent) (map[string]any, error) {
	if c.Family != consent.AccountAccess {
		return nil, fmt.Errorf("consent %s: no summary for the family %q", c.ID, c.Family)
	}
	var req accountinfo.OBReadConsent1
	if err := json.Unmarshal(c.Request, &req); err != nil {
		return nil, fmt.Errorf("stored consent %s: %w", c.ID, err)
	}
	permissions := make([]string, 0, len(req.Data.Permissions))
	for _, p := range req.Data.Permissions {
		permissions = append(permissions, string(p))
	}
	return map[string]any{"permissions": permissions}, nil
}

// read answers GET /internal/v1/authorisations/{consentId}?client_id=<id>.
func (s *Server) read(w http.ResponseWriter, r *http.Request) {
	c, ok := s.load(w, r)
	if !ok {
		return
	}
	if r.URL.Query().Get("client_id") != c.ClientID {
		fail(w, http.StatusForbidden, "client-mismatch")
		return
	}

		return

// account is one account the customer may choose.
type account struct {
	ID           string `json:"id"`
	DisplayName  string `json:"displayName"`  // the nickname, or the sub-type when the account has no nickname
	MaskedNumber string `json:"maskedNumber"` // four asterisks and the last four characters of the identification
	Currency     string `json:"currency"`
}

// mask hides all but the last four characters of an account identification. An identification
// of four characters or fewer is not shown at all.
func mask(identification string) string {
	r := []rune(identification)
	if len(r) <= 4 {
		return ""
	}
	return "****" + string(r[len(r)-4:])
}

// customer answers POST /internal/v1/authorisations/{consentId}/customer.
func (s *Server) customer(w http.ResponseWriter, r *http.Request) {
	c, ok := s.load(w, r)
	if !ok {
		return
	}
	var body struct {
		Identity *struct {
			Scheme     string            `json:"scheme"`
			Subject    string            `json:"subject"`
			Attributes map[string]string `json:"attributes"`
		} `json:"identity"`
	}
	if err := decode(r, &body); err != nil || body.Identity == nil || body.Identity.Scheme == "" || body.Identity.Subject == "" {
		fail(w, http.StatusBadRequest, "bad-request")
		return
	}
	if c.State != consent.Awaiting {
		fail(w, http.StatusConflict, "not-awaiting")
		return
	}
	cust, err := s.cfg.Ledger.ResolveCustomer(r.Context(), body.Identity.Scheme, body.Identity.Subject, body.Identity.Attributes)
	if errors.Is(err, ledgerclient.ErrNotFound) {
		fail(w, http.StatusNotFound, "customer-unknown")
		return
	}
	if err == nil && cust.GetCustomerId() == "" {
		err = errors.New("the ledger resolved a customer without an identifier")
	}
	var accounts []account
	if err == nil {
		list, lerr := s.cfg.Ledger.Accounts(r.Context(), cust.GetCustomerId())
		err = lerr
		accounts = make([]account, 0, len(list))
		for _, a := range list {
			name := a.GetNickname()
			if name == "" {
				name = a.GetSubType()
			}
			accounts = append(accounts, account{ID: a.GetAccountId(), DisplayName: name, MaskedNumber: mask(a.GetIdentification()), Currency: a.GetCurrency()})
		}
	}
	if err != nil {
		s.cfg.Logf("authz: consent %s: %v", c.ID, err)
		fail(w, http.StatusBadGateway, "ledger-unavailable")
		return
	}
	write(w, http.StatusOK, map[string]any{"customerId": cust.GetCustomerId(), "accounts": accounts})
}
