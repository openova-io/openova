# CTL-815 — One Continuum definition file

## In plain words

**The problem today.** The definition of the Continuum kind is kept twice, byte for byte, in the platform umbrella chart and in the Continuum chart. A script keeps the two equal, and whichever chart upgrades last replaces the other's copy on the cluster. Two copies of one contract are one more thing to keep in step and one more way to drift.

**What changes.** Only the Continuum chart carries the definition. It is the one chart that runs in every region, so every region still gets the kind. The umbrella's copy and the script that compared the two are deleted, and the API's schema test reads the file that stays.

**Done means:**

- The repository holds exactly one definition of the Continuum kind, in the Continuum chart.
- The script that compared two copies is gone, and no workflow calls it.
- The API still validates Continuum objects against the same schema, and its test fails when that schema and the definition file differ.
- A change to the Continuum definition starts the API's test workflow.
- The generated inventory of custom resources lists the Continuum kind once.

The rest of this ticket is the exact instruction for the model that does the work.
