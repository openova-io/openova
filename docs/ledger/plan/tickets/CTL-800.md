# CTL-800 — Decision record 0027: the region-loss contract

## In plain words

**The problem today.** The platform has no accepted answer to what a Sovereign of two regions keeps, and how fast it recovers, when one region is lost. When the lost region holds the writer of Git, no region can commit any more, so no move can run, and the only thing that acts is an older automatic promoter of the shared database that runs outside Git and fences nothing.

**What changes.** A new accepted decision record states the numbers for each kind of data, gives each region's Git server its own database with a push from the writer, and makes the promotion of the surviving region one commit, fenced by a lease outside both regions. The index of decision records lists it.

Written by work package CTL-800. It states what a Sovereign of two regions keeps, and how fast it recovers, when one region is lost and the other survives. It decides decisions R1 to R10: the numbers per data class, how the follower region gets its copy of Git (after lab test CTL-055, `docs/ledger/plan/spikes/CTL-055.md`), the lease that fences the writer, how a surviving region becomes the writer, and what this does to the bucket `dr-leases`, lock stage `topology`, per-Application DNS and the mesh loop of the API. It settles the two limits that ADR-0015 decision D8 left open: the loss of the writer region, and the database pair shared-pg, which D8 excluded because it holds the Git server's database. The loss of both regions stays the subject of ADR-0036. The four `Unfreezes:` lines are explained under "What the Unfreezes lines permit".

Terms used here:

- **Writer region**: the region whose Git server accepts commits and whose controllers and API run (ADR-0021). Every other region is a **follower region**.
- **Writer lease**: the lease, held outside both regions, that names the writer region (R3).
- **Region loss**: a region whose observations stop answering for longer than `spec.transition.regionLossSeconds` of its Continuum (ADR-0015 D8).

## Context

Measured on `main` at commit `2c6c25e1c`, on 2026-11-24.

- Each region runs its own Git server with its own repository disk. On a Sovereign of two regions both Git servers use one database: the database pair shared-pg, reached through its write alias `shared-pg-mesh-rw` (`infra/providers/_shared/cloudinit-control-plane.tftpl`, `clusters/_template/bootstrap-kit/10-gitea.yaml`). When the writer region is lost, the follower's Git server loses its database with it.
- The follower's copy of Git comes from a CronJob that runs every minute, pulls each repository from the writer and force-pushes it into the follower's Git server (`clusters/_template/sovereign-region/multi-region-follower/git-sync-cronjob.yaml`). It is an entry of the polling allow-list `scripts/baselines/polling.json`, "kept until the follower region's Git has its own database".
- Lab test CTL-055 ran Gitea 1.22.3, the version the platform pins, with two Git servers on one database. The push mirror with sync on commit carried 10 of 10 commits in each of three runs, each in 2.7 to 3.6 seconds. It needs `[migrations] ALLOWED_DOMAINS` naming the follower. A repository must exist on the follower before its mirror is created. The mirror row's `last_error` is not a health signal. Pull-request refs are not copied. On promotion each mirror must be created again in the other direction.
- ADR-0015 decision D8: the Continuum moves the Primary of a group only by commits to Git. The lease of one transition is a file in Git (`core/controllers/continuum/internal/transition/lease.go`). |---|---|
| R1 | **The numbers.** One region is lost and the other survives. Recovery time is counted from the loss. Git: at most 60 seconds of commits to a default branch are lost; the survivor accepts commits within 10 minutes. Database pair at `dataDurability: required` (ADR-0004): nothing is lost; at another durability, what the replica had not received. Its survivor is writable within 15 minutes. OpenBao: a shared value whose write to the peer's store returned is not lost; each region serves its own store, so recovery takes no time (ADR-0018 S14). etcd: it is not copied between regions, and the survivor's etcd is complete for its own region; a rebuilt region comes from Git and from the copies of ADR-0036. DNS of an Application: the survivor's edge answers within 2 minutes (R9). Domain events: a message of the lost region that no consumer had taken is lost. Check CTL-G10 (CTL-820) measures these numbers. |
| R2 | **The follower's Git server has its own database, and the writer pushes to it.** Each region's Git server uses its own database cluster `gitea-pg` in its own region: the own-cluster path that `clusters/_template/bootstrap-kit/10-gitea.yaml` has today, in every region. The writer's Git server pushes every repository to each follower with Gitea's push mirror and sync on commit. For each repository, the repository is first created on each follower's Git server, then the mirror on the writer. Every creation of a repository does both, and a one-time backfill does both for the repositories that exist. The writer's Git server gets `[migrations] ALLOWED_DOMAINS` with the follower's Git host; `ALLOW_LOCALNETWORKS` stays off. Health is the comparison of the default-branch heads of writer and follower. The mesh part, with area NET: the writer region gets a stub Service of each follower's Git server and the egress rule to it, as the follower has for the writer today. The one-minute job and its polling entry are deleted. A running Sovereign moves the writer's Git database out of shared-pg once; the follower's database starts empty and the backfill fills it. |
| R3 | **The writer lease is held by the lease-witness Worker.** One slot per Sovereign, `<fqdn>/writer`, held by a region id, with a time to live of 60 seconds, renewed every 20 seconds. A region acts as the writer only while it holds the lease: its controllers commit, its API accepts the routes that change intent, and its Git server runs the push mirrors. A holder that cannot renew before expiry stops acting as the writer. The Worker stays, so FND-170 removes nothing. The Continuum controller gets a client of the Worker's contract. ## What is open

1. **The writer lease when the Worker cannot be reached.** A holder that cannot renew stops after one time to live (R3). While neither region reaches the Worker, no region is the writer: no change of intent is accepted and nothing is promoted, while Applications keep serving. Whether a second witness or an override by the sovereign-admin is added is not decided here.
2. **What is lost between the last mirror push and the loss.** Commits that the lost writer accepted after its last mirror push to the survivor are not on the survivor, and R6 overwrites them when the region returns. Whether they are kept for review before that overwrite is not decided here. Pull requests, their refs and every other row of the writer's Git database are not copied; a pull request that is open at the loss is lost (lab test CTL-055, point 6).
3. **Writes that bypass the platform.** The writer lease stops the platform's own writers. It does not make a Git server read-only, so a person who commits directly on the old writer's Git server during a partition writes a commit that R6 later overwrites.

## Alternatives rejected

**R2.** (a) Keep the one-minute job: up to a minute of commits lost, and the follower still depends on the writer region's database. (b) The push mirror on one shared database, as lab test CTL-055 ran it: the follower's Git server loses its database with the writer region, so it can never become the writer. (c) A database pair for Git across the regions: the Git server would be writable only after a database promotion, which needs a commit, which needs a writable Git server.

**R3.** (a) The Git lease file of D8: it lives on the writer's Git server and is lost with it. (b) A Kubernetes Lease: it lives in the etcd of one region. (c) The bucket `dr-leases`: it lives in the JetStream of one region. (d) A vote of the two regions: two members cannot tell a lost peer from a cut link.

**R4.** (a) An approval step through break-glass: a second path beside Git, which ADR-0021 C6 keeps for emergencies by a person, not for a planned contract. (b) An imperative switchover in the API: the API runs in the lost region. (c) Keep the legacy auto-promoters: they decide from probes inside one region with no fence, and they patch and suspend HelmReleases outside Git.

**R9.** (a) The Continuum calls the PowerDNS API: ADR-0015 D8 forbids it. (b) The wildcard record alone: it follows the control-plane region, not an Application's Primary.

## Consequences

- Until the two packages of R2 and R4 have merged, the loss of the writer region still leaves every group Blocked, and the legacy promoters stay. CTL-810 waits for the promotion package.
- The API keeps its flat files in one region until ADR-0021 C16. A promoted writer's API starts from Git and from the cluster, without them.
