# CTL-045 — Publish contract C9 and its tool

## In plain words

**The problem today.** The platform has more than three hundred routes and tools that change state, spread over a dozen services. Nothing lists them, so nobody can say which of them still write straight into the cluster, which already go through Git, and which package is meant to change each one. A new route that writes into the cluster can be added without anyone noticing.

**What changes.** One contract file lists every state-changing route and tool, each with its write class today, its write class in the target and the package that carries it there. Checks on every pull request fail when the code and the file disagree, and the number of routes that still write into the cluster can only go down.

**Done means:**

- The contract file lists all 314 state-changing routes and tools of today, one line each, and every line names where its effect goes in the target.
- 40 entries still write straight into the cluster, and the baseline holds that number.
- A pull request that adds a state-changing route to a listed service, or removes one, without changing the file turns red.
- A pull request that marks a route as done before the package that moves it has merged turns red.
- The Go test of catalyst-api fails when its router and the file disagree.
- The generator proves on itself that each of its rules can fail.
- No product code changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Contract C9, the mutating-route table, is the file `docs/contracts/C9-mutating-routes.yaml`. It has one entry, on one line, for every route that changes state (POST, PUT, PATCH, DELETE) of twelve components, and for the one write tool of the platform's tool server: 314 entries. Each entry says what the route writes today, where its durable effect goes in the target (Git, a database, an outside service, or nowhere), what happens to it (keep, migrate, refuse, delete), in which batch, by which package, and whether that package has merged. The generator `scripts/generators/mutating-routes.py` writes the file sorted and formatted, and with `--check` it is guard G7: it fails when a route that the code registers has no entry, when an entry names a route the code does not register, when a value is not allowed, and when the number of entries that still write into the cluster (40 today) differs from `scripts/baselines/mutating-routes.json`. The workflow `check-generated-docs` already runs every generator with `--self-test` and `--check` on every pull request, so it runs this one with no workflow change. The Go test `TestMutatingRoutesContract` walks the router of catalyst-api and compares its routes with the table. A person sees the result on any pull request: the check `generated-docs` prints `routes=314` and `open_cluster_writers=40`.

## 3. The model (the law)
1. The table is the block `C9-mutating-routes.yaml` of field 5. Its form: three comment lines, then `schema: openova.io/mutating-routes/v1`, then `operations: [restart, exec, job-retry, reconcile]`, then `routes:` with one flow mapping per line. The keys of an entry, in this order: `component`, `method`, `path`, `today`, `writeClass`, `operation`, `disposition`, `batch`, `package`, `done`. The entries are sorted by component, then path, then method. The operation values are a list inside the file, so a later package that adds an operation (for example `machine-run`) edits the file only.
2. The meaning and the allowed values of every field are written at the head of the generator, rules 1 and 2. In short: `today` is one of `G`, `G-no-reader`, `C`, `C-dead`, `K`, `X`, `D`, `N` (a Git commit that a reconciler reads; a Git commit that nothing reads; a custom resource written to the cluster; one that no chart installs; a workload or core object written to the cluster; an outside API; a database, map or file; no durable change). `writeClass` is one of `git`, `database`, `external`, `none`. `operation` is `""` or a value of `operations`, and not `""` only with `writeClass: none`. `disposition` is one of `keep`, `migrate`, `refuse`, `delete`. `batch` is `"-"` or one capital letter, and `"-"` with `keep`. `package` is a package identifier, an area of three capital letters, or `"-"` when nothing is left to do, and `"-"` only with `keep`. `done` is true when `package` is `"-"`, and may be true with a package identifier only when that package's marker `docs/ledger/plan/done/<package>.yaml` exists.

// TestMutatingRoutesContract walks the router and fails when a POST, PUT,
// PATCH or DELETE route has no entry of component catalyst-api in contract
// C9, or when such an entry names a route the router does not register. A
// path that the router serves for every method is a mount, which the golden
// file writes as ANY; it is not a route of the table.
func TestMutatingRoutesContract(t *testing.T) {
	data, err := os.ReadFile(contractPath)
	if err != nil {
		t.Fatalf("read %s: %v", contractPath, err)
	}
	var table struct {
		Routes []struct {
			Component string `yaml:"component"`
			Method    string `yaml:"method"`
			Path      string `yaml:"path"`
		} `yaml:"routes"`
	}
	if err := yaml.Unmarshal(data, &table); err != nil {
		t.Fatalf("parse %s: %v", contractPath, err)
	}
	listed := map[string]bool{}
	for _, r := range table.Routes {
		if r.Component == "catalyst-api" {
			listed[r.Method+" "+r.Path] = true
		}
	}
	methods := map[string][]string{}
	err = chi.Walk(buildRouter(goldenDeps()), func(method, path string, _ http.Handler, _ ...func(http.Handler) http.Handler) error {
		methods[path] = append(methods[path], method)
		return nil
	})
	if err != nil {
		t.Fatalf("walk the router: %v", err)
	}
	served := map[string]bool{}
	for path, ms := range methods {
		sort.Strings(ms)
		if strings.Join(ms, " ") == allMethods {
			continue
		}
		for _, m := range ms {
			switch m {
			case http.MethodPost, http.MethodPut, http.MethodPatch, http.MethodDelete:
				served[m+" "+path] = true
			}
		}
	}
	if len(served) == 0 {
		t.Fatal("the router has no POST, PUT, PATCH or DELETE route; the walk is broken")
	}
	for _, c := range []struct {
		these, other map[string]bool
		message      string
	}{
		{served, listed, "registered in the router and missing from " + contractPath},
		{listed, served, "listed in " + contractPath + " and not registered in the router"},
	} {
		var missing []string
		for route := range c.these {
			if !c.other[route] {
				missing = append(missing, route)
			}
		}
		sort.Strings(missing)
		for _, route := range missing {
			t.Errorf("%s: %s", route, c.message)
		}
	}
}
