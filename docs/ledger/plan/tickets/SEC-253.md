# SEC-253 — The metrics chart's object-store password is generated and read from an environment variable

## In plain words

**The problem today.** The object store that the metrics chart runs for itself has a root password that is fixed in the chart: the same on every Sovereign, and public in this repository. The chart writes it into a Secret and, in plain text, into the configuration of every metrics component.

**What changes.** Each region's object store gets a random password that External Secrets makes in OpenBao. The store, its bucket Job and every metrics component read it from an environment variable when they start, and they restart together when it changes.

**Done means:**

- No object that the metrics chart renders holds the old fixed password, and the chart renders no Secret of its own.
- The chart generates the password through the secrets library: a generator, a push into the region's OpenBao, and an ExternalSecret that writes the Secret the readers use.
- The three storage sections of the metrics configuration read the password from an environment variable, and the store, the bucket Job and all ten metrics components take that variable or file from the generated Secret.
- Helm's upgrade from the release a Sovereign runs today applies to every object and changes the Pod template of the store and of all ten metrics components, so all of them restart on the new password in that one upgrade.
- The register of Secret objects names the new Secret, and the allow-list of plain Secret manifests no longer lists the chart.
- No chart version line changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
bp-mimir runs its own MinIO in namespace `mimir` (kit slot 23, placement `vcluster: host`). Today its root password is the literal `supersecret` of the chart, in Secret `mimir-minio` and in Mimir's storage configuration (ConfigMap `mimir-config`). After this ticket the password is the generated value `mimir-minio-password` of the chart (row M1, gap G9 of `docs/ledger/plan/spikes/SEC-227.md`): External Secrets makes it with a Password generator, pushes it once into the region's OpenBao and writes Secret `mimir-minio-password` (key `password`). MinIO reads it from `MINIO_ROOT_PASSWORD`, the bucket Job from a projected file, and every Mimir component from `MINIO_ROOT_PASSWORD`, which Mimir expands into the three S3 stanzas of its configuration. The old value is public, so it is rotated, never seeded. The proof is the case `TestMimirAppliesOverEveryState` of `tools/chart-upgrade`, run by the new chart test `platform/mimir/chart/tests/upgrade-over-deployed.sh`: it renders bp-mimir 1.0.14 (the pin of kit slot 23) from the history of the repository and the chart under test, finds the literal nowhere and no Secret in the new render, computes Helm's three-way patch for every object over 1.0.14 deployed and live, shows that MinIO and every Mimir component restart in that upgrade, and runs the bucket script with a stand-in `mc`.

## 3. The model (the law)
1. **No literal, no Secret.** No object of the render at the default values holds `supersecret`, as text or as base64, and the release renders no object of kind Secret.
2. **Generated, one value per region.** `platform/mimir/chart/values.yaml` holds `generatedSecrets.mimir-minio-password` with `delivery: synced`, `registerId: mimir-minio-password`, `epoch: 1`, `sharedAcrossRegions: false`. The new template `templates/generated-secrets.yaml` renders it through the library `platform/secrets-lib` (a `file://` dependency of `Chart.yaml`) with no peers: ServiceAccount `eso-reader`, SecretStore `openbao`, Password `mimir-minio-password-e1` (32 characters, letters and digits only), PushSecret `mimir-minio-password-e1` (`updatePolicy: IfNotExists`) to `openova/apps/mimir/mimir-minio-password/e1`, and ExternalSecret `mimir-minio-password` (`creationPolicy: Owner`) that writes Secret `mimir-minio-password`, key `password`. Each region runs its own MinIO, so each region generates its own value.
3. **Who reads it, and when.** Each reader reads the value when its container starts:
   - MinIO: `MINIO_ROOT_PASSWORD` from `secretKeyRef` `mimir-minio-password`/`password`; `MINIO_ROOT_USER` is the literal `grafana-mimir`, which is no secret (it is the `access_key_id` of Mimir's configuration).
   - The bucket Job (post-install and post-upgrade hook): the key `password` projected as `/config/rootPassword`; the user from `MINIO_ROOT_USER`.
   - Every Mimir component (alertmanager, compactor, distributor, ingester, overrides-exporter, querier, query-frontend, query-scheduler, ruler, store-gateway) and the upstream smoke-test Job: `MINIO_ROOT_PASSWORD` from the same Secret through `mimir-distributed.global.extraEnv`. The three stanzas `blocks_storage`, `ruler_storage` and `alertmanager_storage` read `secret_access_key: "${MINIO_ROOT_PASSWORD}"`, which Mimir expands because the upstream chart runs every component with `-config.expand-env=true`.
4. **Rotated on purpose, the store and the components together.** The Pods of MinIO and of every component carry `secret.reloader.stakater.com/reload: mimir-minio-password` (MinIO in its template, the components through `mimir-distributed.global.podAnnotations`). Raising `epoch` makes a new value, the Secret changes, and bp-reloader (kit slot 28, strategy annotations, every namespace) rolls MinIO and all ten components. The value is never seeded from the old one.
5. **The upgrade applies over what runs.** For every object of the new render, Helm's three-way patch over bp-mimir 1.0.14 deployed and live applies and gives the new render; the kinds of External Secrets are new and are created. The patch changes the Pod template of MinIO and of each of the ten components. Secret `mimir-minio` leaves the release and Helm deletes it; it carries no keep annotation, and nothing else reads it.
6. **No silent empty value.** Without `generatedSecrets.mimir-minio-password` the render fails with `generatedSecrets.mimir-minio-password is required`. The value `mimir-distributed.minio.rootPassword` is no longer read; no file of the tree sets it.
7. **Nothing else.** No chart version line, no kit slot, no file of `platform/secrets-lib`, no other file of `tools/chart-upgrade` changes, and no Python is added.
