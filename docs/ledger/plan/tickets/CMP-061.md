# CMP-061 — Engine values, informer kinds and mode adapter for the current policy kinds

## In plain words

**The problem today.** The policy engine runs with policy exceptions switched off, so a waiver can never be honoured at admission. catalyst-api neither watches the engine's new policy kinds nor can read their mode, so a policy rewritten to a new kind would drop out of the compliance views. Two label policies ship in the engine chart that no Sovereign switches on.

**What changes.** The engine honours exceptions placed in one namespace, which the policy chart creates. catalyst-api watches the two new policy kinds once the engine serves them and can read the mode of every policy kind; the two unused label policies and their values are gone.

**Done means:**

- The admission, background and reports controllers of the engine render with policy exceptions on and the exception namespace catalyst-policy-exceptions.
- The policy chart renders the Namespace catalyst-policy-exceptions.
- catalyst-api registers validatingpolicy and mutatingpolicy (group policies.kyverno.io, version v1, cluster-scoped) as optional informer kinds, and its ClusterRole may get, list and watch them.
- A test reads enforce or audit from a legacy ClusterPolicy, a ValidatingPolicy and a MutatingPolicy, and refuses every other kind; it fails when the rule of any kind is broken.
- The legacy policy guard counts 45 objects, and the two deleted templates are listed as deleted paths.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The engine chart `platform/kyverno/chart` switches policy exceptions on under its `kyverno:` key and names one exception namespace, `catalyst-policy-exceptions`; the policy chart `platform/kyverno-policies/chart` creates that namespace. The engine chart no longer carries the two label policies `mutate-add-openova-labels` and `validate-require-openova-labels` nor their values block `kyvernoOverlay.labelVocab`. catalyst-api registers the informer kinds `validatingpolicy` and `mutatingpolicy` (group `policies.kyverno.io`, version `v1`, cluster-scoped, optional), its ClusterRole grants get, list and watch on them, and the new file `products/catalyst/bootstrap/api/internal/compliance/adapters/policymode.go` reads the mode (`enforce` or `audit`) of a legacy `ClusterPolicy` and of the two new kinds. A person sees it in the rendered engine and policy charts, in `scripts/check-kyverno-legacy-policies.sh`, which prints `legacy_policy_objects=45`, and in the tests of package `adapters`. This prepares the rewrite of the policies to the new kinds (CMP-062 to CMP-065) and the exception of a waiver (CMP-083).

## 3. The model (the law)
1. **Exceptions in one namespace.** The engine values are `kyverno.features.policyExceptions.enabled: true` and `kyverno.features.policyExceptions.namespace: catalyst-policy-exceptions` (the value names recorded by spike CMP-S1, `docs/ledger/plan/spikes/CMP-S1.md` lines 77 to 78). They render as `--enablePolicyException=true` and `--exceptionNamespace=catalyst-policy-exceptions` into the admission, background and reports controllers: three of each. Nothing else of the engine render changes.
2. **The namespace** is created by the policy chart (`platform/kyverno-policies/chart/templates/namespace-exceptions.yaml`), unconditionally, labelled `pod-security.kubernetes.io/enforce: restricted`. It holds exceptions only, never a workload.
3. **Deleted.** `platform/kyverno/chart/templates/clusterpolicy-mutate-add-openova-labels.yaml`, `platform/kyverno/chart/templates/clusterpolicy-validate-require-openova-labels.yaml`, and the values block `kyvernoOverlay.labelVocab` of `platform/kyverno/chart/values.yaml`. Both policies are off by default and no Sovereign overlay switches them on, so they render nothing today. Their two entries leave `scripts/baselines/kyverno-legacy.json`, and their paths are appended to `docs/ledger/deleted-paths.txt`.
4. **Informer kinds.** `k8scache.DefaultKinds` gains `validatingpolicy` (resource `validatingpolicies`) and `mutatingpolicy` (resource `mutatingpolicies`), group `policies.kyverno.io`, version `v1` (served on engine v1.19.2, spike CMP-S1 line 51), `Namespaced: false`, `Optional: true`: an engine that does not serve the group starts no informer, and CMP-016 starts it when the definition arrives. The names are the constants `KindValidatingPolicy` and `KindMutatingPolicy`.
5. **The role.** `products/catalyst/chart/templates/clusterrole-cutover-driver.yaml` gains one rule: group `policies.kyverno.io`, resources `validatingpolicies` and `mutatingpolicies`, verbs get, list and watch. Read-only, like the rule of the legacy kind above it.
6. **The mode adapter.** `adapters.PolicyMode` has `Kinds()` (`clusterpolicy`, then the two new kinds) and `Mode(obj)`, which returns `enforce` or `audit` and true for a policy of the three kinds and false for any other object. A `ValidatingPolicy` or `MutatingPolicy` of group `policies.kyverno.io` enforces when `spec.validationActions` holds `Deny`. A `ClusterPolicy` of group `kyverno.io` enforces when `spec.validationFailureAction` is `Enforce`, or when `validate.failureAction` of one of its rules is. Each kind is read only by its own fields; upper and lower case are the same; it keeps no state and calls no API server.
7. **Not changed.** The engine pin, the report API group the engine writes, every policy of the policy chart, and `products/catalyst/bootstrap/api/internal/handler/compliance.go` (it still reads the mode of `clusterpolicy` events through its own `enginePolicyMode`; field 11).

+// LegacyPolicyGroup is the API group of the legacy policy kind ClusterPolicy;

+const (
+	LegacyPolicyGroup = "kyverno.io"
+	PolicyGroup       = "policies.kyverno.io"

+// PolicyMode reads the mode of the engine's policy objects: the legacy kind
+// and the two new kinds. It keeps no state and never calls an API server.
+type PolicyMode struct{}
+
+// Kinds returns the informer kinds of the policy objects: the legacy kind
+// first, then the two new kinds.
+func (PolicyMode) Kinds() []string {
+	return []string{"clusterpolicy", k8scache.KindValidatingPolicy, k8scache.KindMutatingPolicy}
+}
+
+// Mode returns the mode of one policy object, "enforce" or "audit", and false
+// for an object of any other kind. A ValidatingPolicy or a MutatingPolicy of
+// group policies.kyverno.io enforces when spec.validationActions holds Deny.
+// A ClusterPolicy of group kyverno.io enforces when spec.validationFailureAction
+// is Enforce, or when validate.failureAction of one of its rules is. Each kind
+// is read only by its own fields; every other policy of the three kinds
+// audits. Upper and lower case are the same.
+func (PolicyMode) Mode(obj *unstructured.Unstructured) (string, bool) {
+	if obj == nil {
+		return "", false
+	}
+	gv, err := schema.ParseGroupVersion(obj.GetAPIVersion())
+	if err != nil {
+		return "", false
+	}
+	switch {
+	case gv.Group == PolicyGroup && (obj.GetKind() == "ValidatingPolicy" || obj.GetKind() == "MutatingPolicy"):
+		return newKindMode(obj), true
+	case gv.Group == LegacyPolicyGroup && obj.GetKind() == "ClusterPolicy":
+		return legacyKindMode(obj), true
+	}
+	return "", false
+}
+
+// newKindMode: Deny in spec.validationActions enforces.
+func newKindMode(obj *unstructured.Unstructured) string {
+	actions, _, _ := unstructured.NestedSlice(obj.Object, "spec", "validationActions")
+	for _, a := range actions {
+		if s, _ := a.(string); isWord(s, "Deny") {
+			return ModeEnforce
+		}
+	}
+	return ModeAudit
+}
+
+// legacyKindMode: Enforce in spec.validationFailureAction or in the
+// validate.failureAction of any rule enforces.
+func legacyKindMode(obj *unstructured.Unstructured) string {
+	if vfa, _, _ := unstructured.NestedString(obj.Object, "spec", "validationFailureAction"); isWord(vfa, "Enforce") {
+		return ModeEnforce
+	}
+	rules, _, _ := unstructured.NestedSlice(obj.Object, "spec", "rules")
+	for _, ri := range rules {
+		r, ok := ri.(map[string]any)
+		if !ok {
+			continue
+		}
+		if fa, _, _ := unstructured.NestedString(r, "validate", "failureAction"); isWord(fa, "Enforce") {
+			return ModeEnforce
+		}
+	}
+	return ModeAudit
+}
