# ACC-102 — The web application, its database, the seed Job and the CronJob leave the chart

## In plain words

**The problem today.** The access chart still installs the Guacamole web application with its own database, a seed Job that copies connection credentials into that database and a CronJob that rewrites permissions every minute. The access design keeps only the protocol engine and gives the gateway no credential store at all. As long as these parts are installed, the gateway holds a standing administrator model and a second copy of every connection secret.

**What changes.** The chart renders one object, the Application card of its kit slot, and nothing that stores or copies a credential. The sign-on gate in front of the old web application is switched off until the access controller takes its place, so the gateway host does not answer in between.

**Done means:**

- Installing the chart with the values of its kit slot creates one object, the Application of the slot, and no Deployment, Service, Job, CronJob, Secret or network policy, even with the old web application switched on.
- The deleted templates, the database schema and the tests of the removed parts are gone, and each is listed as a deleted path.
- The access guards count no CronJob, no credential copy, no provider name and no image tag in the access chart.
- Gate check ACC-G01 passes when namespace guacamole holds neither the web application nor a database, and fails when either is still there.
- The sign-on gate instance of the old web application is off, and the image build no longer mirrors the web application image or writes values into the chart.

The rest of this ticket is the exact instruction for the model that does the work.
