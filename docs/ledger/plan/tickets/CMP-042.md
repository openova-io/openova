# CMP-042 — ComplianceModel: the per-cluster loader of catalyst-api, and check CMP-G03

## In plain words

**The problem today.** The policy chart renders one compliance model in every cluster, with the checks, the weights and the exempt namespaces of the platform, but the API does not read it. The API still scores every cluster with a built-in fallback in which every check it happens to see weighs the same, so the shown scores ignore the model.

**What changes.** The API reads the model object of each cluster and scores that cluster with it; a cluster without a model shows no score instead of an invented one. The model of a cluster names only the checks whose policy is installed there. A check of the acceptance suite proves in every region that the model is there and that the policies and the API agree with it. It is required on the gate of a Sovereign; the hermetic test pack, which runs the API image of main until this change is pinned, runs it as expected to fail, a marking that a pass does not break.

**Done means:**

- A cluster whose model object named default has loaded is scored with that object's checks, weights and exemptions, and the object of one cluster never scores another.
- A cluster without that object has no score, and its scores give the reason model not loaded.
- A model object that does not load is logged once and the cluster keeps the model it had; a deleted object leaves the cluster with no score.
- The service account of the API may read model objects, nothing else about its permissions changes, and the inventory of custom resources says that the kind is named in Go code.
- The acceptance suite has the required check CMP-G03, which fails when a region has no model, when the policies of a region and its model disagree, or when the API scores without the model.
- A policy that a cluster's values turn off is not in that cluster's model: the local pack, which installs no local-path policy, has a model without that check, and the chart's own values keep every check.
- In the local pack the check CMP-G03 runs as expected to fail, with its reason written in the pack's list of such checks: the pull request stays green whether the check fails there or passes, and a run on a Sovereign still requires it.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
catalyst-api watches the cluster-scoped kind `ComplianceModel` (`compliance.openova.io/v1alpha1`, plural `compliancemodels`), whose definition and one object `default` the policy chart `platform/kyverno-policies/chart` renders (CMP-041, merged). Its compliance read model keeps one model per cluster, loaded from that cluster's object `default`, and scores the cluster with it: the checks, the weights of severity and the exemptions of the policy chart's data files. A cluster without the object has subjects and findings but no score; every posture of it carries the reason `model not loaded`. The built-in fallback model, in which every observed check weighed 1, is gone. The acceptance suite gains check CMP-G03 (`tests/acceptance/sovereign/internal/suite/check_compliance_model.go`): in every region the object exists, the engine's validating policies and the model's `kyverno` checks are the same names, the policies route of the API weighs each check as the model does, and the checks have results. `docs/ledger/gates.yaml` marks CMP-G03 `required`. The object the chart renders names exactly the checks whose policy the same render installs: the template `platform/kyverno-policies/chart/templates/compliance-model.yaml` leaves out a check whose values block is turned off, so a kit that turns a policy off (the local provider pack turns off `forbidLocalPath`) gets a model without that check, and CMP-G03 finds model and policies in agreement there too. CMP-G03 stays `required` in `docs/ledger/gates.yaml`, the gate of a Sovereign, but the job `conformance-local` runs it at `expected-fail`: the local pack installs a change's kit charts from the tree but runs the catalyst-api image that `products/catalyst/chart/values.yaml` pins from main, so step CMP-G03.3 can pass there only after the merge and the next pin. The pack's list of such checks, `tests/acceptance/sovereign/local-pack-expected-fail.txt`, names CMP-G03 with that reason; a run in local reads it (`internal/suite/pack_hold.go`), a run in cloud or in self does not. Expected-fail tolerates both outcomes, so the job stays green when CMP-G03 starts to pass by itself after the pin; a later package of area CMP takes the line out and makes the check required in the pack.

## 3. The model (the law)
1. **One kind of the informer registry.** `k8scache.KindComplianceModel = "compliancemodel"`, GVR `compliance.openova.io/v1alpha1/compliancemodels`, cluster-scoped, `Optional: true` (the definition exists only where the policy Blueprint is installed, so the informer starts when the definition arrives). The compliance aggregator subscribes to it (`ComplianceConfig.SubscribeKinds`).
2. **One model per cluster, from that cluster's object.** `ReadModel.ApplyModel` loads the object named `default` (`ModelObjectName`) of an event with `LoadModel` and makes it the model of the event's cluster only; an object of another name is ignored. A deleted object leaves the cluster with no model. An object that does not load leaves the cluster with the model it had; `Apply` logs one warning line (`the ComplianceModel object did not load`, with the cluster) and changes nothing else. The gauge `catalyst_compliance_model_valid{cluster}` is 1 when the cluster's object loaded and 0 when its last version did not load or it was deleted. After a load or a delete every subject of the cluster is returned, in key order, so that the aggregator publishes their new scores.
3. **No model, no score.** A cluster without a model has `Posture` values with no score and the reason `ReasonModelNotLoaded` (`model not loaded`) in `Rollup.Reason` and `SubjectView.Reason`; `SubjectView.Results` is then empty and `Checks(cluster)` is nil. `DefaultModel()`, the embedded fallback and `withObserved` (one check of weight 1 for every observed check) are deleted. `NewReadModel` takes a warning function instead of a base model: `NewReadModel(warn WarnFunc, r Resolver, adapters ...Adapter)`.
4. **Ownership by the cluster's model.** A finding of the engine (`kyverno`) or of the evaluator is always kept; a finding of any other source is kept only when a check of that cluster's model names that source, and dropped and counted otherwise.
5. **Read-only access.** The ClusterRole `catalyst-api-cutover-driver` (`products/catalyst/chart/templates/clusterrole-cutover-driver.yaml`), bound to the service account `catalyst-api-cutover-driver` that the API's pod runs as, gains one rule: `compliance.openova.io`, `compliancemodels`, `get`, `list`, `watch`. Nothing in the API writes the object; the policy chart is its one writer.
6. **Check CMP-G03.** Four steps, each a failure reason of its own (the row of `tests/acceptance/sovereign/README.md`): the object exists in every region and holds a `kyverno` check, and every check has a weight (its own or its severity's); in every region the validating policy objects of the engine (every `ValidatingPolicy`, and every `ClusterPolicy` with a validate rule) are by name the `kyverno` checks of that region's model; `GET /api/v1/sovereigns/{id}/compliance/policies` lists every `kyverno` check of the first region's model with source `kyverno` and the model's weight, and no `kyverno` policy the model does not weigh; and at least one `kyverno` check has a result in the region's policy reports, a check with none being listed as `no subject`. It reads with `kubectl get` and the API; it writes nothing.
7. **The records.** `docs/ledger/gates.yaml`: CMP-G03 `state: required`, `implementation: tests/acceptance/sovereign/internal/suite/check_compliance_model.go` (`delivered_by: CMP-042` is already there; rule 2 of `scripts/plan.py check-pr` lets a package change only the state and implementation lines of a check). `docs/generated/custom-resources.md`: the row ComplianceModel ends in `yes` (named in Go code), as `scripts/generators/custom-resources.py` writes it once `kinds.go` names `"compliancemodels"`.
8. **The model follows the switches of the policies.** `platform/kyverno-policies/chart/templates/compliance-model.yaml` builds `spec.checks` from `model/checks.yaml`, each entry verbatim and in its order, less every check whose values block `compliancePolicies.<valuesKey>` is a map without a true `enabled`: the one switch each policy template of the chart reads before it renders its policy. One value decides both, so a policy the values turn off is not in the model. Since CMP-086 (merged) the chart renders the policy of `useraccess-boundary` itself (`templates/baseline/25-useraccess-boundary.yaml`, block `useraccessBoundary`), so every one of the 22 checks has a values block; a check whose values key were no block would stay. The exemptions are built from the checks that stay. With the chart's own values every one of the 22 checks is in the model; with the values of the local provider pack (`clusters/_template/providers/local/kit/policy-values.yaml`, `forbidLocalPath.enabled: false`) 21 are, without `forbid-local-path-storage`. The chart test `platform/kyverno-policies/chart/tests/model-render.sh` holds it (assertion 6 and two defect copies): the model's checks are the names of the validating policies of the same render, with no check of another chart added. CMP-G03 is not changed.
9. Not here: no data file, policy, schema or value of the policy chart changes (CMP-041 merged them; CMP-068 adds a check); no version line of a `Chart.yaml`; no new Python; no change to a live system.
10. **Required on the gate, held in the pack.** `tests/acceptance/sovereign/local-pack-expected-fail.txt` is the list of the checks that the run in local (the local provider pack of `conformance-local`) holds at `expected-fail`: one line per check, its identifier, a space and the reason; `#` lines and blank lines are skipped. It holds one line, CMP-G03, whose reason says that the pack runs the catalyst-api image pinned from main, which holds this loader only after the merge and the next pin, and that a later package of area CMP makes the check required in the pack. `HoldForPack` (`tests/acceptance/sovereign/internal/suite/pack_hold.go`) applies it in `Execute` after the manifest is loaded (`runner.go`) and prints one line per hold: `<id> runs at expected-fail in the local pack (<file>): <reason>`. It holds nothing for a run in cloud or in self and reads no file there, and a missing file holds nothing. A line without a reason, or a check that is not in the manifest, is not `required`, does not list `local` in `runs_in`, or is named twice, stops the run with `ErrManifest` (exit code 2, no record). Expected-fail is the marking because it tolerates both outcomes: `Run.Finalize` (`internal/suite/result.go`, the loop "A required check must pass") fails a run only on a required check that does not pass, so a held check that fails or passes leaves the record PASS; `scripts/acceptance-gate.py` `validate-record` (pass rule 5) also reads only required checks, and the job's last step needs result PASS. No rule fails a run on an expected-fail check that passes, so the pin that makes CMP-G03 pass cannot turn main red. `docs/ledger/gates.yaml` keeps CMP-G03 `required`; the check itself is not changed.

+func (c complianceModelCheck) readModel(ctx context.Context, r kube.Region) (regionModel, error) {
+	out, err := c.kubectl(r, ctx, nil, "get", modelResource, modelObject, "-o", "json")
+	if err != nil {
+		return regionModel{}, fmt.Errorf("%s: %s %s: %w", r.ID, modelResource, modelObject, err)

+		return regionModel{}, fmt.Errorf("%s: %s %s: %w", r.ID, modelResource, modelObject, err)
+	}

+			continue
+		}

+		}
+		m.weights[chk.Str("id")] = int(w)
+	}
+	if len(m.weights) == 0 {

+// conformance-local) holds at expected-fail. The pack installs the kit charts
+// of a change from the tree, but runs the images that the kit pins from main;
+// a check that proves a change to such an image passes there only after the
+// merge and the next pin.
+const PackHoldFile = "tests/acceptance/sovereign/local-pack-expected-fail.txt"

+// Hold is one line of PackHoldFile: a check and the reason it is held.
+type Hold struct {
+	ID     string
+	Reason string
+}
+
+// HoldForPack sets to expected-fail, in m, every check that PackHoldFile
+// under repoRoot names, when r is RunInLocal; a run in cloud or in self holds
+// nothing and reads no file, so the gate of a Sovereign keeps every check at
+// its state of the manifest. Expected-fail tolerates both outcomes: a held
+// check that fails does not fail the run, and one that passes is recorded PASS
+// and fails nothing (Run.Finalize fails a run on a required check only).
+//
+// A line is a check identifier, a space and the reason; blank lines and lines
+// that start with # are skipped. A missing file holds nothing. A line without
+// a reason, a check that is not in m, is not required, does not list local in
+// runs_in, or is named twice is an error that wraps ErrManifest: the run stops
+// and writes no record. HoldForPack returns the holds in the order of the file.
+func HoldForPack(m *Manifest, r RunIn, repoRoot string) ([]Hold, error) {
+	if r != RunInLocal {
+		return nil, nil
+	}
+	b, err := os.ReadFile(filepath.Clean(filepath.Join(repoRoot, filepath.FromSlash(PackHoldFile))))
+	if errors.Is(err, fs.ErrNotExist) {
+		return nil, nil
+	}
+	if err != nil {
+		return nil, fmt.Errorf("%w: %v", ErrManifest, err)
+	}
+	holds := []Hold{}
+	sc := bufio.NewScanner(bytes.NewReader(b))
+	for n := 1; sc.Scan(); n++ {
+		line := strings.TrimSpace(sc.Text())
+		if line == "" || strings.HasPrefix(line, "#") {
+			continue
+		}
+		id, reason, _ := strings.Cut(line, " ")
+		reason = strings.TrimSpace(reason)
+		at := fmt.Sprintf("%s line %d", PackHoldFile, n)
+		i := slices.IndexFunc(m.Checks, func(e ManifestCheck) bool { return e.ID == id })
+		switch {
+		case reason == "":
+			return nil, fmt.Errorf("%w: %s: %s has no reason", ErrManifest, at, id)
+		case slices.ContainsFunc(holds, func(h Hold) bool { return h.ID == id }):
+			return nil, fmt.Errorf("%w: %s: %s is named twice", ErrManifest, at, id)
+		case i < 0:
+			return nil, fmt.Errorf("%w: %s: %s is not a check of the manifest", ErrManifest, at, id)
+		case m.Checks[i].State != StateRequired:
+			return nil, fmt.Errorf("%w: %s: %s is %s, and only a required check is held", ErrManifest, at, id, m.Checks[i].State)
+		case !slices.Contains(m.Checks[i].RunsIn, string(RunInLocal)):
+			return nil, fmt.Errorf("%w: %s: %s does not run in local", ErrManifest, at, id)
+		}
+		m.Checks[i].State = StateExpectedFail
+		holds = append(holds, Hold{ID: id, Reason: reason})
+	}
+	if err := sc.Err(); err != nil {
+		return nil, fmt.Errorf("%w: %s: %v", ErrManifest, PackHoldFile, err)
+	}
+	return holds, nil
+}

+# The expectations of the local provider pack: gate checks that the run in
+# local of this suite (the job conformance-local) holds at expected-fail
+# although docs/ledger/gates.yaml has them required. They stay required on the
+# gate of a Sovereign: a run in cloud or in self reads no such file. One check

+# (internal/suite/pack_hold.go) and stops with no record when a line has no

+# fails never fails the run, and one that passes is recorded PASS and fails
+# nothing (Run.Finalize in internal/suite/result.go fails a run on a required

+# green; the package that makes it required in the pack takes its line out.

+# tree, but runs the images that the kit pins from main (the image tags of
+# products/catalyst/chart/values.yaml). A check that proves a change to such
