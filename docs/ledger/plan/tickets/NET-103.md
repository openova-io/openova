# NET-103 — Gate check NET-G18: full-size transfers between two workers over the node network, in each region and across regions

## In plain words

**The problem today.** When the MTU that Cilium runs with is below the MTU of the node's network, every encrypted packet between two workers that is larger than it is dropped by the receiving host without a word. Small requests still pass, so an install looks healthy while image copies between nodes stall for minutes. No acceptance check moves a full-size transfer between two workers, and the control plane, which is outside node encryption, hides the defect.

**What changes.** A new required gate check starts two probe Pods on the host network in each region, compares the MTU of cilium_host with the node interface's MTU, and fetches more than one full-size packet from the other worker, in each region and across regions, after the same fetch from the control-plane node.

**Done means:**

- A gate run fails NET-G18 when, on a worker, cilium_host has a smaller MTU than the interface that holds the node's address, naming the node and both values.
- A gate run fails NET-G18 when a fetch of at least 16384 bytes from another worker's Hubble metrics listener does not end within 5 seconds, naming the source, the destination, the exit code and the bytes.
- A pair whose fetch from the control-plane node fails is reported as not measured and fails, so a listener that does not answer is never read as a pass.
- A region with fewer than two Ready, schedulable workers fails as not measured.
- The probe Pods run on the host network as an unprivileged user with a read-only root, no capability, no volume, no token and no Service, in a namespace of their own that the check deletes at the end.
- The tests of the check run without a cluster and fail for each rule that is broken.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Gate check NET-G18 "Full-size transfers between workers over the node network" exists in `tests/acceptance/sovereign/internal/suite/check_network_full_size.go` and is `required` in `docs/ledger/gates.yaml`. On every install it runs in the cloud: in each region it chooses two workers, starts one probe Pod on the host network of each, compares the MTU of `cilium_host` with the MTU of the interface that holds the node's InternalIP, and fetches `http://<InternalIP>:9965/metrics` (the Hubble metrics listener of the Cilium agent) of the other worker with at least 16384 bytes within 5 seconds, both ways, each after the same fetch from the control-plane node of the destination's region; the first chosen workers of every two regions do the same across the regions. It deletes its namespace at the end and changes nothing of the install. Its tests need no cluster and run on every pull request.

## 3. The model (the law)
1. **The files are fixed.** The change is the block `NET-103.patch` at the end of field 20, applied by work step 4, and the command of work step 7. The patch creates `check_network_full_size.go` and `check_network_full_size_test.go` and changes `tests/acceptance/sovereign/internal/kube/kube.go` (its comment) and `tests/acceptance/sovereign/README.md`; work step 6 fixes the four files by their checksums. Work step 7 changes two lines of the entry NET-G18 of `docs/ledger/gates.yaml`.
2. **The workers (step 1 of each region).** The check reads the nodes of the region (`kubectl get nodes -o json`) and sorts them by name. A worker is a node that is Ready (condition `Ready` is `True`), has an IPv4 InternalIP, has no label `node-role.kubernetes.io/control-plane` (any value) and is not unschedulable. The first two by name are chosen. Fewer than two fail the region as not measured, before anything is created. The control node of the region is the first Ready node by name that carries that label and has an IPv4 InternalIP; a region without one fails. The value of `mtu` in ConfigMap `kube-system/cilium-config` is read once as evidence; a failed read is recorded as `unread` and fails nothing.
3. **The probe Pods.** In a namespace `net-path-<run>` of its own (one run identifier for every region) the check creates `probe-0` and `probe-1`, one on each chosen worker (`spec.nodeName`), and waits up to 180 seconds for both to be Ready. Each Pod: image `secProbeImage` (`sec_probe.go` line 21), `hostNetwork: true`, `runAsUser` and `runAsGroup` 65534, `runAsNonRoot`, `readOnlyRootFilesystem`, `allowPrivilegeEscalation: false`, every capability dropped, no volume, `automountServiceAccountToken: false`, tolerations `Exists`, a command that only waits 900 seconds. No Service of any kind is created. The Dialer of `check_policy_dials.go` is not used: its Pods are on the Pod network, and the defect is host to host.
4. **The MTU (one step per worker).** `kubectl exec` runs the script of the check with `sh -s -- /sys/class/net mtu <InternalIP>`: it names the interface that holds the address (`ip -o -4 addr show`) and prints its MTU and the MTUs of `cilium_host` and `cilium_wg0` from `/sys/class/net/<device>/mtu`. The step fails unless an interface holds the address and the MTU of `cilium_host` equals the MTU of that interface; the reason names the node and both values. `cilium_wg0` and `cilium-config` are evidence only.
5. **The transfers (one step per direction).** A GET is `sh -s -- /sys/class/net get <address> 9965 5`: busybox `wget -q -O - http://<address>:9965/metrics` under `timeout 5`; the script prints the exit code, the bytes received and the start and end of `/proc/uptime`. A GET passes with exit code 0 and at least 16384 bytes. In each region worker 0 fetches from worker 1 and worker 1 from worker 0. Then, for every ordered pair of two regions, the first chosen worker of the one fetches from the first chosen worker of the other. Before each such GET, the same GET of the control node of the destination's region is made; when it fails the step fails as not measured, naming the control node, and the worker is not fetched. The evidence of a step holds both GETs: source, destination, address, exit code, bytes and seconds.
6. **Order and cleanup.** The steps of a region start only when its Pods are Ready; the steps across regions only when the Pods of both regions are Ready. A namespace that was created is deleted at the end (`--wait=false --ignore-not-found`), also when a step failed. The check writes with `kubectl create`, `wait` and `delete` only.
7. **The manifest entry.** In `docs/ledger/gates.yaml` the entry NET-G18 changes `state` from `not-built` to `required` and gains `implementation: tests/acceptance/sovereign/internal/suite/check_network_full_size.go`. Its `asserts`, `title`, `runs_in` (`[cloud]`) and `delivered_by` stay as the plan wrote them.
8. **Nothing is deleted.** Check NET-G08 (`check_network_registry.go`) stays as it is: it compares the registry with `cilium-config`, two copies of the same number, and is not a proof of the path.

+// Check NET-G18, full-size transfers between workers over the node network.
+//
+// Between two workers every packet goes through node-to-node encryption, and
+// the receiving host hands the decrypted packet to cilium_host. When the MTU
+// that Cilium runs with is below the MTU of the node's interface, every
+// packet larger than it is dropped there without a word: small requests pass,
+// a transfer of more than one full-size packet never ends. The control plane
+// opts out of node encryption, so a transfer from it passes either way.
+//
+// In every region the check chooses two workers: Ready, schedulable, without
+// the label node-role.kubernetes.io/control-plane, the first two by name;
+// fewer than two fail the region as not measured. In a namespace
+// net-path-<run> of its own it starts one probe Pod on each, on the host
+// network, as user 65534 with a read-only root, no capability, no volume and
+// no token; it creates no Service. Then, with `kubectl exec`:
+//
+//	(a) on each worker the interface that holds the node's InternalIP and
+//	    its MTU, and the MTU of cilium_host, are read from /sys/class/net;
+//	    they must be equal (cilium_wg0 and cilium-config's mtu are evidence);

+//	    Ready control-plane node by name of the destination's region must

+//	    fetched;
+//	(c) the first chosen worker of every region does the same with the first
