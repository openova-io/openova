# NET-133 — A local-affinity decision on every global Service

## In plain words

**The problem today.** Thirteen chart files publish a Service to the mesh between regions without saying how traffic should prefer a region. Each of these Services has its workload in one region only, but nothing in the file says so. The network guard for global Services therefore still allows them on its list of old offenders.

**What changes.** Each of these Services carries the line that records that its backend runs in one region. The guard's list of old offenders keeps only the three files under the frozen topology paths.

**Done means:**

- Each of the thirteen files has the line single-region backend directly above every global-Service annotation.
- No annotation value changes: the rendered objects of the six charts are the same as before, apart from the new comment lines.
- The network guard passes, and its list of old offenders for global Services names only the two region-layout files and the Continuum Service file.
- A new global Service without a locality decision outside those three files turns the network guard red.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
Every manifest file under `platform`, `products`, `clusters` and `core` that sets the Cilium annotation `service.cilium.io/global: "true"` also states how the Service's traffic is placed between regions, except three files under frozen topology paths. ## 3. The model (the law)
1. The rule. A global Service whose backends run in more than one region gets `service.cilium.io/affinity: "local"`, so that each region prefers its own backends. A global Service whose backends run in exactly one region gets the comment line `# single-region backend` directly above its `service.cilium.io/global` line. A Service without a selector is a stub that receives the backends of one peer region, so it counts as a single-region backend.
2. All thirteen files of this ticket are single-region backends. The facts for each are in field 4. So every one of them gets the comment, and none gets an affinity annotation.
3. The comment is placed directly above every line `service.cilium.io/global: "true"` of each file, with the same indentation as that line. A file with three such Services gets three comment lines.
4. No annotation, label, selector, port or other value changes. The only added lines are comment lines.
5. The 13 `G6` lines of these files leave `scripts/network-guards-baseline.tsv` in the same change. No other line of that file changes.
6. Three files are skipped and keep their `G6` baseline lines: `clusters/_template/sovereign-region/multi-region-follower/gitea-writer-stub.yaml`, `clusters/_template/sovereign-region/multi-region/gitea-region-service.yaml` and `products/continuum/chart/templates/service.yaml`. They lie under the frozen topology paths (field 11).
7. No chart `version:` line, no pin and no `blueprint.yaml` changes. CI writes versions after the merge.
8. This ticket deletes no file.
