# SVC-170 — Contract C1: class and lifecycle on every Blueprint, with their readers

## In plain words

**The problem today.** Every Blueprint carries up to five free-text classifiers that disagree with each other, and nothing acts on them. Nothing says whether a Blueprint is an application a person uses or cluster plumbing, or whether it is still offered: an Organization can install the platform's own plumbing from the catalogue, and a retired Blueprint can still be installed.

**What changes.** Every Blueprint says one class and one lifecycle, taken from a fixed table, and the old classifiers are gone. The catalogue, the install route and the Catalog page read the class and the lifecycle, and a file that breaks the format fails its pull request.

**Done means:**

- Every Blueprint file says its class and its lifecycle, and none carries a card category, a card family or a category, tier or section label.
- Cluster plumbing is never listed in the catalogue, and an Organization that tries to install it is refused.
- A deprecated Blueprint cannot be installed by anyone, and the Applications that exist keep running.
- A Blueprint file that lacks its class or its lifecycle, or carries an old classifier, turns its pull request red.
- A Blueprint can be marked supported only while the newest counting gate record shows its function test passed.
- The Catalog page shows each card's class and an Experimental or Deprecated badge.

The rest of this ticket is the exact instruction for the model that does the work.

+// Refusal is an Application create refused because of what its Blueprint is
+// (contract C1: spec.class and spec.lifecycle), before anything is written.
+type Refusal struct {
+	Status  int
+	Code    string
+	Message string
+}
+
+// ClassLifecycleRefusal returns the refusal of a create of an Application of
+// the Blueprint named blueprint, or nil when the create may go on:
+//
+//   - class platform-component: only a sovereign-admin installs it
+//     (403 class-not-installable);
+//   - lifecycle deprecated: no new Application (409 blueprint-deprecated);
+//     the Applications that exist keep running.
+//
+// An empty class or lifecycle (an object written before contract C1) is not
+// refused: the definition's defaults are application and experimental.
+func ClassLifecycleRefusal(blueprint, class, lifecycle string, sovereignAdmin bool) *Refusal {
+	switch {
+	case class == "platform-component" && !sovereignAdmin:
+		return &Refusal{Status: http.StatusForbidden, Code: "class-not-installable",
+			Message: fmt.Sprintf("Blueprint %s is a platform component; only a sovereign-admin installs it", blueprint)}
+	case lifecycle == "deprecated":
+		return &Refusal{Status: http.StatusConflict, Code: "blueprint-deprecated",
+			Message: fmt.Sprintf("Blueprint %s is deprecated; no new Application may be created from it", blueprint)}
+	}
+	return nil
+}
