# NET-041 — Remove the firewall claims from the storefront and the console

## In plain words

**The problem today.** The platform installs a web application firewall that is attached to no listener, so it filters nothing. Yet the storefront's stand-in list of add-ons offers it, the console's setup wizard shows it as a component every Sovereign gets, and the console's product pages say that it filters every public request. A customer or an operator reading these screens is promised a protection that does not exist.

**What changes.** The firewall add-on leaves the storefront's stand-in list and the two unit-test copies of the catalog list. The console no longer shows a firewall card, preselects it, or describes request filtering in its networking texts, and three code comments stop naming the firewall.

**Done means:**

- When the storefront cannot read its add-on list, the list it shows instead has no web application firewall.
- The setup wizard of the console shows no firewall card, does not preselect one, and its networking family no longer mentions a firewall.
- The console's networking product texts say nothing about a firewall or about filtering requests.
- None of the twelve changed files names the Coraza firewall.
- The storefront unit tests, the console type check and unit tests, and the catalog service tests pass on the pull request.

The rest of this ticket is the exact instruction for the model that does the work.
