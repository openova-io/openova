# FND-032 — Record version 2 and the check registry

## In plain words

**The problem today.** The acceptance suite can run only its five built-in journeys. A new automatic check cannot be added without editing files that every other check shares. The record of a run does not say which release candidate was tested, who produced the record, or which checks ran. The tool that guards the list of checks accepts a check file that never registers its check.

**What changes.** Each check becomes one file that registers itself. The suite runs the checks that the list of checks selects and writes one result for each into a record of version 2. The guard tool refuses a check file that does not register its check.

**Done means:**

- A check is added to the suite by adding one file. No shared file of the suite changes for it.
- A run that is given the list of checks stops before it does anything when a selected check has no code.
- A check that needs something the run did not declare is skipped and is not run.
- A required check that does not pass makes the run fail. A check that is expected to fail does not.
- The record of a run names the candidate, where the run ran, who produced it, and one result for each check.
- The guard tool refuses a check file that does not register its check.
- Records of the older version are still read.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite under `tests/acceptance/sovereign/` has a check registry. A gate check is one file `check_<name>.go` that registers itself; adding one changes no other file of the suite. When a run is given the gate manifest as JSON (`--manifest`), it selects the registered checks that the manifest asks for, runs them after the journeys, and writes one result for each into the record. The record has schema `openova.io/acceptance-sovereign/v2`: it also says where the run ran, which capability flags it declared, which candidate it tested and who produced it. `scripts/acceptance_record.py` reads records of both versions. `scripts/acceptance-gate.py validate` refuses a manifest entry whose check file does not register the check. A run without `--manifest` drives the same journeys as before and runs no check.

## 3. The model (the law)
1. The nine files of field 14 are the result of the embedded patch `FND-032.patch`, byte for byte. Work step 5 states the checksum of each.
2. The registry is the file `tests/acceptance/sovereign/internal/suite/registry.go`, package `suite`. It declares these exported names and no other: the type `RunIn` with the constants `RunInLocal` (`local`), `RunInCloud` (`cloud`) and `RunInSelf` (`self`); the constants `ManifestSchema` (`openova.io/gates/v1`), `StateExpectedFail` and `StateRequired`; the error `ErrManifest`; the types `ManifestCheck`, `Manifest`, `Candidate`, `DeploymentInfo`, `CheckContext`, `StepRecorder` and `Check`; the functions `RegisterCheck`, `RegisteredChecks`, `LoadManifest` and `SelectChecks`. `DeploymentInfo` has one field, `ID`.
3. A check implements `Check`: `ID() string` returns the manifest identifier, and `Run(ctx, cc, rec)` performs the check and records at least one step through `rec`. `RegisterCheck` panics when an identifier is registered twice. `RegisteredChecks` returns the checks sorted by identifier.
4. `LoadManifest(path)` reads the JSON that `python3 scripts/acceptance-gate.py export` prints. It returns an error for a file that is missing, that is not JSON, or whose `schema` is not `openova.io/gates/v1`.
5. `SelectChecks(m, r)` returns, in the order of the manifest, the registered check of every entry whose `state` is `expected-fail` or `required`, whose `runs_in` lists `r`, and that is not `destructive` when `r` is `self`. When such an entry has no registered check it returns the error `gate manifest: no registered check for <id>`. An entry in state `not-built` is never selected and needs no registered check.
6. Every error of `LoadManifest` and `SelectChecks` wraps `ErrManifest`. The suite selects the checks before it sends its first request. On such an error the binary prints `FATAL: gate manifest: ...` on standard error, exits with code 2 and writes no record.
7. The selected checks run after the discovery block and the journeys, in the order of the manifest. `CheckContext.Prior` holds the steps recorded before the first check started. For each selected check exactly one entry is appended to the record field `checks`:
   - When one of the entry's `needs` is not among the capability flags of the run, the check is not run. Its status is `SKIP` and its reason is `the run does not declare <flags>`.
   - Otherwise, when the discovery block failed, the check is not run. Its status is `SKIP` and its reason is `discovery (D0) failed`.
   - Otherwise the check runs. An error returned by `Run` is recorded as a failed step. A check that records no step gets a failed step with the text `the check recorded no step`.
   - The status is `FAIL` when one step of the check failed, and the reason is the error of the first failed step. Otherwise it is `SKIP` when one step was skipped, with that step's reason. Otherwise it is `PASS`.
   - Every step of a check carries the check identifier in the step field `journey`.
8. The record. `schema` is `openova.io/acceptance-sovereign/v2`. This package adds these fields and no other: `run_in` (`local` or `cloud`), `capabilities` (a list of strings, empty when none was declared), `candidate` (`id` and `commit`), `producer` (`kind`, and for a workflow `workflow`, `run_id` and `run_attempt`) and `checks` (a list, empty when no check was selected; each entry has `id`, `state_at_run`, `status`, and `reason` when the status is not `PASS`). Every field of version 1 stays, with the same name and the same meaning.
   - `candidate.id` is the value of `--candidate-id`. `candidate.commit` is the output of `git rev-parse HEAD` in the directory of `--repo-root`, or empty when that command fails.
   - `producer.kind` is `workflow` when the environment variable `GITHUB_ACTIONS` is `true`, else `manual`. For a workflow, `workflow` is the file name in `GITHUB_WORKFLOW_REF` (the text between the last `/` and the `@`), `run_id` is `GITHUB_RUN_ID` and `run_attempt` is `GITHUB_RUN_ATTEMPT` as a number.
   - The record object `provision` of the schema in `scripts/acceptance-gate.py` is not written by this package (field 11).
9. The result. `result` is `PASS` only when the conditions of version 1 hold (every step of the discovery block passed and every requested journey passed) and every check in state `required` has status `PASS`, or status `SKIP` because the run did not declare its `needs`. A check in state `expected-fail` never changes the result.
10. The command line gains five flags, each with an environment variable as its default: `--run-in` (`ACCEPT_RUN_IN`, default `cloud`), `--manifest` (`ACCEPT_MANIFEST`, default empty), `--candidate-id` (`ACCEPT_CANDIDATE_ID`, default empty), `--repo-root` (`ACCEPT_REPO_ROOT`, default `.`) and `--capabilities` (`ACCEPT_CAPABILITIES`, default empty, a comma list). A value of `--run-in` other than `local` or `cloud` prints `--run-in must be local or cloud` and exits with code 2. With an empty `--manifest`, and in the mode `discover`, no manifest is read and no check runs.
11. `scripts/acceptance_record.py` accepts a record whose `schema` is version 1 or version 2 and refuses every other value. Its constant `SCHEMA` keeps the version 1 string, because two other scripts read it.
12. `scripts/acceptance-gate.py`, rule 3, gains the registration clause. It applies to an `implementation` path that is a Go file under `tests/acceptance/sovereign/` and whose file name starts with `check_`. Such a file must hold, outside its comment lines (lines whose first characters after the indentation are `//`), the text `RegisterCheck(` and the identifier of the check in double quotes. When it does not, `validate` prints the failure line `rule 3: <id>: implementation <path> does not register the check: it needs RegisterCheck( and "<id>"`. A Go file of the suite whose name does not start with `check_` is not asked for a registration. The self-test has 101 cases.
13. The module `tests/acceptance/sovereign` keeps using the Go standard library only. Its `go.mod` is not changed.
14. `tests/acceptance/sovereign/internal/suite/journeys.go`, `match.go` and `discover.go` are not changed.
15. This ticket deletes no file. The only text it removes without a replacement of the same meaning is the comment `# A Go file of the suite. Package FND-032 adds the registration clause here.` in `scripts/acceptance-gate.py`.

+func (c checkRecorder) Skip(id, name, reason string) {
+	now := time.Now().UTC()
+	c.r.run.Steps = append(c.r.run.Steps, &Step{Journey: c.id, ID: id, Name: name, Status: Skip,
+		StartedAt: now, FinishedAt: now, Error: reason})

+// runChecks records one result for every selected check, in manifest order.
+// A check whose needs the run did not declare is skipped and not run. When
+// discovery failed no check is run: each is recorded SKIP with that reason.
+func (r *runner) runChecks(ctx context.Context, m *Manifest, checks []Check, cc *CheckContext, discovered bool) {
+	cc.Prior = append([]*Step(nil), r.run.Steps...)
+	for _, c := range checks {
+		e := m.entry(c.ID())
+		res := CheckResult{ID: e.ID, StateAtRun: e.State, Status: Pass}
+		rec := checkRecorder{r: r, id: e.ID}
+		first := len(r.run.Steps)
+		missing := []string{}
+		for _, n := range e.Needs {
+			if !cc.Caps[n] {
+				missing = append(missing, n)
+			}
+		}
+		switch {
+		case len(missing) > 0:
+			res.unmet = true
+			rec.Skip("-", "check not run", "the run does not declare "+strings.Join(missing, ", "))
+		case !discovered:
+			rec.Skip("-", "check not run", "discovery (D0) failed")
+		default:
+			if err := c.Run(ctx, cc, rec); err != nil {
+				rec.Step("-", "the check could run", func(Evidence) error { return err })
+			}
+			if len(r.run.Steps) == first {
+				rec.Step("-", "the check recorded a step", func(Evidence) error {
+					return errors.New("the check recorded no step")
+				})
+			}
+		}
+		for _, s := range r.run.Steps[first:] {
+			switch {
+			case s.Status == Fail && res.Status != Fail:
+				res.Status, res.Reason = Fail, s.Error
+			case s.Status == Skip && res.Status == Pass:
+				res.Status, res.Reason = Skip, s.Error
+			}
+		}
+		r.run.Checks = append(r.run.Checks, res)
+	}
