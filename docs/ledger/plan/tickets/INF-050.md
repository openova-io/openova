# INF-050 — Install kured

## In plain words

**The problem today.** The platform has a chart that coordinates node reboots and owns the node's update settings, but no Sovereign installs it. Nodes that need a reboot after a security update are therefore not rebooted in a controlled way.

**What changes.** Every Sovereign's bootstrap kit installs kured in the namespace kube-system right after the network layer. kured then reboots one node at a time, drained, between 00:30 and 22:00 UTC, and a Sovereign can later move that span with three variables.

**Done means:**

- The bootstrap kit has a slot 04b that installs the chart bp-kured 0.1.0 into kube-system after Cilium.
- Rendered with the slot's values, the chart reboots only between 00:30 and 22:00 UTC, pulls its node-patch image through the platform's registry proxy and contains no NodePort.
- The slot is listed in the kit, in the placement table and in the dependency list, and the generated slot and component lists show it.
- The slot carries the foundation ring label, so the service-model ratchet does not rise.
- The slot's chart version equals the chart's own version.

The rest of this ticket is the exact instruction for the model that does the work.

   Flux gives the value of a key when the Sovereign's variables set it and it is not empty, else the default after `:=`. The defaults equal the chart's defaults, so a Sovereign without the keys renders the chart's span. Flux writes the object out again as YAML before it substitutes, so the quotes of the source are not kept (`scripts/check-kit-render-equivalence.sh` lines 20 to 23 model that). The values are strings all the same: Go YAML, which Flux and Helm read with, has no base-60 numbers, so it reads an unquoted `00:30` and `22:00` as text (measured with Helm, field 4). The image is the reference that 43 lines in 23 charts under `platform/` use for their hook Jobs (field 4), among them `platform/kyverno/chart/values.yaml` line 471. kured's own image stays the chart's default.
5. **The ring label.** `foundation`. The guard `scripts/check-service-model.py` counts slot files whose HelmRelease has no ring label (`G8.slots-without-ring`, baseline 68) and refuses a rise; slot 15b carries the same label. kured runs on every cluster and is never switched off.
