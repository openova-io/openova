# SEC-212 — First-party proof: the auth service reads its refresh-token signing secret from a mounted file

## In plain words

**The problem today.** The auth service takes its refresh-token signing secret from an environment variable that a Secret object fills, and the chart creates that Secret with a random value on install. The value can be read by anyone who can read Secrets in the namespace. No first-party service shows yet how a service reads a secret that is mounted as a file, and twelve later packages wait for that pattern.

**What changes.** The value is created once in OpenBao and reaches the auth service as a mounted file, which the service reads at start through a small tested package that the later services copy. The Secret object keeps its other keys and loses this one.

**Done means:**

- The auth service starts only when the file of its refresh-token signing secret is mounted and not empty, and it no longer reads the environment variable.
- The package that reads a mounted secret is tested on a missing file, an empty file, a trailing newline and a file that the driver rotated.
- The chart renders the mounted volume on the auth Pod, the object that names the OpenBao path, and the Job that creates the value in the namespace of the auth service, and no rendered document names the old key.
- Raising the epoch of the value moves the Pod annotation, the object and the plan of the Job to the new path together, so the Pod rolls onto the new value.
- The network policy in front of OpenBao admits the namespace of that Job, on a Sovereign of one region as well.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The auth service of the Organization back end (`core/services/auth`, Deployment `auth` in namespace `org-services`) reads its refresh-token signing secret from the file `/var/run/secrets/openova/jwt-refresh-secret`, which the Secrets Store CSI driver mounts from OpenBao. The value is written once, create-only, by the birth Job of `platform/secrets-lib` that the umbrella chart renders in `org-services`; no Secret object holds it. The service reads the file through package `secretfile`, the first copy of the small reader that each later Go module copies into its own `internal/secretfile`. This is the first-party proof of the mounted secret: one writer (the birth Job), one reader (the auth service). Twelve later packages copy the pattern (SEC-221, SEC-231 to SEC-236, SEC-242, SEC-244 to SEC-247).

## 3. The model (the law)
1. One writer, one reader. The writer is the birth Job of `platform/secrets-lib`, from `orgServices.generatedSecrets.jwt-refresh-secret` of `products/catalyst/chart/values.yaml` (`delivery: mounted`, `scope: sa`, `serviceAccount: auth`, `length: 64`, `sharedAcrossRegions: false`, `epoch: 1`), rendered by `templates/org-services/org-services-secrets.yaml` with `"namespace" "org-services"` and no peers: each region births its own value, as the per-region random it replaces did. The reader is `core/services/auth/main.go`, through the volume `openova-secrets` and SecretProviderClass `auth` of `templates/org-services/auth.yaml`.
2. Key `JWT_REFRESH_SECRET` and its `randAlphaNum 64` site leave Secret `org-services-secrets`. The Secret keeps its other ten keys, their `lookup` persistence, the fallback to the legacy `sme/sme-secrets` and the reflector mirror into `catalyst-system`. The random-secrets baseline of that template goes from 5 to 4.
3. The value never becomes a Secret object: SecretProviderClass `auth` has no `secretObjects`. The driver logs in to OpenBao as role `workload` with the auth Pod's own token (audience `openbao`), which reads only `mounted/data/org-services/sa/auth/*`.
4. The auth Pod carries the OpenBao path of the value as the annotation `secrets.openova.io/jwt-refresh-secret`. Raising the epoch moves the annotation, the object's path and the birth plan line to the new path together, so the Pod rolls onto the new value.
5. The chart refuses at render a value the auth Pod cannot read as a file: delivery other than `mounted`, scope other than `sa`, a service account other than `auth`.
6. Package `secretfile` (`core/services/auth/internal/secretfile`) has `Dir` (default `/var/run/secrets/openova`, tests may change it), `Read(name)`, `ErrNotMounted` and `ErrEmpty`. `Read` opens the file on every call, so a call after a rotation returns the new value; it drops the line ends at the end; it refuses a name that is not one plain file name. There is no `ReadOrEnv`: this value needs no migration window (point 8), and a later package that needs one adds it to its own copy.
7. The service exits at start with a message when the file is missing or empty. The variable `JWT_REFRESH_SECRET` is no longer read.
8. No session ends. No handler signs with `Handler.JWTRefreshSecret`: a refresh token is a random UUID stored as its SHA-256 hash (`core/services/auth/handlers/handlers.go` lines 627 to 646), and access tokens are signed with `JWT_SECRET`, which does not change. The new value on the delivery that carries this package therefore ends no refresh session.
9. The birth Job reaches OpenBao at `openbao.openbao.svc:8200`. NetworkPolicy `openbao-default-deny` of `platform/plane-isolation` admits namespace `org-services`, because bp-openbao's peer trust admits a birth Job only on a Sovereign of more than one region. SEC-250 (pull request 8989) admitted `cert-manager` the same way, with a chart test of its own; this package does the same with `tests/openbao-birth-ingress.sh`.
10. No new Python, no change to a live system, and no chart version line is touched.

+// Package secretfile reads a secret that the Secrets Store CSI driver mounts as a
+// file: one file per value, named by the objectName of the pod's SecretProviderClass,
+// under the pod's mount directory (/var/run/secrets/openova).
+//
+// The first copy lives in core/services/auth (SEC-212). Each Go module that reads a
+// mounted secret holds its own copy under internal/secretfile; there is no shared
+// module for these few lines.
+package secretfile
+
+import (
+	"errors"
+	"fmt"
+	"io/fs"
+	"os"
+	"path/filepath"
+	"strings"
+)
+
+// Dir is the mount directory. Tests may change it.
+var Dir = "/var/run/secrets/openova"
+
+// ErrNotMounted means the file of the value does not exist: the volume is not
+// mounted, or it does not hold that object.
+var ErrNotMounted = errors.New("secretfile: not mounted")
+
+// ErrEmpty means the file exists and holds nothing but line ends.
+var ErrEmpty = errors.New("secretfile: empty")
+
+// Read returns the content of Dir/<name> without the line ends at its end. It opens
+// the file on every call, so a call after the driver rotated the file returns the new
+// value. A name that is not one plain file name is refused.
+func Read(name string) (string, error) {
+	if name == "" || name != filepath.Base(name) || strings.HasPrefix(name, ".") {
+		return "", fmt.Errorf("secretfile: %q is not a file name", name)
+	}
+	path := filepath.Join(Dir, name)
+	b, err := fs.ReadFile(os.DirFS(Dir), name)
+	if errors.Is(err, fs.ErrNotExist) {
+		return "", fmt.Errorf("%w: %s", ErrNotMounted, path)
+	}
+	if err != nil {
+		return "", fmt.Errorf("secretfile: %w", err)
+	}
+	v := strings.TrimRight(string(b), "\r\n")
+	if v == "" {
+		return "", fmt.Errorf("%w: %s", ErrEmpty, path)
+	}
+	return v, nil
+}
