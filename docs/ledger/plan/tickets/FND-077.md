# FND-077 — The flight sweep counts the DNS records a wiped deployment left

## In plain words

**The problem today.** After a wipe, the flight sweep lists what the deployment left in the cloud account, but not the DNS names it left in its parent zone. A name that still answers sends traffic to an address the cloud has already released. The clean-wipe check needs a count of these names and fails while nothing counts them.

**What changes.** The sweep asks the authoritative name servers of the parent domain about every name the platform writes for a Sovereign and reports, as the kind dns_records, the names that still answer. A name that cannot be asked makes the sweep say not measured.

**Done means:**

- The sweep report ends with the entry dns_records, which names every DNS name of the wiped deployment that the authoritative servers of its parent domain still answer.
- A name that still answers counts as a leftover: the sweep exits 1.
- When the name servers cannot be found, or a name gets no usable answer from any of them, the sweep exits 3 and prints no report.
- The names asked are the apex of the Sovereign, every subdomain the provisioning API writes for it, the wildcard name and the admin name.
- The sweep only reads: it sends DNS queries and changes nothing.
- The README of the acceptance suite says that the leftovers of dns_records come from this entry.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After a wipe, `scripts/flight-sweep.sh <variables document>` prints a report whose list `kinds` ends with the entry `{"kind": "dns_records", "asked": <n>, "leftovers": [...]}`. `leftovers` names, sorted, each DNS name of the wiped deployment that the authoritative servers of its parent domain still answer. `leftoverCount` counts these names too. The script exits 1 when one name still answers, and 3, with no report, when a name could not be asked. The suite README tells the person who writes the pre-flight numbers that `left` of `dns_records` is the length of that list.

## 3. The model (the law)
1. **The names asked.** For the Sovereign FQDN `<fqdn>` of the variables document (key `sovereign_fqdn`, lower-cased, a trailing dot removed): the apex `<fqdn>`; `<sub>.<fqdn>` for every entry `<sub>` of `handler.CanonicalSovereignSubdomains` in `products/catalyst/bootstrap/api/internal/handler/sovereign_dns_records.go` (the record set the provisioning API writes into the parent zone and the wipe deletes); `*.<fqdn>` and `admin.<fqdn>` (written by `cmd/catalyst-dns` for a pool domain). Each name once, sorted. The list is read from the handler package, never copied.
2. **The parent domain** is `<fqdn>` without its first label. An FQDN with one label has none: not measured.
3. **The servers.** The hosts of the NS records of the parent domain, looked up with the system resolver, sorted; for each host its addresses, IPv4 first. A host whose addresses cannot be looked up is skipped. No address at all, or an NS look-up that fails: not measured.
4. **One question.** A DNS query for the A records of the name, over UDP to port 53, without recursion, with a random id. A reply counts only when it carries that id.
5. **The judgement of a reply** (from its header): an authoritative NXDOMAIN means the name is gone. An authoritative reply with code 0 (with or without records) means the name still answers. A reply with code 0, no answer and records in the authority section is a referral: the name is delegated and still answers. Anything else (no reply within 3 seconds, another reply code, a reply that is not authoritative, a reply that is not a response) means this server could not be asked, and the next server is tried.
6. **Fail closed.** A name that no server can be asked about ends the count with an error. The program then exits 3 with the line `flight-sweep: not measured: dns_records: <reason>` on standard error and prints no report.
7. **The report.** The entry `dns_records` has the fields `kind`, `asked` (how many names were asked) and `leftovers` (never null). It has no `used`: queries cannot count a zone. It comes after every kind of the cloud listing. `leftoverCount` is the sum of the leftovers of the cloud kinds and of `dns_records`; the exit code is 1 when it is above 0.
8. **Order.** The DNS count runs after the cloud listing succeeded. A usage error (exit 2) or a cloud listing that cannot be made (exit 3) asks no DNS server.
9. **Read only.** The program sends DNS queries and nothing else that is new. It never writes to a DNS server.
10. **Nothing is deleted.** The cloud listing, its kinds and its exit codes stay as they are.
