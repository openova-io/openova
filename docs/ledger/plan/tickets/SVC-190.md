# SVC-190 — Delete the Blueprint controller

## In plain words

**The problem today.** A second Blueprint validator sits in the repository as a controller that the platform chart never switches on. Its image is still built, its pin is still bumped, and two guards, the image sweep and the dependency bot still list it. It costs CI time and misleads a reader about where Blueprints are validated.

**What changes.** The controller's code, its build workflow, its chart templates and its values block are deleted. The lists that name them are corrected in the same change, and the list of deleted paths keeps them out.

**Done means:**

- The controller's folder, its build workflow and its four chart templates no longer exist, and the list of deleted paths names all six, so a pull request that brings one back turns red.
- The platform chart values hold no block for the controller, and the chart renders the same objects as before.
- The Go module of the controllers builds, and its checks and tests pass without the folder.
- The single-replica guard, the workflow-uniformity guard and the image-tag freshness guard pass and no longer list the controller.
- Neither the dependency bot nor the image sweep of the platform build names the controller.

The rest of this ticket is the exact instruction for the model that does the work.
