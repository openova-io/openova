# SOV-343 — The cutover copies the OpenTofu provider packages into the Sovereign and pivots the provider pod to them

## In plain words

**The problem today.** The pod that runs OpenTofu for the cloud Workspaces installs its providers from a mirror at the origin. The cutover moves every other artefact into the Sovereign but not these packages, and leaves the pod's configuration pointing at the origin. After the cutover the Sovereign cannot reach the origin, so the Workspaces that hold its own cloud resources fail, and the acceptance check does not look at that configuration.

**What changes.** The cutover copies the listed packages into the Sovereign's registry by digest, moves the pod's configuration there in the Sovereign's own Git, and waits until the running pod reads it. The day-two loop copies a package listed later, and the acceptance check fails when the configuration names anything but the right registry.

**Done means:**

- Cutover step 03 copies each listed OpenTofu provider package from the origin by its digest into the Sovereign's registry, and fails, naming the package, when a copy fails or the registry holds that version at another digest.
- Cutover step 11 rewrites the mirror address of the CLI configuration in the Sovereign's Git only when every listed package is served there at its digest, and reports success only when the running provider pod reads the new address.
- The release stage keeps the local address when a release changes the CLI configuration.
- The day-two reconciler copies a listed package that the registry lacks and leaves one it holds.
- Gate check CLD-G06 fails when the CLI configuration is absent, names a direct or other method, or names a registry other than the Sovereign's after the cutover or other than the origin before it.

The rest of this ticket is the exact instruction for the model that does the work.

1. No provider name enters a shared file: the packages are read from the live list at run time.
2. One reading of the list, the define `bp-self-sovereign-cutover.tofuProviders` (block `tofu-providers-list`): `tofu_list_read FILE` (0 read, 2 the ConfigMap does not exist, 1 it cannot be read), `tofu_list_line LINE` (a line is `<host>/<namespace>/<type> <version> sha256:<64 hex>`), `tofu_local_digest REPO REF` (the `Docker-Content-Digest` of a registry v2 HEAD of `TOFU_LOCAL_PATH/REPO` at REF, through the in-cluster Harbor service). A package is present when its version's tag serves the listed digest.
3. Step 03, Phase A5 (after A4, before Phase B; block `tofu-providers-copy`): for each listed package, a tag at the listed digest is left; a tag at another digest fails the step, named (a tag never moves, #7938); otherwise `offlinemirror_copy` (the one copy of every write into the registry: each manifest of the index by digest, then the index, digests preserved) copies `<originPrefix>/<namespace>/<type>@<digest>` to `<HARBOR_HOST>/<localPath>/<namespace>/<type>:<version>` with the pull credential of Phase A, up to `PREWARM_COPY_ATTEMPTS` times, and the tag must then serve the listed digest, else the step fails, named. No list ConfigMap: one line, nothing copied. A list that cannot be read or names no package fails.
4. Step 11, Phase 0.6 (block `tofu-cli-pivot`), before the clone of Phase 2: every listed version must be served at its digest, else FATAL naming each and nothing is rewritten. Phase 2 then rewrites, in the clone, every `repository_template` of `TOFU_CLI_FILE` that names `originPrefix` to `<registry_host>/<localPath>`; `registry_host` is the host of `sovereign.harborPublicURL`, the host step 06 merges into the pull Secret that the provider pod mounts as the credential of the configuration. The rewrite is part of the one commit of Phase 2. The live object is not edited by the step.
5. The rewrite is one copy: `tofu_cli_pivot_file FILE HOST` and `tofu_cli_local FILE HOST` in `provider-pivot.sh`, which step 11 sources and the release stage applies again. `provider-pivot.sh` carries the three last settings of rule 1 as defaults (`: "${TOFU_CLI_FILE:=...}"`), because the release stage receives only `SOVEREIGN_FQDN`, `REGISTRY_PATH`, `UPSTREAM_HOST` and `MOTHERSHIP_PROXY_PREFIX` from step 11 (`products/catalyst/bootstrap/api/internal/lifecycle/release_job.go` line 255) and the key may hold no Helm action (`release_scripts_test.go` line 71). The stage test checks that the defaults equal step 11's settings.
6. Success of step 11 also needs, inside `LIVE_SETTLE_SECONDS` counted from the start of the Provider wait: the Kustomization named by the Flux labels of the live ConfigMap has applied the commit (`lp_applied`), the live ConfigMap's `.tofurc` names only `<registry_host>/<localPath>/`, and so does `<mountPath>/.tofurc` read with `kubectl exec ... cat` in every running pod that mounts that ConfigMap. Otherwise FATAL naming what is not settled; the engine retries the step. No list ConfigMap: no pivot, one line.
7. The release stage (`files/release/release-region.sh`, kept byte for byte equal to `products/catalyst/bootstrap/api/internal/lifecycle/release/release-region.sh`): with a `provider-pivot.sh` that defines `tofu_cli_pivot_file`, a conflicted `TOFU_CLI_FILE` whose region side is exactly the rewrite of the merge base, to the region's registry host `reg`, is taken from the candidate (how `tofu`); after the merge, when the branch the region runs names `reg/<localPath>/` in that file, the rewrite is applied again and the stage refuses when the file then names any other mirror. A `provider-pivot.sh` of before changes nothing.
8. The day-two reconciler gains a leg `reconcile_tofu_once` (switch `daytwoReconciler.tofuProviders.enabled`, default true): a listed version whose tag does not serve the listed digest is copied by digest from the origin through `offlinemirror_copy`, behind the same delivery gate as the image leg (`daytwo_delivery_allowed`: mode `warm`, or an open request), and must then serve it; otherwise it is a `TOFU` line of the missing manifest. A tag at another digest is never copied over. A list that cannot be read is NOT-READY (`tofu-leg-unreadable`); a missing package is NOT-READY (`unservable-tofu-providers=<n>`).
9. Gate check CLD-G06 (`tests/acceptance/sovereign/internal/suite/check_crossplane.go`), in the primary region's step: the CLI configuration must exist with a non-empty `.tofurc`, name at least one `repository_template` and no `direct`, `network_mirror`, `filesystem_mirror` or `dev_overrides`; when `catalyst/self-sovereign-cutover-status` says `cutoverComplete=true` every mirror starts with `registry.<SOVEREIGN_FQDN>/openova-io/tofu-providers/` or `harbor.<SOVEREIGN_FQDN>/openova-io/tofu-providers/` (`SOVEREIGN_FQDN` of `flux-system/sovereign-variables`), before it with `ghcr.io/openova-io/tofu-providers/`.
