# AIP-156 — Delete the long-lived bearer seed

## In plain words

**The problem today.** When catalyst-api provisions an Organization, it mints an administrator session bearer for that Organization that lives for one year and stores it in the Sovereign secret store; its seed reconciler mints it again whenever that stored copy is missing. Since the agent workspace renews a short-lived tool identity of its own, that year-long bearer is a standing administrator key in every Organization that nothing needs.

**What changes.** catalyst-api no longer mints or stores that bearer: the code that made it is deleted, and the seed reconciler keeps only its two Sovereign-wide credentials.

**Done means:**

- Provisioning an Organization mints no tool bearer and writes nothing under the Organization's agent path in the secret store.
- A pass of the seed reconciler writes nothing when both Sovereign-wide credentials are healthy, even with Organizations listed and a signer present.
- No code of the platform holds a one-year bearer lifetime any more.
- The two deleted files are recorded in the list of deleted paths, and the agent-plane and API-structure guards pass with their stored numbers lowered.

The rest of this ticket is the exact instruction for the model that does the work.
