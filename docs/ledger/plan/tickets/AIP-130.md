# AIP-130 — Model contract conformance client

## In plain words

**The problem today.** The gate checks of the model gateway need to send requests the way an agent does and to judge each answer against the model contract. The acceptance suite has no such client today, so every model check would have to write its own requests and its own reading of the contract.

**What changes.** The acceptance suite gains one client of the model contract that every model check uses. It sends the requests the contract describes and names the section of the contract whose clause an answer broke. No gate check changes in this task.

**Done means:**

- The acceptance suite has a client that sends a tool round trip, two tools at once, a streamed call with tool deltas, a plain call, a call without a token and a call to an unknown model, and reads the model list.
- An answer that breaks a clause of the model contract makes the client return an error that starts with the number of that section.
- Each request carries its own request identifier, and an answer of 200 that does not echo it is an error.
- The agent token never appears in an error of the client.
- The client's tests run against an in-process gateway that answers by the rules of the stub back end, and each rule the client checks has a test in which it fails.
- No gate check and no record file changes.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
The acceptance suite (`tests/acceptance/sovereign`, Go module `github.com/openova-io/openova/tests/acceptance/sovereign`) gains the package `internal/modelcontract`, one file `client.go` and its test `client_test.go`, standard library only. `Client{BaseURL, Token}` talks to the model gateway at `BaseURL` (`http://<address>/v1`) with the agent token as a bearer. Its probes are `ToolRoundTrip` (one tool offered, one call back, the result `probe-result-42` sent in, a text out), `ParallelTools` (two tools offered at once, one answer holds two calls), `StreamWithToolDeltas` (one tool offered streamed: the call comes as deltas with an index), `UsageNonZero` (one question, a text and a usage with no zero count), `Unauthorized` (no token: 401 `invalid_token`) and `UnknownModel` (the model `nope`: 404 `model_not_found`), plus `Chat` (one question with extra headers), `Stream` (one plain streamed question) and `ModelOwner` (the `owned_by` of an alias in `GET /v1/models`). Each probe returns a `Reply` (status, error code, request id, text, calls, finish reason, usage) and nil, or an error whose text starts with the section of `docs/contracts/model-contract.md` whose clause the answer broke first: `1.1`, `1.4` or `1.5`. The checks AIP-G02 to AIP-G05 that call this client, the meter reader and `ModelUsageProbe` are AIP-131; this ticket changes no gate check.

## 3. The model (the law)
1. The package imports the standard library only: `go list -f '{{join .Imports " "}}' ./internal/modelcontract/` prints no path with a dot in it.
2. Every request carries its own `x-request-id` of the form `mc-` and 16 hexadecimal digits, which matches `^[A-Za-z0-9._-]{8,64}$` of section 3 of the contract, so the gateway keeps it. A 200 answer of `POST /v1/chat/completions` whose `x-request-id` differs is a `1.4` error.
3. An answered request (section 1.4): status 200; each tool call has a unique `id`, `type` `function`, a name the request offered and arguments that are a JSON object; with tools offered there is a call and `finish_reason` `tool_calls`, without tools a text and `stop`; `prompt_tokens`, `completion_tokens` and `total_tokens` are not zero and `prompt_tokens_details.cached_tokens` is present.
4. A stream (section 1.4) is, in this order: a first chunk with `delta.role`; deltas, every tool-call delta with an `index`; a chunk with `finish_reason`; a usage chunk with empty `choices`; `data: [DONE]`. A chunk after the usage chunk or after `[DONE]`, a delta after the finish reason, or a stream that ends without the usage chunk and `[DONE]` is a `1.4` error. The joined stream is then judged as in point 3.
5. A refused request (section 1.5) must have the status and the `error.code` of the contract: 401 `invalid_token` without a token, 404 `model_not_found` for a model that is not an alias. A different status or a different code is a `1.5` error.
6. `ModelOwner` returns the `owned_by` of the alias in `GET /v1/models`; an alias the list lacks is a `1.1` error.
7. The token is sent only in the `Authorization` header; no error text contains it.
8. The tests answer by the stub's rules (`core/services/model-meter/meter/stub.go`: a tool result is echoed, the first tool is called once, otherwise the user text is echoed; the usage is the byte length divided by 4, rounded up) behind a fake gateway, and each rule of points 2 to 7 has a test case in which the client fails.

+func (g gateway) ServeHTTP(w http.ResponseWriter, r *http.Request) {
+	if g.fault != "no-echo" {
+		w.Header().Set("X-Request-Id", r.Header.Get("X-Request-Id"))
+	}
+	reply := func(status int, doc any) {
+		w.WriteHeader(status)
+		_ = json.NewEncoder(w).Encode(doc)
+	}
+	failure := func(status int, code string) {
+		if g.fault == "code" {
+			code = "error"
+		}
+		reply(status, map[string]any{"error": map[string]string{"code": code}})
+	}
+	if r.Header.Get("Authorization") != "Bearer s3cr3t-jwt" && g.fault != "open" {
+		failure(401, "invalid_token")
+		return
+	}
+	if r.Header.Get("X-Request-Id") == "" { // the client sends one with every request
+		failure(400, "invalid_request")
+		return
+	}
+	if r.Method == http.MethodGet {
+		reply(200, map[string]any{"data": []any{map[string]string{"id": ConformanceAlias, "owned_by": "stub"}}})
+		return
+	}
+	body, _ := io.ReadAll(r.Body)
+	var req struct {
+		Model    string
+		Stream   bool
+		Messages []struct{ Role, Content string }
+		Tools    []struct{ Function struct{ Name string } }
+	}
+	if json.Unmarshal(body, &req) != nil || req.Model != ConformanceAlias {
+		failure(404, "model_not_found")
+		return
