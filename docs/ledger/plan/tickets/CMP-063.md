## 3. The model (the law)
1. **In place.** Each of the five templates keeps its path, its `metadata.name`, its labels and annotations (the read model reads title, severity and description from them), its values keys under `compliancePolicies.<key>`, its `enabled` switch and every exclusion. Nothing a policy checks changes; no two policies merge.
2. **Shape.** The shape of CMP-062: `apiVersion: policies.kyverno.io/v1`, `kind: ValidatingPolicy`; `spec.validationActions` from the helper `bp-kyverno-policies.actions`, except `forbid-local-path-storage`, which keeps the fixed `[Deny]` because its legacy policy fixed `Enforce` and did not follow the bootstrap window (the template says why); `spec.evaluation.background.enabled: true`; `spec.matchConstraints.resourceRules` with operations `CREATE` and `UPDATE`; namespace exclusions as a match condition from the helper `bp-kyverno-policies.excludeNamespacesExpr`; the checks as CEL `validations`. No automatic generation of controller rules: `harbor-proxy-pull`, `image-tag-pinned` and `secret-not-in-env` keep one explicit resource rule each for Pods, for Deployments, StatefulSets and DaemonSets, and for Jobs and CronJobs, so every resource gets exactly one result. `harbor-proxy-pull` reads the namespace label `openova.io/organization` through `namespaceObject`, as its legacy rule read it through the namespace selector.
3. **The bootstrap window.** The helpers of CMP-062 are used unchanged; `tests/bootstrap-window.sh` counts both kinds, and its counts stay 1, 9 and 9.
4. **Same verdicts.** Each suite was written and run on the legacy render first (tool v1.19.2) and was green there. Then only `policy.yaml` (the new render) and one key of each result (`rule: <name>` became `isValidatingPolicy: true`) changed; the resources and the expected results are the same, and the suite is green. The legacy policies with one rule per path shape or per kind (`harbor-proxy-pull` and `image-tag-pinned`: Pod, workload, CronJob; `forbid-local-path-storage`: claims, classes, volumes) gave one result per resource too, because each resource met one rule. Flipping any single expected result of a new suite turns it red. No resource of `tests/fixtures/` is edited.
5. **What the legacy suites could not prove.** On the legacy kind the tool reports a resource that a namespace exclusion leaves out as `Excluded` and accepts that for any expected result. On the new kind the same resource gives `skip`, which the suites now assert. `secret-not-in-env`: cases 6, 8 and 10 (no container with `env`) had no result on the legacy kind and were reported `Excluded`; the new policy skips exactly those objects through its match condition `containers-with-env`.
6. **The Crossplane runtime suite.** `crossplane-package-runtime-admitted/policy.yaml` is the render of `10-flux-managed.yaml` (legacy) and `04-probes.yaml` (new). Its results of `probes-present` carry `isValidatingPolicy: true`. Case 10 is the DELETE that Crossplane's deactivation sends: it keeps the result of `flux-managed` only, because the tool sends no DELETE to a ValidatingPolicy, and `values.yaml` no longer lists `probes-present`. The check C3 of `tests/crossplane-runtime-suite-current.sh` fails when the rendered `probes-present` matches any operations list other than `["CREATE", "UPDATE"]`; its self-test has a passing and a failing case for it (4 cases).
7. **Current copies.** `tests/suites-current.sh` lists the five suites in `SUITES`. Its check C4 also accepts a suite listed in `ELSEWHERE` when the test named there exists and names the suite's directory (`crossplane-package-runtime-admitted`, kept current by `crossplane-runtime-suite-current.sh`); its self-test gains one passing and one failing case (10 cases).
8. **Baselines.** `scripts/baselines/kyverno-legacy.json` loses the five template entries (38 to 33 objects); `scripts/baselines/policy-suites.json` loses the five checks that now have a suite.
9. **One difference, by convention.** The legacy rules named no operation; the new policies match `CREATE` and `UPDATE` only, so a `DELETE` request is no longer judged.
