# NET-071 — Remove the zone virtual-cluster dialog, tab and stub kind

## In plain words

**The problem today.** A Sovereign region is one cluster whose edge, platform and Organizations are separated by namespaces and network policy; a virtual cluster is the boundary of one Organization only. The console still shows the withdrawn zone design: a DMZ tab that tells the reader to enable a DMZ virtual cluster, a vClusters page that speaks of DMZ, RTZ and MGMT slices and shows an isolation value the API never sends, and an API route that serves that tab. A chart still installs an empty stub kind that only that route and tab needed.

**What changes.** The DMZ tab, its API route, its handler and its client call are deleted. The vClusters page says one virtual cluster per Organization and shows the Organization of each one instead of an isolation value. The console type and the two graph views stop reading the isolation field, and the stub kind leaves the chart, with the two guard baselines lowered and the deleted file recorded.

**Done means:**

- The Networking page shows four tabs, Policies, ClusterMesh, NetBird and Hubble, and the old DMZ address opens the Policies tab.
- The API answers no route under /networking/dmz, and its recorded route table no longer lists one.
- The vClusters page reads 'One virtual cluster per Organization.' and its table and detail drawer show an Organization column instead of Isolation.
- No console source reads an isolation field of a virtual cluster.
- The vCluster source chart renders a namespace and a HelmRepository only, and its CRD template is on the list of deleted paths.
- The API and the console build, their tests pass, and the guards on the handler package size and on polling pass with lowered numbers.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. A Sovereign region is one cluster. Its zones are the edge, the platform namespaces and the Organizations. A virtual cluster is the boundary of one Organization and runs in that Organization's namespace. Decision record `docs/adr/0019-zones-are-namespaces-and-an-edge-pool.md` states this; this ticket does not change it.
2. These are deleted, and nothing replaces them:
   - the route `GET /api/v1/sovereigns/{id}/networking/dmz` (one line of `products/catalyst/bootstrap/api/cmd/api/routes_sovereigns.go`), its line in `products/catalyst/bootstrap/api/cmd/api/testdata/routes.golden`, the handler `HandleNetworkingDMZ`, the types `dmzResponse` and `dmzVCluster`, and the test `TestHandleNetworkingDMZ_HappyPath`;
   - the DMZ tab of the Networking page (the component `DMZTab` with its three "DMZ vCluster not installed" panels), its slug `dmz`, its two unit tests, the client call `getNetworkingDMZ` and the types `DMZVCluster` and `DMZResponse`;
   - the console type `IsolationMode` and the field `isolationMode` of `VClusterSpec`;
   - the file `platform/bp-vcluster-helmrepo/chart/templates/vcluster-crd.yaml` and the block `vclusterCRD` of that chart's `values.yaml`.
3. The four other Networking tabs, their routes and their handlers do not change. A slug that is not one of the four tabs renders the Policies tab, as the page already does for any unknown slug.
4. The vClusters page lists the virtual clusters that the topology read returns, one row each, as before. Its Organization column, its sort column `organization` and its detail row `Organization` show `vcluster.namespace`, or `—` when the namespace is absent. Its search also matches the namespace.
5. Where the topology layout and the architecture graph showed `isolationMode`, they show the namespace: the layout's sublabel is `vc.namespace ?? ''`; the graph node's sublabel is `vc.namespace` and its metadata is `{ namespace: vc.namespace ?? '' }`.
6. Clusters that already run the chart keep their CRD `vclusters.vcluster.com`: it carries `helm.sh/resource-policy: keep`, so Helm does not delete it when the template leaves the chart. A new Sovereign gets no such CRD. The topology read already treats a missing kind as an empty list and falls back to namespaces and StatefulSets.
7. The deleted file is recorded as the last line of `docs/ledger/deleted-paths.txt`. The handler-size baseline falls by the 81 lines and 1 method that leave `internal/handler`, and the polling baseline of `NetworkingPage.tsx` falls by the one `refetchInterval` of the DMZ tab. Both are written by the guards' own `--write-baseline`, never raised and never edited by hand.
8. The chart's version lines are written by CI. This ticket changes no `version:` line, no pin and no `Chart.yaml`.
