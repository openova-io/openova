# SEC-110 — Truth in the security documents

## In plain words

**The problem today.** The security document and the OpenBao and External Secrets READMEs describe protections that do not run: replication between regions that OpenBao does not have, unseal keys that are said never to be Secrets, values said never to be in Git, rotation and dynamic credentials that no code provides. The status page still calls External Secrets a README and OpenBao unwired. A reader cannot tell what protects a Sovereign today.

**What changes.** The sentences this task names are replaced by what the code does today, the sections that describe a design not yet built say so in their first line, and the security document gains a table of what each kind of attacker obtains today and in the target. The control file names the gate check that will prove five of its controls.

**Done means:**

- The OpenBao and External Secrets READMEs no longer name Performance Replication and no longer say that replication carries values between regions. They say that the primary region pushes shared values into the OpenBao of each region, and that a Sovereign with a hot standby also copies a snapshot through object storage. They still call the OpenBao of a region a replica.
- The security document and the OpenBao README say where the unseal key and the first root token are kept today. The security document also says that etcd holds Secrets in the clear and where Git still holds secret values.
- Two parts of the security document still mention replication: the section on multi-region OpenBao, which now starts with "Target, not built.", and the path of a secret value, which a later task changes.
- The sections on dynamic credentials, multi-region OpenBao and rotation each start with the words "Target, not built." and the fact of today.
- The security document holds, between two markers in its threat-model section, one table of ten kinds of attacker with what each obtains today and in the target.
- The status page says that OpenBao and External Secrets are installed by the bootstrap kit, and that the per-Organization repository bootstrap is not wired.
- The control file names a gate check for five controls and a decision record for one, and the generated control matrix shows them, with every control still target.

The rest of this ticket is the exact instruction for the model that does the work.
