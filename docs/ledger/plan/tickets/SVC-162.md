# SVC-162 — Shelf deletion: README-only folders and scaffold Blueprint files

## In plain words

**The problem today.** Fifteen folders of the repository describe components that were never built: each holds a long README written as if the component existed, and nine also hold a Blueprint file with no chart. Two of these Blueprints are written into the catalogue that every Sovereign installs, as entries that can never install. A reader cannot tell them from the components that exist.

**What changes.** The fifteen folders are deleted, and every catalogue file that named them is regenerated or corrected. One short roadmap section in the status document says, for each of them and for the two later products, what it would be and that it is not built.

**Done means:**

- The fifteen folders are gone and recorded as deleted paths, so a change that brings one back turns its pull request red.
- The catalogue that the console, the platform API and every Sovereign read holds none of the nine Blueprints; the two unlisted seed entries that could never install are gone.
- The register of unpublished pins is empty, and the GHCR gate accepts an empty register while it still refuses a register it cannot read.
- The status document has a roadmap section with one entry for each deleted component and the two entries of the AI hub and open banking, each marked as not built.
- The architecture inventory and the Crossplane README no longer link to a deleted folder.
- The service-model guard passes with its baseline lowered by the counts the deleted files carried, and every step of the tree guards passes.

The rest of this ticket is the exact instruction for the model that does the work.
