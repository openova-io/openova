# CMP-036 — Kit slot 27a: values document, hand-over variable, definitions on upgrade

## In plain words

**The problem today.** The kit slot that installs the policy chart reads no values document, so a policy mode kept in Git could never reach the chart. It does not pass the hand-over variable either, so the end of the policy bootstrap window can only be set from outside the Sovereign. And Helm would never update a resource definition that the chart brings, because the slot does not ask for it on upgrade.

**What changes.** The slot gains an optional values document, the hand-over variable as a chart value with the default origin, and the instruction to create and replace definitions on install and upgrade. A new guard checks these three things on every pull request.

**Done means:**

- The policy chart's slot reads the ConfigMap compliance-policy-values when it exists and installs as before when it does not.
- The slot passes the chart the value compliancePolicies.sovereignConsume, which is origin until the hand-over sets the variable SOVEREIGN_CONSUME to local.
- Helm creates and replaces the definitions of the policy chart on install and on every upgrade.
- Every other line of the slot is unchanged, and the slot does not set the bootstrap switch.
- A pull request that removes one of the three settings from the slot turns red, and the guard proves on every run that each of its rules can fail.

The rest of this ticket is the exact instruction for the model that does the work.

def findings(root):

        if b.get("crds") != "CreateReplace":
