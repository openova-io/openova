# SEC-104 — Unwire bootstrap-kit slot 05

## In plain words

**The problem today.** Every Sovereign still installs the Sealed Secrets controller as slot 05 of its bootstrap kit, although no chart of the platform creates a sealed secret any more. Two other kit slots still wait for that controller before they install. The dependency audit of the kit, the readiness verifier of a Sovereign and the build check of the console still expect it.

**What changes.** Slot 05 leaves the bootstrap kit, so a new Sovereign no longer installs the controller and a running Sovereign removes it at its next update. The two slots that waited for it no longer do, and the lists, inventories and guard numbers that counted the slot are brought in line.

**Done means:**

- The bootstrap kit holds no slot for Sealed Secrets, and the slot file is on the list of deleted paths, so a pull request that brings it back turns red.
- The remote-shell proxy and the remote-desktop gateway no longer wait for the Sealed Secrets controller, and each keeps every other dependency it had.
- The dependency audit of the kit, the placement check and the kit tests pass without the slot.
- The readiness verifier of a Sovereign no longer expects a Sealed Secrets release, and the build check of the console no longer asks for its name.
- The catalogue of the console and the generated slot inventory no longer list the slot.
- The chart folder of Sealed Secrets is still in the repository. A later task deletes it.

The rest of this ticket is the exact instruction for the model that does the work.
