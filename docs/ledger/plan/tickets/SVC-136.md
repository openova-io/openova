# SVC-136 — The foundation function tests pass on a fresh installation

## In plain words

**The problem today.** On a fresh installation the function tests of nine foundation charts fail although the services work. Most run right after their chart is applied and give up before the service is up; one builds a bucket name that no storage server accepts, and one asks an address that answers only after a sign-in. A failed test Pod is also kept with no image recorded, and the identity check counts that as a defect.

**What changes.** Each of the nine tests waits a bounded time for its service and then judges it as before, the bucket and stream names are valid, and the Gitea test asks its health address. The identity check judges every container that runs, and only lists a finished Pod that recorded no image.

**Done means:**

- A function test whose service comes up within four minutes of the install passes; a service that never comes up still fails the test before its five-minute limit.
- The storage test creates a bucket whose name holds only letters, digits and dashes.
- The Gitea test asks the health address, which answers without a sign-in, and passes only when Gitea reached its database.
- The OpenBao test waits for the role of External Secrets that the configuration service writes after the install, and still fails when that role never appears.
- Each of the nine charts' render tests runs its test script against stand-in commands: a late service passes, a dead one fails.
- The identity check passes beside a failed test Pod that recorded no image, and still fails a running container without one.

## 3. The model (the law)
1. A function test waits only for what an installation is still starting, and only until second 240 of its `activeDeadlineSeconds: 300`; then it judges as before. A service that never answers still fails the test, inside 300 seconds.
2. The script of a test Pod holds no `$$`. Kubernetes expands `$(VAR)` and turns `$$` into `$` in a container's `args` before the shell reads them, so `$$` never reaches the shell as its process id.
3. A test asks an address that answers without a credential it does not hold. Gitea with `service.REQUIRE_SIGNIN_VIEW: true` answers 403 to every `/api/v1` request without a sign-in; `/api/healthz` answers 200 only when its database and cache checks pass.
4. The contract of a function test is unchanged (`scripts/check-function-test.py`, rules FT1 to FT13): one Pod, `before-hook-creation,hook-succeeded`, `activeDeadlineSeconds: 300`, the `FUNCTION-TEST pass|fail` last line. A failed test Pod stays until the next test run, so its logs can be read.
5. FND-G01 judges what runs. A container whose Pod has finished and whose status holds no digest runs nothing: it is listed and not judged. A finished Pod's container that has a digest, and every container of a Pod that has not finished, are judged as before.
6. Nothing else changes: the kit slots, the chart values, `Chart.yaml` (the release writer sets versions), the gate check list.
