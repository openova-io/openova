# FND-154 — Check FND-G01 in its `self` form

## In plain words

**The problem today.** The candidate identity check compares what runs with the chart versions pinned in a checkout of the candidate commit. A run inside a Sovereign has no checkout and no candidate, so there the check can only fail, and it cannot be offered to such a run.

**What changes.** In a run in self the check compares each HelmRelease with the chart version that its own spec names, and keeps the image digest rules. Every other run is judged as before.

**Done means:**

- In a run in self, check FND-G01 records no step about the suite commit or the pins, and reads no file of a checkout.
- In a run in self, a HelmRelease that runs another chart version than its own spec names fails the check, and so does one with nothing deployed.
- In a run in self, a container without an image digest fails the check, and so does an image reference with two digests.
- A run in the cloud or on the local pack is judged exactly as before.
- The row of FND-G01 in the suite README describes the self form.

The rest of this ticket is the exact instruction for the model that does the work.

## 2. End goal
After this ticket, check FND-G01 (candidate identity) in `tests/acceptance/sovereign/internal/suite/check_candidate.go` has two forms. When the run is in `self` (a Job inside a Sovereign, `CheckContext.RunIn == RunInSelf`), the check needs no checkout and no candidate: in each region it lists every HelmRelease, compares the newest deployed chart version of each one with the version that its own `spec.chart.spec.version` names, and keeps the two digest rules (every container of the platform namespaces has an image digest; one image reference has one digest, in each region and across the regions). In every other run (`local`, `cloud`) the check is exactly what it is today. A person sees this in the new test `TestCandidateSelf` of `check_candidate_test.go`, whose five cases all pass, and in the row of FND-G01 in `tests/acceptance/sovereign/README.md`. Which checks a run in self selects is set by `runs_in` in `docs/ledger/gates.yaml`; this ticket does not change that file.

## 3. The model (the law)
1. **Which form.** The check reads `cc.RunIn`. When it equals `RunInSelf` (the value `self`, constant of `internal/suite/registry.go`), the self form runs. Any other value, the empty one included, runs the form of today, unchanged in steps, names, messages, evidence and artifacts.
2. **No candidate in self.** The self form records neither the step "the suite was built from the candidate commit" nor the step "the candidate pins a chart version for each HelmRelease of clusters/_template/bootstrap-kit". It does not call `gitSHA` or `readPins` and reads no file under `cc.RepoRoot`. Its step identifiers start at `FND-G01.1`.
3. **The release rule in self.** For each region, in the order of `cc.Regions`, one step named `every HelmRelease runs the chart version its spec names in region <region id>`. It lists `helmreleases.helm.toolkit.fluxcd.io` in every namespace. Every HelmRelease becomes one entry of the artifacts, with `pinned` set to its own `spec.chart.spec.version`. A HelmRelease with `spec.suspend: true`, or whose `spec.chart.spec.version` is empty, is listed and not compared. A compared HelmRelease must have that version as the `chartVersion` of the newest `deployed` entry of `status.history`. A difference is written `<namespace>/<name> runs <version, or "no deployed version"> and its spec names <version>`, and the step fails with `<n> of <m> HelmReleases do not run the chart version their spec names: <differences joined by "; ">`. No HelmRelease, or a list that cannot be read, fails the step as today and the record gets no artifacts.
4. **The digest rules are the same.** The per-region step about digests and the last step "one image reference has one digest across the regions" are unchanged in both forms. In a run in self with one region a run of the check has three steps.
5. **The README row.** The row of FND-G01 in the table of checks of `tests/acceptance/sovereign/README.md` keeps its text and gains the sentences of the self form (field 16, step 6).
6. **The proof.** `TestCandidateSelf` runs the check with `RunIn: RunInSelf`, one fake region, no candidate and no checkout, in five cases: one that passes and four that each fail one rule (another version than the spec, nothing deployed, a container without a digest, one reference with two digests). Each case asserts the exact list of failed steps, so each one fails on the check as it is before this ticket, which records the two candidate steps and fails them.
7. **Standard library only.** No dependency is added; `go.mod` is not changed. No other file of the suite changes.
