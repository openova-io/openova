# CTL-348 — The flow host leaves the sign-in gate and the DNS name list

## In plain words

**The problem today.** The flow server left the bootstrap kit, but three places still treat its public host as a live service. The sign-in gate still runs an instance in front of a Service that no longer exists, catalyst-api still writes a DNS record for the host on every new Sovereign, and the sign-on probe still visits the host, so its two rows can only fail.

**What changes.** The gate instance and the two probe rows are removed, and catalyst-api stops writing the DNS record of the flow host. The wipe of a Sovereign still deletes that record, so a Sovereign installed before this change leaves nothing behind in the parent zone.

**Done means:**

- The sign-in gate of the bootstrap kit has no instance for the flow host, and no gate instance points at the flow server.
- A new Sovereign gets no DNS record for the flow host in its parent zone.
- Wiping a Sovereign still deletes the DNS record of the flow host that an earlier release wrote, so no record is left pointing at a released address.
- The sign-on probe no longer visits the flow host, and the probe still parses and its hubble row still holds.
- The handler package of catalyst-api has the same number of lines as before, so its structure guard stays green without a baseline change.

The rest of this ticket is the exact instruction for the model that does the work.

3. **No DNS record is written for the flow host.** `openova-flow` is not in `CanonicalSovereignSubdomains`. The upsert (`upsertSovereignParentZoneRecords`) and the republish both iterate that list, so neither writes the name.
4. **The wipe still deletes it.** A new package variable `RetiredSovereignSubdomains = []string{"openova-flow"}` sits directly after `CanonicalSovereignSubdomains`. `sovereignParentZoneRecordNames` returns `<sub>.<fqdn>.` for every name of `slices.Concat(CanonicalSovereignSubdomains, RetiredSovereignSubdomains)` and then the apex. `deleteSovereignParentZoneRecords` uses that function, so a wipe deletes `openova-flow.<fqdn>.`. A DELETE of an absent rrset is a no-op in PowerDNS, so this is safe for a Sovereign that never had the record. Nothing else reads the new variable.
5. **The handler package does not grow.** `scripts/check-api-structure.py` counts the lines of the non-test files of `internal/handler` and fails when the count differs from `scripts/baselines/api-structure.json` in either direction. The edits of `sovereign_dns_records.go` add and remove the same number of lines (12 and 12), so the count and the baseline stay equal and the baseline is not touched.
6. **The tests follow.** In `sovereign_dns_records_test.go`: the list of browser-facing names loses `openova-flow` (the comment column of that list is realigned as gofmt writes it); the two tests that count the names the wipe deletes count the retired names too and require `openova-flow.<fqdn>.`; the new test `TestRetiredSovereignSubdomainsAreNotWritten` requires that the upsert writes no retired name and that no retired name is in `CanonicalSovereignSubdomains`.
7. **The probe has no flow row.** The two row objects `openova-flow` and `openova-flow-anon-denied` are deleted from `ROWS` in `scripts/sso-zero-click-probe.mjs`, and the header comment on the anonymous rows names only the marketplace row. No other row changes.
