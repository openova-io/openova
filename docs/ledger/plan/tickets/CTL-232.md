# CTL-232 — Operations audited; reconciler suspend and resume refused

## In plain words

**The problem today.** Restarting a workload, opening a shell in a pod, retrying a job and asking a reconciler to reconcile change the cluster from the console, and none of them leaves a durable record of who did it and whether it worked. Suspend and resume of a reconciler write spec.suspend straight into the cluster, a field whose value Git owns, so the cluster drifts from Git.

**What changes.** Each of the four operations is recorded on the audit stream before it runs and after it ends, and does not run when that record cannot be made. Suspend and resume are refused with an answer that says the change belongs in Git.

**Done means:**

- Restarting a workload, opening a shell, retrying a job and reconciling a reconciler each leave two audit records: one before the action and one after it with its result, ok or error.
- When the audit stream does not take the first record, each of these four actions answers 503 audit-unavailable and does nothing.
- Suspending or resuming a reconciler answers 409 managed-by-git with the reconciler as owner, and changes and records nothing.
- Every answer of these routes that runs is the same as before, and names the same caller.
- The mutating-route contract marks the five operation routes as done, and the direct-write and handler-size guards pass with their stored numbers lowered.

The rest of this ticket is the exact instruction for the model that does the work.

## 3. The model (the law)
1. **Where the audit sits.** Each operation keeps its own gates as today (tier, ownership, parsing, the live reads it needs). Right before the call that acts on the cluster it calls `clusterwrite.Operation(w, r, h.auditBus, clusterwrite.Op{Cluster, Name, Target})`. When that returns false it has written the answer and the handler returns. Otherwise the handler acts and then calls the returned `Finish` with the error of the action (nil on success). The answer the handler writes after that is the answer of today.
2. **The four operations.**

| Operation | `Name` | `Target` | `Cluster` | The action between the two events |
|---|---|---|---|---|
| restart | `restart` | `<resource> <ns>/<name>` (for example `deployments default/wp`) | the sovereign id of the route | the merge patch of `restartedAt` |
| exec session | `exec` | `pods <ns>/<pod>/<container>` | the sovereign id of the route | `CreateSession` of the Guacamole client, or the in-memory fallback session |
| job retry | `job-retry` | `<job kind> <job name>` (for example `install install-velero`) | the deployment id | `dispatchRetry` |
| reconcile | `reconcile` | `<Kind> <ns>/<name>` (for example `HelmRelease flux-system/bp-keycloak`) | the deployment id | the merge patch of the reconcile annotations |

   The audit type is `operation-<Name>`; the actor is `clusterwrite.Actor`. An operation needs no reason and no owner tier.
3. **No record, no action.** When the stream does not take the intent event, the answer is 503 `audit-unavailable` (written by `clusterwrite`) and nothing runs: no patch, no Guacamole session, no remediation and no new Execution of the job.
4. **Suspend and resume are refused.** After the operator-tier gate of `ReconcilerAction` and before any client is built, `suspend` and `resume` answer `clusterwrite.Refuse`: 409 `{"error":"managed-by-git","code":"409","owner":"<Kind> <ns>/<name>","detail":"<action> changes spec.suspend of <Kind> <ns>/<name>, which Git owns; change it in Git"}`. Decided: the owner is the reconciler itself, the Flux object whose spec Git sets; the object is not read. Nothing is written, no audit event and no retry call is recorded. The two patch branches of `spec.suspend` are deleted.
5. **The caller.** `retrycall.Caller(r)` in `jobs_retry.go`, `reconcilers.go` and `schedules.go` becomes `clusterwrite.Actor(claims, r)`. Both return the e-mail of the claims, else their subject, else the header `X-User-Email`, else `operator`, so `requestedBy`, the first log line of a new Execution and the caller label of a schedule clone stay the same.
6. **Exec.** The 502 `guacamole-create-failed` answer moves after `Finish`, so a failed session is recorded with result `error`. `HandleK8sExecWebSocket` (`k8s_exec_ws.go`) and `execSessionCallerAuthorized` stay as they are, for ACC-101 and ACC-123.
7. **Contract and baselines.** The five C9 entries of CTL-232 get `done: true`. `open_cluster_writers` of `scripts/baselines/mutating-routes.json` falls by five. `scripts/baselines/direct-cluster-writes.json` gets three allow entries (owner CTL, metric K, each with its reason): `jobs_retry.go` 5, `k8s_resource_actions.go` 1 (restart; scale, apply and delete stay counted), `reconcilers.go` 1; its counts are written by its own tool. `handler_lines` of `scripts/baselines/api-structure.json` is written by its own tool and falls.
8. **Formatting.** `k8s_exec.go`, `reconcilers.go` and `k8s_exec_test.go` are not gofmt-clean on main. The patch formats its own lines only; nobody runs `gofmt -w` on these three files.
