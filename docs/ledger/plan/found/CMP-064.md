# CMP-064: defects seen and not fixed

- platform/kyverno-policies/chart/templates/baseline/15-otel-injected.yaml (validation, first side): the legacy rule's array pattern `containers: [{name: otel-collector}]` was applied by the engine to every container, so a workload passes that side only when every container is named otel-collector; an app container beside an otel-collector sidecar fails (tests/otel-injected case 2, the same verdict on the legacy and the new kind), while the policy's message tells the owner to add such a sidecar.
- platform/kyverno-policies/chart/templates/baseline/07-pvc-expansion.yaml lines 9 to 13 (header): "the cluster default's expansion ability is checked when the StorageClass itself is admitted (via context.apiCall in a sibling rule)": the policy has no such rule, on the legacy kind or the new one.
- platform/kyverno-policies/chart/templates/baseline/02-pdb.yaml lines 4 to 9 (header): it describes a minAvailable check (minAvailable must not equal the replica count) that the policy never made; only maxUnavailable 0 or "0%" is refused.
- platform/kyverno-policies/chart/templates/baseline/20-backup-configured.yaml (description annotation and message): they name the annotation velero.io/backup-volumes "on the owning Pod template", but the check reads the claim's own annotations, as the legacy pattern did.
