- `products/cortex/cmd/cortex/main.go`: nothing serves the screens of `products/cortex/ui` (the embedded `ui.Web`) or writes their `web/config.json`, and no plan entry has that in its paths: PRD-209 holds the Containerfile, the chart and the Blueprint, not the command. Until a package does, the screens are built and tested but not reachable.
- `products/catalyst/bootstrap/api/internal/handler/applications.go` and `applications_update.go` (the Application read and update routes, CTL-162): the screens read the version from `ETag` on `GET /api/v1/sovereigns/{id}/applications/{name}` and send it as `If-Match` on `PUT`, so the read route must set `ETag` too, not only the write. The screens run on cortex's origin and call the platform API on another one, so the two routes must also answer the browser's preflight for `PUT` with the request headers `Authorization`, `If-Match` and `Content-Type`, and name `ETag` in `Access-Control-Expose-Headers`: a script on another origin cannot read `ETag` otherwise. The token the screens send is the Organization realm's, with the audience `cortex`.
