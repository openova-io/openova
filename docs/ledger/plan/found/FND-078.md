- `.github/workflows/foundation-gate.yaml` (job `live`, `permissions`): the job gets `packages: write`, but in both executions it only pulls (the job `addresses` builds the images). `packages: read` would be enough; the guard `scripts/check-gate-parent-access.py` (`ALLOWED`) admits only `contents: read` and `packages: write`, so its rule P3 would fail the narrower token. The plan entry of FND-078 fixes those two permissions; narrowing `live` means changing the plan entry and `ALLOWED` together, in a later package.
- `scripts/gate-parent-job.sh` (`cmd_run`): the two Secrets of a run carry no `ownerReference` to the Job. When the runner is lost, neither the script's trap nor the `always()` cleanup step runs: the Job deletes itself after `ttlSecondsAfterFinished`, but its Secrets, with both region kubeconfigs, stay in the namespace `acceptance-gate` until `gate-parent-job.sh cleanup` or the namespace's owner deletes them. The warning of the cleanup steps ("the Job deletes itself an hour after it ended") says nothing about the Secrets. A fix creates the Job first, reads its `uid`, and creates the Secrets owned by it (without `blockOwnerDeletion`, which needs a right the access does not have); the Pod mounts the Secret as soon as it exists. Only a run on the parent proves that order, so it is a later package.
- `scripts/gate-parent-job.sh` (`inner_addresses`, `inner_regions`, `inner_live`, `sso_check`, `sso_delete`, `cmd_probe`): the self-test covers the side of the workflow (manifests, retry, log transport, Pod reading, cleanup) against a stand-in `kubectl`; the code that runs inside the Job is proved only by the first parent run after the merge.
- `scripts/gate-parent-job.sh` (`inner_live`, `emit_file`): the container `gate` prints the suite log twice, live through `tee` and then in base64. `kubectl logs` without `-f` returns only the current log file once the kubelet has rotated it (10 MiB by default), so a very long log could lose the outputs or a file block, and the run then fails with "printed no suite return code". Not measured: the first parent run shows the size of that log; a fix prints the suite log once.
