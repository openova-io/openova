- `platform/openbao/chart/templates/sso-configure-deployment.yaml` (`READ_POLICY_PAYLOAD`): the OIDC baseline `sso-operator-read` still has read on `path "*"`, which includes `identity/oidc/token/openbao-peer-push`. Reading that path mints an identity token, and the role template in `platform/openbao/chart/templates/_config.tpl` line 343 is the fixed claim `openova_region`, so by the code (not run) every federated login, viewers included, can mint a token that the peer's `jwt-peer-<region>` role accepts and push under `secret/data/openova/apps/*` of the peer. This predates SEC-190; the package that next owns the sign-on policies should deny `identity/oidc/token/*` to the baseline.
