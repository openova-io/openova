- `products/catalyst/bootstrap/api/internal/store/store.go` (`RedactedRequest`, `Redact`, `ToProvisionerRequest`): the deployment record does not hold `Request.SovereignTimeZone`, which INF-054 adds. `cmd/tfvars-regenerate` (`unheld`, `main.go` line 279) therefore takes the field for a credential: `credentialKeys` gives it a probe value, which lands inside the nested `variables` map, where the search for top-level keys does not find it, so the regeneration writes `SOVEREIGN_TIME_ZONE=UTC` for a Sovereign installed with another zone and reports a changed `variables`. A deployment rehydrated after a restart of catalyst-api (`internal/handler/deployments.go` line 423) has lost the zone as well. `TestRoundTrip` does not see it because `request()` in `cmd/tfvars-regenerate/main_test.go` does not set the field. The repair is to copy the field in `Redact` and `ToProvisionerRequest` (a non-secret field of `RedactedRequest`), to set it in `request()` and to cover it in `store_test.go`; none of these files is allowed to INF-054.
- `core/controllers/pkg/upstream/upstream.go` (`FromMap`): the contract checks only the form of `SOVEREIGN_TIME_ZONE` and `KURED_TIME_ZONE`, so `KURED_TIME_ZONE=Asia/Nowhere` is accepted and reaches kured as `--time-zone`. A check with `time.LoadLocation` in `FromMap` is right, but it cannot land before the repair above: `childVariables` calls `FromMap`, and the probe value `tfvars-regenerate-probe-<n>` that `credentialKeys` writes as the zone is then refused, so every run of `tfvars-regenerate` exits 3 (measured: `TestReportsWhatTheRecordChanges`, `TestRoundTrip_RecordWithoutCredentialsMap` and `TestZeroChangePlanPack` fail with it). Once the record holds the field, the probe no longer touches it and the check can be added.
