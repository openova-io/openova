# CLD-050: Workspace mechanics on Crossplane 2 (lab test result)

Date: 2026-11-13. Type: lab test. Result line: **encryption option: B**

## Question

Can the planned Workspace set-up run on Crossplane 2 with provider-opentofu? It needs state in an S3 bucket, encryption with OpenBao, modules from the Sovereign's Git, provider binaries only from the Sovereign's registry, and an offline copy of the key. The test also asks whether today's adoption Workspaces survive the upgrade path. Twelve rows: E1 to E7 and E13 (these gate this area's packages), then E8, E15, E16 and E17.

## Other measured facts

- **E3 / E13: the meta key name.** OpenTofu stores the wrapped data key in the state's `meta` under the key provider's address, `key_provider.openbao.sovereign`. A drill that names the block differently fails with "no decryption key available" (run 2, and the renamed-block pull in run 3). The drill and every later config must keep the block name.
- **E13: backup needs two key flags.** OpenBao refused the backup ("exporting is disallowed on the policy") until the key had `exportable=true` and `allow_plaintext_backup=true`. OpenBao documents both flags as one-way; this was not measured.
- **E5: where the CLI configuration must live.** During `tofu init` the provider sets `TF_CLI_CONFIG_FILE=./.tofurc`. That overrides a pod-level value. Measured: with a pod-level setting, init warned ".tofurc does not exist" and went to the public registry. What works:
  - a `.tofurc` written by the ProviderConfig `credentials` (from a Secret), or
  - a `TF_CLI_CONFIG_FILE` env on the Workspace (Ready in 4–8 s).
- **E4: the Git credential is shared across ProviderConfigs.** The provider sets `GIT_CRED_DIR` for the whole process. After one ProviderConfig's credential was written, a Workspace on a ProviderConfig without credentials read the private repository (runs 1–3).
- **E15: an Observe-only Workspace is late to report.** On its first observation it shows Synced=True, but no Ready and empty outputs. Ready and outputs appear at the next poll (560 s measured) or 2 s after any annotation change. Likely cause, from reading the crossplane-runtime v2 source: adding the finalizer on the first reconcile overwrites the in-memory status.
- **E7: changes Crossplane makes on the way.**
  - At 2.4.3 Crossplane made a new ProviderRevision for the same v1.1.3 digest.
  - It made ManagedResourceDefinitions for both Workspace kinds, both Active.
  - It added a third CompositionRevision.
  - docker.io/crossplane/crossplane has v1.19.3, v1.20.14 and v2.4.3. That is the path the chart's proxy serves.
  - The raise to v1.1.11 became the active, healthy revision in 6–68 s.
- **Run history.** Two failures were in the test, not the product:
  - Run 1, E3: the env check in the script failed.
  - Run 1, mirror and E8 inline: Python 3.14 rejected the first test CA.
  - Run 2, E13: the drill used a different block name. That is the finding above.

## What later tasks must take into account

All twelve rows ran in CI and have results. The decision rows E1-E7 and E13 all pass, and the record says "encryption option: B". E8 fails: the provider's module field does not accept oci://. E15 and E16 pass. E17 is 1-2 s.

What CI could not measure, and what each needs:
- Huawei OBS as the bucket (S3 API, checksum headers, conditional writes). The stand-in was SeaweedFS 4.22. Needs a lane-A run on a Huawei Sovereign.
- SEC's real token generator and its 15-minute cadence. The re-mint was a script step. The file update in the pod took 56 s.
- Real cloud resources behind E7 and E15. E7 used a cloud-free copy of the adoption module. E15 used a Kubernetes ConfigMap made by the hashicorp/kubernetes provider as the cloud resource.
- Harbor as the OCI mirror. The stand-in was registry 3.0.0.
- The egress block was simulated with hostAliases, not a NetworkPolicy or firewall.

What later packages must take into account:
- CLD-171: OpenTofu keys the wrapped data key in state meta by the key_provider address (key_provider.openbao.sovereign). Renaming that block makes every existing state unreadable, and the offline drill must use the same name. The transit key backup is refused until the key has exportable=true and allow_plaintext_backup=true; SEC must decide this and record it, with the option-B sign-off. The token TTL must cover the cadence plus about 1 min of file update plus the longest run.
- CLD-172: provider-opentofu forces TF_CLI_CONFIG_FILE=./.tofurc during init, so a pod-level CLI configuration is ignored. Deliver it as a ClusterProviderConfig credentials file named .tofurc (from a Secret, or the Filesystem source), or as Workspace env. The OpenTofu in the provider pod reports v1.10.0, although the upstream Dockerfile names 1.10.8.
- CLD-174, CLD-177 and SOV-230: Remote git with .git-credentials works. The provider pod must trust the Git server's CA (GIT_SSL_CAINFO) unless the CA is public. The credential is process-wide (GIT_CRED_DIR): any Workspace in the pod can read the repository, whatever its ProviderConfig.
- E8 fail: SOV keeps the provider-pack Git repository. An oci:// address works only inside an inline module block, which the admission rule does not allow today.
- SOV: an Observe-only Workspace shows no Ready and no outputs after its first observation. They appear at the next poll (560 s) or 2 s after an annotation change. Hand-over gates that read the base Workspace must allow for this.
- CLD-061 to CLD-066: the path passed three times. Provider v1.1.11 also works on Crossplane 1.18 (E7b), so CLD-066 does not have to wait for CLD-065. The Crossplane CLI 1.20 conversion flag is --function-patch-and-transform-ref.
