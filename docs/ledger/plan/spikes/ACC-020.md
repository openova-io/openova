# ACC-020 — guacd 1.6.0 driven without the web application (lab test result)

## Question

Can upstream guacd 1.6.0 be driven by a small relay and the upstream browser library, with no Guacamole web application and no database? If so, what are the exact handshake, tunnel frames and parameter names, how does recording behave, and what do resources and start time look like? Twelve items, (a) to (l).

## What was run

- Where: GitHub Actions in openova-io/openova, branch `spike/ACC-020`. The branch is never merged. The workflow is `.github/workflows/spike-acc-020.yaml` and the code is under `tests/spikes/ACC-020/`. The branch stays as evidence.
- Runs: 43377123004 (commit 84a8b31f7) and 43378598091 (commit 13b6093de). Both succeeded. Run 2 is the evidence run unless a line says otherwise. Run 2 changed only two test methods: the SSH copy drag now stays clear of the terminal scrollbar, and the VNC paste check now reads x11vnc's own counters.
- Cluster: a throwaway single-node k3s v1.31.4+k3s1 (containerd 1.7.23-k3s2) on the runner (Ubuntu 24.04, 4 CPUs). Traefik and the service load balancer were off. Every Service was ClusterIP, and the log line `services with a node port: 0` confirms there were no node ports. The runner reached the session pod directly on its pod IP.
- Session pod: built to the design's fixed shape. It had `guacd` and `agent` containers, ran as non-root uid 10001 with read-only root file systems, all capabilities dropped and RuntimeDefault seccomp, and used no service-account token. A `/rec` emptyDir was read-write for guacd and read-only for the agent. The pod started in that shape without changes.
- guacd: `docker.io/guacamole/guacd@sha256:8974eaa9ba32f713daf311e7cc8cd7e4cdfba1edea39eed75524e78ef4b08f4f` (the index digest of tag 1.6.0; the amd64 manifest is sha256:f39258e3…e515). It runs on Alpine 3.18.12 with libwebsockets 4.3.5. The pod ran it as `guacd -b 127.0.0.1 -l 4822 -L debug -f`. `guacd -v` prints version 1.6.0.
- Relay: a throwaway Go program, `tests/spikes/ACC-020/agent`. It does the handshake against 127.0.0.1:4822 and relays instructions. It also plays the broker's browser-facing part (subprotocol, first frame, ping echo), and query switches turn each of those parts off. The same binary has a scripted Guacamole client ("driver"), which `kubectl exec` runs inside the pod.
- Browser: Chromium 131.0.6778.33 through Playwright 1.49.1. It loads two throwaway pages that use `guacamole-common-js` 1.6.0 `all.min.js`, taken from the Apache release on Maven Central with its SHA-1 checked.
- Targets: an OpenSSH server (Alpine 3.20.3) that accepts a password and trusts the OpenBao user CA, with no authorized_keys file. An Xvfb with x11vnc. A busybox pod in namespace `acme`. The exec proxy built from `core/cmd/k8s-ws-proxy` on origin/main (source tree ebef3b00 in both runs; main at 8d46b20b1 in run 2), using its existing certificate leg. Its certificates were made with openssl: ECDSA P-256, client CN `guacd.guacamole.svc.cluster.local`.
- OpenBao: a development server, quay.io/openbao/openbao:2.1.0, as a container on the runner. It had an `ssh` mount with an ed25519 CA and role `acc.acme.target` (ca type, allowed user `spike`, ttl and max_ttl 5m, permit-pty only). Certificates came from `ssh/issue` with a 5m TTL. The sessions that used them ran 4 seconds after issue.

## Results, one line per item

- (a) PASS. An SSH session with a password worked through the relay's handshake (4 ms to `ready`): `echo SSHPW-$((6*7))` printed `SSHPW-42` 252 ms later. Through the browser library, the typed command ran in all 4 browser sessions that typed (`BROWSER-81` in each typescript). The relay sent `6.select,3.ssh;` and guacd answered `4.args,13.VERSION_1_5_0,…` with 42 parameter names. The relay then sent `4.size,4.1024,3.768,2.96;` `5.audio;` `5.video;` `5.image,9.image/png,10.image/jpeg,10.image/webp;` `8.timezone,3.UTC;` `4.name,20.jane.roe@example.org;`. Then it sent `7.connect,13.VERSION_1_5_0,…` with one value per name in args order and `0.` for absent names. guacd answered `5.ready,37.$<connection id>;`. guacd's first instruction after ready is `4.size,1.1,1.0,1.0;`.
- (b) PASS. The certificate goes in parameter `public-key`, and the key goes in `private-key`. `public-key` must hold the whole OpenSSH line exactly as OpenBao's `signed_key` returns it (`ssh-ed25519-cert-v01@openssh.com AAAA…`, trailing newline accepted). The base64 body alone fails with `Public key authentication failed: Invalid public key data` (status 769). `private-key` takes `private_key` as returned (`-----BEGIN OPENSSH PRIVATE KEY-----` for ed25519). `ssh/issue` returns the keys `private_key`, `private_key_type`, `serial_number` and `signed_key`. sshd logged `Accepted publickey for spike … ED25519-CERT … ID spike-session-ed25519 (serial …) CA ED25519 …`. Negative control: the same key without the certificate was refused with `Username/PublicKey combination invalid` (769). ECDSA P-256 and RSA 2048 certificates from the same ed25519 CA also logged in.
- (c) PASS. Protocol `kubernetes` reached the exec proxy built from main over its certificate leg: `echo K8S-$((6*7))` printed `K8S-42`, `hostname` printed `exec-target`, and the proxy logged `authMode: mtls`, `cmd: ["/bin/sh"]`. guacd asked for `/api/v1/namespaces/acme/pods/exec-target/exec?command=%2Fbin%2Fsh&container=main&stdin=true&stdout=true&tty=true`. Controls: with no client certificate the proxy answered 401 (`X-Catalyst-Timestamp header missing`) and guacd reported `HS: ws upgrade unauthorized` (status 519). With a per-session certificate from the same CA (CN `session-<uid>`, URI SAN), the proxy answered 401 (`client certificate subject not allowed`).
- (d) PASS. A VNC session to x11vnc reached `ready`. guacd drew a 1024x768 framebuffer (12 `img` instructions) with no error. 51 parameter names.
- (e) PASS. guacd created `screen-<n>`, `typescript-<n>` and `typescript-<n>.timing` in /rec at session start, and they grew during the session. Over 12 s with a command every 2 s, the screen file grew at 11 of 22 samples (35,756 bytes, then 88,946 at close) and the typescript and timing files at 5 each. The longest delay from a keystroke to bytes on disk was 41.7 ms for the key in the screen file (median 2.2 ms) and 39.1 ms for its echo in the typescript (median 2.2 ms). That is 20 keystrokes, polled every 2 ms. Run 1 gave 41.8 ms and 2.5 ms. This is far below 5 s, so the chunk time stays.
- (f) PASS. `Guacamole.SessionRecording` replayed the screen file three ways, with identical duration and final picture: streamed through `Guacamole.StaticHTTPTunnel` in 4,093-byte pieces 5 ms apart (the cuts fall inside instructions), joined from separate 16 KiB parts into one Blob, and as one whole Blob. A browser-session recording (23,921 bytes, 6 pieces) played 19,855 ms in all three ways. A driver-session recording (88,946 bytes, 22 pieces) played 15,583 ms in all three ways. Each ended on a 1024x768 picture.
- (g) PASS. The library opens `ws://<host>/tunnel?<connect data>` with subprotocol `guacamole`. If the server does not select it, the browser fails the handshake (close 1006) and the client reports 519. The first frame the library looks for is an internal instruction with an empty opcode and one argument, the tunnel id: `0.,36.<uuid>;`. Without that frame the tunnel still opens on guacd's first instruction, `tunnel.uuid` stays null, the client reaches CONNECTED, and typed input still runs. Ping: the library sends `0.,4.ping,13.<epoch ms>;` when the socket opens, then again whenever 500 ms have passed since the last ping and data has arrived. The server echoes it unchanged. Without the echo, an idle SSH session stayed stable because guacd sends `sync` about once a second. But an idle VNC session went UNSTABLE 4 times in 22 s and ended UNSTABLE. With the echo it went UNSTABLE 0 times (43 echoes). Forwarded to guacd, an internal instruction is ignored with a log line `Handler not found for ""` each time. Instructions split across WebSocket frames parse correctly. The client also sends `3.nop;` every 5 s, `4.sync,<ts>;` replies, and `3.ack,1.1,37.Receiving argument values unsupported,3.256;` once for each of guacd's three `argv` streams.
- (h) PASS. Control on SSH, with both parameters `false`: a clipboard stream plus the middle button ran `echo PASTE-$((3+4))` and printed `PASTE-7`, and a drag selection sent a `clipboard` instruction 203 ms after release. With `disable-copy` and `disable-paste` both `true`: guacd answered the clipboard stream with `ack,7,Clipboard unsupported,256` and `ack,7,File transfer unsupported,256`, the middle button pasted nothing, and a selection sent no `clipboard` in 6 s. Control on VNC: x11vnc counted 1 ClientCutText and the client received the server's text. With both `true`: x11vnc counted 0 ClientCutText, and the server's ServerCutText was not passed on. Inside an SSH session, a selection made on screen can still be pasted back into the same terminal with the middle button. Nothing crosses to or from the browser (seen in run 1).
- (i) PASS. With `recording-write-existing=true` and `recording-name` naming an existing FIFO in /rec, guacd wrote the screen recording into the FIFO. A reader in the agent container got 28,312 bytes: 165 complete instructions, first bytes after 18 ms, EOF at session end. No new file appeared, and `screen-fifo` stayed a FIFO.
- (j) Measured from the cgroup v2 files of the guacd container. guacd forks one process per connection. With no session: 12.1 MiB (anon 10.0 MiB) and 0.04 % of one core. With one idle SSH session: 31.8 MiB (anon 29.0 MiB, so about +19 MiB per idle session) and 0.07 % of one core. With one active SSH session (30 s of continuous `ls -la` output): 100 % of one core and anon 35.0 MiB. The recording files written to the emptyDir added page cache charged to the same container: 105.4 MiB, 171 MiB peak (run 1: 62.6 MiB and 119 MiB). `kubectl top` showed guacd at 1003m and 42Mi. This is far below 256 MiB per idle session.
- (k) Cold start: 4.01 s from the create call to Ready, including 2.96 s for k3s to pull the guacd image (run 1: 4.48 s, with a 3.05 s pull). Warm: 1.09 s, 1.47 s and 1.05 s (run 1: 1.49 s, 1.69 s and 1.69 s). Readiness is the agent's `/healthz`, which opens a TCP connection to guacd, probed once a second.
- (l) Maven Central has `org.apache.guacamole:guacamole-common-js:1.6.0`, which is both the latest and the release version. The files are `.zip`, `.zip.sha1`, `.zip.md5`, `.zip.asc` and `.pom`. There is no `.sha256` and no `.sha512` (both 404). The zip's SHA-1 and MD5 match. Zip SHA-256: 718cde229cfa601c52ddc201afe3f3ed951b8b756957387776d0c460786f0448. The bundled script is `guacamole-common-js/all.min.js`: 78,778 bytes, SHA-256 cc89f710ecc544477dbe6bfea453fab752dafa1b1ab9770f523676e7b744b44a. The OpenPGP signature is good: key F467E54ACC52F1D2778826865B2977AEE5E4518F (Michael Jumper, code signing key), which is in https://downloads.apache.org/guacamole/KEYS. On the npm registry, `guacamole-common-js` has latest 1.5.0 (2023-03-23) and no 1.6.0. It is published by the user `padarom`, maintained by `padarom` and `tophcodes`, with the repository github.com/padarom/guacamole-common-js. That is not the Apache project. `@apache/guacamole-common-js` does not exist (404), and the other packages on npm with that name are third-party scoped repackagings.

decision: A3 stands

## What follows for the plan

- (a), (c), (e), (f) and (g) all passed. The recorded names and frames above go into the tickets of ACC-104, ACC-106 and ACC-107.
- ACC-107 (broker):
  - Select subprotocol `guacamole`.
  - Send `0.,36.<uuid>;` as the first frame. It is optional, but without it `tunnel.uuid` stays empty.
  - Echo every `0.,4.ping,<ts>;` unchanged. This is required for stability when guacd is idle (VNC).
  - Never forward internal instructions to guacd.
  - Frames need not line up with instruction boundaries.
- ACC-106 (agent): the handshake bytes as recorded. The first `connect` value repeats `VERSION_1_5_0`, followed by one value per name in args order. `public-key` gets the whole certificate line.
- ACC-104 and ACC-132:
  - guacd sends `exec-command` as one `command=` value, and the proxy passes it as one argument. `/bin/echo SPLIT-OK` failed with `stat /bin/echo SPLIT-OK: no such file or directory`. A command with arguments, such as the database kind's psql line, does not work until the proxy splits it or the tool image's entry point takes no arguments.
  - The proxy's certificate leg accepts only a fixed CN or DNS name list, so the per-pod certificate needs the planned proxy change.
  - The proxy drops resize messages. A TTY exists (`/dev/pts/0`), but `stty size` shows no size there, while SSH shows `39 99`.
- ACC-131: the certificate parameter is `public-key` with the full OpenSSH line, and its provisional mark can go.
- ACC-111: the chunk time stays.
  - Idle sessions add about 20 bytes per second (one `sync` a second).
  - Heavy output wrote about 1.3 MB/s of screen and up to 3 MB/s of typescript: 39.8 MB and 94.2 MB in 31 s in run 2. At that rate, an unshipped 2 GiB volume fills in about 8 to 13 minutes.
  - Page cache from these files counts toward the guacd container's memory.
- ACC-211: VNC works, and `disable-copy` and `disable-paste` work for VNC as for SSH.
- (i) is noted as a later improvement. Nothing changes.
- (j): no change to the memory request and no session quota.
- (l): the build stage takes the zip from Maven Central. Maven Central publishes no SHA-256, so the build pins the SHA-256 values above and may also check the `.asc` against the Apache KEYS file. npm is not a source.
- guacd warns `No known host keys provided, host identity will not be verified` when `host-key` is empty.

## What a CI job could not measure

- The full three-hop chain: browser, then broker in the access controller, then agent, then guacd. The spike used one relay that played the broker's browser-facing part and the agent's handshake.
- Cilium policies, the admission policy, and credential files from the CSI mount. The spike used a ConfigMap for throwaway credentials; the mount is ACC-030's subject.
- Multi-node or cross-node timing. The numbers for (j) and (k) come from a single 4-CPU GitHub runner.
- What guacd does when no reader holds the FIFO open.

## What later tasks must take into account

Decision: A3 stands. Items (a), (c), (e), (f) and (g) passed in both runs; all twelve items were measured.

Points later packages must take into account:

1. **ACC-104 / ACC-132 (exec command):** guacd sends `exec-command` as one `command=` value, and the exec proxy on main passes it as one argument. `/bin/echo SPLIT-OK` failed with `stat … no such file or directory`. The database kind's psql command line will not run until the proxy splits the command or the tool image's entry point takes no arguments.
2. **ACC-104 (certificate leg):** the proxy accepts only a fixed CN or DNS name list. A per-session certificate (CN `session-<uid>`, URI SAN) from the same CA got 401 `subject not allowed`, so the per-pod certificate needs the planned proxy change.
3. **ACC-104 (resize):** the proxy drops resize messages (channel 4). A TTY exists, but `stty size` shows no size through it, while SSH shows `39 99`.
4. **ACC-107 (broker):**
   - It must select subprotocol `guacamole`.
   - It must echo `0.,4.ping,<ts>;` unchanged. Without the echo, an idle VNC session went UNSTABLE 4 times in 22 s; an idle SSH session hides this because guacd sends `sync` once a second.
   - It must never forward internal instructions to guacd; guacd logs `Handler not found for ""` for each one.
   - The `0.,36.<uuid>;` first frame is optional; it only sets `tunnel.uuid`.
   - Frames need not line up with instructions.
5. **ACC-131:** the certificate parameter is `public-key`, holding the whole OpenSSH line from `signed_key`. The base64 body alone fails. ed25519, ECDSA and RSA certificates all worked.
6. **ACC-111 (recording):**
   - Keystroke to disk took at most 42 ms, so the chunk time stays.
   - Heavy output wrote about 1.3 MB/s of screen and up to 3 MB/s of typescript, which fills a 2 GiB volume in about 8 to 13 minutes if nothing is shipped.
   - Page cache from the recording files is charged to guacd's container (up to 171 MiB peak).
7. **(l) Build stage:** Maven Central publishes only SHA-1, MD5 and an `.asc` signature, no SHA-256. The build must pin its own SHA-256: zip 718cde22…0448, `all.min.js` cc89f710…b44a. The npm package `guacamole-common-js` (latest 1.5.0) is published by a third party (`padarom`), so npm is not a source.

What a CI job could not measure:

- The full three-hop chain through the access controller. One relay played the broker's browser-facing part and the agent's handshake.
- Cilium policies, the admission policy, and the CSI credential mount. A ConfigMap held the throwaway credentials.
- Multi-node timing. The (j) and (k) numbers come from one 4-CPU GitHub runner.
- How guacd behaves when no reader holds the recording FIFO open.
