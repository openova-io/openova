# NET-270 result: firewall attachment on the Cilium gateway

- Measured: 2026-11-14, 09:51 to 10:40 UTC, three CI runs on one hosted runner, no cloud account.
- Re-read: 2026-11-19 against origin/main 347fc0a5a8 and the upstream Cilium v1.19.3 source.
- Outcome: **ATTACHED**. Coraza runs inside the shipped `cilium-envoy` and meets the pass rule on the public port, through a listener the platform writes in front of the gateway listener. The second tier (test ii) also passed and is the measured fallback.

## Question

Can Coraza inspect requests in the public path of the reference class: k3s, Cilium 1.19.3, Gateway API with the gateway in host-network mode?

- **Test (i).** List the HTTP filters compiled into the shipped `cilium-envoy` image, then attach Coraza to the Cilium-managed gateway through Envoy configuration objects.
- **Test (ii).** A second tier: Envoy Gateway pinned to one release, as ordinary pods on an edge-labelled node with host ports, Coraza attached through its extension point, routing to the same backends. No NodePort. Pod-identity policy still applies to it.
- **Pass rule.** Through the gateway, `GET /?q=<script>alert(1)</script>` returns 403 and `GET /` returns 200, with the Core Rule Set at paranoia level 1 in block mode, and the gateway's other routes keep answering.
- **Outcomes.** `ATTACHED` (i passes), `SECOND-TIER` (i fails, ii passes), `NONE` (both fail).

## Answer

**ATTACHED.**

- The shipped `cilium-envoy` carries `envoy.filters.http.wasm`, and Coraza in it meets the pass rule on the public port 80: clean 200, attack 403, SQL injection 403, every route answering, routes still taken from the HTTPRoutes, through restarts of the operator, Envoy and the agent.
- The attachment is a platform-owned CiliumEnvoyConfig in the Gateway's namespace, in front of the gateway listener, reusing the gateway's route config. A filter cannot be added to the listener the operator writes. A cluster-wide object works only with its own route table.
- `SECOND-TIER` passed as well and stays the measured fallback.

## What later tasks must take into account

1. Never patch the listener the operator writes. Its filter list is fixed in code, and an edit is reverted within 0.2 s.
2. A CiliumClusterwideEnvoyConfig cannot reuse the gateway's route config (404). Use a CiliumEnvoyConfig in the Gateway's namespace, or generate the routes. Cluster names are not rewritten and can be shared across objects.
3. Every platform listener needs `cec.cilium.io/use-original-source-address: "false"`. Without it clean requests get 503 while attacks still get 403.
4. Not measured: HTTPS on either mechanism, request-body rules, added latency, memory without the module, more than one node, two regions, and the reference cloud itself. The cluster was k3s on the runner, not a machine of the `local` pack.
5. A module that cannot start fails closed by design. In https://github.com/envoyproxy/envoy/blob/v1.36.6/api/envoy/extensions/wasm/v3/wasm.proto lines 23 to 37 and 177 to 182, the default failure policy is `FAIL_CLOSED` (HTTP 503), an xDS update whose plugin fails to start is rejected, and a proxy whose plugin fails at its first start does not start. So the file must be on every edge node before the listener is applied. `platform/cilium/chart/values.yaml` has no host-path mount for it today; a remote module source with a pinned sha256 was not measured for `cilium-envoy`.
6. Module delivery. The runs used the release zip from GitHub. The image `ghcr.io/corazawaf/coraza-proxy-wasm:0.6.0` answered an anonymous read on 2026-11-19 (token 200, tag list 200, manifest 200: an OCI index whose amd64 manifest is `sha256:65d6009b9da2e8965e592a08b74a86725435fc01aa39c756dce0bd5ea64b3f4e`). `cilium-envoy` cannot pull an OCI image itself; getting the file from that image onto the node was not measured. The platform serves the `.wasm` from its own registry or over HTTP, with the sha256 pinned.
7. The release notes of coraza-proxy-wasm 0.6.0 (https://github.com/corazawaf/coraza-proxy-wasm/releases/tag/0.6.0) warn that the module, built with tinygo, may leak memory and degrade performance, and recommend extensive testing first. The runs measured 315 to 359 MiB for `cilium-envoy` with the module and did not run long enough to see a leak. NET-250 measures memory over time under load before the firewall is offered.
8. Gateway status `Programmed=False` (`AddressNotAssigned` on Cilium, `NoResources` on Envoy Gateway with a ClusterIP proxy) must not gate anything.
9. The second tier needs a ClusterIP proxy Service with host ports, never a node port.
