# CTL-170 result: where chart-seeded Applications live and who reads them

- Measured: 2026-11-23 at 23:18 UTC, read-only, on hw307 (two regions: A is the writer, B the follower), installed fresh that day; and in the code at commit ddcf793274.
- Answer: **no**. No reader uses the chart-seeded Application of a follower region. A follower region has none: it does not serve the Application kind at all. CTL-174 takes variant A.

## Question

Eleven platform charts render their own Application object (label `apps.openova.io/bootstrap-owned: "true"`) and carry its `spec.placement` and `spec.regions` forward with a `lookup` of the live object. CTL-174 moves that placement into Git. Variant A writes one file for the Sovereign under the intent path `clusters/<fqdn>/intent/`, which CTL-120 makes only the writer region apply. Variant B writes one file per region. The question: does any reader use the chart-seeded Application of a follower region? If yes, the follower needs its own file (B). If no, one file is enough (A).

## What was run

- **Live, read-only.** From the agents' host, with one kubeconfig per region, only `kubectl get`, `kubectl api-resources` and `kubectl version`. Nothing was written.
  - In each region: `kubectl get applications.apps.openova.io -A -l apps.openova.io/bootstrap-owned=true -o json`, the same without the label, the Application CRD, the HelmRelease `bp-catalyst-platform`, the Flux Kustomizations, and the Deployments of the platform's controllers.
  - In region A: the Helm history of the slots `bp-openbao`, `bp-keycloak`, `bp-gitea`, `bp-powerdns`, `bp-valkey`, `bp-grafana` and `bp-harbor`.
- **Code.** Every Go, chart and console file that reads the kind `applications.apps.openova.io`, found with `git grep` on the group, the resource name, the label and the cache kind name `application`. For each reader: which cluster its client points at.

## Why a follower region holds none

1. The only definition of the CRD is `products/catalyst/chart/crds/application.yaml` (line 4). No other chart or manifest defines it.
2. That chart is installed by slot 13, `clusters/_template/bootstrap-kit/13-bp-catalyst-platform.yaml`. Line 62 is `suspend: ${SECONDARY_HR_SUSPEND:=false}`. `infra/providers/_shared/cloudinit-control-plane.tftpl` line 772 sets that value to `"true"` in every region whose role is not `primary`.
3. Each chart renders its Application only under `if and .Values.bootstrapOwned.enabled (.Capabilities.APIVersions.Has "apps.openova.io/v1")` (for example `platform/gitea/chart/templates/application-cr.yaml` line 28). In a follower that condition is false, so nothing is rendered there.
4. The acceptance suite states the same rule: `tests/acceptance/sovereign/internal/suite/journeys.go` lines 912 to 923 ("only the region that runs catalyst-api carries the Application CRD"), after decision record 0015, D1.

Three readers reach a follower region: the generic list and stream of catalyst-api, continuum-controller and the acceptance suite. In a follower all three find no Application kind and read nothing. Neither reads `spec.placement` or `spec.regions`. Every reader of placement runs in, or reads from, the writer region.

## What follows

- **CTL-174:** variant A. One file, `clusters/<fqdn>/intent/platform/placement.yaml`, in the writer's intent path. No per-region scope is needed, and contract C4 is not changed.
- **CTL-174, export:** six slots had no live Application to export from on the measured Sovereign. `ExportPlacement` must write every key anyway, from the seed when the object is absent.
- **CTL-172 and CTL-176:** proceed as written; the follower has nothing for `lookup` to find.

## Evidence

Outcome: **no**. The live reads were made by hand on 2026-11-23 from 23:18 UTC, read-only, from the agents' host with the two kubeconfigs of hw307. There is no CI run for them. The code readers are listed with file and line at commit ddcf793274.

## What later tasks must take into account

1. The answer holds while the Application CRD comes only from the slot-13 chart and slot 13 is suspended in every non-primary region. A change that installs the CRD in a follower region, or runs catalyst-api there, reopens this question.
2. If a follower ever served the kind, three readers would see its objects: the generic resource list and stream of catalyst-api, continuum-controller (status only) and the acceptance suite (Organization Applications by name). None of them uses placement.
3. On a fresh install, six of the slots that enable the chart-seeded Application have none until their next Helm release after the CRD exists.
