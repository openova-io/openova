## Lab test AIP-010: model gateway proof (agentgateway)

### Question

Does agentgateway, the named model gateway, meet the model contract on this platform? Tests T1 to T8 form the pass rule. T9 to T12 are informative. Two more informative tests were added by amendment: task routes (record key `taskRoutes`) and `owned_by` per model object (record key `ownedBy`). They are numbered T13 and T14 here. One more informative observation, T15, records how the meter can learn which backend a request is for, and how request identifiers behave.

### What was run

- **Where.** GitHub Actions in openova-io/openova, on branch `spike/AIP-010`. The branch is never merged. The workflow is `.github/workflows/spike-aip-010.yaml`. The scripts are in `tests/spikes/AIP-010/` (`run.sh`, `stub.py`, `probe.py`, `denials.py`, `record.py`). No cloud account, no secret, and no cluster outside the job were used.
- **Environment.** Each job turns its runner into one k3s node with Cilium. The local provider pack is not merged, so the test ran on k3s with Cilium as the plan allows. k3s used the server flags of a Sovereign control plane: `--cluster-init`, no flannel, no network policy controller, no kube-proxy, no traefik, servicelb or local-storage. Cilium ran with kube-proxy replacement, native routing, socket load balancing in the host namespace only, and its Gateway API controller on, as in the platform values. Flux v2.4.0 came from its install.yaml. Kyverno came from chart 3.8.0 (Kyverno v1.18.0). The platform's own `platform/kyverno-policies` chart (bp-kyverno-policies 1.0.53) ran with `bootstrapMode=false`, the post-handover posture: probes, requests, Cilium label, Flux-managed, Harbor proxy, pinned tag, no NodePort, substrate and local-path rules were all Enforce.
- **Legs.**
  - `platform`: k3s v1.31.4+k3s1 and Gateway API CRDs v1.3.0 experimental, rendered from `platform/gateway-api/chart`. These are the versions Sovereigns run today.
  - `supported`: k3s v1.32.13+k3s1 and Gateway API v1.4.1 experimental. This is the lowest Kubernetes minor agentgateway 1.7 supports, and the only Gateway API minor that both agentgateway 1.7 (1.4 to 1.6) and Cilium 1.19.3 (built against 1.4) support.
  - `gwapi16`: setup only, on k3s v1.32.13 with Gateway API v1.6.3 standard.
- **Gateway.** agentgateway v1.7.0, published 2026-10-27. It is the newest release at least 14 days old on 2026-11-13.
  - Charts: `oci://cr.agentgateway.dev/charts/agentgateway-crds:v1.7.0` and `oci://cr.agentgateway.dev/charts/agentgateway:v1.7.0`.
  - Images: proxy `cr.agentgateway.dev/agentgateway@sha256:60216aafb03d37f94e952ff3d51d2f630a65b10ecaebdc0a864882f92610c45b` and controller `cr.agentgateway.dev/controller@sha256:87c1363bf0cbc7fdb375866e592294114c8763097d2d0c9fc45fcb1fe00a4ab8`.
  - Both were installed by Flux HelmReleases, as a kit slot would install them. Images were addressed by Harbor-proxy-style names (`registry.spike.invalid/proxy-agentgateway/...`). The node resolved those names through a containerd mirror and a pre-import, so the `*/proxy-*/*` rule applied unchanged.
- **T1 procedure.**
  - Round A used the upstream values plus the image registry only.
  - Round B used the knobs upstream offers: chart values, a release post-render patch, and the gateway's parameters overlays.
  - After round B, every remaining denial would have been turned into a Kyverno PolicyException and counted. None was needed.
  - The Gateway's parameters object set its Service to ClusterIP before the Gateway existed. No NodePort or LoadBalancer Service was ever created: the guard loop deleted nothing, and every Service listed node port 0.
- **Scaffolding (throwaway).**
  - A key-set server stood at Service `catalyst-api`, namespace `catalyst-system`, port 8080. It answered `GET /api/v1/auth/signers.jwks` with `{"keys":[{"kty":"RSA","use":"sig","alg":"RS256","kid":…,"n":…,"e":"AQAB"}]}` and `Cache-Control: max-age=300`.
  - The scripted backend had the contract's stub behaviour plus test modes. It recorded every request it received. It ran as two instances behind the Services `meter-simulation`, `meter-stub` and `meter-timeout-probe` (instance A) and `meter-selfhosted` (instance B).
  - Tokens were RS256. The `kid` was the RFC 7638 thumbprint, and the claims followed the contract (`aud` = model-gateway, platform-tools, catalyst-api; `org_id`; `agent`; `typ: agent`; 1,800-second life).
- **Gateway configuration.**
  - One Gateway with two listeners: `llm` on 8080 (agent tokens) and `vk` on 8090 (virtual keys).
  - One AgentgatewayModel per alias, all with the Custom provider, format Completions, and a backend Service reference.
  - AgentgatewayPolicy objects for token verification and identity headers, timeouts, and virtual keys.
  - Test traffic went from the node to the gateway's ClusterIP.
- **Runs.** Run 1 (43372601537) gave a full platform leg. Its supported leg used Gateway API v1.6.3; setup failed, and the job was cancelled, so its log was lost. Run 2 (43376048025) fixed two test-harness checks: T8 now tells the backends apart by instance, and T11 now checks the content. It added T14 variants and T15. Run 3 (43378222530) repeated run 2 without the ReferenceGrant for the key-set reference. Runs 2 and 3 are the evidence below. Their platform and supported legs gave identical results.

### Measured values (runs 2 and 3, both legs unless stated)

- **T1 pass.** Exceptions needed after round B: **0**. The controller and proxy Deployments became Ready.
  - Round A denials: the controller Deployment was denied by `probes-present` (no liveness probe). The proxy Deployment that the controller generates was denied by `flux-managed` and `probes-present`.
  - Round B configuration:
    - Chart values: image registry, `podLabels: {policy.cilium.io/enforced: "true"}`, resources.
    - HelmRelease `postRenderers` patch that adds a liveness probe to the controller. The chart has no value for it.
    - AgentgatewayParameters overlays: proxy resources, a liveness probe on container `agentgateway`, the Flux provenance labels `helm.toolkit.fluxcd.io/name` and `helm.toolkit.fluxcd.io/namespace` on the generated Deployment and Service, and Service `type: ClusterIP`.
  - Audit-only findings on both Deployments: `multi-replica-drainability`, `otel-injected`, `resource-limits`.
- **T2 pass.** Two tools were sent as compact JSON. The exact bytes of each tool object appeared in the body the backend received. The `tool_calls` returned to the caller were equal to the backend's: identifiers `call_spike_A1` and `call_spike_B2`, both names, and both argument strings, including non-ASCII characters and escaped quotes.
- **T3 pass.** The tool-call argument was streamed in three chunks five seconds apart. The caller received the first chunk 0.040 to 0.041 s after the backend sent it. The second and third chunks took 0.000 to 0.001 s.
- **T4 pass.** A valid token gave 200. Each of the following gave 401: no token, a bad signature (an unpublished key with the published `kid`), an unknown `kid` signed by the published key, an unknown `kid` with an unpublished key, a wrong issuer, an expired token, and an `aud` without `model-gateway`. As an extra case, `aud` as a single string `model-gateway` was accepted.
- **T5 pass.** The caller sent forged `x-openova-organization`, `x-openova-principal`, `x-openova-principal-kind` and `x-openova-alias`.
  - The backend saw exactly one value of each: organization `acme` (from `org_id`), principal `correlator` (from `agent`), kind `agent`, and alias = the caller's `model`. No forged value reached it.
  - The `Authorization` header is removed before the backend.
- **T6 pass.** `agent-default` reached the backend as `sim-default`, and `agent-fast` as `sim-fast`. An unknown model gave 404 `{"error":{"message":"Model not found","type":"invalid_request_error","code":"model_not_found"}}`. The `model` field in the response to the caller is the upstream name (`sim-default`), not the alias.
- **T7 pass.** With the timeouts set to 1,800 s, a backend silent for 600 s answered: 200 after 600.002 to 600.003 s. Two informative variants:
  - A stream that sent its headers and then stayed silent 600 s also completed.
  - A control backend Service with `backend.http.requestTimeout: 5s` gave 504 `request timeout` at 5.002 s.
- **T8 pass.** `kubectl apply` moved alias `agent-fast` from `meter-simulation` to `meter-selfhosted`. Answers came from the new instance on the first poll after `kubectl apply` returned (0.0 to 1.0 s). The proxy pod's name, UID and restart count were unchanged.
- **T9 pass (informative; `messagesRoute: pass`).** `POST /v1/messages` with one tool returned a `tool_use` block (`call_spike_T9`, `get_weather`, `{"city":"Muscat"}`). The backend received `/v1/chat/completions` because the Custom provider declared only `Completions`.
- **T10 pass (informative).** The virtual key came from a ConfigMap labelled `agentgateway.dev/apikey: "true"`, with `keyHash: sha256:<hex of the key bytes>` and metadata.
  - The backend saw organization `acme` and principal `billing-app` from `apiKey.organization` and `apiKey.name`, with kind `application`.
  - An unknown key gave 401. An agent token on the key listener gave 401.
- **T11 pass (informative).** An 8,388,678-byte request passed. The backend received an 8,388,666-byte body whose 8,388,608-byte user content was intact. The 12 bytes are the alias rename: the gateway re-encodes the JSON body.
- **T12 (informative; `kidlessAccepted: false`).** A token signed by the published key without a `kid` header was refused with 401.
- **T13 pass (informative; `taskRoutes` embeddings, rerank and transcription all pass).** `/v1/embeddings`, `/v1/rerank` and `/v1/audio/transcriptions` each gave 401 without a token and 200 with one. Each reached the backend path of the same name with organization `acme`, and no forged header reached the backend. Embeddings and rerank used Custom formats `Embeddings` and `Rerank`. Transcription used the `OpenAI` provider with a `baseURL`.
- **T14 pass (informative; `ownedBy` is settable).**
  - `owned_by` equals `custom.providerOverride` only when the alias rename is not in `policies.transformations`.
  - With the rename in `policies.transformations`, discovery drops the provider and `owned_by` is `openai`.
  - With the rename in `policies.finalTransformations`, `owned_by` was `simulation` and the backend received `sim-default`.
  - Without a rename, `owned_by` was `stub`.
- **T15 (informative, extra).**
  - The backend sees the caller's `Host` (the gateway address, `<ClusterIP>:8080`) by default.
  - With `traffic.hostRewrite: {mode: Auto}`, the backend sees `meter-stub.model-gateway.svc.cluster.local`, with no port.
  - A per-model header set in AgentgatewayModel `policies.headers.request.set` reached the backend, and a forged value was replaced.
  - A caller's `x-request-id` is forwarded unchanged. None is generated by default, neither to the backend nor in the response. A CEL transformation using `uuid()` generated one, and a response transformation echoed it to the caller.
- **ReferenceGrant.** None is needed for the cross-namespace key-set Service reference: run 3 passed T4 without one.
- **Key set.** The controller, not the proxy, fetches the key set from `http://catalyst-api.catalyst-system.svc.cluster.local:8080/api/v1/auth/signers.jwks`. It stores it in ConfigMap `jwks-store-<hash>` in the gateway namespace. `cacheDuration` is at least 5m.
- **Versions.**
  - agentgateway 1.7.x supports Kubernetes 1.32 to 1.37 and Gateway API 1.4 to 1.6, according to its own support table. The platform leg passed every test on k3s 1.31.4 with Gateway API v1.3.0, but that combination is outside the upstream support range.
  - In leg `gwapi16`, Cilium 1.19.3's operator exits fatally on Gateway API v1.6.3 standard CRDs: `no matches for kind "TLSRoute" in version "gateway.networking.k8s.io/v1alpha2"`. This reproduced in runs 2 and 3.
  - Gateway API v1.4.1 experimental worked with both Cilium and agentgateway.

### Outcome

**pass.** T1 to T8 passed on both legs in runs 2 and 3, with zero policy exceptions.

### What follows for the plan

1. **AIP-140 stands as written.** It takes the values above. The chart depends on two upstream charts: `agentgateway-crds` and `agentgateway`.
2. **The kit slot needs configuration, not exceptions.**
   - A HelmRelease `postRenderers` patch adds a liveness probe to the controller Deployment.
   - The gateway's AgentgatewayParameters must carry the proxy liveness probe, resources, Service `type: ClusterIP`, and the Flux provenance labels on the generated Deployment and Service.
   - The parameters object must exist before the Gateway. The default proxy Service type is LoadBalancer, which allocates node ports and is refused by `forbid-nodeport-service`.
   - The architect should confirm that stamping Flux provenance labels on objects the controller generates is acceptable. The alternative is a `flux-managed` carve-out for `app.kubernetes.io/managed-by: agentgateway`, and that would count as one policy exception.
3. **The meter cannot pick its upstream by the `Host` header as the gateway sends it by default.** There are two measured ways:
   - Set `traffic.hostRewrite: {mode: Auto}`. The meter then keys on `<service>.<namespace>.svc.cluster.local`.
   - Set a per-model request header in the AgentgatewayModel `policies.headers`. The meter then keys on that header.
4. **`x-request-id` is not generated by default.** The chart must add the CEL transformation (`uuid()` when the caller's value is absent or invalid) and a response transformation that echoes it.
5. **`owned_by`.** Put the alias rename in `policies.finalTransformations` and set `custom.providerOverride` to the backend key. The gate check for `owned_by: stub` on `conformance-echo` depends on this.
6. **Timeouts are per backend Service, not per alias.** Two aliases that share one backend Service share one timeout. Either render one meter Service per alias, or accept per-backend timeouts.
7. **No ReferenceGrant is needed** for the key-set reference into `catalyst-system`.
8. **Task routes (AIP-145).** The gateway itself can serve embeddings, rerank and transcription, with the credential check and header removal. The meter does not need to serve them.
9. **Versions.**
   - Sovereigns run k3s 1.31 and Gateway API CRDs v1.3. Both are below agentgateway 1.7's declared support. Every test still passed on them.
   - To be inside upstream support, bump k3s to 1.32 or later, and bump the Gateway API CRDs to v1.4.x experimental only.
   - v1.6.3 standard crashes Cilium 1.19.3's operator. v1.5 was not tested.
10. **Not measured in CI.**
    - A real Sovereign: several nodes, WireGuard, the real Harbor proxy (simulated here by mirror names), the real catalyst-api key-set route (not built yet; a throwaway server returned the same body shape), the real meter, the chart's CiliumNetworkPolicy objects, the global Service across regions, and the vcluster replicated Service.
    - The policy flip from bootstrap to Enforce: the policies were installed at the post-handover posture directly.
    - These need a non-production Sovereign after AIP-120 and AIP-140 are built.

## What later tasks must take into account

Outcome pass: T1-T8 passed on both legs (platform: k3s v1.31.4 + Gateway API v1.3.0; supported: k3s v1.32.13 + Gateway API v1.4.1) in runs 2 and 3, with zero Kyverno policy exceptions. Branch spike/AIP-010 (commits e4b49a10f, 9f50e3d86, e040c846d) is left in place as evidence. Three pushes used.
