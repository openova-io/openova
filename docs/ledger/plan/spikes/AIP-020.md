# AIP-020: simulation back end proof (the agent kit turned inside out)

## Question

Can Axon use its agent kit as a pass-through model back end? The kit is `@anthropic-ai/claude-agent-sdk` 0.3.220, which runs Claude Code 2.1.220 as a child process. Passing through needs six things:

1. The caller's tools reach the model unchanged.
2. A tool call comes back to Axon and is not executed.
3. The run waits up to 600 seconds for the caller's tool result, then continues.
4. No built-in tool can run.
5. The child holds only an access token.
6. The token usage of each model message can be read exactly from the raw stream.

## Outcome

**pass.** Every mandatory test passed: T1, T3, T5, T9, and both T4a and T4b. They passed in three separate runs of the full suite. `childAuth` is `env`.

Two points need the real login, so CI could not measure them:

- T8: how many calls per hour the login allows before the first 429.
- Whether the live service accepts a short-lived access token passed in the environment. The kit sends the same auth and beta headers whether the token comes from the environment or from a credential file. So this point carries little risk.

## What was run

- **Where.** GitHub Actions in openova-io/openova, on the branch `spike/AIP-020`. The branch is never merged. The workflow is `.github/workflows/spike-aip-020.yaml`. The scripts are in `tests/spikes/AIP-020/`: `run.mjs` drives the kit, and `mock.mjs` is a scripted model endpoint.
- **Machine.** Runner ubuntu-24.04 (image 20261028), 4 vCPU, 16 GB RAM. Tests ran in the container `node:22.17.0-bookworm-slim` (Node v22.17.0).
- **Versions.** The same versions as Axon's lockfile:
  - kit 0.3.220, whose child is Claude Code 2.1.220 (native linux-x64 binary)
  - `@modelcontextprotocol/sdk` 1.30.0
  - `@anthropic-ai/sdk` 0.111.0
  - `zod` 4.3.6
- **Steps.**
  1. Install the kit, with network on.
  2. Run `node run.mjs` in a container started with `--network none`.
  3. Print the tail of each child's debug log.
  4. Upload the evidence as an artifact.
- **Two suites run as parallel jobs.**
  - `full`: tests T1 to T10, plus informative variants T3x, T4c, T6r, T5b, T11a and T11b.
  - `extra`: X1 (capacity), X2a to X2c (ending a parked run) and X3a/X3b (egress).
- **No login and no secret.** The tokens were random fake strings.
- **The scripted model endpoint.**
  - It replaces the model. The child reached it through `ANTHROPIC_BASE_URL`.
  - The same listener was the child's HTTPS proxy. It logged and refused every other host.
  - For each test it gave a fixed answer: a tool call, a text answer, or a call to a built-in tool.
  - It sent distinctive token counts for model message n: input 1000+n, cache-write 2000+n, cache-read 3000+n, output 4000+n. This let the script check the kit's stream against what was sent.
- **One test is one `query()` call with the run options the design fixes:**
  - `model`, `systemPrompt`, `tools: []`, `settingSources: []`
  - `mcpServers: { t }`, `allowedTools: ["mcp__t"]`, `permissionMode: "dontAsk"`
  - `persistSession: false`, `includePartialMessages: true`
  - `env`: the process environment without `CLAUDECODE`, `HOME` on a new memory-backed directory, and the token
  - an `abortController` for each run
- **The tool server.**
  - It is the kit's server constructor (`createSdkMcpServer` with no tools), with low-level `tools/list` and `tools/call` handlers set on its `instance.server`.
  - The list handler returns the caller's tools unchanged.
  - The call handler returns a promise that the script answers later. It never executes anything.
- **What scripting the model means.** The model's choices are scripted, so the tests measure the kit, which is the part in doubt. They do not measure whether a real model chooses to call a tool, or real token counts.

## Results

The reference run is 43376542457, and the values below come from it unless noted. Runs 43378019535 and 43379311101 repeated the full suite with the same results.

- **T1: pass.**
  - The model request offered exactly the caller's tools, as `mcp__t__convert` and `mcp__t__lookup`. The input schema of `lookup` was byte-equal to the caller's.
  - The scripted tool use `mcp__t__lookup` with input `{"city":"Muscat","days":3}` reached the caller's assistant message unchanged.
  - The handler was called with name `lookup` and the same arguments.
  - Its answer reached the endpoint as the `tool_result` for the same tool-use id.
  - The run ended with `success` and the endpoint's final text.
- **T2: pass (informative).**
  - The tool-use id is in the call request at `request.params._meta["claudecode/toolUseId"]`.
  - The same value is in the handler's second argument at `extra._meta["claudecode/toolUseId"]`.
  - `_meta` also holds a `progressToken`.
- **T3: pass.**
  - The handler answered after 601 seconds.
  - The run did not end during the wait. The kit emitted a `tool_progress` message about every 30 seconds.
  - After the answer, the tool result reached the endpoint with the right id, and the run ended with `success`.
  - No `MCP_TOOL_TIMEOUT` was set. The server config of the kit has no timeout field, and the kit's default tool timeout was enough.
  - T3x set `MCP_TOOL_TIMEOUT=660000` and gave the same result.
  - Runs 43375030855, 43378019535 and 43379311101 gave the same result.
- **T4a: pass.**
  - Only `CLAUDE_CODE_OAUTH_TOKEN` was set, with no credential file.
  - Every model request carried `Authorization: Bearer <that token>` and no `x-api-key`.
  - No credential file was created. Under `HOME`, the kit wrote only `.claude.json`, one backup of it, and a telemetry spool.
- **T4b: pass.**
  - Only a credential file was given, with `refreshToken: ""` and expiry one hour ahead.
  - Every model request carried its access token as Bearer.
  - The file's hash and modification time did not change.
- **Same headers for T4a and T4b.** The `anthropic-beta` list was identical; it includes `oauth-2025-04-20`. The user agent was identical: `claude-cli/2.1.220 (external, sdk-ts, agent-sdk/0.3.220)`.
- **T4c: informative, added.** The credential file's token expired in 60 seconds, with an empty refresh token. The kit still used the token and did not rewrite the file. There was no sign of a refresh attempt: the only other host contacted was `api.anthropic.com`, which every run contacts.
- **T5: pass.**
  - With `tools: []` and `settingSources: []`, the session's tool list was only `mcp__t__convert` and `mcp__t__lookup`. Model requests offered only those two.
  - The scripted model then asked for the built-in `Read` on a local file. The kit did not run it. It answered `<\tool_use_error>Error: No such tool available: Read. …<\/tool_use_error>`.
  - The file's content never reached the endpoint, and no handler was called.
  - T5b had no tool server. It offered no tools and refused `Read` in the same way.
- **T6: `sequential` (informative).**
  - The tools had no annotations. The kit invoked the second handler of one model message only after the first was answered.
  - In T6r the tools carried `readOnlyHint: true`. Both handlers were invoked together, 2 ms apart.
  - In both cases each result reached the endpoint under its own id.
- **T7: informative.**
  - `rssActiveMi` 223: the highest resident memory while a 15-second answer streamed. Each child is one process.
  - `rssParkedMi` 243.1: measured after 600 seconds parked. It stayed between 242.5 and 243.6 over 20 samples.
  - Other runs gave active 224.2, 234.6 and 236.9, and parked 240.7, 242.5 and 255.0.
- **T8: not run.** It needs the real login.
- **T9: pass.** For each model message, the raw `message_start` carried exactly the input, cache-read and cache-write counts the endpoint sent. The last `message_delta` carried the output count. Example: 1006, 3006, 2006, then 4006.
- **T10: informative.**
  - One model message with text and two tool uses gave 3 assembled `assistant` messages, one per content block.
  - Each repeated the same usage block, and that block's `output_tokens` was 1, the `message_start` value.
  - The real output count (4009) was only in the raw `message_delta`.

## Other measured facts

1. **Hidden title call.**
   - Before its first step, every run sends one extra request to the same model, with no tools. The kit's debug log names its source `generate_session_title`.
   - Setting the `title` option removes it (T11a).
   - Without the option, each chain spends one more model call against the login's limit.
2. **System prompt prefix.**
   - Before the caller's system prompt, the kit sends two blocks of its own: `x-anthropic-billing-header: cc_version=…; cc_entrypoint=sdk-ts;` and `You are a Claude agent, built on Anthropic's Claude Agent SDK.`.
   - The caller's system prompt follows unchanged.
3. **Egress.**
   - Besides the model endpoint, the child contacts `api.anthropic.com:443` for bootstrap data, an MCP registry and event logging. The test refused all of it, and no run was affected.
   - With `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, a run made 0 such attempts, against 4 by default. It also skipped the title call (X3a, X3b).
   - `strictMcpConfig: true` removed only the MCP-registry fetch (T11b).
   - With the token in the environment, the kit skipped the account's claude.ai connectors. Its debug log says "Missing user:mcp_servers scope (scopes=user:inference)".
4. **Ending a parked run (X2a to X2c, run 43379311101; X2a also in run 43378019535).**
   - `abortController.abort()` and `close()` each end the child within about 51 ms.
   - But 10 ms after the call, the child first sends one more model request. It carries a made-up result for the pending tool call, `(mcp__t__lookup completed with no output)`, with `is_error` false.
   - `interrupt()` sends no further request. The run ends with result `error_during_execution`, and the child exits within 54 ms.
5. **Capacity (X1).**
   - Twelve chains were parked at once, the default 4 active plus 8 parked.
   - The children used 2919.2 MiB in one run and 2929.9 MiB in the other: 240.4 to 252.3 MiB each, one process each.
   - The parent node process used 90.8 to 109.1 MiB.
   - All 12 went on to `success` once their handlers were answered.
   - The current memory-limit formula gives 512 Mi + 300 Mi × 12 = 4112 Mi. Measured use was about 3.0 GiB.
6. **Server construction.** `createSdkMcpServer({name: "t", tools: []})` works when followed by `registerCapabilities({tools: {}})` and `setRequestHandler` on `instance.server`. The session reported server `t` as `connected`.

## What is left

These need the real login. The operator runs them on a signed-in workstation or on the standing Sovereign:

1. **T8.** Count the sequential 2,000-token calls completed in one hour before the first upstream 429.
2. **T4a against the live service.** Make one call with a current short-lived access token in `CLAUDE_CODE_OAUTH_TOKEN`. This is a confirmation, because the headers match the credential-file path.
3. **T7 with real conversation sizes.** The CI figures come from short scripted conversations.
4. **claude.ai connectors with a file credential.** Check whether the account's connectors load when the child holds a full-scope credential file. With the token in the environment they are skipped for lack of scope.

## What follows for the plan

1. **Epic AIP-100** stands as written. Children receive the token through the environment variable.
2. **AIP-102, matching results to handlers.**
   - Match each handler to its tool call by `_meta["claudecode/toolUseId"]` of the call request.
   - For tools without annotations, the kit invokes one handler after another. So a result must be stored until its handler is invoked, and the two-map design is needed as written.
   - The first-in-first-out fallback is not needed for 0.3.220. It costs nothing to keep.
3. **AIP-102, usage.** Confirmed: usage must come from the raw stream events. The assembled messages repeat one usage block per content block, and its output count is the `message_start` value (1), not the real one.
4. **AIP-102, closing a run.** `close()` must call `interrupt()` first. Abort or `close()` alone sends one more upstream call with a made-up empty tool result.
5. **Run options, for the architect to approve.**
   - Add `title` with a fixed string, to drop the hidden title call.
   - Set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` in the child environment, so the child talks only to the model endpoint.
6. **Simulation limits.** Add that the kit puts two blocks of its own before the caller's system prompt.
7. **AIP-104, memory.** A child uses about 225 to 255 MiB and the parent about 100 MiB. At the defaults the current formula leaves about 1 GiB of headroom. AIP-104 can keep it, or lower the per-child term after T7 is run with the real login.
8. **Kit upgrades.** The kit is pinned. Re-run this workflow whenever its version changes.
