## Why the namespace was created by hand (ruling 189)

The readers on main (`cloudprofile.InstallationNamespace`) and the delivers text of this package name `catalyst-system`. The parent's engine runs in namespace `catalyst`, and `catalyst-system` did not exist: a server-side dry run of the ConfigMap answered `namespaces "catalyst-system" not found`. Ruling 189: the parent gets the namespace, created by hand, because changing where the readers look would be a larger change than one empty namespace, and no running reader changes behaviour (next section). The engine's ServiceAccount `catalyst/catalyst-api-cutover-driver` may get and list ConfigMaps there (`kubectl auth can-i`: yes, yes).
