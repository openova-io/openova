# FND-079 Operator action: the gate has a scoped access to the parent (result)

Date: 2026-11-18, 23:05 to 23:40 UTC, one session, by hand on the mothership (its Flux controllers are scaled to zero). Outcome: **done**. The parent's API server is reachable from the public internet, the access exists with the rights below and nothing more, and its kubeconfig is the secret `ACCEPTANCE_PARENT_KUBECONFIG` of the environment `gate`, which only the default branch may use.

## Question

Can a job on a machine hosted by GitHub reach the parent (the mothership) with a credential that does only what the gate needs: run short-lived Jobs in one namespace, and run CLD-G12 (`scripts/check-zero-change-plan.sh`) in the engine Pod?

## Reachability

- The API server is `https://45.151.123.50:6443` (k3s v1.34.4, one node, `--tls-san 45.151.123.50`, no source allow-list).
- From this host: `GET /version` answers 401. From six outside probes (Germany, France, Italy, Netherlands, Poland, Ukraine): TCP connect to port 6443 in 13 to 59 ms. A hosted runner reaches it. Nothing was opened for this.

## Rights and what could not be narrowed

`kubectl auth can-i --list` with the credential: in `acceptance-gate` exactly jobs.batch and pods [create get list watch delete], pods/log [get], secrets [create delete]; in `catalyst` exactly deployments.apps `catalyst-api` [get], pods [get list], pods/exec [create]; nothing in any other namespace and nothing cluster-wide (beyond the self-review rules every account has).

Not narrowable with RBAC: pods/exec and get/list on pods in `catalyst` hold for every Pod of that namespace, because a rule cannot select Pods by label and the engine Pod's name changes at every rollout. Today that reaches `catalyst-api` (the target) and `catalyst-ui`. Narrower would need an admission policy keyed on the Pod name; none was added.

The workflow's header is enough as written: with only create on pods/exec, `kubectl exec deploy/catalyst-api` worked with kubectl 1.31 and 1.34 (with and without stdin).

## The credential

A bound ServiceAccount token (`kubectl create token --duration=720h`), issued 2026-11-18T23:14:43Z, **expires 2026-12-18T23:14:43Z** (30 days). The kubeconfig names `https://45.151.123.50:6443` and the cluster CA from the ConfigMap `kube-root-ca.crt` of `acceptance-gate` (the admin kubeconfig of the hosts skips TLS verification and carries no CA, so it is not a source). It was assembled under /dev/shm, never printed, and shredded after the proofs.

Rotate before the expiry: (1) `kubectl -n acceptance-gate create token gate --duration=720h`; (2) assemble the kubeconfig as above in /dev/shm; (3) `base64 -w0` it into `gh secret set ACCEPTANCE_PARENT_KUBECONFIG --env gate -R openova-io/openova`; (4) shred the files. Revoke at once: delete and recreate the ServiceAccount `gate` (its tokens are bound to its UID; the RoleBindings name it and apply to the new one).

## Removal

```sh
kubectl delete namespace acceptance-gate
kubectl -n catalyst delete rolebinding acceptance-gate-cld-g12
kubectl -n catalyst delete role acceptance-gate-cld-g12
gh secret delete ACCEPTANCE_PARENT_KUBECONFIG --env gate -R openova-io/openova
```

The branch policy of `gate` stays; it is wanted with or without this access.

## What later tasks must take into account

1. FND-078: a Job Pod must state requests and limits (the quota), the restricted security context and `automountServiceAccountToken: false`; the run's Secret can be created and deleted but never read back, so the Job mounts it.
2. The mothership's API drops connections now and then (`http2: client connection lost`, TLS handshake timeout: seven times in about 30 minutes). The Job script must retry each call.
3. `kubectl auth can-i create pods/exec` reads `exec` as a Pod name and answers about creating Pods; ask with `--subresource=exec`.
4. `ACCEPTANCE_KUBECONFIG_A` and `ACCEPTANCE_KUBECONFIG_B` are repository secrets, not secrets of the environment `gate`, although the workflow's header says so. Moving them belongs to the guard work of FND-078.
5. The token expires on 2026-12-18; rotate it before then.
