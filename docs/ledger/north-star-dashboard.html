Where we started and where we are

Each bar is the whole target for that area. Dark blue is what the platform's agents had already built on 12 November, after nine months of work: 25,978 commits, 4,464 merged pull requests, 100 Blueprint charts, 1,032 Go test files, 56 browser test specs. Green is what has been added since. Grey is still to do.

How the estimate is built. Measured on the first eight tasks: an Opus 5.5 session executes a task in 2 to 9 minutes with about 2.4 million cached and 90 thousand new tokens. Writing and proof-reading its exact instruction costs about 0.5 million tokens and 20 minutes. Checks and review add about 10 minutes. A product task then waits for the next update of the environment (every 4 hours); a first-boot task waits for the next fresh install (one a day).

Which tickets ship in which batch

A product change ships in an update of the running environment (R). A change to first-boot files ships in a fresh install (F), which creates the next environment. Repository-only tasks are merged one by one and are listed last. The batch a ticket lands in is fixed by what it depends on; the environment name and the date are indicative and move when an environment is replaced earlier or a provisioning fails.

What works today and is kept

  • Installation in two regions, with an application installed, moved between regions and deleted cleanly (proven 11 November).
  • Delivery by Flux in every region.
  • The console core, updated live by events.
  • One boot template shared by both clouds.
  • The billing engine, running on the live environment.
  • 24 baseline policies and a compliance score.
  • The vault and its region-to-region sync.
  • The acceptance test suite and its run records.
Delivered since 12 November

Eight tasks, merged and closed

  • The plan lives in the repository and a tool guards it.
  • CI refuses a change that leaves its allowed files or skips its tests.
  • The test gate judges a feature only from recorded runs.
  • Billing and tool-server tests run before a merge, not after.
  • Every Go module is tested on a pull request, or listed.
  • New Go code is linted; old findings do not block.
  • The policy tests, including the NodePort ban, run on every pull request.
  • A secret is no longer copied into three retired namespaces at first boot.

None of these is a product feature. They are the rails for everything in the backlog. The tickets on GitHub
