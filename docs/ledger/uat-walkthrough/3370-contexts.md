**Result:** ✅ 7 / ❌ 12 (0 un-walkable). The **Contexts model on `shared-pg` is genuinely live** — the 3-row Contexts table (db/gitea·db/registry·db/keycloak, all ready), the consumer-link nav, the PG hero `⛓ shareable · db` badge, the 3-instance table + topologies, and the Valkey `⛓ shareable · keyspace` hero all render correctly. The failures cluster in **discovery + provisioning surfaces**: (1) the **PostgreSQL Blueprint has no card in the Apps·Catalog grid** and the **3 shared-pg instances have no cards in the Apps·Deployments grid** (reachable only by direct URL / the catalog Instances table); (2) the **Harbor "+ New instance" wizard exposes no Backing-services / PostgreSQL selector** (Topology stuck on "Loading…"), so the entire Create-new vs Reuse-existing journey (rows 13–17) is non-existent; (3) the **`bp-gitea` Dependencies tab** shows generic "Pulls in: CloudNative PG", not the `shared-pg / db:gitea` binding; (4) **Valkey has no keyspace Contexts** populated.

**Gaps (confirmed/extended):** Data-instances panel — not present on the PG catalog page; "never removed from the tenant console" half unverified from this walk. The 3 bootstrap DBs reuse-rejection couldn't be exercised because the Harbor backing-services selector is missing entirely (the reuse UI itself is absent, a broader gap than just shared-pg rejection).
