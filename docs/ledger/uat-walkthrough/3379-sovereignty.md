**Result:** ✅ 4 / ❌ 2. Baseline user-facing surfaces all pass — the console loads signed-in, the Apps page renders the full catalog, and both apps (grafana SSO + gitea served from the Sovereign's own local services) render signed-in with no login form. The two ❌ are the honest gaps: (1) there is **no** console UI/badge that surfaces "this Sovereign is now independent / cutover complete", and (2) the **after-cutover** install/local-registry-pull row is unverifiable because **cutover has never been run** on hw133. This confirms the ticket's own framing: sovereignty cutover is an **ops process with almost no end-user UI** — the only positive UI acceptance is the negative one (nothing the user touches breaks), and that baseline holds.

**Verdict:** **not an end-user-UI feature** — an operations process. The only valid web-UI acceptance is the **negative** one (after going independent, the user sees no change). Today the cutover has **never been run** on any handed-over environment, so the post-cutover rows are unexecuted; the baseline (console + apps currently work) does hold.
