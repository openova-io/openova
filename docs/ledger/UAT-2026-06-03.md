## How to read & fill this document

**Result legend** (exactly one per Result cell): ✅ PASS *(evidence required)* · ❌ FAIL *(file defect, leave issue open)* · ⛔ BLOCKED *(couldn't attempt)* · ⏭️ N/A · ☐ NOT WALKED.

Rules: no ✅ without a committed screenshot link; walk top-to-bottom; the executor is **read-only** on the product and **never closes the issue**; report the screen you saw, not the one you expected; "looks right from the code" is banned.

> **Why this walk is BLOCKED, honestly:** a clean zero-touch prov (hw89) was raised to walk these journeys. Its Phase-1 reconcile surfaced — and self-healed from git — two real bugs (#2982 dmz host-namespaces, #2985 external-secrets↔openbao deadlock), then **terminally stalled** on a 3-way SSO-bootstrap deadlock ([#2989](https://github.com/openova-io/openova/issues/2989)): `bp-gitea` can't install without an `sso/gitea` secret that `bp-sso-bridge` can't write until `bp-catalyst-platform`→`bp-gitea` is up. So the console (catalyst-platform) never reaches Ready and `console.hw89.omani.works` does not resolve (verified: HTTP 000, connection timed out). Every live-UI row below is therefore ⛔ until #2989 lands and a fresh prov goes `ready`.

- **Persona:** First-time SME customer emailed a voucher code, on their phone.
- **Goal (user's words):** *"As a new customer, I want to redeem my code and reach my dashboard, so that I can start using my plan."*
